    다음과 같이 접근 시간이 주어졌을 때, 캐시 적중률은? (단, 캐시 적재 시간과 캐시 적중 여부 검사 시간은 제외한다)

    ○ 평균 기억장치 접근 시간 ＝ 2.5 ms

    ○ 주기억 장치 접근 시간 ＝ 11.5 ms

    ○ 캐시 기억장치 접근 시간 ＝ 1.5 ms

    1. 1. 0.8
    2. 2. 0.85
    3. 3. 0.9
    4. 4. 0.95

    정답 3번

    🔍 보기별 해설
    1. 적중률이 0.8이면 평균 접근 시간이 1.5×0.8+11.5×0.2=3.5가 되어 주어진 2.5와 맞지 않으므로 캐시 적중률에 해당하지 않는다.
    2. 적중률이 0.85이면 평균 접근 시간이 1.5×0.85+11.5×0.15=3.0이 되어 주어진 2.5와 맞지 않으므로 캐시 적중률에 해당하지 않는다.
    3. 평균 접근 시간은 h×1.5+(1-h)×11.5이므로 2.5=11.5-10h가 되어 h가 0.9이고 이 값이 주어진 조건과 맞으므로 캐시 적중률에 해당한다(정답).
    4. 적중률이 0.95이면 평균 접근 시간이 1.5×0.95+11.5×0.05=2.0이 되어 주어진 2.5와 맞지 않으므로 캐시 적중률에 해당하지 않는다.
    🧮 풀이
    1. 甲은 캐시가 적중하면 아주 빨리 읽고 빗나가면 주기억장치까지 가야 하는 과정을 시간표로 정리한 학생이다. 적중률이 낮아 평균 시간이 3.5라면 목표 값 2.5와는 거리가 멀다고 계산했다.
    2. 甲은 적중률을 조금씩 올려 가며 평균 접근 시간을 계산한 학생이다. 0.85에서 평균이 3.0으로 나와 목표 값보다 길다는 것을 알고 더 높은 적중률이 필요하다고 판단했다.
    3. 甲은 평균 접근 시간이 2.5가 되도록 식을 세워 적중률을 구한 학생이다. 2.5=11.5-10h를 풀어 0.9가 나오는 것을 확인하고 검산해 식이 성립하는 것을 확인했다.
    4. 甲은 적중률을 너무 높게 잡으면 평균 접근 시간이 목표 값보다 짧아진다는 것을 계산해 본 학생이다. 0.95에서 2.0이 나와 주어진 조건과 다르다고 결론 내렸다. 그래서 이 값은 문제에서 요구하는 값이 아니라고 판단했다.

    평균 접근 시간 2.5는 1.5h+11.5(1-h)이므로 h가 0.9여서 3번이 해당한다.

    다음 그림은 TCP 기반 서버와 클라이언트 간 소켓 통신을 위한 함수 호출 관계를 나타낸다. (가) ～ (다)에 들어갈 내용을 바르게 연결한 것은?

    (가) (나) (다)

    1. 1. request( ) accept( ) 연결 종료 요청
    2. 2. accept( ) connect( ) 연결 종료 요청
    3. 3. listen( ) accept( ) 데이터 송수신
    4. 4. request( ) connect( ) 데이터 송수신

    정답 3번

    🔍 보기별 해설
    1. 서버에서 bind 다음에 오는 (가)가 request이고 (나)가 accept라고 한 이 보기는 request가 소켓 통신 함수가 아니어서 (가)에 맞지 않고 (다)도 연결 종료 요청이 아니라 데이터 송수신이어서 옳지 않으므로 해당하지 않는다.
    2. 서버에서 bind 다음에 오는 (가)가 accept이고 (나)가 connect라고 한 이 보기는 connect가 클라이언트가 쓰는 함수여서 서버의 (나)에 맞지 않으므로 해당하지 않는다.
    3. 서버는 socket, bind 다음에 listen으로 연결 요청을 기다리고 accept로 요청을 받아들이며, 연결 뒤에는 read와 write로 데이터를 주고받으므로 이 보기는 그림에 맞아 해당한다(정답).
    4. 서버에서 bind 다음에 오는 (가)가 request이고 (나)가 connect라고 한 이 보기는 request가 소켓 함수가 아니고 connect가 클라이언트 쪽 함수여서 옳지 않으므로 해당하지 않는다.
    🧮 풀이
    1. 甲은 서버가 소켓을 만들고 주소를 묶은 뒤 다음에 무엇을 하는지 그림으로 확인한 학생이다. 존재하지 않는 함수 이름을 쓴 보기는 소켓 라이브러리 목록에 없는 이름이라 바로 제외했다.
    2. 甲은 클라이언트가 연결을 요청하는 함수를 서버 쪽 칸에 넣은 보기를 발견한 학생이다. 그 함수는 클라이언트에서 호출되므로 서버 흐름에는 들어갈 수 없다고 판단했다. 그래서 서버 흐름을 따라 그리며 이 함수의 자리를 하나씩 제외해 갔다.
    3. 甲은 서버가 접속 요청을 기다리다가 요청이 오면 받아들이고 데이터를 주고받는 순서를 손으로 따라 그린 학생이다. 그림의 화살표 순서와 정확히 맞는 것을 확인했다. 마지막에 연결이 끝나면 양쪽이 각자 소켓을 닫는 것까지 확인했다.
    4. 甲은 서버 흐름에서 요청을 기다리는 단계가 빠진 보기를 발견한 학생이다. 존재하지 않는 함수와 클라이언트 함수가 섞여 있어 그림과 맞지 않는다고 결론 내렸다. 그래서 이 보기도 그림의 함수 순서와 어긋나는 것으로 보았다.

    (가)는 listen, (나)는 accept, (다)는 데이터 송수신이므로 3번이 해당한다.

    프로세스 간 통신에 대한 설명으로 옳지 않은 것은?

    1. 1. 파이프(pipe)는 두 프로세스가 통신할 수 있게 하는 전달자로서 동작한다.
    2. 2. 지명 파이프(named pipe)는 서로 통신하는 프로세스 간 부모－자식 관계가 반드시 필요하다.
    3. 3. 신호(signal)는 알려 줄 사건의 근원지나 이유에 따라 비동기식으로도 전달될 수 있다.
    4. 4. 공유 메모리를 사용하는 프로세스 간 통신에서 프로세스들은 동시에 동일한 위치에 쓰지 않도록 책임져야 한다.

    정답 2번

    🔍 보기별 해설
    1. 파이프는 두 프로세스 사이에서 데이터가 한쪽에서 다른 쪽으로 흐르게 하는 통로 역할의 전달자로 동작하는 통신 수단이므로 이 보기는 옳다.
    2. 지명 파이프는 이름이 있어 서로 관계없는 프로세스도 그 이름으로 접근해 통신할 수 있고 부모-자식 관계가 필요한 것은 이름 없는 파이프이므로 이 보기는 옳지 않다(정답).
    3. 신호는 사건의 근원지나 이유에 따라 프로세스가 예상하지 못한 때에도 비동기로 전달될 수 있는 간단한 통지 수단이므로 이 보기는 옳다.
    4. 공유 메모리는 여러 프로세스가 같은 메모리 영역을 함께 쓰므로 운영체제가 동시 쓰기를 막아 주지 않아 프로세스들이 스스로 동시에 같은 위치에 쓰지 않도록 조정해야 하므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 부모 프로세스가 자식에게 결과를 넘겨주는 간단한 프로그램을 만든 학생이다. 이때 쓰는 통로가 두 프로세스 사이를 잇는 전달자 역할을 한다는 점을 이해했다. 한쪽이 쓰면 다른 쪽이 읽는 식으로 흘러가는 것을 실험으로 확인했다.
    2. 甲은 서로 다른 프로그램이 파일 이름 같은 이름으로 접속해 통신하도록 만든 개발자다. 부모와 자식일 필요가 없다는 점이 이름 있는 통로의 장점이라고 설명했다. 그래서 서로 관계없는 프로그램끼리도 통신이 가능했다.
    3. 甲은 프로세스가 언제 올지 모르는 외부 사건을 알리는 신호를 받아 처리하도록 코드를 짠 학생이다. 신호는 예고 없이 비동기로 도착할 수 있다는 점을 실험으로 확인했다. 언제 올지 모르는 신호를 기다리는 코드를 따로 작성해야 했다.
    4. 甲은 두 프로세스가 같은 메모리 칸에 동시에 값을 쓰다가 결과가 뒤섞이는 것을 겪은 학생이다. 공유 메모리를 쓸 때는 쓰는 쪽이 순서를 스스로 조정해야 한다는 점을 배웠다.

    지명 파이프는 부모와 자식 관계가 없는 프로세스끼리도 통신할 수 있으므로 부모-자식 관계가 반드시 필요하다고 한 2번이 옳지 않다.

    파이프라이닝 기법에 대한 설명으로 옳지 않은 것은?

    1. 1. 데이터 해저드는 앞의 명령 결과가 다음 명령의 입력으로 사용될 때 발생한다.
    2. 2. 이론적으로는 파이프라인의 단계 수만큼 빨라지지만, 이것을 방해하는 요소인 해저드가 발생할 수 있다.
    3. 3. 파이프라이닝은 명령어 하나를 여러 단계로 나누어 각각을 독립적인 장치에서 동시에 실행하는 기법이다.
    4. 4. 제어 해저드는 서로 다른 단계에서 실행되는 명령이 컴퓨터 내의 장치 하나를 동시에 사용하려고 할 때 발생한다.

    정답 4번

    🔍 보기별 해설
    1. 데이터 해저드는 앞의 명령 결과가 다음 명령의 입력으로 쓰이는데 아직 결과가 나오지 않아 기다려야 할 때 생기므로 이 보기는 옳다.
    2. 이론적으로는 파이프라인의 단계 수만큼 빨라지지만 해저드가 이를 방해해 그만큼의 성능 향상이 나오지 않을 수 있으므로 이 보기는 옳다.
    3. 파이프라이닝은 한 명령어를 나눈 여러 단계를 서로 다른 장치가 동시에 맡아 겹쳐 처리해 처리량을 높이는 방식이므로 이 보기는 옳다.
    4. 서로 다른 단계의 명령이 하나의 장치를 동시에 쓰려는 충돌은 구조 해저드이고 제어 해저드는 분기 때문에 명령 흐름이 바뀔 때 생기므로 이 보기는 옳지 않다(정답).
    🧮 풀이
    1. 甲은 앞 명령의 결과를 곧바로 다음 명령이 쓰는 코드를 파이프라인 시뮬레이터에서 실행한 학생이다. 결과가 나오기 전에 읽으려 해 잠시 기다려야 하는 상황이 생겼다. 그래서 결과가 나올 때까지 잠시 한 단계를 비워 두는 방법을 배웠다.
    2. 甲은 다섯 단계 파이프라인이라 다섯 배 빨라질 것으로 기대한 학생이다. 실제로는 기다려야 하는 상황 때문에 그만큼은 빨라지지 않았고 그 원인이 해저드임을 알았다. 그래서 파이프라인의 성능이 이론값에 못 미친다는 점을 정리했다.
    3. 甲은 세탁, 건조, 다림질을 서로 다른 기계로 겹쳐 하는 방법에서 착안해 명령어를 단계별로 처리하는 방법을 배운 학생이다. 단계마다 독립된 장치가 필요하다는 점을 알았다. 세탁물이 다음 기계로 넘어가는 동안 앞 기계가 다음 빨래를 받는다.
    4. 甲은 두 명령이 같은 기억장치를 동시에 읽으려다 한쪽이 멈추는 상황을 본 학생이다. 이것은 분기 때문이 아니라 장치를 함께 쓰려는 충돌에서 생기는 문제라는 점을 알았다. 그래서 이 경우는 분기 때문에 생기는 해저드와 구분해야 했다.

    제어 해저드는 분기 명령으로 명령의 흐름이 바뀔 때 생기고 장치를 동시에 쓰려는 충돌은 구조 해저드이므로 4번이 옳지 않다.

    원형 연결 리스트에 대한 설명으로 옳은 것은?

    1. 1. 하나의 노드에서 모든 노드로의 접근이 가능하다.
    2. 2. 하나의 노드에서 링크를 계속 따라가면 모든 노드를 거쳐도 자기 자신으로 되돌아올 수 없다.
    3. 3. 마지막 노드의 링크 필드 값은 NULL이다.
    4. 4. 리스트의 끝에 노드를 삽입하는 연산이 단순 연결 리스트보다 비효율적이다.

    정답 1번

    🔍 보기별 해설
    1. 원형 연결 리스트는 마지막 노드가 첫 노드를 가리키는 고리 모양이라 어떤 노드에서 출발해도 링크를 따라가면 모든 노드에 접근할 수 있으므로 이 보기는 옳다(정답).
    2. 원형 연결 리스트는 링크를 계속 따라가면 한 바퀴를 돌아 자기 자신으로 돌아오는 구조이므로 되돌아올 수 없다는 이 보기는 옳지 않다.
    3. 원형 연결 리스트의 마지막 노드는 NULL이 아니라 첫 노드를 가리키므로 마지막 노드의 링크 값이 NULL이라는 이 보기는 옳지 않다.
    4. 원형 연결 리스트는 마지막 노드의 위치를 알면 바로 뒤에 삽입할 수 있어 끝에 노드를 삽입하는 연산이 단순 연결 리스트보다 비효율적이지 않으므로 이 보기는 옳지 않다.
    🧮 풀이
    1. 甲은 순환 배차표에서 한 노선의 마지막 정류장이 첫 정류장으로 이어지는 모양을 리스트로 옮겨 본 학생이다. 어느 정류장에서 출발해도 모든 정류장을 방문할 수 있다는 점이 특징이었다.
    2. 甲은 리스트를 한 바퀴 도는 코드를 작성해 본 학생이다. 링크를 계속 따라가니 출발한 노드로 되돌아오는 것을 확인해 되돌아올 수 없다는 말이 틀렸음을 알았다. 그래서 끝없이 돌 수 있어 종료 조건을 따로 넣어야 했다.
