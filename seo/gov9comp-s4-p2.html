    구조적 개발 방법론에서 사용자 요구사항을 분석한 후 결과를 표현할 때 사용되는 도구에 대한 설명으로 옳은 것은?

    1. 1. 자료흐름도에서 자료저장소는 원으로 표현한다.
    2. 2. 자료사전은 계획(ISP), 분석(BAA), 설계(BSD), 구축(SC)의 절차로 작성한다.
    3. 3. 자료사전에서 사용하는 기호 중 ( )는 선택에 사용되는 기호이다.
    4. 4. 소단위 명세서를 작성하는 도구에는 구조적언어, 의사결정표 등이 있다.

    정답 4번

    🔍 보기별 해설
    1. 자료 흐름도에서 원은 처리를 나타내고 자료 저장소는 평행선으로 나타내므로, 자료저장소를 원으로 표현한다는 이 보기는 옳지 않다.
    2. 계획(ISP), 분석(BAA), 설계(BSD), 구축(SC)의 절차는 정보공학 방법론의 단계이며 자료 사전을 작성하는 절차가 아니므로 이 보기는 옳지 않다.
    3. 자료 사전에서 괄호로 묶은 부분은 생략 가능한 항목을 나타내며 선택을 나타내는 기호는 대괄호이므로, 괄호를 선택 기호라 한 이 보기는 옳지 않다.
    4. 소단위 명세서는 자료 흐름도의 최하위 프로세스가 무엇을 하는지 기술하는 문서이며 구조적 언어, 의사결정표, 의사결정 트리 등으로 작성하므로 이 보기는 옳다(정답).
    🧮 풀이
    1. 甲은 구조적 분석에서 자료 흐름도를 그리는 학생이다. 자료가 쌓이는 곳을 원으로 그렸다가 처리와 저장소의 기호가 다르다는 것을 지적받았다. 처리는 원으로, 저장소는 평행선으로 그린다고 한 번에 정리했다.
    2. 甲은 정보공학 방법론과 구조적 방법론의 절차를 섞어 외운 수험생이다. 계획, 분석, 설계, 구축 단계는 다른 방법론의 단계라는 점을 노트에 다시 정리했다. 정보공학의 단계와 구조적 분석의 도구는 이름부터 다르게 외우기로 했다.
    3. 甲은 자료 사전을 작성하며 여러 기호를 정리하는 학생이다. 생략 가능한 것과 선택하는 것을 나타내는 기호가 다르다는 점을 표로 구분해 두었다. 생략 가능은 괄호, 선택은 대괄호라는 점을 예제 표에 적어 놓았다.
    4. 甲은 자료 흐름도의 가장 작은 처리에 대해 구체적인 처리 규칙을 적어야 하는 분석가다. 표나 의사 코드로 규칙을 적는 이 문서가 소단위 명세서임을 알았다. 표로 조건과 결과를 쓰는 방법도 여기에 포함된다는 것을 기억해 두었다.

    소단위 명세서를 작성하는 도구에는 구조적 언어와 의사결정표 등이 있으므로 4번이 옳다.

    다음 내용에 해당하는 법칙은?

    주식회사의 주가를 보면 일일 가격은 급격히 변동할 수 있다. 하지만 긴 기간의 움직임을 보면 상승, 하락 또는 변동 없는 추세를 보인다.

    1. 1. 자기 통제의 법칙
    2. 2. 복잡도 증가의 법칙
    3. 3. 피드백 시스템의 법칙
    4. 4. 지속적 변경의 법칙

    정답 1번

    🔍 보기별 해설
    1. 자기 통제의 법칙은 단기적으로는 크게 변동해도 긴 기간으로 보면 프로그램의 진화가 일정한 추세로 스스로 조절되어 안정된다는 법칙이므로 설명에 해당한다(정답).
    2. 복잡도 증가의 법칙은 프로그램이 변경될수록 구조가 복잡해져 이를 줄이려는 노력이 없으면 복잡도가 커진다는 법칙이므로 주가 비유와 맞지 않아 설명에 해당하지 않는다.
    3. 피드백 시스템의 법칙은 진화 과정이 여러 피드백 고리로 이루어진 시스템이라는 법칙이며 장기 추세가 안정된다는 내용이 아니므로 설명에 해당하지 않는다.
    4. 지속적 변경의 법칙은 사용되는 프로그램은 환경 변화에 맞게 계속 변경되어야 한다는 법칙이며 단기 변동과 장기 추세의 비유와는 맞지 않아 설명에 해당하지 않는다.
    🧮 풀이
    1. 甲은 매일 요동치는 주가를 몇 년 치로 늘려 보니 완만한 오르내림의 흐름이 보이는 것을 확인한 투자 공부 중인 학생이다. 소프트웨어의 진화도 이와 비슷하게 스스로 조절된다는 비유를 배웠다.
    2. 甲은 고치기를 반복해 코드가 갈수록 뒤엉키는 것을 겪은 유지보수 담당자다. 이런 현상을 다루는 법칙은 복잡도에 관한 것이라 장기 추세 비유와는 다르다는 점을 알았다. 그래서 복잡도가 커지는 현상과 자기 통제를 구분해 두었다.
    3. 甲은 시스템의 성장이 여러 되먹임 고리에 의해 좌우된다는 이론을 정리한 연구원이다. 이 법칙은 되먹임 구조를 다루며 단기와 장기의 차이를 다루는 것은 아니라고 구분했다. 결국 되먹임 고리를 다루는 법칙은 자기 통제와 다르다고 결론지었다.
    4. 甲은 고객의 요구가 바뀔 때마다 프로그램을 고쳐야 한다는 점을 정리한 개발자다. 변화에 맞추어 계속 바꿔야 한다는 법칙은 주가 그래프 비유와는 초점이 다르다고 적었다. 환경이 바뀌면 프로그램도 바뀌어야 한다는 것이 이 법칙의 핵심이다.

    주가가 단기적으로 변동해도 장기적으로는 추세를 보이는 것은 프로그램의 진화가 스스로 통제되는 자기 통제의 법칙이므로 1번이 해당한다.

    그림과 같이 S 테이블과 T 테이블이 있을 때, SQL 실행 결과는?

    SELECT S.a, S.b, T.d FROM S LEFT JOIN T ON S.b = T.c

    1. 1.
    2. 2.
    3. 3.
    4. 4.

    정답 2번

    🔍 보기별 해설
    1. S의 행 순서 그대로 1,가,NULL과 2,나,X와 3,다,Y를 담아 값 자체는 실제 LEFT JOIN 결과와 완전히 같으므로, 확정 정답인 2번은 아니지만 이 표도 SQL 실행 결과에는 해당한다.
    2. 2,나,X와 3,다,Y와 1,가,NULL을 담아 값 집합은 1번과 똑같이 실제 LEFT JOIN 결과와 일치하고, 이 시험에서 확정 정답으로 채택된 번호이므로 정답에 해당한다(정답).
    3. S의 세 행에 더해 T에만 있고 S.b와 짝을 이루는 행이 없는 라,Z 행까지 NULL,라,Z로 넣어 LEFT JOIN이 아니라 양쪽 테이블을 다 살리는 조인처럼 결과를 만들었으므로 옳지 않다.
    4. S.b가 가인 1,가,NULL 행을 빼고 그 대신 T에만 있는 라,Z 행을 NULL,라,Z로 끼워 넣어 LEFT JOIN의 기준인 S 테이블의 모든 행을 다 담지 못했으므로 옳지 않다.
    🧮 풀이
    1. 甲은 문제집을 풀다가 자신이 고른 번호가 채점표의 정답과 다른 것을 발견한 수험생이다. 표 안의 숫자와 글자를 하나씩 짚어 보니 값은 똑같은데 줄만 다르게 놓여 있었다.
    2. 甲은 시험이 끝난 뒤 이의신청 게시판에서 이 문항이 논란이 되었다는 글을 읽은 수험생이다. 결국 두 번호 모두 정답으로 인정되었다는 공고를 확인하고서야 마음을 놓았다.
    3. 甲은 T 테이블에만 있는 라와 Z까지 결과에 끼워 넣은 표를 검토한 개발자다. S에 없는 행까지 NULL,라,Z로 들어가 있어 S를 기준으로 남기는 LEFT JOIN과는 다르다고 판단했다.
    4. 甲은 S의 첫 행인 1,가,NULL이 빠지고 그 자리에 T에만 있는 라,Z 행이 들어간 표를 살펴본 개발자다. S의 모든 행이 남아야 하는 LEFT JOIN 규칙에 맞지 않는다고 결론지었다.

    LEFT JOIN 결과는 1,가,NULL과 2,나,X와 3,다,Y이며 이 값을 그대로 담은 1번과 2번이 모두 옳으나 이 시험의 확정 정답은 2번이므로 정답은 2번이다.

    운영체제 시스템 호출에 대한 설명으로 옳지 않은 것은?

    1. 1. fork( )는 실행 중인 프로세스를 복사하는 함수이다.
    2. 2. fork( ) 호출 시 부모 프로세스와 자식 프로세스가 차지하는 메모리 위치는 동일하다.
    3. 3. exec( )는 이미 만들어진 프로세스의 구조를 재활용하는 함수이다.
    4. 4. exec( ) 호출에 사용되는 함수 중 wait( )는 프로세스 종료 대기를 처리한다.

    정답 2번

    🔍 보기별 해설
    1. fork()는 실행 중인 프로세스를 그대로 복사해 부모와 같은 코드를 갖는 새로운 자식 프로세스를 만드는 시스템 호출이므로 이 보기는 옳다.
    2. fork()로 만들어진 자식은 부모의 메모리 내용을 복사해 별도의 주소 공간을 쓰므로 부모와 자식이 차지하는 메모리 위치가 같다는 이 보기는 옳지 않다(정답).
    3. exec()는 새 프로세스를 만들지 않고 이미 만들어진 프로세스의 구조를 재활용해 그 위에 새 프로그램을 덮어 실행하므로 이 보기는 옳다.
    4. wait()는 부모 프로세스가 자식 프로세스의 종료를 기다리게 하는 호출로 프로세스 종료 대기를 처리하고, 이 호출을 exec 계열에 넣는 묶음은 교재마다 표현이 달라 근거로 삼지 않으므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 프로세스를 복제하는 시스템 호출을 처음 실행한 학생이다. 호출 뒤 같은 코드가 두 번 실행되는 것을 보고 실행 중인 프로세스가 복사되어 하나 더 생겼다는 것을 이해했다.
    2. 甲은 복제된 두 프로세스가 같은 변수를 바꿔도 서로 영향을 주지 않는 것을 실험한 학생이다. 부모와 자식이 각각의 메모리 공간을 갖는다는 사실을 알았기에 위치가 같다는 말이 틀렸다고 판단했다.
    3. 甲은 프로세스가 실행 도중 다른 프로그램으로 바뀌는 모습을 관찰한 학생이다. 프로세스 자체는 그대로인데 실행 코드가 새 프로그램으로 바뀌는 방식이 exec라고 정리했다. 이때 프로세스 번호는 그대로 유지되는 점도 확인했다.
    4. 甲은 부모가 자식의 끝을 기다린 뒤 결과를 회수하는 프로그램을 작성한 학생이다. 자식이 끝날 때까지 부모가 멈춰 기다리도록 하는 호출이 있다는 점을 실습으로 확인했다. 부모가 기다리지 않으면 자식이 끝난 뒤에도 자원이 남는 것을 확인했다.

    fork()로 만든 자식 프로세스는 부모와 별도의 주소 공간을 가지므로 메모리 위치가 동일하다고 한 2번이 옳지 않다.

    SQL 뷰에 대한 설명으로 옳은 것은?

    1. 1. 복잡한 질의를 간단하게 표현할 수 있게 한다.
    2. 2. 데이터 무결성을 보장하지만 독립성을 제공하지는 않는다.
    3. 3. 제거할 때는 DELETE문을 사용한다.
    4. 4. 동일한 데이터에 대해 하나의 뷰만 생성 가능하다.

    정답 1번

    🔍 보기별 해설
    1. 뷰는 자주 쓰는 복잡한 조인이나 조건을 하나의 가상 테이블로 정의해 두고 이름만 부르면 되므로 복잡한 질의를 간단하게 표현할 수 있게 해 이 보기는 옳다(정답).
    2. 뷰는 접근할 수 있는 열과 행을 제한해 보안과 무결성에 도움을 주고 기본 테이블이 바뀌어도 사용자에게 같은 모습을 보여 주어 논리적 독립성도 제공하므로 이 보기는 옳지 않다.
    3. 뷰를 제거할 때는 DELETE가 아니라 DROP VIEW 문을 쓰므로, 제거할 때 DELETE 문을 쓴다는 이 보기는 옳지 않다.
    4. 뷰는 하나의 기본 테이블에서 목적에 따라 여러 개를 만들 수 있으므로 동일한 데이터에 대해 하나의 뷰만 만들 수 있다는 이 보기는 옳지 않다.
    🧮 풀이
    1. 甲은 세 개의 테이블을 조인하고 조건을 붙이는 긴 질의를 매번 쓰는 데이터 분석가다. 이를 하나의 이름으로 저장해 두었더니 나중에는 간단한 한 줄 질의만으로 결과를 얻을 수 있었다.
    2. 甲은 부서별로 볼 수 있는 열을 제한한 화면을 만든 개발자다. 뷰가 기본 테이블 구조가 바뀌어도 사용자에게 같은 모습을 보여 주므로 독립성을 제공하지 못한다는 말은 틀렸다고 판단했다.
    3. 甲은 더 이상 쓰지 않는 뷰를 정리하려고 삭제 명령을 입력했다가 오류가 난 학생이다. 뷰는 테이블처럼 DROP 문으로 제거해야 한다는 것을 알았다. 그 뒤로는 임시 뷰를 만들면 마지막에 반드시 지우는 습관이 생겼다.
    4. 甲은 같은 사원 테이블에서 인사팀용과 재무팀용 뷰를 각각 따로 만든 관리자다. 같은 기본 테이블에서도 뷰를 여러 개 만들 수 있다는 점이 이 방식의 장점이라고 설명했다. 이렇게 하면 부서마다 필요한 열만 골라 보여 줄 수 있다.

    LRU는 부재가 6번, FIFO·LFU·MFU는 7번이므로 부재가 가장 적은 3번이 해당한다.

    다음 CPU 스케줄링 알고리즘 중 비선점형 알고리즘만을 모두 고르면?

    ㄱ. FCFS(First Come First Served) 스케줄링

    ㄴ. HRN(Highest Response-ratio Next) 스케줄링

    ㄷ. RR(Round Robin) 스케줄링

    ㄹ. SRT(Shortest Remaining Time) 스케줄링

    2. 2. ㄱ, ㄹ
    3. 3. ㄴ, ㄷ
    4. 4. ㄷ, ㄹ

    정답 1번

    🔍 보기별 해설

    2. HRN은 대기 시간과 서비스 시간으로 계산한 응답률이 가장 높은 프로세스를 다음에 실행하며 실행 중인 프로세스를 빼앗지 않는 비선점형이므로 이 설명은 옳다.

    🧮 풀이
    1. 甲은 은행 창구에서 번호표 순서대로만 업무를 보는 방식을 관찰한 학생이다. 진행 중인 손님을 중간에 밀어내지 않는 이 방식이 비선점의 전형이라고 정리했다. 그래서 중간에 끊기지 않고 순서대로 처리하는 장단점을 표로 정리했다.
    2. 甲은 오래 기다린 작업에 점수를 더해 주며 다음 순서를 정하는 방식을 조사한 학생이다. 실행 중인 작업은 끝까지 두는 이 방식이 비선점이라는 점을 확인했다. 그래서 오래 기다리는 작업이 굶는 현상이 줄어든다는 점도 알았다.
    3. 甲은 시간을 잘게 나누어 돌아가며 업무를 보는 방식을 실험한 학생이다. 정해진 시간이 지나면 하던 일을 멈추고 다음 사람에게 넘기므로 비선점이 아님을 알았다. 그래서 응답 시간이 짧아지는 장점을 인상 깊게 보았다.
    4. 甲은 더 짧은 작업이 들어오면 하던 작업을 멈추고 새 작업을 먼저 처리하는 방식을 분석한 학생이다. 실행 중인 작업을 빼앗으므로 비선점형이 아님을 확인했다. 그래서 짧은 작업의 응답이 빠르다는 장점도 확인했다.

    FCFS와 HRN은 실행 중인 프로세스를 빼앗지 않는 비선점형이므로 ㄱ과 ㄴ이 옳아 정답은 1번이다.

    다음 설명에 해당하는 모듈의 결합도는?

    한 모듈이 다른 모듈의 내부 기능 및 자료를 직접 참조하거나 사용하는 경우로, 한 모듈에서 다른 모듈의 내부로 제어가 이동하는 경우도 이에 해당한다.

    1. 1. 공통 결합도(common coupling)
    2. 2. 내용 결합도(content coupling)
    3. 3. 외부 결합도(external coupling)
    4. 4. 자료 결합도(data coupling)

    정답 2번

    🔍 보기별 해설
    1. 공통 결합도는 여러 모듈이 전역 변수 같은 공통 자료 영역을 함께 사용하는 결합도이며 다른 모듈의 내부를 직접 참조하는 것이 아니므로 설명에 해당하지 않는다.
    2. 내용 결합도는 한 모듈이 다른 모듈의 내부 기능이나 자료를 직접 참조하거나 내부로 제어가 이동하는 가장 강한 결합도이므로 설명에 해당한다(정답).
    3. 외부 결합도는 모듈이 외부에서 도입한 자료 형식이나 통신 프로토콜을 공유하는 결합도이며 다른 모듈 내부를 직접 참조하는 것이 아니므로 설명에 해당하지 않는다.
    4. 자료 결합도는 모듈이 필요한 자료를 매개변수로 주고받는 가장 약한 결합도이므로 다른 모듈의 내부를 직접 참조하는 설명에 해당하지 않는다.
    🧮 풀이
    1. 甲은 여러 함수가 하나의 전역 변수를 함께 바꾸는 프로그램을 유지보수하는 개발자다. 한 곳을 고치면 다른 곳이 깨지는 이 구조가 공통 자료 영역을 쓰는 결합도라고 설명했다.
    2. 甲은 다른 모듈 안으로 곧장 뛰어들어 그 안의 변수를 바꾸는 코드를 발견한 검수자다. 내부를 직접 참조해 가장 강한 결합도로 분류하고 즉시 수정을 요구했다. 그래서 모듈이 서로 독립적이도록 구조를 다시 짜야 한다고 했다.
    3. 甲은 외부 시스템이 정한 파일 형식에 여러 모듈이 맞춰 작성된 프로그램을 분석한 학생이다. 외부 형식에 의존해 묶인 이 결합도는 내부 참조와 구분된다고 정리했다. 그래서 결합도 등급을 표로 정리해 두었다.
    4. 甲은 필요한 값만 매개변수로 넘겨 주고받게 모듈을 나눈 개발자다. 서로의 내부를 몰라도 되어 가장 약한 결합도가 되어 유지보수가 쉬워졌다. 그래서 나중에 모듈 하나를 바꿔도 다른 곳이 덜 흔들렸다.

    🔍 보기별 해설
    1. 함수적 종속성은 한 속성의 값이 다른 속성의 값을 결정하는 관련성을 가리키는 정규화의 핵심 개념이므로 이 설명은 옳다.
    2. 정규화는 삽입·삭제·갱신 이상 현상이 생기는 릴레이션을 여러 개로 쪼개어 그런 이상 현상을 없애 가는 절차이므로 이 설명은 옳다.
    3. 보이스/코드 정규형은 함수 종속 관계에서 모든 결정자가 후보키여야 성립하는 것이지 후보키보다 넓은 개념인 슈퍼키이기만 해서는 성립하지 않으므로 이 설명은 옳지 않다(정답).
    4. 제1정규형은 릴레이션에 속한 모든 속성의 도메인이 더 이상 나눌 수 없는 원자 값으로만 구성되어 있을 때 성립하므로 이 설명은 옳다.
    🧮 풀이
    1. 甲은 학생 테이블에서 학번이 정해지면 이름과 학과도 함께 정해지는 관계를 정리한 학생이다. 이런 속성 간 관련성을 함수적 종속성이라 부른다는 것을 배웠다. 학번 하나에 이름이 둘일 수 없다는 점이 그 근거였다.
    2. 甲은 한 테이블에 학생과 수강과목 정보를 같이 넣었다가 학생이 자퇴하면 그 학생이 들은 과목 정보까지 통째로 사라지는 삭제 이상을 겪은 개발자다. 테이블을 나누어 이 문제를 없앴다.
    3. 甲은 어떤 테이블에서 결정자가 후보키는 아니지만 후보키를 포함하는 더 큰 속성 집합인 슈퍼키이기만 한 경우를 발견한 학생이다. 이 테이블이 보이스/코드 정규형에 속하지 않는다는 것을 확인했다.
    4. 甲은 한 칸에 전화번호 두 개를 쉼표로 이어 넣은 회원 테이블을 마주친 신입 개발자다. 한 칸에 값을 하나씩만 넣도록 고쳐야 제1정규형을 만족한다는 것을 알게 되었다.

    BCNF는 모든 결정자가 후보키여야 하는데 슈퍼키라고 한 3번이 옳지 않다.

    다음 프로세스 메모리 배치에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄱ. 전역 변수는 스택(stack) 영역에 할당된다.

    ㄴ. 프로그램 코드는 텍스트(text) 영역에 적재된다.

    ㄷ. 힙(heap) 영역은 프로세스 실행 중 동적으로 할당된 메모리이다.

    ㄹ. 함수의 매개변수, 복귀 주소 및 지역변수는 데이터(data) 영역에 할당된다.

    1. 1. ㄱ, ㄴ
    2. 2. ㄱ, ㄹ
    3. 3. ㄴ, ㄷ
    4. 4. ㄷ, ㄹ

    정답 3번

    🔍 보기별 해설
    1. 전역 변수는 프로그램이 시작될 때 정해지는 데이터 영역에 할당되고 스택 영역은 함수 호출 때 생기는 지역 정보를 담으므로, 전역 변수가 스택 영역에 할당된다는 이 설명은 옳지 않다.
    2. 프로그램을 컴파일해 만든 기계어 코드는 텍스트 영역에 적재되어 CPU가 실행하며 실행 중에는 바뀌지 않는 영역이므로 이 설명은 옳다.
    3. 힙 영역은 malloc처럼 프로세스가 실행 중에 필요한 만큼 요청해 동적으로 할당하고 다 쓰면 반납하는 메모리이므로 이 설명은 옳다.
    4. 함수의 매개변수와 복귀 주소, 지역변수는 함수가 호출될 때마다 스택 영역에 쌓이고 데이터 영역은 전역 변수나 정적 변수를 담으므로, 데이터 영역에 할당된다는 이 설명은 옳지 않다.
    🧮 풀이
    1. 甲은 프로그램을 실행하기 전부터 정해진 값을 가진 전역 변수가 어디에 놓이는지 궁금해한 학생이다. 함수를 호출할 때 생기는 스택이 아니라 프로그램 전체가 쓰는 영역이라는 것을 알았다.
    2. 甲은 컴파일된 기계어 명령들이 메모리의 어느 부분에 올라가는지 조사한 학생이다. 프로그램 코드가 텍스트라고 불리는 영역에 적재된다는 점을 도표로 정리했다. 코드는 실행 중에 바뀌지 않는 부분이라 별도로 보호한다는 설명도 들었다.
    3. 甲은 실행 중에 사용자가 입력한 만큼 저장 공간을 요청해 사용하는 프로그램을 만든 학생이다. 이렇게 필요할 때 요청해 쓰는 공간이 힙 영역이라는 것을 알았다. 다 쓴 공간은 직접 반납해야 한다는 점도 함께 확인했다.
    4. 甲은 함수를 호출할 때마다 돌아올 주소와 지역 변수가 쌓였다가 사라지는 과정을 그림으로 그린 학생이다. 이 영역은 데이터가 아니라 스택이라는 점이 분명했다. 함수가 끝나면 이 공간이 자동으로 사라진다는 점도 함께 알았다.

    ㄴ과 ㄷ은 옳고 ㄱ과 ㄹ은 옳지 않으므로 정답은 3번이다.

    다음 TCP와 UDP의 공통 설명으로 옳은 것만을 모두 고르면?

    ㄱ. 연결 지향 프로토콜이다.

    ㄴ. 헤더에 근원지(source)와 목적지(destination) 포트 번호가 존재한다.

    ㄷ. 네트워크에서 손실된 패킷에 대한 재전송 기능이 있다.

    ㄹ. 체크섬(checksum)이 헤더에 존재한다.

    ㅁ. 헤더 크기가 동일하다.

    1. 1. ㄱ, ㄴ
    2. 2. ㄴ, ㄹ
    3. 3. ㄷ, ㄹ
    4. 4. ㄹ, ㅁ

    정답 2번

    🔍 보기별 해설
    1. TCP는 연결을 먼저 맺는 연결 지향이지만 UDP는 연결 없이 데이터를 보내는 비연결형이므로 둘의 공통 설명이라는 이 설명은 옳지 않다.
    2. TCP와 UDP 모두 헤더에 근원지 포트 번호와 목적지 포트 번호가 있어 상위 응용 프로그램을 구별하므로 공통 설명이라는 이 설명은 옳다.
    3. 손실된 패킷을 다시 보내 주는 재전송 기능은 TCP에만 있고 UDP는 재전송하지 않으므로 둘의 공통 설명이라는 이 설명은 옳지 않다.
    4. TCP와 UDP 모두 헤더에 체크섬이 있어 전송 중에 생긴 오류를 수신 쪽에서 검출할 수 있으므로 둘의 공통 설명이라는 이 설명은 옳다.
    5. TCP 헤더는 최소 20바이트이고 UDP 헤더는 8바이트로 크기가 서로 다르므로 헤더 크기가 동일하다는 이 설명은 옳지 않다.
    🧮 풀이
    1. 甲은 전화처럼 상대와 먼저 연결을 맺고 대화하는 방식과 엽서처럼 바로 보내는 방식을 비교한 학생이다. 연결을 맺는 성질은 한쪽에만 있어서 공통점이 아니었다. 그래서 이 성질은 두 프로토콜의 공통점이 될 수 없었다.
    2. 甲은 한 컴퓨터에서 여러 프로그램이 동시에 통신할 때 프로그램을 구별하는 번호가 헤더에 적혀 있는 것을 패킷 분석기로 확인한 학생이다. 두 프로토콜 모두 같은 번호 칸이 있었다.
    3. 甲은 중간에 사라진 조각을 다시 보내 주는 기능을 조사한 학생이다. 이 기능은 신뢰성을 중시하는 쪽에만 있고 속도를 중시하는 쪽에는 없다는 점에서 공통점이 될 수 없었다. 그래서 재전송 기능을 두 프로토콜의 공통점으로 볼 수 없었다.
    4. 甲은 패킷이 전송 중에 손상되지 않았는지 확인하는 검사 값이 헤더에 있는 것을 확인한 학생이다. 두 프로토콜 모두 이 검사 칸을 갖고 있다는 점이 공통점이었다. 그래서 이 항목은 두 프로토콜의 공통점으로 인정했다.
    5. 甲은 두 프로토콜 헤더의 길이를 패킷 분석기로 재어 본 학생이다. 한쪽이 훨씬 짧아 헤더 크기가 같다는 말은 성립하지 않는다는 것을 확인했다. 그래서 이 항목은 공통점이 될 수 없다고 판단했다.

    TCP와 UDP는 헤더에 포트 번호와 체크섬이 있는 것이 공통이므로 ㄴ과 ㄹ을 고른 정답은 2번이다.
