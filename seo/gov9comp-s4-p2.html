    구조적 개발 방법론에서 사용자 요구사항을 분석한 후 결과를 표현할 때 사용되는 도구에 대한 설명으로 옳은 것은?

    1. 1. 자료흐름도에서 자료저장소는 원으로 표현한다.
    2. 2. 자료사전은 계획(ISP), 분석(BAA), 설계(BSD), 구축(SC)의 절차로 작성한다.
    3. 3. 자료사전에서 사용하는 기호 중 ( )는 선택에 사용되는 기호이다.
    4. 4. 소단위 명세서를 작성하는 도구에는 구조적언어, 의사결정표 등이 있다.

    정답 4번

    🔍 보기별 해설
    1. 자료흐름도에서 자료저장소는 열린 직사각형이나 두 평행선으로 나타낸다. 원은 처리 과정을 나타내므로 옳지 않다.
    2. 자료사전은 자료흐름도에 나타난 자료 항목의 이름과 구조를 정의한다. 정보화 전략계획부터 구축까지의 절차 이름을 나열하는 도구가 아니므로 옳지 않다.
    3. 자료사전에서 괄호는 반복이나 선택을 나타내는 기호와 구별해 사용한다. 제시한 괄호를 선택 기호로 단정했으므로 옳지 않다.
    4. 소단위 명세서는 자료흐름도의 처리 과정을 상세히 기술한다. 구조적 언어와 의사결정표로 처리 규칙을 표현할 수 있으므로 옳다(정답).
    🧮 풀이
    1. 주문 정보가 처리 과정을 지나 주문 기록으로 저장되는 흐름을 그린다. 저장된 주문 기록은 자료저장소 기호로 표시하고 주문 처리 자체는 원으로 표시한다. 두 기호를 바꾸면 저장 위치와 수행 활동이 혼동된다.
    2. 자료사전에는 고객번호의 형식과 주문내역의 구성 요소를 적는다. 자료흐름도에서 사용한 이름의 뜻을 일관되게 정의하기 위한 문서다. 전체 개발 사업의 계획·분석·설계·구축 절차를 항목별로 나열하는 문서가 아니다.
    3. 고객 정보에 연락처가 있을 수도 없을 수도 있다는 규칙을 자료사전 기호로 적는다. 선택 가능한 항목과 반복되는 항목은 서로 다른 기호로 구분한다. 괄호 하나를 모든 선택 상황의 기호로 사용하면 구조를 잘못 읽게 된다.
    4. 할인 계산 처리에 회원 등급과 구매 금액에 따른 조건이 여러 개 있다. 조건별 할인율을 의사결정표로 정리하거나 구조적 언어의 IF 문장으로 작성한다. 자료흐름도에서 한 덩어리로 보이던 처리 과정을 소단위 명세서가 구체화한다.

    소단위 명세서를 구조적 언어나 의사결정표로 작성할 수 있으므로 정답은 4번이다.

    다음 내용에 해당하는 법칙은?

    주식회사의 주가를 보면 일일 가격은 급격히 변동할 수 있다. 하지만 긴 기간의 움직임을 보면 상승, 하락 또는 변동 없는 추세를 보인다.

    1. 1. 자기 통제의 법칙
    2. 2. 복잡도 증가의 법칙
    3. 3. 피드백 시스템의 법칙
    4. 4. 지속적 변경의 법칙

    정답 1번

    🔍 보기별 해설
    1. 자기 통제의 법칙은 시스템의 단기 변동이 커도 장기적으로는 일정한 경향을 보일 수 있음을 설명한다. 자료의 주가 비유와 맞으므로 옳다(정답).
    2. 복잡도 증가의 법칙은 소프트웨어가 계속 변경되면서 구조가 복잡해지는 경향을 말한다. 장기 추세의 안정성을 설명하는 법칙이 아니므로 옳지 않다.
    3. 피드백 시스템의 법칙은 변화 과정에서 여러 층의 피드백을 고려해야 한다는 설명이다. 단기 변동과 장기 추세의 대비 자체를 가리키지 않으므로 옳지 않다.
    4. 지속적 변경의 법칙은 환경에 맞추려면 소프트웨어가 계속 바뀌어야 한다는 뜻이다. 긴 기간에 나타나는 자기 조절 경향과 다른 내용이므로 옳지 않다.
    🧮 풀이
    1. 주식 가격은 하루 동안 크게 오르거나 내릴 수 있다. 하지만 여러 해의 자료를 함께 보면 일정한 상승·하락 또는 정체 경향을 파악할 수 있다. 장기간의 변동이 스스로 조절되는 듯한 모습을 자기 통제의 비유로 설명한다.
    2. 운영 중인 소프트웨어에 새 기능을 계속 붙이면 기존 모듈과의 의존성이 늘어난다. 구조를 다듬는 작업이 없으면 변경하기도 점점 어려워진다. 이러한 복잡도 증가가 단기 주가 변화와 장기 추세를 비교한 자료의 핵심은 아니다.
    3. 소프트웨어 개발팀이 사용자 오류 보고를 받아 수정하고 운영 지표를 다시 관찰한다. 수정 결과가 다음 작업에 영향을 주는 피드백 과정이다. 여러 피드백의 작동을 설명하는 법칙과 장기 변동의 자기 통제는 초점이 다르다.
    4. 은행 업무 규칙이 바뀌면 운영 중인 프로그램도 새 규칙에 맞춰 고쳐야 한다. 환경이 바뀌는데 프로그램을 그대로 두면 업무에 점차 맞지 않게 된다. 계속 변경해야 한다는 내용은 주가의 장기 경향에 관한 비유와 다르다.

    짧은 기간의 변동에도 긴 기간에는 일정한 경향을 보이는 자기 통제의 법칙이므로 정답은 1번이다.

    SELECT S.a, S.b, T.d FROM S LEFT JOIN T ON S.b = T.c

    1. 1.
    2. 2.
    3. 3.
    4. 4.

    정답 2번

    🔍 보기별 해설
    1. S의 행 순서 그대로 1,가,NULL과 2,나,X와 3,다,Y를 담아 값 자체는 실제 LEFT JOIN 결과와 완전히 같으므로, 확정 정답인 2번은 아니지만 이 표도 SQL 실행 결과에는 해당한다.
    2. 2,나,X와 3,다,Y와 1,가,NULL을 담아 값 집합은 1번과 똑같이 실제 LEFT JOIN 결과와 일치하고, 이 시험에서 확정 정답으로 채택된 번호이므로 정답에 해당한다(정답).
    3. S의 세 행에 더해 T에만 있고 S.b와 짝을 이루는 행이 없는 라,Z 행까지 NULL,라,Z로 넣어 LEFT JOIN이 아니라 양쪽 테이블을 다 살리는 조인처럼 결과를 만들었으므로 옳지 않다.
    4. S.b가 가인 1,가,NULL 행을 빼고 그 대신 T에만 있는 라,Z 행을 NULL,라,Z로 끼워 넣어 LEFT JOIN의 기준인 S 테이블의 모든 행을 다 담지 못했으므로 옳지 않다.
    🧮 풀이
    1. 甲은 문제집을 풀다가 자신이 고른 번호가 채점표의 정답과 다른 것을 발견한 수험생이다. 표 안의 숫자와 글자를 하나씩 짚어 보니 값은 똑같은데 줄만 다르게 놓여 있었다.
    2. 甲은 시험이 끝난 뒤 이의신청 게시판에서 이 문항이 논란이 되었다는 글을 읽은 수험생이다. 결국 두 번호 모두 정답으로 인정되었다는 공고를 확인하고서야 마음을 놓았다.
    3. 甲은 T 테이블에만 있는 라와 Z까지 결과에 끼워 넣은 표를 검토한 개발자다. S에 없는 행까지 NULL,라,Z로 들어가 있어 S를 기준으로 남기는 LEFT JOIN과는 다르다고 판단했다.
    4. 甲은 S의 첫 행인 1,가,NULL이 빠지고 그 자리에 T에만 있는 라,Z 행이 들어간 표를 살펴본 개발자다. S의 모든 행이 남아야 하는 LEFT JOIN 규칙에 맞지 않는다고 결론지었다.

    LEFT JOIN 결과는 1,가,NULL과 2,나,X와 3,다,Y이며 이 값을 그대로 담은 1번과 2번이 모두 옳으나 이 시험의 확정 정답은 2번이므로 정답은 2번이다.

    운영체제 시스템 호출에 대한 설명으로 옳지 않은 것은?

    1. 1. fork( )는 실행 중인 프로세스를 복사하는 함수이다.
    2. 2. fork( ) 호출 시 부모 프로세스와 자식 프로세스가 차지하는 메모리 위치는 동일하다.
    3. 3. exec( )는 이미 만들어진 프로세스의 구조를 재활용하는 함수이다.
    4. 4. exec( ) 호출에 사용되는 함수 중 wait( )는 프로세스 종료 대기를 처리한다.

    정답 2번

    🔍 보기별 해설
    1. fork()는 실행 중인 프로세스를 그대로 복사해 부모와 같은 코드를 갖는 새로운 자식 프로세스를 만드는 시스템 호출이므로 이 보기는 옳다.
    2. fork()로 만들어진 자식은 부모의 메모리 내용을 복사해 별도의 주소 공간을 쓰므로 부모와 자식이 차지하는 메모리 위치가 같다는 이 보기는 옳지 않다(정답).
    3. exec()는 새 프로세스를 만들지 않고 이미 만들어진 프로세스의 구조를 재활용해 그 위에 새 프로그램을 덮어 실행하므로 이 보기는 옳다.
    4. wait()는 부모 프로세스가 자식 프로세스의 종료를 기다리게 하는 호출로 프로세스 종료 대기를 처리하고, 이 호출을 exec 계열에 넣는 묶음은 교재마다 표현이 달라 근거로 삼지 않으므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 프로세스를 복제하는 시스템 호출을 처음 실행한 학생이다. 호출 뒤 같은 코드가 두 번 실행되는 것을 보고 실행 중인 프로세스가 복사되어 하나 더 생겼다는 것을 이해했다.
    2. 甲은 복제된 두 프로세스가 같은 변수를 바꿔도 서로 영향을 주지 않는 것을 실험한 학생이다. 부모와 자식이 각각의 메모리 공간을 갖는다는 사실을 알았기에 위치가 같다는 말이 틀렸다고 판단했다.
    3. 甲은 프로세스가 실행 도중 다른 프로그램으로 바뀌는 모습을 관찰한 학생이다. 프로세스 자체는 그대로인데 실행 코드가 새 프로그램으로 바뀌는 방식이 exec라고 정리했다. 이때 프로세스 번호는 그대로 유지되는 점도 확인했다.
    4. 甲은 부모가 자식의 끝을 기다린 뒤 결과를 회수하는 프로그램을 작성한 학생이다. 자식이 끝날 때까지 부모가 멈춰 기다리도록 하는 호출이 있다는 점을 실습으로 확인했다. 부모가 기다리지 않으면 자식이 끝난 뒤에도 자원이 남는 것을 확인했다.

    fork()로 만든 자식 프로세스는 부모와 별도의 주소 공간을 가지므로 메모리 위치가 동일하다고 한 2번이 옳지 않다.

    SQL 뷰에 대한 설명으로 옳은 것은?

    1. 1. 복잡한 질의를 간단하게 표현할 수 있게 한다.
    2. 2. 데이터 무결성을 보장하지만 독립성을 제공하지는 않는다.
    3. 3. 제거할 때는 DELETE문을 사용한다.
    4. 4. 동일한 데이터에 대해 하나의 뷰만 생성 가능하다.

    정답 1번

    🔍 보기별 해설
    1. 뷰는 질의 결과를 가상 테이블처럼 보여 주어 복잡한 조인이나 조건을 간단한 이름으로 사용할 수 있다. 복잡한 질의의 표현을 줄이므로 옳다(정답).
    2. 뷰는 사용자가 볼 열과 행을 제한하고 기초 테이블의 구조 변화를 숨기는 데 도움을 준다. 데이터 독립성을 제공하지 않는다는 단정이므로 옳지 않다.
    3. 뷰를 제거할 때는 정의를 삭제하는 DROP VIEW 명령을 사용한다. DELETE는 데이터의 행을 지우는 명령이므로 옳지 않다.
    4. 같은 기초 데이터에 대해 목적에 맞춰 여러 뷰를 만들 수 있다. 하나만 생성할 수 있다는 제한이 없으므로 옳지 않다.
    🧮 풀이
    1. 주문과 고객 테이블을 조인하고 최근 주문만 고르는 질의가 길어졌다고 하자. 이 질의에 뷰 이름을 붙이면 보고서 작성자는 간단히 뷰를 조회할 수 있다. 복잡한 검색 조건을 매번 다시 적지 않아도 된다.
    2. 인사 담당자는 급여 열을 볼 수 있지만 일반 직원은 이름과 부서만 보도록 뷰를 나눌 수 있다. 기초 테이블의 일부 구조가 바뀌어도 뷰 정의를 조정해 사용자의 조회 방식을 유지할 수 있다. 뷰가 독립성에 도움을 주는 사례다.
    3. 사용하지 않는 보고서용 뷰를 없애려면 DROP VIEW를 실행한다. DELETE를 실행하면 조회 대상의 행을 지우려는 명령으로 해석되어 목적이 다르다. 뷰 정의와 테이블 데이터를 구별해야 한다.
    4. 같은 직원 테이블에서 부서별 명단 뷰와 직급별 명단 뷰를 각각 만든다. 두 뷰는 동일한 기초 데이터를 서로 다른 조건과 열로 보여 준다. 데이터 한 묶음에 뷰를 하나만 둘 이유가 없다.

    뷰는 복잡한 질의를 이름 붙여 재사용할 수 있으므로 정답은 1번이다.

    ㄷ. RR(Round Robin) 스케줄링

    2. 2. ㄱ, ㄹ
    3. 3. ㄴ, ㄷ
    4. 4. ㄷ, ㄹ

    2. HRN(Highest Response-ratio Next, 최고 응답률 우선)은 대기 시간과 실행 시간을 바탕으로 다음 작업을 고른다. 선택된 작업을 완료할 때까지 실행하는 비선점 방식이므로 옳다.
    3. RR(Round Robin, 라운드 로빈)은 일정한 시간 할당량이 끝나면 실행 중인 프로세스를 대기열로 돌린다. 실행 도중 다른 작업으로 교체하는 선점 방식이므로 옳지 않다.
    4. SRT(Shortest Remaining Time, 최소 잔여 시간 우선)는 새 작업의 남은 실행 시간이 더 짧으면 현재 작업을 중단한다. 선점형 방식이므로 옳지 않다.
    🧮 풀이
    1. 도착 순서가 A, B, C인 작업을 FCFS로 처리한다. A가 시작하면 B가 도착해도 A의 실행을 강제로 끊지 않는다. A가 끝난 뒤에야 B가 실행돼 비선점 방식의 동작이 드러난다. 다음 작업의 도착만으로 실행 순서가 바뀌지 않는다.

    다음 설명에 해당하는 모듈의 결합도는?

    한 모듈이 다른 모듈의 내부 기능 및 자료를 직접 참조하거나 사용하는 경우로, 한 모듈에서 다른 모듈의 내부로 제어가 이동하는 경우도 이에 해당한다.

    1. 1. 공통 결합도(common coupling)
    2. 2. 내용 결합도(content coupling)
    3. 3. 외부 결합도(external coupling)
    4. 4. 자료 결합도(data coupling)

    정답 2번

    🔍 보기별 해설
    1. 공통 결합도는 둘 이상의 모듈이 전역 자료를 함께 사용하는 형태다. 다른 모듈의 내부 기능에 직접 들어가는 경우와는 다르므로 옳지 않다.
    2. 내용 결합도는 한 모듈이 다른 모듈의 내부 자료나 명령을 직접 참조한다. 자료에 적힌 내부 제어 이동도 포함하므로 옳다(정답).
    3. 외부 결합도는 모듈들이 외부에서 정한 자료 형식이나 장치 인터페이스를 함께 따르는 형태다. 다른 모듈의 내부를 직접 참조하는 경우가 아니므로 옳지 않다.
    4. 자료 결합도는 필요한 자료값을 매개변수로 전달해 모듈을 연결한다. 상대 모듈의 내부 구조를 직접 사용하지 않으므로 옳지 않다.
    🧮 풀이
    1. 두 함수가 같은 전역 설정 변수를 읽고 값을 바꾼다. 한 함수의 변경이 다른 함수의 동작에 영향을 줄 수 있다. 공유 전역 자료에 의존하는 연결을 공통 결합도라고 부른다.
    2. 함수 A가 함수 B 내부에 숨겨진 지역 자료를 직접 읽거나 B의 중간 명령 위치로 뛰어든다. B의 구현을 고치면 A까지 깨질 수 있다. 내부 내용에 직접 의존하는 이런 연결은 내용 결합도가 높다.
    3. 두 모듈이 외부 장치에서 정한 고정 길이 메시지 형식을 그대로 사용한다. 장치의 형식이 바뀌면 두 모듈 모두 수정해야 할 수 있다. 외부 규약을 함께 따르는 의존성이 외부 결합도다.
    4. 주문 처리 함수가 가격과 수량을 매개변수로 세금 계산 함수에 보낸다. 세금 계산 함수는 전달받은 값으로 결과를 돌려주며 주문 함수의 내부 변수에 접근하지 않는다. 필요한 자료만 주고받는 연결이 자료 결합도다.

    다른 모듈의 내부 자료나 기능을 직접 건드리는 것은 내용 결합도이므로 정답은 2번이다.

    3. 메모리의 1000번 위치에서 값을 읽으려면 주소 1000을 메모리 주소 레지스터에 적는다. 기억장치는 그 위치에 있는 값을 찾아 반환한다. 주소와 반환된 데이터는 서로 다른 레지스터에서 취급한다.
    4. 프로세서가 메모리 1000번 위치의 값 42를 읽는다. 주소는 메모리 주소 레지스터에 두고 읽힌 42는 메모리 버퍼 레지스터에 잠시 둔다. 반대로 42를 메모리에 쓸 때도 데이터가 이 레지스터를 거친다.

    기억장치로 오가는 데이터가 잠시 머무는 레지스터는 메모리 버퍼 레지스터이므로 정답은 4번이다.

    언어 번역 프로그램에 해당하지 않는 것은?

    1. 1. 어셈블러
    2. 2. 컴파일러
    3. 3. 인터프리터
    4. 4. 워드프로세서

    정답 4번

    🔍 보기별 해설
    1. 어셈블러는 어셈블리어의 기호 명령을 프로세서가 실행할 기계어로 번역한다. 프로그래밍 언어의 표현을 실행 가능한 코드로 바꾸므로 옳다.
    2. 컴파일러는 원시 프로그램을 구문·의미에 따라 분석해 목적 프로그램을 생성한다. 원시 언어를 실행 가능한 형식으로 옮기는 번역 프로그램이므로 옳다.
    3. 인터프리터는 원시 코드의 명령을 읽어 실행하며 번역 과정을 수행한다. 언어 처리 프로그램에 해당하므로 옳다.
    4. 워드프로세서는 글의 입력·편집·서식을 다루는 문서 작성 도구다. 프로그램 언어를 기계가 실행할 형태로 번역하지 않으므로 옳지 않다(정답).
    🧮 풀이
    1. 어셈블리어의 `ADD` 같은 기호 명령을 프로세서가 이해할 기계어 코드로 바꾼다. 이 변환을 마치면 기계가 실행할 명령어열을 얻을 수 있다. 기호 언어와 기계어 사이를 옮기는 도구가 어셈블러다.
    2. 개발자가 작성한 C 프로그램을 컴파일러에 넣는다. 컴파일러는 구문을 검사하고 목적 파일을 만든다. 프로그램 전체를 실행 가능한 형태로 옮기는 언어 번역 작업이다.
    3. 파이썬 프로그램을 실행하면 인터프리터가 소스의 명령을 해석하고 실행한다. 코드의 의미를 처리하며 동작을 이어 간다. 문서 편집 프로그램과 달리 프로그래밍 언어의 실행에 관여한다.
    4. 보고서의 제목 글꼴을 바꾸고 표를 삽입해 문서를 완성한다. 워드프로세서에서는 글과 서식을 편집하는 기능이 중심이다. 작성된 프로그래밍 언어를 기계어로 옮기지는 않는다.

    워드프로세서는 문서 작성 프로그램이며 언어 번역 프로그램이 아니므로 정답은 4번이다.

    데이터베이스 정규화에 대한 설명으로 옳지 않은 것은?

    1. 1. 정규화 과정에서 고려해야 하는 속성 간의 관련성을 함수적 종속성이라고 한다.
    2. 2. 정규화는 이상 현상이 발생하는 릴레이션을 분해하여 이상 현상을 없애는 과정이다.
    3. 3. 릴레이션의 함수 종속 관계에서 모든 결정자가 슈퍼키면 보이스/코드 정규형(BCNF)에 속한다.
    4. 4. 릴레이션에 속한 모든 속성의 도메인이 원자 값(atomic value)만으로 구성되어 있으면 제1 정규형에 속한다.

    정답 3번

    🔍 보기별 해설
    1. 함수적 종속성은 한 속성의 값이 다른 속성의 값을 결정하는 관련성을 가리키는 정규화의 핵심 개념이므로 이 설명은 옳다.
    2. 정규화는 삽입·삭제·갱신 이상 현상이 생기는 릴레이션을 여러 개로 쪼개어 그런 이상 현상을 없애 가는 절차이므로 이 설명은 옳다.
    3. 보이스/코드 정규형은 함수 종속 관계에서 모든 결정자가 후보키여야 성립하는 것이지 후보키보다 넓은 개념인 슈퍼키이기만 해서는 성립하지 않으므로 이 설명은 옳지 않다(정답).
    4. 제1정규형은 릴레이션에 속한 모든 속성의 도메인이 더 이상 나눌 수 없는 원자 값으로만 구성되어 있을 때 성립하므로 이 설명은 옳다.
    🧮 풀이
    1. 甲은 학생 테이블에서 학번이 정해지면 이름과 학과도 함께 정해지는 관계를 정리한 학생이다. 이런 속성 간 관련성을 함수적 종속성이라 부른다는 것을 배웠다. 학번 하나에 이름이 둘일 수 없다는 점이 그 근거였다.
    2. 甲은 한 테이블에 학생과 수강과목 정보를 같이 넣었다가 학생이 자퇴하면 그 학생이 들은 과목 정보까지 통째로 사라지는 삭제 이상을 겪은 개발자다. 테이블을 나누어 이 문제를 없앴다.
    3. 甲은 어떤 테이블에서 결정자가 후보키는 아니지만 후보키를 포함하는 더 큰 속성 집합인 슈퍼키이기만 한 경우를 발견한 학생이다. 이 테이블이 보이스/코드 정규형에 속하지 않는다는 것을 확인했다.
    4. 甲은 한 칸에 전화번호 두 개를 쉼표로 이어 넣은 회원 테이블을 마주친 신입 개발자다. 한 칸에 값을 하나씩만 넣도록 고쳐야 제1정규형을 만족한다는 것을 알게 되었다.

    BCNF는 모든 결정자가 후보키여야 하는데 슈퍼키라고 한 3번이 옳지 않다.

    다음 프로세스 메모리 배치에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄱ. 전역 변수는 스택(stack) 영역에 할당된다.

    ㄴ. 프로그램 코드는 텍스트(text) 영역에 적재된다.

    ㄷ. 힙(heap) 영역은 프로세스 실행 중 동적으로 할당된 메모리이다.

    ㄹ. 함수의 매개변수, 복귀 주소 및 지역변수는 데이터(data) 영역에 할당된다.

    1. 1. ㄱ, ㄴ
    2. 2. ㄱ, ㄹ
    3. 3. ㄴ, ㄷ
    4. 4. ㄷ, ㄹ

    정답 3번

    🔍 보기별 해설
    1. 전역 변수는 프로그램 전반에서 사용하는 데이터 영역에 놓인다. 함수 호출마다 생기는 스택 영역에 놓는다는 진술이므로 옳지 않다.
    2. 프로그램의 기계어 명령은 실행 가능한 코드가 담긴 텍스트 영역에 적재된다. 코드의 배치 영역을 맞게 설명하므로 옳다.
    3. 힙 영역은 실행 도중 요청한 크기만큼 메모리를 동적으로 할당할 때 사용한다. 실행 중 할당이라는 설명이므로 옳다.
    4. 함수의 매개변수·복귀 주소·지역 변수는 일반적으로 호출 스택에서 관리한다. 데이터 영역에 놓인다는 진술이므로 옳지 않다.
    🧮 풀이
    1. 프로그램이 시작할 때 전역 카운터를 하나 정의한다. 여러 함수가 같은 카운터를 읽고 바꾸며 함수가 끝나도 값은 사라지지 않는다. 각 함수 호출이 끝나면 해제되는 스택보다 전역 변수의 수명이 함수 호출보다 길다는 점이 드러난다.
    2. 컴파일한 프로그램의 덧셈과 분기 명령은 실행 코드로 저장된다. 운영체제가 프로그램을 올릴 때 이 명령들을 텍스트 영역에 배치한다. 변수값을 담는 데이터 영역과 코드 영역은 역할이 다르다.
    3. 실행 중 사용자에게 필요한 배열 크기를 입력받아 그 크기만큼 메모리를 요청한다. 요청 시점에 크기가 정해지는 배열은 힙에 할당할 수 있다. 사용이 끝나면 동적 메모리 할당을 해제해야 한다.
    4. 함수에 숫자 5를 전달하고 그 안에서 지역 변수 result를 만든다. 함수가 호출된 동안 매개변수와 지역 변수, 복귀 정보가 호출 스택에 연결된다. 함수가 돌아오면 그 호출에 해당하는 스택 공간은 정리된다.

    전역 변수는 데이터 영역에, 매개변수·복귀 주소·지역변수는 스택에 놓이므로 ㄱ·ㄹ은 틀리고, 옳은 것은 ㄴ·ㄷ이므로 정답은 3번이다.

    다음 TCP와 UDP의 공통 설명으로 옳은 것만을 모두 고르면?

    ㄱ. 연결 지향 프로토콜이다.

    ㄴ. 헤더에 근원지(source)와 목적지(destination) 포트 번호가 존재한다.

    ㄷ. 네트워크에서 손실된 패킷에 대한 재전송 기능이 있다.

    ㄹ. 체크섬(checksum)이 헤더에 존재한다.

    ㅁ. 헤더 크기가 동일하다.

    1. 1. ㄱ, ㄴ
    2. 2. ㄴ, ㄹ
    3. 3. ㄷ, ㄹ
    4. 4. ㄹ, ㅁ

    정답 2번

    🔍 보기별 해설
    1. TCP(Transmission Control Protocol, 전송 제어 프로토콜)는 연결을 설정하지만 UDP(User Datagram Protocol, 사용자 데이터그램 프로토콜)는 연결을 설정하지 않는다. 두 프로토콜의 공통 성질이 아니므로 옳지 않다.
    2. TCP와 UDP의 헤더에는 송신지 포트와 수신지 포트 번호가 있다. 응용 프로그램의 통신 끝점을 구분하므로 옳다.
    3. TCP는 손실된 데이터를 재전송할 수 있지만 UDP 자체에는 재전송 보장이 없다. 두 프로토콜의 공통 기능이 아니므로 옳지 않다.
    4. TCP와 UDP 모두 전송 중 데이터 오류를 확인할 체크섬 필드를 헤더에 둔다. 공통 헤더 요소이므로 옳다.
    5. TCP의 기본 헤더는 UDP 헤더보다 크고 선택 사항에 따라 길이도 달라질 수 있다. 두 헤더 크기가 같다는 진술이므로 옳지 않다.
    🧮 풀이
    1. 웹 서버와 안정적으로 통신할 때 TCP는 연결 수립 절차를 거친다. 짧은 DNS 질의를 UDP로 보낼 때는 같은 연결 수립 과정을 먼저 수행하지 않는다. 연결 지향 여부를 두 방식의 공통점으로 묶을 수 없다. UDP는 데이터그램을 바로 보낼 수 있다.
    2. 한 컴퓨터에서 여러 앱이 동시에 네트워크를 사용한다. 송신지 포트와 수신지 포트가 있으면 도착한 데이터를 알맞은 앱에 전달할 수 있다. TCP와 UDP는 모두 포트 번호를 사용한다.
    3. TCP로 전송한 세그먼트가 손실되면 확인 응답과 타이머를 이용해 다시 보낼 수 있다. UDP로 보낸 데이터그램은 프로토콜이 자동으로 같은 재전송을 보장하지 않는다. 응용 프로그램이 따로 복구 방식을 만들 수는 있다.
    4. 보낸 데이터에 전송 오류가 생겼는지 확인하려고 체크섬을 계산한다. 수신자는 헤더의 체크섬 값과 받은 내용을 비교한다. TCP와 UDP 모두 오류 확인을 위한 필드를 헤더에 둔다.
    5. UDP 헤더에는 기본 필드 네 개가 간단히 들어간다. TCP 헤더에는 순서 번호와 확인 응답 번호 등 추가 제어 필드가 있다. 두 프로토콜의 기본 헤더 길이를 같다고 볼 수 없다.

    TCP와 UDP 헤더에 공통으로 있는 것은 포트 번호와 체크섬이고, 연결 지향·재전송·같은 헤더 크기는 공통이 아니므로 옳은 것은 ㄴ·ㄹ이고 정답은 2번이다.
