    다음 상황에 대한 트랜잭션(transaction)의 특성은?

    제품의 재고량을 갱신하는 트랜잭션이 커밋(commit) 되기 전에 시스템 장애가 발생했다. 장애 후 데이터베이스는 트랜잭션이 수행한 변경 사항을 모두 취소하였고, 시스템은 장애 이전의 상태로 복구되었다.

    1. 1. 일관성(consistency)
    2. 2. 원자성(atomicity)
    3. 3. 지속성(durability)
    4. 4. 고립성(isolation)

    정답 2번

    🔍 보기별 해설
    1. 일관성은 트랜잭션이 성공적으로 끝나면 데이터베이스가 규칙에 맞는 일관된 상태가 되는 성질이며 변경을 통째로 취소하는 성질을 뜻하지 않으므로 상황에 해당하지 않는다.
    2. 원자성은 트랜잭션의 연산이 모두 수행되거나 하나도 수행되지 않아야 하는 성질이라 커밋 전에 장애가 나 변경 사항을 전부 취소하고 이전 상태로 되돌린 것이 이 성질에 해당한다(정답).
    3. 지속성은 커밋된 트랜잭션의 결과가 장애가 나도 유지되어야 하는 성질이며 이 상황은 커밋 전이므로 유지가 아니라 취소가 이루어져 상황에 해당하지 않는다.
    4. 고립성은 실행 중인 트랜잭션의 중간 결과가 다른 트랜잭션에 보이지 않아야 하는 성질이며 장애 뒤에 변경을 취소한 것과는 관계가 없으므로 상황에 해당하지 않는다.
    🧮 풀이
    1. 甲은 이체 처리 프로그램이 끝나고 나서 계좌 잔액의 합이 규칙에 맞는지 확인하는 검산 담당이다. 처리가 끝난 뒤의 데이터가 규칙을 지키는지 살피는 일이며 도중에 사고가 났을 때 되돌리는 일과는 다르다고 정리했다.
    2. 甲은 재고를 갱신하다가 확정 직전에 서버가 꺼졌는데 재가동한 뒤 갱신 전 재고 수량 그대로인 것을 확인한 관리자다. 반쯤 반영된 상태가 남지 않고 처음 상태로 돌아갔다는 점이 인상 깊었다.
    3. 甲은 주문을 확정한 직후 정전이 나도 주문 내역이 그대로 남아 있는지 시험한 담당자다. 확정된 결과가 사라지지 않아야 하는 성질이며 확정 전에 취소되는 성질과는 반대 방향이라고 구분했다.
    4. 甲은 재고 수정 화면을 두 사람이 동시에 열어 저장 버튼을 누른 상황을 실험한 학생이다. 진행 중에 바뀌는 값이 서로에게 비쳐 보이지 않아야 한다는 성질이며 장애 뒤 취소와는 다르다고 정리했다.

    커밋 전 장애로 변경을 모두 취소하고 이전 상태로 복구하는 것은 모두 수행되거나 전혀 수행되지 않는 원자성이므로 2번이 해당한다.

    데이터를 구조 형태에 따라 구분할 때 이에 대한 설명으로 옳지 않은 것은?

    1. 1. XML 문서는 데이터를 교환하는 용도로 활용되고 있다.
    2. 2. 정형 데이터(structured data)는 미리 정해진 구조에 따라 데이터를 저장하며 관계 데이터베이스에서 널리 사용된다.
    3. 3. 비정형 데이터(unstructured data)에는 사전에 데이터 타입이 정해지지 않은 텍스트도 있다.
    4. 4. 반정형 데이터(semi-structured data)는 데이터 구조와 내용을 별도의 파일 형태로 저장한다.

    정답 4번

    🔍 보기별 해설
    1. XML 문서는 태그로 구조를 표현해 서로 다른 시스템 사이에서 데이터를 주고받는 교환 용도로 널리 쓰이는 문서 형식이므로 이 보기는 옳다.
    2. 정형 데이터는 미리 정해진 구조에 따라 열과 자료형을 지켜 저장되며 표 형태의 관계 데이터베이스에서 널리 쓰이므로 이 보기는 옳다.
    3. 비정형 데이터는 정해진 구조가 없는 데이터를 말하며 사전에 데이터 타입이 정해지지 않은 텍스트, 이미지, 영상 등이 포함되므로 이 보기는 옳다.
    4. 반정형 데이터는 구조를 별도 파일로 두지 않고 태그나 키 같은 구조 정보를 데이터 안에 함께 담고 있으므로, 구조와 내용을 별도 파일로 저장한다는 이 보기는 옳지 않다(정답).
    🧮 풀이
    1. 甲은 두 회사가 주문 정보를 주고받을 때 태그로 항목 이름을 붙인 문서를 교환하는 방식을 도입한 개발자다. 태그가 자료의 뜻을 함께 알려 주어 서로 다른 시스템도 읽을 수 있었다.
    2. 甲은 열과 자료형이 미리 정해진 표에 학생 정보를 저장하는 교무 시스템을 운영하는 담당자다. 정해진 구조에 맞춰 넣어야 하는 이 방식이 관계 데이터베이스에 어울린다고 정리했다.
    3. 甲은 고객이 남긴 자유로운 글과 사진을 저장하는 게시판을 만든 개발자다. 일정한 열로 나눌 수 없는 자료라서 정해진 구조가 없는 데이터로 분류한다는 점을 알았다. 이 구분을 나중에 볼 노트에도 한 줄로 옮겨 적었다.
    4. 甲은 항목 이름과 값이 한 덩어리 안에 함께 들어 있는 문서 파일을 열어 본 학생이다. 구조가 별도 파일에 있지 않고 자료 안에 함께 담겨 있어 이를 반정형 데이터라고 부른다는 점을 알았다.

    반정형 데이터는 구조 정보가 데이터 안에 함께 들어 있으므로 구조와 내용을 별도 파일로 저장한다고 한 4번이 옳지 않다.

    다음 릴레이션(relation) R과 S의 카티션 프로덕트(cartesian product) 연산 시 결과 릴레이션의 차수(degree)와 카디널리티(cardinality) 값은?

    R S 번호 이름 번호 나이 100 강감찬 100 82 200 이순신 101 53 300 한용운 102 66 차수 카디널리티

    1. 1. 3 6
    2. 2. 4 6
    3. 3. 3 9
    4. 4. 4 9

    정답 4번

    🔍 보기별 해설
    1. 차수 3과 카디널리티 6은 차수를 합이 아니라 하나로 세고 튜플 수를 곱이 아니라 합으로 계산한 값이므로 결과 릴레이션의 값에 해당하지 않는다.
    2. 차수 4는 맞지만 카디널리티 6은 튜플 수 3과 3을 더한 값이며 카티션 프로덕트는 곱이므로 9가 되어야 해서 결과 릴레이션의 값에 해당하지 않는다.
    3. 차수 3은 공통 속성 번호를 한 번만 센 값인데 카티션 프로덕트는 같은 이름의 속성도 합치지 않고 모두 나열하므로 4이어야 해서 결과 릴레이션의 값에 해당하지 않는다.
    4. R은 속성 2개에 튜플 3개, S도 속성 2개에 튜플 3개이므로 카티션 프로덕트의 차수는 2+2=4, 카디널리티는 3×3=9이므로 결과 릴레이션의 값에 해당한다(정답).
    🧮 풀이
    1. 甲은 두 표의 열을 모두 합쳐 몇 개인지를 세다가 번호 열이 겹쳐 세 개라고 잘못 센 학생이다. 곱 연산은 이름이 같은 열도 합치지 않는다는 점을 확인하고 열 수를 다시 셌다.
    2. 甲은 두 표의 행 수를 더해 여섯이라고 답한 학생이다. 곱 연산에서는 한 표의 각 행이 다른 표의 모든 행과 짝지어지므로 행 수가 곱이 된다는 점을 짝을 지어 보고 알았다.
    3. 甲은 두 표에 같은 이름의 번호 열이 있다는 이유로 열 수를 줄여 세었다가 틀린 학생이다. 곱 연산은 조인과 달리 같은 이름의 열을 하나로 합치지 않는다는 점을 확인했다. 그날 배운 내용을 표로 만들어 책상 앞에 붙여 두었다.
    4. 甲은 학생 세 명과 과목 세 개의 모든 짝을 표로 나열해 본 학생이다. 아홉 줄이 나오고 열은 두 표의 열을 모두 이어 붙여 네 개가 된다는 점을 직접 세어 확인했다. 다음 시간에는 같은 유형의 문제를 하나 더 풀어 보기로 했다.

    카티션 프로덕트의 차수는 두 릴레이션 차수의 합 4, 카디널리티는 튜플 수의 곱 9이므로 4번이 해당한다.

    트랜잭션에 대한 설명으로 옳지 않은 것은?

    1. 1. 커밋된 후에도 해당 트랜잭션은 롤백(rollback)을 사용하여 취소가 가능하다.
    2. 2. 현재 수행 중인 트랜잭션을 롤백하면 트랜잭션에서 SQL 문에 의해 수행된 모든 갱신이 취소(undo)된다.
    3. 3. 현재 수행 중인 트랜잭션을 커밋하면 트랜잭션이 수행한 갱신을 데이터베이스에 영구적으로 반영한다.
    4. 4. 트랜잭션은 데이터베이스 관리 시스템(database management system)에서 데이터를 다루는 논리적인 작업의 단위이다.

    정답 1번

    🔍 보기별 해설
    1. 커밋이 끝난 트랜잭션은 갱신이 데이터베이스에 영구히 반영되어 롤백으로 되돌릴 수 없으므로, 커밋 후에도 롤백으로 취소할 수 있다는 이 보기는 옳지 않다(정답).
    2. 수행 중인 트랜잭션을 롤백하면 그 트랜잭션에서 SQL 문으로 수행된 모든 갱신이 취소되어 시작하기 전 상태로 돌아가므로 이 보기는 옳다.
    3. 커밋을 실행하면 지금까지 수행한 갱신이 확정되어 데이터베이스에 영구히 남고 이후에는 취소할 수 없는 상태가 되므로 이 보기는 옳다.
    4. 트랜잭션은 여러 연산을 하나의 일처럼 묶은 논리적인 작업 단위로 데이터베이스 관리 시스템이 다루는 기본 단위이므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 주문을 확정한 뒤 실수로 잘못 입력한 것을 알고 되돌림 명령을 실행한 사원이다. 이미 확정한 결과는 되돌릴 수 없어 새로운 정정 주문을 넣어야 한다는 점을 알았다. 옆자리 동료에게도 이 점을 짚어 주며 함께 다시 확인했다.
    2. 甲은 여러 수정 명령을 실행한 뒤 확정하기 전에 되돌림 명령을 실행해 처음 상태로 돌아간 것을 확인한 학생이다. 진행 중의 갱신을 모두 취소하는 명령이라는 점을 알았다. 그 뒤로는 같은 실수를 하지 않도록 순서를 종이에 적어 두었다.
    3. 甲은 여러 수정을 마친 뒤 확정 명령을 실행하자 다른 접속에서도 변경된 내용이 보이는 것을 확인한 학생이다. 확정하면 갱신이 영구히 반영된다는 점을 알았다. 결과를 스스로 다시 계산해 보고서야 마음이 놓였다.
    4. 甲은 이체를 위한 두 개의 수정 명령을 하나의 묶음으로 처리하는 프로그램을 만든 학생이다. 둘이 함께 이루어지거나 아무것도 안 되는 논리적 작업의 단위라는 점을 강조했다. 교재의 해당 쪽에 밑줄을 긋고 예시를 하나 덧붙여 두었다.

    커밋한 트랜잭션은 변경이 영구적으로 반영되어 롤백으로 취소할 수 없으므로 롤백으로 취소가 가능하다고 한 1번이 옳지 않다.

    ‘학생’ 테이블에 대한 검색 권한을 사용자 ‘홍길동’에게 부여하는 SQL 문을 완성할 때 (가)와 (나)에 들어갈 내용을 바르게 연결한 것은?

    (가) (나) ON 학생 TO 홍길동; (가) (나)

    1. 1. SELECT REVOKE
    2. 2. SELECT GRANT
    3. 3. GRANT SELECT
    4. 4. REVOKE SELECT

    정답 3번

    🔍 보기별 해설
    1. (가)를 SELECT로, (나)를 REVOKE로 본 이 연결은 권한을 주는 명령어 GRANT가 맨 앞에 와야 하는 문법과 어긋나고 REVOKE는 권한을 회수하는 명령이라 해당하지 않는다.
    2. (가)를 SELECT로, (나)를 GRANT로 본 이 연결은 GRANT가 문장 맨 앞에 오고 권한 이름이 뒤에 오는 순서가 뒤바뀌어 문법에 맞지 않으므로 해당하지 않는다.
    3. GRANT 권한 ON 테이블 TO 사용자의 형식에서 (가)는 권한을 주는 명령어 GRANT이고 (나)는 검색 권한 SELECT이므로 학생 테이블의 검색 권한을 홍길동에게 부여하는 문장이 되어 해당한다(정답).
    4. (가)를 REVOKE로, (나)를 SELECT로 본 이 연결은 REVOKE가 권한을 회수하는 명령이라 권한을 부여하는 문장이 되지 못하고 TO 대신 FROM을 써야 하므로 해당하지 않는다.
    🧮 풀이
    1. 甲은 명령의 첫 낱말에 권한 이름을 쓰고 마지막에 권한을 회수하는 명령을 쓴 학생이다. 권한을 주는 명령이 문장 맨 앞에 와야 한다는 규칙을 몰라 실행 오류를 만났다. 확인한 내용을 발표 자료의 한 장으로 정리해 두었다.
    2. 甲은 권한 이름을 먼저 쓰고 그다음에 권한을 주는 명령을 쓴 학생이다. 문장의 순서가 뒤바뀌어 실행되지 않았고 조교가 정확한 문법 순서를 알려 주었다. 스터디 모임에서 이 점을 다시 설명해 보며 익혔다.

    4. 甲은 한 사원이 여러 자격증과 여러 취미를 갖는 표를 다루며 서로 독립된 다치 값이 섞이는 문제를 발견한 학생이다. 이런 문제는 더 높은 정규형에서 다룬다는 점을 알았다. 이 구분을 나중에 볼 노트에도 한 줄로 옮겨 적었다.

    ㄱ과 ㄷ은 옳고 ㄴ은 이행적 종속 제거가 제3정규형의 조건이며 ㄹ은 다치 종속을 제4정규형에서 다루므로 정답은 2번이다.

    인덱스(index)에 대한 설명으로 옳지 않은 것은?

    4. 4. 데이터에서 수정, 삭제 등의 변경이 발생하면 인덱스를 재구성할 수 있다.

    3. 甲은 학번 순으로 정렬되어 저장된 표에서 몇 번째마다 색인 항목을 하나씩만 둔 학생이다. 정렬된 표라서 이렇게 성기게 만들어도 원하는 행을 찾을 수 있었다. 확인한 내용을 발표 자료의 한 장으로 정리해 두었다.
    4. 甲은 대량의 행을 삭제한 뒤 색인의 상태가 나빠진 것을 확인한 학생이다. 색인을 다시 만들어 상태를 회복하는 방법이 있다는 점을 알았다. 스터디 모임에서 이 점을 다시 설명해 보며 익혔다.

    희소 인덱스는 정렬된 데이터 파일의 클러스터링 인덱스에서 쓸 수 있으므로 사용할 수 없다고 한 3번이 옳지 않다.

    다음 뷰(view)에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄴ. 뷰는 데이터 보안 강화, 복잡한 쿼리 단순화를 위해 사용할 수 있다.

    1. 1. ㄱ, ㄴ
    2. 2. ㄱ, ㄷ

    4. 4. ㄱ, ㄴ, ㄷ

    정답 1번

    🔍 보기별 해설
    1. 실체화된 뷰는 뷰 정의 질의의 결과를 물리적으로 저장해 두었다가 일정 주기로 다시 계산해 새로 갱신할 수 있는 뷰이므로 이 설명은 옳다.
    2. 뷰는 필요한 열만 보이도록 해 데이터 보안을 강화하고 복잡한 질의를 이름 하나로 줄여 단순하게 할 수 있으므로 이 설명은 옳다.
    3. GROUP BY 절로 묶인 뷰의 한 행은 원본의 여러 행이 합쳐진 것이라 그 행을 고쳐도 원본의 어느 행을 고칠지 정할 수 없어 갱신할 수 없으므로, 갱신할 수 있다는 이 설명은 옳지 않다.
    🧮 풀이
    1. 甲은 자주 쓰는 집계 결과를 뷰의 형태로 저장해 두고 매일 밤 다시 계산해 새로 고치는 시스템을 만든 학생이다. 조회가 빨라지는 대신 저장 공간이 든다는 점을 알았다. 문제를 다 푼 뒤 근거가 된 정의를 한 번 더 읽어 보았다.

    1. TS(Ti) < TS(Tj)이면 요청자 Ti가 더 오래되었으므로 wound-wait 기법에서는 Ti가 Tj를 상처 입혀 Tj를 철회시키고 같은 타임스탬프로 재시작하게 하므로 이 보기는 옳다.
    2. TS(Tj) < TS(Ti)이면 Tj가 더 오래된 잠금 보유자이고 wound-wait 기법에서는 젊은 요청자 Ti가 대기하는 것이지 Tj가 대기하는 것이 아니므로, Tj가 대기한다는 이 보기는 옳지 않다(정답).
    3. TS(Tj) < TS(Ti)이면 Ti가 더 젊은 요청자이므로 wait-die 기법에서는 Ti가 죽어 철회하고 같은 타임스탬프로 재시작하므로 이 보기는 옳다.
    4. TS(Ti) < TS(Tj)이면 Ti가 더 오래된 요청자이므로 wait-die 기법에서는 오래된 Ti가 기다리므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 먼저 시작한 작업이 나중에 시작한 작업이 쥔 자원을 요청하면 나중 작업을 되돌려 자원을 넘겨받는 규칙을 실험한 학생이다. 오래된 쪽이 젊은 쪽을 밀어낸다는 점이 이 방식의 특징이었다.
    2. 甲은 신입 작업이 고참 작업이 쥔 자원을 요구할 때 기다리게 하는 규칙을 실험한 학생이다. 기다리는 쪽이 자원을 쥔 쪽이 아니라 요구하는 젊은 쪽이라는 점을 표로 확인했다.
    3. 甲은 젊은 작업이 오래된 작업의 자원을 요청하면 젊은 작업이 스스로 포기하고 같은 순번으로 다시 시작하는 규칙을 실험한 학생이다. 기다리지 않고 포기하는 것이 특징이었다. 그림으로 그려 보니 머릿속이 한결 또렷해졌다.
    4. 甲은 오래된 작업이 젊은 작업이 쥔 자원을 요청하면 기다리게 하는 규칙을 실험한 학생이다. 오래된 쪽을 기다리게 하는 것이 앞의 방식과 다르다는 점을 정리했다. 틀린 이유를 한 줄로 적어 오답 노트에 넣었다.

    wound-wait에서는 오래된 요청자가 젊은 상대를 철회시키고 젊은 요청자는 기다리므로 Tj가 대기한다고 한 2번이 옳지 않다.

    비트맵 인덱스에 대한 설명으로 옳지 않은 것은?

    1. 1. 한 가지 특정 속성값에 대해 하나의 비트맵 인덱스가 만들어진다.
    2. 2. 릴레이션의 카디널리티가 n 일 경우, 비트맵 인덱스의 크기는 log_2 n 비트이다.
    3. 3. 탐색 키의 중복 비율이 높은 속성을 대상으로 수행되는 질의에 효율적이다.
    4. 4. 다중 키를 가진 질의를 쉽게 처리하기 위해 고안된 특수한 형태의 인덱스이다.

    정답 2번

    🔍 보기별 해설
    1. 비트맵 인덱스는 하나의 속성값마다 별도의 비트 벡터를 하나씩 만들므로 특정 속성값에 대해 하나의 비트맵 인덱스가 만들어진다는 이 보기는 옳다.
    2. 비트맵 인덱스의 각 벡터는 릴레이션의 튜플마다 한 비트씩을 가지므로 릴레이션의 카디널리티가 n이면 벡터의 크기는 n 비트이며 log2 n 비트가 아니므로 이 보기는 옳지 않다(정답).
    3. 비트맵 인덱스는 성별처럼 값의 종류는 적고 중복 비율이 높은 속성에 알맞아 이런 속성을 대상으로 하는 질의에 효율적이므로 이 보기는 옳다.
    4. 비트맵 인덱스는 여러 속성에 걸친 조건을 비트 연산으로 빠르게 조합할 수 있어 다중 키 질의를 쉽게 처리하도록 고안된 특수한 인덱스이므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 남성과 여성 두 값만 있는 열에 색인을 만들려고 값마다 자리 표시를 만든 학생이다. 값 하나마다 하나의 표시열이 만들어진다는 점을 알았다. 같은 원리가 다른 문제에도 나오는지 찾아보았다.
    2. 甲은 레코드가 백 개인 표에서 비트맵 한 줄을 만들어 본 학생이다. 각 레코드가 한 칸씩을 차지해 백 칸이 되지 칠 칸이 되는 것이 아니라는 점을 확인했다. 비슷한 예를 하나 더 만들어 스스로 확인해 보았다.
    3. 甲은 등급이 세 가지뿐인 열에서 비트 조합으로 조건을 처리해 본 학생이다. 값이 자주 중복되는 열에서 효과가 크다는 점이 인상적이었다. 헷갈릴 때는 정의로 돌아가는 것이 가장 빠르다고 느꼈다.
    4. 甲은 성별이 여성이면서 등급이 A인 행을 찾기 위해 두 열의 비트 줄을 겹쳐 본 학생이다. 여러 조건을 비트 연산으로 쉽게 처리하도록 만든 인덱스라는 점을 알았다. 이 구분을 나중에 볼 노트에도 한 줄로 옮겨 적었다.

    비트맵 인덱스는 값마다 비트 벡터를 만들고 그 길이가 레코드 수 n이므로 크기가 log2 n 비트라고 한 2번이 옳지 않다.
