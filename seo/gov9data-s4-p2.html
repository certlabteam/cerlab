    다음 상황에 대한 트랜잭션(transaction)의 특성은?

    제품의 재고량을 갱신하는 트랜잭션이 커밋(commit) 되기 전에 시스템 장애가 발생했다. 장애 후 데이터베이스는 트랜잭션이 수행한 변경 사항을 모두 취소하였고, 시스템은 장애 이전의 상태로 복구되었다.

    1. 1. 일관성(consistency)
    2. 2. 원자성(atomicity)
    3. 3. 지속성(durability)
    4. 4. 고립성(isolation)

    정답 2번

    🔍 보기별 해설
    1. 일관성은 완료된 거래가 무결성 조건을 지키는 상태로 데이터베이스를 옮긴다는 성질이다. 미완료 거래의 전부 취소와는 초점이 달라 옳지 않다.
    2. 원자성은 거래의 모든 작업이 함께 완료되거나 모두 취소되게 한다. 커밋 전 변경을 전부 취소한 장면과 맞으므로 옳다(정답).
    3. 지속성은 성공적으로 커밋한 변경을 장애 뒤에도 보존한다. 커밋하지 못한 변경을 취소한 사례가 아니므로 옳지 않다.
    4. 고립성은 동시에 실행되는 거래가 서로의 미완료 중간 상태에 간섭하지 않게 한다. 장애 뒤 전부 취소를 설명하지 않으므로 옳지 않다.
    🧮 풀이
    1. 재고가 음수가 될 수 없다는 규칙을 가진 창고 표가 있다. 정상적으로 완료한 출고 거래는 이 규칙을 지키는 값으로 바꾼다. 무결성 조건을 지키는 것은 일관성의 문제이며 장애 전 작업을 모두 취소했다는 사실만으로 설명되지 않는다.
    2. 출고 거래가 창고 A에서 10개를 빼고 창고 B에 10개를 더하기 전에 서버가 멈춘다. 회복기는 A의 차감도 취소해 두 창고를 시작 상태로 되돌린다. 한쪽 수정만 남기지 않는 결과가 원자성이다.
    3. 상품 재고를 50개에서 40개로 바꾼 거래가 커밋된 뒤 정전이 난다. 재시작해도 40개라는 결과가 남도록 로그로 복구한다. 이는 완료된 거래에 적용되는 지속성이고 발문의 미완료 거래와 다르다.
    4. 동시에 진행된 두 주문이 같은 재고를 읽는다. 한 주문이 아직 확정하지 않은 수량을 다른 주문이 읽지 못하게 격리한다. 발문의 핵심은 동시 간섭이 아니라 장애 때 미완료 작업을 전부 되돌린 일이다.

    커밋 전 장애가 난 거래의 변경을 전부 취소하는 것은 원자성이므로 정답은 2번이다.

    데이터를 구조 형태에 따라 구분할 때 이에 대한 설명으로 옳지 않은 것은?

    1. 1. XML 문서는 데이터를 교환하는 용도로 활용되고 있다.
    2. 2. 정형 데이터(structured data)는 미리 정해진 구조에 따라 데이터를 저장하며 관계 데이터베이스에서 널리 사용된다.
    3. 3. 비정형 데이터(unstructured data)에는 사전에 데이터 타입이 정해지지 않은 텍스트도 있다.
    4. 4. 반정형 데이터(semi-structured data)는 데이터 구조와 내용을 별도의 파일 형태로 저장한다.

    정답 4번

    🔍 보기별 해설
    1. XML은 태그로 자료의 의미와 구조를 표시할 수 있어 시스템 사이의 데이터 교환에 쓰인다. 활용 사례가 맞으므로 옳다.
    2. 정형 데이터는 미리 정한 스키마의 열과 자료형에 맞춰 값을 저장한다. 관계형 데이터베이스의 표가 대표적이므로 옳다.
    3. 비정형 데이터에는 고정된 열·자료형으로 미리 정리되지 않은 자유 텍스트가 있다. 설명과 맞으므로 옳다.
    4. 반정형 데이터는 태그나 키 등 구조 정보가 데이터 내용 안에 함께 나타난다. 구조와 내용을 별도 파일로 저장한다는 설명은 옳지 않다(정답).
    🧮 풀이
    1. 도서관이 도서명과 저자를 XML 태그로 묶어 다른 기관에 보낸다. 받는 기관은 태그 이름을 읽어 각 값의 의미를 알아낸다. 서로 다른 시스템에서 자료를 교환하는 데 XML 형식을 쓸 수 있다.
    2. 학생 테이블에 학번은 정수, 이름은 문자열, 입학일은 날짜로 열을 미리 정의한다. 새 학생 행도 이 열 구성과 자료형에 맞춰 저장한다. 정해진 스키마를 따르는 정형 데이터다.
    3. 상담 기록에 상담자가 자유롭게 적은 장문의 문장이 있다. 문장마다 길이와 표현이 달라 고정된 열 목록만으로 내용을 충분히 나누기 어렵다. 이런 원문 텍스트는 비정형 자료의 사례다.
    4. JSON 문서 안에 상품명 키와 가격 키가 값과 함께 들어 있다. 다른 상품 문서에는 색상 키가 추가될 수도 있다. 키라는 구조 표시를 데이터와 함께 저장하므로 별도 구조 파일이 필수는 아니다.

    반정형 자료는 구조 표시가 내용과 함께 있으므로 정답은 4번이다.

    다음 릴레이션(relation) R과 S의 카티션 프로덕트(cartesian product) 연산 시 결과 릴레이션의 차수(degree)와 카디널리티(cardinality) 값은?

    R S 번호 이름 번호 나이 100 강감찬 100 82 200 이순신 101 53 300 한용운 102 66 차수 카디널리티

    1. 1. 3 6
    2. 2. 4 6
    3. 3. 3 9
    4. 4. 4 9

    정답 4번

    🔍 보기별 해설
    1. 카티션 프로덕트는 R의 열 2개와 S의 열 2개를 합치고 모든 행 쌍을 만든다. 차수 4, 카디널리티 9이므로 옳다(정답).
    🧮 풀이
    1. ① R에는 번호와 이름, S에는 번호와 나이 열이 있다. 결과 행에는 양쪽 열이 모두 들어간다.
    2. → 2+2=4열
    3. ↓
    4. ② R의 첫 행은 S의 세 행 각각과 짝을 이룬다. R의 둘째와 셋째 행도 같은 방식으로 각 세 조합을 만든다.
    5. → 3×3=9행
    6. ↓
    7. ③ 열의 개수는 차수, 행의 개수는 카디널리티로 읽는다. 같은 이름의 번호 열도 카티션 프로덕트에서는 양쪽 열로 센다.
    8. → 차수 4, 카디널리티 9

    두 릴레이션의 열은 2+2=4개, 행은 3×3=9개이므로 정답은 4번이다.

    트랜잭션에 대한 설명으로 옳지 않은 것은?

    1. 1. 커밋된 후에도 해당 트랜잭션은 롤백(rollback)을 사용하여 취소가 가능하다.
    2. 2. 현재 수행 중인 트랜잭션을 롤백하면 트랜잭션에서 SQL 문에 의해 수행된 모든 갱신이 취소(undo)된다.
    3. 3. 현재 수행 중인 트랜잭션을 커밋하면 트랜잭션이 수행한 갱신을 데이터베이스에 영구적으로 반영한다.
    4. 4. 트랜잭션은 데이터베이스 관리 시스템(database management system)에서 데이터를 다루는 논리적인 작업의 단위이다.

    정답 1번

    🔍 보기별 해설
    1. 커밋은 현재 거래의 변경을 확정한다. 확정 뒤 같은 거래를 ROLLBACK으로 되돌릴 수 있다는 설명은 옳지 않다(정답).
    2. 미완료 거래에 ROLLBACK을 실행하면 그 거래의 갱신을 취소한다. 이전 상태로 되돌리는 명령이므로 옳다.
    3. COMMIT은 현재 거래에서 성공한 갱신을 확정해 보존한다. 영구 반영의 의미와 맞으므로 옳다.
    4. 트랜잭션은 한 묶음으로 수행하고 확정·취소하는 논리적 작업 단위다. DBMS가 자료를 다루는 기본 단위이므로 옳다.
    🧮 풀이
    1. 직원이 재고 50개를 40개로 바꾸고 COMMIT을 실행한다. 뒤이어 같은 연결에서 ROLLBACK을 해도 이미 끝난 거래의 재고 40개는 돌아가지 않는다. 보상하려면 새 거래로 재고를 다시 수정해야 한다.
    2. 결제 중 주문 상태와 잔액을 바꾸었지만 아직 COMMIT하지 않았다. 오류를 발견해 ROLLBACK을 실행하면 두 갱신이 함께 취소된다. 결제 전 값으로 돌아가 미완료 거래가 남지 않는다.
    3. 관리자가 고객 주소를 고치고 COMMIT을 실행한다. 그 거래는 성공적으로 종료되고 변경 주소가 보존된다. 이후 장애가 발생해도 완료된 결과를 복구할 수 있어야 한다.
    4. 은행 이체는 보내는 계좌 차감과 받는 계좌 증가를 한 거래로 묶는다. 둘 다 성공하면 커밋하고 하나가 실패하면 전체를 취소한다. 이 묶음이 데이터베이스의 논리적 작업 단위다.

    커밋한 거래는 일반적인 ROLLBACK으로 취소할 수 없으므로 정답은 1번이다.

    ‘학생’ 테이블에 대한 검색 권한을 사용자 ‘홍길동’에게 부여하는 SQL 문을 완성할 때 (가)와 (나)에 들어갈 내용을 바르게 연결한 것은?

    (가) (나) ON 학생 TO 홍길동; (가) (나)

    1. 1. SELECT REVOKE
    2. 2. SELECT GRANT
    3. 3. GRANT SELECT
    4. 4. REVOKE SELECT

    정답 3번

    🔍 보기별 해설

    SQL에서 UNION과 UNION ALL에 대한 설명으로 옳은 것은?

    1. 1. UNION은 UNION ALL과 달리 ORDER BY 절을 자동으로 추가한다.
    2. 2. UNION은 UNION ALL보다 연산 결과 릴레이션의 속성 개수가 크다.
    3. 3. UNION은 중복된 투플을 제거하며, UNION ALL은 중복된 투플을 포함한다.
    4. 4. UNION은 두 릴레이션에서 서로 대응되는 속성의 도메인(domain)이 다를 때만 사용할 수 있다.

    정답 3번

    🔍 보기별 해설
    1. UNION은 결과의 중복 행을 없애지만 출력 순서를 자동 보장하지 않는다. ORDER BY가 자동 추가된다는 설명은 옳지 않다.
    2. UNION과 UNION ALL은 같은 수의 열을 맞춰 결합한다. 중복 처리 방식이 다를 뿐 결과 열 수가 달라지지 않으므로 옳지 않다.
    3. UNION은 같은 행을 한 번만 남기고 UNION ALL은 반복된 행도 모두 반환한다. 두 연산의 차이를 정확히 설명하므로 옳다(정답).
    4. UNION은 대응 열의 자료형이 서로 호환되어야 한다. 도메인이 다를 때만 쓸 수 있다는 설명은 옳지 않다.
    🧮 풀이
    1. 서울 지점과 부산 지점의 고객번호를 UNION으로 합쳤다. 중복 번호는 한 번만 남지만 결과가 고객번호 오름차순으로 나온다는 보장은 없다. 순서가 필요하면 별도로 ORDER BY를 지정한다.
    2. 두 SELECT가 각각 고객번호 한 열을 내면 UNION도 UNION ALL도 고객번호 한 열을 반환한다. ALL 여부가 중복 행 수를 바꾸어도 출력 열 개수는 늘지 않는다. 두 열과 한 열을 그대로 합칠 수는 없다.
    3. 서울 표에 고객번호 10과 20이 있고 부산 표에 20과 30이 있다. UNION 결과는 10·20·30 세 행이고 UNION ALL 결과는 10·20·20·30 네 행이다. 중복 번호 20의 처리에서 차이가 난다.
    4. 첫 질의가 정수 고객번호를 내고 둘째 질의도 호환되는 정수 번호를 내면 UNION으로 합칠 수 있다. 서로 다른 자료형만 허용하는 것이 아니다. 대응 열의 형식이 맞아야 결합된다.

    UNION은 중복을 제거하고 UNION ALL은 그대로 포함하므로 정답은 3번이다.

    3. ↓
    4. ② Dept가 컴퓨터공학이거나 Grade가 B인 행을 남긴다. 경영학 학생 이몽룡과 장보고의 성적은 C·A라 빠진다.

    1. 모순성은 한 거래가 다른 거래의 갱신 사이에서 서로 맞지 않는 값을 읽는 상황을 가리킬 수 있다. 이 일정의 핵심인 수정값 덮어쓰기를 설명하지 못하므로 옳지 않다.
    2. 갱신 분실은 두 거래가 옛 값을 각각 읽고 나중 쓰기가 먼저 쓰기를 덮는 현상이다. T1의 더하기 결과가 T2의 쓰기로 사라지므로 옳다(정답).
    3. 삽입 이상은 관계 설계의 중복 때문에 필요한 행을 독립적으로 넣지 못하는 문제다. 동시 거래의 같은 X 수정과 다르므로 옳지 않다.
    4. 연쇄 복귀는 미완료 거래의 값을 읽은 다른 거래까지 함께 취소해야 하는 상황이다. 여기에는 그런 읽기와 롤백이 없으므로 옳지 않다.
    🧮 풀이
    1. 한 거래가 재고 X를 읽는 사이 다른 거래도 재고를 읽는다. 서로 다른 시점의 값이 섞여 일관되지 않은 보고서가 나오는 문제를 모순성이라 부를 수 있다. 이 일정에서는 두 결과 중 하나가 마지막 쓰기로 사라지는 점이 핵심이다.
    2. X가 처음 100일 때 T1은 100을 읽어 200을 준비하고 T2도 옛 값 100을 읽어 200을 준비한다. T1이 200을 쓴 뒤 T2가 자기 결과 200을 다시 쓴다. T1의 +100이라는 별도 갱신 효과가 최종값에 누적되지 않는다.
    3. 강좌 테이블에 새 과목을 넣으려는데 담당 교수가 아직 정해지지 않아 행을 만들 수 없다. 여러 사실을 한 테이블에 묶은 설계에서 생기는 삽입 이상이다. 두 거래가 같은 X를 읽고 쓰는 이 시간표와 발생 원인이 다르다.
    4. T1이 커밋하지 않은 가격을 T2가 읽고 주문을 저장한 뒤 T1이 취소된다. T2의 주문도 함께 취소해야 한다면 연쇄 복귀다. 제시된 시간표에는 미완료 값을 읽고 취소하는 단계가 나타나지 않는다.

    T2의 마지막 쓰기가 T1의 수정값을 덮으므로 갱신 분실이 정답이다.

    참조 무결성 제약조건(referential integrity constraint)에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄴ. 외래키는 참조되는 테이블의 기본키 값이 삭제될 경우, 해당키를 외래키로 가지는 모든 투플을 삭제해야만 한다.

    ㄷ. 외래키 값은 참조되는 릴레이션의 후보키(candidate key) 값과 일치하거나 NULL이어야 한다.

    1. 1. ㄱ, ㄴ
    2. 2. ㄱ, ㄷ
    3. 3. ㄴ, ㄷ
    4. 4. ㄱ, ㄴ, ㄷ

    정답 2번

    🔍 보기별 해설
    1. 참조 무결성은 외래키로 이어진 두 릴레이션 사이의 일관성을 유지한다. 참조 대상이 존재하는지 확인하므로 옳다.
    2. 참조 대상 기본키가 삭제될 때는 삭제 제한, 연쇄 삭제, NULL 설정 같은 처리 정책이 가능하다. 참조 행을 반드시 전부 삭제해야 한다는 말은 옳지 않다.
    3. 외래키는 참조 대상의 후보키 값과 일치하거나 허용되는 경우 NULL일 수 있다. 존재하지 않는 값을 임의로 가리키지 않아야 하므로 옳다.
    🧮 풀이
    1. 주문 행의 고객번호 10이 고객 테이블의 실제 고객번호 10을 가리킨다. 고객 행을 찾을 수 없으면 주문이 존재하지 않는 고객을 참조하는 문제가 생긴다. 외래키 제약이 두 테이블의 연결을 지킨다.
    2. 고객번호 10을 삭제하려는데 그 고객의 주문이 남아 있다. 시스템은 삭제를 거부하거나 주문을 함께 삭제하거나 외래키를 NULL로 바꾸도록 설정할 수 있다. 무조건 주문을 모두 삭제하는 한 방식만 허용되지는 않는다.
    3. 주문에 고객번호 10을 적었다면 고객 표의 후보키에 10이 있어야 한다. 고객이 아직 정해지지 않은 주문에서는 제약이 허용할 때 NULL을 둘 수 있다. 존재하지 않는 99를 넣으면 참조 무결성을 어긴다.

    다음 정규화(normalization)에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄱ. 제1정규형에서는 릴레이션에 속한 모든 속성의 도메인이 원자값(atomic value)으로만 구성된다.

    ㄷ. 보이스－코드 정규형(BCNF)은 함수 종속의 모든 결정자가 후보키이다.

    ㄹ. 제2정규형 이상에서는 다치 종속(multi valued dependency)을 고려하지 않아도 된다.

    1. 1. ㄱ, ㄴ
    2. 2. ㄱ, ㄷ
    3. 3. ㄴ, ㄹ
    4. 4. ㄱ, ㄷ, ㄹ

    정답 2번

    🔍 보기별 해설
    1. 제1정규형은 릴레이션의 모든 속성의 도메인이 더는 나뉘지 않는 원자값으로만 구성되어야 하는 정규형이라고 정의되므로 이 설명은 옳다.
    2. 이행적 함수 종속을 제거하는 것은 제3정규형의 조건이고 제2정규형은 부분 함수 종속을 제거하는 정규형이므로 제2정규형에서 이행적 종속이 없다는 이 설명은 옳지 않다.
    3. 보이스-코드 정규형은 제3정규형보다 엄격하게 함수 종속 관계의 모든 결정자가 후보키가 되도록 요구하는 정규형으로 정의되므로 이 설명은 옳다.
    4. 다치 종속은 BCNF까지 만족한 뒤에도 남을 수 있어 제4정규형에서 다루므로, 제2정규형 이상에서는 고려하지 않아도 된다는 이 설명은 옳지 않다.
    🧮 풀이
    1. 甲은 표의 한 칸에 전화번호 두 개가 쉼표로 함께 들어 있는 것을 발견한 학생이다. 한 칸에는 하나의 값만 넣어야 한다는 원칙을 어겨 첫 단계 정규화를 다시 해야 했다. 같은 원리가 다른 문제에도 나오는지 찾아보았다.
    2. 甲은 이행적 종속이 남은 표를 제2정규형이라고 단정한 학생이다. 그 조건은 한 단계 위인 정규형의 것이라는 점을 조교가 짚어 주어 구분해 정리했다. 비슷한 예를 하나 더 만들어 스스로 확인해 보았다.
    3. 甲은 모든 결정자가 후보키인지 하나씩 점검하는 실습을 한 학생이다. 후보키가 아닌 결정자가 하나라도 있으면 보이스-코드 정규형이 아니라는 점을 확인했다. 헷갈릴 때는 정의로 돌아가는 것이 가장 빠르다고 느꼈다.
    4. 甲은 한 사원이 여러 자격증과 여러 취미를 갖는 표를 다루며 서로 독립된 다치 값이 섞이는 문제를 발견한 학생이다. 이런 문제는 더 높은 정규형에서 다룬다는 점을 알았다. 이 구분을 나중에 볼 노트에도 한 줄로 옮겨 적었다.

    ㄱ과 ㄷ은 옳고 ㄴ은 이행적 종속 제거가 제3정규형의 조건이며 ㄹ은 다치 종속을 제4정규형에서 다루므로 정답은 2번이다.

    4. 4. 데이터에서 수정, 삭제 등의 변경이 발생하면 인덱스를 재구성할 수 있다.

    🔍 보기별 해설
    1. 인덱스는 테이블의 열 하나 또는 여러 열을 검색키로 삼아 만들 수 있다. 생성 방식에 맞으므로 옳다.
    2. 인덱스는 검색키에서 자료 위치로 가는 경로를 제공한다. 필요한 레코드에 효율적으로 접근하므로 옳다.
    3. 희소 인덱스는 데이터 파일이 키 순서로 정렬된 클러스터링 구조에서 사용할 수 있다. 사용할 수 없다는 설명은 옳지 않다(정답).

    🧮 풀이
    1. 도서 테이블에서 도서번호 한 열로 인덱스를 만들고 저자명과 출판사 두 열의 조합으로도 인덱스를 만든다. 질의가 쓰는 검색 조건에 맞춰 키 열을 고른다. 한 열만 허용되는 구조는 아니다.

    희소 인덱스는 정렬된 파일의 클러스터링 인덱스에 사용할 수 있으므로 정답은 3번이다.

    1. 1. SERIALIZABLE
    2. 2. READ COMMITTED
    3. 3. REPEATABLE READ
    4. 4. READ UNCOMMITTED

    정답 3번

    🔍 보기별 해설
    1. SERIALIZABLE은 가장 높은 고립도로 반복 불가 읽기를 막을 수 있다. 그러나 발문이 묻는 최저 등급은 아니므로 옳지 않다.
    2. READ COMMITTED는 미커밋 값 읽기를 막지만 같은 행을 두 번 읽는 동안 값이 바뀔 수 있다. 반복 불가 읽기를 막는 수준이 아니므로 옳지 않다.
    3. REPEATABLE READ는 같은 행을 거래 안에서 다시 읽어도 값이 달라지지 않게 한다. 필요한 최저 고립도이므로 옳다(정답).

    🧮 풀이
    1. T1이 x=10을 읽고 T2가 x를 20으로 바꾼 뒤 T1이 다시 읽으려 한다. SERIALIZABLE은 이 순서를 직렬 실행과 같은 결과가 되게 제한할 수 있다. 다만 같은 행의 반복 읽기만 보호하려면 그보다 낮은 등급이 있다.
    2. T1이 커밋된 x=10을 읽는다. T2가 x=20을 커밋하면 T1의 다음 SELECT가 20을 볼 수 있다. READ COMMITTED는 더러운 읽기는 막아도 같은 행의 값 변화를 막지는 않는다.
    3. T1이 x=10을 읽고 거래를 끝내기 전에 같은 행을 다시 읽는다. 다른 거래가 그 사이 x를 바꾸려 해도 T1은 같은 값을 유지하도록 격리한다. 반복 불가 읽기를 막는 수준이 REPEATABLE READ다.
    4. T2가 x를 20으로 고치고 아직 커밋하지 않았다. READ UNCOMMITTED의 T1은 이 값을 읽었다가 T2가 취소하면 뒤에 다시 10을 볼 수도 있다. 문제의 반복 값 변화는 물론 미완료 값 읽기까지 허용된다.

    3. 문서 소유자 丙이 동료에게 자신의 표에 대한 SELECT 권한을 준다. 동료는 허용된 범위에서만 자료를 읽는다. 객체 소유자의 권한 부여에 따라 접근이 정해지는 임의 접근제어 사례다.
    4. 사용자 甲이 CREATE TABLE 주문을 실행한다. 甲은 자기가 만든 주문 릴레이션의 구조와 접근 권한을 관리할 수 있다. 소유자가 아무 권한도 자동으로 얻지 못한다는 보기는 실제 소유자 권한과 어긋난다.

    릴레이션 생성자는 자기 객체를 관리할 권한을 자동으로 받으므로 정답은 4번이다.

    다음 에서 교착상태 예방 방법별 동작에 대한 설명으로 옳지 않은 것은?

    트랜잭션 T 에 대한 타임스탬프 TS( T )는 트랜잭션의 시작 시각을 표현하며, TS( T_j ) < TS( T_i )는 T_j 가 T_i 보다 먼저 작업을 시작했다는 의미이다. 트랜잭션 T_j 가 항목 x에 대해 배타 로크(exclusive lock)를 획득하였으며, 트랜잭션 T_i 가 항목 x에 대해 배타 로크를 획득하고자 한다.

    1. 1. TS( T_i ) < TS( T_j )일 때, wound-wait 기법에서 T_j 는 철회하고 동일 타임스탬프를 사용하여 재시작한다.
    2. 2. TS( T_j ) < TS( T_i )일 때, wound-wait 기법에서 T_j 는 대기한다.
    3. 3. TS( T_j ) < TS( T_i )일 때, wait-die 기법에서 T_i 는 철회하고 동일 타임스탬프를 사용하여 재시작한다.
    4. 4. TS( T_i ) < TS( T_j )일 때, wait-die 기법에서 T_i 는 대기한다.

    정답 2번

    🔍 보기별 해설
    1. Ti가 Tj보다 오래되었으면 wound-wait에서 Ti가 젊은 보유자 Tj를 중단시킨다. Tj는 같은 타임스탬프로 재시작하므로 옳다.
    2. Tj가 Ti보다 오래되었으면 젊은 요청자 Ti가 기다린다. 로크 보유자 Tj가 대기한다는 설명은 옳지 않다(정답).
    3. wait-die에서 젊은 요청자 Ti가 오래된 보유자 Tj의 로크를 원하면 Ti를 철회한다. 원래 타임스탬프로 재시작하므로 옳다.
    4. wait-die에서 오래된 요청자 Ti는 젊은 보유자 Tj의 로크를 기다린다. 나이가 많은 쪽이 대기하는 규칙과 맞으므로 옳다.
    🧮 풀이
    1. Ti가 먼저 시작해 타임스탬프가 작고 Tj가 나중에 x의 로크를 잡았다. Ti가 x를 요청하면 wound-wait가 Tj를 중단시켜 로크를 놓게 한다. Tj는 재시작해도 원래 타임스탬프를 유지한다.
    2. Tj가 먼저 시작해 x를 잠근 뒤 젊은 Ti가 x의 로크를 요청한다. wound-wait에서는 Ti가 Tj의 종료를 기다린다. 이미 로크를 가진 오래된 Tj를 대기시킨다는 보기는 두 거래의 역할을 바꿨다.
    3. 오래된 Tj가 x를 잠근 상태에서 나중에 시작한 Ti가 같은 로크를 원한다. wait-die는 젊은 Ti가 기다리지 않고 철회되게 한다. Ti는 재시작할 때 같은 타임스탬프를 사용한다.
    4. Ti가 먼저 시작했고 나중에 시작한 Tj가 x를 잠갔다. wait-die에서 오래된 요청자인 Ti는 로크가 풀릴 때까지 기다릴 수 있다. 젊은 Tj를 기다리는 쪽이 Ti라는 나이 규칙과 맞는다.

    wound-wait에서 젊은 요청자 Ti는 오래된 보유자 Tj를 기다리므로 정답은 2번이다.

    비트맵 인덱스에 대한 설명으로 옳지 않은 것은?

    1. 1. 한 가지 특정 속성값에 대해 하나의 비트맵 인덱스가 만들어진다.
    2. 2. 릴레이션의 카디널리티가 n 일 경우, 비트맵 인덱스의 크기는 log_2 n 비트이다.
    3. 3. 탐색 키의 중복 비율이 높은 속성을 대상으로 수행되는 질의에 효율적이다.
    4. 4. 다중 키를 가진 질의를 쉽게 처리하기 위해 고안된 특수한 형태의 인덱스이다.

    정답 2번

    🔍 보기별 해설
    1. 비트맵 인덱스는 각 속성값에 대응하는 비트열을 만든다. 값마다 한 비트맵을 둔다는 설명은 옳다.
    2. 비트맵의 각 비트는 릴레이션의 한 레코드에 대응한다. 레코드가 n개면 길이는 n비트여서 log₂n비트라는 말은 옳지 않다(정답).
    3. 중복 값이 많은 열에서는 같은 값의 행을 비트열 하나로 표시할 수 있다. 이런 열의 질의에 효율적이므로 옳다.
    4. 여러 속성의 비트열을 AND·OR로 결합하면 다중 키 조건을 처리하기 쉽다. 비트맵 인덱스의 활용 설명이므로 옳다.
    🧮 풀이
    1. 성별 열에 남성·여성 두 값이 있으면 각 값에 비트열을 하나씩 둔다. 남성 비트열은 남성 행의 위치에 1을, 여성 비트열은 여성 행의 위치에 1을 적는다. 값마다 별도 표시가 생긴다.
    2. 학생 레코드가 8개라면 ‘성적 A’ 비트열에는 여덟 자리의 0 또는 1이 필요하다. log₂8은 3이지만 3비트로는 어느 여덟 행이 A인지 모두 표시할 수 없다. 한 레코드마다 한 비트가 대응한다.
    3. 직원 10만 명의 상태 열이 재직·휴직·퇴직 세 값만 가진다. ‘재직’ 비트열의 1인 자리를 빠르게 찾으면 해당 직원 행을 고를 수 있다. 값 종류가 적고 반복이 많을 때 유리하다.
    4. ‘서울 지점’ 비트열과 ‘재직’ 비트열을 준비한다. 같은 행 위치에서 두 비트가 모두 1인지 AND 연산하면 서울 지점의 재직 직원만 남는다. 두 검색 키를 비트 연산으로 함께 처리한다.

    비트맵 한 개의 길이는 레코드 수 n비트이므로 정답은 2번이다.
