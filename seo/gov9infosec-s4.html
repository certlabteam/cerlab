    네트워크 명령어에 대한 설명으로 옳지 않은 것은?

    1. 1. hostname: 컴퓨터 이름을 확인한다.
    2. 2. nslookup: DNS를 통해 도메인 이름을 검색한다.
    3. 3. ipconfig: 인터페이스에 설정된 라우팅 테이블을 검색한다.
    4. 4. ping: 컴퓨터의 네트워크 상태를 점검한다.

    정답 3번

    🔍 보기별 해설
    1. hostname은 현재 시스템에 설정된 호스트 이름, 즉 컴퓨터 이름을 화면에 표시하는 명령이므로 장비의 이름을 확인한다는 설명은 옳다.
    2. nslookup은 DNS 서버에 질의하여 도메인 이름에 대응하는 IP 주소나 관련 DNS 레코드를 조회하는 명령이므로 이 설명은 옳다.
    3. ipconfig는 IP 주소·서브넷 마스크·기본 게이트웨이 등을 확인하며, 라우팅 테이블 조회는 route print가 담당하므로 옳지 않다(정답).
    4. ping은 ICMP Echo Request와 Reply를 이용하여 상대 호스트의 도달 가능 여부와 응답 시간을 확인해 네트워크 상태를 점검하므로 옳다.
    🧮 풀이
    1. 甲이 여러 서버 중 현재 원격 접속한 장비가 어느 것인지 확인하려고 명령창에서 hostname을 실행하자, 화면에 WEB-SERVER-01이라는 컴퓨터 이름이 표시되어 작업 대상을 바로 확인했다.
    2. 甲이 회사 홈페이지의 도메인이 어느 IP 주소와 연결되어 있는지 알아보려고 nslookup을 실행하자, 지정된 DNS 서버가 질의에 응답하며 해당 도메인의 IP 주소를 화면에 표시했다.
    3. 甲이 PC에서 ipconfig를 실행하자 현재 IP 주소와 서브넷 마스크, 기본 게이트웨이는 나타났지만 목적지별 경로가 담긴 라우팅 테이블은 보이지 않아 route print를 다시 실행했다.
    4. 甲이 사무실 PC에서 외부 서버까지 통신이 되는지 확인하려고 ping을 실행하자, 서버에서 ICMP 응답이 돌아오고 각 패킷의 왕복 시간이 차례대로 화면에 표시됐다.

    hostname은 이름, nslookup은 DNS 조회, ipconfig는 인터페이스 설정, ping은 연결 상태를 확인하며 라우팅 테이블 조회는 route print가 담당한다.

    다음에서 설명하는 네트워크 도구는?

    ○ IP 헤더에 있는 TTL의 특성을 이용한다.

    ○ TTL 값은 IP 패킷이 전송될 수 있는 최대 hop 수이다.

    ○ 최종 목적지까지의 라우터에 대한 경로 및 응답속도를 표시해 준다.

    ○ 특정 사이트와의 접속이 느릴 경우 네트워크의 어느 구간에서 느린지 확인할 수 있다.

    1. 1. wireshark
    2. 2. tcpdump
    3. 3. traceroute
    4. 4. netstat

    정답 3번

    🔍 보기별 해설
    1. 와이어샤크는 지나가는 패킷을 포착해 프로토콜별 내용을 분석하는 도구이므로, 홉별 경로를 추적하는 도구라는 설명은 옳지 않다.
    2. 티시피덤프는 명령행에서 네트워크 패킷을 수집하고 내용을 확인하는 도구이므로, 목적지까지의 경로를 조사하는 도구라는 설명은 옳지 않다.
    3. 트레이스라우트는 생존시간을 단계적으로 늘려 각 라우터의 시간초과 응답을 받아 목적지까지 경로와 지연을 파악하므로 옳다(정답).
    4. 넷스탯은 연결 상태와 포트, 라우팅 정보, 프로토콜 통계 등을 확인하는 명령이므로, 홉마다 경로와 응답시간을 추적하는 도구라는 설명은 옳지 않다.
    🧮 풀이
    1. 甲이 사내망에서 오가는 패킷을 와이어샤크로 포착한 뒤 출발지와 목적지 주소, 프로토콜, 데이터 내용을 차례로 펼쳐 보았다. 특정 패킷을 골라 세부 필드까지 확인하고 분석 결과를 기록했다.
    2. 甲이 리눅스 서버의 터미널에서 티시피덤프를 실행하고 특정 네트워크 인터페이스를 지나는 패킷만 골라 수집했다. 이어 주소와 포트 조건을 지정해 필요한 통신 기록을 화면에서 확인했다.
    3. 甲이 해외 서버 접속이 유난히 느려 트레이스라우트를 실행했다. 화면에 차례로 나타난 중간 라우터와 왕복시간을 살펴보다 특정 홉부터 응답시간이 크게 늘어난 구간을 찾아냈다.
    4. 甲이 윈도 서버에서 넷스탯을 실행해 현재 열려 있는 연결과 대기 중인 포트를 살펴보았다. 이어 라우팅 정보와 프로토콜 통계를 확인하며 서버의 네트워크 상태를 점검했다.

    생존시간을 이용해 목적지까지 거치는 라우터와 각 구간의 응답시간을 추적하는 도구는 트레이스라우트이다.

    비대칭키 암호화 알고리즘에서 수신자의 공개키로 데이터를 암호화하여 전송할 때 얻을 수 있는 보안성은?

    1. 1. 가용성
    2. 2. 인증
    3. 3. 부인방지
    4. 4. 기밀성

    정답 4번

    🔍 보기별 해설
    1. 가용성은 인가된 사용자가 필요할 때 정보와 서비스를 이용할 수 있도록 보장하는 성질이며, 수신자의 공개키로 데이터를 암호화한다고 확보되는 것은 아니므로 옳지 않다.
    2. 인증은 상대방의 신원이나 메시지 출처가 올바른지 확인하는 성질이며, 누구나 사용할 수 있는 수신자의 공개키로 암호화하는 것만으로는 얻을 수 없으므로 옳지 않다.
    3. 부인방지는 송신자가 자신의 송신 행위를 나중에 부인하지 못하게 하는 성질로 송신자의 전자서명과 관련되며, 수신자 공개키 암호화로는 얻을 수 없으므로 옳지 않다.
    4. 수신자의 공개키로 암호화한 데이터는 대응하는 수신자의 개인키로만 복호화할 수 있어 제3자에게 내용을 숨기는 기밀성을 얻으므로 옳다(정답).
    🧮 풀이
    1. 甲이 중요한 업무 파일을 수신자의 공개키로 암호화해 서버에 저장했지만 정전으로 서버 자체가 멈추자, 권한 있는 직원도 필요한 순간에 파일과 서비스를 전혀 이용하지 못했다.
    2. 甲이 乙의 공개키로 문서를 암호화해 乙에게 보냈지만 그 공개키는 누구나 이용할 수 있었으므로, 乙은 문서를 복호화할 수 있어도 실제 송신자가 甲인지는 암호화만으로 확인하지 못했다.
    3. 甲이 乙의 공개키로 계약서를 암호화해 전달한 뒤 자신이 보낸 적이 없다고 주장하자, 전자서명을 받아 두지 않은 乙은 공개키 암호화 기록만으로는 甲의 송신 행위를 입증하지 못했다.
    4. 甲이 乙에게 기밀 보고서를 보내면서 乙의 공개키로 암호화하자 전송 중 암호문을 가로챈 丙은 내용을 읽지 못했고, 대응하는 개인키를 가진 乙만 원래 보고서를 복호화했다.

    수신자의 공개키로 암호화하면 대응하는 수신자의 개인키로만 복호화할 수 있으므로 기밀성을 확보한다.

    TCP 포트의 개방 여부를 확인하기 위한 스텔스 스캔으로 옳지 않은 것은?

    1. 1. FIN 스캔
    2. 2. NULL 스캔
    3. 3. XMAS 스캔
    4. 4. TCP Open 스캔

    정답 4번

    🔍 보기별 해설
    1. FIN 스캔은 TCP 연결을 완성하지 않고 FIN 플래그만 설정한 패킷의 응답 차이로 포트 개방 여부를 추정하는 대표적인 스텔스 스캔이므로 옳다.
    2. NULL 스캔은 TCP 헤더의 플래그를 모두 설정하지 않은 패킷을 보내 응답 여부를 바탕으로 포트의 개방 상태를 추정하는 스텔스 스캔이므로 옳다.
    3. XMAS 스캔은 FIN·PSH·URG 플래그를 동시에 설정한 비정상 패킷을 보내 응답 차이로 포트 상태를 추정하는 스텔스 스캔이므로 옳다.
    4. TCP Open 스캔은 SYN·SYN/ACK·ACK의 3-way handshake를 끝까지 수행해 정상 연결을 완성하므로 스텔스 스캔이 아니므로 옳지 않다(정답).
    🧮 풀이
    1. 甲이 실습 서버의 포트 상태를 조사하면서 정상적인 연결 요청 대신 FIN 플래그만 설정한 패킷을 보내자, 닫힌 포트에서는 RST가 돌아오고 열린 포트에서는 별다른 응답이 없었다.
    2. 甲이 방화벽 뒤 서버의 포트를 조용히 조사하려고 TCP 플래그를 하나도 켜지 않은 패킷을 전송하자, 닫힌 포트에서는 RST가 돌아왔지만 열린 포트에서는 응답이 나타나지 않았다.
    3. 甲이 시험용 서버에 FIN·PSH·URG 플래그를 한꺼번에 설정한 TCP 패킷을 보내자, 닫힌 포트가 RST로 응답하고 열린 포트는 응답하지 않아 그 차이로 상태를 추정했다.
    4. 甲이 서버의 80번 포트에 TCP Open 스캔을 수행하자 SYN을 보낸 뒤 SYN/ACK를 받고 다시 ACK를 보내 연결을 완성했으며, 서버에는 정상적인 TCP 연결 기록까지 남았다.

    FIN·NULL·XMAS는 연결을 완성하지 않는 스텔스 스캔이지만 TCP Open 스캔은 3-way handshake를 완성한다.

    스위치 재밍(switch jamming)에 대한 설명으로 옳은 것은?

    1. 1. 스위치 MAC 테이블의 저장 용량을 넘으면 더미 허브(dummy hub)처럼 브로드캐스트(broadcast) 한다.
    2. 2. 방어대책은 게이트웨이 MAC 주소를 동적으로 설정한다.
    3. 3. 공격자는 클라이언트가 DNS 서버로 전송하는 DNS Query 패킷을 중간에 가로챈다.
    4. 4. MAC flooding은 스위치에 이상이 있을 때 자동으로 모든 보안 기능을 차단하는 것이다.

    정답 1번

    🔍 보기별 해설
    1. 스위치 재밍으로 MAC 테이블의 저장 한계를 넘기면 미등록 목적지 프레임을 여러 포트로 플러딩하여 더미 허브와 비슷하게 동작하므로 옳다(정답).
    2. 스위치 재밍은 MAC 테이블을 고갈시키는 공격이므로 포트별 MAC 주소 수를 제한하는 포트 보안이 대책이며, 게이트웨이 MAC의 동적 설정은 대책이 아니므로 옳지 않다.
    3. DNS Query를 중간에서 가로채 거짓 응답 등으로 조작하는 것은 DNS 관련 공격에 해당하며, MAC 테이블을 고갈시키는 스위치 재밍의 설명이 아니므로 옳지 않다.
    4. MAC flooding은 다수의 위조 MAC 주소를 스위치에 보내 MAC 테이블을 가득 채우는 공격이며, 보안 기능을 자동으로 차단하는 기능이 아니므로 옳지 않다.
    🧮 풀이
    1. 甲이 실습용 스위치에 출발지 MAC 주소를 계속 바꾼 프레임을 대량으로 보내 MAC 테이블을 가득 채우자, 스위치가 목적지를 찾지 못한 프레임을 여러 포트로 플러딩하기 시작했다.
    2. 甲이 스위치 재밍을 막으려고 각 액세스 포트에서 학습할 수 있는 MAC 주소 수를 제한하고, 허용 범위를 넘는 새로운 주소가 나타나면 해당 포트를 차단하도록 설정했다.
    3. 甲이 클라이언트가 DNS 서버로 보내는 Query를 중간에서 가로챈 뒤 진짜 서버보다 먼저 위조된 DNS 응답을 돌려보내자, 클라이언트는 공격자가 지정한 엉뚱한 IP 주소로 접속했다.
    4. 甲이 출발지 MAC 주소를 계속 바꾸어 만든 수많은 프레임을 실습 스위치로 전송하자, MAC 테이블에 가짜 주소가 빠르게 쌓여 정상 단말의 주소를 새로 저장할 공간이 부족해졌다.

    스위치 재밍은 MAC flooding으로 MAC 테이블을 고갈시켜 미등록 목적지 프레임이 여러 포트로 플러딩되도록 만드는 공격이다.

    윈도시스템에서 다음과 같이 이더넷 인터페이스의 송수신 패킷 정보를 얻기 위한 netstat 명령어의 옵션은?

    인터페이스 통계 받음 보냄 바이트 3879974308 172124956 유니캐스트 패킷 1098604 985784 비유니캐스트 패킷 11306144 94056 버림 0 0 오류 0 0 알 수 없는 프로토콜 0

    1. 1. netstat -an
    2. 2. netstat -e
    3. 3. netstat -r
    4. 4. netstat -s

    정답 2번

    🔍 보기별 해설
    1. -an은 모든 연결과 수신 대기 포트를 주소와 포트 번호를 숫자 형식으로 표시하는 선택지이므로, 이더넷 송수신 통계를 출력하는 옵션이라는 설명은 옳지 않다.
    2. -e는 이더넷 인터페이스에서 오간 바이트와 유니캐스트·비유니캐스트 패킷, 오류 등의 통계를 보여 주는 옵션이므로 옳다(정답).

    SSL 프로토콜에 대한 설명으로 옳은 것은?

    1. 1. ChangeCipherSpec 프로토콜은 오류와 비정상 상태를 알기 위해 사용한다.
    2. 2. Handshake 프로토콜은 대기와 활성 상태 사이에서 이동되는 값들의 처리 과정을 규정한다.
    3. 3. Record 프로토콜은 기밀성과 메시지 무결성을 제공한다.
    4. 4. Alert 프로토콜은 암호 그룹 협의와 클라이언트와 서버 간 인증 정보를 교환하기 위해 사용한다.

    정답 3번

    🔍 보기별 해설
    1. ChangeCipherSpec은 협상된 암호 명세를 현재 연결에 적용하도록 알리며, 오류와 비정상 상태를 알리는 것은 Alert이므로 옳지 않다.
    2. Handshake는 암호 알고리즘 협상과 인증·키 교환을 담당하며, 대기 상태와 활성 상태 사이의 암호 명세 전환을 담당하는 것은 아니므로 옳지 않다.
    3. Record 프로토콜은 데이터를 단편화한 뒤 MAC과 암호화 등을 적용하여 전송함으로써 기밀성과 메시지 무결성을 함께 제공하므로 옳다(정답).
    4. Alert는 오류나 연결 종료 등의 상태를 알리며, 암호 그룹 협의와 클라이언트·서버 간 인증 정보 교환은 Handshake가 담당하므로 옳지 않다.
    🧮 풀이
    1. 甲이 SSL 연결에서 서버와 암호 알고리즘과 키를 협상한 뒤 ChangeCipherSpec 메시지를 보내자, 이후부터 새로 합의한 암호 명세가 현재 연결의 통신에 적용되기 시작했다.
    2. 甲이 웹서버에 SSL 연결을 시작하자 클라이언트와 서버가 Handshake 메시지를 주고받으며 사용할 암호 알고리즘을 고르고 인증서를 확인한 뒤 세션에서 사용할 키 정보를 마련했다.
    3. 甲이 SSL로 중요한 데이터를 전송하자 Record 계층에서 데이터를 조각내고 무결성 확인값을 붙인 뒤 암호화했으며, 수신 측은 이를 복호화해 데이터의 변조 여부까지 확인했다.
    4. 甲이 SSL 통신 중 상대가 보낸 인증서에 문제가 생기자 Alert 메시지가 전달되어 오류 상태가 통보됐고, 연결을 정상적으로 끝낼 때에도 종료를 알리는 메시지가 교환됐다.

    SSL에서 Handshake는 협상·인증, ChangeCipherSpec은 암호 명세 적용, Alert는 상태 통보, Record는 기밀성과 무결성을 담당한다.

    TLS에 대한 설명으로 옳지 않은 것은?

    1. 1. TLS는 SSL을 기반으로 만들어진 인터넷 표준이다.
    2. 2. TLS의 의사난수 함수(pseudorandom function)는 데이터 확장 함수(data-expansion function)를 활용한다.
    3. 3. TLS의 의사난수 함수는 비밀(secret), 식별용 라벨(label), 종자(seed)를 입력받는다.
    4. 4. TLS의 마스터 비밀(master secret) 생성을 위해 데이터 확장 함수는 사전 마스터 비밀(pre-master secret), ‘master secret’ 문자, 2개의 임의의 수를 입력받는다.

    정답 4번

    🔍 보기별 해설
    1. TLS는 SSL을 토대로 표준화되어 SSL의 보안 통신 구조를 계승하고 개선한 인터넷 표준 프로토콜이므로, SSL을 기반으로 했다는 설명은 옳다.
    2. TLS의 의사난수 함수는 비밀값과 종자에서 필요한 길이의 키 재료를 생성하기 위해 반복적인 데이터 확장 함수인 P_hash를 활용하므로 옳다.
    3. TLS의 의사난수 함수는 비밀값 secret과 용도를 구별하는 label, 난수 등이 결합된 seed를 입력받아 필요한 키 재료를 생성하므로 옳다.
    4. master secret은 PRF에 pre-master secret과 라벨·두 난수를 넣어 생성하며, 이를 데이터 확장 함수 자체의 입력이라고 한 것이 틀리므로 옳지 않다(정답).
    🧮 풀이
    1. 甲이 기존 SSL 기반 보안 통신을 검토하다 국제 표준으로 정비된 TLS를 적용하자, SSL에서 이어진 핸드셰이크와 레코드 계층 구조를 바탕으로 클라이언트와 서버가 암호화 통신을 시작했다.
    2. 甲이 TLS 세션에서 여러 암호키를 만들기 위한 값을 계산하자, 의사난수 함수 내부의 P_hash가 해시 기반 연산을 반복하면서 필요한 길이만큼 키 생성용 데이터를 계속 확장해 냈다.
    3. 甲이 TLS 의사난수 함수에 공유된 secret과 용도를 나타내는 label, 핸드셰이크에서 얻은 난수를 seed로 넣자 세션에서 사용할 키 재료가 정해진 길이만큼 생성됐다.
    4. 甲이 TLS의 master secret을 계산하면서 pre-master secret을 비밀값으로 두고 ‘master secret’을 라벨로 사용한 뒤 두 난수를 seed로 결합하여 PRF에 입력해 48바이트 값을 얻었다.

    TLS의 master secret은 pre-master secret과 라벨·난수를 PRF에 넣어 생성하며, PRF와 그 내부 데이터 확장 함수를 구별해야 한다.

    공격자가 TCP 세션 하이재킹(session hijacking)을 위해 대상 호스트에 첫 번째로 보내는 TCP 패킷 플래그(flag)는?

    1. 1. RST
    2. 2. FIN
    3. 3. ACK
    4. 4. SYN

    정답 1번

    🔍 보기별 해설
    1. TCP 세션 하이재킹에서는 기존 클라이언트의 연결을 끊고 공격자가 세션을 넘겨받기 위해 먼저 RST 패킷을 대상 호스트에 보내므로 옳다(정답).
    2. FIN은 정상적인 TCP 연결 종료 과정에서 한쪽이 더 보낼 데이터가 없음을 알리는 플래그이며, 세션 하이재킹의 첫 단계에 사용하는 플래그는 아니므로 옳지 않다.
    3. ACK는 수신한 TCP 세그먼트와 순서번호에 대한 확인응답을 나타내는 플래그이며, 대상의 기존 세션을 먼저 끊기 위해 보내는 플래그는 아니므로 옳지 않다.
    4. SYN은 새로운 TCP 연결을 시작하면서 초기 순서번호를 동기화할 때 사용하는 플래그이며, 이미 형성된 세션을 탈취하는 첫 패킷은 아니므로 옳지 않다.
    🧮 풀이
    1. 甲이 이미 통신 중인 클라이언트와 서버의 TCP 세션을 탈취하려고 먼저 위조한 RST 패킷을 클라이언트에 보내자 기존 연결이 강제로 끊겼고, 이어서 공격자가 세션을 가로챌 준비를 했다.
    2. 甲이 파일 전송을 모두 마친 뒤 TCP 연결을 정상적으로 종료하려고 FIN 플래그가 설정된 세그먼트를 乙에게 보내자, 乙은 ACK로 응답하고 자신도 FIN을 보내 연결 종료 절차를 진행했다.
    3. 甲이 서버로부터 TCP 데이터를 정상적으로 받은 뒤 다음에 받을 순서번호를 담은 ACK 세그먼트를 보내자, 서버는 해당 데이터가 제대로 도착했음을 확인하고 이어지는 데이터를 계속 전송했다.
    4. 甲이 웹서버와 새로운 TCP 연결을 만들려고 SYN 플래그와 자신의 초기 순서번호를 담은 세그먼트를 보내자, 서버가 SYN/ACK로 응답하면서 3-way handshake가 시작됐다.

    TCP 세션 하이재킹에서는 먼저 RST로 기존 연결을 끊는 과정이 사용되며 FIN·ACK·SYN은 각각 정상 종료·확인응답·연결 시작에 쓰인다.

    1. HTTPS에서는 TLS가 HTTP 요청 내용을 암호화하므로 요청 경로가 포함된 URL 정보도 암호화되며, 네트워크에서 그대로 드러나지 않으므로 옳지 않다.
    2. HTTPS는 TLS로 HTTP 메시지를 보호하므로 서버가 보내는 문서 본문도 암호화되며, 중간에서 패킷을 수집해도 평문 내용을 읽기 어려우므로 옳지 않다.
    3. HTTPS의 TCP 포트 번호는 TLS 암호화가 적용되는 페이로드 바깥의 TCP 헤더에 있으므로 네트워크에서 확인할 수 있어 옳다(정답).
    4. HTTP 헤더는 TLS로 보호되는 HTTP 메시지 내부에 포함되므로 HTTPS 통신에서는 암호화되며, 패킷에서 평문으로 노출되지 않으므로 옳지 않다.
    🧮 풀이
    1. 甲이 HTTPS 사이트에서 비공개 문서의 경로가 포함된 URL을 요청한 뒤 패킷을 캡처해 보자, TLS로 보호된 요청 내부의 경로는 암호문으로 보여 중간에서는 그대로 읽을 수 없었다.
    2. 甲이 HTTPS로 급여 명세서를 내려받는 동안 통신 패킷을 별도 장비에서 수집해 살펴보자, 문서 본문은 TLS 암호문으로 전달되어 급여와 개인정보 내용을 평문으로 확인할 수 없었다.
    3. 甲이 HTTPS 웹사이트에 접속한 트래픽을 패킷 분석기로 살펴보자 HTTP 내용은 암호화되어 있었지만, TCP 헤더의 목적지 포트가 443번이라는 사실은 화면에서 그대로 확인할 수 있었다.
    4. 甲이 HTTPS 요청에 쿠키와 User-Agent 등 여러 HTTP 헤더를 넣어 서버로 전송한 뒤 중간 패킷을 확인하자, 헤더 내용은 TLS 레코드 안에서 암호화되어 평문으로 나타나지 않았다.

    HTTPS는 URL 경로·문서 내용·HTTP 헤더를 암호화하지만 TCP 헤더에 있는 포트 번호는 암호화하지 않는다.

    스니핑(sniffing) 공격에 대한 설명으로 옳은 것은?

    🔍 보기별 해설

    2. 네트워크 장비에 처리할 수 없을 정도의 대량 트래픽을 보내 서비스를 중단시키는 것은 DoS 공격이며, 데이터를 도청하는 스니핑은 아니므로 옳지 않다.

    IPv4 데이터그램 형식에 대한 설명으로 옳지 않은 것은?

    1. 甲이 회사 포털에 한 번 로그인한 뒤 별도의 암호 입력 없이 전자결재와 인사 시스템을 차례로 열었다. 처음 받은 인증 결과가 여러 서비스에서 이어져 재인증 절차가 생략되었다.
    2. 甲이 한 대의 스위치에 연결된 회계팀과 개발팀 컴퓨터를 서로 다른 VLAN(가상 근거리 통신망)으로 나누었다. 같은 스위치를 쓰지만 두 집단의 브로드캐스트 영역은 논리적으로 분리되었다.
    3. 甲이 고객 주민번호가 담긴 문서를 외부 메일로 보내려 하자 DLP(데이터 유출 방지) 프로그램이 민감정보를 찾아 전송을 막았다. 관리 화면에는 차단 사유와 사용자 정보가 기록되었다.
    4. 甲이 외부에서 회사 서버로 들어오는 통신 중 허가된 웹 접속만 통과시키도록 방화벽 규칙을 만들었다. 금지된 포트로 들어온 패킷은 차단되고 허용된 요청만 내부로 전달되었다.

    미리 정한 규칙에 따라 통신을 허용하거나 차단하고 패킷 필터링과 프록시 방식 등을 사용하는 보안 기술은 방화벽이다.

    다음에 기술된 IEEE 802.11i RSN의 동작 단계를 순서대로 나열한 것은?

    (가) 인증(authentication) (나) 탐색(discovery) (다) 안전 데이터 전송(protected data transfer) (라) 키 생성 및 분배(key generation and distribution)

    1. 1. (가) → (나) → (다) → (라)
    2. 2. (가) → (나) → (라) → (다)
    3. 3. (나) → (가) → (라) → (다)
    4. 4. (나) → (라) → (가) → (다)

    정답 3번

    🔍 보기별 해설
    1. RSN(강건 보안 네트워크)은 먼저 탐색하고 인증한 뒤 키를 만들고 분배한 다음 보호된 데이터를 전송하므로, 인증을 탐색보다 앞세운 이 순서는 옳지 않다.
    2. RSN(강건 보안 네트워크)은 탐색이 인증보다 먼저 이루어져야 하므로, 인증 후 탐색을 거쳐 키를 만들고 안전한 통신을 시작하는 이 순서는 옳지 않다.
    3. RSN(강건 보안 네트워크)은 탐색에서 접속 대상을 찾고 인증을 거친 뒤 키를 생성·분배하며 마지막으로 보호된 데이터를 주고받으므로 옳다(정답).
    4. RSN(강건 보안 네트워크)은 인증이 끝난 뒤에 키 생성과 분배가 진행되므로, 탐색 직후 키를 먼저 만들고 나중에 인증하도록 배열한 이 순서는 옳지 않다.
    🧮 풀이
    1. 甲이 무선망 접속 절차를 인증부터 시작하도록 시험 순서를 짰다가 주변 접속점을 먼저 찾지 않은 탓에 연결 대상을 정하지 못했다. 이후 탐색 단계를 인증보다 앞으로 옮겨 절차를 다시 구성했다.
    2. 甲이 노트북의 무선 접속 과정을 기록하면서 인증을 마친 뒤에 주변 무선망을 찾도록 순서를 적었다. 실제 연결 기록에서는 접속점을 찾는 과정이 먼저 나타나 순서표를 수정했다.
    3. 甲이 노트북으로 주변 무선망을 탐색해 접속점을 고르고 사용자 인증을 마쳤다. 이어 암호화에 쓸 키가 생성·분배되자 보호된 상태에서 업무 데이터를 주고받기 시작했다.
    4. 甲이 실습용 무선망에서 접속점을 찾자마자 키를 먼저 나누도록 설정했지만 아직 사용자의 인증이 끝나지 않았다. 인증을 선행하도록 절차를 고친 뒤에야 보호 통신이 정상적으로 시작되었다.

    RSN(강건 보안 네트워크)은 탐색→인증→키 생성·분배→보호된 데이터 전송 순서로 동작한다.

    SNMP에서 관리 대상 장치 내부 객체들에 대한 정보 저장소를 나타내는 용어는?

    1. 1. MIB
    2. 2. Community
    3. 3. PDU
    4. 4. Agent

    정답 1번

    🔍 보기별 해설
    1. MIB는 SNMP가 관리하는 장치의 상태·구성·통계 등 관리 객체를 계층적으로 정의하고 그 값을 저장·관리하는 정보 저장소이므로 옳다(정답).
    2. Community는 SNMP 관리자와 에이전트 사이에서 접근 권한을 구분하는 문자열이며, 관리 대상 객체들의 정보를 저장하는 저장소 자체는 아니므로 옳지 않다.
    3. PDU는 SNMP에서 관리자와 에이전트가 요청·응답·Trap 등의 정보를 주고받을 때 사용하는 메시지 단위이며, 객체 정보 저장소는 아니므로 옳지 않다.
    4. Agent는 관리 대상 장치에서 동작하며 관리 정보를 수집하고 관리자의 SNMP 요청에 응답하는 소프트웨어이며, 객체 정보 저장소 자체는 아니므로 옳지 않다.
    🧮 풀이
    1. 甲이 SNMP 관리 프로그램에서 라우터의 인터페이스 상태와 송수신 바이트 수를 조회하자 MIB에 계층적으로 정의된 각 관리 객체의 OID와 현재 값이 차례로 화면에 표시됐다.
    2. 甲이 SNMP 장비에 접근하면서 올바른 Community 문자열을 입력하자 관리 요청이 허용됐지만, 다른 문자열을 사용하자 같은 장비의 관리 정보에 대한 조회 요청이 거부됐다.
    3. 甲이 SNMP 관리 서버에서 라우터의 인터페이스 값을 요청하자 GetRequest PDU가 전송됐고, 장비의 에이전트가 요청한 값을 담은 Response PDU를 다시 관리 서버로 돌려보냈다.
    4. 甲이 관리 대상 스위치에서 SNMP Agent를 실행하자 장비의 인터페이스 상태와 트래픽 정보를 수집하고 있다가 관리 서버의 조회 요청이 들어오자 해당 관리 값을 응답했다.

    SNMP에서 관리 대상 장치의 객체 정보를 계층적으로 정의하고 관리하는 정보 저장소는 MIB이다.
