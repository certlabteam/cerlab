    네트워크 명령어에 대한 설명으로 옳지 않은 것은?

    1. 1. hostname: 컴퓨터 이름을 확인한다.
    2. 2. nslookup: DNS를 통해 도메인 이름을 검색한다.
    3. 3. ipconfig: 인터페이스에 설정된 라우팅 테이블을 검색한다.
    4. 4. ping: 컴퓨터의 네트워크 상태를 점검한다.

    정답 3번

    🔍 보기별 해설
    1. hostname은 운영체제에 설정된 이 컴퓨터의 호스트 이름을 그대로 출력하는 명령이다. 지금 작업 중인 장비의 이름을 알아낼 때 쓰므로 옳다.
    2. nslookup은 DNS 서버에 질의를 보내 도메인 이름에 대응하는 IP 주소나 각종 레코드를 받아 오는 명령이다. 이름으로 주소를 찾아보는 조회 도구이므로 옳다.
    3. ipconfig는 인터페이스별 IP 주소·서브넷 마스크·기본 게이트웨이 같은 설정값을 보여 주는 명령이다. 라우팅 테이블은 route print나 netstat -r로 출력하므로 옳지 않다(정답).
    4. ping은 ICMP Echo Request를 보내고 Echo Reply가 돌아오는지와 왕복 시간을 재는 명령이다. 상대 컴퓨터까지 통신이 닿는지 점검하는 데 쓰므로 옳다.
    🧮 풀이
    1. 새로 들인 업무용 노트북 열 대에 자산 번호를 붙이던 전산팀 신입이 명령 프롬프트에서 hostname을 입력했다. 화면에 OFFICE-PC07이 찍혀 자산 대장의 장비 이름과 바로 맞춰 볼 수 있었다. 원격 접속 전에 어느 장비인지 가리는 데 이 명령이 쓰인다.
    2. 메일 서버 주소를 바꾼 다음 날 아침, 네트워크 관리자가 nslookup mail.company.co.kr을 입력해 새 IP가 응답으로 돌아오는 것을 받아 냈다. 옛 주소가 나오던 직원 PC는 DNS 캐시를 비우자 새 주소로 바뀌었다. 도메인 이름으로 주소를 조회하는 명령의 쓰임이다.
    3. 총무팀 PC가 외부 사이트에만 접속되지 않자 보안 담당자가 ipconfig를 실행했는데, IP 주소와 기본 게이트웨이까지만 나오고 경로 목록은 보이지 않았다. 경로를 보려고 route print를 따로 입력하니 0.0.0.0 경로가 빠져 있었다. 인터페이스 설정과 라우팅 테이블은 서로 다른 명령으로 본다.
    4. 회의실 프린터가 응답하지 않는다는 연락을 받은 운영자가 ping 192.168.0.50을 보냈다. 네 번 모두 시간 초과가 나와 케이블을 다시 꽂자 응답 시간 1ms로 회신이 돌아왔다. 장비까지 통신이 닿는지 먼저 가려내는 기본 점검이다.

    ipconfig는 인터페이스의 IP 설정을 보여 줄 뿐이고 라우팅 테이블은 route print나 netstat -r로 보므로 정답은 3번이다.

    다음에서 설명하는 네트워크 도구는?

    ○ IP 헤더에 있는 TTL의 특성을 이용한다.

    ○ TTL 값은 IP 패킷이 전송될 수 있는 최대 hop 수이다.

    ○ 최종 목적지까지의 라우터에 대한 경로 및 응답속도를 표시해 준다.

    ○ 특정 사이트와의 접속이 느릴 경우 네트워크의 어느 구간에서 느린지 확인할 수 있다.

    1. 1. wireshark
    2. 2. tcpdump
    3. 3. traceroute
    4. 4. netstat

    정답 3번

    🔍 보기별 해설
    1. wireshark는 인터페이스를 지나는 패킷을 잡아 프로토콜별로 풀어 보여 주는 분석 도구다. TTL을 늘려 가며 라우터 구간을 추적하는 기능은 없으므로 옳지 않다.
    2. tcpdump는 명령행에서 조건에 맞는 패킷을 수집해 헤더 내용을 출력하는 도구다. 목적지까지 거치는 라우터와 구간별 지연을 보여 주지 않으므로 옳지 않다.
    3. traceroute는 TTL을 1부터 하나씩 늘려 보내고 각 라우터가 돌려주는 시간 초과 응답으로 경로를 찾는다. 구간마다 응답 시간이 나와 느린 지점을 가려낼 수 있으므로 옳다(정답).
    4. netstat은 현재 연결 상태·열린 포트·라우팅 정보·프로토콜 통계를 출력하는 명령이다. 홉마다 경로와 응답 속도를 재는 도구가 아니므로 옳지 않다.
    🧮 풀이
    1. 거래처와의 파일 전송이 자꾸 끊기자 사내 네트워크 관리자가 wireshark로 전송 구간의 패킷을 캡처했다. 재전송 표시가 붙은 TCP 세그먼트가 줄줄이 보여 문제의 패킷 흐름은 잡혔지만, 어느 라우터에서 지연되는지는 화면에 나오지 않았다. 패킷 내용 분석과 경로 추적은 다른 일이다.
    2. 서버실 리눅스 장비에 접속한 보안 담당자가 tcpdump -i eth0 port 80을 입력해 웹 요청 패킷을 터미널로 흘려 보았다. 출발지와 목적지 주소, 플래그가 줄마다 찍혔지만 중간 라우터 목록은 하나도 없었다. 이 도구는 지나가는 패킷을 수집하는 쪽이다.
    3. 본사 홈페이지가 지사에서만 느리다는 말을 들은 운영자가 지사 PC에서 traceroute를 실행했다. 다섯 번째 홉부터 응답 시간이 3ms에서 180ms로 뛰어 통신사 구간을 원인으로 좁혔다. TTL 만료 응답을 차례로 받아 구간별 지연을 재는 방식이다.
    4. 퇴근 전 점검을 하던 전산팀 직원이 netstat -an으로 서버의 열린 포트와 연결 목록을 출력했다. ESTABLISHED 연결 스무 개와 대기 중인 포트는 보였지만 바깥 목적지까지의 경로는 알 수 없었다. 연결 상태를 보는 명령과 경로 추적 도구는 쓰임이 다르다.

    TTL을 하나씩 늘려 각 라우터의 시간 초과 응답을 받아 경로와 구간별 응답속도를 보여 주는 도구는 traceroute이므로 정답은 3번이다.

    비대칭키 암호화 알고리즘에서 수신자의 공개키로 데이터를 암호화하여 전송할 때 얻을 수 있는 보안성은?

    1. 1. 가용성
    2. 2. 인증
    3. 3. 부인방지
    4. 4. 기밀성

    정답 4번

    🔍 보기별 해설
    1. 가용성은 인가된 사용자가 필요할 때 정보와 서비스를 쓸 수 있게 보장하는 성질이다. 공개키로 암호화한다고 서비스 중단을 막아 주지는 않으므로 옳지 않다.
    2. 인증은 메시지를 보낸 사람이 정말 그 사람인지 확인해 주는 성질이다. 수신자의 공개키는 누구나 구할 수 있어 아무나 같은 암호문을 만들 수 있으므로 옳지 않다.
    3. 부인방지는 보낸 사람이 나중에 보낸 사실을 부정하지 못하게 하는 성질로, 송신자의 개인키 서명이 있어야 생긴다. 수신자 공개키 암호화로는 송신자를 묶어 둘 수 없으므로 옳지 않다.
    4. 기밀성은 허가받지 않은 사람이 내용을 읽지 못하게 하는 성질이다. 수신자 공개키로 만든 암호문은 짝이 되는 수신자 개인키로만 풀리므로 옳다(정답).
    🧮 풀이
    1. 재무팀 공유 폴더 서버가 디스크 고장으로 멈추자 직원들이 결산 파일을 하루 동안 열지 못했다. 파일이 아무리 단단히 암호화돼 있어도 서버가 꺼져 있으면 쓸 수 없다. 이렇게 필요한 때 쓸 수 있느냐가 가용성의 문제다.
    2. 외부 메일 주소로 사장 명의의 송금 요청이 오자 총무 직원이 발신자를 의심했다. 그 메일은 회사 공개키로 암호화돼 있었지만, 공개키는 홈페이지에 올라 있어 누구라도 같은 암호문을 만들 수 있었다. 보낸 사람을 확인하는 인증은 서명이 있어야 이루어진다.
    3. 협력사 담당자가 납품 단가 메일을 보낸 뒤 그런 메일을 보낸 적이 없다고 버텼다. 메일이 회사 공개키로 암호화만 돼 있고 협력사 개인키로 서명되지 않아 발송 사실을 증명할 자료가 없었다. 부인방지는 송신자의 전자서명이 있어야 생긴다.
    4. 인사 담당자가 연봉 계약서를 신입사원의 공개키로 암호화해 사내 메신저로 보냈다. 중간에 파일을 가로챈 사람이 있어도 신입사원 개인키가 없으면 내용을 볼 수 없다. 받는 사람의 공개키로 잠그면 기밀성이 지켜진다.

    수신자 공개키로 암호화한 데이터는 수신자의 개인키로만 복호화되어 다른 사람이 내용을 볼 수 없으므로 기밀성을 얻는다. 정답은 4번이다.

    TCP 포트의 개방 여부를 확인하기 위한 스텔스 스캔으로 옳지 않은 것은?

    1. 1. FIN 스캔
    2. 2. NULL 스캔
    3. 3. XMAS 스캔
    4. 4. TCP Open 스캔

    정답 4번

    🔍 보기별 해설
    1. FIN 스캔은 연결 없이 FIN 플래그만 켠 패킷을 보내, 닫힌 포트는 RST로 답하고 열린 포트는 답하지 않는 차이를 이용한다. 세션 로그가 남지 않는 스텔스 스캔이므로 옳다.
    2. NULL 스캔은 TCP 플래그를 하나도 켜지 않은 패킷을 보내 응답이 없으면 열린 포트로 추정한다. 3-way handshake를 끝내지 않아 연결 기록이 남지 않는 스텔스 스캔이므로 옳다.
    3. XMAS 스캔은 FIN·PSH·URG 플래그를 한꺼번에 켠 패킷으로 포트의 반응을 본다. 연결을 성립시키지 않고 응답 유무로 상태를 짐작하는 스텔스 스캔이므로 옳다.
    4. TCP Open 스캔은 SYN, SYN/ACK, ACK를 모두 주고받아 연결을 완전히 맺는 방식이다. 대상 시스템에 접속 로그가 그대로 남아 스텔스 스캔으로 볼 수 없으므로 옳지 않다(정답).
    🧮 풀이
    1. 점검 계약을 맺은 날 보안 담당자가 사내 웹서버에 FIN 스캔을 걸자 22번과 80번 포트에서만 응답이 오지 않았다. 나머지 포트는 RST를 돌려줘 닫혀 있음을 알렸다. 연결을 맺지 않고 응답 차이로 포트를 가려내는 방식이다.
    2. 모의 점검 중 운영자가 nmap -sN으로 NULL 스캔을 실행해 플래그가 하나도 없는 패킷을 파일 서버로 보냈다. 서버 접속 기록에는 아무 세션도 남지 않았고, 응답이 없던 445번 포트가 열린 포트로 표시됐다. 연결 흔적 없이 포트 상태를 추정하는 스캔이다.
    3. 야간 점검 시간에 신입 운영자가 nmap -sX로 XMAS 스캔을 돌려 플래그 세 개가 켜진 패킷을 방화벽 뒤 서버로 보냈다. 응답이 없던 포트 목록이 열림 또는 필터됨으로 표시되었다. 패킷의 플래그가 성탄 장식처럼 모두 켜졌다고 해서 붙은 이름이다.
    4. 점검자가 TCP Open 스캔으로 메일 서버의 포트에 하나씩 접속해 보자 서버 로그에 접속과 종료 기록이 수십 줄 쌓였다. 연결을 끝까지 맺었기 때문에 관리자 화면에 점검자 IP가 그대로 나타났다. 완전 연결 방식은 은밀하게 숨을 수 없다.

    FIN·NULL·XMAS 스캔은 연결을 맺지 않고 응답 차이를 보지만 TCP Open 스캔은 3-way handshake를 끝까지 마쳐 로그가 남는다. 정답은 4번이다.

    스위치 재밍(switch jamming)에 대한 설명으로 옳은 것은?

    1. 1. 스위치 MAC 테이블의 저장 용량을 넘으면 더미 허브(dummy hub)처럼 브로드캐스트(broadcast) 한다.
    2. 2. 방어대책은 게이트웨이 MAC 주소를 동적으로 설정한다.
    3. 3. 공격자는 클라이언트가 DNS 서버로 전송하는 DNS Query 패킷을 중간에 가로챈다.
    4. 4. MAC flooding은 스위치에 이상이 있을 때 자동으로 모든 보안 기능을 차단하는 것이다.

    정답 1번

    🔍 보기별 해설
    1. 스위치 재밍은 위조한 MAC 주소를 쏟아부어 MAC 테이블을 가득 채우는 공격이다. 테이블이 넘친 스위치는 목적지를 모르는 프레임을 모든 포트로 내보내 더미 허브처럼 동작하므로 옳다(정답).
    2. 스위치 재밍의 대책은 포트마다 학습할 수 있는 MAC 주소 수를 묶어 두는 포트 보안이다. 게이트웨이 MAC 주소를 동적으로 두면 오히려 ARP 스푸핑에 약해지므로 옳지 않다.
    3. DNS Query 패킷을 중간에 가로채 거짓 응답을 먼저 보내는 것은 DNS 스푸핑의 수법이다. MAC 테이블을 넘치게 하는 스위치 재밍과는 다른 공격이므로 옳지 않다.
    4. MAC flooding은 가짜 MAC 주소를 대량으로 보내 스위치 테이블을 채우는 공격 기법이다. 보안 기능을 자동으로 끊는 장치 기능이 아니므로 옳지 않다.
    🧮 풀이
    1. 공격 실습을 맡은 보안 담당자가 macof로 가짜 MAC 주소 수만 개를 사무실 스위치에 흘려보냈다. 몇 분 뒤 다른 직원 PC끼리 주고받던 프레임까지 담당자 노트북 포트로 들어왔다. 테이블이 넘친 스위치가 허브처럼 모든 포트로 뿌리기 시작한 결과다.
    2. 재밍 공격을 겪은 뒤 네트워크 관리자가 각 포트에 port-security를 켜고 학습 가능한 MAC 주소를 두 개로 제한했다. 다음 실습에서 가짜 주소가 밀려들자 그 포트가 바로 차단되었다. 게이트웨이 MAC은 동적이 아니라 정적으로 고정해 두는 것이 함께 쓰는 대책이다.
    3. 직원 PC가 사내 그룹웨어 주소를 물을 때마다 공격자가 그 DNS Query를 엿보고 가짜 응답을 먼저 보냈다. 직원은 그룹웨어와 똑같이 생긴 피싱 페이지로 이동했다. 이름 풀이 과정을 속이는 DNS 스푸핑이며 스위치 테이블과는 관련이 없다.
    4. MAC flooding을 시험한 운영자는 스위치 관리 화면에서 테이블 항목 수가 최대치에 붙어 있는 것을 보았다. 스위치는 보안 기능을 끄지 않았고 다만 모르는 목적지 프레임을 모든 포트로 내보내고 있었다. 이 기법이 노리는 것은 스위칭 기능의 마비다.

    스위치 재밍으로 MAC 테이블이 넘치면 스위치가 목적지를 모르는 프레임을 모든 포트로 브로드캐스트해 더미 허브처럼 동작한다. 정답은 1번이다.

    🔍 보기별 해설
    1. netstat -an은 모든 연결과 수신 대기 포트를 주소와 포트 번호 숫자로 보여 주는 옵션 조합이다. 바이트와 유니캐스트 패킷 수 같은 이더넷 통계는 나오지 않으므로 옳지 않다.

    2. 사무실 인터넷이 느려지자 네트워크 관리자가 파일 서버에서 netstat -e를 실행했다. 받은 바이트가 보낸 바이트보다 훨씬 많고 오류와 버림은 0으로 나와 회선 고장보다 다운로드 몰림을 원인으로 보았다. 이더넷 인터페이스의 송수신 통계를 보는 옵션이다.

    SSL 프로토콜에 대한 설명으로 옳은 것은?

    1. 1. ChangeCipherSpec 프로토콜은 오류와 비정상 상태를 알기 위해 사용한다.
    2. 2. Handshake 프로토콜은 대기와 활성 상태 사이에서 이동되는 값들의 처리 과정을 규정한다.
    3. 3. Record 프로토콜은 기밀성과 메시지 무결성을 제공한다.
    4. 4. Alert 프로토콜은 암호 그룹 협의와 클라이언트와 서버 간 인증 정보를 교환하기 위해 사용한다.

    정답 3번

    🔍 보기별 해설
    1. ChangeCipherSpec 프로토콜은 협상한 암호 명세를 이제부터 적용한다고 알리는 메시지 하나로 이루어진다. 오류와 비정상 상태를 알리는 일은 Alert 프로토콜이 하므로 옳지 않다.
    2. Handshake 프로토콜은 암호 그룹을 협상하고 서버·클라이언트 인증과 키 교환을 맡는다. 대기 상태의 값을 활성 상태로 옮기는 전환은 ChangeCipherSpec이 하므로 옳지 않다.
    3. Record 프로토콜은 상위 데이터를 조각내고 압축한 뒤 MAC을 붙이고 암호화해서 보낸다. 암호화로 기밀성을, MAC으로 메시지 무결성을 함께 주므로 옳다(정답).
    4. Alert 프로토콜은 오류나 경고, 연결 종료를 상대에게 알리는 데 쓴다. 암호 그룹 협의와 인증 정보 교환은 Handshake 프로토콜이 하므로 옳지 않다.
    🧮 풀이
    1. 사내 그룹웨어의 보안 통신을 분석하던 보안 담당자가 핸드셰이크 끝에 ChangeCipherSpec 메시지 한 개가 오가는 패킷을 캡처했다. 그 직후부터 패킷 내용이 모두 암호문으로 바뀌었다. 협상한 암호 설정을 이 순간부터 쓰겠다는 신호다.
    2. 인트라넷 접속 패킷을 열어 본 운영자가 Handshake 구간에서 ClientHello와 ServerHello, 인증서, 키 교환 메시지를 차례로 찾았다. 여기서 정해진 암호 그룹이 뒤따르는 세션 전체에 쓰였다. 상태 전환 신호는 따로 오는 ChangeCipherSpec이 맡는다.
    3. 급여 명세 조회 페이지의 트래픽을 잡은 네트워크 관리자는 Record 계층 데이터가 모두 알아볼 수 없는 바이트로 바뀌어 있는 것을 보았다. 중간에서 한 바이트를 고쳐 다시 보내자 수신 쪽이 MAC 검증에 실패해 연결을 끊었다. 내용 숨김과 변조 탐지를 이 계층이 함께 한다.
    4. 만료된 인증서를 쓰던 사내 서버에 접속하자 브라우저가 Alert 메시지 certificate_expired를 서버에 보내고 연결을 멈췄다. 이 메시지는 문제를 알릴 뿐 암호 그룹을 고르지는 않는다. 경고와 오류 통보가 Alert 프로토콜의 역할이다.

    SSL Record 프로토콜은 데이터를 조각내 MAC을 붙이고 암호화해서 보내므로 기밀성과 메시지 무결성을 함께 제공한다. 정답은 3번이다.

    IPSec의 ESP 터널 모드에서 암호화 범위로 옳은 것은?

    1. 1. ㉠
    2. 2. ㉡
    3. 3. ㉢
    4. 4. ㉣

    정답 3번

    🔍 보기별 해설
    1. ㉠은 새 IP 헤더까지 포함한 범위다. 새 IP 헤더는 중간 라우터가 읽고 길을 찾아야 하므로 이것까지 암호화하면 전달 자체가 안 되어 옳지 않다.
    2. ㉡은 ESP 헤더부터 잡은 범위다. ESP 헤더의 SPI와 순서번호는 받는 쪽이 복호화하기 전에 읽어 어떤 보안 연관을 쓸지 정해야 하므로 옳지 않다.
    3. ㉢은 원래 IP 헤더부터 TCP 헤더·데이터·ESP 트레일러까지다. 터널 모드는 원래 패킷 전체를 감싸 숨기므로 이 범위가 암호화 범위로 옳다(정답).
    4. ㉣은 TCP 헤더부터 잡은 범위로 전송 모드의 암호화 범위에 가깝다. 터널 모드에서는 원래 IP 헤더까지 숨겨야 하므로 옳지 않다.
    🧮 풀이
    1. 본사와 물류창고를 잇는 IPSec 장비를 시험하던 관리자가 바깥 헤더까지 암호화한 시험 패킷을 만들어 내보내자 첫 라우터에서 버려졌다. 라우터가 목적지 주소를 읽지 못했기 때문이다. 터널 모드에서 새 IP 헤더는 평문으로 남는다.
    2. 보안 담당자가 수신 장비의 디버그 로그를 켜자, 장비가 패킷의 SPI 값으로 보안 연관을 먼저 찾고 나서야 복호화를 시작했다. SPI가 암호문 안에 있었다면 어떤 키로 풀지조차 정할 수 없다. 그래서 ESP 헤더는 암호화 범위 밖에 둔다.
    3. 창고 사무실 직원 PC 10.20.0.15가 본사 ERP 서버로 보낸 패킷을 관리자가 외부 회선에서 캡처했다. 보이는 주소는 두 터널 장비의 공인 IP뿐이고 내부 주소와 TCP 포트는 암호문 속에 감춰져 있었다. 원래 IP 헤더부터 트레일러까지가 암호화되었기 때문이다.
    4. 같은 구간을 전송 모드로 바꿔 캡처한 신입 운영자는 내부 IP 주소가 바깥에 그대로 노출된 패킷을 얻었다. 데이터와 TCP 헤더는 숨겨졌지만 누가 누구와 통신하는지는 보였다. TCP 헤더부터 감추는 범위로는 터널 모드의 목적을 이루지 못한다.

    ESP 터널 모드는 원래 패킷을 통째로 감싸므로 원래 IP 헤더부터 ESP 트레일러까지 암호화하고 새 IP 헤더와 ESP 헤더는 밖에 둔다. 정답은 3번이다.

    TLS에 대한 설명으로 옳지 않은 것은?

    1. 1. TLS는 SSL을 기반으로 만들어진 인터넷 표준이다.
    2. 2. TLS의 의사난수 함수(pseudorandom function)는 데이터 확장 함수(data-expansion function)를 활용한다.
    3. 3. TLS의 의사난수 함수는 비밀(secret), 식별용 라벨(label), 종자(seed)를 입력받는다.
    4. 4. TLS의 마스터 비밀(master secret) 생성을 위해 데이터 확장 함수는 사전 마스터 비밀(pre-master secret), ‘master secret’ 문자, 2개의 임의의 수를 입력받는다.

    정답 4번

    🔍 보기별 해설
    1. TLS는 SSL 3.0을 토대로 IETF가 표준화한 보안 프로토콜이다. SSL의 구조를 이어받아 개선한 인터넷 표준이므로 옳다.
    2. TLS의 의사난수 함수(PRF)는 안쪽에서 P_hash라는 데이터 확장 함수를 써서 짧은 비밀을 원하는 길이로 늘린다. 확장 함수를 활용한다는 설명이므로 옳다.
    3. TLS의 PRF는 secret, 용도를 구분하는 label, 난수로 이루어진 seed 세 가지를 입력으로 받는다. 이 셋으로 필요한 키 재료를 만들어 내므로 옳다.
    4. TLS의 master secret은 pre-master secret, ‘master secret’ 라벨, 두 난수를 PRF에 넣어 만든다. 이 입력을 받는 주체는 데이터 확장 함수가 아니라 PRF이므로 옳지 않다(정답).
    🧮 풀이
    1. 사내 메일 서버의 SSL 3.0 설정을 빼던 관리자가 TLS 1.2만 허용하도록 바꿨다. 접속 화면과 인증서는 그대로였고 메시지 구조도 거의 같아 직원들은 차이를 느끼지 못했다. TLS가 SSL을 바탕으로 표준화된 뒤 다듬어진 프로토콜이기 때문이다.
    2. 인증 모듈을 손보던 개발 담당자가 TLS 1.2의 PRF를 직접 구현하면서 P_SHA256 함수를 반복 호출해 48바이트를 만들어 냈다. 해시 한 번은 32바이트밖에 나오지 않아 두 번을 이어 붙여 길이를 채웠다. 데이터 확장 함수가 PRF 안에서 하는 일이다.
    3. 같은 개발 담당자가 키 블록을 만들 때 PRF에 master secret, ‘key expansion’ 라벨, 서버와 클라이언트 난수를 넣었다. 라벨만 ‘client finished’로 바꾸자 전혀 다른 값이 나왔다. secret·label·seed 세 입력이 결과를 정한다.
    4. 디버깅 중 신입 개발자가 pre-master secret과 두 난수를 P_hash에 곧바로 넣어 master secret을 만들었더니 서버가 계산한 값과 달라 Finished 검증에서 연결이 끊겼다. 라벨을 붙여 PRF로 계산하도록 고치자 핸드셰이크가 끝까지 진행됐다. master secret은 PRF가 만든다.

    TLS의 master secret은 pre-master secret·라벨·두 난수를 PRF에 넣어 만들며, 데이터 확장 함수는 PRF 안에서 쓰일 뿐이다. 정답은 4번이다.

    디지털 포렌식(digital forensic)에서 ‘증거가 위조되거나 변조되지 않았다’는 것을 증명하는 원칙은?

    1. 1. 무결성
    2. 2. 신속성
    3. 3. 재현성
    4. 4. 정당성

    정답 1번

    🔍 보기별 해설
    1. 무결성 원칙은 수집한 디지털 증거가 확보된 뒤 위조·변조되지 않았음을 증명하라는 원칙이다. 해시값을 수집 때와 분석 때 비교해 같음을 보이는 방식으로 입증하므로 옳다(정답).
    2. 신속성 원칙은 메모리처럼 사라지기 쉬운 증거를 지체 없이 확보하라는 원칙이다. 빨리 수집하는 문제일 뿐 변조가 없음을 증명하는 원칙과는 달라 옳지 않다.
    3. 재현성 원칙은 같은 조건과 절차로 다시 분석하면 같은 결과가 나와야 한다는 원칙이다. 결과의 반복 가능성을 말할 뿐 증거의 비변조를 뜻하지 않으므로 옳지 않다.
    4. 정당성 원칙은 적법한 절차와 권한으로 수집한 증거만 효력을 갖는다는 원칙이다. 수집 과정의 적법성을 따지는 것이어서 위·변조가 없음을 보이는 원칙과는 달라 옳지 않다.
    🧮 풀이
    1. 내부 자료 유출 사건을 맡은 보안 담당자가 직원 노트북 디스크를 이미징하면서 SHA-256 해시값을 계산해 봉인 기록지에 적었다. 두 달 뒤 법정 제출 직전에 다시 계산한 값이 처음과 같아 사본이 손대지 않은 그대로임을 보였다. 이것이 무결성 원칙의 입증 방식이다.
    2. 랜섬웨어 감염 신고를 받은 전산팀장이 서버 전원을 끄기 전에 메모리 덤프부터 떴다. 재부팅했다면 실행 중이던 악성 프로세스와 암호화 키 흔적이 모두 사라졌을 것이다. 사라질 증거를 먼저 잡는 신속성 원칙이다.
    3. 회계 부정 조사에서 분석 담당자가 같은 이미지 파일을 다른 분석 도구로 다시 돌려 삭제 파일 목록이 똑같이 나오는 결과를 얻었다. 상대측이 분석 결과에 이의를 걸어도 같은 절차를 되풀이해 보일 수 있다. 결과를 다시 만들 수 있게 하는 재현성 원칙이다.
    4. 의심 직원의 개인 휴대폰을 영장 없이 열어 본 팀장이 메신저 대화를 캡처해 증거로 냈지만 위법 수집이라는 이유로 배제되었다. 내용이 진짜였어도 절차가 어긋나 쓸 수 없었다. 적법한 절차를 요구하는 정당성 원칙이다.

    디지털 증거가 확보된 뒤 위조·변조되지 않았음을 해시값 비교 등으로 증명하는 원칙은 무결성이다. 정답은 1번이다.

    대칭키 암호화 알고리즘으로 옳지 않은 것은?

    1. 1. ARIA
    2. 2. SEED
    3. 3. DES
    4. 4. ECC

    정답 4번

    🔍 보기별 해설
    1. ARIA는 국내에서 개발된 128비트 블록 암호로, 암호화와 복호화에 같은 비밀키를 쓴다. 송신자와 수신자가 키 하나를 나눠 갖는 대칭키 알고리즘이므로 옳다.
    2. SEED는 국내에서 개발된 128비트 블록 암호로, 하나의 비밀키로 암호화와 복호화를 모두 한다. 전자상거래와 금융 보안에 널리 쓰인 대칭키 알고리즘이므로 옳다.
    3. DES는 64비트 블록을 실질 56비트 키로 16라운드 처리하는 블록 암호다. 양쪽이 같은 키를 쓰는 대칭키 알고리즘이므로 옳다.
    4. ECC는 타원곡선 위의 이산대수 문제를 이용한 공개키 암호다. 공개키와 개인키를 따로 쓰는 비대칭 방식이라 대칭키 알고리즘으로 보는 것은 옳지 않다(정답).
    🧮 풀이
    1. 공공기관 납품용 문서 관리 시스템을 만들던 개발팀이 첨부 파일 암호화에 ARIA를 골랐다. 서버와 백업 장비에 같은 비밀키를 안전하게 나눠 두어야 복호화가 되었다. 하나의 키로 잠그고 여는 대칭키 방식이다.
    2. 오래된 결재 시스템의 암호화 모듈을 살피던 관리자가 SEED-CBC로 저장된 첨부 문서를 찾아냈다. 같은 비밀키를 가진 백업 서버에서만 파일이 열렸다. 국내에서 만든 대칭키 블록 암호가 쓰인 예이다.
    3. 십여 년 된 출입 통제 장비가 DES로 카드 정보를 암호화한다는 점검 결과를 받은 보안 담당자가 교체 예산을 올렸다. 키가 56비트뿐이라 지금의 연산 능력으로는 짧은 시간에 전수 조사가 가능하다. 대칭키 블록 암호지만 키 길이가 약점이다.
    4. 사내 VPN 인증서를 새로 발급하던 네트워크 관리자가 키 종류로 RSA 대신 ECC P-256을 선택했다. 개인키는 장비에 두고 공개키만 인증서에 실어 배포했다. 키 두 개를 나눠 쓰는 공개키 방식이다.

    ARIA·SEED·DES는 같은 비밀키로 암호화와 복호화를 하는 대칭키 암호지만 ECC는 타원곡선 기반 공개키 암호이다. 정답은 4번이다.

    네트워크 서비스의 기본 포트 번호로 옳지 않은 것은?

    1. 1. SMTP(Simple Message Transfer Protocol): 25
    2. 2. DNS(Domain Name Service): 53
    3. 3. RPC(Remote Procedure Call): 111
    4. 4. SNMP(Simple Network Management Protocol): 143

    정답 4번

    🔍 보기별 해설
    1. SMTP는 보기에 Simple Message Transfer Protocol로 적혀 있으나 정식 이름은 Simple Mail Transfer Protocol이며, 메일 전송에 TCP 25번 포트를 쓴다. 기본 포트를 25번으로 짝지은 것은 옳다.
    2. DNS(Domain Name Service)는 도메인 이름 조회에 53번 포트를 쓰며, 보통 질의는 UDP로, 영역 전송은 TCP로 한다. 기본 포트를 53번으로 짝지은 것은 옳다.
    3. RPC(Remote Procedure Call)의 포트매퍼는 TCP·UDP 111번에서 각 RPC 서비스가 쓰는 포트를 알려 준다. 기본 포트를 111번으로 든 짝은 옳다.
    4. SNMP(Simple Network Management Protocol)는 요청에 UDP 161번, Trap 수신에 162번을 쓴다. 143번은 IMAP의 포트이므로 SNMP 기본 포트를 143번이라 한 것은 옳지 않다(정답).
    🧮 풀이
    1. 새 메일 서버를 서버실 랙에 들여놓은 관리자가 방화벽 규칙에서 TCP 25번을 열자 사흘째 막혀 있던 외부 거래처 메일이 한꺼번에 들어오기 시작했다. 막혀 있던 동안에는 SMTP 연결이 시간 초과로 끝났다. 메일 서버끼리 주고받는 SMTP의 기본 포트가 25번이기 때문이다.
    2. 보조 DNS 서버를 새로 붙이던 운영자가 방화벽에 UDP 53번만 열었더니 보조 서버로의 영역 전송이 실패했다. TCP 53번까지 열자 동기화가 끝났다. DNS는 53번 포트를 UDP와 TCP 모두에서 쓴다.
    3. NFS로 공유 폴더를 붙이던 리눅스 담당자가 rpcinfo -p를 입력하자 111번 포트의 portmapper가 mountd·nfs 서비스의 포트 목록을 돌려주었다. 111번이 막혀 있을 때는 마운트가 멈춰 있었다. RPC 서비스 위치를 알려 주는 기본 포트다.
    4. 층마다 둔 스위치 다섯 대의 정보를 장비 감시 프로그램이 못 받아 오자 네트워크 관리자가 SNMP 설정을 열어 보니 포트가 143으로 잘못 적혀 있었다. UDP 161로 고치자 트래픽 그래프가 다시 그려졌다. 143번은 메일 조회용 IMAP이 쓰는 번호다.

    SMTP 25, DNS 53, RPC 포트매퍼 111은 맞지만 SNMP는 UDP 161·162번을 쓰고 143번은 IMAP 포트이다. 정답은 4번이다.

    침입탐지시스템(intrusion detection system)에 대한 설명으로 옳지 않은 것은?

    1. 1. 침입탐지 유형에는 비정상행위 탐지(anomaly detection)와 오용 탐지(misuse detection) 등으로 구분된다.
    2. 2. 비정상행위 탐지는 알려지지 않은 공격을 탐지하기에 효과적이지만 False Positive가 높아질 수 있다.
    3. 3. 오용 탐지는 알려진 공격 패턴을 기반으로 공격을 탐지하므로 알려지지 않은 공격 탐지에는 효과적이지 못하다.
    4. 4. 전문가 시스템 모델은 비정상행위 탐지에 널리 사용되는 기법이다.

    정답 4번

    🔍 보기별 해설
    1. 침입탐지는 탐지 방식에 따라 정상 행위에서 벗어난 것을 잡는 비정상행위 탐지와 알려진 공격 패턴을 찾는 오용 탐지로 나뉜다. 대표적인 두 유형을 든 설명이므로 옳다.
    2. 비정상행위 탐지는 정상 프로파일과 다른 행위를 공격으로 보므로 처음 보는 공격도 잡을 수 있다. 그 대신 평소와 다른 정상 행위까지 걸려 False Positive(오탐)가 늘 수 있으므로 옳다.
    3. 오용 탐지는 미리 등록한 공격 시그니처와 일치하는 트래픽만 공격으로 판정한다. 아직 패턴이 만들어지지 않은 새로운 공격은 그냥 지나치기 쉬우므로 옳다.
    4. 전문가 시스템은 알려진 공격 지식을 규칙으로 만들어 판정하는 오용 탐지 기법이다. 비정상행위 탐지에 널리 쓰인다고 한 것은 옳지 않다(정답).
    🧮 풀이
    1. 침입탐지 장비를 새로 들인 보안 담당자가 설정 화면에서 통계 기반 이상 탐지 모듈과 시그니처 탐지 모듈을 각각 켰다. 하나는 평소와 다른 트래픽 양을, 다른 하나는 알려진 공격 문자열을 경보 기준으로 삼았다. 두 방식이 침입탐지의 기본 유형이다.
    2. 결산 마감일에 회계팀이 평소의 열 배가 넘는 파일을 서버로 올리자 비정상행위 탐지 모듈이 데이터 유출 경보를 울렸다. 실제로는 정상 업무여서 담당자는 오탐 처리를 해야 했다. 새 공격을 잡는 힘과 False Positive가 함께 따라온다.
    3. 제로데이 취약점을 노린 공격 패킷이 들어왔지만 시그니처 탐지만 켜 둔 장비는 아무 경보도 내지 않았다. 다음 날 업체가 새 패턴을 배포한 뒤에야 같은 공격이 잡혔다. 알려진 패턴에만 반응하는 오용 탐지의 한계다.
    4. 규칙 엔진을 손보던 운영자가 ‘같은 IP에서 1분에 로그인 실패 20회면 무차별 대입 공격’이라는 규칙을 전문가 시스템에 넣었다. 이 규칙은 공격자가 남기는 알려진 행동을 바탕으로 했다. 전문가 시스템은 이렇게 오용 탐지 쪽에서 쓰인다.

    전문가 시스템은 알려진 공격 지식을 규칙으로 바꿔 판정하는 오용 탐지 기법이므로 비정상행위 탐지에 널리 쓰인다는 설명이 틀렸다. 정답은 4번이다.

    다음에서 설명하는 서비스 거부(denial of service) 공격은?

    ○ ICMP 패킷과 네트워크에 존재하는 임의의 시스템을 이용해 패킷을 확장함으로써 서비스 거부 공격 수행

    ○ 다이렉트 브로드캐스트(direct broadcast) 악용

    1. 1. 티어드롭 공격(teardrop attack)
    2. 2. 스머프 공격(smurf attack)
    3. 3. 죽음의 핑 공격(ping of death attack)
    4. 4. SYN 플러딩 공격(SYN flooding attack)

    정답 2번

    🔍 보기별 해설
    1. 티어드롭 공격은 IP 조각의 오프셋을 서로 겹치게 조작해 재조합 과정에서 시스템 오류를 일으킨다. ICMP 응답을 브로드캐스트로 키우는 공격과는 달라 옳지 않다.
    2. 스머프 공격은 출발지를 피해자 주소로 위조한 ICMP Echo Request를 다이렉트 브로드캐스트 주소로 보낸다. 그 망의 모든 호스트가 피해자에게 응답해 트래픽이 증폭되므로 옳다(정답).
    3. 죽음의 핑 공격은 최대 크기 65,535바이트를 넘는 ICMP 패킷을 조각내 보내 재조합 때 장애를 일으킨다. 브로드캐스트로 응답을 증폭하는 방식과는 달라 옳지 않다.
    4. SYN 플러딩 공격은 SYN만 대량으로 보내고 응답을 끝내지 않아 서버의 반개방 연결 대기열을 채운다. 다이렉트 브로드캐스트를 쓰지 않으므로 옳지 않다.
    🧮 풀이
    1. 운영체제 패치를 미룬 파일 서버가 오프셋이 서로 겹치도록 조작된 조각 패킷 몇 개를 받자마자 블루스크린으로 멈췄다. 공격자는 대량 트래픽 없이 재조합 과정의 오류만 노렸다. 조각 정보를 겹쳐 장비를 쓰러뜨리는 이 방식이 티어드롭 공격이다.
    2. 공격자가 출발지를 회사 웹서버 주소로 바꾼 ping 요청을 외부의 한 브로드캐스트 주소로 보냈다. 그 대역 수백 대가 일제히 웹서버로 응답을 쏟아내 회선이 마비되었다. 라우터에서 다이렉트 브로드캐스트를 막으면 이 스머프 공격의 증폭기가 사라진다.
    3. 보안 점검 중 담당자가 65,535바이트를 넘도록 조작한 ICMP 패킷을 조각내 구형 프린터 서버로 보냈다. 프린터 서버는 조각을 다시 맞추다 버퍼가 넘쳐 재부팅되었다. 응답 증폭 없이 크기 하나로 장비를 쓰러뜨리는 죽음의 핑 공격이다.
    4. 새벽에 그룹웨어 서버로 위조 주소의 SYN 패킷이 초당 수만 개 들어오자 반쯤 열린 연결이 대기열을 가득 채웠다. 직원들은 출근 후 로그인 화면조차 열지 못했다. SYN 쿠키를 켜자 서비스가 돌아온 이 공격은 SYN 플러딩이다.

    피해자 주소로 위조한 ICMP 요청을 다이렉트 브로드캐스트로 보내 여러 호스트의 응답으로 증폭하는 공격은 스머프 공격이다. 정답은 2번이다.

    공격자가 TCP 세션 하이재킹(session hijacking)을 위해 대상 호스트에 첫 번째로 보내는 TCP 패킷 플래그(flag)는?

    1. 1. RST
    2. 2. FIN
    3. 3. ACK
    4. 4. SYN

    정답 1번

    🔍 보기별 해설
    1. RST는 연결을 즉시 끊는 플래그다. 공격자는 먼저 RST로 기존 연결을 끊고 순서번호를 맞춰 그 자리를 차지하므로 첫 패킷의 플래그로 옳다(정답).
    2. FIN은 보낼 데이터가 끝났음을 알려 연결을 정상적으로 닫을 때 쓰는 플래그다. 기존 세션을 끊고 끼어드는 하이재킹의 첫 패킷과는 쓰임이 달라 옳지 않다.
    3. ACK는 받은 데이터의 다음 순서번호를 알려 주는 확인응답 플래그다. 하이재킹 과정 중에도 쓰이지만 처음 보내는 플래그는 RST이므로 옳지 않다.
    4. SYN은 새 연결을 열면서 초기 순서번호를 맞출 때 쓰는 플래그다. 이미 맺어진 세션을 가로채는 첫 단계와 쓰임이 다르므로 옳지 않다.
    🧮 풀이
    1. 모의해킹 실습에서 보안 담당자가 직원 PC와 사내 서버 사이 텔넷 세션을 엿본 뒤 서버 쪽으로 RST 패킷을 보냈다. 서버가 기존 연결을 닫자 담당자는 새 순서번호를 맞춘 패킷으로 그 세션에 끼어들었다. 하이재킹은 이렇게 연결을 끊는 데서 출발한다.
    2. 업무를 마친 직원이 파일 전송 프로그램의 종료 버튼을 누르자 클라이언트가 FIN을 보내고 서버도 FIN으로 답하며 연결이 닫혔다. 양쪽이 합의해 닫는 정상 종료 절차다. 남의 세션을 빼앗는 첫 단계와는 거리가 멀다.
    3. 직원 PC가 파일 서버에서 문서를 내려받는 동안 PC는 받은 바이트만큼 번호를 올린 ACK를 계속 돌려보냈다. 이 확인응답 덕분에 서버는 다음에 보낼 데이터를 정할 수 있었다. 흐름을 이어 가는 신호이고 세션을 끊는 데는 쓰이지 않는다.
    4. 신입 운영자가 사내 웹서버에 처음 접속하자 브라우저가 SYN을 보내고 서버가 SYN/ACK로 답한 뒤 ACK로 연결이 열렸다. 새 연결은 매번 이 동기화로 시작한다. 이미 열려 있는 남의 세션을 가로챌 때 처음 쓰는 플래그와는 다르다.

    TCP 세션 하이재킹은 먼저 RST로 기존 연결을 끊어 동기화를 무너뜨린 뒤 순서번호를 맞춰 끼어들기 때문이다. 정답은 1번이다.

    ICMP에 대한 설명으로 옳은 것은?

    1. 1. 전송 계층에서의 오류 탐지를 위해 사용한다.
    2. 2. 송신자의 패킷이 목적지에 도달하지 못했을 때 송신자는 ICMP Echo Reply 메시지를 수신한다.
    3. 3. TTL이 0이 되면 ICMP 시간초과(time exceeded) 오류 메시지가 발생한다.
    4. 4. UDP에 의해 전송된다.

    정답 3번

    🔍 보기별 해설
    1. ICMP는 IP와 함께 네트워크 계층에서 동작하며 IP 패킷 전달 중 생긴 오류를 알리는 프로토콜이다. 전송 계층의 오류 탐지용으로 보는 것은 옳지 않다.
    2. 목적지에 도달하지 못하면 송신자는 ICMP Destination Unreachable 메시지를 받는다. ICMP Echo Reply는 Echo Request에 대한 정상 응답이므로 옳지 않다.
    3. IP 패킷의 TTL은 라우터를 하나 지날 때마다 1씩 줄고, 0이 되면 그 라우터가 패킷을 버리고 ICMP 시간초과 메시지를 송신자에게 보낸다. 제시된 설명이 이 동작과 같으므로 옳다(정답).
    4. ICMP 메시지는 UDP에 실리지 않고 IP 데이터그램에 바로 담겨 프로토콜 번호 1로 전달된다. UDP로 전송된다는 설명은 옳지 않다.
    🧮 풀이
    1. 지점과 본사 사이 링크가 끊긴 날 관리자 PC에 라우터가 보낸 ICMP 오류 메시지가 찍혔다. 메시지는 IP 계층에서 만들어져 TCP 세그먼트의 재전송 판단과는 따로 움직였다. ICMP는 네트워크 계층에서 IP 전달 문제를 알린다.
    2. 폐기된 옛 서버 주소로 ping을 보낸 운영자는 Reply 대신 ‘Destination host unreachable’ 메시지를 받았다. 기본 게이트웨이가 그 주소로 갈 수 없다며 돌려보낸 오류였다. Echo Reply는 상대가 살아서 답할 때만 돌아온다.
    3. 경로를 추적하려고 TTL을 1로 정한 패킷을 보낸 네트워크 관리자에게 첫 라우터가 ICMP Time Exceeded를 돌려보냈다. TTL을 2, 3으로 늘리자 다음 라우터들이 차례로 같은 메시지를 보냈다. TTL이 0이 되면 시간초과 메시지가 생긴다.
    4. 방화벽 규칙을 만들던 보안 담당자가 UDP 포트를 모두 막았는데도 ping은 계속 오갔다. ICMP는 UDP가 아니라 IP 프로토콜 번호 1로 따로 다뤄지기 때문이다. ICMP를 막으려면 프로토콜 규칙을 별도로 둬야 한다.

    IP 패킷의 TTL이 0이 되면 라우터가 패킷을 버리고 송신자에게 ICMP 시간초과 메시지를 보내기 때문이다. 정답은 3번이다.

    IKE 키 결정 알고리즘의 특징에 대한 설명으로 옳지 않은 것은?

    1. 1. 방해 공격을 방지하기 위해 비표(nonce)를 사용한다.
    2. 2. 두 당사자가 군(group)을 협상할 수 있다.
    3. 3. Diffie-Hellman 공개키 값의 교환이 가능하다.
    4. 4. 중간자 공격을 방지하기 위해 Diffie-Hellman 교환을 인증한다.

    정답 1번

    🔍 보기별 해설
    1. IKE에서 nonce는 매번 새 값을 넣어 재전송 공격을 막는 데 쓴다. 방해(clogging) 공격을 막는 것은 쿠키이므로 비표를 방해 공격 방지용이라 한 것은 옳지 않다(정답).
    2. IKE의 키 결정 알고리즘은 두 당사자가 Diffie-Hellman에 쓸 군(group)을 협상할 수 있게 한다. 양쪽이 지원하는 매개변수를 고를 수 있으므로 옳다.
    3. IKE는 Diffie-Hellman 공개키 값을 서로 교환해 각자 같은 공유 비밀을 계산한다. 공개값 교환이 키 결정의 바탕이므로 옳다.
    4. Diffie-Hellman만으로는 상대가 누구인지 알 수 없어 중간자 공격에 약하다. IKE는 서명이나 사전 공유키로 그 교환을 인증해 중간자 공격을 막으므로 옳다.
    🧮 풀이
    1. 본사와 지점 VPN 장비 사이에 IKE를 설정하던 관리자가 위조 주소로 협상 요청이 쏟아지자 쿠키 교환 단계에서 가짜 요청을 걸러 냈다. 지난 패킷을 다시 보내는 시도는 매번 바뀌는 nonce 덕분에 막혔다. 두 값은 막는 공격이 서로 다르다.
    2. 협상 설정 화면에서 관리자가 DH group 14와 group 19를 함께 제안하자, 상대 장비가 group 14만 지원해 그것으로 정해졌다. 서로 다른 장비끼리도 쓸 수 있는 군을 고른 덕에 터널이 올라왔다. 군 협상이 이런 호환을 만든다.
    3. 터널을 처음 세울 때 두 장비는 각자 고른 비밀 지수로 계산한 Diffie-Hellman 공개값을 주고받았다. 받은 값에 자기 지수를 올리자 양쪽에서 똑같은 공유 비밀이 나왔다. 이 비밀에서 이후 세션 키가 만들어진다.
    4. 공격자가 지점 장비와 본사 장비 사이에 끼어 각각과 따로 DH 교환을 하려 했지만, 본사 장비가 인증서 서명 검증에서 실패를 내고 협상을 끊었다. 공개값만 주고받는 교환이었다면 공격자가 두 키를 모두 손에 넣었을 것이다. 인증이 붙어야 중간자를 막는다.

    IKE에서 방해(clogging) 공격은 쿠키로 막고 nonce는 재전송 공격 방지에 쓰므로 비표가 방해 공격을 막는다는 설명이 틀렸다. 정답은 1번이다.

    IPSec의 보안 연관(security association)을 식별하기 위한 매개변수로 옳지 않은 것은?

    1. 1. 보안 매개변수 색인(security parameters index)
    2. 2. 발신지 IP 주소
    3. 3. 수신지 IP 주소
    4. 4. 보안 프로토콜 식별자(security protocol identifier)

    정답 2번

    🔍 보기별 해설
    1. 보안 매개변수 색인(SPI)은 수신 측이 어떤 보안 연관을 적용할지 고르는 32비트 값이다. SA를 식별하는 세 매개변수 가운데 하나이므로 옳다.
    2. 보안 연관은 한 방향 관계로, 수신지 IP 주소·보안 프로토콜 식별자·SPI 세 값으로 식별한다. 발신지 IP 주소는 이 식별 매개변수에 들지 않으므로 옳지 않다(정답).
    3. 수신지 IP 주소는 SA가 끝나는 쪽 주소로 SA 식별 매개변수 가운데 하나다. 같은 SPI라도 목적지가 다르면 다른 SA로 구분하므로 옳다.
    4. 보안 프로토콜 식별자는 그 SA가 AH(인증 헤더)용인지 ESP(캡슐화 보안 페이로드)용인지를 나타내는 값이다. SA를 식별하는 세 매개변수의 하나이므로 옳다.
    🧮 풀이
    1. IPSec 장비를 설정하던 관리자가 수신 SA 두 개에 SPI를 0x1001과 0x1002로 따로 붙였다. 들어온 패킷의 SPI가 0x1002이면 장비는 두 번째 SA의 키로 바로 복호화했다. SPI가 SA를 가려 주는 꼬리표 구실을 한다.
    2. 지점 세 곳에서 본사 장비로 들어오는 패킷을 관리자가 캡처하니, 장비는 발신지 주소를 보지 않고 목적지 주소·프로토콜·SPI만으로 SA를 찾아 처리했다. 발신지가 바뀐 패킷도 세 값이 같으면 같은 SA로 들어갔다. 발신지 주소는 SA 식별에 쓰이지 않는다.
    3. 본사 장비에 공인 IP가 두 개 있을 때 신입 운영자가 같은 SPI 값을 두 주소에 각각 써 보니 장비가 두 SA를 따로 구분해 처리했다. 수신지 주소가 다르면 다른 연관으로 묶인다. 목적지 주소가 식별 값의 하나이기 때문이다.
    4. AH와 ESP를 함께 적용한 터널에서 보안 담당자가 두 프로토콜에 각각 SA를 만들었다. 장비는 프로토콜 번호 51과 50을 보고 인증 헤더용 SA와 캡슐화용 SA를 갈라 적용했다. 프로토콜 식별자가 있어야 두 SA가 섞이지 않는다.

    IPSec 보안 연관은 수신지 IP 주소·보안 프로토콜 식별자·SPI 세 값으로 식별하며 발신지 IP 주소는 식별 매개변수가 아니다. 정답은 2번이다.

    다음에서 설명하는 프로토콜은?

    ○ 인터넷 환경에서 오류에 관한 처리를 지원한다.

    ○ 네트워크 계층의 프로토콜로, 오류가 발생한 IP 패킷에 대하여 그 원인을 송신 호스트에 전달한다.

    ○ 전송과정에서 문제가 발생하면 필요할 경우 라우터에 의해 이 프로토콜 메시지가 자동으로 발생한다.

    1. 1. ICMP
    2. 2. IGMP
    3. 3. ARP
    4. 4. FTP

    정답 1번

    🔍 보기별 해설
    1. ICMP는 IP 패킷을 처리하다 생긴 오류의 원인을 출발지 호스트에 알리는 네트워크 계층 프로토콜이다. 라우터가 전달에 실패하면 이 메시지를 스스로 만들어 보내므로 제시된 설명과 같아 옳다(정답).
    2. IGMP는 호스트가 멀티캐스트 그룹에 가입하거나 탈퇴할 때 라우터와 주고받는 프로토콜이다. 오류가 난 IP 패킷의 원인을 송신자에게 돌려주는 역할은 하지 않으므로 옳지 않다.
    3. ARP는 같은 네트워크 안에서 IP 주소에 대응하는 MAC 주소를 알아내는 프로토콜이다. 전송 중에 생긴 오류를 송신 호스트에 보고하는 기능이 없으므로 옳지 않다.
    4. FTP는 응용 계층에서 클라이언트와 서버가 파일을 주고받을 때 쓰는 프로토콜이다. 네트워크 계층에서 라우터가 자동으로 만들어 내는 오류 메시지와는 거리가 멀어 옳지 않다.
    🧮 풀이
    1. 전산원 직원이 분교 서버로 ping을 보냈더니 중간 라우터가 목적지 도달 불가 메시지를 되돌려 보냈다. 경로가 끊긴 지점과 이유가 송신 쪽 화면에 그대로 찍혀 복구할 구간을 바로 좁힐 수 있었다. 라우터가 오류를 알려 준 이 메시지가 ICMP다.
    2. 인터넷 강의 방송을 받으려는 기숙사 PC가 멀티캐스트 그룹 가입 보고를 라우터로 보냈다. 라우터는 그 포트로 강의 스트림을 흘려보내기 시작했고 PC가 창을 닫자 탈퇴 보고와 함께 전송이 멈췄다. 그룹 구성원을 관리하는 이 과정이 IGMP다.
    3. 연구실 대학원생이 새 프린터 IP로 인쇄를 걸자 PC가 먼저 그 IP의 MAC 주소를 묻는 브로드캐스트를 뿌렸다. 프린터가 자기 MAC 주소로 답하자 비로소 인쇄 데이터가 전달되었다. 주소를 짝지어 주는 이 절차가 ARP다.
    4. 조교가 강의 자료를 학과 서버에 올리려고 FTP 클라이언트로 접속해 put 명령을 입력했다. 파일이 서버 폴더로 복사되었을 뿐 경로상의 오류를 알리는 메시지는 오가지 않았다. 파일 송수신을 맡은 응용 프로토콜이 FTP다.

    라우터가 오류 원인을 송신 호스트에 자동으로 알려 주는 네트워크 계층 프로토콜은 ICMP이므로 정답은 1번이다.

    HTTPS에 의해 암호화되지 않는 통신 요소는?

    1. 1. 요청 문서 URL
    2. 2. 문서의 내용
    3. 3. 포트 번호
    4. 4. HTTP 헤더의 내용

    정답 3번

    🔍 보기별 해설
    1. 요청 문서 URL의 경로와 질의 문자열은 HTTP 요청 줄에 담겨 TLS 안에서 암호화된다. 도청자가 패킷을 잡아도 어느 문서를 요청했는지 읽지 못하므로 암호화된다는 판단은 옳다.
    2. 문서의 내용, 곧 응답 본문은 TLS 레코드로 감싸진 뒤 전송되어 암호화된다. 중간에서 패킷을 모아도 본문은 알아볼 수 없는 암호문으로만 보이므로 옳다.
    3. 포트 번호는 TLS가 보호하는 데이터 바깥의 TCP 헤더에 들어 있어 암호화되지 않는다. 그래서 도청자도 443 같은 목적지 포트를 그대로 볼 수 있으므로 암호화된다고 보는 것은 옳지 않다(정답).
    4. HTTP 헤더의 내용은 쿠키·Host·User-Agent 등을 담은 HTTP 메시지의 일부라 TLS 안에서 함께 암호화된다. 세션 쿠키가 평문으로 새어 나가지 않으므로 옳다.
    🧮 풀이
    1. 도서관 전산실 직원이 열람 시스템의 검색 주소를 HTTPS로 바꾼 뒤 와이어샤크로 자기 PC 트래픽을 떠 보았다. 검색어가 들어간 요청 문서 URL 경로는 암호문 덩어리로만 보였고 목적지 서버 IP만 드러났다. 요청 줄이 TLS 안에 들어가 보호된 결과다.
    2. 학과 홈페이지 관리자가 성적 안내 문서의 내용을 HTTPS로만 내려보내도록 설정했다. 같은 기숙사망에서 누군가 패킷을 수집해도 본문 자리에는 의미 없는 바이트만 남았다. 응답 본문이 TLS 레코드로 암호화되어 전송된 것이다.
    3. 보안 실습 조교가 HTTPS 접속을 캡처해 TCP 헤더를 열자 목적지 포트 번호 443이 평문 숫자로 찍혀 있었다. 본문과 URL은 읽을 수 없었지만 어떤 서비스로 가는 연결인지는 포트로 드러났다. 포트가 TLS 바깥 계층에 있기 때문이다.
    4. 전산원 개발자가 로그인 쿠키를 실은 HTTP 헤더의 내용을 HTTPS 연결에서 캡처해 보았다. Cookie나 User-Agent 글자는 하나도 보이지 않았고 TLS 레코드만 줄지어 이어졌다. 헤더도 HTTP 메시지의 일부라 함께 암호화된 것이다.

    포트 번호는 TLS로 보호되는 HTTP 메시지 바깥의 TCP 헤더에 들어 있어 암호화되지 않으므로 정답은 3번이다.

    커버로스(Kerberos) 버전4에 대한 설명으로 옳지 않은 것은?

    1. 1. MIT에서 개발되어 공공 및 상업 영역에서 사용된다.
    2. 2. 신뢰하는 제3자 인증 서비스를 사용한다.
    3. 3. 클라이언트, 응용 서버, 커버로스 서버(키분배센터)로 구성된다.
    4. 4. 원격 인증에 사용하기에는 부적절하다.

    정답 4번

    🔍 보기별 해설
    1. Kerberos는 MIT의 Athena 프로젝트에서 개발된 네트워크 인증 프로토콜이다. 이후 대학과 공공기관, 기업 제품에까지 널리 쓰였으므로 옳다.
    2. Kerberos는 클라이언트와 서버가 함께 믿는 제3자인 인증 서버가 신원을 보증하는 방식이다. 서로 비밀번호를 직접 주고받지 않고 그 서버가 발급한 티켓으로 인증하므로 옳다.
    3. Kerberos는 서비스를 쓰려는 클라이언트, 실제 서비스를 주는 응용 서버, 인증 서버와 티켓 발급 서버를 묶은 키분배센터(KDC)로 이루어진다. 세 주체가 티켓을 주고받으며 인증을 마치므로 옳다.
    4. Kerberos는 안전하지 않은 네트워크 너머의 원격 사용자를 인증하려고 설계된 프로토콜이다. 비밀번호를 망에 흘리지 않고 티켓으로 원격 접속을 인증하므로 부적절하다는 설명은 옳지 않다(정답).
    🧮 풀이
    1. 1980년대 MIT 캠퍼스의 Athena 프로젝트 팀은 수많은 워크스테이션에서 학생들이 한 번 로그인으로 여러 서버를 쓰게 하려고 Kerberos를 만들었다. 이 방식은 뒤에 Windows 도메인 인증 같은 상용 제품에도 들어갔다. 대학에서 출발해 공공·상업 영역으로 퍼진 인증 프로토콜이다.
    2. 대학원생이 연구실 파일 서버에 접속하자 PC는 그 서버가 아니라 전산원의 인증 서버에 먼저 신원을 증명했다. 인증 서버가 내준 티켓을 파일 서버가 믿고 접속을 허락했다. 양쪽이 모두 신뢰하는 제3자가 인증을 대신 보증하는 구조다.
    3. 학기 초에 전산원 관리자가 Kerberos를 구축하면서 학생 PC에 클라이언트를, 메일·파일 서버에 서비스 키를 설치하고 별도 장비에 키분배센터를 세웠다. 학생은 키분배센터에서 받은 티켓을 응용 서버에 내밀어 접속했다. 클라이언트·응용 서버·KDC 세 축으로 움직이는 체계다.
    4. 해외 학회에 간 교수가 호텔 공용 와이파이에서 학과 서버에 원격으로 로그인했다. 비밀번호는 망에 나가지 않고 키분배센터가 발급한 티켓만 오가서 도청자가 얻을 것이 없었다. Kerberos가 원격 인증을 위해 설계된 방식이기 때문이다.

    Kerberos는 안전하지 않은 네트워크에서 원격 사용자를 티켓으로 인증하려고 만든 프로토콜이므로 원격 인증에 부적절하다는 4번이 틀렸다. 정답은 4번이다.

    스니핑(sniffing) 공격에 대한 설명으로 옳은 것은?

    1. 1. 네트워크 트래픽에서 데이터를 도청하는 수동적 공격이다.
    2. 2. 네트워크 장비에 대량의 트래픽을 전송하여 서비스를 중단시키는 공격이다.
    3. 3. 공격자가 다른 사용자의 IP 주소를 사용하여 네트워크에 접근하는 공격이다.
    4. 4. 공격자가 특정 값을 찾아내기 위해 모든 조합을 시도하는 공격이다.

    정답 1번

    🔍 보기별 해설
    1. 스니핑은 네트워크를 지나는 패킷을 몰래 수집해 내용을 엿보는 공격이다. 데이터를 바꾸거나 막지 않고 듣기만 하므로 수동적 공격이라는 설명은 옳다(정답).
    2. 대량의 트래픽을 퍼부어 장비나 서비스를 멈추게 하는 것은 서비스 거부(DoS) 공격이다. 스니핑은 서비스를 멈추지 않고 몰래 엿듣는 공격이므로 옳지 않다.
    3. 남의 IP 주소로 출발지를 꾸며 네트워크에 접근하는 것은 IP 스푸핑이다. 스니핑은 자신을 남으로 꾸미지 않고 오가는 패킷을 엿보는 것이므로 옳지 않다.
    4. 가능한 모든 값을 하나씩 대입해 비밀번호 등을 찾아내는 것은 무차별 대입(brute force) 공격이다. 패킷을 엿듣는 스니핑과 방식이 전혀 다르므로 옳지 않다.
    🧮 풀이
    1. 기숙사 같은 허브에 연결된 학생이 랜 카드를 무차별 모드로 바꾸고 tcpdump를 돌렸다. 옆방 PC가 평문 텔넷으로 보낸 아이디와 비밀번호가 그대로 잡혔지만 상대 통신에는 아무 흔적도 남지 않았다. 듣기만 하는 수동적 공격인 스니핑이다.
    2. 축제 기간에 누군가 수강신청 서버로 초당 수십만 건의 요청을 쏟아부어 서버가 응답을 멈췄다. 학생들은 접속조차 하지 못했고 전산원은 공격 IP를 차단하느라 밤을 새웠다. 서비스 자체를 쓰러뜨리는 DoS 공격이다.
    3. 공격자가 도서관 열람 서버가 믿는 관리 PC의 IP 주소를 출발지로 적은 패킷을 만들어 보냈다. 서버는 신뢰하는 주소에서 온 요청으로 여기고 응답을 내주었다. 남의 주소를 빌려 쓴 IP 스푸핑으로, 패킷을 엿보는 일과는 다르다.
    4. 한 학생이 학과 서버 로그인 창에 0000부터 9999까지 네 자리 PIN을 스크립트로 차례차례 넣었다. 수천 번 실패한 끝에 맞는 값이 나오자 계정이 열려 버렸다. 모든 조합을 하나씩 시도하는 무차별 대입 공격이다.

    스니핑은 트래픽을 몰래 수집해 엿듣기만 하는 수동적 공격이며 DoS·IP 스푸핑·무차별 대입 공격과 다르므로 정답은 1번이다.

    다음에서 설명하는 기술은?

    트래픽의 경로를 지정하는 제어 평면과 트래픽 전송을 수행하는 데이터 평면을 분리하여, OpenFlow 프로토콜 등을 통해 네트워크를 프로그램할 수 있다.

    1. 1. BSS(Business Support System)
    2. 2. OSS(Operation Support System)
    3. 3. SDN(Software Defined Networking)
    4. 4. MPLS(Multi-Protocol Label Switching)

    정답 3번

    🔍 보기별 해설
    1. BSS(Business Support System)는 통신사업자의 고객·요금·주문 같은 사업 업무를 돕는 시스템이다. 제어 평면과 데이터 평면을 나누는 네트워크 기술이 아니므로 옳지 않다.
    2. OSS(Operation Support System)는 통신망의 장애·구성·성능을 관리하는 운영 지원 시스템이다. 장비의 제어 기능을 떼어 내 프로그래밍하는 기술이 아니므로 옳지 않다.
    3. SDN(Software Defined Networking)은 경로를 정하는 제어 평면을 중앙 컨트롤러로 모으고 장비에는 전달만 맡기는 기술이다. OpenFlow 같은 프로토콜로 컨트롤러가 장비를 프로그래밍하므로 옳다(정답).
    4. MPLS(Multi-Protocol Label Switching)는 패킷에 짧은 레이블을 붙여 미리 정한 경로로 빠르게 전달하는 기술이다. 제어와 전달을 분리해 소프트웨어로 다루는 것이 핵심이 아니므로 옳지 않다.
    🧮 풀이
    1. 캠퍼스 인터넷을 대 주는 통신사 영업 담당자가 BSS 화면에서 대학의 회선 증설 주문을 받고 다음 달 요금을 새로 계산했다. 망의 경로 설정은 전혀 건드리지 않았다. 고객·요금·주문을 다루는 사업 지원 시스템이 BSS다.
    2. 통신사 망 운영자가 OSS 대시보드에서 대학 구간 회선의 장애 알람을 받고 현장 기사에게 복구 작업 지시를 내렸다. 회선별 성능 그래프와 장비 구성 이력도 같은 화면에서 관리하며 다음 점검 일정을 잡았다. 망 운영을 뒷받침하는 운영 지원 시스템이 OSS다.
    3. 네트워크 연구실 대학원생이 SDN 컨트롤러에 짧은 파이썬 코드를 올리자 OpenFlow로 연결된 스위치들의 흐름 테이블이 한꺼번에 바뀌었다. 스위치를 하나씩 설정하지 않고도 실험 트래픽이 새 경로로 흘렀다. 제어 평면을 떼어 내 소프트웨어로 망을 다루는 SDN이다.
    4. 대학으로 향하는 패킷이 통신사 백본에 들어서자 첫 라우터가 목적지 구간에 맞는 MPLS 레이블을 붙였다. 뒤 라우터들은 IP 헤더를 다시 들여다보지 않고 레이블만 바꿔 달며 정해진 경로로 넘겼다. 레이블 교환으로 전달을 빠르게 하는 MPLS다.

    제어 평면과 데이터 평면을 분리하고 OpenFlow 등으로 네트워크를 프로그래밍하게 하는 기술은 SDN이므로 정답은 3번이다.

    SSL/TLS에 대한 공격유형에 해당하지 않는 것은?

    1. 1. ESP 공격
    2. 2. PKI 공격
    3. 3. 레코드와 응용 데이터 프로토콜 공격
    4. 4. 핸드셰이크 프로토콜 공격

    정답 1번

    🔍 보기별 해설
    1. ESP는 IPSec에서 기밀성과 무결성을 제공하는 보안 프로토콜의 이름이다. SSL/TLS를 겨냥한 공격 분류에는 들어 있지 않으므로 공격 유형으로 보는 것은 옳지 않다(정답).
    2. PKI 공격은 인증서와 인증 기관의 신뢰 구조를 노려 SSL/TLS의 서버 인증을 무너뜨리는 공격 종류다. 위조 인증서 발급 같은 사례가 여기에 들어가므로 옳다.
    3. 레코드 계층과 그 위의 응용 데이터를 겨냥하는 프로토콜 공격은 암호화된 레코드 처리 방식을 노린다. 패딩 오라클 공격처럼 레코드 처리를 악용하는 사례가 여기에 들어가므로 옳다.
    4. 핸드셰이크 프로토콜 공격은 알고리즘 협상과 키 교환 단계를 노리는 공격 종류다. 보안 수준이 낮은 암호로 협상을 끌어내리는 다운그레이드 공격이 대표적이므로 옳다.
    🧮 풀이
    1. 분교 VPN 장비를 점검하던 서버 관리자가 IPSec 설정 화면에서 ESP를 켜 패킷 본문을 암호화했다. 같은 장비의 웹 관리 페이지는 TLS로 따로 보호되었고 ESP는 그 TLS 연결과 아무 관계가 없었다. ESP는 IPSec 계층에 속한 프로토콜의 이름이다.
    2. 모의해킹 동아리 학생이 실습망에서 자체 서명 인증서를 학과 홈페이지 인증서처럼 꾸며 중간 프록시에 올렸다. 신뢰 목록을 엄격히 관리하지 않은 실습 PC는 경고 없이 연결을 맺었다. 인증서 신뢰 구조를 노린 PKI 공격이다.
    3. 보안 연구실 대학원생이 오래된 SSL 3.0 서버에 블록을 하나씩 바꾼 레코드를 보내며 오류 응답의 차이를 모았다. 수백 번 되풀이하자 쿠키 값이 한 바이트씩 드러났다. 레코드 계층을 노린 POODLE 같은 레코드·응용 데이터 공격이다.
    4. 실습 서버를 맡은 조교가 접속 로그를 분석하다가 공격자가 중간에서 클라이언트의 암호 목록을 지우고 수출용 약한 암호만 남긴 흔적을 찾았다. 서버는 그 약한 암호로 협상을 마쳐 버렸다. 협상 단계를 비튼 핸드셰이크 프로토콜 공격이다.

    PKI·레코드와 응용 데이터·핸드셰이크 공격은 SSL/TLS 공격 분류이고 ESP는 IPSec의 보안 프로토콜이므로 정답은 1번이다.

    POP3에 대한 설명으로 옳지 않은 것은?

    1. 1. POP3는 서버로부터 메일을 다운로드하는 기능을 제공한다.
    2. 2. POP3 서버의 well-known 포트는 25번이다.
    3. 3. ＋OK 응답은 요구한 명령을 성공적으로 처리했음을 의미한다.
    4. 4. POP3 클라이언트와 서버는 명령과 응답으로 동작한다.

    정답 2번

    🔍 보기별 해설
    1. POP3는 메일 서버의 사서함에 쌓인 메일을 클라이언트 PC로 내려받는 수신용 프로토콜이다. 내려받은 뒤 서버 사본을 지우는 방식이 기본이므로 옳다.
    2. POP3의 well-known 포트는 TCP 110번이고 25번은 메일 전송용 SMTP의 포트다. 두 번호를 혼동한 설명이므로 옳지 않다(정답).
    3. POP3 서버는 명령을 제대로 처리하면 ＋OK로, 처리하지 못하면 -ERR로 답한다. ＋OK가 성공 응답이라는 설명은 규격과 같으므로 옳다.
    4. POP3는 클라이언트가 USER·PASS·RETR 같은 명령을 보내고 서버가 상태 응답을 돌려주는 방식이다. 텍스트 명령과 응답이 번갈아 오가며 동작하므로 옳다.
    🧮 풀이
    1. 교수가 연구실 PC의 메일 프로그램을 POP3로 설정하고 수신 버튼을 눌렀다. 대학 메일 서버 사서함에 있던 편지 스무 통이 PC로 내려왔고 서버 쪽 사서함은 비었다. 서버에서 메일을 가져오는 POP3의 기본 동작이다.
    2. 신입 조교가 학과 메일 서버 방화벽에 POP3용으로 25번 포트만 열었다가 학생들의 메일 수신이 모두 실패했다. 110번 포트를 추가로 열자 그제야 메일이 내려왔다. 25번은 SMTP가 쓰는 번호이고 POP3는 110번을 쓴다.
    3. 전산원 직원이 텔넷으로 메일 서버 110번에 붙어 USER 명령을 입력하자 ＋OK가 돌아왔다. 일부러 틀린 비밀번호를 넣으니 이번에는 -ERR이 찍혔다. ＋OK는 명령이 성공했다는 POP3 응답이다.
    4. 실습 시간에 학생이 메일 서버와 직접 대화하며 STAT으로 메일 수를 묻고 RETR 1로 첫 메일을 받았다. 명령 하나를 보낼 때마다 서버가 응답 한 줄을 돌려주었다. POP3 클라이언트와 서버는 이렇게 명령과 응답을 주고받는다.

    POP3의 well-known 포트는 TCP 110번이고 25번은 메일 전송용 SMTP의 포트이므로 정답은 2번이다.

    IPv4 데이터그램 형식에 대한 설명으로 옳지 않은 것은?

    1. 1. ‘Flags’는 단편화(fragmentation)와 관련이 있는 필드이다.
    2. 2. ‘Time To Live’는 데이터그램이 방문할 수 있는 최대 라우터의 수를 나타내는 필드이다.
    3. 3. ‘Total Length’는 헤더를 제외한 IP 데이터그램의 길이를 나타내는 필드이다.
    4. 4. ‘Protocol’은 IP 계층의 서비스를 사용하는 상위 계층 프로토콜을 나타내는 필드이다.

    정답 3번

    🔍 보기별 해설
    1. Flags 필드는 단편화 금지(DF)와 추가 단편 있음(MF) 비트를 담는다. Fragment Offset과 함께 쪼개진 데이터그램을 다시 맞추는 데 쓰이므로 옳다.
    2. Time To Live는 라우터를 하나 지날 때마다 1씩 줄고 0이 되면 데이터그램을 버리게 하는 필드다. 결국 거칠 수 있는 라우터 수의 상한이 되므로 옳다.
    3. Total Length는 헤더와 데이터를 합친 IP 데이터그램 전체의 길이를 바이트로 나타내는 필드다. 헤더를 빼고 센다고 한 설명은 정의와 다르므로 옳지 않다(정답).
    4. Protocol 필드는 데이터그램의 데이터를 TCP(6)·UDP(17)·ICMP(1) 가운데 어느 상위 프로토콜에 넘길지 알려 준다. 받는 쪽이 이 값을 보고 처리할 모듈을 고르므로 옳다.
    🧮 풀이
    1. 기숙사망 MTU가 작아 큰 데이터그램이 둘로 나뉘자 첫 조각에는 MF 비트가 1로, 마지막 조각에는 0으로 켜졌다. 받는 PC는 Flags와 오프셋을 보고 두 조각을 원래대로 이어 붙였다. 단편화를 이끄는 필드가 Flags다.
    2. 라우팅 설정 실수로 두 라우터 사이에 패킷이 계속 맴돌자 TTL이 64에서 하나씩 줄다가 0이 되어 버려졌다. 마지막 라우터는 ICMP 시간초과를 보내 출발지에 알렸다. 무한 순환을 끊는 상한이 Time To Live다.
    3. 네트워크 과목 조교가 캡처한 패킷의 헤더 20바이트와 데이터 1,480바이트를 더하자 Total Length 칸의 1,500과 같았다. 데이터만 센 1,480과는 달랐다. Total Length는 헤더까지 포함한 전체 길이다.
    4. 연구원이 수신 PC의 IP 계층 동작을 추적하자 Protocol 값이 6인 패킷은 TCP로, 17인 패킷은 UDP로 넘어갔다. 값이 1이면 ICMP 처리 루틴이 응답을 만들었다. 상위 계층을 고르는 기준이 Protocol 필드다.

    공개키 기반 구조 X.509(PKIX) 모델에서 종단 개체(end entity)와 인증 기관(certificate authority) 간의 관리 기능에 해당하지 않는 것은?

    2. 2. 키 쌍 복구(key pair recovery)
    3. 3. 키 쌍 갱신(key pair update)
    4. 4. 교차 인증(cross-certification)

    정답 4번

    🔍 보기별 해설
    1. 등록은 종단 개체가 인증 기관이나 등록 기관에 자신을 처음 알리고 신원을 확인받는 절차(registration)다. 종단 개체와 CA 사이에서 이루어지는 관리 기능이므로 옳다.
    2. 키 쌍 복구는 종단 개체가 암호화용 개인키를 잃었을 때 백업해 둔 키를 되찾게 하는 기능(recovery)이다. 종단 개체가 CA 쪽에 요청해 처리하므로 옳다.
    3. 키 쌍 갱신은 인증서 만료나 키 노출 때 새 키 쌍과 새 인증서로 바꾸는 기능(update)이다. 종단 개체와 CA가 주고받는 관리 기능이므로 옳다.
    4. 교차 인증은 서로 다른 CA가 상대 CA의 공개키에 인증서를 발급해 신뢰를 맺는 기능(cross-certification)이다. 종단 개체가 아니라 CA와 CA 사이의 일이므로 종단 개체와 CA 사이 기능으로 보는 것은 옳지 않다(정답).
    🧮 풀이
    1. 새로 임용된 교수가 대학 인증센터 웹에 신분 정보와 공개키를 제출하자 등록 담당자가 교원 명부와 대조해 승인했다. 승인이 끝난 뒤에야 전자결재용 인증서가 발급되었다. 종단 개체가 CA에 처음 자신을 알리는 registration 단계다.
    2. 연구원이 노트북을 잃어버려 암호화해 둔 실험 자료를 열 수 없게 되자 인증센터에 key pair recovery를 신청했다. 센터는 보관해 둔 복호화용 개인키를 본인 확인 뒤 돌려주었고 자료가 다시 열렸다. 종단 개체를 위한 키 쌍 복구 기능이다.
    3. 인증서 만료 한 달 전 알림을 받은 행정실 직원이 PC에서 새 키 쌍을 만들어 인증센터에 key pair update 요청을 보냈다. 새 인증서가 내려오자 전자결재 프로그램에 바로 적용했다. 종단 개체가 키를 바꾸는 키 쌍 갱신이다.
    4. 대학 인증센터와 협력 병원 인증센터가 서로의 CA 공개키에 인증서를 발급해 주었다. 그 뒤 교수의 인증서를 병원 시스템도 믿게 되었지만 이 과정에 교수 개인은 전혀 끼지 않았다. 두 CA끼리 맺는 cross-certification이다.

    등록·키 쌍 복구·키 쌍 갱신은 종단 개체와 CA 사이의 관리 기능이고 교차 인증은 CA끼리의 기능이므로 정답은 4번이다.

    다음에 기술된 IEEE 802.11i RSN의 동작 단계를 순서대로 나열한 것은?

    (가) 인증(authentication) (나) 탐색(discovery) (다) 안전 데이터 전송(protected data transfer) (라) 키 생성 및 분배(key generation and distribution)

    1. 1. (가) → (나) → (다) → (라)
    2. 2. (가) → (나) → (라) → (다)
    3. 3. (나) → (가) → (라) → (다)
    4. 4. (나) → (라) → (가) → (다)

    정답 3번

    🔍 보기별 해설
    1. IEEE 802.11i RSN(강건 보안 네트워크)은 단말이 먼저 AP를 찾는 탐색 단계를 거친 뒤에야 인증할 수 있다. 인증을 맨 앞에 두고 키 분배보다 데이터 전송을 먼저 둔 순서이므로 옳지 않다.
    2. RSN에서는 인증할 상대를 정하려면 탐색이 먼저 끝나야 한다. 인증을 탐색보다 앞에 둔 순서이므로 키 생성 뒤 데이터를 보내는 뒷부분이 맞아도 옳지 않다.
    3. RSN은 탐색으로 AP와 보안 능력을 맞추고, 인증을 거친 뒤 키를 만들어 나누고, 그 키로 보호된 데이터를 전송한다. (나)→(가)→(라)→(다) 순서와 같으므로 옳다(정답).
    4. RSN의 키 생성과 분배는 인증으로 얻은 마스터 키를 바탕으로 이루어진다. 인증보다 키 분배를 먼저 둔 순서는 성립하지 않으므로 옳지 않다.
    🧮 풀이
    1. 기숙사 와이파이를 처음 켠 학생의 노트북이 인증 요청부터 보내려 했지만 접속할 AP의 비컨을 아직 받지 못해 보낼 곳이 없었다. 프로브 요청으로 AP를 찾은 뒤에야 인증이 시작되었다. 탐색이 인증보다 앞서야 한다.
    2. 무선 실습에서 대학원생이 인증 패킷을 먼저 흘리고 탐색 패킷을 나중에 보내도록 스크립트를 짰다. AP는 아직 연결 정보가 없는 단말의 인증 요청을 버렸고 키 교환 단계까지 가지도 못했다. 첫머리 순서가 뒤집히면 RSN이 시작되지 않는다.
    3. 무선망에 붙는 연구실 노트북은 비컨으로 AP를 찾아 보안 능력을 맞추고, RADIUS 서버로 802.1X 인증을 마친 뒤, 4-way 핸드셰이크로 키를 받는다. 그 키로 암호화한 데이터만 오간다. 탐색, 인증, 키 분배, 보호된 전송으로 이어지는 RSN 순서다.
    4. 한 실험 장비가 탐색 직후 4-way 핸드셰이크부터 시도하자 AP는 건넬 키가 없어 응답하지 못했다. 802.1X 인증이 끝나 마스터 키가 생긴 뒤에야 핸드셰이크가 이루어졌다. 키 분배는 인증 다음 단계다.

    IEEE 802.11i RSN은 탐색 뒤 인증하고, 인증 결과로 키를 생성·분배한 다음 보호된 데이터를 전송하므로 정답은 3번이다.

  • 34

    SNMP에서 관리 대상 장치 내부 객체들에 대한 정보 저장소를 나타내는 용어는?

    1. 1. MIB
    2. 2. Community
    3. 3. PDU
    4. 4. Agent

    정답 1번

    🔍 보기별 해설
    1. MIB는 SNMP가 관리하는 장치 안의 객체들을 트리 구조로 정의하고 그 값을 모아 둔 관리 정보 저장소다. 관리자는 OID로 원하는 객체를 찾아 값을 읽으므로 옳다(정답).
    2. Community는 SNMPv1·v2c에서 관리자와 에이전트가 접근 권한을 맞춰 보는 공유 문자열이다. 일종의 비밀번호일 뿐 객체 정보를 담아 두는 저장소가 아니므로 옳지 않다.
    3. PDU는 GetRequest·SetRequest·Trap처럼 관리자와 에이전트가 주고받는 SNMP 메시지 단위다. 정보를 실어 나르는 그릇이지 장치 객체를 쌓아 두는 저장소가 아니므로 옳지 않다.
    4. Agent는 관리 대상 장치에서 돌며 관리자의 요청에 답하고 이상이 생기면 Trap을 보내는 프로그램이다. 저장소의 값을 읽어 전하는 주체일 뿐 저장소 자체가 아니므로 옳지 않다.
    🧮 풀이
    1. 학과 서버 관리자가 snmpget으로 연구실 스위치의 ifInOctets 객체를 조회하자 포트별 수신 바이트 값이 돌아왔다. 그 값은 스위치 내부 MIB 트리의 정해진 OID 자리에 저장되어 있던 것이다. 관리 객체를 모아 둔 저장소가 MIB다.
    2. 외부 스캐너가 대학 프린터에 SNMP 요청을 보내며 Community 문자열로 기본값 public을 넣었다. 관리자가 문자열을 바꿔 둔 덕에 요청이 거부되어 아무 정보도 나가지 않았다. Community는 접근을 허락하는 공유 문자열이다.
    3. 패킷을 캡처한 대학원생이 SNMP 메시지 안쪽을 열자 요청 ID와 객체 이름·값 목록이 담긴 GetResponse PDU가 나왔다. 장치 정보는 이 메시지에 실려 관리자에게 전달되었을 뿐이다. 주고받는 메시지 단위가 PDU다.
    4. 도서관 UPS에 설치된 SNMP Agent가 배터리 잔량이 20% 아래로 떨어지자 관리 서버로 Trap을 보냈다. 관리자가 상태를 묻자 같은 Agent가 장치 MIB의 값을 읽어 답해 주었다. 장치에서 동작하는 관리 프로그램이 Agent다.

    SNMP에서 관리 대상 장치 내부 객체들의 정보를 계층적으로 정의하고 저장하는 저장소는 MIB이므로 정답은 1번이다.
