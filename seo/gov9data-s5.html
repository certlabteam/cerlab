    알고리즘의 조건에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄱ. 모든 명령은 모호하지 않고 명확해야 한다.

    ㄴ. 모든 명령은 실행 가능한 연산이어야 한다.

    ㄷ. 모든 명령은 반복적으로 무한히 실행되어야 한다.

    1. 1. ㄱ
    2. 2. ㄱ, ㄴ
    3. 3. ㄴ, ㄷ
    4. 4. ㄱ, ㄴ, ㄷ

    정답 2번

    🔍 보기별 해설
    1. ㄱ은 명령이 모호하지 않아야 한다는 명확성 조건으로 참이다. 다만 실행 가능성을 말한 ㄴ도 참인데 그것이 빠져 있어 참인 진술을 하나 놓친 묶음이므로 옳지 않다.
    2. 명령이 모호하지 않아야 한다는 명확성과 실제로 수행할 수 있는 연산이어야 한다는 실행 가능성은 둘 다 알고리즘의 조건이다. 무한 반복을 뺀 두 진술의 묶음이 맞다.
    3. ㄴ은 참이지만 ㄷ은 알고리즘이 유한한 단계를 거친 뒤 반드시 끝나야 한다는 종료성과 정면으로 어긋난다. 참인 ㄱ까지 빠진 묶음이므로 옳지 않다.
    4. 세 진술 가운데 ㄷ은 무한히 실행하라는 뜻이어서 거짓이다. 알고리즘은 입력을 받아 유한 단계 뒤에 출력을 내고 끝나야 하므로 ㄷ을 포함한 묶음은 옳지 않다.
    🧮 풀이
    1. 甲은 요리 레시피에 「적당히 볶는다」라고만 적힌 것을 보고 사람마다 다르게 읽히는 명령은 알고리즘이 될 수 없다고 생각했다. 「중불에서 3분 볶는다」처럼 한 가지로만 읽히는 문장으로 고쳐 적어 두었다.
    2. 甲은 길 찾기 순서도에서 「왼쪽으로 돈다」는 명령이 뜻도 분명하고 실제로 할 수 있어 명확성과 실행 가능성을 함께 갖췄다고 표시했다. 반면 「목적지를 마음으로 느낀다」는 칸은 수행할 수 없어 지우고 다른 명령으로 바꿔 넣었다.
    3. 甲은 로봇 청소기가 방을 끝없이 돌기만 하고 멈추지 않는 동작 기록을 보았다. 동작 하나하나는 실행할 수 있어도 끝나지 않는 명령의 나열은 알고리즘이 아니라고 보고 종료 조건 한 줄을 추가했다.
    4. 甲은 세 진술을 카드 한 장씩에 옮겨 순서도에 하나씩 대 보았다. 명확성과 실행 가능성 카드는 통과했지만 무한 실행 카드는 유한 단계 뒤에 끝나야 한다는 조건과 맞지 않아 옆으로 치워 두었다.

    알고리즘은 명령이 명확하고 실행 가능해야 하며 유한한 단계 안에 끝나야 한다. 무한 반복은 조건이 아니다. 정답은 2번.

    알고리즘의 수행 시간 분석에 대한 설명으로 옳지 않은 것은?

    1. 1. 알고리즘의 수행 시간은 컴퓨터 성능에 관계없이 명확하게 정의되어야 한다.
    2. 2. 알고리즘의 시간복잡도는 수행하는 기본적인 연산 횟수를 입력 크기에 대한 함수로 표현한다.
    3. 3. 최선의 경우의 알고리즘 수행 시간은 모든 입력의 수행 시간에 대한 상한이 된다.
    4. 4. 알고리즘의 수행 시간 분석에는 최악의 경우, 평균의 경우, 최선의 경우가 있다.

    정답 3번

    🔍 보기별 해설
    1. 실제로 재는 초 단위 시간은 컴퓨터마다 달라 알고리즘 자체의 성능을 견주기 어렵다. 그래서 하드웨어와 무관하게 정의해야 한다는 원칙을 말한 진술이므로 맞다.
    2. 시간복잡도는 덧셈이나 비교 같은 기본 연산이 몇 번 일어나는지를 입력 크기 n에 대한 함수로 나타낸 것이다. 이렇게 셈해야 기계와 상관없이 견줄 수 있으므로 맞다.
    3. 가장 유리한 입력에서의 수행 시간은 다른 입력들의 수행 시간보다 짧거나 같은 하한이 된다. 모든 입력을 덮는 상한은 가장 불리한 최악의 경우가 맡으므로 옳지 않다(정답).
    4. 입력이 가장 불리한 최악, 가능한 모든 입력의 기댓값을 보는 평균, 가장 유리한 최선의 세 관점으로 수행 시간을 분석한다. 시간복잡도 분석의 표준 구분이므로 맞다.
    🧮 풀이
    1. 甲은 같은 정렬 프로그램을 오래된 노트북과 최신 서버에서 돌려 걸린 시간이 열 배 넘게 다른 것을 보았다. 초 단위 값은 기계에 따라 흔들리니 연산 횟수로 세어야 한다고 적어 두었다.
    2. 甲은 배열에서 값을 찾는 반복문을 한 줄씩 짚으며 비교 연산이 몇 번 실행되는지 세었다. 원소가 n개면 최대 n번이라는 식을 만들어 입력 크기에 대한 함수로 공책에 옮겨 적었다.
    3. 甲은 이미 정렬된 배열에 삽입 정렬을 돌렸을 때 비교가 n번 정도로 끝나는 것을 확인했다. 이 값은 가장 유리한 경우라 다른 입력의 시간보다 작아 상한이 아닌 하한임을 표에 표시했다.
    4. 甲은 순차 탐색에서 찾는 값이 맨 앞에 있을 때와 맨 뒤에 있을 때, 중간에 있을 때의 비교 횟수를 나눠 세었다. 각각 최선, 최악, 평균이라 이름 붙여 세 칸짜리 표에 정리해 두었다.

    최선의 경우는 다른 입력의 수행 시간보다 짧은 하한이고, 모든 입력을 덮는 상한은 최악의 경우가 맡는다.

    다음은 그래프에서 너비 우선 탐색(breadth first search) 알고리즘이 동작하는 과정이다. (가) ～ (다)에 들어갈 내용을 바르게 연결한 것은?

    [단계 1] 시작 정점을 ‘visited’로 표시하고 (가) 에(서) (나) 한다.

    [단계 2] (가) 에(서) 정점을 (다) 하고, 제거한 정점의 인접 정점 중 아직 방문하지 않은 곳들은 ‘visited’로 표시하고 (가) 에(서) (나) 한다.

    [단계 3] (가) 가/이 비워질 때까지 [단계 2]를 반복한다. (가) (나) (다)

    1. 1. Queue Dequeue Enqueue
    2. 2. Queue Enqueue Dequeue
    3. 3. Stack Pop Push
    4. 4. Stack Push Pop

    정답 2번

    🔍 보기별 해설
    1. 너비 우선 탐색이 큐를 쓴다는 점은 맞지만 (나)와 (다)가 서로 뒤바뀌었다. 시작 정점을 큐에 넣는 동작이 먼저이고 꺼내는 동작이 그다음인데 넣기 자리에 꺼내기를 써서 옳지 않다.
    2. 너비 우선 탐색은 가까운 정점부터 차례로 다루려고 먼저 들어간 것을 먼저 꺼내는 큐를 쓴다. 시작 정점과 새 인접 정점은 큐에 넣고 정점은 큐에서 꺼내는 순서이므로 옳다(정답).
    3. 스택은 나중에 넣은 것을 먼저 꺼내는 구조라 가장 깊은 곳까지 파고드는 깊이 우선 탐색에 어울린다. 너비 우선 탐색에 쓰는 자료구조가 아니므로 옳지 않다.
    4. 넣고 꺼내는 이름은 짝지어 놓았지만 자료구조가 후입선출이라 방문 순서가 층별로 퍼지지 않고 깊이를 따라간다. 너비 우선 탐색에는 큐가 필요하므로 옳지 않다.
    🧮 풀이
    1. 甲은 은행 창구에서 번호표를 뽑은 사람이 아직 없는데 번호부터 부르는 순서도를 그려 놓고 이상하다고 느꼈다. 줄에 세우는 일이 앞이고 부르는 일이 뒤이니 두 동작 이름을 맞바꿔 다시 적었다.
    2. 甲은 놀이공원 입구에서 먼저 도착한 사람이 먼저 입장하는 줄을 한참 관찰했다. 줄 끝에 서는 것을 넣기, 맨 앞 사람이 들어가는 것을 꺼내기로 나누어 적고 탐색 순서와 견주어 보았다.
    3. 甲은 접시를 쌓아 두고 맨 위 접시부터 집어 쓰는 식당 주방을 지켜보았다. 마지막에 올린 것을 먼저 쓰는 이 방식이 Push와 Pop으로 부르는 스택의 동작임을 공책에 메모했다.
    4. 甲은 미로에서 갈림길을 만날 때마다 한 길로 끝까지 들어가는 자신의 걸음을 지도에 그렸다. 스택에 좌표를 넣었다 꺼내는 이 경로가 층별로 퍼지지 않고 깊게 파고드는 모양임을 표시했다.

    너비 우선 탐색은 큐를 쓴다. 시작 정점과 새 인접 정점은 Enqueue로 넣고 정점은 Dequeue로 꺼낸다.

    입력 크기 n 에 대한 수행 횟수를 빅오(big-oh) 표기법으로 표현했을 때 옳지 않은 것은?

    1. 1. n^4 ＋2^n ＋5 - > O (n^4)
    2. 2. 3n^2 ＋8n＋7 - > O (n^2)
    3. 3. 2n^2 ＋2n log n＋4n - > O (n^2)
    4. 4. 3n＋5n log n＋2 - > O (n log n)

    정답 1번

    🔍 보기별 해설
    1. 지수 함수 2^n은 n이 커질수록 다항식 n^4보다 훨씬 빠르게 커져 결국 가장 큰 항이 된다. 이 식의 빅오는 2^n이어야 하는데 n^4으로 적었으므로 옳지 않다(정답).
    2. 3n^2+8n+7에서 가장 빨리 자라는 항은 n^2이고 앞의 계수 3과 낮은 차수의 항은 버린다. 결과가 O(n^2)이 되는 올바른 표기이므로 맞다.
    3. 2n^2, 2n log n, 4n 가운데 n^2이 가장 빨리 커지고 n log n과 n은 그보다 작다. 계수를 떼면 O(n^2)이 남는 올바른 표기이므로 맞다.
    4. 3n, 5n log n, 2 중에서는 n log n이 가장 빨리 커지므로 나머지 항과 계수를 버린다. 남는 O(n log n)이 정확한 표기이므로 맞다.
    🧮 풀이
    1. 甲은 n이 10이면 n^4이 만이고 2^n이 천이십사이지만 n이 40이 되면 2^n이 훨씬 커지는 표를 만들었다. 큰 n에서는 지수 항이 지배하니 결과를 O(2^n)으로 고쳐 적었다.
    2. 甲은 3n^2+8n+7에 n=1000을 넣어 각 항이 내는 값을 견주었다. n^2 항이 삼백만인데 나머지는 팔천 남짓이라 수백 배 차이가 나는 것을 보고 계수를 뗀 n^2만 남겼다.
    3. 甲은 2n^2과 2n log n을 n=1024에서 견주어 앞의 값은 약 이백만이고 뒤의 값은 약 이만임을 계산했다. n^2이 지배한다고 보고 결과를 O(n^2)로 적어 두었다.
    4. 甲은 3n+5n log n+2에서 n log n과 n을 나란히 놓고 n이 커질수록 log n 배만큼 벌어지는 것을 그래프로 그렸다. 더 빠르게 자라는 n log n만 남기고 상수와 계수를 지웠다.

    빅오는 가장 빨리 커지는 항만 남긴다. 2^n은 n^4보다 빨리 커지므로 결과는 O(n^4)이 아니라 O(2^n)이다.

    다음 의사코드(pseudo code)가 설명하는 정렬 알고리즘은?

    ○ 입력: 크기가 n인 배열 A

    ○ 출력: 정렬된 배열 A for i = 0 to n-2 min = i for j = i+1 to n-1 if(A[j] < A[min]) min = j A[i] ↔ A[min] return A

    1. 1. 버블 정렬(bubble sort)
    2. 2. 삽입 정렬(insertion sort)
    3. 3. 선택 정렬(selection sort)
    4. 4. 퀵 정렬(quick sort)

    정답 3번

    🔍 보기별 해설
    1. 버블 정렬은 이웃한 두 원소를 비교해 계속 자리를 바꾸며 큰 값을 뒤로 밀어낸다. 코드는 이웃 비교 없이 최솟값의 위치만 찾아 한 번 바꾸므로 옳지 않다.
    2. 삽입 정렬은 뒤쪽 원소를 앞의 정렬된 구간에서 알맞은 자리를 찾아 끼워 넣고 나머지를 뒤로 밀어낸다. 코드에는 원소를 밀어 자리를 만드는 과정이 없으므로 옳지 않다.
    3. 바깥 반복마다 나머지 구간에서 가장 작은 원소의 위치 min을 찾고 그것을 i번 자리와 한 번 맞바꾼다. 이 동작이 선택 정렬 그 자체이므로 옳다(정답).
    4. 퀵 정렬은 피벗을 정해 작은 값과 큰 값으로 나눈 뒤 양쪽을 재귀로 정렬한다. 코드에는 피벗도 분할도 재귀 호출도 없으므로 옳지 않다.
    🧮 풀이
    1. 甲은 5, 1, 4에서 인접한 두 수를 비교해 5와 1을 바꾸고 다시 5와 4를 바꾸며 가장 큰 수가 끝으로 흘러가는 과정을 그렸다. 이웃끼리만 바꾸는 이 움직임을 코드와 견주어 보았다.
    2. 甲은 카드 게임에서 손에 든 카드들 사이에 새로 받은 카드를 알맞은 자리에 끼워 넣는 모습을 떠올렸다. 뒤 카드들을 한 칸씩 밀어 자리를 만드는 동작을 코드에서 찾지 못해 표에 가위표를 쳤다.
    3. 甲은 29, 10, 14, 37, 13에서 가장 작은 10의 위치를 찾아 맨 앞 29와 한 번 맞바꾸는 과정을 손으로 따라갔다. 이어 남은 구간에서 다시 최솟값을 찾아 둘째 자리와 바꾸며 단계마다 적어 두었다.
    4. 甲은 6, 2, 9, 4, 7에서 첫 원소 6을 기준으로 작은 값은 왼쪽, 큰 값은 오른쪽으로 모으는 그림을 그렸다. 나뉜 양쪽을 다시 같은 방식으로 정렬한다는 것을 화살표로 표시했다.

    반복마다 남은 구간의 최솟값 위치를 찾아 맨 앞과 한 번 맞바꾸는 코드는 선택 정렬이다.

    다음 fib() 함수는 피보나치 수열을 계산한다. fib(6)을 실행할 때, fib() 함수의 호출 횟수는? (단, fib(6)의 호출은 제외한다)

    int fib(int n)

    {

    if(n == 0) return 0;

    if(n == 1) return 1;

    return ( fib(n-1) + fib(n-2) );

    }

    ○ 음수의 가중치를 가진 간선(edge)이 있어도 수행될 수 있다.

    ○ 동적 계획법(dynamic programming)의 원리를 이용한다.

    2. 2. 플로이드－워셜(Floyd-Warshall) 알고리즘

    2. 플로이드-워셜은 중간 정점을 하나씩 늘려 가며 모든 정점 쌍의 최단 거리를 표로 갱신하는 동적 계획법이다. 삼중 반복문이라 O(n^3)이고 음수 간선도 허용하므로 옳다(정답).

    4. KMP는 텍스트에서 패턴 문자열을 찾는 문자열 매칭 알고리즘이다. 그래프의 최단 거리와는 관계가 없는 알고리즘이므로 옳지 않다.

    2. 甲은 해가 주어졌을 때 다항 시간에 맞는지 확인만 하면 되는 문제들을 NP로 묶었다. 그 안에는 첫 조건만 만족하는 쉬운 문제도 들어 있어 두 조건을 모두 만족하는 것과 같지 않다고 표시했다.
    3. 甲은 NP에 속하지 않는 정지 문제를 예로 떠올렸다. 모든 NP 문제를 옮겨 올 수 있으나 NP 소속이 아니므로 둘째 조건만 만족한다고 적어 NP-하드와 NP-완전을 구분했다.
    4. 甲은 3-SAT을 예로 들어 해를 넣고 다항 시간에 검증할 수 있음과 다른 NP 문제를 이 문제로 옮길 수 있음을 확인했다. 두 조건에 모두 표시하고 NP-완전 칸에 넣어 두었다.

    NP에 속하면서 모든 NP 문제를 다항 시간에 이 문제로 변환할 수 있으면 NP-완전이다.

    다음 의사코드(pseudo-code)로 표현된 알고리즘의 수행시간을 T (n) 으로 나타낼 때, T (n) 의 계산식과 T (n) 의 점근적 복잡도로 옳은 것은? (단, n 은 1보다 큰 정수이고 c 는 양의 상수이다)

    algo(n) { if (n ≤ 1) return 0; return 1 + algo(n / 2); }

    1. 1. T (n) = T ({n / 2}) + c , Θ (n)
    2. 2. T (n) = T ({n / 2}) + c , Θ (log_2 n)
    3. 3. T (n) = 2T ({n / 2}) + c , Θ (n)
    4. 4. T (n) = 2T ({n / 2}) + n , Θ (n log_2 n)

    정답 2번

    🔍 보기별 해설
    1. 식 T(n)=T(n/2)+c는 맞지만 결과가 Θ(n)은 아니다. n을 절반씩 줄이면 log2 n번 만에 1이 되고 호출마다 c가 들어 Θ(log2 n)이므로 옳지 않다.
    2. algo(n)은 algo(n/2)를 한 번만 부르고 상수 c의 일을 하므로 T(n)=T(n/2)+c다. n을 절반씩 줄여 log2 n번 만에 끝나므로 Θ(log2 n)이라서 옳다(정답).
    3. 식에 2T(n/2)가 들어 있어 재귀 호출이 두 번이라고 말하는데, 이 코드의 호출은 한 번뿐이다. 호출 수와 식의 계수가 맞지 않으므로 옳지 않다.
    4. 2T(n/2)+n은 절반씩 나눈 두 문제를 풀고 합치는 데 n이 드는 병합 정렬형 점화식이다. 이 코드에는 두 번째 호출도 합치는 비용도 없으므로 옳지 않다.
    🧮 풀이
    1. 甲은 algo(16)을 따라가 algo(8), algo(4), algo(2), algo(1)로 다섯 번 호출됨을 세었다. 호출당 상수 c이고 n이 절반씩 줄어 다섯 번뿐이라 n에 비례하지 않는다고 적었다.
    2. 甲은 n을 2로 계속 나누면 몇 번 만에 1이 되는지를 n=1024에서 세어 10번임을 얻었다. 호출마다 c씩 드니 c·log2 n이라 식으로 정리해 Θ(log2 n)이라고 적었다.
    3. 甲은 함수 본문에 재귀 호출이 한 번뿐인데 식에 2T가 적힌 보기를 훑어보았다. 호출 수와 식의 계수가 서로 맞지 않는다는 점을 짚어 그 보기를 후보 목록에서 지워 두었다.
    4. 甲은 병합 정렬이 두 절반을 각각 정렬하고 합치는 데 n이 드는 2T(n/2)+n의 형태임을 떠올렸다. 이 코드에는 합치는 비용도 두 번째 호출도 없어 그 식은 병합 정렬에 해당한다고 옆에 적었다.

    호출이 하나이고 n을 절반으로 줄이므로 T(n)=T(n/2)+c이며 c가 log2 n번 더해져 Θ(log2 n)이다.
