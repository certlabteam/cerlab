    알고리즘의 조건에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄱ. 모든 명령은 모호하지 않고 명확해야 한다.

    ㄴ. 모든 명령은 실행 가능한 연산이어야 한다.

    ㄷ. 모든 명령은 반복적으로 무한히 실행되어야 한다.

    1. 1. ㄱ
    2. 2. ㄱ, ㄴ
    3. 3. ㄴ, ㄷ
    4. 4. ㄱ, ㄴ, ㄷ

    정답 2번

    🔍 보기별 해설
    1. 알고리즘의 각 명령은 실행자가 같은 입력에 같은 동작을 적용하도록 모호함 없이 적어야 한다. 명확성 조건에 해당하므로 옳다.
    2. 알고리즘의 단계는 컴퓨터나 실행자가 제한된 시간 안에 실제로 수행 가능한 기본 연산이어야 한다. 유효성 조건에 해당하므로 옳다.
    3. 알고리즘은 정해진 결과를 내고 유한한 단계 뒤에 실행을 끝내야 한다. 명령을 아무 조건 없이 무한히 반복해야 한다는 설명은 옳지 않다.
    🧮 풀이
    1. 정렬 절차에 ‘두 값 중 작은 값을 앞으로 옮긴다’고 명시하면 비교 대상과 동작이 정해진다. 수행자는 같은 입력에서 같은 단계를 실행할 수 있다. ‘적당히 정리한다’처럼 판단이 흔들리는 명령은 쓰지 않는다.
    2. 두 정수를 비교하고 배열 칸을 서로 바꾸는 연산은 실제 컴퓨터가 수행할 수 있다. 알고리즘의 단계마다 입력을 받아 계산 가능한 동작이 정해져 있다. 실행할 수 없는 명령을 넣으면 절차가 완성되지 않는다.
    3. 배열을 앞에서 뒤로 한 번 훑는 탐색은 끝에 도달하면 성공 또는 실패를 반환한다. 배열 끝에서도 계속 처음으로 돌아가 아무 조건 없이 반복하면 결과를 내지 못한다. 종료 조건이 있어야 알고리즘이 된다.

    정답은 2번이다.

    알고리즘의 수행 시간 분석에 대한 설명으로 옳지 않은 것은?

    1. 1. 알고리즘의 수행 시간은 컴퓨터 성능에 관계없이 명확하게 정의되어야 한다.
    2. 2. 알고리즘의 시간복잡도는 수행하는 기본적인 연산 횟수를 입력 크기에 대한 함수로 표현한다.
    3. 3. 최선의 경우의 알고리즘 수행 시간은 모든 입력의 수행 시간에 대한 상한이 된다.
    4. 4. 알고리즘의 수행 시간 분석에는 최악의 경우, 평균의 경우, 최선의 경우가 있다.

    정답 3번

    🔍 보기별 해설
    1. 수행 시간 분석은 특정 컴퓨터의 초 단위 속도보다 연산 횟수를 기준으로 정의할 수 있다. 기종과 독립된 분석을 뜻하므로 옳다.
    2. 시간복잡도는 비교나 대입 같은 기본 연산이 입력 크기 n에 따라 몇 번 실행되는지 함수로 나타낸다. 하드웨어와 구별한 분석 정의에 맞으므로 옳다.
    3. 최선의 경우는 가능한 입력 중 수행 시간이 가장 적은 경우다. 모든 입력 시간의 상한이라는 설명은 옳지 않다(정답).
    4. 입력 데이터의 배치에 따라 최악·평균·최선의 수행 시간을 각각 구별해 분석할 수 있다. 세 경우를 비교하는 대표적인 분석 관점이므로 옳다.
    🧮 풀이
    1. 두 컴퓨터가 같은 정렬 코드를 실행하면 실제 밀리초는 다를 수 있다. 그러나 입력 n개를 비교하는 횟수의 증가 형태는 같은 알고리즘에서 분석할 수 있다. 하드웨어 성능에 좌우되는 시간을 그대로 복잡도의 정의로 삼지 않는다.
    2. 선형 탐색은 원소 n개를 담은 배열에서 찾는 값이 마지막에 있으면 n번 비교한다. 입력 크기가 바뀌면 비교 횟수도 달라진다. 이를 n에 대한 함수로 적어 수행 시간을 분석한다.
    3. 선형 탐색에서 찾는 값이 배열 첫 칸에 있으면 한 번만 비교한다. 마지막 칸에 있으면 n번 비교한다. 최선 시간 1은 가능한 시간 가운데 작은 값이지 모든 입력을 덮는 상한이 아니다.
    4. 탐색 대상이 첫 칸에 있을 때, 임의 위치에 있을 때, 마지막 칸에 있을 때의 비교 횟수를 각각 살핀다. 첫 경우는 최선, 마지막 경우는 최악이며 입력 분포를 정하면 평균도 계산할 수 있다. 분석 관점마다 값이 달라진다.

    최선 수행 시간은 입력별 수행 시간의 하한이므로 정답은 3번이다.

    입력 크기 n 에 대한 수행 횟수를 빅오(big-oh) 표기법으로 표현했을 때 옳지 않은 것은?

    1. 1. n^4 ＋2^n ＋5 - > O (n^4)
    2. 2. 3n^2 ＋8n＋7 - > O (n^2)
    3. 3. 2n^2 ＋2n log n＋4n - > O (n^2)
    4. 4. 3n＋5n log n＋2 - > O (n log n)

    정답 1번

    🔍 보기별 해설
    1. n⁴+2ⁿ+5에서는 지수항 2ⁿ이 다항항 n⁴보다 빠르게 증가한다. 전체를 O(n⁴)로 묶을 수 없으므로 옳지 않다(정답).
    2. 3n²+8n+7에서는 입력 n이 커질 때 제곱항 n²이 나머지 항보다 빠르게 커진다. 상수와 낮은 차수 항을 빼고 O(n²)로 나타내므로 옳다.
    3. 2n²+2n log n+4n에서는 입력이 커질 때 n² 항이 n log n과 n보다 더 빠르게 커진다. O(n²)라는 점근적 상한 표현이 맞으므로 옳다.
    4. 3n+5n log n+2에서는 상수항과 선형항보다 n log n 항이 더 빠르게 증가한다. 지배항을 기준으로 O(n log n)으로 표현할 수 있으므로 옳다.
    🧮 풀이
    1. 입력 n이 커질수록 2ⁿ을 n⁴의 일정 배수 안에 계속 가둘 수 없다. 예를 들어 충분히 큰 n에서는 지수항이 다항항을 앞질러 격차를 넓힌다. 전체 식의 증가율을 n⁴만으로 제한하는 상한은 성립하지 않는다.
    2. n=100이면 3n²은 30000이고 8n+7은 807이다. n이 더 커질수록 제곱항의 영향이 커진다. 고정 계수 3과 낮은 차수 항을 제거해도 증가 차수는 n²로 남는다.
    3. n이 커지면 n log n과 n보다 n² 항이 더 빠르게 증가한다. 세 항을 모두 계산해도 n²의 상수배로 상한을 둘 수 있다. 따라서 최고 성장 항 n²가 빅오 표기를 결정한다.
    4. n=1000인 입력에서 n log n 항은 선형 n보다 더 크게 증가한다. 상수 5와 나머지 3n·2는 점근적 증가 차수를 바꾸지 않는다. 전체 반복 횟수의 상한을 n log n으로 표현한다.

    2ⁿ은 n⁴보다 빨리 커지므로 첫 식은 O(n⁴)가 아니고 정답은 1번이다.

    다음 의사코드(pseudo code)가 설명하는 정렬 알고리즘은?

    ○ 입력: 크기가 n인 배열 A

    ○ 출력: 정렬된 배열 A for i = 0 to n-2 min = i for j = i+1 to n-1 if(A[j] < A[min]) min = j A[i] ↔ A[min] return A

    1. 1. 버블 정렬(bubble sort)
    2. 2. 삽입 정렬(insertion sort)
    3. 3. 선택 정렬(selection sort)
    4. 4. 퀵 정렬(quick sort)

    정답 3번

    🔍 보기별 해설
    1. 버블 정렬은 이웃한 두 값을 반복 비교·교환해 큰 값 등을 끝으로 보낸다. 남은 구간의 최소 위치를 찾아 한 번 교환하는 코드와 다르므로 옳지 않다.
    2. 삽입 정렬은 새 값을 앞의 정렬된 부분에 맞는 위치로 밀어 넣는다. 최소 인덱스를 찾는 반복 구조와 다르므로 옳지 않다.
    3. 선택 정렬은 현재 위치부터 끝까지 최솟값의 인덱스를 찾아 현재 위치와 바꾼다. min과 교환을 쓰는 코드에 맞으므로 옳다(정답).
    4. 퀵 정렬은 피벗을 기준으로 자료를 분할하고 부분 배열에 재귀적으로 적용한다. 이 코드에는 피벗·분할·재귀가 없으므로 옳지 않다.
    🧮 풀이
    1. 배열 [4,2,3]의 이웃 4와 2를 비교해 바꾸고 다음 이웃 4와 3을 비교해 바꾼다. 큰 값 4가 끝으로 이동하는 과정은 버블 정렬이다. 전체 남은 구간에서 최솟값 인덱스를 하나 찾는 코드와 움직임이 다르다.
    2. 배열 [2,4,3]에서 새 값 3을 정렬된 앞부분 [2,4] 사이에 넣는다. 4를 한 칸 밀고 3을 그 자리에 놓는다. 최소 위치를 전체 미정렬 구간에서 찾는 절차가 아니다.
    3. 배열 [4,2,3]에서 i=0일 때 min은 값 2의 인덱스 1이 된다. A[0]과 A[1]을 바꿔 [2,4,3]을 만든다. 다음 i=1에서 남은 [4,3]의 최솟값 3을 골라 [2,3,4]로 마친다.
    4. 배열에서 3을 피벗으로 골라 3보다 작은 값과 큰 값을 양쪽으로 나눈다. 양쪽 부분 배열을 다시 정렬하는 것은 퀵 정렬의 흐름이다. 제시된 코드는 피벗 없이 매 회차 최솟값 하나를 선택한다.

    매 위치에서 남은 구간의 최솟값을 찾아 교환하는 코드는 선택 정렬이므로 정답은 3번이다.

    1. 정렬된 목록에서 특정 값이 있는지 다항식 시간에 판정할 수 있다. 이런 문제는 P에 속할 수 있지만 그 사실만으로 모든 NP 문제의 대표적 난도를 가진다고 말할 수 없다. 환원 조건을 별도로 확인해야 한다.
    2. 어떤 배치가 규칙을 만족하는지 후보 답을 받아 짧은 시간에 검사할 수 있다. 검증 가능성만 확인하면 NP 소속을 말할 수 있다. 다른 모든 NP 문제를 이 문제로 환원할 수 있는지는 아직 알 수 없다.
    3. 문제 B로 모든 NP 문제를 다항식 시간에 바꿔 풀 수 있다고 하자. 이 조건은 B가 NP·하드임을 뜻한다. B 자체의 답을 다항식 시간에 검증할 수 있는지 확인하지 않으면 NP·완전이라고 할 수 없다.
    4. SAT 문제는 해인 진리값 배치를 빠르게 검증할 수 있고 다른 NP 문제를 다항식 시간에 SAT로 바꿀 수 있다. NP 소속과 NP·하드 조건이 함께 성립한다. 이 두 조건을 모두 요구하는 분류가 NP·완전이다.

    NP에 속하고 모든 NP 문제가 다항식 환원되는 문제는 NP·완전이므로 정답은 4번이다.

    다음 의사코드(pseudo-code)로 표현된 알고리즘의 수행시간을 T (n) 으로 나타낼 때, T (n) 의 계산식과 T (n) 의 점근적 복잡도로 옳은 것은? (단, n 은 1보다 큰 정수이고 c 는 양의 상수이다)

    algo(n) { if (n ≤ 1) return 0; return 1 + algo(n / 2); }

    1. 1. T (n) = T ({n / 2}) + c , Θ (n)
    2. 2. T (n) = T ({n / 2}) + c , Θ (log_2 n)
    3. 3. T (n) = 2T ({n / 2}) + c , Θ (n)
    4. 4. T (n) = 2T ({n / 2}) + n , Θ (n log_2 n)

    정답 2번

    🔍 보기별 해설
    1. 한 호출에서 크기 n/2의 재귀 호출 한 번과 상수 작업만 수행한다. T(n)=T(n/2)+c이고 깊이가 log₂n이므로 옳다(정답).
    🧮 풀이
    1. ① algo(16)은 1+algo(8)을 호출한다. 한 단계에 재귀 함수가 하나만 생기므로 앞에 2T(8)을 쓰지 않는다.
    2. → T(16)=T(8)+c
    3. ↓
    4. ② 입력은 16→8→4→2→1로 절반씩 줄어든다. 일반적인 n에서 2^k≥n이면 종료하므로 단계 수는 log₂n 차수다.
    5. → k≈log₂n
    6. ↓
    7. ③ 각 단계의 더하기와 비교가 상수 시간이다. 상수 작업을 log₂n 단계에 걸쳐 합한다.
    8. → Θ(log₂n)

    재귀 호출 하나마다 n을 절반으로 줄여 T(n)=T(n/2)+c, Θ(log₂n)이므로 정답은 2번이다.
