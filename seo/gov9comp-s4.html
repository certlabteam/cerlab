    대표적인 반도체 메모리인 DRAM과 SRAM에 대한 설명으로 옳지 않은 것은?

    1. 1. DRAM은 휘발성이지만 SRAM은 비휘발성이어서 전원이 공급되지 않아도 기억을 유지할 수 있다.
    2. 2. DRAM은 축전기(Capacitor)의 충전상태로 비트를 저장한다.
    3. 3. SRAM은 주로 캐시 메모리로 사용된다.
    4. 4. 일반적으로 SRAM의 접근속도가 DRAM보다 빠르다.

    정답 1번

    🔍 보기별 해설
    1. DRAM(Dynamic Random Access Memory)과 SRAM(Static Random Access Memory)은 모두 전원 공급이 중단되면 저장 내용을 잃는다. SRAM만 비휘발성이라는 설명은 옳지 않다(정답).
    2. DRAM(Dynamic Random Access Memory)은 축전기 전하의 유무로 0과 1을 표현한다. 전하가 새어 나가 재충전도 필요하므로 옳다.
    3. SRAM(Static Random Access Memory)은 플립플롭으로 값을 유지하며 빠르게 접근할 수 있다. 프로세서 캐시에 주로 쓰이므로 옳다.
    4. SRAM(Static Random Access Memory)은 재충전이 필요 없는 플립플롭 구조라 DRAM보다 접근이 빠른 편이다. 속도 비교가 맞으므로 옳다.
    🧮 풀이
    1. 실행 중인 컴퓨터의 DRAM 주기억장치와 SRAM 캐시에 서로 다른 값을 올렸다. 전원 공급을 끊었다가 다시 켜니 두 메모리의 값이 모두 사라졌다. 저장장치의 파일은 남았지만 두 반도체 메모리는 휘발성이었다.
    2. DRAM 셀의 작은 축전기에 전하를 채워 비트 1을 기록했다. 시간이 지나 전하가 누설되자 제어기가 읽고 다시 써 전하를 보충했다. 이 재충전 주기를 놓치면 저장 비트를 안정적으로 유지할 수 없었다.
    3. 프로세서가 반복해 읽는 데이터를 SRAM 캐시에 놓았다. 플립플롭 셀이 전원 공급 동안 비트를 유지해 축전기 재충전 대기 없이 데이터를 내놓았다. 작고 빠른 캐시가 주기억장치 접근 횟수를 줄였다.
    4. 같은 데이터를 SRAM 캐시와 DRAM 주기억장치에서 차례로 읽었다. 프로세서에 가까운 SRAM은 셀 구조와 접근 경로 덕분에 더 빠르게 값을 돌려주었다. 용량은 작아도 자주 쓰는 자료를 캐시에 두는 이유가 됐다.

    DRAM과 SRAM은 모두 전원이 끊기면 데이터가 사라지는 휘발성 메모리다. SRAM을 비휘발성이라 한 1번이 옳지 않다.

    정렬 알고리즘 중 최악의 경우를 가정할 때 시간복잡도가 다른 것은?

    1. 1. 삽입 정렬(Insertion sort)
    2. 2. 쉘 정렬(Shell sort)
    3. 3. 버블 정렬(Bubble sort)
    4. 4. 힙 정렬(Heap sort)

    정답 4번

    🔍 보기별 해설
    1. 삽입 정렬은 역순 입력에서 각 원소를 앞의 모든 원소와 비교·이동해 O(n²)이 된다. 다른 세 알고리즘과 다른 최악 차수가 아니므로 옳지 않다.
    2. 쉘 정렬의 최악 시간복잡도는 간격 수열에 좌우되며 통상적인 교재의 간격 설정에서는 O(n²)로 분류한다. 이 문항의 다른 값이 아니므로 옳지 않다.
    3. 버블 정렬은 이웃 원소를 반복 비교해 최악에 약 n(n−1)/2번 비교한다. O(n²)이므로 다른 차수를 고르는 답은 옳지 않다.
    4. 힙 정렬은 힙에서 최댓값을 꺼낼 때마다 O(log n)의 재정렬을 n번 수행한다. 최악에도 O(n log n)이라 다른 셋과 달라 옳다(정답).
    🧮 풀이
    1. 큰 수부터 작은 수로 놓인 배열을 삽입 정렬로 오름차순 정렬했다. 새 원소마다 앞의 정렬된 값들을 연달아 밀어야 했다. 원소가 n개면 비교·이동 횟수가 삼각수처럼 늘어 입력이 커질수록 제곱 차수가 드러났다.
    2. 쉘 정렬에서 간격을 넓게 시작해 점차 1로 줄이는 수열을 적용했다. 각 간격의 부분 배열을 삽입 정렬하면서 입력 배치에 따라 비교 횟수가 달라졌다. 통상적인 간격 설정의 최악 경우는 제곱 차수로 분류됐다.
    3. 역순 배열을 버블 정렬하자 큰 값이 한 차례마다 뒤쪽으로 이동했다. 첫 차례에 n−1번, 다음에 n−2번 비교하는 흐름이 이어졌다. 총 비교 횟수가 n(n−1)/2에 가까워 O(n²)이 됐다.
    4. 배열을 최대 힙으로 만든 뒤 루트의 최댓값을 배열 끝으로 옮겼다. 남은 힙에서 루트를 내려보내는 데 트리 높이만큼인 log n 단계가 들었다. 이 추출을 n번 반복해도 최악 시간은 O(n log n)이었다.

    삽입·쉘·버블 정렬은 제시한 최악 시간복잡도를 O(n²)로 다루고 힙 정렬은 O(n log n)이다. 4번이 옳다.

    기계 학습에서 지도 학습과 비지도 학습에 대한 설명으로 옳은 것은?

    1. 1. 지도 학습의 대표적인 기법에는 군집화가 있다.
    2. 2. 비지도 학습의 기법에는 분류와 회귀분석 등이 있다.
    3. 3. 지도 학습은 학습 알고리즘이 수행한 행동에 대해 보상을 받는 학습 방식이다.
    4. 4. 비지도 학습은 정답이 없는 데이터를 보고 유용한 패턴을 추출하는 학습 방식이다.

    정답 4번

    🔍 보기별 해설
    1. 군집화는 정답 레이블 없이 비슷한 자료를 묶는 비지도 학습 기법이다. 지도 학습의 대표 기법이라는 설명은 옳지 않다.
    2. 분류와 회귀는 입력과 정답이 짝지어진 자료로 예측 규칙을 배우는 지도 학습이다. 비지도 학습이라는 설명은 옳지 않다.
    3. 행동의 결과로 보상을 받아 정책을 개선하는 방식은 강화 학습이다. 지도 학습의 정의로 든 것은 옳지 않다.
    4. 비지도 학습은 정답 표지가 없는 데이터에서 군집이나 잠재 구조를 찾는다. 유용한 패턴 추출이라는 설명이 맞으므로 옳다(정답).
    🧮 풀이
    1. 고객 구매 기록에 미리 정한 고객 유형 표지를 붙이지 않고 군집화 모델에 넣었다. 모델은 구매 품목이 비슷한 고객들을 여러 집단으로 묶었다. 정답표를 보고 맞히는 과정 없이 자료의 유사성이 집단을 만들었다.
    2. 스팸으로 표시된 이메일과 정상으로 표시된 이메일을 학습 자료로 준비했다. 분류 모델이 메일 내용과 정답 표지의 관계를 학습한 뒤 새 메일의 종류를 예측했다. 정답을 이용하는 지도 학습이었다.
    3. 게임 에이전트가 여러 행동을 시도하고 점수를 받도록 환경을 만들었다. 높은 보상을 준 행동이 다음 선택에서 더 자주 나타나도록 정책을 바꿨다. 미리 붙인 분류 정답 대신 행동의 보상을 학습 신호로 썼다.
    4. 정답 표지가 없는 서버 사용 기록을 비지도 모델에 입력했다. 접속 시간과 사용량이 비슷한 기록들이 묶였고 특이한 기록은 멀리 떨어졌다. 운영자는 이 패턴으로 일반 사용군과 이상 사용군을 구별할 단서를 얻었다.

    정답 표지가 없는 자료에서 내부 구조를 찾는 것은 비지도 학습이다. 4번이 옳다.

    무선주파수를 이용하며 반도체 칩이 내장된 태그와 리더기로 구성된 인식시스템은?

    1. 1. RFID
    2. 2. WAN
    3. 3. Bluetooth
    4. 4. ZigBee

    정답 1번

    🔍 보기별 해설
    1. RFID(Radio Frequency Identification)는 태그의 칩 정보를 무선주파수 리더기로 읽어 물체를 식별한다. 제시한 시스템이므로 옳다(정답).
    2. WAN(Wide Area Network)은 떨어진 지역의 컴퓨터망을 넓은 범위로 연결한다. 태그와 리더기로 사물을 읽는 체계가 아니므로 옳지 않다.
    3. Bluetooth는 가까운 기기 사이 자료를 주고받는 무선 통신 규격이다. 반도체 태그 식별 시스템 자체가 아니므로 옳지 않다.
    4. ZigBee는 저전력 센서와 기기들이 근거리에서 통신하는 네트워크 규격이다. RFID 태그·리더기 체계가 아니므로 옳지 않다.
    🧮 풀이
    1. 물류 상자마다 칩이 든 태그를 붙이고 출고문에 리더기를 설치했다. 상자가 문을 지나자 무선주파수 신호로 태그 식별자가 읽혀 재고 목록이 갱신됐다. 카메라로 글자를 촬영하거나 상자마다 접촉할 필요가 없었다.
    2. 서울 본사와 다른 지역 지사의 사내망을 통신 회선으로 연결했다. 두 지역의 컴퓨터가 같은 업무망 자원에 접근했다. 넓은 지역의 망을 잇는 WAN은 상자 표면의 작은 칩을 읽는 장치와 달랐다.
    3. 노트북과 무선 이어폰을 Bluetooth로 연결했다. 가까운 두 기기가 음성 데이터를 주고받아 이어폰에서 소리가 났다. 물류 상자에 붙인 태그의 식별자를 고정 리더기로 일괄 읽는 방식과 구별됐다.
    4. 건물의 온도 센서와 조명 제어기를 ZigBee 망에 연결했다. 적은 전력으로 여러 센서가 서로 측정값과 제어 명령을 보냈다. 태그의 고유 번호를 출입문 리더기로 읽는 RFID 시스템은 사용하지 않았다.

    태그의 반도체 칩을 무선주파수 리더기로 읽어 물체를 식별하는 방식은 RFID다. 1번이 옳다.

    클라우드 컴퓨팅에 대한 설명으로 옳지 않은 것은?

    1. 1. 클라우드 컴퓨팅은 기업의 IT 요구를 매우 경제적이고, 신뢰성 있게 충족시킬 수 있는 수단이 된다.
    2. 2. 클라우드 컴퓨팅 서비스 모델에는 IaaS, PaaS, SaaS가 있다.
    3. 3. 클라우드 컴퓨팅을 이용하는 방식에는 사설 클라우드, 공용 클라우드, 하이브리드 클라우드가 있다.
    4. 4. IaaS를 통해 사용자는 소프트웨어 설치 및 유지보수에 대한 비용을 절감할 수 있다.

    정답 4번

    🔍 보기별 해설
    1. 클라우드는 필요한 자원을 사용량에 따라 빌려 초기 설비비와 운영 부담을 조정할 수 있다. 기업의 IT 수요를 경제적으로 채울 수 있어 옳다.
    2. IaaS(Infrastructure as a Service)는 인프라, PaaS(Platform as a Service)는 개발 플랫폼, SaaS(Software as a Service)는 완성된 소프트웨어를 제공한다. 서비스 모델 목록이 맞아 옳다.
    3. 사설 클라우드는 단일 조직용, 공용 클라우드는 여러 사용자용, 하이브리드는 둘을 결합한 배치 방식이다. 이용 방식 구분이 맞아 옳다.
    4. IaaS(Infrastructure as a Service)는 가상 서버와 저장소를 주지만 응용 소프트웨어의 설치·유지보수는 사용자가 맡는다. 그 부담을 덜어 주는 SaaS의 특징을 IaaS에 붙여 옳지 않다(정답).
    🧮 풀이
    1. 소규모 서비스가 방문량이 늘 때만 클라우드 서버 수를 늘리고 줄어들면 다시 축소했다. 자체 서버실을 처음부터 크게 사지 않아도 요청을 처리했다. 사용량과 장애 대응 방식에 맞춰 비용과 가용성을 관리했다.
    2. 개발팀은 가상 서버를 빌릴 때 IaaS, 실행 환경을 빌릴 때 PaaS, 완성된 협업 프로그램을 구독할 때 SaaS를 선택했다. 같은 클라우드라도 제공자가 관리하는 범위가 달랐다. 필요한 계층에 따라 계약을 나눴다.
    3. 민감한 내부 자료는 회사 전용 사설 환경에 두고 공개 웹 서비스는 공용 클라우드에 배치했다. 두 환경의 통신을 연결해 하나의 업무 흐름으로 운영했다. 사설과 공용을 함께 쓰는 하이브리드 배치였다.
    4. 가상 서버만 빌린 개발팀은 운영체제와 응용 프로그램을 직접 설치했다. 보안 패치와 버전 교체도 팀이 수행해야 서비스가 계속 작동했다. 소프트웨어 관리를 제공자에게 맡긴 SaaS와 책임 범위가 달랐다.

    IaaS는 서버·저장소를 빌려 주고 운영체제와 응용 소프트웨어의 설치·관리는 사용자가 맡는다. 비용 절감을 IaaS에 돌린 4번이 옳지 않다.

    C 언어에서 함수 호출 시 매개변수 전달 방법에는 값에 의한 호출(Call by Value)과 참조에 의한 호출(Call by Reference)이 있다. C 프로그램 코드가 다음과 같을 때 설명으로 옳지 않은 것은?

    int get_average(int score[], int n) { int i, sum; for(i = 0; i < n; i++) sum += score[i]; return sum / n; } void main(void) { int score[3] = { 1, 2, 5 }; printf(“%d\n”, get_average(score, 3)); }

    1. 1. 전달할 데이터의 양이 많을 경우에는 참조에 의한 호출이 효율적이다.
    2. 2. 값에 의한 호출로 전달된 데이터는 호출된 함수에서 값을 변경하더라도 함수 종료 후 해당 함수를 호출한 상위 함수에 반영되지 않는다.

    정답 2번

    2. 정수 배열의 첫 칸에 10을 넣고 ap가 그 칸을 가리키게 했다. `*ap`에서 10을 읽은 뒤 1을 더해 출력하니 11이 나왔다. 기준 표현식 `ary[1]`도 둘째 칸의 11을 읽었다.

    자료 흐름의 방향과 동시성 여부에 따라 분류한 통신 방식 중 다음에서 설명하는 통신 방식으로 옳은 것은? (단, DTE(Data Terminal Equipment)는 컴퓨터, 휴대폰, 단말기 등과 같이 통신망에서 네트워크의 끝에 연결된 장치들을 총칭하는 용어이다)

    4. 멀리 떨어진 두 사무소를 장거리 회선으로 연결했다. 거리만으로는 동시에 말할 수 있는지 또는 순서를 기다려야 하는지가 정해지지 않았다. 별도로 사용한 채널의 송수신 규칙이 동시성 방식을 결정했다.

    TCP(Transmission Control Protocol) 기반 응용 프로토콜에 해당하지 않는 것은?

    1. 1. Telnet
    2. 2. FTP
    3. 3. SMTP
    4. 4. SNMP

    정답 4번

    🔍 보기별 해설
    1. Telnet은 원격 단말 접속에서 TCP(Transmission Control Protocol) 연결을 사용한다. TCP 기반이 아닌 프로토콜로 고르면 옳지 않다.
    2. FTP(File Transfer Protocol)는 제어와 파일 전송에 TCP 연결을 사용한다. TCP 기반이 아닌 것으로 고르면 옳지 않다.
    3. SMTP(Simple Mail Transfer Protocol)는 메일 서버 사이의 메시지 전달에 TCP를 사용한다. TCP 기반이 아닌 것으로 고르면 옳지 않다.
    4. SNMP(Simple Network Management Protocol)는 장비 상태 조회와 알림에 주로 UDP(User Datagram Protocol)를 사용한다. TCP 기반 응용 프로토콜이 아니므로 옳지 않다(정답).
    🧮 풀이
    1. 관리용 단말에서 원격 서버에 Telnet 세션을 열었다. 먼저 TCP 연결이 성립한 뒤 입력한 명령과 서버 응답이 같은 연결을 통해 오갔다. 서버 접속이 유지되는 동안 바이트 흐름의 순서가 보장됐다.
    2. 웹 서버에 파일을 올리려고 FTP 클라이언트가 서버와 제어 연결을 맺었다. 파일 데이터도 별도의 TCP 연결로 보내 전송 순서를 유지했다. 손실된 세그먼트는 TCP가 재전송해 파일을 완성했다.
    3. 메일 클라이언트가 SMTP 서버의 전송 포트에 TCP 연결을 열었다. 연결 위에서 받는 사람과 본문을 순서대로 보내고 서버의 응답을 받았다. 메일 전송 절차가 TCP 바이트 흐름에 실렸다.
    4. 네트워크 관리 서버가 스위치 상태를 짧은 SNMP 요청으로 조회했다. 요청과 응답은 일반적으로 UDP 데이터그램으로 전달됐다. 다음 주기에도 다시 조회하므로 매 조회마다 TCP 연결을 여는 방식이 아니었다.

    Telnet·FTP·SMTP는 TCP를 쓰지만 장비 관리를 위한 SNMP는 주로 UDP를 쓴다. 4번이 옳지 않다.

    운영체제에서 프로세스의 정보를 관리하는 프로세스 제어블록(Process Control Block)의 포함 요소로 옳지 않은 것은?

    1. 1. 프로세스 식별자
    2. 2. 인터럽트 정보
    3. 3. 프로세스의 우선순위
    4. 4. 프로세스의 상태

    정답 2번

    🔍 보기별 해설
    1. 프로세스 식별자는 운영체제가 개별 실행 단위를 구분하려고 부여하는 번호다. 프로세스 제어블록의 기본 항목이므로 옳다.
    2. 인터럽트 정보는 장치·시스템의 사건 발생과 처리에 관한 정보다. 개별 프로세스의 제어블록에 넣는 대표 항목이 아니므로 옳지 않다(정답).
    3. 프로세스 우선순위는 스케줄러가 실행 순서를 정할 때 참조하는 값이다. 프로세스마다 관리하므로 제어블록 항목으로 옳다.
    4. 프로세스 상태는 실행·준비·대기처럼 현재 어느 단계에 있는지를 기록한다. 상태 전이를 관리해야 하므로 제어블록 항목으로 옳다.
    🧮 풀이
    1. 운영체제가 두 작업을 동시에 관리하면서 각자에게 서로 다른 프로세스 식별자를 부여했다. 스케줄러는 그 번호로 해당 제어블록을 찾아 레지스터와 상태를 저장했다. 번호가 없으면 같은 이름의 작업 둘을 구별하기 어려웠다.
    2. 네트워크 장치에서 인터럽트가 발생하자 운영체제의 인터럽트 처리기가 원인을 받아 처리했다. 사건은 장치와 시스템의 처리 경로에 속했다. 한 프로세스의 고유 식별자나 상태처럼 그 프로세스만의 제어블록 항목은 아니었다.
    3. 처리해야 할 작업 둘의 우선순위를 각각 5와 10으로 설정했다. 스케줄러가 각 프로세스의 제어블록에서 이 값을 읽어 실행 순서를 골랐다. 우선순위가 바뀌면 다음 스케줄링 결정도 달라졌다.
    4. 프로세스가 입출력을 요청하자 운영체제는 상태를 실행에서 대기로 바꿨다. 입출력이 끝나면 다시 준비로 기록하고 실행 차례를 기다리게 했다. 상태값은 해당 프로세스의 제어블록에서 계속 갱신됐다.

    프로세스 제어블록은 개별 프로세스의 식별자·우선순위·상태를 담는다. 시스템 사건인 인터럽트 정보는 그 목록이 아니므로 2번이 옳지 않다.

    SSD(Solid-State Drive)에 대한 설명으로 옳지 않은 것은?

    1. 1. 반도체 기억장치 칩들을 이용하여 구성된 저장장치이다.
    2. 2. 하드디스크에 비해 저장용량 대비 가격이 비싸다.
    3. 3. 기계적 장치를 사용하여 하드디스크보다 데이터 입출력 속도가 빠르다.
    4. 4. 하드디스크를 대체하려고 개발한 저장장치로서 플래시 메모리로 구성된다.

    정답 3번

    🔍 보기별 해설
    1. SSD(Solid-State Drive)는 플래시 메모리 칩과 제어기로 이루어진 저장장치다. 반도체 칩을 쓴다는 설명이므로 옳다.
    2. SSD는 플래시 칩 가격 때문에 같은 용량의 하드디스크보다 저장 단가가 높은 편이다. 용량 대비 가격 설명이므로 옳다.
    3. SSD에는 회전판이나 이동 헤드가 없어 기계적 탐색 대기가 없다. 기계 장치를 사용해서 빠르다는 설명은 옳지 않다(정답).
    4. SSD는 플래시 메모리를 사용해 하드디스크의 저장장치 역할을 대체한다. 매체와 개발 목적의 설명이므로 옳다.
    🧮 풀이
    1. 노트북의 SSD 덮개를 열어 기판 위 플래시 칩과 제어기를 확인했다. 데이터를 쓰면 전하 상태가 반도체 셀에 저장됐다. 원판이 돌거나 읽기 헤드가 이동하는 기계 부품은 들어 있지 않았다.
    2. 같은 1TB 용량의 SSD와 하드디스크 견적을 비교했다. 반도체 플래시를 쓰는 SSD의 가격이 더 높게 나왔다. 구매 계획은 빠른 접근이 필요한 시스템용에 SSD를 우선 배치했다.
    3. 무작위 위치에 저장된 작은 파일을 연달아 읽었다. 하드디스크는 헤드를 옮기고 회전 위치를 기다렸지만 SSD는 전자적으로 셀에 접근했다. SSD의 짧은 지연은 기계 부품이 없기 때문에 생겼다.
    4. 하드디스크가 장착된 노트북에서 기존 저장장치를 SSD로 교체했다. 운영체제와 파일을 플래시 메모리 셀로 옮겼고 저장 기능은 그대로 유지됐다. 물리 매체는 회전 자기 디스크에서 반도체로 바뀌었다.

    SSD는 회전판·헤드 없이 반도체 칩에 저장한다. 기계 장치 때문에 빠르다는 3번이 옳지 않다.

    다음 후위 표기 식을 전위 표기 식으로 변환하였을 때 옳은 것은?

    3 1 4 1 － * ＋

    1. 1. 3 ＋ 1 * 4 － 1
    2. 2. 4 － 1 * 1 ＋ 3
    3. 3. ＋ 3 * 1 － 4 1
    4. 4. ＋ 3 － 4 1 * 1

    정답 3번

    🔍 보기별 해설
    1. 후위식은 3+1×(4−1)로 묶인다. 연산자를 각 피연산자 앞에 놓은 + 3 * 1 − 4 1이므로 3번이 옳다(정답).
    🧮 풀이
    1. ① 후위식 `3 1 4 1 − * +`를 왼쪽부터 읽는다. 앞의 네 숫자 3·1·4·1을 순서대로 스택에 넣는다.
    2. → 스택: 3 | 1 | 4 | 1
    3. ↓
    4. ② `−`를 만나 마지막 두 값 4와 1을 결합한다. 이어 `*`는 남은 1과 뺄셈 결과를 결합한다.
    5. → 4−1, 이어 1×(4−1)
    6. ↓
    7. ③ 마지막 `+`는 3과 곱셈 결과를 결합한다. 연산자를 각 결합의 앞에 배치해 전위 표기로 쓴다.
    8. → + 3 * 1 − 4 1

    후위식의 연산 순서는 4−1, 그 결과에 1을 곱하기, 마지막으로 3 더하기다. 전위식은 + 3 * 1 − 4 1이므로 3번이다.

    운영체제의 세마포어(Semaphore)에 대한 설명으로 옳지 않은 것은?

    1. 1. 프로세스 간 상호배제(Mutual Exclusion)의 원리를 보장하는 데 사용된다.
    2. 2. 여러 개의 프로세스가 동시에 그 값을 수정하지 못한다.
    3. 3. 세마포어에 대한 연산은 수행 중에 인터럽트 될 수 있다.
    4. 4. 세마포어는 플래그 변수와 그 변수를 검사하거나 증감시키는 연산들로 정의된다.

    정답 3번

    🔍 보기별 해설
    1. 세마포어는 임계구역에 들어갈 수 있는 프로세스 수를 제어해 상호배제를 구현한다. 동기화 도구의 용도를 맞게 적어 옳다.
    2. 세마포어 값을 바꾸는 wait·signal 연산은 원자적으로 처리된다. 여러 프로세스가 같은 값을 동시에 수정하지 못하므로 옳다.
    3. 세마포어의 검사와 값 변경 사이가 끊기면 둘 이상의 프로세스가 같은 자리를 차지할 수 있다. 연산이 수행 중 인터럽트될 수 있다는 설명은 옳지 않다(정답).
    4. 세마포어는 정수 상태값과 이를 검사·증감하는 원자적 연산으로 정의한다. 구성 요소를 맞게 설명하므로 옳다.
    🧮 풀이
    1. 공유 파일을 수정하는 프로그램 두 개 앞에 값 1인 세마포어를 놓았다. 첫 프로그램이 들어가면 값이 0이 되어 둘째는 기다렸다. 첫 프로그램이 끝나 신호를 보낸 뒤에야 둘째가 들어가 파일 충돌이 없어졌다.
    2. 프로세스 둘이 값 1인 세마포어에 동시에 접근했다. 원자적 wait 연산 때문에 먼저 처리된 쪽만 1을 0으로 바꾸고 다른 쪽은 대기했다. 값이 두 번 소비되어 둘 다 임계구역에 들어가는 일이 생기지 않았다.
    3. 세마포어 값을 읽은 뒤 감소시키기 전에 실행이 끊기는 잘못된 구현을 가정했다. 두 프로세스가 모두 값 1을 보고 진입하면 공유 자료를 동시에 바꿨다. 검사와 변경을 원자적으로 묶어야 이 경쟁이 사라졌다.
    4. 값 2인 세마포어에 작업 셋이 접근했다. 원자적 wait 두 번으로 값이 차례로 1과 0이 되어 작업 둘이 통과했고 셋째는 대기했다. 완료 신호가 값을 올린 뒤 대기 작업이 진행됐다.

    세마포어의 검사·변경 연산은 중간에 다른 연산이 끼지 않는 원자적 절차여야 한다. 인터럽트될 수 있다는 3번이 옳지 않다.

    소프트웨어에 대한 ISO/IEC 품질 표준 중에서 프로세스 품질 표준으로 옳은 것은?

    1. 1. ISO/IEC 12119
    2. 2. ISO/IEC 12207
    3. 3. ISO/IEC 14598
    4. 4. ISO/IEC 25010

    정답 2번

    🔍 보기별 해설
    1. ISO/IEC 12119(국제표준화기구·국제전기기술위원회의 소프트웨어 패키지 품질 표준)는 패키지 제품의 요구사항과 시험을 다룬다. 개발·운영 활동의 절차를 정하는 표준이 아니므로 옳지 않다.
    2. ISO/IEC 12207(국제표준화기구·국제전기기술위원회의 소프트웨어 생명주기 프로세스 표준)은 개발부터 운영·유지보수까지의 활동을 규정한다. 제품의 성질보다 수행 과정을 다루므로 옳다(정답).
    3. ISO/IEC 14598(국제표준화기구·국제전기기술위원회의 소프트웨어 제품 평가 표준)은 완성된 제품을 평가하는 절차를 다룬다. 생명주기 활동 자체를 규정하는 표준이 아니므로 옳지 않다.
    4. ISO/IEC 25010(국제표준화기구·국제전기기술위원회의 시스템 및 소프트웨어 품질 모델)은 제품의 품질 특성을 제시한다. 개발 활동의 순서를 정하는 프로세스 표준이 아니므로 옳지 않다.
    🧮 풀이
    1. 배포할 패키지 소프트웨어를 검수할 때는 제품이 정해진 품질 요구를 충족하는지 시험한다. 설치와 사용 과정에서 제품 자체가 기준을 만족하는지가 평가 대상이다. 이처럼 패키지 품질을 확인하는 일은 개발 조직의 생명주기 절차를 규정하는 일과 구별된다.
    2. 한 개발 조직이 요구사항 분석, 설계, 구현, 운영, 유지보수에서 누가 어떤 활동을 맡는지 문서화한다. 각 단계에서 나올 산출물과 책임을 정하는 일은 소프트웨어 생명주기 프로세스에 해당한다. ISO/IEC 12207을 적용하면 제품 출시 뒤의 운영과 유지보수 활동도 같은 체계에서 다룰 수 있다.
    3. 완성된 업무 프로그램을 구매하기 전에 평가 계획을 세우고 시험 결과를 검토한다. 이때 평가 기준을 적용해 제품이 기대한 품질에 도달했는지 판단한다. 소프트웨어 제품의 평가 절차가 중심이므로 개발·운영 활동을 정의하는 표준과 대상이 다르다.
    4. 동영상 서비스의 응답 시간과 장애 복구 능력을 품질 항목으로 적는다. 제품이 얼마나 빠르고 안정적으로 작동하는지 설명하는 특성이 품질 모델에 들어간다. 이런 항목을 정리해도 개발팀이 언제 어떤 절차로 작업할지는 별도로 정해야 한다.

    4. 인덱스 어드레싱은 기준 주소에 인덱스 레지스터의 값을 더해 유효 주소를 계산한다. 레지스터 값 하나를 그대로 주소로 쓰는 방식이 아니므로 옳지 않다.

    3. 명령어의 주소 필드가 메모리 500을 가리키고 메모리 500에 실제 데이터 주소 1000이 저장돼 있다. 간접 주소 방식은 메모리 500을 읽은 뒤 다시 1000으로 접근한다. 주소를 한 번 더 읽는 장소가 메모리라는 점이 핵심이다.
    4. 배열의 시작 주소가 1000이고 인덱스 레지스터에 3이 들어 있다. 한 칸 크기가 1이라면 유효 주소 1003을 계산해 네 번째 원소에 접근한다. 기준 주소와 인덱스를 합성한다는 점에서 레지스터 간접 방식과 다르다.

    레지스터가 피연산자의 주소를 담는 방식이므로 정답은 1번이다.

    3. SOAP(Simple Object Access Protocol, 단순 객체 접근 프로토콜)는 구조화된 메시지 교환에 쓰인다. 네트워크 설정을 자동 배포하는 프로토콜이 아니므로 옳지 않다.
    4. DHCP(Dynamic Host Configuration Protocol, 동적 호스트 구성 프로토콜)는 장치에 IP 주소와 네트워크 설정을 임대한다. 동적 주소 할당에 해당하므로 옳다(정답).
    🧮 풀이
    1. 컴퓨터가 웹 서버와 연결한 뒤 TCP로 데이터 조각의 순서와 수신 여부를 관리한다. 이미 네트워크 설정을 받은 상태에서 통신의 신뢰성을 높이는 일이다. 컴퓨터의 주소를 처음 정하는 단계와는 역할이 다르다.
    2. 브라우저에서 example.com을 입력하면 DNS 서버가 그 이름에 대응하는 IP 주소를 찾아 알려 준다. 조회 결과를 이용해 목적지 서버로 접속한다. 도메인 이름을 주소로 해석해도 사용자 컴퓨터의 주소가 새로 배정되지는 않는다.
    3. 서로 다른 업무 시스템이 정해진 형식의 요청과 응답 메시지를 주고받는다. SOAP는 메시지 구조와 교환 규칙을 정의해 서비스 호출을 돕는다. 컴퓨터가 네트워크에 접속할 때 받을 주소를 고르는 기능과는 관련이 없다.
    4. 새 노트북이 사무실 무선망에 연결되면 DHCP 서버에 네트워크 설정을 요청한다. 서버는 사용 가능한 IP 주소와 임대 기간, 게이트웨이 정보를 보내 준다. 노트북은 수동으로 주소를 입력하지 않고도 통신을 시작한다.

    네트워크에 접속한 장치에 IP 주소를 동적으로 배정하는 프로토콜은 DHCP이므로 정답은 4번이다.

    UDP 프로토콜에 대한 설명으로 옳지 않은 것은?

    2. UDP는 데이터그램마다 독립적으로 전송하며 수신 순서를 보장하지 않는다. 순차적 전달을 보장한다는 설명이므로 옳지 않다(정답).

    🧮 풀이
    1. 실시간 음성 통화에서 일부 음성 패킷이 늦게 도착하면 재전송을 기다리는 편이 오히려 대화를 끊기게 할 수 있다. 응용 프로그램은 손실을 감수하고 최신 음성을 재생한다. UDP는 이러한 선택을 응용 계층에 맡긴다.

    3. DNS 질의 프로그램은 서버와 긴 연결을 먼저 맺지 않고 요청 데이터그램을 보낸다. 서버가 응답 데이터그램을 보내면 한 번의 질의가 끝난다. 이처럼 연결 수립 절차 없이 통신을 시작할 수 있다.
    4. 영상 스트림의 패킷 하나가 손실되더라도 UDP가 자동 재전송 요청을 보내지는 않는다. 영상 프로그램이 필요에 따라 오류를 숨기거나 별도의 복구 방식을 적용한다. 손실 처리 정책을 프로토콜 바깥에서 정한다.

    UDP는 순차 전달을 보장하지 않으므로 정답은 2번이다.

    유닉스 시스템 신호에 대한 설명으로 옳은 것은?

    1. 1. SIGKILL: abort()에서 발생되는 종료 시그널
    2. 2. SIGTERM: 잘못된 하드웨어 명령어를 수행하는 시그널
    3. 3. SIGILL: 터미널에서 CTRL ＋ Z 할 때 발생하는 중지 시그널
    4. 4. SIGCHLD: 프로세스의 종료 혹은 중지를 부모에게 알리는 시그널

    정답 4번

    🔍 보기별 해설
    1. SIGKILL은 프로세스를 즉시 종료시키는 신호다. abort()가 일으키는 종료 신호는 SIGABRT이므로 옳지 않다.
    2. SIGTERM은 프로세스에 정상 종료를 요청하는 신호다. 잘못된 기계어 명령에 해당하는 신호는 SIGILL이므로 옳지 않다.
    3. SIGILL은 불법 명령어를 실행했을 때 발생한다. 터미널에서 Ctrl+Z를 누를 때의 정지 신호는 SIGTSTP이므로 옳지 않다.
    4. SIGCHLD는 자식 프로세스가 종료되거나 멈추는 등의 상태 변화를 부모 프로세스에 알린다. 자식의 상태를 확인할 계기를 제공하므로 옳다(정답).
    🧮 풀이
    1. 응답하지 않는 프로그램을 관리자가 강제로 중단시킬 때 SIGKILL을 보낸다. 프로그램은 이 신호를 잡아 종료 정리 작업을 할 수 없다. 프로그램이 abort()를 호출해 비정상 종료를 알리는 상황에는 별도의 SIGABRT가 쓰인다.
    2. 서비스 운영자가 종료 요청을 보내면 프로세스는 SIGTERM을 받아 파일을 닫고 작업을 마무리할 수 있다. 불법 명령을 실행해 오류가 난 상황과 원인이 다르다. 그 오류를 가리키는 이름은 SIGILL이다.
    3. 사용자가 터미널에서 Ctrl+Z를 누르면 앞에서 실행 중인 작업이 일시 중지된다. 터미널이 보내는 신호는 SIGTSTP이다. SIGILL은 프로세서가 허용하지 않는 명령을 실행했을 때의 오류 신호다.
    4. 부모 프로세스가 자식 프로세스를 시작한 뒤 다른 일을 수행한다. 자식이 끝나면 부모에게 SIGCHLD가 전달되고 부모는 자식의 종료 상태를 수거할 수 있다. 자식 상태 변화를 알리는 통지가 이 신호의 역할이다.

    자식 프로세스의 상태 변화를 부모에게 알리는 SIGCHLD가 맞으므로 정답은 4번이다.
