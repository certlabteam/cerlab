    사용자의 신원을 검증하고 전송된 메시지의 출처를 확인하는 정보보호 개념은?

    1. 1. 무결성
    2. 2. 기밀성
    3. 3. 인증성
    4. 4. 가용성

    정답 3번

    🔍 보기별 해설
    1. 무결성은 데이터가 허가 없이 바뀌지 않았는지 확인하는 성질이다. 사용자의 신원을 검증하는 개념이 아니므로 옳지 않다.
    2. 기밀성은 허가받지 않은 사람이 정보를 읽지 못하게 하는 성질이다. 발신자의 신원을 확인하는 성질이 아니므로 옳지 않다.
    3. 인증성은 통신 상대와 메시지 출처가 주장한 신원과 맞는지 확인하는 성질이다. 발문의 두 검증 활동에 해당하므로 옳다(정답).
    4. 가용성은 이용자가 필요한 때 시스템과 정보에 접근할 수 있도록 유지하는 성질이다. 통신 상대나 발신자의 신원을 검증하는 목적과 다르므로 옳지 않다.
    🧮 풀이
    1. 파일을 내려받은 뒤 해시값을 비교해 전송 중 내용이 바뀌지 않았는지 확인한다. 파일을 누가 보냈는지는 이 비교만으로 알 수 없다. 내용 변경 여부를 보는 성질이 무결성이다.
    2. 고객의 카드 번호를 암호화해 전송한다. 네트워크를 엿보는 사람이 내용을 읽지 못하게 하는 것이 목적이다. 암호화로 내용을 숨기는 성질은 기밀성이다. 정보가 노출되지 않도록 접근 권한을 함께 제한할 수 있다.
    3. 서버가 사용자의 로그인 자격을 확인하고, 사용자는 서버의 인증서를 검증한다. 이어 서명된 메시지를 받아 누가 보냈는지도 확인한다. 통신 주체와 출처의 신원을 확인하는 성질이 인증성이다.
    4. 재난 상황에도 병원 시스템이 접속 요청을 처리할 수 있도록 이중 서버를 운영한다. 한 서버가 멈추면 다른 서버가 서비스를 이어 간다. 필요할 때 이용할 수 있다는 성질이 가용성이다.

    사용자와 메시지 발신처의 신원을 확인하는 성질은 인증성이므로 정답은 3번이다.

    TCP에 대한 설명으로 옳지 않은 것은?

    1. 1. 비연결 지향 프로토콜이다.
    2. 2. 3-Way Handshaking을 통해 서비스를 연결 설정한다.
    3. 3. 포트 번호를 이용하여 서비스들을 구별하여 제공할 수 있다.
    4. 4. SYN Flooding 공격은 TCP 취약점에 대한 공격이다.

    정답 1번

    🔍 보기별 해설
    1. TCP(Transmission Control Protocol, 전송 제어 프로토콜)는 통신 전에 연결을 수립한다. 비연결 지향이라는 설명은 옳지 않다(정답).
    2. TCP의 3-Way Handshaking은 SYN, SYN-ACK, ACK 세 메시지를 교환해 양쪽의 연결 준비 상태를 확인한다. 통신 전에 연결을 수립하는 절차이므로 옳다.
    3. TCP는 송신지와 수신지 포트 번호로 통신 응용 서비스를 구분한다. 같은 장치의 여러 서비스를 나눠 연결할 수 있으므로 옳다.
    4. SYN Flooding은 연결 요청을 대량 보내 서버의 대기 자원을 소모시키는 공격이다. TCP 연결 수립 절차를 악용하므로 옳다.
    🧮 풀이
    1. 웹 브라우저가 서버와 자료를 주고받기 전에 TCP 연결을 설정한다. 연결이 잡힌 뒤에야 데이터 전달과 확인 응답을 관리한다. 사전 연결이 없는 전송 방식으로 설명할 수 없다. 연결 상태를 유지한다는 점이 핵심이다.
    2. 클라이언트가 SYN을 보내고 서버가 SYN-ACK로 응답한다. 클라이언트가 ACK를 보내면 양쪽이 연결 상태를 확인한다. 세 메시지의 교환이 3단계 연결 수립 절차다.
    3. 한 서버에서 웹 서비스와 원격 접속 서비스를 함께 운영한다. 패킷의 목적지 포트 번호를 보면 어느 서비스로 보낼지 구분할 수 있다. 전송 계층의 포트가 응용 프로그램의 통신 끝점을 나눈다.
    4. 공격자가 연결 요청 SYN을 대량 전송하고 마지막 확인 응답을 보내지 않는다. 서버는 완성되지 않은 연결을 기다리느라 자원을 점유한다. TCP 연결 대기 과정을 노리는 SYN Flooding 사례다.

    TCP는 연결 지향 프로토콜이므로 비연결 지향이라는 1번이 정답이다.

    암호 알고리즘에 대한 설명으로 옳지 않은 것은?

    1. 1. 일반적으로 대칭키 암호 알고리즘은 비대칭키 암호 알고리즘에 비하여 빠르다.
    2. 2. 대칭키 암호 알고리즘에는 Diffie-Hellman 알고리즘이 있다.
    3. 3. 비대칭키 암호 알고리즘에는 타원 곡선 암호 알고리즘이 있다.
    4. 4. 인증서는 비대칭키 암호 알고리즘에서 사용하는 공개키 정보를 포함하고 있다.

    정답 2번

    🔍 보기별 해설
    1. 대칭키 암호는 같은 비밀키로 암호화와 복호화를 수행해 일반적으로 공개키 연산보다 빠르다. 통상적인 성능 비교이므로 옳다.
    2. Diffie-Hellman 알고리즘은 통신 당사자가 공개 정보를 교환해 공유 비밀을 만드는 키 합의 방식이다. 평문을 직접 암호화하는 대칭키 암호 알고리즘으로 분류한 설명은 옳지 않다(정답).
    3. 타원 곡선 암호는 타원 곡선의 수학적 구조를 이용하는 공개키 암호 방식이다. 비대칭키 알고리즘에 속하므로 옳다.
    4. 인증서는 공개키와 그 소유자 정보를 묶고 인증기관의 서명으로 관계를 확인하게 한다. 공개키 정보를 포함한다는 설명이므로 옳다.
    🧮 풀이
    1. 파일 여러 개를 같은 비밀키로 빠르게 암호화한다. 큰 데이터를 반복 처리할 때 대칭키 방식의 연산 부담이 상대적으로 작다. 공개키 방식은 키 교환이나 서명처럼 다른 용도로 함께 쓸 수 있다.
    2. 두 통신 당사자가 공개값을 교환한 뒤 각자의 비밀값을 결합해 같은 공유 비밀을 얻는다. 네트워크를 엿본 사람에게는 개인 비밀값이 드러나지 않는다. 이 과정은 암호문을 직접 만드는 대칭키 암호가 아니라 키 합의다.
    3. 서버가 타원 곡선 기반 키 쌍을 만들고 공개키를 배포한다. 개인키는 서버만 보관하며 공개키와 짝을 이루는 연산에 사용한다. 두 키를 구분하는 공개키 구조이므로 비대칭키 방식이다.
    4. 브라우저가 서버 인증서를 받아 도메인 이름과 인증기관 서명을 확인한다. 인증서 안의 서버 공개키가 실제 서버의 것인지 검증한다. 공개키만 별도로 전달받는 것보다 소유자 확인 근거를 제공한다.

    Diffie–Hellman은 키 합의 방식이지 대칭키 암호 알고리즘이 아니므로 정답은 2번이다.

    TCP 세션 하이재킹에 대한 설명으로 옳은 것은?

    1. 1. 서버와 클라이언트가 통신할 때 TCP의 시퀀스 넘버를 제어하는 데 문제점이 있음을 알고 이를 이용한 공격이다.
    2. 2. 공격 대상이 반복적인 요구와 수정을 계속하여 시스템 자원을 고갈시킨다.
    3. 3. 데이터의 길이에 대한 불명확한 정의를 악용한 덮어쓰기로 인해 발생한다.
    4. 4. 사용자의 동의 없이 컴퓨터에 불법적으로 설치되어 문서나 그림 파일 등을 암호화한다.

    정답 1번

    🔍 보기별 해설
    1. TCP 세션 하이재킹은 연결의 순서 번호를 예측하거나 조작해 통신 흐름에 끼어든다. 기존 세션을 빼앗는 설명이므로 옳다(정답).
    2. 반복 요청으로 시스템 자원을 고갈시키는 것은 서비스 거부 공격에 가깝다. 세션 순서 번호를 이용한 가로채기가 아니므로 옳지 않다.
    3. 입력 길이를 잘못 검사해 메모리를 덮어쓰는 것은 버퍼 오버플로 취약점이다. TCP 세션 탈취의 정의가 아니므로 옳지 않다.
    4. 문서 파일을 암호화하고 금전을 요구하는 것은 랜섬웨어의 행동이다. 세션 순서 번호를 악용하는 공격과 다르므로 옳지 않다.
    🧮 풀이
    1. 공격자가 이미 연결된 두 장치 사이의 TCP 순서 번호를 알아낸다. 한쪽 장치인 것처럼 위조한 패킷을 맞는 번호로 보내면 통신 흐름을 가로챌 수 있다. 기존 연결을 끊거나 통제권을 빼앗는 세션 하이재킹의 사례다.
    2. 서버에 자동화된 요청을 매우 많이 보내 처리 대기열을 가득 채운다. 정상 이용자는 응답을 받기 어려워진다. 자원을 소모시키는 서비스 거부 공격의 모습이며 특정 TCP 세션의 순서 번호를 탈취하는 방식은 아니다.
    3. 프로그램이 입력 문자열의 길이를 확인하지 않고 작은 버퍼에 복사한다. 넘친 데이터가 옆 메모리를 덮어써 비정상 동작이 생긴다. 길이 검사 실패를 이용한 취약점과 세션 가로채기는 공격 지점이 다르다.
    4. 사용자가 열지 않은 첨부파일로 악성 프로그램이 설치된다. 프로그램이 문서를 암호화하고 복구 대가를 요구한다. 파일을 잠그는 랜섬웨어는 네트워크 세션 번호를 조작하는 공격과 다르다.

    TCP 순서 번호를 악용해 기존 연결을 가로채는 공격은 세션 하이재킹이므로 정답은 1번이다.

    생체 인증 측정에 대한 설명으로 옳지 않은 것은?

    1. 1. FRR는 권한이 없는 사람이 인증을 시도했을 때 실패하는 비율이다.
    2. 2. 생체 인식 시스템의 성능을 평가하는 지표로는 FAR, EER, FRR 등이 있다.
    3. 3. 생체 인식 정보는 신체적 특징과 행동적 특징을 이용하는 것들로 분류한다.
    4. 4. FAR는 권한이 없는 사람이 인증을 시도했을 때 성공하는 비율이다.

    정답 1번

    🔍 보기별 해설
    1. FRR(False Rejection Rate, 오거부율)은 정당한 사용자를 잘못 거부한 비율이다. 권한 없는 사람의 인증 실패율로 설명해 옳지 않다(정답).
    2. FAR(False Acceptance Rate, 오인수율), EER(Equal Error Rate, 동일 오류율), FRR은 생체 인증 성능을 평가할 때 쓴다. 대표 지표의 열거이므로 옳다.
    3. 생체 인식은 지문·얼굴 같은 신체 특징과 음성 습관·서명 동작 같은 행동 특징을 이용한다. 분류가 맞으므로 옳다.
    4. FAR은 권한이 없는 사람을 인증 시스템이 잘못 받아들인 비율이다. 무권한자의 인증 시도 가운데 성공으로 처리된 경우에 관한 지표이므로 옳다.
    🧮 풀이
    1. 등록된 직원의 지문이 건조해져 인식 장치가 출입을 거절한다. 출입 권한이 있는 사람을 잘못 막은 건수로 오거부율을 계산한다. 무권한자가 거절된 정상 결과와는 다르다.
    2. 출입 시스템의 시험에서 등록자 거부 건수와 미등록자 허용 건수를 따로 센다. 두 오류율이 같아지는 설정 지점을 동일 오류율로 기록한다. 여러 지표를 함께 보아야 사용성과 보안의 균형을 알 수 있다. 설정값에 따라 두 오류율은 서로 달라진다.
    3. 지문과 얼굴 모양은 신체에서 측정하는 특징이다. 걸음걸이와 서명하는 손의 움직임은 행동에서 나타나는 특징이다. 생체 인증 자료는 이런 신체적·행동적 특징으로 나눌 수 있다.
    4. 등록되지 않은 사람이 지문 인식기로 출입을 시도했는데 장치가 통과시켰다. 무권한자를 잘못 받아들인 사건이다. 전체 무권한자 시도 가운데 이런 허용이 차지하는 비율이 오인수율이다.

    FRR은 정당한 사용자를 거부한 비율이므로 무권한자 실패율이라는 1번이 정답이다.

    블록암호 카운터 운영모드에 대한 설명으로 옳지 않은 것은?

    1. 1. 암호화와 복호화는 같은 구조로 구성되어 있다.
    2. 2. 병렬로 처리할 수 있는 능력에 따라 처리속도가 결정된다.
    3. 3. 카운터를 암호화하고 평문블록과 XOR하여 암호블록을 생성한다.
    4. 4. 블록을 순차적으로 암호화․복호화 한다.

    정답 4번

    🔍 보기별 해설
    1. 카운터 모드는 암호화한 카운터 값과 데이터를 배타적 논리합한다. 암호화와 복호화에서 같은 블록 암호화 구조를 사용할 수 있으므로 옳다.
    2. 각 블록에 서로 다른 카운터를 주면 카운터의 암호화를 병렬 수행할 수 있다. 병렬 처리 능력이 처리 속도에 영향을 주므로 옳다.
    3. 카운터 값을 블록 암호로 암호화한 뒤 평문 블록과 XOR(Exclusive OR, 배타적 논리합)한다. 암호문을 만드는 절차와 맞으므로 옳다.
    4. 카운터 모드에서는 블록별 입력이 독립적이어서 암호화와 복호화를 병렬 처리할 수 있다. 반드시 블록을 순차 처리한다는 설명은 옳지 않다(정답).
    🧮 풀이
    1. 첫 번째 카운터를 암호화한 값을 평문과 XOR해 암호문을 만든다. 복호화할 때도 같은 카운터를 암호화해 암호문과 XOR하면 원래 평문이 나온다. 블록 암호의 복호화 함수가 아니라 암호화 함수를 양쪽에서 쓴다.
    2. 서로 다른 네 카운터 값을 네 연산 장치에 동시에 넣는다. 각 장치는 자기 카운터의 암호화 결과를 해당 데이터 블록에 적용한다. 앞 블록의 결과를 기다리지 않아도 되어 병렬 장치 수가 처리량에 영향을 준다.
    3. 카운터 1을 암호화해 얻은 비트열과 첫 평문 블록을 XOR한다. 카운터 2에는 다른 비트열이 생겨 둘째 평문 블록과 결합한다. 각 블록에 다른 카운터를 적용해 암호문을 얻는다.
    4. 블록 A의 암호문을 계산하는 동안 다른 장치가 블록 B의 카운터를 암호화한다. B는 A의 암호문을 입력으로 쓰지 않는다. 이런 독립성 때문에 반드시 앞 블록이 끝난 뒤 다음 블록을 시작할 필요가 없다.

    카운터 모드는 블록별 카운터를 독립적으로 처리할 수 있어 순차 처리라는 4번이 정답이다.

    AES 알고리즘에 대한 설명으로 옳지 않은 것은?

    1. 1. 대먼과 리즈먼이 제출한 Rijndael이 AES 알고리즘으로 선정되었다.
    2. 2. 암호화 과정의 모든 라운드에서 SubBytes, ShiftRows, MixColumns, AddRoundKey 연산을 수행한다.
    3. 3. 키의 길이는 128, 192, 256 bit의 크기를 사용한다.
    4. 4. 입력 블록은 128 bit이다.

    정답 2번

    🔍 보기별 해설
    1. AES(Advanced Encryption Standard, 고급 암호화 표준)는 Rijndael을 바탕으로 선정됐다. 대먼과 리즈먼의 제출안이라는 설명이므로 옳다.
    2. AES의 마지막 라운드는 SubBytes, ShiftRows, AddRoundKey를 수행하고 MixColumns를 생략한다. 모든 라운드에서 네 연산을 수행한다는 설명은 옳지 않다(정답).
    3. AES는 128비트, 192비트, 256비트의 세 가지 키 길이를 지원한다. 키 선택에 따라 라운드 수가 달라질 수 있으며 제시된 길이는 모두 허용되므로 옳다.
    4. AES의 암호화 대상 데이터 블록은 키 길이와 상관없이 128비트로 고정된다. 256비트 키를 사용하더라도 입력 블록은 128비트이므로 옳다.
    🧮 풀이
    1. Rijndael 설계안이 표준 선정 절차를 거쳐 AES로 채택됐다. 설계자들의 이름과 알고리즘의 이름은 구분된다. 여러 후보 가운데 선택된 블록 암호라는 사실이 이 설명의 근거다. 선정 뒤 표준 문서에 구체적인 변환 절차가 정해졌다.
    2. 일반 라운드에서는 바이트 치환, 행 이동, 열 혼합, 라운드 키 결합을 수행한다. 마지막 라운드에서는 열 혼합 단계를 제외하고 나머지 변환으로 마무리한다. 따라서 마지막까지 네 연산을 모두 수행한다는 문장은 맞지 않는다.
    3. 같은 AES 구현에서 128비트 키로 암호화할 수도 있고 192비트나 256비트 키를 선택할 수도 있다. 키 길이에 따라 필요한 라운드 수가 달라진다. 키 길이의 선택 폭과 데이터 블록 크기는 서로 다른 항목이다.
    4. 128비트 평문 블록 하나를 AES에 넣어 암호화한다. 256비트 키를 선택해도 입력 데이터 블록은 여전히 128비트다. 키가 길어졌다고 입력 블록까지 두 배가 되는 것은 아니다.

    AES의 마지막 라운드에는 MixColumns가 빠지므로 모든 라운드에서 수행한다는 2번이 정답이다.

    비트코인 블록 헤더의 구조에서 머클 루트에 대한 설명으로 옳지 않은 것은?

    1. 1. 머클 트리 루트의 해시값이다.
    2. 2. 머클 트리는 이진트리 형태이다.
    3. 3. SHA-256으로 해시값을 계산한다.
    4. 4. 필드의 크기는 64바이트이다.

    정답 4번

    🔍 보기별 해설
    1. 머클 루트는 블록 안 거래들의 해시를 트리로 결합해 얻은 최상위 해시다. 머클 트리 루트의 해시값이므로 옳다.
    2. 머클 트리는 자식 해시를 쌍으로 묶어 부모 해시를 만드는 이진트리 형태로 구성된다. 트리 구조의 설명이므로 옳다.
    3. 비트코인은 거래 해시 결합에 SHA-256(Secure Hash Algorithm 256-bit, 256비트 보안 해시 알고리즘)을 사용한다. 머클 루트 계산 방식에 맞으므로 옳다.
    4. 비트코인 블록 헤더의 머클 루트 필드는 256비트이며 8비트를 1바이트로 나누면 32바이트다. 64바이트라고 한 크기는 두 배로 잘못 적었으므로 옳지 않다(정답).
    🧮 풀이
    1. 블록에 거래 네 건이 있으면 각 거래의 해시를 계산한다. 두 개씩 묶어 상위 해시를 만들고 다시 합쳐 최상단 해시를 얻는다. 이 최상단 값이 블록 헤더에 기록되는 머클 루트다.
    2. 거래 해시 A와 B를 결합해 부모 해시를 만들고 C와 D도 같은 방식으로 결합한다. 두 부모 해시를 다시 합치면 하나의 루트가 된다. 자식 두 개가 부모 하나에 연결되는 이진트리 구조다.
    3. 거래의 식별 해시와 쌍을 이룬 노드의 값을 결합해 SHA-256 기반 해시를 계산한다. 한 거래가 바뀌면 위로 이어지는 해시도 달라진다. 루트 값으로 거래 묶음의 무결성을 검증할 수 있다. 계산된 결과는 상위 노드의 입력이 된다.
    4. 머클 루트의 해시 출력은 256비트다. 8비트가 1바이트이므로 256÷8=32바이트가 된다. 64바이트는 두 배 크기라 헤더 필드의 값과 맞지 않는다. 필드 길이와 해시 계산에 사용한 입력 길이를 혼동해서는 안 된다.

    비트코인 블록 헤더의 머클 루트는 32바이트이므로 64바이트라는 4번이 정답이다.

    SET에 대한 설명으로 옳지 않은 것은?

    정답 3번

    🔍 보기별 해설
    1. SET(Secure Electronic Transaction, 안전한 전자 거래)은 인터넷 신용카드 결제의 보안 절차를 위해 설계됐다. 신용카드 지불 기술이라는 설명이므로 옳다.
    2. SET의 인증기관은 참여자의 인증서를 발급하고 신원을 확인하는 역할을 한다. 구성원의 정당성 확인과 관련되므로 옳다.

    🧮 풀이
    1. 고객이 온라인 상점에서 신용카드로 결제한다. SET은 카드 정보와 상점의 주문 정보를 안전하게 처리하도록 참여자의 인증서와 암호 기술을 사용한다. 인터넷 신용카드 거래를 위한 기술이다. 결제 참여자의 신원 확인도 포함된다.
    2. 카드 소지자와 상점이 각자 자신의 공개키 인증서를 제시한다. 인증기관의 서명을 확인하면 상대가 등록된 참여자인지 검증할 수 있다. 인증기관은 거래의 신원 확인을 뒷받침한다.
    3. 새 카드 소지자가 SET 거래를 사용하려면 고객 등록 절차와 인증서 발급 절차를 거친다. 인증기관이 고객의 공개키 인증서를 다루는 주체다. 지불 게이트웨이는 카드 결제 승인 경로에 관여하므로 고객 인증서 발급 창구와 다르다.
    4. 온라인 상점이 인증기관에 등록해 공개키 인증서를 받는다. 고객은 거래할 때 그 인증서를 확인해 상점의 신원을 검증한다. 상점 등록과 결제 승인은 참여 시점과 담당 역할이 구별된다.

    고객 등록과 인증서 처리는 인증기관을 거치며 지불 게이트웨이를 통한다는 3번이 정답이다.

    1. IPv6(Internet Protocol version 6, 인터넷 프로토콜 6판)는 IPv4의 주소 부족 문제에 대응해 도입됐다. 도입 배경을 맞게 설명하므로 옳다.
    2. IPv6 주소의 길이는 128비트로 IPv4의 32비트보다 훨씬 넓은 주소 공간을 제공한다. 주소 크기를 바르게 적었으므로 옳다.
    3. IPv6 유니캐스트 주소는 네트워크에서 하나의 인터페이스를 식별한다. 지정한 단일 목적지로 패킷을 보내는 주소 유형이므로 옳다.
    4. IPv6는 유니캐스트·애니캐스트·멀티캐스트를 사용하고 브로드캐스트 주소를 따로 두지 않는다. 브로드캐스트를 유형에 넣었으므로 옳지 않다(정답).
    🧮 풀이
    1. 인터넷에 연결하는 장치가 늘어나면서 기존 IPv4 주소만으로 모두에게 고유 주소를 주기 어려워졌다. IPv6는 훨씬 넓은 주소 공간을 마련했다. 주소 부족에 대응하려는 필요가 도입 배경이다.
    2. IPv4의 32비트 주소와 IPv6의 128비트 주소를 비교한다. 주소 길이가 네 배가 되면 가능한 주소 조합의 수는 훨씬 크게 늘어난다. IPv6의 주소 필드 길이는 128비트다.
    3. 한 서버의 특정 네트워크 인터페이스에 유니캐스트 주소를 부여한다. 그 주소로 보낸 패킷은 해당 인터페이스를 목적지로 삼는다. 하나의 목적지를 지정한다는 점이 유니캐스트의 뜻이다.
    4. 같은 네트워크의 모든 장치에 보내던 IPv4 브로드캐스트를 생각할 수 있다. IPv6에서는 필요한 집합을 멀티캐스트 주소로 나타낸다. 유니캐스트·애니캐스트·멀티캐스트는 있지만 브로드캐스트 주소 유형은 없다.

    IPv6에는 브로드캐스트가 없어 이를 주소 유형으로 넣은 4번이 정답이다.

    SSH를 구성하는 프로토콜에 대한 설명으로 옳은 것은?

    1. 1. SSH는 보통 TCP상에서 수행되는 3개의 프로토콜로 구성된다.
    2. 2. 연결 프로토콜은 서버에게 사용자를 인증한다.
    3. 3. 전송계층 프로토콜은 SSH 연결을 사용하여 한 개의 논리적 통신 채널을 다중화한다.
    4. 4. 사용자 인증 프로토콜은 전방향 안전성을 만족하는 서버인증만을 제공한다.

    정답 1번

    🔍 보기별 해설
    1. SSH(Secure Shell, 보안 셸)는 보통 TCP 위에서 전송계층·사용자 인증·연결 프로토콜을 사용한다. 세 구성 프로토콜의 설명이므로 옳다(정답).
    2. 연결 프로토콜은 인증 뒤의 논리 채널을 다중화한다. 서버에 사용자를 인증하는 역할은 사용자 인증 프로토콜이므로 옳지 않다.
    3. SSH 전송계층 프로토콜은 암호화와 무결성, 서버 인증을 제공한다. 논리 채널의 다중화는 연결 프로토콜의 역할이므로 옳지 않다.
    4. 사용자 인증 프로토콜은 서버에 접속하려는 사용자를 확인한다. 서버 인증만 제공한다는 설명은 역할을 뒤집어 옳지 않다.
    🧮 풀이
    1. 관리자가 원격 서버에 안전하게 접속한다. TCP 연결 위에서 SSH 전송계층이 보호된 통로를 만들고 사용자 인증을 거쳐 여러 채널을 사용한다. 세 프로토콜이 차례로 다른 일을 맡는다.
    2. 로그인한 관리자가 같은 SSH 접속에서 명령 셸과 파일 전달 채널을 함께 사용한다. 여러 논리 채널을 하나의 연결에 싣는 것은 연결 프로토콜의 일이다. 비밀번호나 공개키로 사용자를 확인하는 단계와 구별된다.
    3. 클라이언트가 서버의 호스트 키를 확인하고 통신 내용을 암호화한다. SSH 전송계층은 안전한 통신 통로를 제공한다. 그 위에서 채널을 여러 개 여는 기능은 연결 프로토콜이 처리한다.
    4. 원격 서버가 접속자의 공개키 서명이나 비밀번호를 확인한다. 누가 로그인하려는지 검증하는 단계가 사용자 인증 프로토콜이다. 서버 자체의 신원을 확인하는 전송계층 기능과 방향이 다르다.

    SSH는 전송계층·사용자 인증·연결의 세 프로토콜로 구성되므로 정답은 1번이다.

    유럽의 국가들에 의해 제안된 것으로 자국의 정보보호 시스템을 평가하기 위하여 제정된 기준은?

    1. 1. TCSEC
    2. 2. ITSEC
    3. 3. PIMS
    4. 4. ISMS-P

    정답 2번

    🔍 보기별 해설
    1. TCSEC(Trusted Computer System Evaluation Criteria, 신뢰 컴퓨터 시스템 평가 기준)은 미국의 보안 평가 기준이다. 유럽 국가들이 제안한 기준이 아니므로 옳지 않다.
    2. ITSEC(Information Technology Security Evaluation Criteria, 정보기술 보안 평가 기준)은 유럽에서 마련한 보안 평가 기준이다. 발문의 지역과 목적에 맞으므로 옳다(정답).
    3. PIMS(Personal Information Management System, 개인정보 관리체계)는 개인정보 보호 관리에 관한 체계다. 유럽의 보안 제품 평가 기준이 아니므로 옳지 않다.
    4. ISMS-P(Information Security Management System–Personal Information, 정보보호 및 개인정보보호 관리체계)는 국내의 관리체계 인증이다. 유럽 국가들의 평가 기준이 아니므로 옳지 않다.
    🧮 풀이
    1. 미국이 컴퓨터 시스템의 보안 기능을 등급별로 평가하려고 TCSEC을 사용했다. 제품의 신뢰 수준을 따지는 기준이었다. 지역과 명칭이 유럽의 ITSEC과 다르다. 유럽 기준과 혼동하지 않도록 지역도 함께 확인한다.
    2. 유럽 여러 국가가 정보기술 제품의 보안 기능을 공통 기준으로 평가하려 했다. ITSEC은 이런 요구에 맞춰 제시된 평가 기준이다. 발문의 '유럽의 국가들'이라는 단서와 직접 연결된다.
    3. 조직이 보유한 개인정보를 어떻게 수집·이용·보호하는지 관리 절차를 만든다. PIMS는 이런 개인정보 관리체계 맥락의 용어다. 컴퓨터 제품의 보안 등급을 평가하는 유럽 기준과 목적이 다르다.
    4. 국내 기업이 정보보호와 개인정보보호 관리체계를 구축하고 인증을 받는다. ISMS-P는 조직의 보호 활동을 심사하는 국내 인증 체계다. 유럽에서 제정된 정보기술 보안 제품 평가 기준과 구별된다.

    유럽 국가들의 정보기술 보안 평가 기준은 ITSEC이므로 정답은 2번이다.

    「개인정보 보호법」 제3조(개인정보 보호 원칙)에 대한 설명으로 옳지 않은 것은?

    2. 2. 개인정보의 처리 목적에 필요한 범위에서 개인정보의 정확성, 완전성 및 최신성이 보장되도록 하여야 한다.
    3. 3. 개인정보 처리방침 등 개인정보의 처리에 관한 사항을 비공개로 하여야 하며, 열람청구권 등 정보주체의 권리를 보장하여야 한다.

    정답 3번

    🔍 보기별 해설
    1. 처리 목적을 분명히 하고 필요한 범위에서 최소한의 개인정보만 적법하게 수집해야 한다. 법 제3조의 최소 수집 원칙이므로 옳다.
    2. 처리 목적에 필요한 범위에서 개인정보를 정확하고 완전하며 최신 상태로 유지해야 한다. 법 제3조의 정확성 원칙이므로 옳다.
    3. 개인정보 처리방침 등 처리에 관한 사항은 공개하고 정보주체의 권리를 보장해야 한다. 비공개로 하라는 설명은 옳지 않다(정답).
    4. 익명으로도 목적을 달성할 수 있으면 익명으로 처리하고 그렇지 않으면 가명 처리를 고려한다. 법 제3조의 처리 원칙에 맞으므로 옳다.
    🧮 풀이
    1. 서비스 운영자 甲이 회원가입에 이름과 연락처만 필요하다고 확인했다. 필요하지 않은 가족 정보까지 요구하지 않고 수집 목적을 알린다. 목적에 필요한 최소한의 항목만 모으는 방식이다.

    3. 쇼핑몰 甲이 개인정보 처리방침을 내부 직원만 볼 수 있는 페이지에 둔다. 고객 乙은 어떤 정보를 어떻게 처리하는지 확인할 수 없다. 처리방침을 공개하고 열람청구권 등 권리를 보장해야 한다는 원칙에 어긋난다.
    4. 연구기관 甲이 통계 작성에 개인의 이름이 필요하지 않다고 판단했다. 개인을 알아볼 수 없도록 익명 처리해도 목적을 달성한다면 익명 처리를 우선한다. 익명으로 목적을 달성할 수 없을 때에는 가명 처리를 검토한다.

    개인정보 처리방침은 공개해야 하므로 비공개라고 한 3번이 정답이다.

    🔍 보기별 해설

    2. 스위치의 모니터링 포트는 다른 포트의 트래픽을 복제해 관찰할 수 있다. 이를 악용하면 통신 내용을 엿볼 수 있으므로 옳다.

    4. 스위치 재밍은 위조한 MAC(Media Access Control, 매체 접근 제어) 주소를 대량 학습시켜 주소 테이블을 교란한다. 트래픽 노출을 유도할 수 있으므로 옳다.
    🧮 풀이

    2. 네트워크 관리자가 장애 분석을 위해 스위치의 모니터링 포트에 패킷 분석기를 연결한다. 설정된 포트의 트래픽이 복제되어 분석기에 보인다. 허가 없는 사용자가 이 기능을 악용하면 내용을 엿볼 수 있다.

    4. 공격자가 서로 다른 위조 MAC 주소를 가진 프레임을 스위치에 계속 보낸다. 주소 학습 테이블이 가득 차거나 혼란스러워져 트래픽이 의도치 않게 노출될 수 있다. 이를 이용한 스위치 재밍은 스니핑과 연결된다.

    4. Lattice 모델은 보안 등급과 권한 관계를 격자 구조로 나타내는 접근제어 틀이다. 특정한 무결성 모델의 이름이 아니므로 옳지 않다.
    🧮 풀이
    1. 낮은 신뢰도의 외부 자료가 중요한 회계 장부를 바꾸지 못하도록 제한한다. Biba 모델은 정보가 잘못된 값으로 오염되는 것을 막는 방향에 초점을 맞춘다. 기밀 문서의 유출 방지와는 주된 보호 대상이 다르다.
    2. 비밀 등급이 낮은 사용자가 높은 등급의 문서를 읽지 못하게 한다. Bell-LaPadula의 관심은 비밀 정보가 낮은 등급으로 흘러가지 않게 하는 것이다. 자료 내용의 정확성보다 기밀성을 중심에 둔다.
    3. 컨설턴트가 경쟁 기업 A의 비밀 자료를 읽은 뒤 기업 B의 자료에는 접근하지 못하게 한다. 앞서 어떤 기업의 자료를 보았는지에 따라 권한이 달라진다. 이해충돌을 막는 Chinese Wall 방식이다.
    4. 보안 등급이 여러 단계이고 각 등급 사이에 허용되는 정보 흐름을 정한다. 등급 관계를 격자 구조로 표현하면 접근 정책을 체계화할 수 있다. 격자는 정책을 나타내는 일반 틀이지 무결성 보호에 특화된 Biba의 이름은 아니다. Lattice라는 영어 이름은 격자를 뜻한다.

    정보의 무결성을 중심으로 등급을 정하는 Biba 모델이므로 정답은 1번이다.

    허니팟에 대한 설명으로 옳지 않은 것은?

    1. 1. 공격자가 중요한 시스템에 접근하지 못하도록 실제 시스템처럼 보이는 곳으로 유인한다.
    2. 2. 공격자의 행동 패턴에 관한 정보를 수집한다.
    3. 3. 허니팟은 방화벽의 내부망에는 설치할 수 없다.
    4. 4. 공격자가 가능한 한 오랫동안 허니팟에서 시간을 보내도록 하고 그사이 관리자는 필요한 대응을 준비한다.

    정답 3번

    🔍 보기별 해설
    1. 허니팟은 공격자가 실제 운영 시스템 대신 접근하도록 꾸민 유인 시스템이다. 중요한 시스템을 보호하며 관찰할 수 있으므로 옳다.
    2. 허니팟은 공격자가 사용한 명령과 접근 경로를 기록해 행동 패턴을 분석한다. 정보 수집 목적으로 쓰이므로 옳다.
    3. 허니팟은 운영 목적과 격리 방식에 따라 방화벽 내부망에도 설치할 수 있다. 내부 설치가 불가능하다는 단정은 옳지 않다(정답).
    4. 공격자가 허니팟에서 활동하는 동안 관리자는 경보를 받고 공격 수법을 파악할 수 있다. 대응 시간을 확보하는 목적이므로 옳다.
    🧮 풀이
    1. 운영 서버와 비슷하게 보이는 가짜 서버를 별도 구역에 둔다. 공격자가 그곳에 접속하면 진짜 고객 데이터가 있는 서버로 가는 시도를 늦출 수 있다. 유인과 관찰이 허니팟의 역할이다.
    2. 가짜 서버가 받은 로그인 시도와 사용 명령을 기록한다. 관리자는 어떤 계정 이름을 시도하고 어떤 파일을 찾는지 분석한다. 공격자의 행동 패턴을 이해하는 자료가 된다.
    3. 사내망에서 내부 이동을 탐지하려고 격리된 허니팟을 둔다. 허니팟이 내부망에 있더라도 실제 업무 시스템과 분리해 운영할 수 있다. 방화벽 안쪽에 절대 둘 수 없다는 규칙은 없다.
    4. 공격자가 가짜 파일과 서비스를 조사하는 사이 보안 담당자가 경보를 받는다. 담당자는 관련 계정을 차단하고 다른 시스템의 로그를 확인한다. 허니팟은 대응을 준비할 시간을 주는 도구다.

    허니팟은 내부망에도 배치할 수 있으므로 설치할 수 없다는 3번이 정답이다.

    다음에 설명하는 위험 분석 방법은?

    ○ 구조적인 방법론에 기반하지 않고 분석가의 경험이나 지식을 사용하여 위험 분석을 수행한다.

    ○ 중소 규모의 조직에는 적합할 수 있으나 분석가의 개인적 경험에 지나치게 의존한다는 단점이 있다.

    1. 1. 기준선 접근법
    2. 2. 비정형 접근법
    3. 3. 상세 위험 분석
    4. 4. 복합 접근법

    정답 2번

    🔍 보기별 해설
    1. 기준선 접근법은 공통 보안 기준을 정해 위험 평가의 출발점으로 사용한다. 개인 경험만으로 분석하는 방식이 아니므로 옳지 않다.
    2. 비정형 접근법은 분석가의 지식과 경험으로 위험을 판단하며 정해진 구조가 약하다. 자료의 장단점과 같으므로 옳다(정답).
    3. 상세 위험 분석은 자산·위협·취약점 등을 체계적으로 조사한다. 구조적 방법 없이 경험에만 의존하는 방식과 다르므로 옳지 않다.
    4. 복합 접근법은 기준선 적용과 상세 분석 등 여러 방법을 결합한다. 비정형 단일 접근의 설명이 아니므로 옳지 않다.
    🧮 풀이
    1. 조직이 모든 서버에 적용할 기본 보안 설정과 점검 목록을 정한다. 각 시스템을 공통 기준에 맞춰 먼저 점검한다. 기준선을 활용하는 방식은 담당자의 경험만으로 판단하는 방식과 다르다.
    2. 작은 회사의 보안 담당자가 과거 사고 경험을 바탕으로 중요한 위험부터 적는다. 별도의 체계적 분석 표는 만들지 않는다. 빠르게 시작할 수 있지만 담당자가 바뀌면 판단 결과가 달라질 수 있다.
    3. 중요 서버의 자산 가치와 가능한 공격, 알려진 취약점을 각각 조사한다. 위험의 가능성과 영향을 정해진 절차로 평가한다. 시간이 더 들지만 경험에만 기대는 평가보다 근거를 체계적으로 남긴다.
    4. 일반 업무용 장비에는 공통 기준을 먼저 적용하고 핵심 결제 시스템에는 상세 분석을 더한다. 자산의 중요도에 따라 서로 다른 평가 방법을 조합한다. 이런 결합이 복합 접근법이다.

    분석가의 경험에 의존하고 정형 방법론을 쓰지 않는 비정형 접근법이므로 정답은 2번이다.

    RSA를 적용하여 7의 암호문 11과 35의 암호문 42가 주어져 있을 때, 알고리즘의 수학적 특성을 이용하여 계산한 245(＝7 * 35)의 암호문은? (단, RSA 공개 모듈 n ＝ 247, 공개 지수 e ＝ 5)

    1. 1. 2
    2. 2. 215
    3. 3. 239
    4. 4. 462

    정답 2번

    🔍 보기별 해설
    1. 7과 35의 암호문을 곱하면 11×42=462이고 이를 공개 모듈 247로 나눈 나머지는 215다. 245의 암호문이 215이므로 옳다(정답).
    🧮 풀이
    1. ① 목표 평문 245를 7과 35의 곱으로 본다. 문제에 두 값의 암호문 11과 42가 각각 주어져 있다.
    2. → 245=7×35
    3. ↓
    4. ② RSA의 곱셈 성질에 따라 두 암호문을 곱한다. 11×42=462다.
    5. → E(245)≡462 mod 247
    6. ↓
    7. ③ 공개 모듈 247로 나눈 나머지를 구한다. 462에서 247을 빼면 215가 남는다.
    8. → 215
