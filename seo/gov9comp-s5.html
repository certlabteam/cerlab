    사용자의 신원을 검증하고 전송된 메시지의 출처를 확인하는 정보보호 개념은?

    1. 1. 무결성
    2. 2. 기밀성
    3. 3. 인증성
    4. 4. 가용성

    정답 3번

    🔍 보기별 해설
    1. 무결성은 정보가 허가 없이 변경되거나 삭제되지 않고 원래대로 유지된다는 성질이다. 신원이나 출처를 확인하는 것이 아니라 내용의 변조를 막는 개념이므로 옳지 않다.
    2. 기밀성은 허가받지 않은 사람이 정보를 알 수 없도록 지키는 성질로 암호화와 접근통제로 구현한다. 사용자가 누구인지 확인하는 개념은 아니므로 옳지 않다.
    3. 인증성은 사용자의 신원을 검증하고 전송된 메시지가 실제로 주장한 송신자에게서 왔는지 확인하는 성질이다. 신원 검증과 출처 확인이라는 발문의 두 요소를 모두 담고 있으므로 옳다(정답).
    4. 가용성은 허가된 사용자가 필요할 때 정보와 시스템을 지체 없이 이용할 수 있게 보장하는 성질이다. 서비스거부 공격을 막는 것과 관련이 깊고 신원 확인과는 무관하므로 옳지 않다.
    🧮 풀이
    1. 甲은 회사 문서 서버에서 결재 문서의 내용이 슬쩍 바뀐 사고 사례를 읽었다. 문서를 지키는 성질이 무엇인지 따져 보고 변조를 막는 개념은 인증이 아니라 무결성이라고 노트에 메모해 두었다.
    2. 甲은 비밀번호 없이 누구나 열어 볼 수 있던 인사 파일이 외부에 새어 나간 기사를 읽었다. 비인가자에게 알려지지 않게 하는 성질이 기밀성이라고 적고 신원 확인과 구분되게 다른 색으로 밑줄을 그었다.
    3. 甲은 메일로 온 송금 요청이 사장 이름을 달고 있어도 실제 사장이 보낸 것인지 전화로 되묻는 절차를 보았다. 보낸 사람이 누구인지 확인하는 이 과정이 인증성이라고 정리해 절차도 옆에 그려 보았다.
    4. 甲은 명절 예매 시간에 접속이 폭주해 사이트가 열리지 않은 사례를 찾아보았다. 정상 사용자가 서비스를 쓰지 못한 문제는 가용성에 해당한다고 보고 인증성과 나란히 표로 견주어 놓았다.

    사용자 신원 검증과 메시지 출처 확인은 인증성이다. 무결성은 변조 방지, 기밀성은 비인가 노출 방지, 가용성은 필요할 때 이용 보장이다.

    TCP에 대한 설명으로 옳지 않은 것은?

    1. 1. 비연결 지향 프로토콜이다.
    2. 2. 3-Way Handshaking을 통해 서비스를 연결 설정한다.
    3. 3. 포트 번호를 이용하여 서비스들을 구별하여 제공할 수 있다.
    4. 4. SYN Flooding 공격은 TCP 취약점에 대한 공격이다.

    정답 1번

    🔍 보기별 해설
    1. TCP는 데이터를 보내기 전에 연결을 먼저 맺고 순서 번호와 확인 응답으로 신뢰성을 확보하는 연결 지향 프로토콜이다. 비연결 지향은 UDP의 특징이므로 옳지 않다(정답).
    2. TCP는 SYN, SYN+ACK, ACK 세 번의 메시지 교환으로 연결을 설정한다. 이를 3-Way Handshaking이라 하고 양쪽의 시작 순서 번호를 맞추는 절차이므로 적절하다.
    3. TCP와 UDP는 IP 주소에 더해 포트 번호로 한 호스트 안의 응용 서비스를 구분한다. 웹은 80, SSH는 22처럼 서비스마다 포트를 다르게 쓰므로 적절하다.
    4. SYN Flooding은 SYN만 대량으로 보내 서버의 연결 대기 큐를 채워 새 연결을 받지 못하게 하는 공격이다. 3-Way Handshaking 과정의 취약점을 악용하므로 적절하다.
    🧮 풀이
    1. 甲은 파일 전송이 도중에 끊기지 않고 순서대로 도착하는 이유를 찾아보았다. 연결을 맺고 확인 응답으로 재전송하는 TCP 방식을 UDP와 나란히 표로 그리고 연결 지향 칸에 TCP를 적어 넣었다.
    2. 甲은 패킷 분석 도구로 웹 접속 장면을 잡아 첫 세 패킷의 플래그를 살펴보았다. SYN, SYN+ACK, ACK 순으로 오간다는 점을 확인하고 화살표 세 개로 그려 공책에 붙여 두었다.
    3. 甲은 한 서버에서 웹과 원격 접속이 동시에 돌아가는 화면을 열어 보았다. 두 서비스가 각각 80번과 22번 포트를 쓴다는 점을 짚고 포트 번호가 서비스를 구분하는 열쇠라고 옆에 적었다.
    4. 甲은 반쯤 열린 연결이 서버 대기 큐에 쌓이는 시험 환경 실습 그림을 보았다. 세 번째 ACK가 오지 않는 자리에서 큐가 차는 것을 확인하고 그 지점에 붉은 동그라미를 쳐 두었다.

    TCP는 연결 지향 프로토콜이다. 비연결 지향은 UDP의 성질이므로 1번이 옳지 않다.

    암호 알고리즘에 대한 설명으로 옳지 않은 것은?

    1. 1. 일반적으로 대칭키 암호 알고리즘은 비대칭키 암호 알고리즘에 비하여 빠르다.
    2. 2. 대칭키 암호 알고리즘에는 Diffie-Hellman 알고리즘이 있다.
    3. 3. 비대칭키 암호 알고리즘에는 타원 곡선 암호 알고리즘이 있다.
    4. 4. 인증서는 비대칭키 암호 알고리즘에서 사용하는 공개키 정보를 포함하고 있다.

    정답 2번

    🔍 보기별 해설
    1. 대칭키 알고리즘은 암호화와 복호화에 같은 키를 쓰고 연산이 단순해 지수 연산을 쓰는 비대칭키 방식보다 훨씬 빠르다. 그래서 대용량 데이터는 대칭키로 암호화하므로 적절하다.
    2. Diffie-Hellman은 이산 로그 문제에 기대어 두 사람이 공개된 채널에서 공통 비밀값을 만드는 키 교환 알고리즘이며 공개키 계열이다. 대칭키 알고리즘의 예가 아니므로 옳지 않다(정답).
    3. 타원 곡선 암호(ECC)는 타원 곡선 위의 이산 로그 문제에 기반한 공개키 암호로 RSA보다 짧은 키로 비슷한 강도를 얻는다. 비대칭키 알고리즘의 예로 맞으므로 적절하다.
    4. 인증서는 공개키와 소유자 정보를 묶어 인증기관이 전자서명한 문서이다. 공개키가 누구의 것인지 보증하는 도구로 비대칭키 방식에서 쓰이므로 적절하다.
    🧮 풀이
    1. 甲은 대용량 백업 파일을 암호화할 방법을 고르며 AES와 RSA의 처리 속도를 비교한 자료를 읽었다. 같은 키를 쓰는 AES가 훨씬 빠르다는 수치를 표에 옮겨 적고 대칭키 열에 별표를 달았다.
    2. 甲은 두 사람이 처음 만나 비밀 통신을 시작하는 그림에서 Diffie-Hellman을 보았다. 이 방식이 암호문을 만드는 것이 아니라 공통 비밀값을 만드는 키 교환이라는 설명에 밑줄을 긋고 분류표에서 공개키 칸으로 옮겼다.
    3. 甲은 스마트폰 서명에 쓰이는 알고리즘이 RSA보다 키가 훨씬 짧다는 기사를 읽었다. 타원 곡선 암호가 그 주인공이라는 점을 확인하고 공개키 알고리즘 목록에 RSA와 나란히 표시해 놓았다.
    4. 甲은 웹 브라우저의 자물쇠 표시를 눌러 사이트 인증서 창을 열었다. 발급 기관 서명과 공개키가 한 문서에 들어 있는 것을 눈으로 확인하고 각 항목 이름을 공책에 옮겨 적었다.

    Diffie-Hellman은 대칭키가 아니라 키 교환 알고리즘이며 공개키 계열이다. 대칭키 예는 AES·DES 등이다.

    TCP 세션 하이재킹에 대한 설명으로 옳은 것은?

    1. 1. 서버와 클라이언트가 통신할 때 TCP의 시퀀스 넘버를 제어하는 데 문제점이 있음을 알고 이를 이용한 공격이다.
    2. 2. 공격 대상이 반복적인 요구와 수정을 계속하여 시스템 자원을 고갈시킨다.
    3. 3. 데이터의 길이에 대한 불명확한 정의를 악용한 덮어쓰기로 인해 발생한다.
    4. 4. 사용자의 동의 없이 컴퓨터에 불법적으로 설치되어 문서나 그림 파일 등을 암호화한다.

    정답 1번

    🔍 보기별 해설
    1. TCP는 순서 번호를 통해 세션을 식별하고 순서를 맞추는데, 공격자가 이 번호를 알아내 정상 사용자인 척 패킷을 끼워 넣어 세션을 가로챈다. 서술 내용과 정확히 일치하므로 옳다(정답).
    2. 반복적인 요구로 시스템 자원을 고갈시키는 것은 서비스거부(DoS) 공격의 설명이다. 세션을 가로채는 하이재킹과는 목적과 방식이 다르므로 옳지 않다.
    3. 데이터 길이 정의가 불명확한 점을 악용해 덮어쓰는 것은 버퍼 오버플로우의 설명이다. 순서 번호를 이용하는 하이재킹과 원리가 다르므로 옳지 않다.
    4. 사용자 동의 없이 설치되어 파일을 암호화하는 것은 랜섬웨어의 설명이다. 이미 맺어진 연결을 가로채는 하이재킹과는 관계가 없으므로 옳지 않다.
    🧮 풀이
    1. 甲은 서버와 클라이언트가 주고받는 패킷에 붙은 순서 번호를 분석 도구로 열어 보았다. 공격자가 이 번호를 맞혀 끼어들면 세션을 가로챌 수 있다는 설명을 읽고 번호가 이어지는 화살표를 그려 보았다.
    2. 甲은 콘서트 예매 사이트가 요청 폭주로 멈춘 사고를 다룬 기사를 읽었다. 자원을 고갈시키는 서비스거부 공격이라 세션 하이재킹과 다르다고 판단하고 두 공격의 목적을 표에 나누어 적었다.
    3. 甲은 입력 길이를 검사하지 않는 C 함수 예제 코드를 열어 보았다. 긴 문자열이 옆 메모리를 덮어쓰는 버퍼 오버플로우 현상이라고 이름 붙이고 세션 하이재킹 항목과 선으로 갈라 놓았다.
    4. 甲은 어느 날 문서가 전부 암호화되고 금전을 요구하는 화면이 뜬 사례를 찾아보았다. 랜섬웨어의 증상이라는 점을 정리하고 하이재킹 설명과 나란히 붙여 두 공격의 차이를 표시했다.

    TCP 세션 하이재킹은 시퀀스 번호 제어의 허점을 이용해 연결에 끼어드는 공격이다.

    생체 인증 측정에 대한 설명으로 옳지 않은 것은?

    1. 1. FRR는 권한이 없는 사람이 인증을 시도했을 때 실패하는 비율이다.
    2. 2. 생체 인식 시스템의 성능을 평가하는 지표로는 FAR, EER, FRR 등이 있다.
    3. 3. 생체 인식 정보는 신체적 특징과 행동적 특징을 이용하는 것들로 분류한다.
    4. 4. FAR는 권한이 없는 사람이 인증을 시도했을 때 성공하는 비율이다.

    정답 1번

    🔍 보기별 해설
    1. FRR(오거부율)은 등록된 정당한 사용자가 인증을 시도했는데 거부당하는 비율이다. 권한 없는 사람이 시도해 실패하는 비율로 설명한 것은 사실과 다르므로 옳지 않다(정답).
    2. 생체 인식 시스템은 오인식률 FAR, 오거부율 FRR, 두 값이 같아지는 교차 오류율 EER 등으로 성능을 평가한다. 지표의 나열이 정확하므로 적절하다.
    3. 생체 정보는 지문·홍채·얼굴 같은 신체적 특징과 서명·걸음걸이·키보드 입력 습관 같은 행동적 특징으로 나눈다. 분류가 정확하므로 적절하다.
    4. FAR(오인식률)은 권한이 없는 사람이 다른 사람으로 인식되어 인증에 성공하는 비율이다. 보안 강도와 직결되는 지표이며 서술이 맞으므로 적절하다.
    🧮 풀이
    1. 甲은 지문 출입 장치가 등록된 직원의 손가락을 자꾸 거부하는 상황을 보았다. 정당한 사용자가 거부되는 비율이 FRR이라고 정리하고 오인식률과 헷갈리지 않게 정의를 옆에 굵게 적어 두었다.
    2. 甲은 얼굴 인식 시스템 제안서에 FAR, FRR, EER 세 지표가 함께 제시된 것을 보았다. 임계값을 조정할 때 두 오류율이 서로 반대로 움직인다는 그래프를 공책에 그려 보았다.
    3. 甲은 스마트폰 설정에서 지문 인식과 얼굴 인식, 손으로 그리는 서명 인식을 하나씩 켜 보았다. 신체 특징과 행동 특징으로 나누어 표를 만들고 걸음걸이와 서명은 행동 칸에 적어 넣었다.
    4. 甲은 남의 지문이 등록자로 잘못 인식되는 사고를 가정해 보았다. 이런 경우가 FAR로 측정된다는 점을 확인하고 보안 강도를 높이려면 이 값을 낮춰야 한다는 문장에 밑줄을 그었다.

    4. AES는 128비트 블록 단위로 입력을 받아 처리하는 블록 암호이다. 키 길이와 무관하게 블록 크기는 128비트로 고정이므로 서술이 정확해 적절하다.

    IPv6에 대한 설명으로 옳지 않은 것은?

    1. 1. IP주소 부족 문제를 해결하기 위하여 등장하였다.
    2. 2. 128 bit 주소공간을 제공한다.
    3. 3. 유니캐스트는 단일 인터페이스를 정의한다.
    4. 4. 목적지 주소는 유니캐스트, 애니캐스트, 브로드캐스트 주소로 구분된다.

    정답 4번

    🔍 보기별 해설
    1. IPv6는 IPv4의 주소 고갈 문제를 해결하려고 나온 프로토콜이다. 훨씬 넓은 주소 공간이 등장의 핵심 동기이므로 서술이 정확해 적절하다.
    2. IPv6는 128비트 주소를 사용해 IPv4의 32비트 주소보다 훨씬 많은 주소를 제공한다. 주소 길이 서술이 맞으므로 적절하다.
    3. IPv6 유니캐스트 주소는 하나의 인터페이스를 식별하며 이 주소로 보낸 패킷은 그 인터페이스 하나에만 전달된다. 정의가 맞으므로 적절하다.
    4. IPv6의 목적지 주소는 유니캐스트, 멀티캐스트, 애니캐스트로 나뉘며 브로드캐스트는 없고 멀티캐스트가 그 역할을 대신한다. 브로드캐스트를 포함했으므로 옳지 않다(정답).
    🧮 풀이
    1. 甲은 스마트폰과 사물인터넷 기기가 늘어나 IPv4 주소가 바닥났다는 통계를 읽었다. 이 문제를 풀려고 IPv6가 나왔다는 설명을 찾아 두 방식의 등장 배경을 표에 나란히 옮겨 적었다.
    2. 甲은 IPv4는 32비트, IPv6는 128비트라는 사실을 표로 정리했다. 128비트가 2의 128제곱 개의 주소를 뜻한다는 점을 계산기로 두드려 보고 숫자 자릿수를 옆에 써 넣었다.
    3. 甲은 IPv6 주소 세 가지를 그림으로 구분해 보았다. 유니캐스트는 한 기기, 멀티캐스트는 그룹, 애니캐스트는 가장 가까운 한 기기로 향하는 화살표를 그려 넣고 이름 옆에 뜻을 메모해 두었다.
    4. 甲은 IPv6 규격 자료에서 브로드캐스트라는 낱말을 찾아보았지만 어디에도 나오지 않았다. 그 역할을 멀티캐스트가 맡는다는 설명에 밑줄을 긋고 IPv4 주소 종류 표와 나란히 견주었다.

    IPv6에는 브로드캐스트가 없다. 주소는 유니캐스트·멀티캐스트·애니캐스트로 구분한다.

    SSH를 구성하는 프로토콜에 대한 설명으로 옳은 것은?

    1. 1. SSH는 보통 TCP상에서 수행되는 3개의 프로토콜로 구성된다.
    2. 2. 연결 프로토콜은 서버에게 사용자를 인증한다.
    3. 3. 전송계층 프로토콜은 SSH 연결을 사용하여 한 개의 논리적 통신 채널을 다중화한다.
    4. 4. 사용자 인증 프로토콜은 전방향 안전성을 만족하는 서버인증만을 제공한다.

    정답 1번

    🔍 보기별 해설
    1. SSH는 서버 인증과 암호화를 맡는 전송 계층, 클라이언트 인증을 맡는 사용자 인증, 채널을 다중화하는 연결의 세 프로토콜로 구성되며 보통 TCP 위에서 수행된다. 서술이 맞으므로 옳다(정답).
    2. 서버에게 사용자를 인증하는 것은 사용자 인증 프로토콜의 역할이다. 연결 프로토콜은 하나의 연결 안에 여러 논리 채널을 다중화하므로 옳지 않다.
    3. 한 개의 SSH 연결에 여러 논리 채널을 다중화하는 것은 연결 프로토콜의 역할이다. 전송 계층 프로토콜은 서버 인증·암호화·무결성을 맡으므로 옳지 않다.
    4. 사용자 인증 프로토콜은 서버에게 클라이언트를 인증하는 절차이고 서버 인증은 전송 계층 프로토콜에서 이루어진다. 서버 인증만 제공한다는 서술은 맞지 않으므로 옳지 않다.
    🧮 풀이
    1. 甲은 SSH 구조를 다룬 자료에서 프로토콜이 세 개라는 대목을 읽었다. 전송 계층, 사용자 인증, 연결을 위에서 아래로 쌓은 그림을 그리고 TCP 위에서 돈다고 밑에 적었다.
    2. 甲은 SSH 접속 때 서버에서 비밀번호나 키를 요구하는 단계를 관찰했다. 이 단계가 클라이언트를 서버에 인증하는 사용자 인증 프로토콜이라고 정리해 연결 프로토콜 칸과 구분해 표시했다.
    3. 甲은 하나의 SSH 세션에서 셸과 파일 전송이 동시에 돌아가는 장면을 보았다. 논리 채널 여러 개를 한 연결에 얹는 일을 연결 프로토콜이 맡는다고 그림 아래에 적어 두었다.
    4. 甲은 처음 접속할 때 서버 지문을 확인하라는 경고창을 열어 보았다. 서버 인증은 전송 계층에서 끝나고 사용자 인증은 그 뒤에 이어진다는 순서를 공책에 그려 붙여 두었다.

    SSH는 전송 계층, 사용자 인증, 연결의 세 프로토콜로 구성되며 TCP 위에서 동작한다.

    RSA를 적용하여 7의 암호문 11과 35의 암호문 42가 주어져 있을 때, 알고리즘의 수학적 특성을 이용하여 계산한 245(＝7 * 35)의 암호문은? (단, RSA 공개 모듈 n ＝ 247, 공개 지수 e ＝ 5)

    1. 1. 2
    2. 2. 215
    3. 3. 239
    4. 4. 462

    정답 2번

    🔍 보기별 해설
    1. 2는 두 암호문 11과 42를 곱한 뒤 n으로 나눈 나머지가 아니다. RSA의 곱셈 동형 성질로 계산하면 11×42=462를 247로 나눈 나머지 215가 나오므로 옳지 않다.
    2. RSA는 E(a)×E(b) mod n = E(a×b) 성질이 있으므로 11×42=462이고 462 mod 247=215이다. 따라서 245의 암호문은 215이므로 옳다(정답).
    3. 239는 두 암호문의 곱을 n으로 나눈 나머지와 일치하지 않는다. 462에서 247을 한 번 빼면 215가 되므로 옳지 않다.
    4. 462는 두 암호문을 곱하기만 하고 모듈러 n 연산을 하지 않은 값이다. RSA 암호문은 0 이상 n 미만이므로 247로 나눈 나머지를 구해야 하므로 옳지 않다.
    🧮 풀이
    1. 甲은 7의 암호문이 11, 35의 암호문이 42라는 값을 종이 위쪽에 적었다. 두 암호문을 곱한 462를 247로 나누어 나머지 215를 얻고 이것이 245의 암호문이라고 적어 넣었다.
    2. 甲은 나머지가 2가 되는 계산이 있는지 궁금해 11과 42로 여러 조합을 계산해 보았다. 곱해서 247로 나누면 215만 나온다는 점을 확인하고 다른 값들에는 가위 표시를 했다.
    3. 甲은 462에서 247을 빼는 계산을 종이에 직접 해 보았다. 한 번 빼면 215가 남고 239와는 맞지 않는다는 점을 확인해 그 옆에 빼기 과정을 함께 별표로 남겨 두었다.
    4. 甲은 462를 그대로 답으로 적으려다 손을 멈췄다. 암호문은 n보다 작은 값이라야 한다는 조건을 떠올리고 모듈러 연산을 거치는 과정을 계산식으로 보충해 적어 놓았다.

    RSA는 곱셈에 대해 동형이므로 E(7)·E(35) mod 247 = E(245)이다. 11×42=462, 462 mod 247=215이다.
