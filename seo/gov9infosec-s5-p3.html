    다음 리눅스 시스템의 ‘/etc/passwd’ 파일 내용에 대한 설명으로 옳지 않은 것은?

    root : x : 0 : 0 : root : /root : /bin/bash

    1. 1. 계정명은 ‘root’이다.
    2. 2. 패스워드는 ‘x’이다.
    3. 3. 홈 디렉터리는 ‘/root’이다.
    4. 4. 기본 shell 설정은 ‘bash’이다.

    정답 2번

    🔍 보기별 해설
    1. 계정명이 root라는 것은 필드를 콜론으로 나눴을 때 맨 앞자리에 그대로 적힌 값이 실제 그대로 맞으므로 이 설명은 옳다.
    2. 패스워드 자리에 적힌 x는 실제 패스워드 값이 아니라 진짜 암호화된 패스워드는 shadow 파일에 따로 있다는 것을 나타내는 표시일 뿐인데 지문은 이를 패스워드 자체라고 말하니 이 설명은 옳지 않다(정답).
    3. 홈 디렉터리가 /root라는 것은 필드를 콜론으로 나눴을 때 여섯 번째 자리에 그대로 적힌 값이므로 이 설명은 옳다.
    4. 기본 셸 설정이 bash라는 것은 필드를 콜론으로 나눴을 때 맨 마지막 자리에 그대로 적힌 값이므로 이 설명은 옳다.
    🧮 풀이
    1. 甲은 passwd 파일의 첫 필드를 콜론 기준으로 잘라내 그 자리에 계정명이 적혀 있는 것을 하나하나 확인해 보았다. root라는 값이 그대로 찍혀 있는 것을 정리했다.
    2. 甲은 두 번째 필드에 적힌 x라는 값을 실제 패스워드로 여기고 그 값을 그대로 로그인 시도에 써 보았다가 실패했다. 진짜 패스워드는 shadow 파일에 따로 암호화돼 있다는 것을 뒤늦게 확인했다.
    3. 甲은 passwd 파일의 여섯 번째 필드를 확인해 홈 디렉터리 경로가 /root로 적혀 있는 것을 확인해 보았다. 그 경로로 실제 로그인해 보니 정확히 그 위치에 놓이는 것을 확인했다.
    4. 甲은 passwd 파일 맨 마지막 필드에 적힌 셸 경로를 확인해 bash가 기본 셸로 지정된 것을 확인해 보았다. 로그인하자 실제로 그 셸이 실행되는 것을 확인했다.

    'x'는 패스워드 그 자체가 아니라 shadow에 있다는 표시라 2번이 옳지 않다.

    2021년에 발표된 OWASP Top 10의 항목 중, 서버가 적절한 검증 절차를 거치지 않은 요청을 처리하여, 접근통제를 우회하는 방식으로 서버의 내부 데이터가 탈취될 수 있는 취약점은?

    1. 1. XXE
    2. 2. SSRF
    3. 3. Cryptographic Failures
    4. 4. Insufficient Logging & Monitoring

    정답 2번

    🔍 보기별 해설
    1. XXE는 외부 XML 개체를 처리하는 과정이 취약해 서버 파일을 읽어내는 취약점이라 서버가 다른 곳으로 보낼 요청 자체를 위조당하는 이번 설명과는 다르므로 이 답은 옳지 않다.
    2. SSRF는 서버가 사용자 입력값을 제대로 검증하지 않고 그 값으로 만든 요청을 대신 보내면서 내부망 자원에 접근통제를 우회해 접근하게 되는 취약점이므로 이 답이 옳다(정답).
    3. Cryptographic Failures는 암호화가 허술하거나 아예 빠져 민감정보가 노출되는 문제라 접근통제 우회로 내부 데이터를 탈취하는 이번 설명과는 다르므로 이 답은 옳지 않다.
    4. Insufficient Logging & Monitoring은 침해 사고가 일어나도 기록과 감시가 부족해 알아차리지 못하는 문제라 접근통제 우회 자체를 가리키는 이번 설명과는 다르므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 XML 파싱 기능에 외부 개체 참조를 심어 서버의 내부 파일이 읽히는지 시험해 보았다. 이 취약점은 서버가 대신 요청을 보내는 방식과는 다른 갈래라는 것을 정리했다.
    2. 甲은 이미지 URL 입력창에 내부망 주소를 몰래 넣어 서버가 그 주소로 대신 요청을 보내게 만들어 보았다. 서버가 검증 없이 그 요청을 처리해 내부 시스템 정보가 응답으로 새어 나오는 것을 확인하고 SSRF 취약점으로 기록했다.
    3. 甲은 데이터베이스에 저장된 개인정보가 암호화 없이 평문 그대로인 것을 발견해 화면에 노출되는 것을 확인했다. 접근통제 우회가 아니라 암호화 자체가 빠진 문제라는 것을 정리했다.
    4. 甲은 침해 사고가 일어난 뒤 로그를 뒤져 봤지만 관련 기록이 거의 남아 있지 않은 것을 확인했다. 이 문제도 접근통제를 직접 우회하는 것과는 다른 갈래라는 것을 정리했다.

    검증 없이 요청을 처리해 접근통제를 우회당하는 취약점은 SSRF이므로 2번이 정답이다.

    HTTP 상태 코드에 대한 설명으로 옳지 않은 것은?

    1. 1. 301: Moved Permanently
    2. 2. 304: Not Modified
    3. 3. 401: Unauthorized
    4. 4. 405: Request Entity Too Large

    정답 4번

    🔍 보기별 해설
    1. 301은 요청한 자원이 새 주소로 영구히 옮겨졌다는 것을 나타내는 상태코드로 실제 표기 그대로이므로 이 설명은 옳다.
    2. 304는 캐시된 내용과 달라진 것이 없어 새로 보낼 필요가 없다는 것을 나타내는 상태코드로 실제 표기 그대로이므로 이 설명은 옳다.
    3. 401은 인증이 안 됐거나 실패해 접근이 거부됐다는 것을 나타내는 상태코드로 실제 표기 그대로이므로 이 설명은 옳다.
    4. 405는 요청 본문이 너무 크다는 뜻이 아니라 그 자원에 허용되지 않은 메소드로 요청했다는 것을 나타내는 상태코드인데 지문은 크기 문제라고 다르게 말하니 이 설명은 옳지 않다(정답).
    🧮 풀이
    1. 甲은 옛 주소로 접속했는데 브라우저가 자동으로 새 주소로 넘어가는 것을 확인하며 응답 코드가 301인 것을 개발자도구로 확인해 보았다. 영구 이동을 뜻하는 코드라는 것을 정리했다.
    2. 甲은 이미 캐시해 둔 페이지를 다시 요청했을 때 서버가 본문 없이 304 코드만 돌려주는 것을 확인해 보았다. 달라진 내용이 없어 새로 받을 필요가 없다는 뜻이라는 것을 정리했다.
    3. 甲은 로그인하지 않은 채로 보호된 페이지에 접근했을 때 401 코드가 돌아오는 것을 개발자도구 콘솔 화면으로 여러 번 확인해 보았다. 인증이 필요하다는 뜻이라는 것을 정리했다.
    4. 甲은 GET만 허용된 주소에 DELETE 요청을 보내 405 코드가 돌아오는 것을 확인해 보았다. 요청 크기가 아니라 허용되지 않은 메소드 때문이라는 것을 확인했다.

    405는 큰 요청이 아니라 허용되지 않은 메소드를 가리키는 코드인데 지문이 다르게 말해 4번이 옳지 않다.

    삽입된 악성 스크립트를 통해 사용자가 인지하지 못하는 상태에서 사용자의 권한으로 서버에 공격자가 의도한 요청을 하는 공격은?

    1. 1. Slowloris
    2. 2. CSRF
    3. 3. Heartbleed
    4. 4. DNS Cache Poisoning

    정답 2번

    🔍 보기별 해설
    1. Slowloris는 연결을 일부러 느리게 유지해 서버의 연결 자원을 고갈시키는 공격이라 사용자 권한을 빌려 요청을 대신 보내는 것과는 다르므로 이 답은 옳지 않다.
    2. CSRF는 사용자가 알아차리지 못하는 사이에 삽입된 스크립트나 링크가 그 사용자의 권한으로 서버에 원치 않은 요청을 대신 보내게 만드는 공격이므로 이 답이 옳다(정답).
    3. Heartbleed는 TLS의 하트비트 처리 취약점을 악용해 서버 메모리 내용을 몰래 읽어내는 공격이라 사용자 권한을 빌려 요청을 보내는 것과는 다르므로 이 답은 옳지 않다.
    4. DNS Cache Poisoning은 DNS 서버의 캐시에 거짓 정보를 심어 엉뚱한 주소로 연결시키는 공격이라 사용자 권한을 빌려 요청을 보내는 것과는 다르므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 서버에 연결을 걸어 두고 일부러 데이터를 아주 천천히 보내며 연결이 끊기지 않게 유지해 보았다. 연결 자원이 고갈되는 것을 확인하고 CSRF와는 다른 공격으로 기록했다.
    2. 甲은 로그인해 둔 사용자가 악성 이미지 태그가 심어진 페이지를 열자 그 사용자의 권한으로 비밀번호 변경 요청이 서버에 몰래 전송되는 것을 재현해 보았다. 사용자는 전혀 눈치채지 못하는 것을 확인하고 CSRF로 기록했다.
    3. 甲은 옛 버전의 취약한 TLS 서버에 조작된 짧은 하트비트 신호를 보내 되돌아오는 응답에 서버 메모리 조각이 함께 섞여 나오는지 눈으로 확인해 보았다. 사용자 권한을 빌려 요청을 대신 보내는 방식과는 다른 갈래라는 것을 정리했다.
    4. 甲은 DNS 서버의 캐시에 거짓 주소 정보를 주입해 사용자가 가짜 사이트로 연결되는지 시험해 보았다. 이 공격 역시 사용자 권한으로 요청을 대신 보내는 방식과는 다르다는 것을 정리했다.

    삽입된 스크립트가 사용자 몰래 그 권한으로 서버에 요청을 대신 보내는 공격은 CSRF이므로 2번이 정답이다.

    TLS에 속한 프로토콜 중 세션을 활성 상태로 유지하는 목적으로 사용하는 것은?

    1. 1. Alert Protocol
    2. 2. Connection Protocol
    3. 3. Heartbeat Protocol
    4. 4. Application Data Protocol

    정답 3번

    🔍 보기별 해설
    1. Alert Protocol은 오류나 경고 상황이 생겼을 때 그 사실을 상대에게 알리는 용도라 세션을 계속 살려 두는 목적과는 다르므로 이 답은 옳지 않다.
    2. Connection Protocol은 TLS가 아니라 SSH 같은 다른 프로토콜 계열에서 실제 데이터 채널을 여는 데 쓰이는 이름이라 이번 TLS 구성요소와는 다르므로 이 답은 옳지 않다.
    3. Heartbeat Protocol은 일정한 간격으로 짧은 신호를 주고받아 연결이 끊기지 않고 세션이 계속 살아 있도록 유지하는 목적으로 쓰이므로 이 답이 옳다(정답).
    4. Application Data Protocol은 실제 애플리케이션 데이터를 암호화해 주고받는 용도라 세션을 살려 두는 것 자체가 목적인 프로토콜과는 다르므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 TLS 세션 도중 오류가 발생하자 Alert Protocol을 통해 상대편에 경고 메시지가 전달되는 것을 패킷 캡처로 확인해 보았다. 세션을 살려 두는 것과는 다른 목적이라는 것을 정리했다.
    2. 甲은 SSH 접속에서 실제 명령을 주고받는 채널이 Connection Protocol로 열리는 것을 문서로 확인해 보았다. TLS의 세션 유지 기능과는 다른 계열의 용어라는 것을 정리했다.
    3. 甲은 TLS 연결을 맺어 둔 채 한동안 데이터를 안 보내도 Heartbeat Protocol 덕분에 세션이 끊기지 않고 유지되는 것을 확인해 보았다. 일정 간격으로 짧은 신호가 오가는 것을 패킷으로 확인했다.
    4. 甲은 로그인 뒤 실제 요청과 응답이 Application Data Protocol로 암호화돼 오가는 것을 패킷 캡처로 확인해 보았다. 세션 유지 자체를 위한 프로토콜과는 다른 역할이라는 것을 정리했다.

    세션을 활성 상태로 유지하는 목적의 TLS 프로토콜은 Heartbeat Protocol이므로 3번이 정답이다.

    프로세스에서 사용하는 메모리 영역의 위치를 랜덤하게 배치하는 기법은?

    1. 1. X.509
    2. 2. PAM
    3. 3. ASLR
    4. 4. ASBR

    정답 3번

    🔍 보기별 해설
    1. X.509는 공개키 인증서의 형식을 정한 표준이라 메모리 주소를 무작위로 배치하는 기법과는 다르므로 이 답은 옳지 않다.
    2. PAM은 여러 인증 방식을 통합해 관리할 수 있게 해 주는 모듈 체계라 메모리 주소를 무작위로 배치하는 기법과는 다르므로 이 답은 옳지 않다.
    3. ASLR은 프로그램이 실행될 때마다 스택·힙 같은 메모리 영역의 위치를 무작위로 흩어 놓아 공격자가 주소를 추측하기 어렵게 만드는 기법이므로 이 답이 옳다(정답).
    4. ASBR은 라우팅 프로토콜에서 다른 영역과 경계를 이루는 라우터를 가리키는 용어라 메모리 배치 기법과는 다르므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 서버에 설치된 공개키 인증서를 열어 X.509 형식으로 발급된 것을 상세정보로 확인해 보았다. 이 표준이 메모리 배치와는 무관한 인증서 형식이라는 것을 정리했다.
    2. 甲은 로그인 방식을 지문과 비밀번호 두 가지로 통합해 쓸 수 있도록 PAM 설정 파일을 고쳐 보았다. 이 체계가 메모리 주소를 흩는 기법과는 다른 목적이라는 것을 정리했다.

    3. SetUID는 맨 앞자리 숫자가 4일 때 표시되는 특수권한이라 이번 숫자 1과는 다르므로 이 답은 옳지 않다.
    4. chmod 1111에서 맨 앞자리 숫자 1은 Sticky Bit를 나타내고 나머지 세 자리 111은 소유자·그룹·기타 모두에게 실행 권한만 준다는 뜻이므로 특수권한으로는 Sticky Bit라는 이 답이 옳다(정답).
    🧮 풀이
    1. 甲은 디렉터리 권한을 ls -l로 확인하며 각 자리 맨 끝에 붙은 읽기 표시가 특수권한 숫자 자리와는 서로 다른 위치에 나타나는 것을 하나하나 자세히 확인해 보았다.
    2. 甲은 SetGID를 걸어 둔 디렉터리의 권한 숫자 맨 앞자리가 2로 나오는 것을 chmod 명령 결과로 확인해 보았다. 이번 문제의 1과는 다른 값이라는 것을 정리했다.
    3. 甲은 관리자 소유 실행파일에 SetUID를 걸어 두고 일반 계정으로 그 파일을 실행하며 권한 숫자 맨 앞자리 4가 뜻하는 대로 관리자 권한을 빌려 동작하는 것을 확인했다.
    4. 甲은 chmod 1111 명령으로 공유 디렉터리 권한을 설정한 뒤 ls -ld로 결과를 확인해 보았다. 맨 앞자리 특수권한이 t로 표시되며 Sticky Bit가 걸린 것을 확인했다.

    chmod 1111의 맨 앞자리 1은 Sticky Bit를 가리키므로 4번이 정답이다.

    보안 운영체제(Secure OS)에 대한 설명으로 옳지 않은 것은?

    1. 1. 보안 커널은 접근 제어 및 감사 추적을 위한 메커니즘을 포함하고 있다.
    2. 2. 패스워드의 설정 및 접근 허용의 변경 등과 같은 보안 관련 작업의 안전한 수행을 위해 안전한 경로(trusted path)를 제공한다.
    3. 3. TCB(Trusted Computing Base) 분할은 TCB를 계층화 구조로 구현하고, 각 계층은 고유의 보안 정책을 정의하기 때문에 기존의 TCB를 재사용할 수 없다.
    4. 4. 운영체제에 내재된 결함 때문에 발생할 수 있는 각종 해킹으로부터 시스템을 보호하기 위해 보안 기능이 통합된 보안 커널을 추가로 이식한 운영체제이다.

    정답 3번

    🔍 보기별 해설
    1. 보안 커널이 접근 제어와 감사 추적을 위한 메커니즘을 담고 있다는 것은 보안 운영체제의 핵심 구성 그대로이므로 이 설명은 옳다.
    2. 패스워드 설정이나 접근 허용 변경 같은 보안 작업을 안전하게 수행하도록 안전한 경로를 제공한다는 것은 보안 운영체제의 실제 기능 그대로이므로 이 설명은 옳다.
    3. TCB를 계층 구조로 나누면 각 계층이 저마다의 보안정책을 갖되 기존에 만들어 둔 TCB 계층을 그대로 가져다 다시 쓸 수 있는 것이 실제 목적인데 지문은 재사용할 수 없다고 거꾸로 말하니 이 설명은 옳지 않다(정답).
    4. 운영체제 안에 원래 없던 취약점을 노려 벌어지는 여러 해킹 시도를 막으려고 보안 기능을 하나로 묶은 보안 커널을 별도로 얹은 것이 보안 운영체제라는 정의이므로 이 설명은 옳다.
    🧮 풀이
    1. 甲은 보안 커널 안에 접근 제어 규칙과 감사 로그를 남기는 기능이 함께 들어 있는 것을 설계 문서로 확인해 보았다. 두 기능이 한 몸으로 묶여 동작하는 것을 정리했다.
    2. 甲은 관리자가 패스워드 정책을 바꿀 때 거치는 안전한 경로 화면이 따로 마련된 것을 직접 실습해 보았다. 일반 경로로는 그 작업을 할 수 없게 막혀 있는 것을 확인했다.
    3. 甲은 새 보안 정책을 적용하려고 TCB를 계층별로 나눈 뒤 이미 검증받은 아래 계층 TCB를 그대로 가져다 새 계층 위에 얹어 보았다. 기존 계층을 다시 만들지 않고도 재사용할 수 있는 것을 확인했다.
    4. 甲은 기존 운영체제의 커널 안에 보안 기능 모듈을 새로 이식해 각종 접근 시도가 그 모듈을 거치도록 설정해 보았다. 이식 전보다 통제가 훨씬 촘촘해지는 것을 시험 접속으로 확인했다.

    TCB 계층화는 오히려 기존 TCB를 재사용할 수 있게 해 주는 방식인데 지문이 못 한다고 해 3번이 옳지 않다.

    다음에서 설명하는 접근통제 모델은?

    ○ 정보 소유자가 정보의 보안 수준을 결정하고 그에 대한 접근 통제까지 설정하는 모델이다.

    ○ 중앙 집중화된 정보 관리가 어려워서 정보에 대한 엄격한 접근 통제는 거의 불가능하다.

    1. 1. 비바(Biba)
    2. 2. 임의적 접근통제(DAC)
    3. 3. 역할기반 접근통제(RBAC)
    4. 4. 벨 라파둘라(Bell-LaPadula)

    정답 2번

    🔍 보기별 해설
    1. 비바는 무결성을 지키기 위해 낮은 등급에서 높은 등급으로 함부로 쓰지 못하게 막는 모델이라 정보 소유자가 직접 접근통제를 정하는 이번 설명과는 다르므로 이 답은 옳지 않다.
    2. 임의적 접근통제는 정보를 가진 사람이 스스로 그 정보의 보안 수준과 접근 범위를 정하는 방식이라 중앙에서 일괄 관리하기 어려운 이번 설명과 그대로 맞으므로 이 답이 옳다(정답).
    3. 역할기반 접근통제는 직책이나 역할에 따라 미리 정해진 권한을 부여하는 방식이라 개인이 각자 접근통제를 정하는 이번 설명과는 다르므로 이 답은 옳지 않다.
    4. 벨 라파둘라는 기밀성을 지키기 위해 높은 등급의 정보가 낮은 등급으로 새지 못하게 막는 모델이라 정보 소유자가 직접 접근통제를 정하는 이번 설명과는 다르므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 군사기밀 문서가 상위 등급에서 하위 등급 사용자에게 새어 나가지 않는지 비바 모델 규칙으로 점검해 보았다. 이 규칙이 정보 소유자가 직접 접근통제를 정하는 방식과는 다르다는 것을 정리했다.
    2. 甲은 자신이 만든 문서 파일의 공유 설정을 열어 누구에게 읽기 권한을 줄지 스스로 하나하나 정해 보았다. 관리자가 일괄로 정한 것이 아니라 문서 소유자인 자신이 직접 정하는 것을 확인했다.
    3. 甲은 부서장이라는 직책에 미리 정해진 결재 권한이 자동으로 부여되는 것을 시스템 설정으로 확인해 보았다. 개인이 각자 접근통제를 정하는 방식과는 다르다는 것을 정리했다.
    4. 甲은 상위 등급 문서를 열람한 사용자가 그 내용을 하위 등급 문서에 복사해 옮기지 못하도록 막힌 것을 시험해 보았다. 이 통제 역시 정보 소유자가 직접 정하는 방식과는 다른 잣대라는 것을 정리했다.

    정보 소유자가 직접 보안수준과 접근통제를 정해 중앙관리가 어려운 모델은 DAC이므로 2번이 정답이다.

    멀웨어(Malware)에 대한 설명으로 옳은 것은?

    1. 1. 스파이웨어(Spyware)는 사용자 동의 없이 정보를 수집하여 전송한다.
    2. 2. 트로이목마(Trojan Horse)는 시스템 자원을 암호화하여 금전을 요구하는 공격을 수행한다.
    3. 3. 바이러스(Virus)는 독립적으로 실행되며, 취약점을 이용하여 스스로 전파된다.
    4. 4. 웜(Worm)은 정상 프로그램이나 실행 가능한 부분에 자신 또는 자신의 변형을 복사하며, 다른 네트워크의 시스템으로 스스로 전파하지 못한다.

    정답 1번

    🔍 보기별 해설
    1. 스파이웨어는 사용자가 알지 못하고 동의하지도 않은 채로 개인정보나 사용 기록을 몰래 모아 외부로 전송하는 악성코드이므로 이 설명이 옳다(정답).
    2. 시스템 자원을 암호화해 금전을 요구하는 것은 트로이목마가 아니라 랜섬웨어의 특징이므로 이 설명은 옳지 않다.
    3. 독립적으로 실행되며 취약점을 이용해 스스로 전파되는 것은 바이러스가 아니라 웜의 특징이라 이 설명은 옳지 않다.
    4. 정상 프로그램에 자신을 복사해 넣고 다른 네트워크로는 스스로 전파하지 못하는 것은 웜이 아니라 바이러스의 특징이라 이 설명은 옳지 않다.
    🧮 풀이
    1. 甲은 감염된 PC에서 사용자 몰래 방문 기록과 입력 내용이 외부 서버로 전송되는 것을 네트워크 로그로 확인해 보았다. 사용자 동의 없이 정보를 모아 보내는 스파이웨어의 전형적인 동작이라는 것을 정리했다.
    2. 甲은 회사 서버의 파일이 통째로 암호화되고 복구 대가를 요구하는 화면이 뜬 사고를 조사하며 그것을 트로이목마가 아니라 랜섬웨어로 분류했다. 자원을 인질로 잡는 방식이 트로이목마의 정의와는 다르다는 것을 확인했다.
    3. 甲은 한 대에서 시작된 감염이 취약점을 타고 같은 네트워크의 다른 PC로 순식간에 번지는 것을 관찰하며 그것을 바이러스가 아니라 웜으로 분류했다. 독립적으로 스스로 퍼지는 특징이 바이러스와는 다르다는 것을 확인했다.
    4. 甲은 정상 문서 파일에 몰래 끼어들어 그 파일이 열릴 때마다 함께 실행되는 코드를 발견하고 그것을 웜이 아니라 바이러스로 분류했다. 숙주 파일 없이는 전파되지 못하는 특징이 웜과는 다르다는 것을 확인했다.

    스파이웨어는 동의 없이 정보를 모아 전송하는 악성코드라는 설명이 맞아 1번이 정답이다.

    다음에서 설명하는 공격은?

    ○ 공격자가 특정 대상을 목표로 다양한 공격 기술을 이용해 지속적으로 공격한다.

    ○ 이 공격의 사례는 제로데이 취약점을 활용한 Stuxnet이 있다.

    1. 1. APT
    2. 2. DDoS
    3. 3. Ransomware
    4. 4. Reverse Engineering

    정답 1번

    🔍 보기별 해설
    1. APT는 특정 대상을 정해 놓고 여러 공격 기술을 오래도록 동원해 끈질기게 공격하는 방식이며 제로데이를 활용한 Stuxnet이 대표 사례로 꼽히므로 이 답이 옳다(정답).
    2. DDoS는 여러 곳에서 한꺼번에 트래픽을 퍼부어 서비스를 마비시키는 공격이라 특정 대상을 오래도록 노리는 지속적 공격과는 다르므로 이 답은 옳지 않다.
    3. Ransomware는 자원을 암호화해 금전을 요구하는 악성코드라 여러 기술을 동원한 지속적인 표적 공격 방식과는 다르므로 이 답은 옳지 않다.
    4. Reverse Engineering은 프로그램을 분석해 내부 동작을 파악하는 기법이라 특정 대상을 노린 공격 그 자체와는 다르므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 특정 발전소 시설을 겨냥해 여러 달에 걸쳐 다양한 방법으로 침투를 시도한 사고 사례를 조사하며 그것을 APT 공격으로 분류했다. Stuxnet 사례와 비슷한 성격이라는 것을 확인했다.
    2. 甲은 여러 대의 좀비 PC가 동시에 서버로 트래픽을 쏟아부어 서비스가 마비되는 것을 모니터링 화면으로 지켜보았다. 특정 대상을 오래도록 노리는 것이 아니라 순간적으로 몰아치는 방식이라는 것을 정리했다.
    3. 甲은 감염된 서버의 파일이 암호화되고 복구 대가를 요구하는 화면을 발견해 랜섬웨어 사고로 판단했다. 여러 기술을 동원한 지속적 표적 공격과는 다른 성격이라는 것을 정리했다.
    4. 甲은 배포된 프로그램의 실행파일을 디스어셈블러로 천천히 열어 내부 로직을 한 줄씩 자세히 분석해 보았다. 이 작업 자체는 공격이 아니라 분석 기법이라는 것을 정리했다.

    특정 대상을 목표로 지속적으로 공격하며 Stuxnet이 사례로 꼽히는 공격은 APT이므로 1번이 정답이다.

    침입탐지시스템(IDS)에 대한 설명으로 옳지 않은 것은?

    1. 1. 이상탐지(Anomaly Detection)는 시그니처(Signature) 기반 탐지라고도 한다.
    2. 2. 제로데이(Zero-day) 공격에 대한 탐지는 오용탐지에 비해 이상탐지가 효율적이다.
    3. 3. 오용탐지(Misuse Detection)는 알려진 공격의 패턴을 탐지하는 방법이다.
    4. 4. 이상탐지(Anomaly Detection)는 정상적이고 평균적인 상태를 크게 벗어나는 이벤트가 발생하는 것을 탐지하는 방법이다.

    정답 1번

    🔍 보기별 해설

    2. 甲은 (나) 자리에 적힌 최대 사용 일수가 지나도록 패스워드를 안 바꾼 계정이 로그인 화면에서 강제로 변경을 요구받는 모습을 여러 번 직접 눈으로 확인해 보았다.
    3. 甲은 (다) 자리에 적힌 경고 일수만큼 만료가 다가오면 로그인할 때마다 곧 바꾸라는 안내 문구가 화면 위에 빠짐없이 계속 뜨는 것을 여러 날에 걸쳐 확인해 보았다.
    4. 甲은 (라) 자리를 계정이 아예 사라지는 만료일로 여기고 그날이 지나면 계정이 삭제될 것이라 짐작했다가 실제로는 패스워드 만료 뒤 계정이 잠기기까지 걸리는 유예 일수라는 것을 문서로 다시 확인했다.
