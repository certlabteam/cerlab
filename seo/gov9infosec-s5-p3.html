    다음 리눅스 시스템의 ‘/etc/passwd’ 파일 내용에 대한 설명으로 옳지 않은 것은?

    root : x : 0 : 0 : root : /root : /bin/bash

    1. 1. 계정명은 ‘root’이다.
    2. 2. 패스워드는 ‘x’이다.
    3. 3. 홈 디렉터리는 ‘/root’이다.
    4. 4. 기본 shell 설정은 ‘bash’이다.

    정답 2번

    🔍 보기별 해설
    1. /etc/passwd의 첫째 필드는 사용자 계정명이고 이 줄에는 root가 적혀 있다. 계정명을 바르게 읽었으므로 옳다.
    2. 둘째 필드의 x는 실제 비밀번호가 아니라 암호화된 비밀번호가 /etc/shadow에 따로 저장되어 있다는 표시다. 비밀번호 자체를 x로 본 것은 잘못이므로 옳지 않다(정답).
    3. 여섯째 필드는 로그인 후 처음 들어가는 홈 디렉터리이며 이 줄에는 /root가 적혀 있다. 홈 디렉터리를 바르게 읽었으므로 옳다.
    4. 마지막 필드는 로그인 셸의 경로이고 /bin/bash가 적혀 있어 기본 셸은 bash다. 셸 설정을 바르게 읽었으므로 옳다.
    🧮 풀이
    1. 사내 서버를 넘겨받은 스타트업 개발자 甲은 cut -d: -f1 /etc/passwd를 실행해 계정 목록을 뽑았다. 맨 위 줄 첫 칸에 root가 나와 관리자 계정 이름이 그대로 쓰이고 있었고, 甲은 원격 root 로그인을 막았다. 첫 필드가 계정명이다.
    2. 신입 보안 담당 甲은 passwd 파일 둘째 칸의 x를 비밀번호로 착각해 x를 입력해 로그인하려다 실패했다. 선배는 진짜 해시값은 root만 읽을 수 있는 /etc/shadow에 있다고 알려 주었다. x는 섀도 패스워드를 쓴다는 표시일 뿐이다.
    3. 운영팀 甲은 통신사 서버에 root로 로그인하자마자 pwd를 입력해 현재 위치가 /root로 나오는 것을 보았다. 일반 사용자처럼 /home 아래가 아니라 별도 경로가 홈 디렉터리로 지정되어 있었다. 여섯째 필드가 홈 경로를 정한다.
    4. 서버 관리자 甲은 게임 서버에 root로 로그인한 직후 echo $SHELL을 실행해 /bin/bash가 출력되는 것을 보았다. passwd 마지막 칸에 적힌 셸이 로그인할 때 그대로 실행된 것이다. 甲은 서비스 계정만 /sbin/nologin으로 바꿔 로그인을 막았다.

    passwd 둘째 필드의 x는 비밀번호 자체가 아니라 암호화된 비밀번호가 /etc/shadow에 따로 있다는 표시이므로 정답은 2번이다.

    2021년에 발표된 OWASP Top 10의 항목 중, 서버가 적절한 검증 절차를 거치지 않은 요청을 처리하여, 접근통제를 우회하는 방식으로 서버의 내부 데이터가 탈취될 수 있는 취약점은?

    1. 1. XXE
    2. 2. SSRF
    3. 3. Cryptographic Failures
    4. 4. Insufficient Logging & Monitoring

    정답 2번

    🔍 보기별 해설
    1. XXE(XML External Entity)는 XML 파서가 외부 엔티티를 처리할 때 이를 악용해 서버 파일을 읽는 취약점으로, 2021년판에서는 보안 설정 오류 항목에 묶였다. 검증 없는 요청 처리로 접근통제를 우회하는 독립 항목이 아니므로 옳지 않다.
    2. SSRF(Server-Side Request Forgery)는 서버가 사용자가 준 URL을 검증 없이 대신 요청하게 만들어 내부망 자원에 접근하는 취약점으로 2021년 A10에 새로 들어갔다. 서버를 앞세워 접근통제를 우회한다는 설명과 같으므로 옳다(정답).
    3. Cryptographic Failures는 약한 알고리즘 사용이나 평문 전송처럼 암호화가 부족해 민감 정보가 노출되는 취약점으로 2021년 A02 항목이다. 서버가 요청을 대신 보내는 문제와 다르므로 옳지 않다.
    4. Insufficient Logging & Monitoring은 공격 흔적을 기록·감시하지 못해 침해를 늦게 알게 되는 취약점을 가리키던 2017년판 항목 이름이다. 접근통제를 우회해 데이터가 빠지는 원리를 말하지 않으므로 옳지 않다.
    🧮 풀이
    1. 견적서 업로드 기능을 만든 제조 스타트업 개발자 甲은 XML 파일에 외부 엔티티로 /etc/passwd를 불러오는 구문이 들어간 것을 발견했다. 파서가 그대로 처리해 응답 화면에 서버 계정 목록이 찍혀 나왔고, 甲은 외부 엔티티 처리를 꺼 버렸다. XXE 공격이다.
    2. 이미지 미리보기 기능을 운영하던 클라우드 업체 개발자 甲은 URL 칸에 169.254.169.254 내부 주소가 입력된 요청을 로그에서 찾았다. 서버가 그 주소를 대신 불러 클라우드 접근 키가 담긴 메타데이터를 응답에 실어 보냈고, 甲은 내부 대역 주소로 가는 요청을 막는 허용 목록을 만들었다. 외부 사용자가 서버를 앞세워 내부에 들어온 SSRF다.
    3. 회원 DB를 점검하던 게임사 보안 담당 甲은 비밀번호가 솔트 없이 MD5로만 저장되어 있는 것을 발견했다. 유출된 해시는 레인보 테이블로 몇 분 만에 풀렸고, 甲은 bcrypt로 저장 방식을 바꿨다. 암호화가 부실한 Cryptographic Failures 사례다.
    4. 침해 사고를 조사하던 통신사 보안관제 甲은 공격자가 석 달 동안 관리자 페이지에 드나들었는데도 접속 로그가 하나도 없는 것을 발견했다. 기록도 경보도 없어 침해 사실을 고객 신고로 처음 알게 된 것이었다. Insufficient Logging & Monitoring의 결과다.

    서버가 사용자가 준 URL을 검증 없이 대신 요청해 내부 자원이 노출되는 취약점은 2021년 A10 SSRF이므로 정답은 2번이다.

    HTTP 상태 코드에 대한 설명으로 옳지 않은 것은?

    1. 1. 301: Moved Permanently
    2. 2. 304: Not Modified
    3. 3. 401: Unauthorized
    4. 4. 405: Request Entity Too Large

    정답 4번

    🔍 보기별 해설
    1. 301 Moved Permanently는 요청한 자원이 새 URL로 영구히 옮겨졌음을 알리는 리다이렉션 코드다. 코드와 의미가 바르게 짝지어졌으므로 옳다.
    2. 304 Not Modified는 조건부 요청에서 자원이 바뀌지 않아 브라우저 캐시를 그대로 쓰면 된다는 응답이다. 코드와 의미가 일치하므로 옳다.
    3. 401 Unauthorized는 인증 정보가 없거나 틀려 먼저 인증을 거쳐야 접근할 수 있다는 응답이다. 코드와 이름이 맞으므로 옳다.
    4. 405는 Method Not Allowed로 자원이 그 HTTP 메소드를 허용하지 않을 때 쓰며, Request Entity Too Large는 413번 코드다. 405에 413의 이름을 붙였으므로 옳지 않다(정답).
    🧮 풀이
    1. 도메인을 바꾼 스타트업 개발자 甲은 옛 주소로 들어오는 요청에 301 Moved Permanently와 새 주소를 돌려주도록 웹 서버를 설정했다. 몇 주 뒤 검색엔진도 새 주소를 정식 주소로 바꿔 등록했다. 영구 이동을 알리는 응답이다.
    2. 게임 공지 페이지를 운영하는 웹 담당 甲은 브라우저가 If-Modified-Since 헤더를 붙여 다시 요청하자 서버가 본문 없이 304 Not Modified만 돌려주는 것을 보았다. 바뀐 것이 없어 이미 받아 둔 캐시가 화면에 바로 떴다. 트래픽을 줄이는 응답이다.
    3. 공장 설비 API를 호출하던 협력사 개발자 甲은 토큰을 빠뜨린 채 요청했다가 401 Unauthorized를 받았다. 발급받은 인증 토큰을 헤더에 넣어 다시 보내자 정상 데이터가 왔다. 인증이 먼저 필요하다는 신호다.
    4. 요금 조회 API를 시험하던 통신사 개발자 甲은 조회 전용 주소에 DELETE 요청을 보냈다가 405 응답을 받았다. 이어 50MB 파일을 업로드 창에 올렸을 때는 413 Request Entity Too Large가 돌아왔다. 메소드 거부와 본문 크기 초과는 서로 다른 코드다.

    405는 Method Not Allowed이고 Request Entity Too Large는 413번 코드이므로 둘을 잘못 짝지은 4번이 옳지 않다. 정답은 4번이다.

    삽입된 악성 스크립트를 통해 사용자가 인지하지 못하는 상태에서 사용자의 권한으로 서버에 공격자가 의도한 요청을 하는 공격은?

    1. 1. Slowloris
    2. 2. CSRF
    3. 3. Heartbleed
    4. 4. DNS Cache Poisoning

    정답 2번

    🔍 보기별 해설
    1. Slowloris는 HTTP 헤더를 아주 느리게 조금씩 보내 웹 서버 연결을 오래 붙잡아 두는 서비스 거부 공격이다. 사용자 권한으로 요청을 위조하는 공격이 아니므로 옳지 않다.
    2. CSRF(Cross-Site Request Forgery)는 피해자가 로그인한 상태에서 악성 스크립트가 피해자 모르게 그 권한으로 서버에 요청을 보내게 하는 공격이다. 사용자 몰래 공격자가 원하는 요청을 대신 보내게 하므로 옳다(정답).
    3. Heartbleed는 OpenSSL의 하트비트 확장이 요청 길이를 검증하지 않아 서버 메모리 내용이 새어 나간 취약점이다. 요청 위조가 아닌 메모리 노출 문제이므로 옳지 않다.
    4. DNS Cache Poisoning은 DNS 서버 캐시에 위조된 응답을 심어 사용자를 가짜 IP로 보내는 공격이다. 사용자의 권한을 빌려 서버에 요청하는 방식이 아니므로 옳지 않다.
    🧮 풀이
    1. 게임 웹사이트 운영자 甲은 동시 접속이 수백 개뿐인데도 웹 서버가 새 연결을 받지 못하는 현상을 겪었다. 연결마다 헤더가 몇 초에 한 줄씩만 들어와 서버 작업자가 모두 묶여 있었고, 甲은 헤더 수신 시간 제한을 걸었다. Slowloris 공격이다.
    2. 온라인 쇼핑몰에 로그인해 둔 통신사 직원 甲은 커뮤니티 게시글 하나를 열었을 뿐인데 배송지가 낯선 주소로 바뀌었다. 글에 숨은 스크립트가 甲의 세션 쿠키를 그대로 실어 배송지 변경 요청을 쇼핑몰로 보낸 것이었다. 쇼핑몰은 요청마다 CSRF 토큰을 검사하도록 고쳤다.
    3. 2014년 서버를 점검하던 스타트업 개발자 甲은 사용 중인 OpenSSL 버전이 Heartbleed에 취약하다는 경보를 받았다. 하트비트 요청 하나로 서버 메모리가 최대 64KB씩 새어 나가 개인키까지 노출될 수 있어, 甲은 패치 후 인증서를 다시 발급했다. 길이 검증이 빠진 결함이었다.
    4. 사내 DNS 서버를 운영하는 제조사 전산팀 甲은 직원들이 협력사 포털 주소로 접속하면 피싱 페이지가 뜬다는 신고를 받았다. 캐시에 위조된 IP 응답이 저장되어 있어 甲은 캐시를 비우고 DNSSEC 검증을 켰다. DNS Cache Poisoning 피해다.

    로그인한 사용자도 모르게 그 사용자의 권한으로 공격자가 원하는 요청을 서버에 보내게 하는 공격은 CSRF이므로 정답은 2번이다.

    TLS에 속한 프로토콜 중 세션을 활성 상태로 유지하는 목적으로 사용하는 것은?

    1. 1. Alert Protocol
    2. 2. Connection Protocol
    3. 3. Heartbeat Protocol
    4. 4. Application Data Protocol

    정답 3번

    🔍 보기별 해설
    1. Alert Protocol은 TLS 통신 중 생긴 오류나 연결 종료를 상대에게 경고 메시지로 알리는 프로토콜이다. 세션을 살려 두는 용도가 아니므로 옳지 않다.
    2. Connection Protocol은 SSH를 이루는 프로토콜 이름이고 TLS의 하위 프로토콜에는 이런 이름이 없다. TLS 세션을 유지하는 기능과 무관하므로 옳지 않다.
    3. Heartbeat Protocol은 데이터가 오가지 않는 동안에도 짧은 요청과 응답을 보내 상대가 살아 있는지 보고 세션을 유지하는 TLS 확장이다. 세션을 활성 상태로 유지하는 목적과 같으므로 옳다(정답).
    4. Application Data Protocol은 핸드셰이크로 정한 키로 응용 계층 데이터를 암호화해 실어 나르는 프로토콜이다. 실제 데이터 전송이 목적이지 세션 유지용이 아니므로 옳지 않다.
    🧮 풀이
    1. 결제 서버를 운영하는 핀테크 스타트업 개발자 甲은 인증서가 만료된 서버에 접속하자 클라이언트가 즉시 연결을 끊는 것을 보았다. 패킷을 열어 보니 certificate expired 경고가 Alert Protocol 메시지로 오가 있었다. 오류를 알리는 TLS 프로토콜이다.
    2. SSH 접속 장애를 분석하던 통신사 엔지니어 甲은 채널 열기와 포트 포워딩을 맡는 부분이 SSH의 Connection Protocol이라는 것을 문서에서 보았다. TLS 패킷에는 그런 이름의 레코드 타입이 없어 甲은 분석 대상을 SSH 쪽으로 좁혔다. 두 보안 프로토콜은 구성이 다르다.
    3. 실시간 대전 게임 서버를 운영하는 甲은 플레이어가 잠시 입력을 멈춰도 연결이 끊기지 않도록 TLS Heartbeat Protocol을 켰다. 몇 초마다 작은 요청과 응답이 오가며 세션이 살아 있음을 서로 알렸다. 이 확장의 구현 결함이 뒷날 Heartbleed로 이어졌다.
    4. 스마트 공장 센서 데이터를 서버로 보내는 엔지니어 甲은 핸드셰이크가 끝난 뒤 실제 측정값이 Application Data Protocol 레코드로 암호화되어 전송되는 것을 보았다. 패킷을 캡처해도 측정값은 읽히지 않았다. 응용 데이터를 운반하는 TLS 프로토콜이다.

    프로세스에서 사용하는 메모리 영역의 위치를 랜덤하게 배치하는 기법은?

    1. 1. X.509
    2. 2. PAM
    3. 3. ASLR
    4. 4. ASBR

    정답 3번

    🔍 보기별 해설
    1. X.509는 공개키 인증서의 형식과 필드를 정한 ITU-T 표준이다. 인증서 규격이지 메모리 배치를 바꾸는 기법이 아니므로 옳지 않다.
    2. PAM(Pluggable Authentication Modules)은 리눅스에서 인증 방식을 모듈로 끼워 바꿀 수 있게 한 인증 체계다. 메모리 주소를 무작위로 두는 기법이 아니므로 옳지 않다.
    3. ASLR(Address Space Layout Randomization)은 실행할 때마다 스택·힙·라이브러리의 메모리 주소를 무작위로 바꾸는 기법이다. 메모리 영역 위치를 랜덤하게 배치한다는 설명과 같으므로 옳다(정답).
    4. ASBR은 OSPF 라우팅에서 다른 자율 시스템과 경로를 주고받는 경계 라우터(Autonomous System Boundary Router)를 가리킨다. 메모리 보호 기법의 이름이 아니므로 옳지 않다.
    🧮 풀이
    1. PKI 담당 甲은 통신사 인증서를 openssl로 열어 발급자, 유효기간, 공개키 필드가 X.509 형식대로 들어 있는 것을 보았다. 브라우저도 같은 형식을 읽어 그 인증서를 믿을지 판단한다. 인증서 규격이 X.509다.
    2. 리눅스 서버에 OTP 로그인을 붙이려던 게임사 관리자 甲은 /etc/pam.d/sshd에 OTP 모듈 한 줄을 추가했다. SSH 프로그램을 고치지 않았는데도 다음 로그인부터 비밀번호 뒤에 OTP를 묻게 되었다. 모듈만 바꿔 끼우는 PAM 구조 덕분이다.
    3. 취약점을 시험하던 보안 연구원 甲은 같은 프로그램을 세 번 실행하며 libc 주소를 출력했는데 매번 값이 달랐다. 미리 알아 둔 고정 주소로 짠 공격 코드는 실행할 때마다 엉뚱한 곳으로 뛰어 번번이 실패했다. 운영체제의 ASLR이 스택과 라이브러리 위치를 매번 흩어 놓았기 때문이다.
    4. 망 연동을 설계하던 통신사 네트워크 엔지니어 甲은 사내 OSPF 망과 외부 BGP 망이 만나는 라우터를 ASBR로 지정했다. 이 라우터가 외부 경로를 OSPF 안으로 전달했다. 라우팅 장비의 역할 이름이지 메모리 보호 기법은 아니다.

    실행할 때마다 스택·힙·공유 라이브러리의 메모리 주소를 무작위로 배치하는 기법은 ASLR이므로 정답은 3번이다.

    PGP에 대한 설명으로 옳지 않은 것은?

    1. 1. IETF에 의해 개발되었다.
    2. 2. 전자 서명을 통해 인증을 제공한다.
    3. 3. ZIP 알고리즘으로 압축을 제공한다.
    4. 4. 대칭 키 암호를 통해 기밀성을 제공한다.

    정답 1번

    🔍 보기별 해설
    1. PGP는 1991년 필 짐머만(Phil Zimmermann)이 개인적으로 개발해 공개한 전자우편 보안 프로그램이며, IETF는 뒤에 이를 OpenPGP 표준으로 만들었다. IETF가 개발했다는 말은 잘못이므로 옳지 않다(정답).
    2. PGP는 송신자의 개인키로 메시지 해시에 전자 서명을 붙여 받는 쪽이 보낸 사람과 내용의 무결성을 검증하게 한다. 서명으로 인증을 제공하므로 옳다.
    3. PGP는 서명 뒤 암호화 전에 ZIP 알고리즘으로 메시지를 압축해 크기를 줄이고 암호 강도를 높인다. 압축 기능을 제공하므로 옳다.
    4. PGP는 메시지를 일회용 세션키로 대칭 암호화하고 그 세션키만 수신자 공개키로 암호화해 보낸다. 대칭 키 암호로 기밀성을 지키므로 옳다.
    🧮 풀이
    1. 메일 보안 교육 자료를 만들던 통신사 보안팀 甲은 PGP를 IETF가 만든 것으로 적었다가 출처를 다시 찾았다. PGP는 짐머만이 혼자 만들어 배포했고, IETF는 이후 RFC로 OpenPGP 형식을 표준화한 것이었다. 甲은 자료의 개발 주체를 고쳤다.
    2. 협력 공장에 설계 변경 메일을 보내는 엔지니어 甲은 PGP로 메일에 전자 서명을 붙였다. 받은 쪽은 甲의 공개키로 서명을 검증해 위조 메일이 아님을 바로 알 수 있었다. 서명이 보낸 사람을 인증해 준 것이다.
    3. 대용량 로그를 PGP로 암호화해 보내던 스타트업 개발자 甲은 결과 파일이 원본보다 훨씬 작아진 것을 보았다. 암호화 전에 ZIP 압축 단계가 들어가 되풀이되는 문자열이 줄어든 것이었다. 압축은 전송량을 줄이고 패턴 분석도 어렵게 한다.
    4. 상금 명단을 보내는 게임 대회 운영자 甲은 PGP가 명단 파일을 무작위 세션키로 대칭 암호화하는 것을 보았다. 그 세션키만 받는 사람의 공개키로 감싸 함께 보내니 빠르면서도 안전했다. 기밀성은 대칭 암호가 맡는다.

    PGP는 IETF가 아니라 필 짐머만이 개인적으로 개발했고 IETF는 뒤에 이를 OpenPGP로 표준화했으므로 정답은 1번이다.

    nmap 명령어의 옵션에 대한 설명으로 옳지 않은 것은?

    1. 1. -O 옵션은 운영체제를 확인한다.
    2. 2. -R 옵션은 RPC 스캔을 실시한다.
    3. 3. -n 옵션은 DNS Lookup을 하지 않는다.
    4. 4. -v 옵션은 스캔 결과를 상세하게 출력한다.

    정답 2번

    🔍 보기별 해설

    2. nmap의 -R 옵션은 모든 대상에 역방향 DNS 조회를 항상 하도록 하는 옵션이고, RPC 스캔은 예전 -sR 옵션이 맡았다. -R을 RPC 스캔으로 본 것은 잘못이므로 옳지 않다(정답).
    3. nmap의 -n 옵션은 IP 주소를 호스트 이름으로 바꾸는 DNS Lookup을 건너뛰게 해 스캔을 빠르게 한다. 이름 풀이 생략 옵션이므로 옳다.
    4. nmap의 -v 옵션은 진행 상황과 결과를 더 자세히 보여 주는 verbose 출력 옵션이다. 상세 출력 기능이므로 옳다.

    1. 공장 네트워크 자산을 조사하던 보안 담당 甲은 생산 라인 서버 한 대에 nmap -O를 실행했다. 결과에 리눅스 커널 4 계열로 추정된다는 줄이 나와 甲은 그 장비를 리눅스 패치 대상 목록에 넣었다. 응답 특성으로 OS를 맞히는 기능이다.
    2. RPC 서비스를 찾던 통신사 점검팀 甲은 nmap -R을 붙였는데 결과에 IP마다 호스트 이름만 늘어났다. 매뉴얼을 보니 -R은 역방향 DNS 조회를 강제하는 옵션이었고 RPC 탐지는 -sV 버전 탐지가 맡고 있었다. 甲은 옵션을 바꿔 다시 스캔했다.
    3. 대역 전체를 급히 훑어야 하던 모의해킹 담당 甲은 DNS 서버 응답이 느려 스캔이 지연되자 nmap -n을 붙였다. 호스트 이름 조회를 건너뛰니 같은 대역의 스캔 시간이 절반 가까이 줄었다. DNS Lookup을 생략한 효과다.
    4. 신입 관제요원 甲은 nmap 스캔이 조용히 멈춘 것처럼 보이자 -v를 붙여 다시 실행했다. 열린 포트를 찾을 때마다 바로 화면에 표시되고 남은 시간도 나와 진행 상황을 따라갈 수 있었다. 출력을 자세히 보여 주는 옵션이다.

    nmap의 -R은 모든 대상에 역방향 DNS 조회를 강제하는 옵션이지 RPC 스캔 옵션이 아니므로 정답은 2번이다.

    빈칸에 들어갈 내용은?

    프로그램을 실행시키기 위한 가상의 메모리 공간이 할당되면, 할당된 메모리 공간은 여러 영역으로 나뉘어 관리된다. 그중 은 프로세스 로직이 실행되는 데 필요한 파라미터, 지역변수, 반환 주소 등이 저장된다.

    1. 1. 텍스트 영역
    2. 2. 힙 영역
    3. 3. 스택 영역
    4. 4. 데이터 영역

    정답 3번

    🔍 보기별 해설
    1. 텍스트 영역은 CPU가 실행할 기계어 코드가 읽기 전용으로 올라가는 곳이다. 파라미터나 지역변수를 담지 않으므로 옳지 않다.
    2. 힙 영역은 malloc이나 new처럼 실행 중에 동적으로 할당하는 메모리가 놓이는 곳이다. 함수 호출 정보를 쌓는 곳이 아니므로 옳지 않다.
    3. 스택 영역은 함수가 호출될 때마다 파라미터, 지역변수, 돌아갈 반환 주소를 프레임 단위로 쌓았다가 함수가 끝나면 해제하는 곳이다. 빈칸의 설명과 같으므로 옳다(정답).
    4. 데이터 영역은 전역변수와 static 변수처럼 프로그램이 끝날 때까지 유지되는 값이 저장되는 곳이다. 지역변수나 반환 주소가 들어가지 않으므로 옳지 않다.
    🧮 풀이
    1. 클라이언트 분석을 하던 게임사 보안 연구원 甲은 코드 영역에 값을 쓰려다 접근 위반 오류를 만났다. 기계어가 올라간 텍스트 영역은 읽기와 실행만 허용되어 덮어쓸 수 없었다. 실행 코드를 보호하는 메모리 구역이다.
    2. 센서 모니터링 프로그램을 만드는 공장 개발자 甲은 센서 수만큼 배열을 malloc으로 그때그때 늘려 썼다. free를 빼먹은 탓에 하루가 지나자 힙 사용량이 계속 불어나 프로그램이 멈췄다. 동적 할당 메모리는 힙에 쌓인다.
    3. 디버거로 함수 호출을 따라가던 통신 장비 개발자 甲은 함수에 들어갈 때마다 인자와 지역변수, 돌아갈 주소가 한 묶음씩 쌓이는 것을 보았다. 재귀 호출을 끝없이 돌리자 그 묶음이 한계를 넘어 프로그램이 죽었다. 스택 영역이 넘친 것이다.
    4. 접속자 수를 전역변수로 관리하던 스타트업 개발자 甲은 함수가 여러 번 끝나도 그 값이 사라지지 않고 계속 쌓이는 것을 보았다. 이 변수는 프로그램 시작부터 끝까지 데이터 영역에 머물렀다. 지역변수와 달리 수명이 프로그램 전체다.

    함수가 호출될 때마다 파라미터·지역변수·반환 주소를 프레임으로 쌓는 메모리 영역은 스택 영역이므로 정답은 3번이다.

    다음 명령을 수행한 후 ‘/directory’에 부여된 권한은?

    chmod 1111 /directory

    1. 1. Read
    2. 2. SetGID
    3. 3. SetUID
    4. 4. Sticky Bit

    정답 4번

    🔍 보기별 해설
    1. Read 권한은 rwx 숫자에서 4로 표현되며, 1111의 뒤 세 자리 1은 실행(x) 권한만 뜻한다. 읽기 권한은 부여되지 않으므로 옳지 않다.
    2. SetGID는 특수 권한 자리의 2로 표현되는데 chmod 1111의 맨 앞 숫자는 1이다. SetGID가 아닌 다른 특수 권한이 부여되므로 옳지 않다.
    3. SetUID는 특수 권한 자리의 4로 표현되어 4755처럼 쓴다. 맨 앞이 1인 1111과는 맞지 않으므로 옳지 않다.
    4. Sticky Bit는 특수 권한 자리의 1로 표현되며, 걸린 디렉터리에서는 파일 소유자만 자기 파일을 지우거나 이름을 바꿀 수 있다. 1111의 맨 앞 1이 Sticky Bit를 부여하므로 옳다(정답).
    🧮 풀이
    1. 공유 폴더를 만들던 스타트업 관리자 甲은 chmod 1111을 준 뒤 ls -ld로 보니 권한이 d--x--x--t로 나왔다. 일반 사용자는 폴더 안 목록을 읽지 못했고 cd로 들어가는 것만 가능했다. 1은 Read가 아니라 실행 권한이다.
    2. 팀 작업 폴더를 만든 게임사 관리자 甲은 chmod 2775를 주었다. 그 안에 누가 파일을 만들든 그룹이 폴더 그룹으로 자동 지정되어 팀원 모두가 편집할 수 있었다. SetGID는 맨 앞 숫자 2로 준다.
    3. 비밀번호 변경 도구를 점검하던 통신사 보안 담당 甲은 /usr/bin/passwd 권한이 -rwsr-xr-x, 숫자로 4755인 것을 보았다. 일반 사용자가 실행해도 root 권한으로 shadow 파일을 고칠 수 있는 이유가 SetUID였다. 맨 앞 4가 SetUID다.
    4. 여러 작업자가 함께 쓰는 공장 서버 관리자 甲은 업로드 폴더에 chmod 1777을 주었다. 그 뒤 다른 작업자가 남의 생산 보고서를 지우려 하자 Operation not permitted가 떴다. /tmp처럼 소유자만 지울 수 있게 하는 Sticky Bit다.

    chmod 1111의 맨 앞 숫자 1은 특수 권한 가운데 Sticky Bit를 뜻하고 뒤 세 자리는 실행 권한이므로 정답은 4번이다.

    보안 운영체제(Secure OS)에 대한 설명으로 옳지 않은 것은?

    1. 1. 보안 커널은 접근 제어 및 감사 추적을 위한 메커니즘을 포함하고 있다.
    2. 2. 패스워드의 설정 및 접근 허용의 변경 등과 같은 보안 관련 작업의 안전한 수행을 위해 안전한 경로(trusted path)를 제공한다.
    3. 3. TCB(Trusted Computing Base) 분할은 TCB를 계층화 구조로 구현하고, 각 계층은 고유의 보안 정책을 정의하기 때문에 기존의 TCB를 재사용할 수 없다.
    4. 4. 운영체제에 내재된 결함 때문에 발생할 수 있는 각종 해킹으로부터 시스템을 보호하기 위해 보안 기능이 통합된 보안 커널을 추가로 이식한 운영체제이다.

    정답 3번

    🔍 보기별 해설
    1. 보안 커널은 보안 운영체제의 중심으로 접근 제어와 감사 추적 기능을 함께 갖춘다. 누가 무엇에 접근하는지 막고 그 흔적을 남기는 두 기능을 담는다는 설명이므로 옳다.
    2. 안전한 경로(trusted path)는 패스워드 변경 같은 보안 작업 때 위조 프로그램이 끼어들지 못하게 사용자와 커널을 직접 잇는 통로다. 보안 운영체제가 제공하는 기능이므로 옳다.
    3. TCB(Trusted Computing Base) 분할은 TCB를 계층으로 나누어 계층마다 제 보안 정책을 맡게 하는 방식이다. 이렇게 나누면 기존 TCB를 그대로 재사용하기 쉬워지므로 재사용할 수 없다는 설명은 옳지 않다(정답).
    4. 보안 운영체제는 운영체제 자체의 결함을 노린 해킹을 막으려고 보안 기능을 묶은 보안 커널을 기존 운영체제에 더 심은 것이다. 보안 운영체제의 정의를 바르게 말했으므로 옳다.
    🧮 풀이
    1. 도청 전산팀 甲은 보안 운영체제를 들인 뒤 인사 파일에 권한 없는 계정이 접근하자 커널이 바로 거부하는 것을 겪었다. 거부된 시도는 시각과 계정 이름까지 감사 로그에 남아 다음 날 추적에 쓰였다. 보안 커널이 접근 제어와 감사 추적을 함께 맡은 결과다.
    2. 구청 민원 서버 담당 甲이 패스워드를 바꾸려고 보안 키 조합을 누르자 다른 프로그램 창이 모두 가려지고 커널이 띄운 입력 창만 남았다. 화면을 흉내 낸 가짜 로그인 창이 떠 있었더라도 이 입력은 가로챌 수 없었다. 안전한 경로가 보안 작업을 보호한 장면이다.
    3. 국책 연구소 개발자 甲은 보안 운영체제의 TCB를 계층으로 나누어 하위 계층은 기존 것을 그대로 두고 새 정책은 위 계층에만 붙였다. 그 덕분에 인증 심사를 마친 아래 계층을 다시 만들거나 다시 검증받을 필요가 없어 개발 기간이 절반으로 줄었다. TCB 분할이 오히려 재사용을 쉽게 만든 사례다.
    4. 공단 시스템팀 甲은 기존 운영체제를 새로 깔지 않고 보안 커널을 추가로 이식해 보안 운영체제로 바꾸었다. 그 뒤 운영체제 버그를 노린 권한 상승 시도가 들어와도 커널의 강제 접근 통제에 막혔다. 결함이 남아 있어도 보안 커널이 시스템을 지켜 준다.

    TCB를 계층으로 나누는 분할은 기존 TCB를 재사용하기 쉽게 하는데 재사용할 수 없다고 했으므로 정답은 3번이다.

    다음에서 설명하는 접근통제 모델은?

    ○ 정보 소유자가 정보의 보안 수준을 결정하고 그에 대한 접근 통제까지 설정하는 모델이다.

    ○ 중앙 집중화된 정보 관리가 어려워서 정보에 대한 엄격한 접근 통제는 거의 불가능하다.

    1. 1. 비바(Biba)
    2. 2. 임의적 접근통제(DAC)
    3. 3. 역할기반 접근통제(RBAC)
    4. 4. 벨 라파둘라(Bell-LaPadula)

    정답 2번

    🔍 보기별 해설
    1. 비바(Biba) 모델은 무결성을 지키려고 낮은 등급 주체가 높은 등급 객체에 쓰지 못하게 하는 강제적 접근통제 모델이다. 소유자가 마음대로 정하는 방식이 아니므로 옳지 않다.
    2. 임의적 접근통제(DAC)는 정보 소유자가 누구에게 어떤 접근을 허락할지 스스로 정하는 모델이다. 그래서 중앙에서 일관되게 관리하기 어렵다는 설명과 맞으므로 옳다(정답).
    3. 역할기반 접근통제(RBAC)는 직무 역할에 권한을 묶고 사용자에게는 역할을 주는 모델이다. 관리자가 중앙에서 역할을 정하므로 소유자가 정하는 모델이 아니어서 옳지 않다.
    4. 벨 라파둘라(Bell-LaPadula) 모델은 기밀성을 위해 보안 등급에 따라 읽기와 쓰기를 강제로 제한하는 모델이다. 시스템이 등급 규칙을 강제하므로 설명과 달라 옳지 않다.
    🧮 풀이
    1. 국방 연구소 甲은 Biba 규칙을 적용한 문서 시스템에서 외부 인턴 계정으로 검증된 설계 문서를 고치려 했지만 쓰기가 막혔다. 낮은 무결성 등급이 높은 등급 자료를 오염시키지 못하게 한 것이다. 문서 주인이 허락해도 이 규칙은 바뀌지 않았다.
    2. 시청 홍보팀 甲은 자기가 만든 공유 폴더에 동료 두 명만 읽기 권한을 주었다가, 퇴근길에 친한 다른 부서 직원에게도 권한을 열어 주었다. 정보보호 담당자는 이런 권한 부여를 한곳에서 통제할 수 없었다. 소유자가 권한을 정하는 DAC 방식의 약점이다.
    3. 보건소 전산 담당 甲이 '간호사' 역할에 진료 기록 조회 권한을 묶어 두자 새로 온 간호사는 역할만 받고 바로 일을 시작했다. 개인이 권한을 나눠 줄 수는 없었고 역할 정의는 담당 부서만 바꿀 수 있었다. RBAC가 중앙 관리에 강한 이유다.
    4. 군 정보부대 장교 甲은 '비밀' 등급 인가로 '극비' 문서를 열려 했지만 읽기가 거부됐다. 반대로 자신이 쓴 보고서를 '대외비' 폴더에 내려 저장하는 것도 막혔다. Bell-LaPadula 모델이 기밀 유출을 막으려고 시스템 차원에서 거는 제한이다.

    소유자가 보안 수준과 접근 권한을 스스로 정해 중앙에서 엄격하게 관리하기 어려운 모델은 임의적 접근통제이므로 정답은 2번이다.

    멀웨어(Malware)에 대한 설명으로 옳은 것은?

    1. 1. 스파이웨어(Spyware)는 사용자 동의 없이 정보를 수집하여 전송한다.
    2. 2. 트로이목마(Trojan Horse)는 시스템 자원을 암호화하여 금전을 요구하는 공격을 수행한다.
    3. 3. 바이러스(Virus)는 독립적으로 실행되며, 취약점을 이용하여 스스로 전파된다.
    4. 4. 웜(Worm)은 정상 프로그램이나 실행 가능한 부분에 자신 또는 자신의 변형을 복사하며, 다른 네트워크의 시스템으로 스스로 전파하지 못한다.

    정답 1번

    🔍 보기별 해설
    1. 스파이웨어(Spyware)는 사용자 몰래 설치되어 검색 기록이나 계정 정보 같은 자료를 모아 외부로 보내는 악성코드다. 동의 없는 수집과 전송을 특징으로 든 설명이므로 옳다(정답).
    2. 트로이목마(Trojan Horse)는 정상 프로그램처럼 꾸며 설치를 유도한 뒤 뒷문을 열거나 정보를 빼가는 악성코드다. 자원을 암호화해 돈을 요구하는 것은 랜섬웨어의 특징이므로 옳지 않다.
    3. 바이러스(Virus)는 다른 프로그램에 자신을 붙여 그 프로그램이 실행될 때 함께 퍼지는 악성코드다. 혼자 실행되며 스스로 전파되는 것은 웜의 특징이므로 옳지 않다.
    4. 웜(Worm)은 숙주 파일 없이 독립적으로 실행되고 네트워크 취약점을 이용해 다른 시스템으로 스스로 퍼진다. 프로그램에 자신을 복사한다는 것은 바이러스의 성질이고 전파하지 못한다는 것도 틀려 옳지 않다.
    🧮 풀이
    1. 학교 행정실 직원 甲이 무료 PDF 변환기를 깔자 브라우저에 낯선 툴바가 붙었고, 이후 접속한 사이트 주소가 몰래 외부 서버로 넘어갔다. 백신 검사에서 이 툴바가 Spyware로 잡혀 삭제되었다. 甲은 수집에 동의한 적이 한 번도 없었다.
    2. 출판사 디자이너 甲은 글꼴 묶음 파일을 내려받아 실행했는데 겉으로는 글꼴만 설치되었다. 그런데 뒤에서 원격 접속 포트가 열려 외부 공격자가 甲의 PC를 마음대로 조종했다. 정상 파일로 위장해 들어오는 Trojan Horse의 전형이다.
    3. 공장 설비팀 甲이 USB에서 감염된 실행 파일을 열자 그 PC의 다른 exe 파일에도 같은 악성 코드가 붙었다. 감염 파일을 아무도 실행하지 않은 옆 PC는 멀쩡했다. 숙주 파일이 실행되어야 퍼지는 Virus의 성질이다.
    4. 대학 전산원 관리자 甲은 패치하지 않은 서버 한 대가 감염되자 몇 분 만에 같은 대역 서버 수십 대로 번지는 것을 막느라 밤을 새웠다. 누가 파일을 열지 않았는데도 취약한 포트를 찾아 스스로 옮겨 갔다. 네트워크로 혼자 퍼지는 Worm이다.

    스파이웨어는 사용자 동의 없이 정보를 모아 밖으로 보내는 악성코드라는 설명이 맞으므로 정답은 1번이다.

    다음에서 설명하는 공격은?

    ○ 공격자가 특정 대상을 목표로 다양한 공격 기술을 이용해 지속적으로 공격한다.

    ○ 이 공격의 사례는 제로데이 취약점을 활용한 Stuxnet이 있다.

    1. 1. APT
    2. 2. DDoS
    3. 3. Ransomware
    4. 4. Reverse Engineering

    정답 1번

    🔍 보기별 해설
    1. APT(Advanced Persistent Threat)는 특정 조직을 겨냥해 여러 기법을 섞어 오랜 기간 몰래 공격을 계속하는 지능형 지속 위협이다. 제로데이를 쓴 Stuxnet이 대표 사례이므로 옳다(정답).
    2. DDoS는 여러 대의 좀비 PC로 한꺼번에 트래픽을 보내 서비스를 마비시키는 분산 서비스 거부 공격이다. 특정 대상을 오래 몰래 노리는 공격이 아니므로 옳지 않다.
    3. Ransomware는 파일을 암호화한 뒤 풀어 주는 대가로 돈을 요구하는 악성코드다. 지속적인 표적 침투와 Stuxnet 사례를 설명한 것이 아니므로 옳지 않다.
    4. Reverse Engineering은 완성된 프로그램을 분석해 구조와 동작 원리를 거꾸로 알아내는 기법이다. 지속적인 표적 공격 형태를 가리키는 말이 아니므로 옳지 않다.
    🧮 풀이
    1. 발전 설비 회사 보안 책임자 甲은 협력업체 메일, 감염된 USB, 패치되지 않은 제로데이 취약점이 몇 달에 걸쳐 차례로 쓰인 흔적을 찾았다. 공격자는 제어 시스템에 닿을 때까지 조용히 머물렀다. 표적을 정해 오래 파고드는 APT 공격의 흐름이다.
    2. 쇼핑몰 운영자 甲은 할인 행사 첫날 수만 대의 감염 PC가 한꺼번에 보낸 접속 요청 때문에 결제 페이지가 멈추는 일을 겪었다. 데이터는 빼앗기지 않았지만 몇 시간 동안 주문을 받지 못했다. 서비스를 쓰러뜨리는 것이 목표인 DDoS 공격이다.
    3. 병원 원무과 甲이 출근해 PC를 켜자 진료 예약 파일이 모두 이상한 확장자로 바뀌어 열리지 않았다. 화면에는 비트코인을 보내야 복호화 키를 준다는 안내가 떠 있었다. 파일을 인질로 잡는 Ransomware 피해다.
    4. 백신 연구원 甲은 새로 잡힌 악성 파일을 IDA 같은 분석 도구로 열어 명령어 흐름을 한 줄씩 따라가며 통신 서버 주소를 찾아냈다. 이 분석 결과로 차단 규칙을 만들었다. Reverse Engineering은 공격이 아니라 분석 기법으로도 널리 쓰인다.

    특정 대상을 정해 여러 기법으로 오래 공격하고 제로데이를 쓴 Stuxnet이 대표 사례인 공격은 APT이므로 정답은 1번이다.

    침입탐지시스템(IDS)에 대한 설명으로 옳지 않은 것은?

    1. 1. 이상탐지(Anomaly Detection)는 시그니처(Signature) 기반 탐지라고도 한다.
    2. 2. 제로데이(Zero-day) 공격에 대한 탐지는 오용탐지에 비해 이상탐지가 효율적이다.
    3. 3. 오용탐지(Misuse Detection)는 알려진 공격의 패턴을 탐지하는 방법이다.
    4. 4. 이상탐지(Anomaly Detection)는 정상적이고 평균적인 상태를 크게 벗어나는 이벤트가 발생하는 것을 탐지하는 방법이다.

    정답 1번

    🔍 보기별 해설
    1. 이상탐지(Anomaly Detection)는 정상 행동의 기준을 세우고 그 기준에서 벗어난 활동을 잡는 방식이다. 시그니처(Signature) 기반 탐지는 오용탐지를 부르는 다른 이름이므로 옳지 않다(정답).
    2. 제로데이(Zero-day) 공격은 아직 알려진 패턴이 없어 오용탐지로는 잡기 어렵다. 패턴 없이 정상 범위를 벗어난 행동을 보는 이상탐지가 더 유리하므로 옳다.
    3. 오용탐지(Misuse Detection)는 알려진 공격 패턴을 미리 등록해 두고 일치하는 트래픽을 찾아내는 방식이다. 오탐은 적지만 새 공격에는 약한 방식이라는 정의와 맞으므로 옳다.
    4. 이상탐지(Anomaly Detection)는 평소의 통계적 상태를 학습해 두고 그와 크게 다른 이벤트를 경보로 올린다. 정상 상태에서 벗어난 정도를 기준으로 삼는다는 설명이므로 옳다.
    🧮 풀이
    1. 통신사 관제요원 甲은 IDS 규칙에 공격 문자열을 등록해 두고 그 문자열이 든 패킷만 잡는 Signature 방식을 쓰고 있었다. 동료가 이것을 Anomaly Detection이라 부르자 甲은 등록된 패턴과 맞춰 보는 오용탐지라고 바로잡았다. 두 방식은 판단 기준이 다르다.
    2. 증권사 보안팀 甲은 패턴이 공개되지 않은 Zero-day 공격이 들어온 날, 시그니처 장비는 조용했지만 이상탐지 장비가 새벽 3시의 대량 외부 전송을 경보로 올렸다. 평소와 다른 행동만으로 공격을 먼저 찾아낸 것이다.
    3. 대학병원 관제 담당 甲은 보안 업체가 배포한 최신 공격 패턴 목록을 IDS에 올렸고, 그날 오후 같은 패턴의 웹 공격을 바로 차단했다. 다만 목록에 없는 변종은 그대로 통과했다. Misuse Detection의 강점과 한계가 함께 보인다.
    4. 물류센터 서버 관리자 甲은 이상탐지 장비에 한 달 동안의 평균 로그인 횟수와 전송량을 학습시켰다. 어느 날 한 계정이 평소 수십 배의 파일을 내려받자 장비가 즉시 경보를 띄웠다. Anomaly Detection이 평균 상태를 기준으로 움직인 결과다.

    시그니처 기반 탐지는 이상탐지가 아니라 알려진 공격 패턴을 찾는 오용탐지를 가리키므로 정답은 1번이다.

    다음에서 설명하는 도구는?

    웹 브라우저와 웹 서버가 통신할 때, 중간에 위치하여 웹 브라우저의 요청 메시지를 받아 웹 서버로 전송하고, 웹 서버에서 받은 응답 메시지도 웹 브라우저로 전달하는 역할을 한다. 이것을 이용하면 웹 클라이언트와 웹 서버가 교환하는 모든 데이터를 중간에서 수정이 가능하다.

    1. 1. 루트킷(rootkit)
    2. 2. 웹 프록시(web proxy)
    3. 3. 애드웨어(adware)
    4. 4. 포트 스캐너(port scanner)

    정답 2번

    🔍 보기별 해설
    1. 루트킷(rootkit)은 침입 뒤 관리자 권한을 유지하고 자신의 흔적을 숨기는 도구 모음이다. 브라우저와 서버 사이에서 메시지를 중계하는 도구가 아니므로 옳지 않다.
    2. 웹 프록시(web proxy)는 브라우저와 웹 서버 사이에 서서 요청과 응답을 대신 받아 전달하는 도구다. 그래서 오가는 데이터를 중간에서 고쳐 보낼 수 있으므로 옳다(정답).
    3. 애드웨어(adware)는 사용자 화면에 광고를 띄워 수익을 얻는 프로그램이다. 웹 통신을 중간에서 받아 넘기는 기능과 관계가 없으므로 옳지 않다.
    4. 포트 스캐너(port scanner)는 대상 호스트의 어떤 포트가 열려 있는지 차례로 조사하는 도구다. 웹 요청과 응답을 중계하거나 고치는 도구가 아니므로 옳지 않다.
    🧮 풀이
    1. 침해사고 대응관 甲은 해킹당한 서버에서 ps 명령으로는 보이지 않던 프로세스를 메모리 분석으로 찾아냈다. 공격자가 심은 rootkit이 시스템 명령을 바꿔치기해 자신을 숨기고 있었다. 숨기고 버티는 것이 이 도구의 목적이다.
    2. 모의해킹 업체 직원 甲은 Burp Suite 같은 web proxy를 브라우저에 연결하고 결제 요청을 중간에서 멈췄다. 가격 값을 10000에서 100으로 바꿔 서버로 보내자 결제가 그대로 통과했다. 서버가 값을 다시 검증하지 않는 결함을 이렇게 찾는다.
    3. 회사원 甲이 무료 게임을 설치한 뒤로 브라우저를 열 때마다 팝업 광고가 서너 개씩 떴다. 제어판에서 게임과 함께 깔린 adware를 지우자 광고가 사라졌다. 통신 중계와는 거리가 먼 광고 프로그램이다.
    4. 보안 점검원 甲은 nmap 같은 port scanner로 구청 서버를 훑어 22번과 3306번 포트가 외부에 열려 있는 것을 찾았다. 쓰지 않는 3306번 포트는 방화벽에서 막았다. 열린 문을 찾는 도구일 뿐 오가는 메시지를 고치지는 않는다.

    브라우저와 서버 사이에서 요청과 응답을 받아 넘기며 오가는 데이터를 고칠 수 있는 도구는 웹 프록시이므로 정답은 2번이다.

    다음과 관련된 공격은?

    SELECT * FROM member WHERE id = 'admin' and password = ''or''='';

    1. 1. XSS
    2. 2. CSRF
    3. 3. SQL Injection
    4. 4. Format String

    정답 3번

    🔍 보기별 해설
    1. XSS(Cross-Site Scripting)는 게시글 등에 악성 스크립트를 심어 다른 사용자의 브라우저에서 실행되게 하는 공격이다. 주어진 SQL 쿼리 조작과는 다른 공격이므로 옳지 않다.
    2. CSRF(Cross-Site Request Forgery)는 로그인한 사용자가 모르게 위조된 요청을 서버로 보내게 만드는 공격이다. 쿼리 조건을 언제나 참으로 만드는 것과 관계없으므로 옳지 않다.
    3. SQL Injection은 입력값에 SQL 구문을 끼워 넣어 쿼리의 뜻을 바꾸는 공격이다. 비밀번호 칸의 ''or''=''가 조건을 언제나 참으로 만들어 인증을 건너뛰므로 옳다(정답).
    4. Format String 공격은 printf 같은 함수에 %n, %x 같은 서식 문자를 넣어 메모리를 읽거나 쓰는 공격이다. 데이터베이스 쿼리를 조작하는 공격이 아니므로 옳지 않다.
    🧮 풀이
    1. 커뮤니티 운영자 甲은 한 회원이 올린 글을 연 사람마다 쿠키가 외부 주소로 전송되었다는 신고를 받았다. 글 본문에 숨은 script 태그가 원인이었고, 甲은 출력할 때 특수문자를 바꾸도록 고쳤다. 전형적인 XSS 피해다.
    2. 은행 고객 甲이 인터넷뱅킹에 로그인한 채 메일 속 이벤트 이미지를 열자, 甲 모르게 이체 요청이 은행으로 날아갔다. 은행은 이후 요청마다 임의 토큰을 붙여 검증하도록 바꾸었다. 사용자의 로그인 상태를 악용한 CSRF 공격이다.
    3. 웹 개발자 甲은 시험 서버 로그인 창의 비밀번호 칸에 ''or''=''를 넣자 아무 비밀번호 없이 admin으로 들어가지는 것을 재현했다. 입력값을 쿼리에 그대로 붙인 코드가 원인이어서 Prepared Statement로 바꿨다. SQL Injection을 막는 기본 조치다.
    4. 보안 교육 강사 甲은 C 프로그램에서 입력을 그대로 서식 자리에 넘기는 printf(user) 코드에 %x%x%x를 넣어 스택 값이 줄줄이 찍히게 했다. 서식 문자열을 고정하고 입력은 인자로만 넘기자 문자 그대로 출력되었다. Format String 취약점의 원리다.

    비밀번호 조건에 ''or''=''를 넣어 WHERE 절을 언제나 참으로 만든 쿼리는 SQL Injection이므로 정답은 3번이다.

    다음은 시스템의 보안 기능에 대한 설명이다. (가) ～ (다)에 들어갈 용어를 바르게 연결한 것은?

    ○ (가) 는 사용자와 시스템 또는 두 시스템 간에 활성화된 접속을 관리하는 것이다.

    ○ (나) 는 시스템 자체의 결함 때문에 발생하는 보안 문제를 체계적으로 관리하는 것이다.

    ○ (다) 는 시스템 내부 또는 외부에서 시스템에 어떤 영향을 미쳤을 경우, 해당 사항을 기록하고 관리한다. (가) (나) (다)

    1. 1. 로그 관리 취약점 관리 계정 관리
    2. 2. 로그 관리 취약점 관리 세션 관리
    3. 3. 세션 관리 권한 관리 로그 관리
    4. 4. 세션 관리 취약점 관리 로그 관리

    정답 4번

    🔍 보기별 해설
    1. 로그 관리는 시스템에 영향을 준 사건을 기록하는 기능이라 (가)의 접속 관리 자리가 아니다. (다)에 계정 관리를 둔 것도 기록 관리와 맞지 않으므로 옳지 않다.
    2. 로그 관리를 (가)에 둔 연결은 활성 접속을 관리하는 세션 관리 자리를 잘못 채웠다. (다)의 사건 기록 자리에 세션 관리를 놓은 것도 뒤바뀐 것이므로 옳지 않다.
    3. 세션 관리를 (가)에, 로그 관리를 (다)에 둔 것은 맞지만 (나)에 권한 관리를 넣었다. 시스템 자체 결함에서 생기는 보안 문제를 다루는 것은 취약점 관리이므로 옳지 않다.
    4. 세션 관리는 활성 접속을, 취약점 관리는 시스템 결함을, 로그 관리는 영향을 준 사건의 기록을 맡는다. (가)·(나)·(다)를 모두 바르게 이었으므로 옳다(정답).

    3. 문맥 교환(context switch)은 CPU가 실행하던 프로세스의 상태를 저장하고 다른 프로세스의 상태를 불러오는 일이다. 한 프로세스 안에서 메모리 공간을 옮길 때 생기는 것이 아니므로 옳지 않다(정답).

    3. 임베디드 개발자 甲은 음악 재생 프로세스와 문자 수신 프로세스가 번갈아 CPU를 쓰는 흐름을 디버거로 추적했다. 전환될 때마다 앞 프로세스의 레지스터 값이 저장되고 다음 프로세스 값이 복원되었다. 서로 다른 프로세스 사이의 context switch다.
    4. 커널 개발자 甲은 멈춘 프로세스를 조사하려고 그 프로세스의 PCB를 열어 상태 값, 프로그램 카운터, 열린 파일 목록을 읽어 냈다. 거기서 대기 상태로 묶여 있던 원인을 찾았다. 운영체제는 process control block으로 각 프로세스를 관리한다.

    문맥 교환은 한 프로세스 안이 아니라 CPU를 쓰는 프로세스가 다른 프로세스로 바뀔 때 일어나므로 정답은 3번이다.

    4. 홈페이지 이전 담당 甲은 chown -R www-data /var/www를 실행해 하위 파일 수백 개의 소유자를 한 번에 바꿨다. 그러나 rw-r--r-- 같은 권한은 하나도 바뀌지 않아 chmod를 따로 실행했다. 소유자와 권한은 다른 명령이 맡는다.

    2. SET은 주문 정보와 지불 정보를 각각 해시해 묶은 뒤 고객이 한 번에 서명하는 이중 서명을 쓴다. 이중 서명 프로토콜을 사용한다는 설명이므로 옳다.

    4. 카드 발급 은행 직원 甲은 결제 승인 화면에서 금액과 카드 번호는 보았지만 손님이 무엇을 샀는지는 알 수 없었다. 주문 정보는 상점 키로만 풀리게 암호화되어 있었다. 이중 서명이 은행이 보는 범위를 지불 정보로만 묶었다.

    SET은 이중 서명으로 상점은 지불 정보를, 은행은 주문 정보를 모르게 하므로 은행이 주문 정보를 안다고 한 설명이 틀려 정답은 4번이다.

    1. (가)는 패스워드를 바꾼 뒤 다시 바꾸기까지 기다려야 하는 최소 사용 일수다. 이 값이 0이면 기다릴 필요 없이 바로 다시 바꿀 수 있으므로 옳다.
    2. (나)는 패스워드를 바꾸지 않고 쓸 수 있는 최대 일수로, 이 기간이 지나면 변경을 요구받는다. 최대 사용 일수라는 설명이므로 옳다.
    3. (다)는 패스워드 만료일을 앞두고 며칠 전부터 경고 메시지를 보여 줄지 정하는 경고 일수다. 경고 시작 일수라는 설명이므로 옳다.
    4. (라)는 패스워드가 만료된 뒤 계정을 잠그기까지 기다려 주는 비활성 유예 일수다. 계정 만료일은 그다음 여덟째 칸이므로 옳지 않다.
    🧮 풀이
    1. 공단 전산 담당 甲은 user01의 최소 사용 일수를 0으로 둔 채 비밀번호를 바꾸고, 오타가 생각나 바로 한 번 더 바꿨다. 최소 일수가 7이던 동료 계정은 같은 시도에서 거부되었다. 0이면 언제든 다시 바꿀 수 있다.
    2. 지방법원 서버 관리자 甲은 최대 사용 일수를 90으로 정해 두었다. 마지막 변경 뒤 91일째 로그인한 직원에게는 새 비밀번호를 정해야 들어갈 수 있다는 안내가 떴다. 같은 비밀번호를 오래 쓰지 못하게 하는 장치다.
    3. 시청 정보보호 담당 甲은 경고 일수를 7로 두었다. 비밀번호 만료 일주일 전부터 직원들이 로그인할 때마다 남은 날짜를 알리는 메시지가 떠, 대부분 만료 전에 미리 비밀번호를 바꿨다.
    4. 연구재단 관리자 甲은 일곱째 칸에 5를 넣었더니 비밀번호가 만료되고 5일이 지나도록 바꾸지 않은 계정이 잠겼다. 계약 종료일에 맞춰 계정을 끊는 일은 여덟째 칸의 만료 날짜로 따로 정했다. 두 칸의 쓰임은 다르다.
