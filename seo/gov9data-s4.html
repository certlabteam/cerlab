    다음에서 설명하는 데이터 마이닝 분석 기법은?

    ○ 장바구니 분석이라고도 한다.

    ○ 데이터 간의 발생 빈도를 분석하여 그 속에 숨겨진 규칙을 파악하는 방법으로, 상품이나 서비스 간의 관계를 분석하여 마케팅에 주로 활용한다.

    1. 1. 분류 분석
    2. 2. 군집 분석
    3. 3. 연관 분석
    4. 4. 회귀 분석

    정답 3번

    🔍 보기별 해설
    1. 분류 분석은 이미 정해진 범주를 학습해 새 자료의 범주를 예측한다. 상품 간 동시 발생 규칙을 찾는 설명과 다르므로 옳지 않다.
    2. 군집 분석은 정답 범주 없이 비슷한 자료끼리 묶는다. 함께 팔리는 상품 사이의 규칙을 찾는 기법이 아니므로 옳지 않다.
    3. 연관 분석은 거래 기록에서 함께 나타나는 품목의 관계를 규칙으로 추출한다. 장바구니 분석이라는 설명과 같으므로 옳다(정답).
    4. 회귀 분석은 입력값과 연속된 수치 결과 사이의 관계를 추정한다. 상품의 동시 구매 규칙을 찾는 설명과 다르므로 옳지 않다.
    🧮 풀이
    1. 온라인 상점이 과거 구매자를 ‘재구매’와 ‘미재구매’로 표시해 학습시킨다. 새 구매자가 어느 범주에 들지 예측하면 분류 분석이다. 두 상품이 함께 담기는 빈도를 규칙으로 뽑지는 않는다.
    2. 고객의 구매 금액과 방문 빈도를 기준으로 성향이 비슷한 고객을 묶는다. 미리 정한 고객 범주 없이 집단을 만드는 것은 군집 분석이다. 우유를 산 사람이 빵도 사는지 규칙을 얻는 일과 목적이 다르다.
    3. 마트 거래 1만 건에서 우유를 산 영수증에 빵도 자주 함께 나타난다. 분석가는 두 상품의 지지도와 신뢰도를 계산해 ‘우유 구매 → 빵 구매’ 규칙을 만든다. 이 규칙을 진열과 묶음 할인에 활용한다.
    4. 매장이 광고비와 다음 달 매출의 관계를 학습해 광고비 100만 원 증가 시 예상 매출액을 계산한다. 결과가 연속된 금액이면 회귀 분석이다. 상품 두 개의 동시 출현을 세는 장바구니 분석과 다르다.

    장바구니에서 상품의 동시 구매 규칙을 찾는 기법은 연관 분석이므로 정답은 3번이다.

    시스템 카탈로그에 대한 설명으로 옳지 않은 것은?

    1. 1. 데이터 사전(data dictionary)이라고도 한다.
    2. 2. 각 릴레이션의 튜플 수와 블록 수가 저장된다.
    3. 3. 일반 사용자도 시스템 카탈로그에 내용을 추가하거나 수정할 수 있다.
    4. 4. RDBMS마다 서로 다른 형태로 시스템 카탈로그를 제공한다.

    정답 3번

    🔍 보기별 해설
    1. 시스템 카탈로그는 테이블과 열, 제약조건 같은 메타데이터를 보관하는 데이터 사전이다. 같은 대상을 가리키므로 옳다.
    2. 시스템 카탈로그에는 릴레이션의 튜플 수나 저장 블록 수 같은 통계도 보관될 수 있다. 질의 최적화에 쓰이므로 옳다.
    3. 시스템 카탈로그는 DBMS(Database Management System)가 스키마 변경에 맞춰 관리한다. 일반 사용자가 내용을 직접 추가·수정할 수 있다는 말은 옳지 않다(정답).
    4. 관계형 데이터베이스 관리 시스템은 제품마다 카탈로그의 테이블과 열 구조가 다르다. 구현 형태가 동일하지 않으므로 옳다.
    🧮 풀이
    1. 관리자가 고객 테이블에 이메일 열을 추가하면 데이터 사전에도 열 이름과 자료형이 기록된다. 사용자는 테이블의 정의를 조회해 어떤 열이 있는지 알아낸다. 기록 대상은 고객의 실제 이메일 값이 아닌 테이블 구조다.
    2. 질의 최적화기가 주문 테이블의 행 수와 디스크 페이지 수를 읽는다. 행이 10건인 표와 100만 건인 표의 조인 순서를 달리 정할 수 있다. 이때 카탈로그의 통계가 실행 계획 선택에 쓰인다.
    3. 사용자 甲이 시스템 카탈로그의 기본키 정의를 직접 바꿔 중복 키를 허용하려 한다. DBMS가 관리하는 내부 메타데이터를 임의로 고치는 방식은 허용되지 않는다. 권한 있는 스키마 변경 명령을 거쳐야 정의가 바뀐다.
    4. 한 DBMS에서는 테이블 정보가 INFORMATION_SCHEMA 뷰에 보이고 다른 제품은 자체 시스템 뷰를 제공한다. 같은 메타데이터를 다뤄도 카탈로그의 이름과 구성은 다를 수 있다. 응용 프로그램은 제품별 구조를 확인해 조회한다.

    일반 사용자는 시스템 카탈로그의 내용을 임의로 고치지 못하므로 정답은 3번이다.

    다음에서 설명하는 데이터베이스 무결성 제약조건(integrity constraint)은?

    ○ 기본키 제약(primary key constraint)이라고도 한다.

    ○ 기본키는 널(NULL) 값을 가져서는 안되며 릴레이션 내에 오직 하나의 값만 존재해야 한다.

    1. 1. 개체 무결성 제약조건
    2. 2. 고유 무결성 제약조건
    3. 3. 도메인 무결성 제약조건
    4. 4. 참조 무결성 제약조건

    정답 1번

    🔍 보기별 해설
    1. 개체 무결성은 각 행을 식별하는 기본키가 NULL이거나 중복되지 않도록 한다. 발문의 기본키 제약과 같으므로 옳다(정답).
    2. 고유 제약은 지정한 열 값의 중복을 막지만 기본키의 모든 조건을 뜻하지는 않는다. 기본키 제약의 이름으로는 옳지 않다.
    3. 도메인 무결성은 열 값이 자료형이나 허용 범위에 맞는지 확인한다. 기본키의 NULL·중복 금지를 가리키지 않으므로 옳지 않다.
    4. 참조 무결성은 외래키가 가리키는 값이 참조 대상에 존재하도록 한다. 자기 테이블의 기본키 조건과 다르므로 옳지 않다.
    🧮 풀이
    1. 기본키로 지정한 학번에는 두 학생이 같은 값을 쓸 수 없다. 학번이 비어 있는 행도 저장되지 않아 각 학생을 구별할 수 있다. 이 두 조건이 개체 무결성을 지킨다.
    2. 직원 테이블에서 사내 이메일에 UNIQUE 제약을 건다. 두 직원이 같은 이메일을 쓰지 못하게 할 수 있지만 이 열이 곧 기본키가 되는 것은 아니다. 기본키의 NULL 금지까지 묻는 발문과 범위가 다르다.
    3. 상품 가격 열을 0원 이상으로 제한하고 날짜 열에는 올바른 날짜만 입력하게 한다. 잘못된 자료형이나 범위의 값을 거부하는 것은 도메인 무결성이다. 상품번호 기본키의 중복 여부와는 별개의 검사다.
    4. 주문 테이블의 고객번호가 고객 테이블의 실제 고객번호를 가리키도록 외래키를 건다. 존재하지 않는 고객번호의 주문은 저장되지 않는다. 이는 두 테이블 사이의 참조를 지키는 조건이다.

    기본키의 NULL과 중복을 금하는 조건은 개체 무결성이므로 정답은 1번이다.

    데이터베이스 모델에서 사용되는 키(key)에 대한 설명으로 옳지 않은 것은?

    1. 1. 후보키(candidate key)는 유일성과 최소성의 특성을 만족하는 속성 또는 속성들의 집합이다.
    2. 2. 슈퍼키(super key)는 유일성의 특성을 만족하는 속성 또는 속성들의 집합이다.
    3. 3. 대체키(alternate key)는 기본키(primary key)로 선택되지 못한 외래키(foreign key)들이다.
    4. 4. 널(NULL) 값을 가질 수 있는 속성이 포함된 후보키는 기본키로 부적합하다.

    정답 3번

    🔍 보기별 해설
    1. 후보키는 행을 유일하게 식별하면서 더 뺄 수 없는 최소한의 속성 집합이다. 유일성과 최소성을 모두 요구하므로 옳다.
    2. 슈퍼키는 행을 유일하게 식별하는 속성 집합이다. 최소성은 요구하지 않아 여분의 열을 포함해도 되므로 옳다.
    3. 대체키는 후보키 중 기본키로 선택되지 않은 키다. 외래키 중 선택되지 않은 것이라는 설명은 옳지 않다(정답).
    4. 기본키에는 NULL을 허용할 수 없다. NULL을 가질 수 있는 속성이 포함된 후보키는 그대로 기본키로 정하기 부적합하므로 옳다.
    🧮 풀이
    1. 학번 하나만으로 테이블의 각 학생을 식별할 수 있다. 학번을 빼면 식별할 수 없어 최소성도 충족한다. 학번은 후보키가 될 수 있고 다른 후보키가 있다면 그중 하나를 기본키로 고른다.
    2. 학번만으로 행이 구별되면 학번과 이름을 합쳐도 행을 유일하게 찾는다. 이름은 불필요한 열이므로 이 조합은 슈퍼키이되 최소성은 없다. 후보키보다 넓은 개념임을 확인할 수 있다.
    3. 회원 테이블에서 회원번호와 주민등록번호가 각각 후보키라면 회원번호를 기본키로 정할 수 있다. 선택되지 않은 주민등록번호는 대체키다. 다른 테이블을 가리키는 외래키와는 역할이 다르다.
    4. 상품 테이블에서 상품코드 열의 값이 비어 있을 수 있다면 그 상태로 기본키로 지정할 수 없다. 기본키가 비면 한 행을 안정적으로 식별할 수 없기 때문이다. NULL을 금지하는 조건을 갖춘 후보키를 선택해야 한다.

    대체키는 후보키 중 기본키로 선택되지 않은 키이므로 정답은 3번이다.

    릴레이션 R1, R2, R3의 스키마는 R1(A, B, C), R2(C, D, E), R3(E, F)이고, 기본키는 각각 A, C, E이다. 튜플의 수가 R1은 100개, R2는 150개, R3은 75개라고 할 때, R1 ⋈N R2 ⋈N R3의 결과에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄱ. R1 ⋈N (R2 ⋈N R3)의 결과와 동일하다.

    ㄴ. 결과 릴레이션의 튜플은 최대 100개이다.

    ㄷ. 결과 릴레이션의 속성은 8개이다.

    1. 1. ㄱ
    2. 2. ㄴ
    3. 3. ㄱ, ㄴ
    4. 4. ㄱ, ㄴ, ㄷ

    정답 3번

    🔍 보기별 해설
    1. 자연 조인은 공통 열 C와 E를 기준으로 결합하며 결합 순서를 바꾸어도 같은 결과 관계를 얻는다. 따라서 괄호를 바꾼 두 식은 옳다.
    2. R2의 기본키 C와 R3의 기본키 E는 결합 상대의 각 행에 최대 한 번 대응한다. R1의 100행 각각이 최대 한 행으로 이어지므로 옳다.
    3. 결과 속성은 A, B, C, D, E, F의 6개다. 공통 속성 C와 E가 각각 한 번만 남으므로 8개라는 설명은 옳지 않다.
    🧮 풀이
    1. R1의 A가 1인 행에 C=10이 있고 R2의 C=10인 행에 E=20이 있다. R3에서 E=20인 행을 찾으면 어느 두 릴레이션을 먼저 조인해도 A=1, C=10, E=20이 연결된다. 공통 값이 맞는 행만 최종 결과에 남는다.
    2. R1에 A가 1부터 100까지 100행 있다고 하자. R2는 C가 기본키라 각 R1행의 C에 맞는 행이 많아야 하나이고, R3도 E가 기본키라 다시 많아야 하나가 붙는다. 조인 과정에서 새로 행이 복제되지 않아 최종 행 수는 100을 넘지 않는다.
    3. R1의 A·B·C, R2의 C·D·E, R3의 E·F를 이어 붙인다. 자연 조인은 같은 이름의 C와 E를 하나씩 합치므로 결과 열은 A·B·C·D·E·F다. 원래 열 수 3+3+2=8을 그대로 쓰면 중복 열 두 개를 잘못 센다.

    정답은 3번이다.

    데이터베이스의 스키마와 인스턴스에 관한 설명을 바르게 연결한 것은?

    ㄱ. 데이터베이스의 논리적, 물리적 구조 정의

    ㄴ. 특정 시점에 데이터베이스에 저장되어 있는 실제 값

    ㄷ. DML(Data Manipulation Language)을 활용하여 생성 및 변환

    ㄹ. DDL(Data Definition Language)을 활용하여 생성 및 변환 스키마 인스턴스

    1. 1. ㄱ, ㄴ ㄷ, ㄹ
    2. 2. ㄱ, ㄹ ㄴ, ㄷ
    3. 3. ㄴ, ㄷ ㄱ, ㄹ
    4. 4. ㄴ, ㄹ ㄱ, ㄷ

    정답 2번

    🔍 보기별 해설
    1. 논리적·물리적 구조의 정의는 데이터베이스 스키마다. 어떤 데이터가 어떤 형태로 저장될지 정하는 설계 내용이다.
    2. 특정 시점에 저장된 실제 값은 인스턴스다. 같은 스키마 아래에서도 데이터가 갱신되면 인스턴스가 바뀐다.

    데이터베이스 회복(recovery) 기법에 대한 설명으로 옳은 것은?

    2. 2. ‘40000 <> ANY (SELECT 가격 FROM 상품)’은 참이다.
    3. 3. ‘30000 <> ALL (SELECT 가격 FROM 상품)’은 참이다.
    4. 4. ‘30000 > ALL (SELECT 가격 FROM 상품)’은 거짓이다.

    정답 3번

    🔍 보기별 해설

    🧮 풀이
    1. ① 상품 테이블의 가격 열에서 세 값을 읽는다. ANY와 ALL은 이 세 값을 각각 비교할 대상 집합으로 쓴다.
    2. → {25000, 30000, 40000}
    3. ↓
    4. ② ③의 30000 <> ALL을 검사한다. 30000−30000=0이므로 집합 속 같은 값과의 비교가 거짓이다.

    6. ↓
    7. ③ ALL은 모든 비교가 참이어야 하는데 하나가 거짓이다. 따라서 ③에서 적은 참 판정과 비교 결과가 어긋난다.
    8. → ③

    가격 집합에 30000이 포함되므로 ‘30000 <> ALL’은 거짓이고 정답은 3번이다.

    2. GRANT는 사용자나 역할에 객체 접근 권한을 부여하는 DCL(Data Control Language)이다. 제어어에 속하므로 옳다.
    3. DROP은 기존 테이블이나 뷰 같은 객체를 제거하는 DDL(Data Definition Language)이다. 권한을 회수하는 명령이 아니므로 옳지 않다.

    역정규화(denormalization)에 대한 설명으로 옳지 않은 것은?

    1. 1. 중복된 데이터를 일관성 있게 유지하기 위한 추가적인 작업이 필요하다.
    2. 2. 갱신 시간이 중요한(time critical) 연산을 지원하기 위해 사용된다.
    3. 3. 더 높은 정규형 릴레이션들을 조인한 결과를 저장하여 더 낮은 정규형으로 되돌아가는 과정이다.
    4. 4. 여러 테이블을 결합하는 데 시간이 오래 걸리는 경우, 역정규화를 통해 검색 시간을 단축할 수 있다.

    정답 2번

    🔍 보기별 해설
    1. 역정규화는 같은 값이 여러 곳에 저장될 수 있어 수정할 때 일관성 유지 작업이 필요하다. 중복의 부작용을 설명하므로 옳다.
    2. 역정규화는 주로 조인과 복잡한 조회의 비용을 줄이기 위해 사용한다. 갱신 시간이 중요한 연산을 지원하려고 쓴다는 설명은 옳지 않다(정답).
    3. 정규화한 릴레이션을 미리 조인한 결과로 저장하는 것은 역정규화의 한 방식이다. 조회를 위해 중복을 허용하므로 옳다.
    4. 여러 테이블을 매번 조인하면 조회 비용이 클 수 있다. 자주 쓰는 결합 결과를 저장해 검색 시간을 줄일 수 있으므로 옳다.
    🧮 풀이

    2. 매장 시스템이 주문 상태를 초당 수천 번 수정해야 한다. 고객명까지 주문 행마다 복제하면 고객명이 바뀔 때 더 많은 행을 갱신해야 한다. 갱신 성능을 우선할 때 중복 저장은 오히려 부담을 늘릴 수 있다.
    3. 고객 테이블과 주문 테이블을 분리해 두었다가 보고서에서 두 테이블의 결합 결과를 자주 요구한다. 관리자가 고객명과 주문번호를 함께 담은 읽기용 표를 만든다. 이미 결합한 값을 보관하는 것이 역정규화의 사례다.
    4. 보고서가 주문·상품·공급자 테이블을 매번 결합하느라 오래 걸린다. 자주 조회하는 상품별 공급자명을 주문 요약 표에 보관하면 실행 때 조인 수가 줄어든다. 읽기 속도가 개선되는 대신 값 동기화는 별도로 관리한다.

    역정규화는 조회 성능을 높이려고 사용하며 갱신 시간을 중시하는 목적은 아니므로 정답은 2번이다.

    4. 4. 트랜잭션이 (나)까지 성공적으로 완료되면 A고객과 B고객의 포인트 변경 결과는 장애가 발생하더라도 손실되지 않도록 보장되어야 한다.

    정답 1번

    🔍 보기별 해설

    4. 두 갱신을 모두 완료하고 커밋한 결과는 장애가 나도 보존되어야 한다. 트랜잭션의 지속성에 해당하므로 옳다.
    🧮 풀이
    1. A의 포인트 5000점에서 1000점을 빼 4000점이 되었지만 B에게 더하기 전이다. 다른 거래가 이때 두 잔액을 읽으면 합계가 잠시 4200점으로 보인다. 격리성을 지키면 이런 미완료 중간 상태를 노출하지 않는다.

    3. A가 5000점에서 4000점으로 줄고 B가 200점에서 1200점으로 늘어난다. 한쪽에서 뺀 1000점을 다른 쪽에 그대로 더했다. 두 고객의 합계는 송금 전후 모두 5200점이다.

    데이터베이스 및 데이터베이스 관리시스템(DBMS)의 사용자와 관련된 설명으로 옳지 않은 것은?

    1. 1. 일반 사용자(end user)는 응용 프로그램을 통해 데이터베이스에 접속하여 원하는 정보를 얻는 사용자를 말한다.
    2. 2. 데이터베이스 관리자(DBA)는 일반 사용자가 편리하게 데이터베이스에 접근할 수 있도록 인터페이스를 개발한다.
    3. 3. 일반 사용자는 데이터의 삽입, 삭제, 갱신 작업을 수행하기도 한다.
    4. 4. 응용 프로그래머(application programmer)는 프로그래밍 언어를 이용하여 데이터베이스 응용 프로그램을 개발하는 사용자이다.

    정답 2번

    🔍 보기별 해설
    1. 일반 사용자는 응용 프로그램을 통해 필요한 데이터베이스 정보를 조회한다. 사용자 역할에 맞는 설명이므로 옳다.
    2. DBA(Database Administrator)는 권한·저장·성능·회복 등을 관리한다. 일반 사용자용 인터페이스를 개발하는 역할로 설명한 것은 옳지 않다(정답).

    4. 응용 프로그래머는 프로그래밍 언어로 데이터베이스와 연결되는 프로그램을 만든다. 사용자 유형과 역할이 맞으므로 옳다.
    🧮 풀이
    1. 은행 고객이 모바일 앱에서 자신의 거래 내역을 연다. 앱이 데이터베이스에 질의를 보내고 결과를 화면에 보여 준다. 고객은 저장 구조나 SQL을 직접 알지 않아도 필요한 정보를 얻는다.
    2. DBA는 고객 테이블의 접근 권한을 정하고 백업과 복구 계획을 관리한다. 로그인 화면의 버튼과 입력 칸을 구현하는 사람은 응용 프로그래머다. DBA의 관리 책임과 화면 개발 업무를 구별한다.
    3. 창고 직원이 업무 프로그램에서 새 입고 수량을 입력하고 잘못 등록된 행을 삭제한다. 직원에게 부여된 권한 안에서 데이터베이스의 값이 바뀐다. 일반 사용자도 조회만 하는 것은 아니다.
    4. 개발자가 Java로 주문 입력 화면을 만들고 SQL을 호출하도록 연결한다. 직원이 주문번호를 넣으면 프로그램이 데이터베이스에 행을 등록한다. 이런 응용 프로그램을 작성하는 사람이 응용 프로그래머다.

    사용자 인터페이스 개발은 응용 프로그래머의 일이며 DBA의 주된 역할이 아니므로 정답은 2번이다.

    데이터베이스 트랜잭션이 올바르게 수행된다는 것을 보장하기 위해 지원해야 하는 트랜잭션 성질에 대한 설명으로 옳지 않은 것은?

    1. 1. 각 트랜잭션의 모든 연산이 정상적으로 수행 완료되거나, 아니면 어떠한 연산도 수행되지 않은 원래 상태가 되어야 한다.
    2. 2. 트랜잭션이 그 실행을 성공적으로 완료하면 언제나 일관성 있는 데이터베이스 상태로 변환한다.
    3. 3. 트랜잭션이 성공적으로 끝난 뒤에는, 시스템에 오류가 발생하더라도 트랜잭션에 의해 변경된 데이터베이스 내용은 계속 유지되어야 한다.
    4. 4. 트랜잭션이 실행되는 동안의 값은 다른 트랜잭션이 접근할 수 있어야 한다.

    정답 4번

    🔍 보기별 해설
    1. 원자성은 트랜잭션의 모든 작업이 함께 완료되거나 함께 취소되게 한다. 일부만 반영되지 않아야 하므로 옳다.
    2. 일관성은 성공한 트랜잭션이 무결성 조건을 지키는 상태로 데이터베이스를 옮긴다는 성질이다. 설명과 맞으므로 옳다.
    3. 지속성은 커밋된 변경이 장애 뒤에도 유지되게 한다. 성공한 결과의 보존을 말하므로 옳다.
    4. 격리성은 한 트랜잭션의 미완료 중간 값을 다른 트랜잭션이 보지 못하게 한다. 실행 중인 값을 접근하도록 허용해야 한다는 말은 옳지 않다(정답).
    🧮 풀이
    1. 고객 A에서 1000원을 빼고 고객 B에게 1000원을 더하는 거래를 시작한다. 두 번째 작업이 실패하면 첫 번째 차감도 취소해 두 계좌가 원래 상태로 돌아간다. 한쪽만 반영하지 않는 것이 원자성이다.
    2. 계좌 잔액이 음수가 되지 않아야 한다는 제약이 있다. 성공한 이체 뒤에도 모든 계좌가 이 조건을 만족하도록 거래가 처리된다. 트랜잭션 전후의 유효한 상태를 지키는 것이 일관성이다.

    4. 고객 A의 잔액만 먼저 줄인 송금이 아직 끝나지 않았다. 다른 거래가 이 중간 잔액을 읽으면 두 계좌의 합이 일시적으로 줄어든 듯 보인다. 격리성이 있으면 완료 전 상태를 다른 거래에 보여 주지 않는다.

    미완료 트랜잭션의 중간 값은 다른 거래에 노출하지 않아야 하므로 정답은 4번이다.

    관계형 데이터베이스의 릴레이션에 대한 특성으로 옳지 않은 것은?

    2. 2. 릴레이션의 투플에 저장되는 값의 집합을 도메인(domain)이라 한다.
    3. 3. 하나의 릴레이션에서 투플의 순서는 의미가 없다.
    4. 4. 하나의 릴레이션에는 동일한 이름의 속성(attribute)을 가질 수 없다.

    정답 2번

    🔍 보기별 해설
    1. 관계형 릴레이션은 같은 속성값 조합의 튜플을 중복해 가지지 않는다. 관계의 집합 성질에 맞으므로 옳다.
    2. 도메인은 속성 하나가 취할 수 있는 값의 집합이다. 튜플에 실제 저장된 값들의 모음이라고 한 설명은 옳지 않다(정답).

    4. 한 릴레이션 안에서는 속성 이름을 구별할 수 있어야 한다. 같은 이름의 속성을 둘 수 없으므로 옳다.
    🧮 풀이

    2. 성적 속성의 도메인을 0부터 100까지의 정수로 정한다. 현재 테이블에 75와 88만 저장되어 있어도 90은 여전히 허용된 도메인 값이다. 실제 저장 값 둘만 도메인이라고 부르면 범위를 잘못 좁힌다.
    3. 학번순 출력과 이름순 출력은 학생 테이블의 같은 행 집합을 보여 준다. 화면에서 행 순서는 달라져도 저장된 튜플의 집합은 같다. 정렬 순서가 릴레이션 자체의 의미를 바꾸지 않는다.
    4. 한 학생 테이블에 학번과 이름이라는 서로 다른 속성을 둔다. 두 열을 모두 이름이라고 부르면 질의에서 어느 열을 뜻하는지 구별할 수 없다. 관계 스키마는 각 속성의 이름을 고유하게 정한다.

    도메인은 한 속성에 허용되는 값의 집합이므로 정답은 2번이다.

    데이터베이스 및 DBMS에 대한 설명으로 옳은 것은?

    1. 1. 개념적 데이터 모델(conceptual data model)은 데이터가 컴퓨터의 저장 장치에 어떻게 저장되는가에 대한 세부 사항을 명시하는 개념을 제공한다.
    2. 2. 데이터 정의어(DDL)를 이용하면 개념 스키마를 정의할 수 있다.
    3. 3. 데이터 조작어(DML)는 무결성 제약 조건을 정의하는 명령어를 포함한다.
    4. 4. DBMS는 데이터베이스 관리자나 일반 사용자가 아닌 응용 프로그래머를 위한 모듈은 제공하지 않는다.

    정답 2번

    🔍 보기별 해설
    1. 개념적 데이터 모델은 업무 개체와 관계를 높은 수준에서 표현한다. 디스크에 저장되는 세부 방식을 설명하는 모델이 아니므로 옳지 않다.
    2. DDL(Data Definition Language)은 테이블과 제약조건 같은 데이터베이스 구조를 정의한다. 개념 스키마를 명시할 수 있으므로 옳다(정답).
    3. DML(Data Manipulation Language)은 저장된 행을 조회·삽입·수정·삭제한다. 무결성 제약의 정의를 맡는 언어라는 설명은 옳지 않다.
    4. DBMS는 응용 프로그램이 데이터에 접근할 수 있도록 질의·연결 등의 모듈을 제공한다. 응용 프로그래머를 위한 모듈이 없다는 말은 옳지 않다.
    🧮 풀이
    1. 대학 데이터베이스를 설계하며 학생과 교과목, 수강 관계를 개체·관계로 그린다. 이 그림은 학번이 디스크의 어느 블록에 저장되는지는 정하지 않는다. 업무의 의미를 모델링하는 단계다.
    2. 관리자가 CREATE TABLE 학생으로 학번 열과 기본키를 정의한다. DBMS는 이 구조를 스키마에 등록하고 이후 학생 행을 받는다. DDL로 저장 자료의 논리적 정의를 명시하는 사례다.
    3. 직원이 INSERT로 학생 한 명을 등록하고 UPDATE로 이름을 고친다. 이 명령들은 현재 저장된 데이터를 다룬다. 학번 열의 자료형이나 기본키 제약 자체를 정의하지 않는다.
    4. 개발자가 프로그램에서 데이터베이스 연결 모듈을 사용해 주문 정보를 조회한다. DBMS가 제공하는 질의 처리 기능과 연결 인터페이스를 이용해 앱을 만든다. 응용 프로그래머도 DBMS 기능을 사용한다.

    DDL은 개념 스키마의 구조를 정의하는 데 사용할 수 있으므로 정답은 2번이다.

    ○ 릴레이션 R의 함수 종속 관계에서 결정자(determinant) 중에 후보키가 아닌 것이 포함되어 있을 수 있다.

    2. 2. 제3정규형
    3. 3. 제4정규형

    2. 첫 명령 뒤 U2는 성적을 조회할 수 있었다. 네 번째 명령에서 U1이 U2의 SELECT를 REVOKE하자 그 조회 권한은 사라진다. U3와 U4 사이의 별도 권한 경로는 이 회수의 대상이 아니다.
    3. U3는 U1에게 SELECT WITH GRANT OPTION을 받아 U4에게 조회 권한을 준다. 뒤이어 U1이 U2의 조회 권한만 회수한다. U3를 거친 경로는 남아 U4가 성적 테이블을 조회할 수 있다.
    4. U4가 다섯 번째 명령으로 U5에게 조회 권한을 주려 한다. U4가 받은 것은 단순 SELECT라 위임 옵션이 없다. GRANT가 허용되지 않아 U5에게 유효한 조회 권한이 생기지 않는다.

    U3가 U4에게 준 SELECT 권한은 유지되며 U5에게는 위임되지 않으므로 정답은 3번이다.

    NoSQL의 특징으로 옳은 것만을 모두 고르면?

    ㄱ. 반정형 데이터(semi-structured data)를 처리하기에는 적합하지 않다.

    ㄴ. 트랜잭션의 ACID 성질을 완벽히 보장하는 것이 중요하다.

    ㄷ. 문서－기반 모델은 NoSQL에서 사용되는 데이터 모델의 한 종류이다.

    ㄹ. 스키마를 요구하지 않는 경우가 있다.

    1. 1. ㄱ, ㄴ
    2. 2. ㄱ, ㄷ
    3. 3. ㄴ, ㄹ
    4. 4. ㄷ, ㄹ

    정답 4번

    🔍 보기별 해설
    1. NoSQL은 문서 같은 반정형 자료를 다루는 데 사용된다. 반정형 데이터에 부적합하다는 설명은 옳지 않다.
    2. NoSQL 전체가 ACID(Atomicity, Consistency, Isolation, Durability)를 완전 보장하는 설계를 핵심으로 삼지는 않는다. 그 보장이 가장 중요하다는 설명은 옳지 않다.
    3. 문서 기반 데이터 모델은 JSON 유사 문서를 저장하는 NoSQL의 한 유형이다. NoSQL 모델의 예로 옳다.
    4. NoSQL 저장소에는 고정된 열 스키마를 요구하지 않는 형태가 있다. 문서마다 필드 구성이 달라도 저장할 수 있으므로 옳다.
    🧮 풀이
    1. 상품 문서마다 색상과 크기 필드가 다르게 들어간다. 문서형 데이터베이스는 정해진 열을 모두 채우지 않아도 각각의 문서를 저장할 수 있다. 반정형 자료를 처리하기에 적합한 장면이다.
    2. 여러 지역에 분산된 키·값 저장소가 빠른 응답과 가용성을 우선하도록 설계된다. 일부 저장소는 강한 트랜잭션 보장 대신 다른 일관성 방식을 선택한다. 모든 NoSQL이 관계형 거래와 똑같은 ACID 보장을 최우선으로 하지는 않는다.
    3. 온라인 상점이 상품 한 건을 이름·가격·태그가 든 문서 한 개로 저장한다. 검색할 때 해당 문서를 읽어 여러 필드를 함께 얻는다. 문서 기반 저장은 NoSQL 데이터 모델의 실제 사례다.
    4. 상품 A 문서에는 색상 필드가 있고 상품 B 문서에는 유통기한 필드가 있다. 저장소는 두 문서에 같은 열 집합을 강제하지 않는다. 필요한 필드를 상품 유형에 따라 달리 기록할 수 있다.

    정답은 4번이다.

    B+－트리 인덱스에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄱ. 루트(root)를 포함한 내부 노드(internal node)는 데이터 파일 레코드를 가리키는 포인터를 갖는다.

    ㄴ. 트리의 루트(root)에서 단말 노드(leaf node)까지 모든 경로의 길이가 같은 균형 트리(balanced tree) 형태이다.

    ㄷ. 단말 노드(leaf node)는 검색키 값을 기초로 선형 순서로 되어 있어 데이터 레코드들을 그 키 값의 순서에 따라 능률적으로 순차 접근할 수 있게 해 준다.

    1. 1. ㄱ, ㄴ
    2. 2. ㄱ, ㄷ
    3. 3. ㄴ, ㄷ
    4. 4. ㄱ, ㄴ, ㄷ

    정답 3번

    🔍 보기별 해설
    1. B+ 트리의 내부 노드는 탐색 경로를 고르는 키와 자식 노드 포인터를 담는다. 데이터 파일의 레코드 포인터가 내부 노드에 있다는 설명은 옳지 않다.
    2. B+ 트리는 모든 단말 노드가 같은 깊이에 놓이도록 유지하는 균형 트리다. 루트에서 단말까지 경로 길이가 같으므로 옳다.
    3. B+ 트리의 단말 노드는 키 순서로 배열·연결된다. 이 순서를 따라가면 범위에 든 레코드에 효율적으로 순차 접근할 수 있으므로 옳다.
    🧮 풀이
    1. 주문번호를 찾으며 루트의 경계 키를 보고 왼쪽 또는 오른쪽 자식으로 내려간다. 내부 노드의 포인터는 다음 인덱스 노드로 이어진다. 실제 주문 레코드를 찾는 정보는 단말 쪽에서 얻는다.
    2. 새 키를 삽입하다가 단말이 가득 차면 노드를 분할하고 부모의 경계 키를 조정한다. 트리가 커져도 모든 단말은 같은 단계에 놓인다. 어느 주문번호를 찾아도 루트에서 단말까지 같은 층수를 지나간다.
    3. 주문번호 100부터 150까지 읽어야 할 때 먼저 100이 있는 단말을 찾는다. 이어 연결된 단말 노드를 키 순서로 따라가며 범위 값을 읽는다. 매 키마다 루트로 돌아가지 않아 순차 접근에 유리하다.

    정답은 3번이다.
