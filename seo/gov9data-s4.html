    다음에서 설명하는 데이터 마이닝 분석 기법은?

    ○ 장바구니 분석이라고도 한다.

    ○ 데이터 간의 발생 빈도를 분석하여 그 속에 숨겨진 규칙을 파악하는 방법으로, 상품이나 서비스 간의 관계를 분석하여 마케팅에 주로 활용한다.

    1. 1. 분류 분석
    2. 2. 군집 분석
    3. 3. 연관 분석
    4. 4. 회귀 분석

    정답 3번

    🔍 보기별 해설
    1. 분류 분석은 이미 알려진 범주로 새 데이터를 나누는 기법이며 장바구니처럼 함께 나타나는 항목 사이의 규칙을 찾는 기법이 아니므로 설명에 해당하지 않는다.
    2. 군집 분석은 정해진 범주 없이 비슷한 데이터끼리 묶는 기법이며 상품 사이의 발생 빈도로 규칙을 찾는 기법이 아니므로 설명에 해당하지 않는다.
    3. 연관 분석은 데이터 사이의 발생 빈도를 분석해 함께 나타나는 항목의 숨은 규칙을 찾으며 장바구니 분석이라고도 부르고 마케팅에 쓰이므로 설명에 해당한다(정답).
    4. 회귀 분석은 변수들 사이의 관계를 함수로 만들어 값을 예측하는 기법이며 항목이 함께 팔리는 규칙을 찾는 기법이 아니므로 설명에 해당하지 않는다.
    🧮 풀이
    1. 甲은 스팸으로 표시된 메일과 그렇지 않은 메일을 학습해 새 메일이 스팸인지 나누는 프로그램을 만든 학생이다. 미리 정해진 범주로 나누는 이 방식은 상품이 함께 팔리는 규칙을 찾는 방식과 다르다고 설명했다.
    2. 甲은 고객 이천 명을 나이와 구매액이 비슷한 집단으로 묶어 각 집단의 특성을 살펴본 마케팅 담당자다. 정해진 범주 없이 비슷한 것끼리 묶는 이 방식은 함께 사는 상품의 규칙을 찾는 것과 다르다고 정리했다.
    3. 甲은 마트의 영수증 기록을 분석해 기저귀를 사는 사람이 맥주도 함께 사는 경우가 많다는 규칙을 발견한 담당자다. 함께 팔리는 상품의 빈도를 분석해 진열을 바꾸었고 매출이 늘었다.
    4. 甲은 광고비와 매출의 관계를 식으로 만들어 다음 달 매출을 예측한 분석가다. 변수 사이의 관계로 값을 예측하는 이 방식은 함께 팔리는 상품의 규칙을 찾는 것과 다르다는 점을 알았다.

    발생 빈도를 분석해 상품 사이의 규칙을 찾는 장바구니 분석은 연관 분석이므로 3번이 해당한다.

    시스템 카탈로그에 대한 설명으로 옳지 않은 것은?

    1. 1. 데이터 사전(data dictionary)이라고도 한다.
    2. 2. 각 릴레이션의 튜플 수와 블록 수가 저장된다.
    3. 3. 일반 사용자도 시스템 카탈로그에 내용을 추가하거나 수정할 수 있다.
    4. 4. RDBMS마다 서로 다른 형태로 시스템 카탈로그를 제공한다.

    정답 3번

    🔍 보기별 해설
    1. 시스템 카탈로그는 데이터베이스에 저장된 데이터의 구조를 설명하는 정보를 담고 있어 데이터 사전이라고도 부르므로 이 보기는 옳다.
    2. 시스템 카탈로그에는 각 릴레이션의 튜플 수와 블록 수 같은 통계 정보가 저장되어 DBMS가 질의 최적화에 활용하므로 이 보기는 옳다.
    3. 시스템 카탈로그는 DBMS가 스스로 만들고 관리하는 정보라서 일반 사용자가 내용을 추가하거나 수정하면 데이터베이스가 손상될 수 있으므로, 수정할 수 있다는 이 보기는 옳지 않다(정답).
    4. 시스템 카탈로그는 DBMS 제품마다 저장 방식과 테이블 구조가 서로 다른 형태로 제공되어 제품이 달라지면 조회 방법도 달라지므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 데이터베이스에 어떤 테이블이 있고 각 테이블에 열이 몇 개인지를 한곳에서 조회해 본 학생이다. 이런 정보를 모아 둔 곳을 데이터 사전이라고도 부른다는 것을 알게 되었다.
    2. 甲은 질의를 실행하기 전에 DBMS가 테이블의 행 수와 저장 블록 수를 참고해 실행 계획을 세운다는 설명을 들은 학생이다. 이런 통계가 카탈로그에 저장되어 있다는 것을 확인했다.
    3. 甲은 일반 사용자 계정으로 시스템 테이블에 항목을 넣어 보려 했으나 거부당한 학생이다. DBMS가 스스로 관리하는 정보를 사용자가 고칠 수 없게 막아 둔다는 것을 알았다. 그래서 카탈로그 정보는 관리자도 직접 고치지 않는다고 했다.
    4. 甲은 서로 다른 두 종류의 DBMS에서 카탈로그를 조회해 본 학생이다. 같은 정보를 담고 있어도 테이블 이름과 열 구성이 제품마다 다르다는 점을 표로 정리했다. 그래서 제품을 바꾸면 조회 쿼리도 다시 익혀야 한다고 했다.

    시스템 카탈로그는 DBMS가 스스로 생성하고 유지하는 메타데이터이므로 일반 사용자가 수정할 수 있다고 한 3번이 옳지 않다.

    다음에서 설명하는 데이터베이스 무결성 제약조건(integrity constraint)은?

    ○ 기본키 제약(primary key constraint)이라고도 한다.

    ○ 기본키는 널(NULL) 값을 가져서는 안되며 릴레이션 내에 오직 하나의 값만 존재해야 한다.

    1. 1. 개체 무결성 제약조건
    2. 2. 고유 무결성 제약조건
    3. 3. 도메인 무결성 제약조건
    4. 4. 참조 무결성 제약조건

    정답 1번

    🔍 보기별 해설
    1. 개체 무결성 제약조건은 기본키가 NULL 값을 가질 수 없고 릴레이션 안에서 유일해야 한다는 규칙이며 기본키 제약이라고도 하므로 설명에 해당한다(정답).
    2. 고유 무결성 제약조건은 UNIQUE 속성 값이 중복되지 않도록 하는 규칙이며 NULL을 허용할 수 있어 기본키 제약과는 다르므로 설명에 해당하지 않는다.
    3. 도메인 무결성 제약조건은 속성 값이 정해진 도메인 안의 값이어야 한다는 규칙이며 기본키의 유일성과 NULL 금지를 뜻하지 않으므로 설명에 해당하지 않는다.
    4. 참조 무결성 제약조건은 외래키 값이 참조되는 릴레이션의 기본키 값과 일치하거나 NULL이어야 한다는 규칙이며 기본키 자체의 제약이 아니므로 설명에 해당하지 않는다.
    🧮 풀이
    1. 甲은 학생 테이블에 학번이 비어 있는 행을 넣으려다 거부당한 학생이다. 행을 구별하는 열은 값이 비어서도 중복되어서도 안 된다는 규칙 때문이라는 것을 알았다. 그래서 이 열은 비어 있거나 중복되면 행을 구별할 수 없다고 했다.
    2. 甲은 전화번호 열에 중복 값을 넣지 못하도록 제약을 걸었으나 일부 행은 전화번호가 비어 있어도 허용되는 것을 확인한 학생이다. 이 제약은 기본키와 달리 빈 값을 허용한다는 점이 다르다.
    3. 甲은 나이 열에 영보다 작은 값이 들어가지 않도록 범위를 정한 학생이다. 이 규칙은 값이 올 수 있는 범위를 정할 뿐 행을 구별하는 열의 규칙과는 다르다는 점을 정리했다. 결국 이 제약은 열의 값 범위만 정해 준다는 점을 표로 정리했다.
    4. 甲은 주문 테이블에 고객 테이블에 없는 고객 번호를 넣으려다 거부당한 학생이다. 다른 테이블의 값을 참조하는 열의 규칙이라 행을 구별하는 열의 규칙과는 다르다고 설명했다. 결국 이 규칙은 테이블 사이의 연결을 지키는 것이라 기본키와 다르다고 했다.

    기본키 제약이라고도 하며 기본키가 NULL이 될 수 없고 유일해야 하는 제약은 개체 무결성 제약조건이므로 1번이 해당한다.

    데이터베이스 모델에서 사용되는 키(key)에 대한 설명으로 옳지 않은 것은?

    1. 1. 후보키(candidate key)는 유일성과 최소성의 특성을 만족하는 속성 또는 속성들의 집합이다.
    2. 2. 슈퍼키(super key)는 유일성의 특성을 만족하는 속성 또는 속성들의 집합이다.
    3. 3. 대체키(alternate key)는 기본키(primary key)로 선택되지 못한 외래키(foreign key)들이다.
    4. 4. 널(NULL) 값을 가질 수 있는 속성이 포함된 후보키는 기본키로 부적합하다.

    정답 3번

    🔍 보기별 해설
    1. 후보키는 각 튜플을 유일하게 식별하는 유일성과 속성을 빼면 유일성이 깨지는 최소성을 함께 만족하는 속성 집합이므로 이 보기는 옳다.
    2. 슈퍼키는 각 튜플을 유일하게 식별하는 유일성만 만족하면 되고 최소성은 요구하지 않아 불필요한 속성이 들어 있어도 되는 속성 집합이므로 이 보기는 옳다.
    3. 대체키는 후보키 중 기본키로 선택되지 못한 나머지 키이며 다른 릴레이션을 참조하는 외래키와는 다른 개념이므로, 기본키로 선택되지 못한 외래키라는 이 보기는 옳지 않다(정답).
    4. 널 값을 가질 수 있는 속성이 포함된 후보키는 개체 무결성 때문에 기본키로 삼을 수 없어 기본키로 부적합하므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 학생 테이블에서 학번, 주민번호, 이메일이 모두 학생을 하나로 식별할 수 있음을 확인한 학생이다. 이 중 하나를 기본키로 정하고 나머지를 대체할 수 있는 키로 남겨 둔다는 점을 알았다.
    2. 甲은 학번과 이름을 합친 속성 집합도 학생을 유일하게 식별하는 것을 확인한 학생이다. 그러나 이름을 빼도 유일하므로 최소성이 없어 후보키는 아니고 슈퍼키라고 정리했다. 그래서 최소성이 후보키의 필수 조건임을 다시 확인했다.
    3. 甲은 주문 테이블의 고객번호가 고객 테이블을 참조하는 열임을 확인한 학생이다. 이렇게 다른 테이블을 참조하는 열은 외래키이며 기본키에서 밀려난 후보키와는 다르다는 것을 알았다.
    4. 甲은 이메일이 비어 있는 학생이 있는 테이블에서 이메일을 기본키로 삼으려던 학생이다. 기본키는 값이 비면 안 되어 이 후보키는 기본키로 쓸 수 없다는 점을 알고 학번으로 바꾸었다.

    대체키는 기본키로 선택되지 못한 후보키이지 외래키가 아니므로 3번이 옳지 않다.

    릴레이션 R1, R2, R3의 스키마는 R1(A, B, C), R2(C, D, E), R3(E, F)이고, 기본키는 각각 A, C, E이다. 튜플의 수가 R1은 100개, R2는 150개, R3은 75개라고 할 때, R1 ⋈N R2 ⋈N R3의 결과에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄱ. R1 ⋈N (R2 ⋈N R3)의 결과와 동일하다.

    ㄴ. 결과 릴레이션의 튜플은 최대 100개이다.

    ㄷ. 결과 릴레이션의 속성은 8개이다.

    1. 1. ㄱ
    2. 2. ㄴ
    3. 3. ㄱ, ㄴ
    4. 4. ㄱ, ㄴ, ㄷ

    정답 3번

    🔍 보기별 해설
    1. 자연 조인은 결합 법칙이 성립해 R1 ⋈ R2 ⋈ R3의 결과가 R1 ⋈ (R2 ⋈ R3)의 결과와 같으므로 이 설명은 옳다.
    2. C가 R2의 기본키이고 E가 R3의 기본키라서 R1의 각 튜플은 R2의 튜플 최대 하나와, R2의 튜플은 R3의 튜플 최대 하나와 맞아 결과의 튜플은 최대 R1의 100개이므로 이 설명은 옳다.
    3. 결과 릴레이션의 속성은 공통 속성 C와 E를 한 번씩만 나타내 A, B, C, D, E, F의 6개이므로 8개라는 이 설명은 옳지 않다.
    🧮 풀이
    1. 甲은 세 테이블을 순서를 바꿔 가며 조인해 본 학생이다. 묶는 순서를 달리해도 결과 튜플이 같은 것을 확인하고 조인의 결합 법칙이 성립한다는 것을 알았다. 그래서 어떤 순서로 묶어도 같은 결과라는 점이 편했다.
    2. 甲은 기본키로 연결된 세 테이블을 조인해 결과 행의 수를 세어 본 학생이다. 기본키 값은 한 번만 나타나므로 첫 테이블의 행 수를 넘지 않는다는 점이 이해되었다. 결국 결과 행의 상한이 첫 테이블 행 수라는 것을 알았다.
    3. 甲은 세 릴레이션의 속성 수를 모두 더해 여덟 개라고 답한 학생이다. 자연 조인은 같은 이름의 속성을 한 번만 남긴다는 점을 놓쳤음을 알고 고쳤다. 그래서 계산할 때 공통 속성이 몇 번 나타나는지 먼저 세기로 했다.

    ㄱ과 ㄴ은 옳고 ㄷ은 결과 속성이 6개라서 옳지 않으므로 정답은 3번이다.

    데이터베이스의 스키마와 인스턴스에 관한 설명을 바르게 연결한 것은?

    SQL에서 다음 상품 테이블에 대한 ANY와 ALL 연산의 결과로 옳지 않은 것은?

    상품 상품번호 가격 1 25000 2 30000 3 40000

    1. 1. ‘40000 = ANY (SELECT 가격 FROM 상품)’은 참이다.
    2. 2. ‘40000 <> ANY (SELECT 가격 FROM 상품)’은 참이다.
    3. 3. ‘30000 <> ALL (SELECT 가격 FROM 상품)’은 참이다.
    4. 4. ‘30000 > ALL (SELECT 가격 FROM 상품)’은 거짓이다.

    정답 3번

    🔍 보기별 해설
    1. 가격 집합에 40000이 있으므로 40000 = ANY (25000, 30000, 40000)은 하나라도 같으면 참이어서 이 설명은 옳다.
    2. 40000과 다른 값인 25000이 집합에 있어 40000 <> ANY는 하나라도 다르면 참이라는 조건이 성립하므로 이 설명은 옳다.
    3. 집합에 30000이 들어 있으므로 30000 <> ALL은 모든 값과 달라야 참인데 30000과 같은 값이 있어 거짓이므로, 참이라는 이 설명은 옳지 않다(정답).
    4. 집합에 40000이 있어 30000이 모든 값보다 크다는 조건이 성립하지 않으므로 30000 > ALL은 거짓이라는 이 설명은 옳다.
    🧮 풀이
    1. 甲은 상품 가격 중 하나라도 사만 원과 같은지 묻는 질의를 실행한 학생이다. 사만 원이 집합에 있어 참이 나오는 것을 확인하고 어느 하나라도 만족하면 되는 연산임을 알았다.
    2. 甲은 사만 원과 다른 가격이 하나라도 있는지 묻는 질의를 실행한 학생이다. 이만 오천 원이 있어 참이 되는 것을 보고 하나라도 다르면 참이라는 규칙을 익혔다. 그래서 하나라도 다르면 참인 조건임을 표로 적어 두었다.
    3. 甲은 삼만 원이 모든 가격과 다른지 묻는 질의를 실행한 학생이다. 삼만 원과 같은 가격이 하나 있어 거짓이 나오는 것을 보고 모두 달라야 참이라는 규칙을 이해했다. 그래서 모두 다를 때만 참인 조건이라고 정리해 두었다.
    4. 甲은 상품 가격 중 가장 높은 값과 삼만 원을 견주어 본 학생이다. 사만 원이 있어 삼만 원이 모든 값을 넘지 못하므로 조건이 거짓이 되는 이유를 규칙으로 확인했다. 그래서 모두를 넘을 때만 참인 조건이라고 정리해 두었다.

    30000은 상품 가격 집합에 있으므로 30000 <> ALL은 거짓이며 참이라고 한 3번이 옳지 않다.

    SQL 명령어 중에서 데이터 제어어(DCL)만을 모두 고르면?

    ㄱ. CREATE

    ㄴ. GRANT

    ㄷ. DROP

    ㄹ. REVOKE

    1. 1. ㄱ, ㄴ
    2. 2. ㄴ, ㄹ
    3. 3. ㄷ, ㄹ
    4. 4. ㄴ, ㄷ, ㄹ

    2. GRANT는 사용자에게 테이블에 대한 권한을 부여하는 명령으로 권한을 다루는 데이터 제어어에 속하는 대표적인 명령이므로 이 설명은 옳다.
    3. DROP은 테이블 같은 객체를 삭제하는 데이터 정의어이므로 권한을 다루는 데이터 제어어에 해당하지 않아 이 설명은 옳지 않다.
    4. REVOKE는 사용자에게 이미 준 권한을 회수하는 명령으로 권한을 다루는 데이터 제어어에 속하는 대표적인 명령이므로 이 설명은 옳다.
    🧮 풀이
    1. 甲은 새로운 직원 테이블을 만드는 명령을 실행한 개발자다. 테이블 구조를 만드는 명령이라 권한을 다루는 명령이 아니라 구조를 정의하는 명령이라는 점을 확인했다. 그래서 구조를 만드는 명령은 권한 명령이 아니라고 구분했다.
    2. 甲은 신입 직원에게 매출 테이블을 조회할 권한을 주는 명령을 실행한 관리자다. 권한을 부여하는 이 명령이 제어어에 속한다는 것을 보고서에 정리했다. 그래서 권한을 주는 명령을 제어어라고 부른다는 점을 표로 적었다.
    3. 甲은 더 이상 쓰지 않는 테이블을 삭제하는 명령을 실행한 개발자다. 이 명령은 객체를 없애는 구조 정의 명령이어서 권한과는 무관하다는 점을 알았다. 그래서 객체를 없애는 일도 권한이 아니라 구조 정의라고 구분했다.
    4. 甲은 퇴사자의 계정에 열람 권한이 그대로 남아 있는 것을 발견한 보안 담당자다. 이미 준 권한을 거두는 명령으로 정리했고 이것이 제어어의 역할임을 확인했다. 그래서 준 권한을 거두는 명령도 제어어에 속한다고 정리했다.

    데이터 제어어는 권한을 주는 GRANT와 회수하는 REVOKE이므로 ㄴ과 ㄹ을 고른 정답은 2번이다.

    역정규화(denormalization)에 대한 설명으로 옳지 않은 것은?

    1. 1. 중복된 데이터를 일관성 있게 유지하기 위한 추가적인 작업이 필요하다.
    2. 2. 갱신 시간이 중요한(time critical) 연산을 지원하기 위해 사용된다.
    3. 3. 더 높은 정규형 릴레이션들을 조인한 결과를 저장하여 더 낮은 정규형으로 되돌아가는 과정이다.
    4. 4. 여러 테이블을 결합하는 데 시간이 오래 걸리는 경우, 역정규화를 통해 검색 시간을 단축할 수 있다.

    정답 2번

    🔍 보기별 해설
    1. 역정규화로 중복 데이터가 생기면 여러 곳에 저장된 같은 값이 어긋나지 않도록 유지하는 추가 작업이 필요해지므로 이 보기는 옳다.
    2. 역정규화는 조인을 줄여 조회를 빠르게 하는 것이 목적이며 중복 때문에 갱신 성능이 나빠지므로, 갱신 시간이 중요한 연산을 지원한다는 이 보기는 옳지 않다(정답).
    3. 역정규화는 높은 정규형 릴레이션들을 조인한 결과를 저장해 성능을 위해 더 낮은 정규형으로 되돌아가는 과정이므로 이 보기는 옳다.
    4. 조인이 느린 질의는 결합 결과를 미리 테이블로 저장해 두면 조회할 때 조인 없이 바로 읽을 수 있어 검색 시간이 줄어들므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 상품 정보를 여러 테이블에 나누어 저장한 뒤 값을 하나 바꿀 때마다 여러 곳을 고쳐야 하는 불편을 겪은 개발자다. 중복 저장을 하면 이런 작업이 늘어난다는 점을 알았다.
    2. 甲은 조회는 빨라졌으나 주문이 들어올 때마다 중복된 값을 함께 고쳐야 해서 처리 속도가 느려진 담당자다. 이 방식이 갱신 시간이 중요한 연산에는 불리하다는 것을 확인했다. 그래서 갱신이 많은 시스템에서는 조심해서 써야 한다고 했다.
    3. 甲은 세 개의 테이블을 합쳐 하나의 테이블로 저장해 둔 개발자다. 이렇게 하면 원래 지키던 정규형보다 낮은 정규형이 된다는 점을 기록으로 남겼다. 그래서 낮은 정규형으로 되돌아가는 대신 조회가 빨라지는 것이 목적이라고 했다.
    4. 甲은 매번 다섯 개 테이블을 조인하느라 응답이 느려진 서비스의 담당자다. 조인 결과를 미리 저장하자 조회 시간이 크게 줄어드는 것을 확인했다. 그래서 조회가 중요한 화면에는 역정규화가 알맞다고 판단했다.

    역정규화는 검색 시간을 줄이려는 것이지 갱신 시간이 중요한 연산을 돕는 것이 아니므로 2번이 옳지 않다.

    데이터베이스 및 DBMS에 대한 설명으로 옳은 것은?

    1. 1. 개념적 데이터 모델(conceptual data model)은 데이터가 컴퓨터의 저장 장치에 어떻게 저장되는가에 대한 세부 사항을 명시하는 개념을 제공한다.
    2. 2. 데이터 정의어(DDL)를 이용하면 개념 스키마를 정의할 수 있다.
    3. 3. 데이터 조작어(DML)는 무결성 제약 조건을 정의하는 명령어를 포함한다.
    4. 4. DBMS는 데이터베이스 관리자나 일반 사용자가 아닌 응용 프로그래머를 위한 모듈은 제공하지 않는다.

    정답 2번

    🔍 보기별 해설
    1. 개념적 데이터 모델은 사용자가 이해하기 쉬운 개념을 제공하며 저장 장치에 저장하는 세부 사항을 명시하는 것은 물리적 데이터 모델이므로 이 보기는 옳지 않다.
    2. 데이터 정의어(DDL)는 테이블 구조와 제약조건을 정의하는 명령이므로 이를 이용하면 개념 스키마를 정의할 수 있어 이 보기는 옳다(정답).
    3. 무결성 제약 조건을 정의하는 명령은 데이터 정의어에 포함되며 데이터 조작어는 데이터를 검색하고 삽입·삭제·수정하는 명령이므로 이 보기는 옳지 않다.
    4. DBMS는 관리자와 일반 사용자뿐 아니라 응용 프로그래머를 위한 프로그래밍 언어 연동 모듈도 제공하므로 이 보기는 옳지 않다.
    🧮 풀이
    1. 甲은 데이터 모델이 데이터가 디스크에 어떻게 저장되는지를 자세히 규정한다고 생각한 학생이다. 저장 방식은 물리적 모델의 몫이고 개념적 모델은 사용자 관점의 개념이라는 점을 알게 되었다.
    2. 甲은 테이블을 만들고 열의 자료형과 기본키를 정의하는 명령을 실행한 학생이다. 이런 정의 명령이 조직 전체 구조를 나타내는 개념 스키마를 만드는 것이라는 점을 알았다. 테이블을 만드는 CREATE 문이 그것이다.
    3. 甲은 무결성 제약을 정의하는 명령을 조작어라고 여겼던 학생이다. 제약도 구조의 일부라 정의어로 작성한다는 점을 조교가 짚어 주었다. 무결성 제약도 구조의 일부라 정의어로 적는다.
    4. 甲은 개발자가 응용 프로그램에 데이터베이스 질의를 넣을 수 있도록 DBMS가 연동 도구를 제공하는 것을 확인한 학생이다. 응용 프로그래머를 위한 모듈이 없다는 말이 틀렸음을 알았다.

    데이터 정의어를 이용하면 개념 스키마를 정의할 수 있으므로 2번이 옳다.

    다음 상황에 대한 트랜잭션(transaction)의 특성은?

    제품의 재고량을 갱신하는 트랜잭션이 커밋(commit) 되기 전에 시스템 장애가 발생했다. 장애 후 데이터베이스는 트랜잭션이 수행한 변경 사항을 모두 취소하였고, 시스템은 장애 이전의 상태로 복구되었다.

    1. 1. 일관성(consistency)
    2. 2. 원자성(atomicity)
    3. 3. 지속성(durability)
    4. 4. 고립성(isolation)

    정답 2번

    🔍 보기별 해설
    1. 일관성은 트랜잭션이 성공적으로 끝나면 데이터베이스가 규칙에 맞는 일관된 상태가 되는 성질이며 변경을 통째로 취소하는 성질을 뜻하지 않으므로 상황에 해당하지 않는다.
    2. 원자성은 트랜잭션의 연산이 모두 수행되거나 하나도 수행되지 않아야 하는 성질이라 커밋 전에 장애가 나 변경 사항을 전부 취소하고 이전 상태로 되돌린 것이 이 성질에 해당한다(정답).
    3. 지속성은 커밋된 트랜잭션의 결과가 장애가 나도 유지되어야 하는 성질이며 이 상황은 커밋 전이므로 유지가 아니라 취소가 이루어져 상황에 해당하지 않는다.
    4. 고립성은 실행 중인 트랜잭션의 중간 결과가 다른 트랜잭션에 보이지 않아야 하는 성질이며 장애 뒤에 변경을 취소한 것과는 관계가 없으므로 상황에 해당하지 않는다.
    🧮 풀이
    1. 甲은 이체 처리 프로그램이 끝나고 나서 계좌 잔액의 합이 규칙에 맞는지 확인하는 검산 담당이다. 처리가 끝난 뒤의 데이터가 규칙을 지키는지 살피는 일이며 도중에 사고가 났을 때 되돌리는 일과는 다르다고 정리했다.
    2. 甲은 재고를 갱신하다가 확정 직전에 서버가 꺼졌는데 재가동한 뒤 갱신 전 재고 수량 그대로인 것을 확인한 관리자다. 반쯤 반영된 상태가 남지 않고 처음 상태로 돌아갔다는 점이 인상 깊었다.
    3. 甲은 주문을 확정한 직후 정전이 나도 주문 내역이 그대로 남아 있는지 시험한 담당자다. 확정된 결과가 사라지지 않아야 하는 성질이며 확정 전에 취소되는 성질과는 반대 방향이라고 구분했다.
    4. 甲은 재고 수정 화면을 두 사람이 동시에 열어 저장 버튼을 누른 상황을 실험한 학생이다. 진행 중에 바뀌는 값이 서로에게 비쳐 보이지 않아야 한다는 성질이며 장애 뒤 취소와는 다르다고 정리했다.

    커밋 전 장애로 변경을 모두 취소하고 이전 상태로 복구하는 것은 모두 수행되거나 전혀 수행되지 않는 원자성이므로 2번이 해당한다.

    3. 3. 현재 수행 중인 트랜잭션을 커밋하면 트랜잭션이 수행한 갱신을 데이터베이스에 영구적으로 반영한다.
    4. 4. 트랜잭션은 데이터베이스 관리 시스템(database management system)에서 데이터를 다루는 논리적인 작업의 단위이다.

    3. 보이스-코드 정규형은 제3정규형보다 엄격하게 함수 종속 관계의 모든 결정자가 후보키가 되도록 요구하는 정규형으로 정의되므로 이 설명은 옳다.
    4. 다치 종속은 BCNF까지 만족한 뒤에도 남을 수 있어 제4정규형에서 다루므로, 제2정규형 이상에서는 고려하지 않아도 된다는 이 설명은 옳지 않다.
    🧮 풀이
    1. 甲은 표의 한 칸에 전화번호 두 개가 쉼표로 함께 들어 있는 것을 발견한 학생이다. 한 칸에는 하나의 값만 넣어야 한다는 원칙을 어겨 첫 단계 정규화를 다시 해야 했다. 같은 원리가 다른 문제에도 나오는지 찾아보았다.

    3. 甲은 모든 결정자가 후보키인지 하나씩 점검하는 실습을 한 학생이다. 후보키가 아닌 결정자가 하나라도 있으면 보이스-코드 정규형이 아니라는 점을 확인했다. 헷갈릴 때는 정의로 돌아가는 것이 가장 빠르다고 느꼈다.
    4. 甲은 한 사원이 여러 자격증과 여러 취미를 갖는 표를 다루며 서로 독립된 다치 값이 섞이는 문제를 발견한 학생이다. 이런 문제는 더 높은 정규형에서 다룬다는 점을 알았다. 이 구분을 나중에 볼 노트에도 한 줄로 옮겨 적었다.

    ㄱ과 ㄷ은 옳고 ㄴ은 이행적 종속 제거가 제3정규형의 조건이며 ㄹ은 다치 종속을 제4정규형에서 다루므로 정답은 2번이다.

    2. 열 이름이 S이고 값이 4인 결과는 별칭 S를 결과의 열 이름으로 착각하고 A 그룹을 4개로 센 것이므로 결과에 해당하지 않는다.

    4. 甲은 합이 아홉인 그룹까지 조건에 맞는다고 센 학생이다. 십을 넘어야 하는데 아홉은 넘지 못한다는 점을 다시 확인하고 개수를 바로잡았다. 그 뒤로는 같은 실수를 하지 않도록 순서를 종이에 적어 두었다.

    인덱스(index)에 대한 설명으로 옳지 않은 것은?

    1. 1. 테이블에서 한 개 이상의 속성을 이용하여 생성한다.
    2. 2. 빠른 검색과 효율적인 레코드 접근을 가능하게 한다.
    3. 3. 희소 인덱스(sparse index)는 그 인덱스가 클러스터링 인덱스인 경우 사용할 수 없다.
    4. 4. 데이터에서 수정, 삭제 등의 변경이 발생하면 인덱스를 재구성할 수 있다.

    2. 인덱스는 원하는 레코드의 위치를 미리 알려 주는 구조라서 전체를 훑지 않고도 빠른 검색과 효율적인 레코드 접근을 가능하게 하므로 이 보기는 옳다.
    3. 희소 인덱스는 일부 검색키 값에만 항목을 두는 인덱스이며 데이터가 검색키 순으로 정렬된 클러스터링 인덱스에서 사용할 수 있으므로, 클러스터링 인덱스에서 사용할 수 없다는 이 보기는 옳지 않다(정답).

    3. 甲은 학번 순으로 정렬되어 저장된 표에서 몇 번째마다 색인 항목을 하나씩만 둔 학생이다. 정렬된 표라서 이렇게 성기게 만들어도 원하는 행을 찾을 수 있었다. 확인한 내용을 발표 자료의 한 장으로 정리해 두었다.
    4. 甲은 대량의 행을 삭제한 뒤 색인의 상태가 나빠진 것을 확인한 학생이다. 색인을 다시 만들어 상태를 회복하는 방법이 있다는 점을 알았다. 스터디 모임에서 이 점을 다시 설명해 보며 익혔다.

    희소 인덱스는 정렬된 데이터 파일의 클러스터링 인덱스에서 쓸 수 있으므로 사용할 수 없다고 한 3번이 옳지 않다.

    다음 뷰(view)에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄴ. 뷰는 데이터 보안 강화, 복잡한 쿼리 단순화를 위해 사용할 수 있다.

    1. 1. ㄱ, ㄴ
    2. 2. ㄱ, ㄷ
    3. 3. ㄴ, ㄷ
    4. 4. ㄱ, ㄴ, ㄷ

    정답 1번

    🔍 보기별 해설

    2. 뷰는 필요한 열만 보이도록 해 데이터 보안을 강화하고 복잡한 질의를 이름 하나로 줄여 단순하게 할 수 있으므로 이 설명은 옳다.
    3. GROUP BY 절로 묶인 뷰의 한 행은 원본의 여러 행이 합쳐진 것이라 그 행을 고쳐도 원본의 어느 행을 고칠지 정할 수 없어 갱신할 수 없으므로, 갱신할 수 있다는 이 설명은 옳지 않다.
    🧮 풀이

    1. TS(Ti) < TS(Tj)이면 요청자 Ti가 더 오래되었으므로 wound-wait 기법에서는 Ti가 Tj를 상처 입혀 Tj를 철회시키고 같은 타임스탬프로 재시작하게 하므로 이 보기는 옳다.
    2. TS(Tj) < TS(Ti)이면 Tj가 더 오래된 잠금 보유자이고 wound-wait 기법에서는 젊은 요청자 Ti가 대기하는 것이지 Tj가 대기하는 것이 아니므로, Tj가 대기한다는 이 보기는 옳지 않다(정답).
    3. TS(Tj) < TS(Ti)이면 Ti가 더 젊은 요청자이므로 wait-die 기법에서는 Ti가 죽어 철회하고 같은 타임스탬프로 재시작하므로 이 보기는 옳다.
    4. TS(Ti) < TS(Tj)이면 Ti가 더 오래된 요청자이므로 wait-die 기법에서는 오래된 Ti가 기다리므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 먼저 시작한 작업이 나중에 시작한 작업이 쥔 자원을 요청하면 나중 작업을 되돌려 자원을 넘겨받는 규칙을 실험한 학생이다. 오래된 쪽이 젊은 쪽을 밀어낸다는 점이 이 방식의 특징이었다.
    2. 甲은 신입 작업이 고참 작업이 쥔 자원을 요구할 때 기다리게 하는 규칙을 실험한 학생이다. 기다리는 쪽이 자원을 쥔 쪽이 아니라 요구하는 젊은 쪽이라는 점을 표로 확인했다.
    3. 甲은 젊은 작업이 오래된 작업의 자원을 요청하면 젊은 작업이 스스로 포기하고 같은 순번으로 다시 시작하는 규칙을 실험한 학생이다. 기다리지 않고 포기하는 것이 특징이었다. 그림으로 그려 보니 머릿속이 한결 또렷해졌다.
    4. 甲은 오래된 작업이 젊은 작업이 쥔 자원을 요청하면 기다리게 하는 규칙을 실험한 학생이다. 오래된 쪽을 기다리게 하는 것이 앞의 방식과 다르다는 점을 정리했다. 틀린 이유를 한 줄로 적어 오답 노트에 넣었다.

    wound-wait에서는 오래된 요청자가 젊은 상대를 철회시키고 젊은 요청자는 기다리므로 Tj가 대기한다고 한 2번이 옳지 않다.

    비트맵 인덱스에 대한 설명으로 옳지 않은 것은?

    1. 1. 한 가지 특정 속성값에 대해 하나의 비트맵 인덱스가 만들어진다.
    2. 2. 릴레이션의 카디널리티가 n 일 경우, 비트맵 인덱스의 크기는 log_2 n 비트이다.
    3. 3. 탐색 키의 중복 비율이 높은 속성을 대상으로 수행되는 질의에 효율적이다.
    4. 4. 다중 키를 가진 질의를 쉽게 처리하기 위해 고안된 특수한 형태의 인덱스이다.

    정답 2번

    🔍 보기별 해설
    1. 비트맵 인덱스는 하나의 속성값마다 별도의 비트 벡터를 하나씩 만들므로 특정 속성값에 대해 하나의 비트맵 인덱스가 만들어진다는 이 보기는 옳다.
    2. 비트맵 인덱스의 각 벡터는 릴레이션의 튜플마다 한 비트씩을 가지므로 릴레이션의 카디널리티가 n이면 벡터의 크기는 n 비트이며 log2 n 비트가 아니므로 이 보기는 옳지 않다(정답).
    3. 비트맵 인덱스는 성별처럼 값의 종류는 적고 중복 비율이 높은 속성에 알맞아 이런 속성을 대상으로 하는 질의에 효율적이므로 이 보기는 옳다.
    4. 비트맵 인덱스는 여러 속성에 걸친 조건을 비트 연산으로 빠르게 조합할 수 있어 다중 키 질의를 쉽게 처리하도록 고안된 특수한 인덱스이므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 남성과 여성 두 값만 있는 열에 색인을 만들려고 값마다 자리 표시를 만든 학생이다. 값 하나마다 하나의 표시열이 만들어진다는 점을 알았다. 같은 원리가 다른 문제에도 나오는지 찾아보았다.
    2. 甲은 레코드가 백 개인 표에서 비트맵 한 줄을 만들어 본 학생이다. 각 레코드가 한 칸씩을 차지해 백 칸이 되지 칠 칸이 되는 것이 아니라는 점을 확인했다. 비슷한 예를 하나 더 만들어 스스로 확인해 보았다.
    3. 甲은 등급이 세 가지뿐인 열에서 비트 조합으로 조건을 처리해 본 학생이다. 값이 자주 중복되는 열에서 효과가 크다는 점이 인상적이었다. 헷갈릴 때는 정의로 돌아가는 것이 가장 빠르다고 느꼈다.
    4. 甲은 성별이 여성이면서 등급이 A인 행을 찾기 위해 두 열의 비트 줄을 겹쳐 본 학생이다. 여러 조건을 비트 연산으로 쉽게 처리하도록 만든 인덱스라는 점을 알았다. 이 구분을 나중에 볼 노트에도 한 줄로 옮겨 적었다.

    비트맵 인덱스는 값마다 비트 벡터를 만들고 그 길이가 레코드 수 n이므로 크기가 log2 n 비트라고 한 2번이 옳지 않다.
