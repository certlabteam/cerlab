    다음에서 설명하는 데이터 마이닝 분석 기법은?

    ○ 장바구니 분석이라고도 한다.

    ○ 데이터 간의 발생 빈도를 분석하여 그 속에 숨겨진 규칙을 파악하는 방법으로, 상품이나 서비스 간의 관계를 분석하여 마케팅에 주로 활용한다.

    1. 1. 분류 분석
    2. 2. 군집 분석
    3. 3. 연관 분석
    4. 4. 회귀 분석

    정답 3번

    🔍 보기별 해설
    1. 분류 분석은 이미 알려진 범주로 새 데이터를 나누는 기법이며 장바구니처럼 함께 나타나는 항목 사이의 규칙을 찾는 기법이 아니므로 설명에 해당하지 않는다.
    2. 군집 분석은 정해진 범주 없이 비슷한 데이터끼리 묶는 기법이며 상품 사이의 발생 빈도로 규칙을 찾는 기법이 아니므로 설명에 해당하지 않는다.
    3. 연관 분석은 데이터 사이의 발생 빈도를 분석해 함께 나타나는 항목의 숨은 규칙을 찾으며 장바구니 분석이라고도 부르고 마케팅에 쓰이므로 설명에 해당한다(정답).
    4. 회귀 분석은 변수들 사이의 관계를 함수로 만들어 값을 예측하는 기법이며 항목이 함께 팔리는 규칙을 찾는 기법이 아니므로 설명에 해당하지 않는다.
    🧮 풀이
    1. 甲은 스팸으로 표시된 메일과 그렇지 않은 메일을 학습해 새 메일이 스팸인지 나누는 프로그램을 만든 학생이다. 미리 정해진 범주로 나누는 이 방식은 상품이 함께 팔리는 규칙을 찾는 방식과 다르다고 설명했다.
    2. 甲은 고객 이천 명을 나이와 구매액이 비슷한 집단으로 묶어 각 집단의 특성을 살펴본 마케팅 담당자다. 정해진 범주 없이 비슷한 것끼리 묶는 이 방식은 함께 사는 상품의 규칙을 찾는 것과 다르다고 정리했다.
    3. 甲은 마트의 영수증 기록을 분석해 기저귀를 사는 사람이 맥주도 함께 사는 경우가 많다는 규칙을 발견한 담당자다. 함께 팔리는 상품의 빈도를 분석해 진열을 바꾸었고 매출이 늘었다.
    4. 甲은 광고비와 매출의 관계를 식으로 만들어 다음 달 매출을 예측한 분석가다. 변수 사이의 관계로 값을 예측하는 이 방식은 함께 팔리는 상품의 규칙을 찾는 것과 다르다는 점을 알았다.

    발생 빈도를 분석해 상품 사이의 규칙을 찾는 장바구니 분석은 연관 분석이므로 3번이 해당한다.

    시스템 카탈로그에 대한 설명으로 옳지 않은 것은?

    1. 1. 데이터 사전(data dictionary)이라고도 한다.
    2. 2. 각 릴레이션의 튜플 수와 블록 수가 저장된다.
    3. 3. 일반 사용자도 시스템 카탈로그에 내용을 추가하거나 수정할 수 있다.
    4. 4. RDBMS마다 서로 다른 형태로 시스템 카탈로그를 제공한다.

    정답 3번

    🔍 보기별 해설
    1. 시스템 카탈로그는 데이터베이스에 저장된 데이터의 구조를 설명하는 정보를 담고 있어 데이터 사전이라고도 부르므로 이 보기는 옳다.
    2. 시스템 카탈로그에는 각 릴레이션의 튜플 수와 블록 수 같은 통계 정보가 저장되어 DBMS가 질의 최적화에 활용하므로 이 보기는 옳다.
    3. 시스템 카탈로그는 DBMS가 스스로 만들고 관리하는 정보라서 일반 사용자가 내용을 추가하거나 수정하면 데이터베이스가 손상될 수 있으므로, 수정할 수 있다는 이 보기는 옳지 않다(정답).
    4. 시스템 카탈로그는 DBMS 제품마다 저장 방식과 테이블 구조가 서로 다른 형태로 제공되어 제품이 달라지면 조회 방법도 달라지므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 데이터베이스에 어떤 테이블이 있고 각 테이블에 열이 몇 개인지를 한곳에서 조회해 본 학생이다. 이런 정보를 모아 둔 곳을 데이터 사전이라고도 부른다는 것을 알게 되었다.
    2. 甲은 질의를 실행하기 전에 DBMS가 테이블의 행 수와 저장 블록 수를 참고해 실행 계획을 세운다는 설명을 들은 학생이다. 이런 통계가 카탈로그에 저장되어 있다는 것을 확인했다.
    3. 甲은 일반 사용자 계정으로 시스템 테이블에 항목을 넣어 보려 했으나 거부당한 학생이다. DBMS가 스스로 관리하는 정보를 사용자가 고칠 수 없게 막아 둔다는 것을 알았다. 그래서 카탈로그 정보는 관리자도 직접 고치지 않는다고 했다.
    4. 甲은 서로 다른 두 종류의 DBMS에서 카탈로그를 조회해 본 학생이다. 같은 정보를 담고 있어도 테이블 이름과 열 구성이 제품마다 다르다는 점을 표로 정리했다. 그래서 제품을 바꾸면 조회 쿼리도 다시 익혀야 한다고 했다.

    시스템 카탈로그는 DBMS가 스스로 생성하고 유지하는 메타데이터이므로 일반 사용자가 수정할 수 있다고 한 3번이 옳지 않다.

    다음에서 설명하는 데이터베이스 무결성 제약조건(integrity constraint)은?

    ○ 기본키 제약(primary key constraint)이라고도 한다.

    ○ 기본키는 널(NULL) 값을 가져서는 안되며 릴레이션 내에 오직 하나의 값만 존재해야 한다.

    1. 1. 개체 무결성 제약조건
    2. 2. 고유 무결성 제약조건
    3. 3. 도메인 무결성 제약조건
    4. 4. 참조 무결성 제약조건

    정답 1번

    🔍 보기별 해설
    1. 개체 무결성 제약조건은 기본키가 NULL 값을 가질 수 없고 릴레이션 안에서 유일해야 한다는 규칙이며 기본키 제약이라고도 하므로 설명에 해당한다(정답).
    2. 고유 무결성 제약조건은 UNIQUE 속성 값이 중복되지 않도록 하는 규칙이며 NULL을 허용할 수 있어 기본키 제약과는 다르므로 설명에 해당하지 않는다.
    3. 도메인 무결성 제약조건은 속성 값이 정해진 도메인 안의 값이어야 한다는 규칙이며 기본키의 유일성과 NULL 금지를 뜻하지 않으므로 설명에 해당하지 않는다.
    4. 참조 무결성 제약조건은 외래키 값이 참조되는 릴레이션의 기본키 값과 일치하거나 NULL이어야 한다는 규칙이며 기본키 자체의 제약이 아니므로 설명에 해당하지 않는다.
    🧮 풀이
    1. 甲은 학생 테이블에 학번이 비어 있는 행을 넣으려다 거부당한 학생이다. 행을 구별하는 열은 값이 비어서도 중복되어서도 안 된다는 규칙 때문이라는 것을 알았다. 그래서 이 열은 비어 있거나 중복되면 행을 구별할 수 없다고 했다.
    2. 甲은 전화번호 열에 중복 값을 넣지 못하도록 제약을 걸었으나 일부 행은 전화번호가 비어 있어도 허용되는 것을 확인한 학생이다. 이 제약은 기본키와 달리 빈 값을 허용한다는 점이 다르다.
    3. 甲은 나이 열에 영보다 작은 값이 들어가지 않도록 범위를 정한 학생이다. 이 규칙은 값이 올 수 있는 범위를 정할 뿐 행을 구별하는 열의 규칙과는 다르다는 점을 정리했다. 결국 이 제약은 열의 값 범위만 정해 준다는 점을 표로 정리했다.
    4. 甲은 주문 테이블에 고객 테이블에 없는 고객 번호를 넣으려다 거부당한 학생이다. 다른 테이블의 값을 참조하는 열의 규칙이라 행을 구별하는 열의 규칙과는 다르다고 설명했다. 결국 이 규칙은 테이블 사이의 연결을 지키는 것이라 기본키와 다르다고 했다.

    기본키 제약이라고도 하며 기본키가 NULL이 될 수 없고 유일해야 하는 제약은 개체 무결성 제약조건이므로 1번이 해당한다.

    데이터베이스 모델에서 사용되는 키(key)에 대한 설명으로 옳지 않은 것은?

    1. 1. 후보키(candidate key)는 유일성과 최소성의 특성을 만족하는 속성 또는 속성들의 집합이다.
    2. 2. 슈퍼키(super key)는 유일성의 특성을 만족하는 속성 또는 속성들의 집합이다.
    3. 3. 대체키(alternate key)는 기본키(primary key)로 선택되지 못한 외래키(foreign key)들이다.
    4. 4. 널(NULL) 값을 가질 수 있는 속성이 포함된 후보키는 기본키로 부적합하다.

    정답 3번

    🔍 보기별 해설
    1. 후보키는 각 튜플을 유일하게 식별하는 유일성과 속성을 빼면 유일성이 깨지는 최소성을 함께 만족하는 속성 집합이므로 이 보기는 옳다.
    2. 슈퍼키는 각 튜플을 유일하게 식별하는 유일성만 만족하면 되고 최소성은 요구하지 않아 불필요한 속성이 들어 있어도 되는 속성 집합이므로 이 보기는 옳다.
    3. 대체키는 후보키 중 기본키로 선택되지 못한 나머지 키이며 다른 릴레이션을 참조하는 외래키와는 다른 개념이므로, 기본키로 선택되지 못한 외래키라는 이 보기는 옳지 않다(정답).
    4. 널 값을 가질 수 있는 속성이 포함된 후보키는 개체 무결성 때문에 기본키로 삼을 수 없어 기본키로 부적합하므로 이 보기는 옳다.
    🧮 풀이
    1. 甲은 학생 테이블에서 학번, 주민번호, 이메일이 모두 학생을 하나로 식별할 수 있음을 확인한 학생이다. 이 중 하나를 기본키로 정하고 나머지를 대체할 수 있는 키로 남겨 둔다는 점을 알았다.
    2. 甲은 학번과 이름을 합친 속성 집합도 학생을 유일하게 식별하는 것을 확인한 학생이다. 그러나 이름을 빼도 유일하므로 최소성이 없어 후보키는 아니고 슈퍼키라고 정리했다. 그래서 최소성이 후보키의 필수 조건임을 다시 확인했다.
    3. 甲은 주문 테이블의 고객번호가 고객 테이블을 참조하는 열임을 확인한 학생이다. 이렇게 다른 테이블을 참조하는 열은 외래키이며 기본키에서 밀려난 후보키와는 다르다는 것을 알았다.
    4. 甲은 이메일이 비어 있는 학생이 있는 테이블에서 이메일을 기본키로 삼으려던 학생이다. 기본키는 값이 비면 안 되어 이 후보키는 기본키로 쓸 수 없다는 점을 알고 학번으로 바꾸었다.

    대체키는 기본키로 선택되지 못한 후보키이지 외래키가 아니므로 3번이 옳지 않다.

    릴레이션 R1, R2, R3의 스키마는 R1(A, B, C), R2(C, D, E), R3(E, F)이고, 기본키는 각각 A, C, E이다. 튜플의 수가 R1은 100개, R2는 150개, R3은 75개라고 할 때, R1 ⋈N R2 ⋈N R3의 결과에 대한 설명으로 옳은 것만을 모두 고르면?

    ㄱ. R1 ⋈N (R2 ⋈N R3)의 결과와 동일하다.

    ㄴ. 결과 릴레이션의 튜플은 최대 100개이다.

    ㄷ. 결과 릴레이션의 속성은 8개이다.

    1. 1. ㄱ
    2. 2. ㄴ
    3. 3. ㄱ, ㄴ
    4. 4. ㄱ, ㄴ, ㄷ

    정답 3번

    🔍 보기별 해설
    1. 자연 조인은 결합 법칙이 성립해 R1 ⋈ R2 ⋈ R3의 결과가 R1 ⋈ (R2 ⋈ R3)의 결과와 같으므로 이 설명은 옳다.
    2. C가 R2의 기본키이고 E가 R3의 기본키라서 R1의 각 튜플은 R2의 튜플 최대 하나와, R2의 튜플은 R3의 튜플 최대 하나와 맞아 결과의 튜플은 최대 R1의 100개이므로 이 설명은 옳다.
    3. 결과 릴레이션의 속성은 공통 속성 C와 E를 한 번씩만 나타내 A, B, C, D, E, F의 6개이므로 8개라는 이 설명은 옳지 않다.
    🧮 풀이
    1. 甲은 세 테이블을 순서를 바꿔 가며 조인해 본 학생이다. 묶는 순서를 달리해도 결과 튜플이 같은 것을 확인하고 조인의 결합 법칙이 성립한다는 것을 알았다. 그래서 어떤 순서로 묶어도 같은 결과라는 점이 편했다.
    2. 甲은 기본키로 연결된 세 테이블을 조인해 결과 행의 수를 세어 본 학생이다. 기본키 값은 한 번만 나타나므로 첫 테이블의 행 수를 넘지 않는다는 점이 이해되었다. 결국 결과 행의 상한이 첫 테이블 행 수라는 것을 알았다.
    3. 甲은 세 릴레이션의 속성 수를 모두 더해 여덟 개라고 답한 학생이다. 자연 조인은 같은 이름의 속성을 한 번만 남긴다는 점을 놓쳤음을 알고 고쳤다. 그래서 계산할 때 공통 속성이 몇 번 나타나는지 먼저 세기로 했다.

    SQL에서 다음 상품 테이블에 대한 ANY와 ALL 연산의 결과로 옳지 않은 것은?

    1. 1. ‘40000 = ANY (SELECT 가격 FROM 상품)’은 참이다.
    2. 2. ‘40000 <> ANY (SELECT 가격 FROM 상품)’은 참이다.
    3. 3. ‘30000 <> ALL (SELECT 가격 FROM 상품)’은 참이다.
    4. 4. ‘30000 > ALL (SELECT 가격 FROM 상품)’은 거짓이다.

    정답 3번

    🔍 보기별 해설
    1. 가격 집합에 40000이 있으므로 40000 = ANY (25000, 30000, 40000)은 하나라도 같으면 참이어서 이 설명은 옳다.
    2. 40000과 다른 값인 25000이 집합에 있어 40000 <> ANY는 하나라도 다르면 참이라는 조건이 성립하므로 이 설명은 옳다.
    3. 집합에 30000이 들어 있으므로 30000 <> ALL은 모든 값과 달라야 참인데 30000과 같은 값이 있어 거짓이므로, 참이라는 이 설명은 옳지 않다(정답).
    4. 집합에 40000이 있어 30000이 모든 값보다 크다는 조건이 성립하지 않으므로 30000 > ALL은 거짓이라는 이 설명은 옳다.
    🧮 풀이
    1. 甲은 상품 가격 중 하나라도 사만 원과 같은지 묻는 질의를 실행한 학생이다. 사만 원이 집합에 있어 참이 나오는 것을 확인하고 어느 하나라도 만족하면 되는 연산임을 알았다.
    2. 甲은 사만 원과 다른 가격이 하나라도 있는지 묻는 질의를 실행한 학생이다. 이만 오천 원이 있어 참이 되는 것을 보고 하나라도 다르면 참이라는 규칙을 익혔다. 그래서 하나라도 다르면 참인 조건임을 표로 적어 두었다.
    3. 甲은 삼만 원이 모든 가격과 다른지 묻는 질의를 실행한 학생이다. 삼만 원과 같은 가격이 하나 있어 거짓이 나오는 것을 보고 모두 달라야 참이라는 규칙을 이해했다. 그래서 모두 다를 때만 참인 조건이라고 정리해 두었다.
    4. 甲은 상품 가격 중 가장 높은 값과 삼만 원을 견주어 본 학생이다. 사만 원이 있어 삼만 원이 모든 값을 넘지 못하므로 조건이 거짓이 되는 이유를 규칙으로 확인했다. 그래서 모두를 넘을 때만 참인 조건이라고 정리해 두었다.

    30000은 상품 가격 집합에 있으므로 30000 <> ALL은 거짓이며 참이라고 한 3번이 옳지 않다.

    2. 역정규화는 조인을 줄여 조회를 빠르게 하는 것이 목적이며 중복 때문에 갱신 성능이 나빠지므로, 갱신 시간이 중요한 연산을 지원한다는 이 보기는 옳지 않다(정답).

    4. 조인이 느린 질의는 결합 결과를 미리 테이블로 저장해 두면 조회할 때 조인 없이 바로 읽을 수 있어 검색 시간이 줄어들므로 이 보기는 옳다.

    관계형 데이터베이스의 릴레이션에 대한 특성으로 옳지 않은 것은?

    2. 2. 릴레이션의 투플에 저장되는 값의 집합을 도메인(domain)이라 한다.

    2. 도메인은 한 속성이 가질 수 있는 값의 집합이며 투플에 실제로 저장된 값들의 집합이 아니므로, 투플에 저장되는 값의 집합을 도메인이라 한다는 이 보기는 옳지 않다(정답).

    4. 릴레이션의 속성은 이름으로 서로 구별하므로 하나의 릴레이션에 같은 이름의 속성이 둘 이상 있을 수 없어 이름이 겹치지 않는다는 이 보기는 옳다.
    🧮 풀이
    1. 甲은 학생 테이블에 같은 학번과 같은 이름의 행을 또 넣으려다 거부당한 학생이다. 릴레이션은 집합이라 같은 튜플이 둘 있을 수 없다는 점을 알게 되었다. 릴레이션이 튜플의 집합이기 때문이다.
    2. 甲은 성별 열에 남성과 여성 두 값만 들어갈 수 있도록 정한 학생이다. 그 열에 실제로 저장된 값이 아니라 저장될 수 있는 값의 집합이 도메인이라는 점을 알았다. 성별 열의 도메인은 남성과 여성 둘이다.
    3. 甲은 같은 학생 행들을 순서만 바꾸어 다시 저장해 본 학생이다. 튜플의 순서는 의미가 없어서 두 릴레이션이 같은 것으로 취급된다는 점을 확인했다. 순서를 바꿔도 같은 릴레이션이다.
    4. 甲은 한 테이블에 이름이라는 열을 두 개 만들려다 오류를 만난 학생이다. 속성은 이름으로 구별하므로 같은 이름의 속성을 둘 수 없다는 점을 알았다. 속성은 이름으로 서로 구별하기 때문이다.

    도메인은 한 속성이 가질 수 있는 값의 집합이지 투플에 저장된 값의 집합이 아니므로 2번이 옳지 않다.

    데이터베이스 및 DBMS에 대한 설명으로 옳은 것은?

    1. 1. 개념적 데이터 모델(conceptual data model)은 데이터가 컴퓨터의 저장 장치에 어떻게 저장되는가에 대한 세부 사항을 명시하는 개념을 제공한다.
    2. 2. 데이터 정의어(DDL)를 이용하면 개념 스키마를 정의할 수 있다.
    3. 3. 데이터 조작어(DML)는 무결성 제약 조건을 정의하는 명령어를 포함한다.
    4. 4. DBMS는 데이터베이스 관리자나 일반 사용자가 아닌 응용 프로그래머를 위한 모듈은 제공하지 않는다.

    정답 2번

    🔍 보기별 해설
    1. 개념적 데이터 모델은 사용자가 이해하기 쉬운 개념을 제공하며 저장 장치에 저장하는 세부 사항을 명시하는 것은 물리적 데이터 모델이므로 이 보기는 옳지 않다.
    2. 데이터 정의어(DDL)는 테이블 구조와 제약조건을 정의하는 명령이므로 이를 이용하면 개념 스키마를 정의할 수 있어 이 보기는 옳다(정답).
    3. 무결성 제약 조건을 정의하는 명령은 데이터 정의어에 포함되며 데이터 조작어는 데이터를 검색하고 삽입·삭제·수정하는 명령이므로 이 보기는 옳지 않다.
    4. DBMS는 관리자와 일반 사용자뿐 아니라 응용 프로그래머를 위한 프로그래밍 언어 연동 모듈도 제공하므로 이 보기는 옳지 않다.
    🧮 풀이
    1. 甲은 데이터 모델이 데이터가 디스크에 어떻게 저장되는지를 자세히 규정한다고 생각한 학생이다. 저장 방식은 물리적 모델의 몫이고 개념적 모델은 사용자 관점의 개념이라는 점을 알게 되었다.
    2. 甲은 테이블을 만들고 열의 자료형과 기본키를 정의하는 명령을 실행한 학생이다. 이런 정의 명령이 조직 전체 구조를 나타내는 개념 스키마를 만드는 것이라는 점을 알았다. 테이블을 만드는 CREATE 문이 그것이다.
    3. 甲은 무결성 제약을 정의하는 명령을 조작어라고 여겼던 학생이다. 제약도 구조의 일부라 정의어로 작성한다는 점을 조교가 짚어 주었다. 무결성 제약도 구조의 일부라 정의어로 적는다.
    4. 甲은 개발자가 응용 프로그램에 데이터베이스 질의를 넣을 수 있도록 DBMS가 연동 도구를 제공하는 것을 확인한 학생이다. 응용 프로그래머를 위한 모듈이 없다는 말이 틀렸음을 알았다.

    데이터 정의어를 이용하면 개념 스키마를 정의할 수 있으므로 2번이 옳다.

    🧮 풀이
    1. 甲은 학원생 명단에서 전화번호가 겹치는 학생이 있는지 확인한 학생이다. 네 명의 전화번호가 모두 달라 한 명씩을 정확히 구별할 수 있다는 점을 알았다. 네 명의 전화번호가 모두 서로 다르다.
    2. 甲은 이름으로 학원생을 찾으려다 홍길동이라는 이름이 두 명이라 구별이 안 된다는 것을 발견한 학생이다. 이름은 학원생을 유일하게 식별하지 못한다는 점을 알았다. 명단에 홍길동이 두 명 있었다.
    3. 甲은 전화번호와 학년을 함께 묶어 학원생을 식별하려던 학생이다. 전화번호만으로 이미 유일하므로 학년을 덧붙이는 것은 불필요해 최소성이 없다는 점을 알았다. 전화번호 하나만으로 이미 유일하다.
    4. 甲은 학년과 반의 조합으로 학원생을 식별하려던 학생이다. 학년 3, 반 1인 학생이 두 명 있어 중복이 생긴다는 점을 표에서 확인하고 후보키가 아님을 알았다. 학년 3 반 1 인 학생이 두 명이다.
