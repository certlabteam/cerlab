    네트워크 계층에서 스니핑 시스템을 네트워크에 존재하는 또 다른 라우터라고 알림으로써 패킷의 흐름을 바꾸는 공격은?

    1. 1. DNS 스푸핑 공격
    2. 2. E-mail 스푸핑 공격
    3. 3. IP 스푸핑 공격
    4. 4. ICMP 리다이렉트 공격

    정답 4번

    🔍 보기별 해설
    1. DNS 스푸핑은 조작된 DNS 응답으로 도메인을 공격자가 원하는 IP에 연결시키는 공격이며, 자신을 다른 라우터로 알려 패킷 경로를 바꾸는 공격은 아니므로 옳지 않다.
    2. E-mail 스푸핑은 전자우편의 발신자 주소 등을 위조하여 정상 사용자가 보낸 것처럼 속이는 공격이며, 네트워크의 라우팅 경로를 변경하는 공격은 아니므로 옳지 않다.
    3. IP 스푸핑은 패킷의 출발지 IP 주소를 다른 호스트의 주소로 위조하는 공격이며, 라우터 정보를 보내 호스트의 패킷 경로를 바꾸는 공격은 아니므로 옳지 않다.
    4. ICMP Redirect는 더 적절한 라우터가 있다고 호스트에 알려 경로를 변경시키므로, 이를 위조하면 스니핑 장비 쪽으로 패킷을 유도할 수 있어 옳다(정답).
    🧮 풀이
    1. 甲이 사용자의 DNS 질의보다 먼저 위조된 응답을 보내 정상 은행 도메인에 공격자 서버의 IP 주소를 연결하자, 사용자는 주소를 정확히 입력하고도 가짜 은행 사이트로 접속했다.
    2. 甲이 피싱 메일을 보내면서 From 항목을 회사 대표의 정상 메일 주소처럼 위조하자, 수신자는 실제 대표가 보낸 업무 요청으로 착각해 첨부된 문서를 열려고 했다.
    3. 甲이 자신이 만든 IP 패킷의 출발지 주소를 신뢰받는 내부 서버의 주소로 바꾸어 전송하자, 수신 장비는 패킷 헤더만 보고 해당 내부 서버에서 온 통신처럼 인식했다.
    4. 甲이 피해 호스트에 위조한 ICMP Redirect 메시지를 보내 자신이 연결된 장비를 더 적절한 라우터라고 알리자, 이후 피해 호스트의 패킷이 공격자의 스니핑 장비를 거쳐 전달됐다.

    위조한 라우팅 안내로 호스트의 패킷 경로를 공격자 쪽으로 변경해 스니핑하는 방식은 ICMP Redirect 공격이다.

    다음과 같이 각 문자에 숫자를 배정할 때, 시저 암호 치환식 C ＝ (P ＋ 3) mod 26을 활용하여 평문 STUDY를 암호화한 것은? (단, 치환식에서 C는 암호문, P는 평문이다)

    1. 1. VWXGB
    2. 2. UVWFA
    3. 3. TUVEZ
    4. 4. VWXFN

    정답 1번

    🔍 보기별 해설
    1. S는 18이라 21인 V, T는 19라 22인 W, U는 20이라 23인 X, D는 3이라 6인 G, Y는 24라 27을 26으로 나눈 나머지 1인 B가 되므로 옳다(정답).
    2. UVWFA는 각 문자를 두 칸씩만 민 결과라, 치환식이 더하라고 정한 값 3이 아니라 2를 적용한 것이어서 옳지 않다.
    3. TUVEZ는 각 문자를 한 칸씩만 민 결과여서, 배정 숫자에 3을 더하라는 치환식을 전혀 따르지 않았으므로 옳지 않다.
    4. VWXFN은 앞 세 글자는 맞지만 D와 Y를 잘못 옮겨, 마지막 글자에서 26으로 나눈 나머지를 구하지 않았으므로 옳지 않다.
    🧮 풀이
    1. 甲이 배정표에서 S가 18인 것을 확인하고 3을 더해 21을 얻은 뒤, 다시 표에서 21에 해당하는 글자가 V임을 찾아 첫 글자를 옮겨 적고 같은 방법으로 나머지 네 글자도 차례로 바꾸어 나갔다.
    2. 甲이 급한 마음에 각 글자를 두 칸씩만 밀어 UVWFA를 적었다가, 문제에 적힌 치환식의 더할 값이 2가 아니라 3인 것을 다시 읽고 적어 둔 답을 지운 뒤 처음부터 다시 계산했다.
    3. 甲이 알파벳 순서대로 한 칸씩만 옮겨 TUVEZ를 만든 뒤 평문 STUDY와 나란히 견주어 보니, 세 칸을 밀어야 한다는 조건을 아예 빠뜨린 채 옮겨 적었다는 것을 알아차렸다.
    4. 甲이 마지막 글자 Y에 3을 더해 27을 얻고 그대로 두려다가, 배정표의 숫자가 25에서 끝나는 것을 보고 26으로 나눈 나머지 1을 구해 그 자리 글자인 B로 바로잡아 적었다.

    시저 암호는 각 문자의 배정 숫자에 3을 더하고 26으로 나눈 나머지를 다시 문자로 바꾸므로 STUDY는 VWXGB가 된다.

    SSL Handshake 프로토콜의 2단계 ‘서버 인증과 키 교환(server authentication and key exchange)’에서 인증서(certificate) 메시지가 사용되지 않는 기법은?

    1. 1. RSA 기법
    2. 2. Anonymous DH 기법
    3. 3. Ephermeral DH 기법
    4. 4. Fixed DH 기법

    정답 2번

    🔍 보기별 해설
    1. RSA 방식의 서버 인증에서는 서버가 자신의 RSA 공개키가 담긴 인증서를 클라이언트에 제시하여 신원을 증명해야 하므로 Certificate 메시지가 사용되어 옳지 않다.
    2. Anonymous DH는 서버와 클라이언트가 인증 없이 Diffie-Hellman 값을 교환하므로 서버 인증서가 필요하지 않아 Certificate 메시지가 사용되지 않으므로 옳다(정답).
    3. Ephemeral DH는 서버가 임시 DH 공개값을 인증하기 위해 인증서의 공개키로 서명하므로 서버의 Certificate 메시지가 사용되어 옳지 않다.
    4. Fixed DH는 서버 인증서 자체에 고정된 Diffie-Hellman 공개키가 포함되므로 서버가 해당 인증서를 전달하는 Certificate 메시지가 사용되어 옳지 않다.
    🧮 풀이
    1. 甲이 RSA 방식으로 SSL 서버에 접속하자 서버가 RSA 공개키와 신원 정보가 들어 있는 인증서를 Certificate 메시지로 보내왔고, 甲은 인증기관의 서명을 검증한 뒤 연결을 계속했다.
    2. 甲이 Anonymous DH 방식의 SSL 연결을 시험하자 서버는 인증서를 보내지 않고 DH 공개값만 교환했으며, 양쪽은 이를 이용해 공유 비밀을 계산했지만 서버 신원은 별도로 인증하지 않았다.
    3. 甲이 Ephemeral DH 방식으로 서버에 접속하자 서버가 일회성 DH 공개값을 보내면서 인증서의 공개키에 대응하는 개인키로 서명했고, 甲은 받은 인증서로 그 서명을 검증했다.
    4. 甲이 Fixed DH 방식의 서버와 SSL 연결을 시작하자 서버가 고정된 DH 공개키가 포함된 인증서를 보내왔고, 甲은 인증기관의 서명을 확인한 뒤 그 공개키로 키 교환을 진행했다.

    SSL 서버 인증·키 교환에서 RSA·Ephemeral DH·Fixed DH는 인증서를 사용하지만 Anonymous DH는 인증서를 사용하지 않는다.

    전자 서명(digital signature)에 대한 설명으로 옳지 않은 것은?

    1. 1. 서명된 문서는 기밀성이 보장된다.
    2. 2. 서명된 문서는 데이터가 변조되지 않았음을 보장하는 무결성을 만족한다.
    3. 3. 한 번 생성된 서명을 다른 문서의 서명으로 사용할 수 없다.
    4. 4. 전자 서명과 관련된 표준으로 DSS가 있다.

    정답 1번

    🔍 보기별 해설
    1. 전자 서명은 서명자 인증과 문서의 무결성 및 부인 방지를 제공하지만 문서 내용을 암호화하는 기능은 아니므로 기밀성이 보장된다는 설명은 옳지 않다(정답).
    2. 전자 서명은 문서의 해시값 등을 이용하여 생성되므로 서명 후 문서 내용이 변경되면 검증 결과가 달라져 변조 여부를 확인할 수 있으므로 옳다.
    3. 전자 서명은 해당 문서에서 계산한 해시값을 바탕으로 생성되므로 다른 문서는 해시값이 달라 기존에 생성한 서명을 그대로 사용할 수 없으므로 옳다.
    4. DSS는 미국 NIST가 제정한 전자 서명 관련 표준으로, 전자 서명의 생성과 검증에 사용할 알고리즘 등을 규정하고 있으므로 옳다.
    🧮 풀이
    1. 甲이 계약서에 자신의 개인키로 전자 서명을 붙여 乙에게 전송했지만 문서 자체에는 별도의 암호화를 적용하지 않았다. 전송 과정에서 파일을 확보한 사람이 계약서 내용을 그대로 읽을 수 있었고, 乙은 서명 검증을 통해 작성자와 변조 여부만 확인했다.
    2. 甲이 전자 서명된 계약서를 받은 뒤 시험 삼아 계약 금액의 숫자 하나를 변경했다. 乙이 공개키를 이용해 서명을 검증하자 현재 문서에서 계산한 해시값과 서명에 대응하는 값이 일치하지 않았고, 서명 이후 문서 내용이 바뀌었다는 사실이 드러났다.
    3. 甲이 첫 번째 계약서에 생성한 전자 서명을 내용이 다른 두 번째 계약서에 그대로 붙여 乙에게 전달했다. 乙이 두 번째 문서에서 새로 계산한 해시값을 이용해 검증하자 원래 서명이 만들어질 때의 값과 일치하지 않아 서명 검증이 실패했다.
    4. 甲이 전자 서명 기능을 갖춘 보안 프로그램을 개발하면서 관련 표준 문서를 조사했다. 미국 NIST가 마련한 DSS에서 전자 서명의 생성과 검증에 이용할 알고리즘과 처리 기준을 확인한 뒤 그 규격에 맞추어 프로그램의 서명 기능을 구현했다.

    전자 서명은 인증·무결성·부인 방지를 제공하지만 문서 내용을 숨기는 암호화 기능이 아니므로 기밀성을 직접 보장하지 않는다.

    NAC(Network Access Control) 시스템에 대한 설명으로 옳지 않은 것은?

    1. 1. ARP 방식은 차단하려는 단말에 ARP 스푸핑 패킷을 보내 네트워크 접근을 제어한다.
    2. 2. 802.1x 방식은 802.1x RADIUS 서버와 802.1x를 지원하는 스위치가 필요하다.
    3. 3. 소프트웨어 에이전트 설치 방식은 네트워크에 접속하려는 모든 클라이언트에 에이전트를 설치할 필요는 없다.
    4. 4. VLAN 방식은 인가받지 않은 클라이언트가 인가된 클라이언트와는 다른 별도의 VLAN으로 격리된다.

    정답 3번

    🔍 보기별 해설
    1. ARP 방식 NAC는 차단 대상 단말에 위조된 ARP 정보를 보내 정상적인 게이트웨이 통신을 방해하는 방식으로 네트워크 접근을 통제하므로 옳다.
    2. 802.1X 방식 NAC는 포트 기반 접근제어를 위해 802.1X를 지원하는 스위치와 인증을 처리할 RADIUS 서버가 필요하므로 옳다.
    3. 에이전트 설치 방식은 단말의 보안 상태를 검사하기 위해 접속하려는 각 클라이언트에 에이전트를 설치해야 하므로, 설치가 불필요하다는 설명은 옳지 않다(정답).
    4. VLAN 방식 NAC는 인증되지 않았거나 보안 정책을 만족하지 못한 단말을 정상 사용자와 다른 VLAN으로 분리해 접근 범위를 제한하므로 옳다.
    🧮 풀이
    1. 甲이 NAC에서 접속이 금지된 노트북을 발견하자 해당 단말에 게이트웨이의 MAC 주소를 위조한 ARP 정보를 반복해서 보내 정상적인 게이트웨이 통신을 하지 못하도록 차단했다.
    2. 甲이 사내 유선망에 802.1X 기반 NAC를 구축하면서 802.1X를 지원하는 스위치와 RADIUS 인증 서버를 연결하자, 인증을 통과한 단말만 스위치 포트를 통해 업무망에 접속했다.
    3. 甲이 에이전트 방식 NAC를 도입한 뒤 업무망에 접속할 직원 PC마다 검사 프로그램을 설치하자, 에이전트가 백신과 보안 패치 상태를 확인한 후 기준을 충족한 단말만 접속을 허용했다.
    4. 甲이 보안 패치가 되지 않은 노트북으로 사내망에 접속하자 NAC가 정상 업무용 VLAN 대신 격리 VLAN을 배정했고, 해당 단말은 업데이트 서버 외의 내부 시스템에는 접근하지 못했다.

    NAC는 ARP·802.1X·에이전트·VLAN 방식 등으로 접근을 통제하며 에이전트 방식은 각 접속 단말에 에이전트 설치가 필요하다.

    IPSec에 대한 설명으로 옳지 않은 것은?

    1. 1. 네트워크 계층에서 동작하는 보안 프로토콜이다.
    2. 2. 트래픽을 암호화하고, 무결성을 보장하며, 인증을 제공한다.
    3. 3. 전송 모드와 터널 모드가 있다.
    4. 4. IPSec에서 AH 프로토콜은 페이로드 데이터를 암호화한다.

    정답 4번

    🔍 보기별 해설

    2. 2. 시간 동기화 방식

    S/KEY는 비밀키에 해시 함수를 반복 적용해 만든 해시 체인의 값을 역순으로 사용하여 매 인증마다 다른 일회용 비밀번호를 제공한다.

    WPA(Wi-Fi Protected Access)에 대한 설명으로 옳지 않은 것은?

    1. 1. WPA는 WEP의 보안 취약점을 보완하기 위해 제안되었다.
    2. 2. WPA의 TKIP는 암호 알고리즘으로 AES를 사용한다.
    3. 3. WPA-EAP는 인증을 위해서 RADIUS 서버를 이용할 수 있다.
    4. 4. WPA-PSK는 사전에 공유된 비밀키를 사용한다.

    정답 2번

    🔍 보기별 해설
    1. WPA는 기존 WEP의 취약한 암호화와 키 관리 문제를 개선하기 위해 제안된 무선 랜 보안 규격이므로 WEP의 보완 기술이라는 설명은 옳다.
    2. WPA의 TKIP는 기존 장비와의 호환을 위해 RC4를 기반으로 사용하며, AES를 암호 알고리즘으로 사용한다고 한 부분은 옳지 않다(정답).
    3. WPA-EAP는 기업 환경에서 802.1X 인증과 연계하며, 사용자 인증 정보를 확인하는 인증 서버로 RADIUS를 이용할 수 있으므로 옳다.
    4. WPA-PSK는 별도의 인증 서버 없이 AP와 접속 단말이 미리 정해 둔 비밀키를 공유하여 무선 네트워크 인증에 사용하는 방식이므로 옳다.
    🧮 풀이
    1. 甲이 오래된 WEP 무선망에서 키 재사용과 취약한 암호화 문제가 발견되자 장비를 WPA로 전환했고, TKIP의 동적 키 관리 기능을 이용해 기존 WEP보다 강화된 보안을 적용했다.
    2. 甲이 WPA가 적용된 구형 무선 AP의 TKIP 패킷을 분석하자 AES가 아니라 RC4 기반 암호화가 사용되고 있었고, 패킷마다 키를 변화시키는 방식으로 WEP의 약점을 보완하고 있었다.
    3. 甲이 회사 무선망을 WPA-EAP 방식으로 구성하자 직원의 접속 요청이 RADIUS 서버로 전달됐고, 서버가 계정 정보를 확인해 인증에 성공한 직원에게 무선 접속을 허용했다.
    4. 甲이 소규모 사무실의 무선 AP에 WPA-PSK를 설정하고 직원 노트북에도 같은 사전 공유 비밀키를 입력하자, 별도의 RADIUS 서버 없이 무선망 인증과 접속이 이루어졌다.

    WPA는 WEP의 취약점을 보완하며 TKIP는 AES가 아닌 RC4 기반이고, WPA-EAP는 RADIUS를, WPA-PSK는 사전 공유키를 이용한다.

    DoS 공격 방식에 대한 설명으로 옳지 않은 것은?

    1. 1. 스머프(Smurf) 공격은 발신지 주소가 거짓으로 조작된 ICMP 패킷을 받은 네트워크의 많은 컴퓨터들이 발신지 주소로 응답을 보내게 하여 트래픽 범람을 일으키는 것이다.
    2. 2. 티어드롭(Teardrop) 공격은 IP 패킷 헤더 정보를 조작해서 패킷 조각(fragment)이 중첩되도록 보내어 이를 전달받은 시스템의 IP 패킷 재조합 과정에서 오류를 발생시킨다.
    3. 3. 슬로로리스(Slowloris) 공격은 HTTP 메시지 헤더의 Content-Length 필드에 임의의 큰 값을 설정하여 웹 서버가 클라이언트에서 해당 크기의 메시지를 전송할 때까지 연결을 유지하게 함으로써 정상적인 사용자의 접속을 받아들일 수 없게 하는 것이다.
    4. 4. HTTP GET 플러딩 공격은 정상적인 TCP 세션과 함께 정상적으로 보이는 과도한 HTTP GET을 요청받은 웹 서버에 과부하가 걸리게 한다.

    정답 3번

    🔍 보기별 해설
    1. 스머프 공격은 피해자의 IP로 출발지를 위조한 ICMP 요청을 브로드캐스트하여 여러 호스트의 응답을 피해자에게 집중시키는 DoS 공격이므로 옳다.
    2. 티어드롭은 IP 단편의 오프셋 등을 조작해 단편들이 서로 중첩되도록 보내고 수신 시스템의 패킷 재조립 과정에서 오류를 일으키므로 옳다.
    3. Content-Length를 크게 설정하고 본문을 천천히 보내 연결을 유지하는 것은 RUDY 공격이며, 이를 Slowloris라고 한 부분은 옳지 않다(정답).
    4. HTTP GET 플러딩은 정상 TCP 연결을 맺은 뒤 대량의 GET 요청을 보내 웹서버의 처리 자원을 소모시켜 서비스를 방해하므로 옳다.
    🧮 풀이
    1. 甲이 피해 서버의 IP를 출발지로 위조한 ICMP Echo Request를 브로드캐스트 주소로 보내자, 네트워크의 여러 호스트가 피해 서버에 Echo Reply를 한꺼번에 보내 트래픽이 폭증했다.
    2. 甲이 IP 단편의 Fragment Offset 값을 조작해 서로 겹치는 조각들을 취약한 서버에 보내자, 서버가 원래 데이터그램으로 재조립하는 과정에서 중첩된 단편 때문에 오류를 일으켰다.
    3. 甲이 웹서버에 큰 Content-Length를 적은 POST 요청을 보낸 뒤 본문 데이터를 아주 조금씩 전송하자, 서버는 본문이 모두 오기를 기다리며 연결을 계속 유지해 가용 연결이 줄어들었다.
    4. 甲이 웹서버와 정상적으로 TCP 연결을 맺은 여러 단말에서 실제 페이지를 요청하는 것처럼 대량의 HTTP GET을 계속 보내자, 서버 처리량이 한계에 이르러 정상 요청까지 지연됐다.

    Slowloris는 불완전한 HTTP 헤더를 천천히 보내며, 큰 Content-Length와 느린 본문 전송을 이용하는 RUDY와 구별해야 한다.

    4. Telnet은 원격 호스트에 접속하여 명령을 수행하는 터미널 서비스를 제공하는 응용계층 프로토콜이며, 하위 계층에서는 TCP를 이용하므로 옳다.

    1. 甲이 외부에서 회사 서버를 관리해야 하자 평문으로 정보를 보내는 Telnet 대신 SSH로 접속했다. 같은 네트워크의 공격자가 패킷을 수집했지만 로그인 비밀번호와 관리 명령이 암호화되어 있어 실제 내용을 그대로 읽어 내지 못했다.
    2. 甲이 인터넷 쇼핑몰에서 카드 정보를 입력하기 전에 주소창의 HTTPS 연결 상태를 확인했다. 브라우저와 웹 서버 사이의 통신이 TLS로 암호화되어 같은 무선망에서 누군가 패킷을 가로채더라도 입력한 카드 번호를 평문으로 확인하기 어려웠다.
    3. 甲이 사무실의 여러 컴퓨터를 스위치 대신 더미 허브에 연결한 뒤 패킷 분석기를 실행했다. 한 컴퓨터가 보낸 프레임이 허브의 다른 모든 포트로도 전달되어 공격용 컴퓨터에서 다른 직원들의 네트워크 트래픽까지 쉽게 수집되었다.
    4. 甲이 외부 거래처의 乙에게 기밀 자료를 이메일로 보내기 전에 S/MIME을 적용해 메시지를 암호화했다. 전송 경로에서 공격자가 메일 데이터를 가로채더라도 乙의 개인키가 없으면 암호화된 본문 내용을 그대로 읽을 수 없었다.

    스니핑 방어에는 SSH·HTTPS·S/MIME과 같은 암호화가 효과적이며 더미 허브 사용은 오히려 도청 위험을 높인다.

    블록체인에서 보유한 자산에 대한 지분율에 비례하여 의사결정 권한을 주는 합의 알고리즘은?

    1. 1. PoS(Proof of Stake)
    2. 2. PoW(Proof of Work)
    3. 3. PRNG(Pseudo-Random Number Generator)
    4. 4. PBFT(Practical Byzantine Fault Tolerance)

    정답 1번

    🔍 보기별 해설
    1. PoS는 검증자가 보유하거나 예치한 자산의 지분을 기준으로 블록 생성과 검증 등 합의 과정의 참여 권한을 부여하는 알고리즘이므로 옳다(정답).
    2. PoW는 참여자가 계산 작업을 수행하여 먼저 유효한 해시값을 찾는 연산 능력을 기준으로 합의에 참여하며, 보유 자산의 지분율을 기준으로 하지 않으므로 옳지 않다.
    3. PRNG는 초기값을 바탕으로 난수처럼 보이는 수열을 생성하는 알고리즘이며, 보유 자산의 지분에 따라 블록체인의 의사결정 권한을 주는 합의 방식은 아니므로 옳지 않다.
    4. PBFT는 여러 노드가 메시지를 교환하고 일정 비율 이상의 합의로 결과를 확정하는 방식이며, 보유 자산의 지분율에 비례해 권한을 주는 방식은 아니므로 옳지 않다.
    🧮 풀이
    1. 甲이 블록체인 검증에 참여하려고 자신이 가진 코인을 네트워크에 예치하자, 예치한 지분을 기준으로 블록 검증에 참여할 기회가 주어지고 올바른 검증에 대한 보상을 받았다.
    2. 甲이 PoW 블록체인에서 새 블록을 만들기 위해 컴퓨터로 nonce 값을 계속 바꾸며 해시 계산을 반복하자, 목표값보다 작은 유효 해시를 먼저 찾은 채굴자가 블록을 제안했다.
    3. 甲이 프로그램에서 시드 값을 PRNG에 입력하자 겉으로는 무작위처럼 보이는 숫자들이 연속해서 생성됐지만, 그 결과가 코인 보유량에 따른 블록 검증 권한으로 이어지지는 않았다.
    4. 甲이 네 개의 검증 노드로 구성된 실습망에서 거래 승인 메시지를 주고받자, 일부 노드가 잘못된 값을 보내도 나머지 노드들이 정해진 절차에 따라 같은 결과에 동의해 거래를 확정했다.

    보유하거나 예치한 자산의 지분을 기준으로 블록 생성·검증 권한을 부여하는 합의 알고리즘은 PoS이다.

    다음 랜(LAN)에서 ‘공격시스템’이 ARP 스푸핑(spoofing) 공격을 위해 (가), (나)에서 수행하는 작업을 ㄱ ～ ㄹ에서 찾아 바르게 연결한 것은? (단, MAC 주소는 24비트로 가정한다)

    ㄱ. 시스템1의 MAC 주소를 AA-AA-AA라고 알린다.

    ㄴ. 시스템2의 MAC 주소를 AA-AA-AA라고 알린다.

    ㄷ. 시스템1의 MAC 주소를 CC-CC-CC라고 알린다.

    ㄹ. 시스템2의 MAC 주소를 BB-BB-BB라고 알린다. (가) (나)

    1. 1. ㄴ ㄱ
    2. 2. ㄴ ㄷ
    3. 3. ㄹ ㄱ
    4. 4. ㄹ ㄷ

    정답 1번

    🔍 보기별 해설
    1. 시스템1에는 상대인 시스템2의 MAC이 AA라 알리고 시스템2에는 시스템1의 MAC이 AA라 알려야 양쪽 통신이 공격자를 지나가므로 옳다(정답).
    2. (나)에서 시스템1의 MAC을 CC라 알리면 시스템2가 자기 주소로 프레임을 보내게 되어 공격자를 거치지 않으므로 옳지 않다.
    3. (가)에서 시스템2의 MAC을 BB라 알리면 시스템1이 자기 주소로 프레임을 내보내게 되어 공격이 아예 서지 않으므로 옳지 않다.
    4. (가)와 (나) 어느 쪽도 공격자 주소인 AA를 가리키지 않아 양쪽 패킷이 원래 경로로만 오가므로 옳지 않다.
    🧮 풀이
    1. 甲이 공격 장비에서 시스템1에게는 0.6의 MAC이 AA라고, 시스템2에게는 0.5의 MAC이 AA라고 잇따라 알리자 두 시스템이 주고받는 패킷이 모두 공격 장비를 지나갔다.
    2. 甲이 시스템2에게 상대 MAC을 CC라고 잘못 알리자 시스템2가 자기 자신에게 패킷을 보내려 했고, 두 시스템 사이 통신이 끊기기만 할 뿐 공격 장비로는 아무것도 흘러들지 않았다.
    3. 甲이 시스템1에게 상대 MAC을 BB라고 알리자 시스템1이 자기 주소로 프레임을 내보냈고, 스위치가 그 프레임을 그대로 버려 공격 장비의 화면에는 한 건도 잡히지 않았다.
    4. 甲이 두 방향 모두 공격 장비가 아닌 주소를 알리자 두 시스템의 패킷이 원래 경로로만 오갔고, 공격 장비에서 한참 트래픽을 떠 보아도 잡히는 것이 한 건도 없었다.

    ARP 스푸핑은 양쪽 모두에게 상대의 MAC이 공격자 주소라고 알려 통신을 가로채는 것이므로 정답은 1번이다.
