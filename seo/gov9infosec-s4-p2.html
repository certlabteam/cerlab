    네트워크 계층에서 스니핑 시스템을 네트워크에 존재하는 또 다른 라우터라고 알림으로써 패킷의 흐름을 바꾸는 공격은?

    1. 1. DNS 스푸핑 공격
    2. 2. E-mail 스푸핑 공격
    3. 3. IP 스푸핑 공격
    4. 4. ICMP 리다이렉트 공격

    정답 4번

    🔍 보기별 해설
    1. DNS 스푸핑 공격은 위조한 DNS 응답으로 도메인 이름을 공격자의 IP에 묶는 공격이다. 자기를 다른 라우터라고 알려 경로를 바꾸는 방식이 아니므로 옳지 않다.
    2. E-mail 스푸핑 공격은 메일 발신자 주소를 위조해 다른 사람이 보낸 것처럼 꾸미는 공격이다. 네트워크 계층에서 패킷 흐름을 돌리는 공격이 아니므로 옳지 않다.
    3. IP 스푸핑 공격은 패킷의 출발지 IP 주소를 남의 주소로 바꿔 신분을 위장하는 공격이다. 라우터 정보를 퍼뜨려 상대의 경로를 바꾸는 것과는 다르므로 옳지 않다.
    4. ICMP 리다이렉트 공격은 더 나은 경로가 있다는 위조 ICMP Redirect 메시지로 피해 호스트가 공격자를 게이트웨이로 쓰게 만드는 공격이다. 패킷이 스니핑 시스템을 거쳐 흐르게 되므로 옳다(정답).
    🧮 풀이
    1. 기숙사망에 숨어든 공격자가 학생 PC의 DNS 질의를 가로채 학교 포털 주소를 가짜 서버 IP로 바꾼 응답을 먼저 보냈다. 학생은 주소창을 그대로 둔 채 가짜 로그인 화면에 비밀번호를 넣었다. 이름 풀이를 속인 DNS 스푸핑이다.
    2. 총장 명의 메일을 받은 행정 직원이 헤더를 열어 발송 경로를 추적하니 발신자 칸만 총장 주소였고 실제 발송 서버는 해외 호스팅이었다. 직원은 즉시 전 교직원에게 열람 금지 공지를 보냈다. 보낸 사람을 위조한 E-mail 스푸핑이다.
    3. 실습망에서 학생이 hping3로 출발지 IP를 10.0.0.99로 바꾼 SYN 패킷을 대상 서버에 보냈다. 서버의 SYN-ACK는 엉뚱한 10.0.0.99 장비로 날아갔다. 출발지 주소를 위장한 IP 스푸핑이다.
    4. 같은 서브넷의 공격자가 교수 PC에 ‘외부로 가는 패킷은 이 주소로 보내라’는 ICMP Redirect를 위조해 보냈다. 교수 PC의 라우팅 표가 바뀌어 메일 트래픽이 공격자 노트북을 거쳐 나갔고 그 사이 내용이 수집되었다. 경로를 비튼 ICMP 리다이렉트 공격이다.

    자신을 또 다른 라우터라고 알리는 위조 ICMP Redirect로 피해 호스트의 경로를 바꿔 패킷을 가로채는 공격이므로 정답은 4번이다.

    다음과 같이 각 문자에 숫자를 배정할 때, 시저 암호 치환식 C ＝ (P ＋ 3) mod 26을 활용하여 평문 STUDY를 암호화한 것은? (단, 치환식에서 C는 암호문, P는 평문이다)

    1. 1. VWXGB
    2. 2. UVWFA
    3. 3. TUVEZ
    4. 4. VWXFN

    정답 1번

    🔍 보기별 해설
    1. VWXGB는 S(18)→21(V), T(19)→22(W), U(20)→23(X), D(3)→6(G), Y(24)→27 mod 26=1(B)로 각 글자에 3을 더한 결과다. 치환식을 다섯 글자 모두에 그대로 적용했으므로 옳다(정답).
    2. UVWFA는 S→U, T→V, U→W, D→F, Y→A로 모든 글자를 2칸씩만 민 결과다. 치환식이 요구하는 3이 아니라 2를 더했으므로 옳지 않다.
    3. TUVEZ는 S→T, T→U, U→V, D→E, Y→Z로 모든 글자를 1칸씩만 민 결과다. 3을 더하라는 치환식과 맞지 않으므로 옳지 않다.
    4. VWXFN은 앞의 VWX는 3을 더한 값과 같지만 D는 G(6)가 아닌 F(5)로, Y는 B(1)가 아닌 N(13)으로 바뀌었다. 뒤의 두 글자가 치환식 결과와 다르므로 옳지 않다.
    🧮 풀이
    1. 암호학 수업 조교가 칠판에 STUDY를 적고 학생들과 숫자표로 한 글자씩 바꿨다. 18, 19, 20, 3, 24에 3을 더해 21, 22, 23, 6, 27을 얻고 27은 26으로 나눈 나머지 1로 돌렸다. 그렇게 나온 VWXGB가 시저 암호문이다.
    2. 한 학생이 키를 2로 잘못 알고 STUDY의 숫자에 2씩 더해 20, 21, 22, 5, 0을 얻었다. 그대로 글자로 바꾸니 UVWFA가 나왔고 짝꿍이 키 3으로 풀자 엉뚱한 글이 되었다. 키 값이 하나 틀리면 암호문 전체가 달라진다.
    3. 퀴즈를 서두르던 학생이 STUDY의 각 글자를 알파벳 바로 다음 글자로 옮겨 TUVEZ를 적었다. 채점하던 조교가 숫자로 되짚자 모든 글자에 1만 더한 것이었다. 치환식의 3을 1로 바꿔 버린 결과다.
    4. 다른 학생은 VWX까지 맞게 쓰고 D를 F로, Y를 N으로 옮겨 VWXFN을 냈다. D는 3에 3을 더한 6이라 G, Y는 27을 26으로 나눈 나머지 1이라 B인데 두 글자를 놓쳤다. mod 26 계산을 빠뜨리면 끝 글자가 어긋난다.

    각 글자의 숫자에 3을 더하고 26으로 나눈 나머지를 다시 글자로 바꾸면 STUDY는 VWXGB가 되므로 정답은 1번이다.

    SSL Handshake 프로토콜의 2단계 ‘서버 인증과 키 교환(server authentication and key exchange)’에서 인증서(certificate) 메시지가 사용되지 않는 기법은?

    1. 1. RSA 기법
    2. 2. Anonymous DH 기법
    3. 3. Ephermeral DH 기법
    4. 4. Fixed DH 기법

    정답 2번

    🔍 보기별 해설
    1. RSA 기법에서는 서버가 RSA 공개키가 든 인증서를 Certificate 메시지로 보내고 클라이언트는 그 키로 사전 마스터 비밀을 암호화한다. 인증서 메시지가 반드시 쓰이므로 쓰인다는 판단은 옳다.
    2. Anonymous DH 기법은 서버가 서명이나 인증서 없이 Diffie-Hellman 공개값만 ServerKeyExchange로 보낸다. Certificate 메시지가 빠지므로 인증서가 쓰인다고 보는 것은 옳지 않다(정답).
    3. Ephermeral DH(Ephemeral DH) 기법은 서버가 임시 DH 공개값을 자기 개인키로 서명해 보내고 그 서명을 검증할 인증서를 Certificate 메시지로 전한다. 인증서가 쓰이므로 옳다.
    4. Fixed DH 기법은 서버의 고정 DH 공개값이 CA가 서명한 인증서 안에 들어 있다. 그 인증서를 Certificate 메시지로 보내야 키 교환이 되므로 인증서가 쓰인다는 판단은 옳다.
    🧮 풀이
    1. RSA 키 교환으로 웹서버를 설정한 관리자가 핸드셰이크를 캡처하자 ServerHello 뒤에 Certificate 메시지가 실려 왔다. 브라우저는 그 인증서의 공개키로 사전 마스터 비밀을 암호화해 보냈다. RSA 기법은 인증서가 있어야 돌아간다.
    2. 암호 실습에서 대학원생이 OpenSSL 서버를 익명 DH 암호군(ADH)으로 띄우고 접속을 캡처했다. Certificate 메시지 없이 ServerKeyExchange에 DH 값만 실려 왔고 서버가 누구인지 증명할 길이 없었다. Anonymous DH는 인증서 없이 키만 나눈다.
    3. 연구실 서버를 DHE 암호군으로 바꾼 조교가 핸드셰이크를 열자 서버가 접속마다 새 DH 값을 만들어 RSA 서명을 붙여 보냈다. 그 서명을 검증하라고 Certificate 메시지도 함께 왔다. Ephemeral DH 역시 인증서를 쓴다.
    4. 인증센터에서 DH 공개값이 박힌 인증서를 발급받은 서버 관리자가 Fixed DH 설정을 적용했다. 클라이언트는 받은 Certificate 메시지에서 서버 DH 값을 꺼내 공유 비밀을 계산했다. 고정 DH 값을 인증서로 전하는 방식이다.

    Anonymous DH는 인증 없이 Diffie-Hellman 공개값만 교환하므로 서버 인증서를 담는 Certificate 메시지가 쓰이지 않는다. 정답은 2번이다.

    전자 서명(digital signature)에 대한 설명으로 옳지 않은 것은?

    1. 1. 서명된 문서는 기밀성이 보장된다.
    2. 2. 서명된 문서는 데이터가 변조되지 않았음을 보장하는 무결성을 만족한다.
    3. 3. 한 번 생성된 서명을 다른 문서의 서명으로 사용할 수 없다.
    4. 4. 전자 서명과 관련된 표준으로 DSS가 있다.

    정답 1번

    🔍 보기별 해설
    1. 전자 서명은 서명자 인증, 무결성, 부인 방지를 주지만 문서 내용을 숨기지는 않는다. 서명만 붙인 문서는 누구나 읽을 수 있으므로 기밀성이 보장된다는 설명은 옳지 않다(정답).
    2. 전자 서명은 문서의 해시값에 서명자의 개인키를 적용해 만든다. 서명 뒤 한 글자라도 바뀌면 해시가 달라져 검증이 실패하므로 무결성을 만족한다는 설명은 옳다.
    3. 전자 서명은 서명할 문서의 해시값에 묶여 있어 다른 문서에 옮겨 붙이면 검증이 맞지 않는다. 서명을 재사용할 수 없다는 성질이므로 옳다.
    4. DSS(Digital Signature Standard)는 미국 NIST가 정한 전자 서명 표준이며 DSA 알고리즘을 규정한다. 전자 서명 관련 표준의 대표 예이므로 옳다.
    🧮 풀이
    1. 인사 발령 문서에 총장이 전자 서명을 붙였고 행정실 직원이 그 파일을 메일로 돌렸다. 메일을 가로챈 외부인도 서명 덕분에 문서가 진짜임은 알 수 있었지만 내용 역시 그대로 읽혔다. 서명만으로는 내용이 숨겨지지 않는다.
    2. 교수가 전자 서명해 올린 성적표 파일을 내려받은 한 학생이 자기 학점 B를 A로 고쳐 장학금 서류로 제출했다. 학사 시스템이 서명을 검증하자 문서 해시가 서명과 맞지 않아 즉시 위변조 경고가 떴다. 서명이 무결성을 지켜 준 결과다.
    3. 연구원이 지난달 교수가 서명한 결재 문서에서 서명값만 복사해 자기가 새로 만든 연구비 신청서에 붙였다. 검증 프로그램은 새 문서의 해시와 서명이 맞지 않는다며 접수를 거부했다. 서명은 그 문서에만 묶여 있어 옮겨 쓸 수 없다.
    4. 정부 과제용 서명 모듈을 만들던 대학원생이 NIST의 DSS 문서를 받아 DSA 키 생성과 검증 절차를 그대로 구현했다. 완성된 모듈은 표준 시험 벡터를 모두 통과했다. DSS가 전자 서명 표준이기 때문이다.

    전자 서명은 인증·무결성·부인 방지를 제공할 뿐 문서를 암호화하지 않으므로 기밀성이 보장된다는 1번이 틀렸다. 정답은 1번이다.

    NAC(Network Access Control) 시스템에 대한 설명으로 옳지 않은 것은?

    1. 1. ARP 방식은 차단하려는 단말에 ARP 스푸핑 패킷을 보내 네트워크 접근을 제어한다.
    2. 2. 802.1x 방식은 802.1x RADIUS 서버와 802.1x를 지원하는 스위치가 필요하다.
    3. 3. 소프트웨어 에이전트 설치 방식은 네트워크에 접속하려는 모든 클라이언트에 에이전트를 설치할 필요는 없다.
    4. 4. VLAN 방식은 인가받지 않은 클라이언트가 인가된 클라이언트와는 다른 별도의 VLAN으로 격리된다.

    정답 3번

    🔍 보기별 해설
    1. ARP 방식 NAC는 차단할 단말에 게이트웨이 MAC을 거짓으로 알리는 ARP 스푸핑 패킷을 보낸다. 그 단말의 통신이 엉뚱한 곳으로 가서 접근이 막히므로 옳다.
    2. 802.1x 방식 NAC는 스위치 포트에서 인증을 요구하므로 802.1x를 따르는 스위치와 인증을 판정할 RADIUS 서버가 있어야 한다. 장비 요건을 바르게 든 설명이므로 옳다.
    3. 소프트웨어 에이전트 방식은 접속하려는 단말마다 에이전트를 깔아 보안 상태를 검사하는 방식이다. 설치하지 않은 단말은 검사할 수 없으므로 설치가 필요 없다는 설명은 옳지 않다(정답).
    4. VLAN 방식 NAC는 인가받지 못한 단말을 정상 단말과 다른 격리 VLAN에 넣는다. 격리된 단말은 업데이트 서버 등 허용된 곳에만 닿으므로 옳다.
    🧮 풀이
    1. 기숙사망 NAC가 백신 미설치 노트북을 찾아내자 그 PC에 게이트웨이 MAC을 가짜로 적은 ARP 응답을 계속 보냈다. 노트북의 패킷은 NAC 장비로 빨려 들어가 안내 페이지만 떴다. ARP 스푸핑으로 접근을 막는 방식이다.
    2. 도서관 열람석 포트에 802.1x를 켠 담당자가 스위치 펌웨어를 지원 버전으로 올리고 RADIUS 서버에 학번 계정을 연동했다. 학생이 랜선을 꽂으면 학번 인증을 통과해야 포트가 열렸다. 두 장비가 모두 있어야 돌아가는 방식이다.
    3. 에이전트 방식 NAC를 도입한 학과에서 에이전트를 깔지 않은 교수의 개인 노트북이 접속하자 보안 상태를 보고할 수단이 없어 격리망으로 밀려났다. 에이전트를 설치한 뒤에야 정상 접속이 되었다. 모든 단말에 설치가 필요하다.
    4. 인증을 거치지 않은 방문객 노트북이 강의실 포트에 연결되자 스위치가 그 포트를 격리용 VLAN 99로 옮겼다. 노트북은 패치 서버와 안내 페이지에만 접속할 수 있었다. 미인가 단말을 다른 VLAN에 가두는 방식이다.

    에이전트 방식 NAC는 단말에 깐 에이전트로 보안 상태를 검사하므로 접속하는 클라이언트마다 설치가 필요하다. 정답은 3번이다.

    IPSec에 대한 설명으로 옳지 않은 것은?

    1. 1. 네트워크 계층에서 동작하는 보안 프로토콜이다.
    2. 2. 트래픽을 암호화하고, 무결성을 보장하며, 인증을 제공한다.
    3. 3. 전송 모드와 터널 모드가 있다.
    4. 4. IPSec에서 AH 프로토콜은 페이로드 데이터를 암호화한다.

    정답 4번

    🔍 보기별 해설
    1. IPSec은 IP 패킷 단위로 보안을 적용하는 네트워크 계층의 보안 프로토콜 묶음이다. 위의 응용 프로그램을 고치지 않아도 모든 IP 통신을 보호하므로 옳다.
    2. IPSec은 ESP로 트래픽을 암호화하고, AH와 ESP로 무결성 검사와 출처 인증을 제공한다. 세 가지 보안 기능을 모두 갖추므로 옳다.
    3. IPSec에는 원래 IP 헤더를 두고 페이로드만 보호하는 전송 모드와 패킷 전체를 감싸 새 IP 헤더를 붙이는 터널 모드가 있다. 두 모드를 지원하므로 옳다.
    4. IPSec의 AH(Authentication Header)는 무결성과 출처 인증만 제공하고 암호화 기능은 없다. 페이로드 암호화는 ESP의 일이므로 AH가 암호화한다는 설명은 옳지 않다(정답).
    🧮 풀이
    1. 연구실 서버 두 대 사이에 IPSec을 걸자 SSH, 웹, 데이터베이스 접속이 프로그램 설정 하나 바꾸지 않고 모두 보호되었다. 보호가 IP 패킷 단계에서 일어났기 때문이다. IPSec이 네트워크 계층에서 동작한다는 뜻이다.
    2. 분교와 본교 서버실을 연결하는 IPSec 터널을 연 관리자가 패킷을 캡처하니 본문은 암호문이었고 한 바이트를 조작한 패킷은 무결성 검사에서 버려졌다. 상대 장비는 사전 공유키로 신원을 증명했다. 암호화·무결성·인증을 함께 쓴 결과다.
    3. 서버 관리자가 연구실 두 서버 사이에는 전송 모드를, 분교 라우터와 본교 라우터 사이에는 터널 모드를 설정했다. 전송 모드 패킷은 원래 IP 헤더가 그대로였고 터널 모드 패킷은 새 IP 헤더를 달고 나갔다. IPSec이 두 모드를 갖춘 것이다.
    4. AH만 켠 실습 터널에서 대학원생이 패킷을 캡처하니 페이로드의 텍스트가 평문으로 읽혔다. 내용을 바꾼 패킷은 AH 검사에서 버려졌지만 엿보는 것은 막지 못했다. 암호화가 필요하면 ESP를 써야 한다.

    IPSec의 AH는 무결성과 출처 인증만 제공하고 페이로드 암호화는 ESP가 맡으므로 AH가 암호화한다는 4번이 틀렸다. 정답은 4번이다.

    공격자가 ARP 스푸핑 공격으로 위조하려는 것은?

    1. 1. Port 번호
    2. 2. ICMP 에코 요청 패킷
    3. 3. MAC 주소
    4. 4. DNS 응답 메시지

    정답 3번

    🔍 보기별 해설
    1. Port 번호는 TCP·UDP 헤더에서 어느 응용 서비스로 갈지 가리키는 값이다. ARP 스푸핑은 IP와 MAC의 대응을 속이는 공격이라 포트 번호를 위조 대상으로 삼지 않으므로 옳지 않다.
    2. ICMP 에코 요청 패킷은 ping이 상대의 도달 여부를 묻는 데 쓰는 메시지다. ARP 응답을 꾸미는 일과는 다른 프로토콜의 메시지여서 ARP 스푸핑의 위조 대상으로 보는 것은 옳지 않다.
    3. MAC 주소는 같은 LAN 안에서 프레임을 실제로 배달할 때 쓰는 하드웨어 주소다. ARP 스푸핑은 게이트웨이 IP에 공격자의 MAC 주소를 짝지은 거짓 ARP 응답을 뿌려 이 값을 위조하므로 옳다(정답).
    4. DNS 응답 메시지를 위조해 도메인을 엉뚱한 IP로 이어 주는 것은 DNS 스푸핑이다. ARP 캐시가 아니라 이름 풀이 결과를 속이는 공격이어서 ARP 스푸핑의 위조 대상으로 보는 것은 옳지 않다.
    🧮 풀이
    1. 쇼핑몰 운영자가 결제 서버의 443번 Port 번호를 8443번으로 바꿔 열어 두었다. 같은 LAN의 공격자가 거짓 ARP 응답을 뿌리자 포트 번호는 그대로인 채 프레임만 공격자 노트북으로 먼저 흘러갔다. 포트를 바꿔도 ARP 스푸핑은 막히지 않는다.
    2. 백엔드 개발자가 장애를 의심해 서버에 ping을 보내 ICMP 에코 요청 패킷의 응답 시간을 쟀다. 응답은 정상이었지만 같은 망의 공격자가 ARP 캐시를 바꿔 둔 탓에 실제 웹 트래픽은 엉뚱한 장비를 거치고 있었다. ping 메시지와 ARP 위조는 서로 다른 층의 일이다.
    3. 카페 공용 와이파이에 접속한 공격자가 공유기 IP 192.168.0.1에 자기 노트북의 MAC 주소를 짝지은 ARP 응답을 계속 보냈다. 손님들의 ARP 캐시가 바뀌자 결제 페이지로 가는 프레임이 모두 공격자 노트북으로 먼저 들어왔다. ARP 스푸핑이 위조한 것은 MAC 주소다.
    4. 호스팅 엔지니어가 고객 도메인이 낯선 IP로 열린다는 신고를 받고 DNS 응답 메시지를 캡처했다. 누군가 질의에 먼저 위조 응답을 보내 도메인을 가짜 서버 주소로 이어 놓았고, 엔지니어는 이를 ARP가 아닌 DNS 스푸핑 사고로 분류해 대응했다.

    ARP 스푸핑은 거짓 ARP 응답으로 IP 주소에 공격자의 MAC 주소를 짝지어 프레임을 가로채는 공격이므로 정답은 3번이다.

    route 명령으로 얻은 라우팅 테이블 정보와 같은 결과물을 출력할 수 있는 것은?

    1. 1. traceroute
    2. 2. tcpdump
    3. 3. netstat
    4. 4. ping

    정답 3번

    🔍 보기별 해설
    1. traceroute는 TTL을 1씩 늘려 보내며 목적지까지 거치는 라우터를 홉 단위로 보여 준다. 한 경로의 중계 지점만 나열할 뿐 내 시스템의 라우팅 테이블 전체를 출력하지 않으므로 옳지 않다.
    2. tcpdump는 네트워크 인터페이스를 지나는 패킷을 잡아 헤더와 내용을 보여 주는 캡처 도구다. 오가는 패킷을 기록할 뿐 커널이 가진 경로 표를 출력하지 않으므로 옳지 않다.
    3. netstat은 연결 상태 외에 -r 옵션으로 커널의 라우팅 테이블을 출력할 수 있다. route 명령이 보여 주는 목적지·게이트웨이·인터페이스 정보를 그대로 얻을 수 있으므로 옳다(정답).
    4. ping은 ICMP Echo Request를 보내고 Reply를 받아 상대의 도달 여부와 왕복 시간을 잰다. 연결이 되는지만 알려 줄 뿐 라우팅 테이블을 출력하는 기능은 없으므로 옳지 않다.
    🧮 풀이
    1. 개발팀 서버 담당자가 해외 CDN이 느리다는 말에 traceroute를 실행했다. 화면에는 거쳐 간 라우터 열두 개와 구간별 지연 시간만 나왔고 서버의 기본 게이트웨이 설정은 한 줄도 보이지 않았다. 경로 추적과 경로 표 조회는 서로 다른 일이다.
    2. 결제 오류를 추적하던 백엔드 개발자가 tcpdump로 443번 포트 패킷을 10분 동안 파일에 저장했다. 저장된 것은 오간 패킷의 헤더와 내용뿐이어서 어느 게이트웨이로 나가도록 설정됐는지는 따로 찾아야 했다. 캡처 도구는 경로 표를 출력하지 않는다.
    3. 호스팅 엔지니어가 새 서버에서 route 명령 대신 netstat -r 을 입력했다. 목적지 네트워크, 게이트웨이, 인터페이스가 줄마다 찍혀 route 출력과 같은 표를 얻었고 기본 경로가 빠진 것을 찾아 바로 추가했다. netstat으로도 라우팅 테이블을 볼 수 있다.
    4. 포스기 결제가 끊기자 카페 사장이 노트북에서 ping 8.8.8.8 을 실행했다. 응답이 정상으로 돌아와 인터넷 연결이 살아 있음은 드러났지만 어떤 게이트웨이로 나가는지는 화면 어디에도 나오지 않았다. ping은 도달 여부와 왕복 시간만 알려 준다.

    route와 같은 라우팅 테이블은 netstat -r로 출력할 수 있고 나머지는 경로 추적·패킷 캡처·도달 여부 점검 도구이므로 정답은 3번이다.

    다음에서 설명하는 것은?

    ○ 외부 방화벽과 내부 방화벽 사이에 존재한다.

    ○ 외부에서 접속할 수 있어야 하며 보호되어야 하는 시스템(예: 회사의 웹사이트, 이메일 서버 등)을 여기에 배치한다.

    1. 1. NAT(Network Address Translation)
    2. 2. DMZ(Demilitarized Zone)
    3. 3. VPN(Virtual Private Network)
    4. 4. PAN(Personal Area Network)

    정답 2번

    🔍 보기별 해설
    1. NAT(Network Address Translation)는 사설 IP와 공인 IP를 서로 바꿔 주는 주소 변환 기술이다. 서버를 두는 구역이 아니라 주소를 고치는 기능이어서 두 방화벽 사이 영역을 가리킨다고 보는 것은 옳지 않다.
    2. DMZ(Demilitarized Zone)는 외부 방화벽과 내부 방화벽 사이에 만든 완충 구역이다. 웹·메일 서버처럼 외부 접속이 필요한 시스템을 여기에 두어 내부망과 떼어 보호하므로 옳다(정답).
    3. VPN(Virtual Private Network)은 공중망 위에 암호화 터널을 만들어 사설망처럼 쓰는 기술이다. 통신 경로를 보호하는 방식일 뿐 공개 서버를 놓는 중간 구역이 아니므로 옳지 않다.
    4. PAN(Personal Area Network)은 블루투스처럼 한 사람 주변 몇 미터 안의 기기를 잇는 망이다. 기업 방화벽 구조와 무관한 소규모 망이어서 공개 서버를 배치하는 구역으로 보는 것은 옳지 않다.
    🧮 풀이
    1. 스타트업 네트워크 담당자가 사무실 공유기에 NAT를 켜 직원 PC 스무 대가 공인 IP 하나로 인터넷에 나가게 했다. 외부에서는 사설 주소가 보이지 않게 되었지만 외부 공개용 웹 서버를 따로 떼어 둘 구역이 생기지는 않았다. NAT는 주소를 바꾸는 기술이다.
    2. 쇼핑몰 인프라 담당자가 웹 서버와 메일 서버를 외부 방화벽과 내부 방화벽 사이 구간으로 옮겼다. 몇 달 뒤 웹 서버가 뚫렸을 때도 공격자는 내부 방화벽에 막혀 주문 데이터베이스까지 들어가지 못했다. 이 완충 구간이 DMZ다.
    3. 재택근무를 하는 개발자가 집에서 VPN 클라이언트를 켜고 회사 내부 Git 서버에 접속했다. 공용 인터넷을 지나는 동안 트래픽은 암호화 터널 안에 담겨 오갔지만 서버가 놓인 자리는 그대로였다. VPN은 안전한 통로를 만드는 기술이다.
    4. 카페 매니저가 스마트폰과 무선 이어폰, 스마트워치를 블루투스로 묶어 PAN을 구성했다. 몇 미터 안의 개인 기기끼리만 데이터를 주고받았고 방화벽이나 서버 배치와는 아무 관련이 없었다. PAN은 개인 주변의 작은 망이다.

    외부 방화벽과 내부 방화벽 사이에서 외부 공개 서버를 내부망과 떼어 두는 구역은 DMZ이므로 정답은 2번이다.

    접근 제어 방식에 대한 다음 설명의 (가)와 (나)에 들어갈 내용을 바르게 연결한 것은?

    (가) 는 사용자 ID가 아닌 시스템에서 정의한 사용자의 역할을 바탕으로 접근 권한을 정의한다. 각 사용자는 (나) 정적 또는 동적으로 할당될 수 있다. (가) (나)

    1. 1. DAC 하나의 역할에만
    2. 2. DAC 여러 개의 역할에
    3. 3. RBAC 하나의 역할에만
    4. 4. RBAC 여러 개의 역할에

    정답 4번

    🔍 보기별 해설
    1. DAC(임의적 접근통제)는 객체 소유자가 사용자 ID별로 권한을 나눠 주는 방식이다. 역할로 권한을 정하는 (가)에 들어갈 수 없고 하나의 역할에만 배정한다는 (나)도 어긋나므로 옳지 않다.
    2. DAC(임의적 접근통제)는 사용자 신원과 소유자 판단으로 접근을 허락하는 방식이어서 역할 기반과 거리가 멀다. 여러 개의 역할에 배정된다는 (나)는 그럴듯해도 (가)부터 어긋나므로 옳지 않다.
    3. RBAC(역할 기반 접근통제)는 사용자 ID가 아닌 역할에 권한을 묶어 두는 방식이어서 (가)에는 들어맞는다. 그러나 한 사용자가 여러 역할을 맡을 수 있어 하나의 역할에만 배정된다는 (나)는 옳지 않다.
    4. RBAC(역할 기반 접근통제)는 시스템이 정의한 역할에 권한을 주고 사용자를 그 역할에 배정하는 방식이다. 한 사용자가 여러 개의 역할에 정적·동적으로 배정될 수 있으므로 옳다(정답).
    🧮 풀이
    1. 고객 서버 폴더마다 호스팅 회사 관리자가 소유자에게 읽기·쓰기 권한을 사용자 이름으로 직접 지정하게 했다. 담당자가 바뀔 때마다 소유자가 사람 이름을 하나씩 고쳐야 했고 역할이라는 묶음은 어디에도 없었다. 소유자 재량으로 사람마다 권한을 주는 DAC 방식이다.
    2. 개발팀 리더가 공유 문서 하나를 만들고 동료 세 명의 계정에 편집 권한을 직접 체크해 주었다. 권한은 문서 주인의 판단으로 계정마다 붙었고 역할이 여러 개인지 하나인지 따질 단계 자체가 없었다. DAC는 소유자가 계정 단위로 권한을 나눠 준다.
    3. 신입 직원 계정을 쇼핑몰 운영자가 상품등록 역할 하나에만 넣으려고 관리자 페이지를 열었다. RBAC 도구는 한 계정에 상품등록과 고객응대 역할을 함께 붙이는 칸을 기본으로 갖추고 있었고, 운영자는 두 역할을 모두 붙였다. 역할 수를 하나로 묶는 규칙은 RBAC에 없다.
    4. 스타트업 CTO가 백엔드 개발자 계정에 개발자 역할과 야간 당직 역할을 함께 배정했다. 평소에는 개발 권한만 쓰다가 당직 시간에는 장애 대응 권한이 켜지도록 세션마다 역할을 골라 활성화했다. RBAC는 이렇게 한 사용자에게 여러 역할을 건다.

    (가)는 사용자 ID 대신 역할로 권한을 정하는 RBAC이고, 한 사용자는 여러 개의 역할에 배정될 수 있으므로 정답은 4번이다.

    HTTP 버전 1.1에서 정의된 메소드의 설명으로 옳지 않은 것은?

    1. 1. POST는 서버가 클라이언트에게 문서를 전달하는 데 사용한다.
    2. 2. GET은 클라이언트가 서버에게 문서를 요청할 때 사용한다.
    3. 3. HEAD는 클라이언트가 문서 자체가 아니라 문서에 대한 정보를 원할 때 사용한다.
    4. 4. TRACE는 클라이언트가 검사 목적으로 서버에게 정보 반환을 요청하는 데 사용한다.

    정답 1번

    🔍 보기별 해설
    1. POST는 클라이언트가 폼 데이터나 파일을 요청 본문에 담아 서버로 보내는 메소드다. 문서를 서버에서 클라이언트로 내려보내는 용도로 설명해 방향이 거꾸로이므로 옳지 않다(정답).
    2. GET은 클라이언트가 URI로 지정한 자원을 서버에 달라고 요청하는 가장 기본적인 메소드다. 웹 페이지나 이미지를 받아 올 때 쓰므로 옳다.
    3. HEAD는 GET과 같은 요청을 보내되 응답에서 본문을 빼고 헤더만 받는 메소드다. 문서 크기나 수정 시각 같은 정보만 알고 싶을 때 쓰므로 옳다.
    4. TRACE는 서버가 받은 요청 메시지를 그대로 되돌려 보내게 하는 진단용 메소드다. 요청이 중간 경로에서 어떻게 바뀌었는지 검사하는 데 쓰므로 옳다.
    🧮 풀이
    1. 회원가입 화면을 만든 백엔드 개발자가 아이디와 비밀번호를 POST 요청 본문에 담아 서버로 보내게 했다. 서버는 받은 값을 회원 테이블에 저장하고 가입 완료 페이지로 응답했다. POST는 클라이언트가 서버로 데이터를 보낼 때 쓰는 메소드다.
    2. 손님이 쇼핑몰 상품 목록을 누르자 브라우저가 GET /products 요청을 서버에 보냈다. 서버는 상품 목록 HTML을 응답 본문에 담아 돌려주었고 화면에 사진과 가격이 줄지어 떴다. GET은 자원을 달라고 요청할 때 쓴다.
    3. 이미지 서버를 점검하던 호스팅 엔지니어가 HEAD 요청으로 큰 동영상 파일의 Content-Length와 Last-Modified만 받아 보았다. 수 기가바이트 본문을 내려받지 않고도 파일 크기와 수정 시각을 바로 얻었다. HEAD는 문서 대신 문서 정보만 준다.
    4. 프록시를 거친 요청이 이상하다는 보고에 개발자가 TRACE 요청을 서버로 보냈다. 서버가 받은 그대로 되돌려준 메시지에 프록시가 끼워 넣은 헤더가 보여 경로 중간에서 바뀐 부분을 찾아냈다. TRACE는 진단용으로 요청을 되돌려 받는 메소드다.

    POST는 클라이언트가 데이터를 서버로 보내 처리하게 하는 메소드인데 서버가 문서를 내려보낸다고 거꾸로 설명했으므로 정답은 1번이다.

    DNS 스푸핑 공격의 순서를 바르게 나열한 것은?

    (가) 클라이언트는 공격자가 전송한 DNS Response를 올바른 메시지로 인식한다. (나) 로컬에 존재하며 DNS 서버보다 클라이언트와 가까이 위치한 공격자는 위조된 DNS Response를 클라이언트에게 전송한다. (다) 공격자는 스니핑 공격을 통해 클라이언트가 DNS 서버로 DNS Query를 전송하는 것을 확인한다.

    1. 1. (가) → (나) → (다)
    2. 2. (나) → (가) → (다)
    3. 3. (나) → (다) → (가)
    4. 4. (다) → (나) → (가)

    정답 4번

    🔍 보기별 해설
    1. DNS 스푸핑에서 클라이언트가 위조 응답을 정상으로 믿는 일은 맨 마지막에 일어난다. 이 배열은 그 결과를 맨 앞에 두고 질의 포착을 맨 끝에 두어 인과가 뒤집혔으므로 옳지 않다.
    2. DNS 스푸핑의 공격자는 클라이언트의 DNS Query를 먼저 엿봐야 그에 맞는 위조 응답을 만들 수 있다. 위조 응답 전송을 맨 앞에, 스니핑을 맨 뒤에 둔 이 순서는 옳지 않다.
    3. DNS 스푸핑은 질의를 본 뒤에야 짝이 맞는 위조 응답을 보낼 수 있는 공격이다. 위조 응답 전송을 질의 확인보다 앞에 둔 이 순서는 공격의 선후가 어긋나 옳지 않다.
    4. DNS 스푸핑은 스니핑으로 질의를 확인하고, 진짜 DNS 서버보다 가까운 공격자가 위조 응답을 먼저 보내고, 클라이언트가 그것을 정상으로 믿는 차례다. (다)→(나)→(가)이므로 옳다(정답).
    🧮 풀이
    1. 카페 와이파이에 붙은 공격자가 손님 노트북이 은행 도메인을 묻는 순간을 기다렸다. 질의가 나오기 전에는 무엇을 위조할지 정할 수 없었고, 손님 쪽에서 응답을 믿는 단계는 위조 응답이 도착한 뒤에야 생겼다. 응답을 믿는 단계가 맨 처음에 올 수는 없다.
    2. 모의해킹을 맡은 보안 업체 직원이 위조 DNS 응답을 미리 마구 쏘아 보냈지만 손님 노트북이 아직 질의를 내지 않아 응답이 모두 버려졌다. 질의의 ID와 포트를 스니핑으로 본 뒤에 보낸 응답만 받아들여졌다. 위조 응답보다 질의 포착이 먼저다.
    3. 공격 도구 설정을 바꾸던 공격자가 응답 전송 단계를 스니핑 단계 앞으로 옮겼다. 그러자 질의 번호를 모르는 채 보낸 응답이 계속 짝을 찾지 못해 공격이 한 번도 통하지 않았다. 질의 포착이 응답 위조보다 앞서야 공격이 선다.
    4. 로그를 맞춰 보던 쇼핑몰 보안 담당자는 직원 PC의 DNS Query가 먼저 스니핑되었고, 같은 LAN의 공격자가 진짜 서버보다 빨리 위조 응답을 보냈음을 찾아냈다. 직원 PC는 그 응답을 정상으로 믿고 가짜 관리자 페이지로 접속했다. 질의 포착, 위조 응답, 정상 인식의 차례다.

    공격자는 먼저 질의를 스니핑하고, 진짜 서버보다 빨리 위조 응답을 보내며, 클라이언트가 이를 정상으로 믿으므로 정답은 4번이다.

    서버가 클라이언트로부터 받은 비밀키에 대하여 여러 번 해시 함수를 적용하여 얻은 해시 체인으로 일회용 비밀번호(OTP)를 생성하는 것은?

    1. 1. S/KEY 방식
    2. 2. 시간 동기화 방식
    3. 3. 이벤트 동기화 방식
    4. 4. 챌린지－응답 방식

    정답 1번

    🔍 보기별 해설
    1. S/KEY 방식은 비밀값에 해시 함수를 n번 거듭 적용해 해시 체인을 만들고 그 값을 거꾸로 하나씩 OTP로 쓴다. 해시를 여러 번 거쳐 일회용 비밀번호를 만드는 방식이므로 옳다(정답).
    2. 시간 동기화 방식은 사용자와 서버가 같은 비밀값과 현재 시각으로 짧은 주기마다 OTP를 새로 계산한다. 반복 해시 체인이 아니라 시각을 입력으로 쓰므로 옳지 않다.
    3. 이벤트 동기화 방식은 버튼을 누른 횟수 같은 카운터 값과 비밀값으로 OTP를 만든다. 양쪽 카운터를 맞추는 방식일 뿐 해시 체인을 거꾸로 쓰는 구조가 없으므로 옳지 않다.
    4. 챌린지－응답 방식은 서버가 보낸 임의의 질문 값에 사용자가 비밀값으로 계산한 답을 돌려준다. 매번 서버의 질문에 따라 답이 정해지므로 해시 체인으로 만든다고 보는 것은 옳지 않다.
    🧮 풀이
    1. 사내 서버 관리자가 S/KEY를 설정하며 비밀 문구에 해시를 100번 거듭 적용한 값을 서버에 등록했다. 첫 로그인 때는 99번 적용한 값을 입력했고, 서버는 이를 한 번 더 해시해 등록값과 같아지자 통과시킨 뒤 등록값을 그 값으로 바꿔 놓았다. 다음 로그인에는 98번째 값을 쓰며 해시 체인을 거꾸로 내려간다.
    2. 인터넷 뱅킹을 쓰는 쇼핑몰 회계 담당자가 OTP 앱에 30초마다 바뀌는 여섯 자리 숫자를 입력했다. 앱과 서버가 같은 비밀값과 현재 시각으로 각자 숫자를 계산하므로 휴대폰 시계가 크게 어긋나자 인증이 실패했다. 시간 동기화 방식은 시각을 입력으로 쓴다.
    3. 외주 개발자가 버튼식 OTP 토큰을 세 번 눌러 보기만 하고 로그인하지 않았다. 토큰의 카운터만 앞서 나가 서버와 차이가 벌어졌고, 서버가 허용 범위 안에서 카운터를 다시 맞춘 뒤에야 로그인이 되었다. 이벤트 동기화 방식은 누른 횟수를 입력으로 쓴다.
    4. 원격 서버에 접속하던 호스팅 엔지니어의 화면에 서버가 보낸 여섯 자리 질문 값이 떴다. 엔지니어가 그 값을 토큰에 입력해 나온 답을 돌려보내자 접속이 열렸고, 다음 접속 때는 전혀 다른 질문 값이 왔다. 챌린지－응답 방식은 서버의 질문마다 답이 달라진다.

    비밀키에 해시 함수를 거듭 적용한 해시 체인을 거꾸로 하나씩 OTP로 쓰는 것은 S/KEY 방식이므로 정답은 1번이다.

    WPA(Wi-Fi Protected Access)에 대한 설명으로 옳지 않은 것은?

    1. 1. WPA는 WEP의 보안 취약점을 보완하기 위해 제안되었다.
    2. 2. WPA의 TKIP는 암호 알고리즘으로 AES를 사용한다.
    3. 3. WPA-EAP는 인증을 위해서 RADIUS 서버를 이용할 수 있다.
    4. 4. WPA-PSK는 사전에 공유된 비밀키를 사용한다.

    정답 2번

    🔍 보기별 해설
    1. WPA는 WEP의 짧은 IV와 고정 키 같은 약점을 메우려고 Wi-Fi Alliance가 내놓은 무선 보안 규격이다. WEP 보완이 목적이었으므로 옳다.
    2. WPA의 TKIP는 기존 WEP 장비에서도 돌 수 있게 RC4 스트림 암호를 그대로 쓰면서 키를 패킷마다 바꾼다. AES 알고리즘을 쓰는 것은 WPA2의 CCMP이므로 옳지 않다(정답).
    3. WPA-EAP는 802.1X 인증을 써서 사용자마다 계정을 확인하는 기업용 방식이다. 이 인증을 처리하는 서버로 RADIUS를 쓸 수 있으므로 옳다.
    4. WPA-PSK는 AP와 단말이 미리 나눠 가진 비밀 문구로 인증하는 개인용 방식이다. 별도 인증 서버 없이 사전 공유키를 쓰므로 옳다.
    🧮 풀이
    1. 오래된 공유기를 쓰던 카페 사장이 손님 노트북으로 WEP 암호가 몇 분 만에 풀렸다는 말을 듣고 보안 설정을 WPA로 바꿨다. 패킷마다 키가 바뀌게 되어 같은 IV를 모아 키를 알아내는 공격이 더는 통하지 않았다. WPA는 WEP의 약점을 메우려고 나왔다.
    2. 구형 무선 카드를 쓰는 스타트업 직원이 WPA의 TKIP로는 접속되는데 WPA2-AES로 바꾸자 연결이 끊겼다. 구형 칩이 RC4 암호는 처리하지만 AES 알고리즘 연산은 지원하지 않았기 때문이다. TKIP는 RC4 위에서 동작한다.

    4. LEA는 국내에서 개발한 경량 블록 암호로 블록 크기는 128비트이고 키는 128·192·256비트 가운데 고를 수 있다. 블록과 키 길이 모두 바르므로 옳다.
    🧮 풀이
    1. 국내 금융 규격을 맞춰야 하는 쇼핑몰 결제 모듈 개발자가 SEED 256을 골라 256비트 키를 넣었다. 암호화된 결과는 키 길이와 상관없이 16바이트 블록 단위로 잘려 나왔다. SEED의 블록은 128비트로 같고 키 길이만 달라진다.
    2. 배송 추적용 IoT 태그 펌웨어를 짜던 스타트업 개발자가 HIGHT를 넣고 입력 버퍼를 16바이트로 잡았다. 시험해 보니 암호화가 8바이트 단위로 이루어져 버퍼를 64비트 블록에 맞게 고쳐야 했다. HIGHT는 128비트 키에 64비트 블록을 쓴다.
    3. 거래처 시스템과 연동하던 백엔드 개발자가 DES 라이브러리 설정에서 블록 8바이트, 라운드 16이라는 값을 보았다. 키가 짧아 무차별 대입에 약하다는 점 때문에 개발자는 연동 방식을 3DES나 AES로 바꾸는 일정을 잡았다. DES는 64비트 블록 16라운드 구조다.
    4. 모바일 앱 데이터 암호화를 맡은 개발자가 LEA를 고르고 키 길이를 192비트로 설정했다. 블록은 16바이트로 그대로였고 키 길이만 128·192·256비트 가운데서 바꿀 수 있었다. LEA는 128비트 블록을 쓰는 국산 경량 암호다.

    HIGHT는 128비트 키를 쓰지만 블록 크기는 64비트인데 128비트 블록 암호라고 했으므로 정답은 2번이다.

    HMAC에 대한 설명으로 옳지 않은 것은?

    1. 1. IP 보안에서 메시지 인증 목적으로 사용된다.
    2. 2. MD5, SHA-1, RIPEMD-160과 같은 해시 함수를 내장하고 있다.
    3. 3. 비밀키를 적용한 블록 암호화와 해시 함수를 사용해서 결과를 산출한다.
    4. 4. IEEE 802.11i의 의사 난수 생성 과정에 사용된다.

    정답 3번

    🔍 보기별 해설
    1. HMAC은 비밀키와 해시 함수를 엮어 메시지 인증 코드를 만드는 방식이다. IP 보안(IPSec)의 AH와 ESP가 무결성과 출처 인증에 HMAC을 쓰므로 옳다.
    2. HMAC은 특정 해시에 묶이지 않고 MD5, SHA-1, RIPEMD-160 같은 해시 함수를 그대로 넣어 쓰는 구조다. 넣은 해시에 따라 HMAC-SHA-1처럼 이름을 붙이므로 옳다.
    3. HMAC은 키를 내부·외부 패딩과 섞어 해시 함수를 두 번 돌릴 뿐 블록 암호를 쓰지 않는다. 블록 암호로 인증값을 만드는 것은 CMAC 같은 방식이므로 옳지 않다(정답).
    4. IEEE 802.11i는 PTK 같은 키를 뽑는 의사 난수 함수를 HMAC-SHA-1로 구성한다. 무선 랜의 키 생성 과정에 HMAC이 쓰이므로 옳다.
    🧮 풀이
    1. 두 데이터센터를 IPSec으로 잇던 호스팅 엔지니어가 ESP 무결성 알고리즘으로 HMAC-SHA-256을 골랐다. 중간에서 바이트 하나가 바뀐 패킷은 수신 측이 계산한 인증값과 달라 그대로 버려졌다. IP 보안이 메시지 인증에 HMAC을 쓴다.
    2. API 서명 기능을 만들던 백엔드 개발자가 처음에는 HMAC-MD5로 짰다가 해시만 SHA-1로, 다시 RIPEMD-160으로 바꿔 시험했다. 키를 섞는 바깥 구조는 그대로 두고 안의 해시 함수만 바꿔도 서명이 제대로 만들어졌다. HMAC은 해시를 골라 넣는 구조다.
    3. 웹훅 서명을 구현하던 개발자가 HMAC 안에 AES 블록 암호를 넣는 줄 알고 키를 16바이트 블록으로 쪼개 두었다. 표준 문서를 열어 보니 키를 ipad·opad와 XOR한 뒤 해시 함수만 두 번 돌리는 방식이어서 쪼갠 코드를 지웠다. 블록 암호 기반 인증은 CMAC이다.
    4. WPA2 공유기를 시험하던 네트워크 엔지니어가 4-way 핸드셰이크에서 PTK가 만들어지는 과정을 추적했다. 사전 공유키와 두 난수, 두 MAC 주소를 넣은 의사 난수 함수가 HMAC-SHA-1을 되풀이해 키를 뽑아냈다. IEEE 802.11i 키 생성에 HMAC이 쓰인다.

    HMAC은 비밀키와 해시 함수만으로 인증값을 만들 뿐 블록 암호를 쓰지 않으므로 블록 암호화를 쓴다는 설명이 틀렸다. 정답은 3번이다.

    DNSSEC(DNS Security Extensions)에 대한 설명으로 옳지 않은 것은?

    1. 1. DNS 응답 메시지에 대한 기밀성을 제공한다.
    2. 2. DNS 데이터에 공개키 기반 전자서명을 추가하여 데이터의 무결성을 제공한다.
    3. 3. DNS 응답 수신자(resolver)는 수신한 데이터에 대한 서명을 검증한다.
    4. 4. DNSSEC는 DNS 캐시 포이즈닝 공격을 방어하도록 설계되었다.

    정답 1번

    🔍 보기별 해설
    1. DNSSEC는 DNS 응답에 전자서명을 붙여 출처와 무결성을 증명할 뿐 응답 내용을 암호화하지 않는다. 누구나 응답을 읽을 수 있어 기밀성을 제공한다는 설명은 옳지 않다(정답).
    2. DNSSEC는 존의 레코드마다 개인키로 만든 RRSIG 서명을 붙여 둔다. 받는 쪽이 공개키로 서명을 검증해 레코드가 바뀌지 않았음을 알 수 있으므로 옳다.
    3. DNSSEC를 쓰는 resolver는 응답에 딸린 RRSIG를 DNSKEY로 검증하고 상위 존까지 신뢰 사슬을 따라간다. 서명 검증은 응답을 받은 resolver가 맡으므로 옳다.
    4. DNS 캐시 포이즈닝은 위조 응답을 캐시에 심는 공격이다. DNSSEC는 서명이 맞지 않는 응답을 걸러 위조 레코드가 캐시에 들어가지 못하게 하려고 설계되었으므로 옳다.
    🧮 풀이
    1. 고객 도메인에 DNSSEC를 켠 호스팅 엔지니어가 카페 와이파이에서 그 도메인 질의를 캡처했다. 응답 레코드와 서명값이 평문 그대로 보여 손님이 어떤 사이트를 찾는지 누구나 읽을 수 있었다. DNS 응답을 숨기려면 DoH 같은 별도 암호화가 필요하다.
    2. 쇼핑몰 도메인을 관리하는 운영자가 DNS 관리 화면에서 DNSSEC 서명을 켜자 A 레코드 옆에 RRSIG 레코드가 새로 생겼다. 이 서명은 존의 개인키로 만들어져 레코드가 조금만 바뀌어도 검증에 실패한다. 공개키 서명으로 무결성을 지킨다.
    3. 사내 캐시 DNS 서버에 검증 기능을 켠 스타트업 인프라 담당자가 서명이 깨진 시험 도메인을 질의했다. resolver는 RRSIG 검증에 실패하자 주소 대신 SERVFAIL을 돌려주었다. 서명 검증은 응답을 받는 resolver가 한다.
    4. 공격자가 쇼핑몰 도메인에 대한 위조 응답을 대량으로 보내 캐시를 오염시키려 했다. DNSSEC 검증을 켠 resolver는 서명이 없는 위조 응답을 모두 버렸고 진짜 주소만 캐시에 남았다. DNS 캐시 포이즈닝을 막으려는 것이 DNSSEC의 목적이다.

    DNSSEC는 전자서명으로 DNS 데이터의 출처와 무결성을 보장할 뿐 응답을 암호화하지 않아 기밀성은 없으므로 정답은 1번이다.

    하트블리드(Heartbleed)에 대한 다음 설명의 (가)와 (나)에 들어갈 내용을 바르게 연결한 것은?

    TLS를 구현하기 위한 오픈 소스인 OpenSSL에 내재된 버그로, (가) 프로토콜의 요청을 받은 컴퓨터에서 적절한 (나) 이 이루어지지 않아서 피해자가 의도하지 않은 내용이 응답 패킷의 페이로드에 복사되어 공격자에게 전송될 수 있다. (가) (나)

    1. 1. Handshake 페이로드 길이 확인
    2. 2. Handshake 사용자 인증
    3. 3. Heartbeat 페이로드 길이 확인
    4. 4. Heartbeat 사용자 인증

    정답 3번

    🔍 보기별 해설
    1. 하트블리드는 Handshake가 아니라 Heartbeat 확장의 요청 처리에서 생긴 OpenSSL 버그다. 페이로드 길이 확인이 빠졌다는 (나)는 들어맞아도 (가)가 어긋나므로 옳지 않다.
    2. 하트블리드가 노린 것은 Handshake가 아니라 연결 유지를 묻는 Heartbeat 메시지다. 원인도 사용자 인증 누락이 아니라 길이 값을 검사하지 않은 데 있으므로 옳지 않다.
    3. 하트블리드는 Heartbeat 요청에 적힌 페이로드 길이를 실제 길이와 대조하지 않은 OpenSSL 버그다. 공격자가 길이를 부풀리면 서버 메모리가 최대 64KB까지 응답에 실려 나가므로 옳다(정답).
    4. 하트블리드가 Heartbeat 요청을 노린 공격이라는 점은 들어맞는다. 그러나 문제는 사용자 인증이 아니라 페이로드 길이 확인을 빠뜨린 데 있으므로 옳지 않다.
    🧮 풀이
    1. 보안 점검을 맡은 호스팅 엔지니어가 TLS Handshake 단계의 메시지를 하나하나 조작해 보았지만 서버 메모리는 새지 않았다. 같은 서버에 길이를 부풀린 Heartbeat 요청을 보내자 그제야 응답에 메모리 내용이 섞여 나왔다. 하트블리드는 Handshake가 아닌 Heartbeat의 결함이다.
    2. 로그인 화면이 없는 쇼핑몰 이미지 서버를 운영하던 개발자가 인증과 무관하니 하트블리드도 상관없다고 여겼다. 그런데 공격자는 Heartbeat 요청 하나로 서버 메모리의 개인키 조각을 빼내 갔다. 원인은 Handshake나 사용자 인증이 아니라 길이 확인 누락이다.
    3. 실제로는 1바이트만 담은 Heartbeat 요청에 공격자가 페이로드 길이를 64KB로 적어 쇼핑몰 웹 서버에 보냈다. 패치 전 OpenSSL은 적힌 길이만큼 메모리를 복사해 돌려주었고 응답에는 다른 손님의 세션 쿠키가 섞여 있었다. 페이로드 길이 확인이 빠진 하트블리드다.
    4. 취약점 보고서를 받은 스타트업 CTO가 Heartbeat 요청에 사용자 인증을 붙이면 막을 수 있다고 생각했다. 하지만 인증된 사용자도 길이를 부풀린 요청으로 메모리를 빼낼 수 있어 결국 OpenSSL을 1.0.1g로 올려 길이 검사를 넣었다. 핵심은 인증이 아니라 길이 확인이다.

    하트블리드는 OpenSSL이 Heartbeat 요청의 페이로드 길이를 확인하지 않아 서버 메모리가 응답에 실려 나간 버그이므로 정답은 3번이다.

    SSH(Secure Shell)에 대한 설명으로 옳지 않은 것은?

    1. 1. SSH는 안전한 원격 로그온 기능을 제공하기 위해 설계되었다.
    2. 2. 사용자 인증 프로토콜을 통해 사용자가 서버에게 인증받는다.
    3. 3. 포트 전달을 통해 임의의 안전하지 않은 TCP 연결을 안전한 SSH 연결로 변환시킬 수 있다.
    4. 4. 전송 계층 프로토콜은 하나의 SSH 연결을 여러 개의 논리적 통신 채널로 다중화한다.

    정답 4번

    🔍 보기별 해설
    1. SSH는 Telnet·rlogin처럼 평문으로 오가던 원격 접속을 암호화해 안전한 원격 로그온을 제공하려고 만들어졌다. 설계 목적을 바르게 말했으므로 옳다.
    2. SSH 사용자 인증 프로토콜은 전송 계층 프로토콜이 암호 통로를 연 뒤 비밀번호나 공개키로 사용자를 서버에 인증한다. 사용자가 서버에게 인증받는 단계이므로 옳다.
    3. SSH 포트 전달은 다른 TCP 응용의 연결을 SSH 연결 안에 넣어 실어 나른다. 평문으로 오가던 TCP 연결도 암호화된 통로를 지나게 되므로 옳다.
    4. 하나의 SSH 연결을 여러 논리 채널로 나누어 쓰는 것은 연결 프로토콜이 맡는 일이다. 전송 계층 프로토콜은 서버 인증과 암호화·무결성을 맡을 뿐이어서 옳지 않다(정답).
    🧮 풀이
    1. Telnet으로 서버에 접속하던 호스팅 고객이 카페 와이파이에서 비밀번호를 도청당했다. 엔지니어가 Telnet을 막고 SSH로 바꾸자 같은 망에서 캡처한 패킷에는 알아볼 수 없는 암호문만 남았다. SSH는 안전한 원격 로그온을 위해 설계되었다.
    2. 배포 서버에 접속하는 백엔드 개발자가 비밀번호 대신 공개키를 서버에 등록해 두었다. 암호화 통로가 먼저 열린 뒤 서버가 개발자의 개인키 서명을 검증하자 셸이 열렸다. 이 과정을 맡는 것이 SSH 사용자 인증 프로토콜이다.
    3. 외부에 열면 안 되는 데이터베이스를 쓰던 스타트업 개발자가 ssh -L 5432:localhost:5432 로 포트 전달을 걸었다. 노트북의 5432번으로 보낸 평문 TCP 연결이 SSH 통로 안에 실려 서버로 건너가 암호화된 채 오갔다. 이것이 SSH 포트 전달이다.
    4. 서버 한 대에 SSH로 접속한 엔지니어가 같은 연결 안에서 셸 창 두 개와 파일 전송을 동시에 열었다. 세 작업은 연결 프로토콜이 나눈 논리 채널로 따로 흘렀고 전송 계층은 그 아래에서 암호화만 맡았다. 다중화는 연결 프로토콜의 일이다.

    SSH에서 하나의 연결을 여러 논리 채널로 다중화하는 것은 연결 프로토콜이고 전송 계층은 서버 인증과 암호화를 맡으므로 정답은 4번이다.

    다음은 사용자 A와 B가 Diffie-Hellman 알고리즘에 의한 키 교환을 시도하려는 도중에 발생한 중간자 공격의 개념을 도시한 것이다. 공격자가 A와의 공유비밀키 KA와 B와의 공유비밀키 KB를 산출하는 계산식을 바르게 연결한 것은? (단, p는 소수, g는 p의 원시근, x, y, a, b는 p보다 작은 임의의 양의 정수)

    KA KB

    1. 1. R1a mod p R2b mod p
    2. 2. R1b mod p R2a mod p
    3. 3. R2a mod p R1b mod p
    4. 4. R2b mod p R1a mod p

    정답 2번

    🔍 보기별 해설
    1. R1a mod p는 A가 보낸 R1에 공격자가 B에게 쓴 지수 a를 올린 값이라 A가 계산한 키와 다르다. R2b mod p도 같은 이유로 B의 키와 어긋나므로 옳지 않다.
    2. 공격자는 A에게 g의 b제곱을 건넸으므로 A와의 키는 R1b mod p, B에게 g의 a제곱을 건넸으므로 B와의 키는 R2a mod p다. 각 상대가 계산한 키와 똑같아지므로 옳다(정답).
    3. R2a mod p는 B와 나눌 키라서 KA 자리에 올 수 없고, R1b mod p는 A와 나눌 키라서 KB 자리에 올 수 없다. 두 값을 맞바꿔 적었으므로 옳지 않다.
    4. R2b mod p와 R1a mod p는 상대의 공개값에 그 상대에게 보내지 않은 지수를 올린 값이다. A·B 어느 쪽이 계산한 키와도 같아지지 않으므로 옳지 않다.
    🧮 풀이
    1. 암호 실습에서 공격자 역할을 맡은 개발자가 A에게 g의 b제곱을 보내 놓고 A의 공개값 R1에 지수 a를 올려 R1a mod p를 계산했다. A가 자기 쪽에서 구한 g의 xb제곱과 값이 달라 A가 보낸 암호문을 하나도 풀지 못했다. 상대에게 건넨 지수를 써야 키가 같아진다.
    2. 중간에 숨어든 공격자가 카페 와이파이에서 A의 R1을 가로채 A에게는 g의 b제곱을, B의 R2를 가로채 B에게는 g의 a제곱을 보냈다. 그 뒤 R1b mod p로 A와의 키를, R2a mod p로 B와의 키를 계산해 양쪽 암호문을 풀고 다시 암호화해 넘겼다. 인증 없는 Diffie-Hellman이 중간자 공격에 뚫리는 이유다.
    3. 보안 교육 자료를 만들던 호스팅 엔지니어가 KA 칸에 R2a mod p, KB 칸에 R1b mod p를 적었다. 시뮬레이터로 돌려 보니 공격자가 A와 B의 암호문을 서로 바뀐 키로 풀려다 둘 다 실패했다. 각 상대의 공개값과 그 상대에게 준 지수를 짝지어야 한다.
    4. 중간자 공격 코드를 짜던 신입 개발자가 KA를 R2b mod p로, KB를 R1a mod p로 계산하게 만들었다. 결과값은 A의 g의 xb제곱과도, B의 g의 ya제곱과도 달라 가로챈 메시지가 모두 깨져 보였다. 공개값과 지수를 동시에 엇갈리게 쓴 탓이다.

    공격자는 A의 공개값 R1에 A에게 보낸 지수 b를, B의 공개값 R2에 B에게 보낸 지수 a를 올려 키를 만들므로 정답은 2번이다.

    정보보안 3대 요소 중 서비스 거부(Denial of Service) 공격의 침해 대상은?

    1. 1. 가용성
    2. 2. 기밀성
    3. 3. 무결성
    4. 4. 익명성

    정답 1번

    🔍 보기별 해설
    1. 가용성은 인가된 사용자가 필요한 때에 정보와 서비스를 쓸 수 있도록 보장하는 성질이다. 서비스 거부 공격은 자원을 고갈시켜 정상 사용자의 이용을 막으므로 침해 대상으로 옳다(정답).
    2. 기밀성은 허가받지 않은 사람이 정보를 읽지 못하게 막는 성질이다. 서비스 거부 공격은 내용을 엿보는 것이 아니라 서비스를 멈추게 하는 데 목적이 있으므로 침해 대상으로 옳지 않다.
    3. 무결성은 정보가 허가 없이 바뀌거나 지워지지 않도록 지키는 성질이다. 서비스 거부 공격은 데이터를 고치기보다 접속 자체를 막으므로 이를 침해 대상으로 보는 것은 옳지 않다.
    4. 익명성은 행위자의 신원을 드러내지 않는 성질로 기밀성·무결성·가용성의 3대 요소에 들지 않는다. 3대 요소 가운데 고르라는 물음에서 벗어난 보기이므로 옳지 않다.
    🧮 풀이
    1. 대학병원 전산실의 예약 서버에 봇넷이 초당 수만 건의 접속 요청을 쏟아붓는다. 환자들은 진료 예약 화면이 열리지 않아 전화 창구로 몰리고, 서버 안의 기록은 그대로인데 아무도 쓸 수가 없다. 필요할 때 쓸 수 있어야 한다는 가용성이 무너진 결과다.
    2. 은행 지점의 IT 직원이 고객 대출 서류 폴더를 암호화하고 열람 권한을 심사역 두 명에게만 준다. 창구 직원이 파일을 열려고 하면 접근 거부 창이 떠 내용을 읽지 못한다. 허가받은 사람만 읽게 하는 이 장치가 기밀성을 지킨다.
    3. 시청 정보통신과 주무관이 민원 처리 결과 파일마다 해시값을 계산해 따로 보관한다. 누군가 처리 날짜를 몰래 고치면 다시 계산한 해시값이 달라져 위변조가 곧바로 잡힌다. 내용이 바뀌지 않았음을 보장하는 무결성 관리다.
    4. 보건소 상담 게시판 운영자가 질문자의 이름을 가리고 닉네임으로만 글이 올라가게 설정한다. 상담 내용은 공개되지만 누가 썼는지는 남들이 알 수 없다. 이렇게 신원을 숨기는 익명성은 정보보안 3대 요소 목록 밖의 성질이다.

    서비스 거부 공격은 정상 사용자가 필요할 때 서비스를 쓰지 못하게 만들어 3대 요소 중 가용성을 침해하므로 정답은 1번이다.

    네트워크에서 서버의 작동과 서버가 제공하는 서비스 존재 여부를 확인하는 것은?

    1. 1. 스캐닝(scanning)
    2. 2. 스미싱(SMishing)
    3. 3. 스위칭(switching)
    4. 4. 스풀링(SPOOLing)

    정답 1번

    🔍 보기별 해설
    1. 스캐닝(scanning)은 대상 서버에 탐색 패킷을 보내 살아 있는지와 열린 포트를 알아내는 활동이다. 응답을 보고 어떤 서비스가 돌아가는지까지 파악하므로 옳다(정답).
    2. 스미싱(SMishing)은 문자메시지에 악성 링크를 넣어 앱 설치나 개인정보 입력을 꾀는 사기 수법이다. 사람을 속이는 공격일 뿐 서버의 동작과 서비스를 조사하는 일과는 다르므로 옳지 않다.
    3. 스위칭(switching)은 프레임의 목적지 주소를 보고 알맞은 포트로 내보내는 전달 기능이다. 장비가 트래픽을 나르는 일이지 서버에 어떤 서비스가 있는지 알아내는 활동은 아니므로 옳지 않다.
    4. 스풀링(SPOOLing)은 프린터처럼 느린 장치로 보낼 작업을 디스크에 잠시 쌓아 두었다가 차례로 처리하는 기법이다. 운영체제의 입출력 처리 방식이라 서버 탐색과 관계가 없으므로 옳지 않다.
    🧮 풀이
    1. 외주 보안 점검 기사가 승인을 받고 병원 서버 대역에 nmap을 돌린다. 결과표에 22번과 443번 포트가 열려 있고 각각 SSH와 웹 서비스가 응답한다고 나온다. 서버의 작동과 서비스 존재를 알아내는 이 작업이 스캐닝(scanning)이다.
    2. 지점 고객 한 명이 「택배 주소 확인」 문자 속 링크를 누르자 출처를 알 수 없는 앱이 깔린다. 그 앱이 문자 인증번호를 가로채 계좌 이체에 쓰이고, 은행 창구에 피해 신고가 들어온다. 문자로 시작되는 이 사기가 스미싱(SMishing)이다.
    3. 청사 전산실 스위치가 2번 포트로 들어온 프레임의 출발지 MAC을 주소 테이블에 적어 둔다. 다음에 그 주소로 가는 프레임이 오면 다른 포트에는 보내지 않고 2번 포트로만 내보낸다. 주소를 보고 길을 골라 주는 이 기능이 스위칭(switching)이다.
    4. 원무과 직원 열 명이 동시에 진료비 영수증 인쇄를 누르자 작업이 디스크의 대기열에 먼저 쌓인다. 프린터는 한 장씩 차례로 꺼내 출력하고 직원들은 기다리지 않고 다음 업무로 넘어간다. 이 대기 저장 방식이 스풀링(SPOOLing)이다.

    서버가 살아 있는지와 열린 포트로 어떤 서비스가 제공되는지 알아내는 활동은 스캐닝이므로 정답은 1번이다.

    응용계층 프로토콜로 옳지 않은 것은?

    1. 1. FTP(File Transfer Protocol)
    2. 2. SCTP(Stream Control Transmission Protocol)
    3. 3. SMTP(Simple Mail Transfer Protocol)
    4. 4. Telnet

    정답 2번

    🔍 보기별 해설
    1. FTP(File Transfer Protocol)는 클라이언트와 서버가 파일을 주고받게 해 주는 응용계층 프로토콜이다. 제어 연결과 데이터 연결을 TCP 위에서 따로 열어 쓰므로 응용계층으로 분류한 것은 옳다.
    2. SCTP(Stream Control Transmission Protocol)는 TCP·UDP와 나란히 놓이는 전송계층 프로토콜이다. 여러 스트림과 멀티호밍을 지원하며 종단 간 전달을 맡으므로 응용계층으로 본 것은 옳지 않다(정답).
    3. SMTP(Simple Mail Transfer Protocol)는 메일을 보내거나 메일 서버끼리 넘길 때 쓰는 응용계층 프로토콜이다. 기본 25번 포트로 TCP 연결을 맺고 명령과 응답을 주고받으므로 옳다.
    4. Telnet은 원격 호스트에 접속해 명령을 입력하는 가상 터미널용 응용계층 프로토콜이다. 23번 포트를 쓰며 내용을 평문으로 보내는 약점이 있지만 계층 분류로는 옳다.
    🧮 풀이
    1. 약제부 직원이 도매업체 서버에 FTP 프로그램으로 접속해 의약품 단가표를 내려받는다. 로그인 명령은 제어 연결로, 파일 본문은 따로 열린 데이터 연결로 오간다. 사용자가 직접 부리는 파일 전송 기능이라 FTP(File Transfer Protocol)는 응용계층에 놓인다.
    2. 통신 장비 업체 기사가 은행 전산센터 두 곳을 잇는 신호 연결에 SCTP를 설정한다. 회선 하나가 끊겨도 다른 주소로 바로 넘어가 데이터 전달이 이어진다. 응용 데이터를 실어 나르는 운반층 역할이므로 SCTP(Stream Control Transmission Protocol)는 전송계층에 속한다.
    3. 보건소 메일 서버가 외부 기관으로 가는 공문을 들고 상대 서버에 접속한다. HELO, MAIL FROM, RCPT TO 명령을 차례로 보내고 본문을 넘기자 상대 서버가 250 응답으로 받는다. 서버끼리 편지를 넘기는 이 대화 규칙이 응용계층의 SMTP다.
    4. 야간 당직 기사가 오래된 검사 장비에 Telnet으로 접속해 재시작 명령을 친다. 패킷을 떠 보니 입력한 계정과 비밀번호가 평문 그대로 보인다. 원격 터미널 서비스를 주는 Telnet은 응용계층에 있고 그래서 SSH로 바꾸라는 권고가 나온다.

    FTP·SMTP·Telnet은 사용자 서비스를 주는 응용계층 프로토콜이고 SCTP는 TCP·UDP와 같은 전송계층 프로토콜이므로 정답은 2번이다.

    IEEE 802.11 무선 랜에서 네트워크를 식별하기 위해 사용되는 것은?

    1. 1. OID(Object IDentifier)
    2. 2. SSID(Service Set IDentifier)
    3. 3. RFID(Radio Frequency IDentification)
    4. 4. NIDS(Network-based Intrusion Detection System)

    정답 2번

    🔍 보기별 해설
    1. OID(Object IDentifier)는 SNMP의 관리 정보 체계에서 관리 객체를 점으로 이은 숫자 경로로 가리키는 식별자다. 객체에 붙는 번호이지 무선 랜 네트워크의 이름이 아니므로 옳지 않다.
    2. SSID(Service Set IDentifier)는 802.11에서 하나의 서비스 세트, 곧 무선 네트워크를 다른 망과 구별하는 이름이다. 단말은 이 이름을 보고 접속할 망을 고르므로 옳다(정답).
    3. RFID(Radio Frequency IDentification)는 전파로 태그에 담긴 정보를 접촉 없이 읽어 물건이나 사람을 식별하는 기술이다. 태그를 알아보는 기술이지 무선 랜을 구별하는 값이 아니므로 옳지 않다.
    4. NIDS(Network-based Intrusion Detection System)는 네트워크 트래픽을 감시해 침입 징후를 찾아내는 보안 시스템이다. 공격을 탐지하는 장비이지 무선 네트워크를 가리키는 식별자가 아니므로 옳지 않다.
    🧮 풀이
    1. 네트워크 관리 서버를 운영하는 병원 담당자가 스위치의 가동 시간을 묻기 위해 1.3.6.1.2.1.1.3 값을 요청한다. 스위치 에이전트는 그 번호에 걸린 객체 값을 돌려준다. 관리 객체를 숫자 경로로 짚어 주는 이 번호가 OID(Object IDentifier)다.
    2. 시청 민원실에 공유기를 새로 단 주무관이 무선 네트워크 이름을 CityHall-Guest로 정한다. 방문객 휴대폰의 와이파이 목록에 그 이름이 뜨고, 직원망 이름과 나뉘어 보인다. 망을 구별해 주는 이 이름이 SSID(Service Set IDentifier)다.
    3. 병원 의료기기실 기사가 수액 펌프마다 태그를 붙이고 출입문에 리더기를 단다. 펌프가 문을 지나가면 리더기가 전파로 태그 번호를 읽어 위치 기록이 갱신된다. 이렇게 사물을 비접촉으로 알아보는 기술이 RFID(Radio Frequency IDentification)다.
    4. 은행 본점 보안팀이 인터넷 회선 앞단에 센서를 달아 지나가는 패킷을 복사해 분석한다. 특정 포트를 차례로 훑는 패턴이 잡히자 관제 화면에 경보가 울린다. 망 전체 흐름을 감시해 침입을 찾는 이 장비가 NIDS(Network-based Intrusion Detection System)다.

    IEEE 802.11 무선 랜에서 단말이 접속할 네트워크를 다른 무선망과 구별하는 이름은 SSID이므로 정답은 2번이다.

    한 번의 시스템 인증을 통하여 여러 정보 시스템에 재인증 절차 없이 접근할 수 있는 통합 로그인 기술은?

    1. 1. DRM
    2. 2. SSO
    3. 3. SET
    4. 4. PGP

    정답 2번

    🔍 보기별 해설
    1. DRM은 디지털 콘텐츠의 복제와 이용 권한을 통제하는 저작권 보호 기술이다. 콘텐츠를 누가 얼마나 쓰는지 관리할 뿐 여러 시스템 로그인을 하나로 묶지 않으므로 옳지 않다.
    2. SSO는 한 번 인증한 사용자가 연계된 여러 시스템에 다시 로그인하지 않고 들어가게 하는 통합 인증 기술이다. 인증 결과를 토큰 등으로 넘겨 재인증을 없애므로 옳다(정답).
    3. SET은 인터넷 신용카드 결제에서 카드 정보와 주문 정보를 보호하려고 만든 전자상거래 보안 프로토콜이다. 결제 안전을 위한 규약이지 통합 로그인 기술이 아니므로 옳지 않다.
    4. PGP는 전자우편을 암호화하고 전자서명을 붙여 기밀성과 인증을 주는 메일 보안 기술이다. 메일 내용을 지키는 도구일 뿐 여러 시스템 접속을 한 번에 여는 기술은 아니므로 옳지 않다.
    🧮 풀이
    1. 의학도서관 담당자가 구독한 전자 교과서에 DRM을 걸어 열람은 원내 PC에서만, 인쇄는 하루 열 쪽까지만 되게 설정한다. 파일을 USB로 옮긴 레지던트는 집에서 문서를 열지 못한다. 콘텐츠 사용 범위를 묶어 두는 장치가 DRM이다.
    2. 간호사가 출근해 병원 포털에 한 번 로그인한 뒤 전자의무기록, 처방 조회, 근무표 화면을 차례로 연다. 세 시스템 모두 아이디와 비밀번호를 다시 묻지 않고 바로 열린다. 한 번의 인증으로 여러 시스템을 쓰게 하는 이 방식이 SSO다.
    3. 카드사업부 개발자가 온라인 결제 시험 환경에 SET 방식을 적용해 본다. 가맹점 서버에는 주문 내용만, 카드사 서버에는 결제 정보만 전달되도록 이중 서명이 붙는다. 결제 정보를 지키는 이 규약이 SET이고 로그인과는 관계가 없다.
    4. 감염병 담당자가 역학조사 보고서를 질병관리청 담당자의 공개키로 암호화하고 자기 개인키로 서명해 메일로 보낸다. 받는 쪽은 서명을 검증해 보낸 사람을 알아보고 자기 개인키로만 본문을 연다. 메일을 이렇게 보호하는 도구가 PGP다.

    한 번의 인증으로 연계된 여러 정보 시스템에 재인증 없이 접근하게 하는 통합 로그인 기술은 SSO이므로 정답은 2번이다.

    스니핑(sniffing) 공격에 대한 보안 대책으로 옳지 않은 것은?

    1. 1. 원격 접속 시 SSH 사용
    2. 2. 웹 환경에서 HTTPS 사용
    3. 3. 스위치 대신 더미 허브 사용
    4. 4. 이메일 환경에서 S/MIME 사용

    정답 3번

    🔍 보기별 해설
    1. SSH는 원격 접속 때 계정 정보와 입력하는 명령을 모두 암호화해 보내는 프로토콜이다. 도청자가 패킷을 가로채도 평문을 얻지 못하므로 스니핑 대책으로 옳다.
    2. HTTPS는 HTTP 메시지를 TLS로 암호화해 웹 브라우저와 서버 사이의 통신을 보호한다. 로그인 폼이나 조회 결과가 패킷에 평문으로 남지 않으므로 스니핑 대책으로 옳다.
    3. 더미 허브는 받은 프레임을 모든 포트로 똑같이 뿌리는 장비다. 같은 허브에 물린 공격자가 남의 트래픽까지 쉽게 받아 보게 되어 대책은커녕 위험을 키우므로 옳지 않다(정답).
    4. S/MIME은 인증서를 이용해 전자우편 본문을 암호화하고 서명하는 표준이다. 메일이 중간에서 수집되어도 받는 사람의 개인키 없이는 내용을 읽기 어려우므로 스니핑 대책으로 옳다.
    🧮 풀이
    1. 협력업체 기사가 병원 서버를 원격으로 점검할 때 Telnet 대신 SSH 클라이언트로 접속한다. 같은 망에서 누가 패킷을 떠도 계정과 명령은 알아볼 수 없는 암호문으로만 남는다. 원격 접속 구간을 암호화해 엿보기를 막는 방법이다.
    2. 인터넷뱅킹 개발자가 로그인 페이지를 HTTP에서 HTTPS로 옮기고 서버 인증서를 설치한다. 카페 와이파이에서 누가 패킷을 모아도 아이디와 비밀번호 대신 암호문만 얻는다. 웹 통신을 TLS로 감싸 스니핑을 무력하게 만든 조치다.
    3. 예산이 빠듯한 보건지소가 고장 난 스위치를 창고에 있던 더미 허브로 바꿔 단다. 그 뒤 한 직원 PC에 깔린 패킷 수집 도구가 옆자리 진료 기록 전송까지 모두 받아 낸다. 모든 포트로 프레임을 뿌리는 장비가 도청을 쉽게 만든 결과다.
    4. 시청 감사관실 주무관이 인증서를 발급받아 감사 결과 메일에 S/MIME 암호화를 켠다. 메일이 중간 서버를 거치며 복사되더라도 받는 사람의 개인키 없이는 본문이 열리지 않는다. 메일 내용을 암호화해 엿보기를 막는 대책이다.

    스니핑은 암호화로 막는데 더미 허브는 모든 포트로 프레임을 뿌려 도청을 오히려 쉽게 하므로 대책이 될 수 없어 정답은 3번이다.

    블록체인에서 보유한 자산에 대한 지분율에 비례하여 의사결정 권한을 주는 합의 알고리즘은?

    1. 1. PoS(Proof of Stake)
    2. 2. PoW(Proof of Work)
    3. 3. PRNG(Pseudo-Random Number Generator)
    4. 4. PBFT(Practical Byzantine Fault Tolerance)

    정답 1번

    🔍 보기별 해설
    1. PoS(Proof of Stake)는 검증자가 보유하거나 예치한 자산의 지분에 따라 블록 생성과 검증 권한을 받는 합의 방식이다. 지분율에 비례해 의사결정 권한을 주므로 옳다(정답).
    2. PoW(Proof of Work)는 참여자가 많은 연산으로 조건에 맞는 해시값을 먼저 찾아 블록을 만드는 합의 방식이다. 권한이 계산 능력에서 나오고 지분율과는 상관이 없으므로 옳지 않다.
    3. PRNG(Pseudo-Random Number Generator)는 시드값에서 난수처럼 보이는 수열을 만드는 알고리즘이다. 난수를 뽑는 도구이지 블록체인 참여자 사이의 합의 방식이 아니므로 옳지 않다.
    4. PBFT(Practical Byzantine Fault Tolerance)는 노드들이 메시지를 여러 차례 주고받아 3분의 2를 넘는 동의가 모이면 결과를 확정하는 합의 방식이다. 투표가 노드 단위로 이루어져 지분율과 무관하므로 옳지 않다.
    🧮 풀이
    1. 의료 데이터 공유 블록체인에 참여한 병원 다섯 곳이 각각 토큰을 예치한다. 가장 많이 맡긴 병원이 다음 블록을 만들 확률도 가장 높게 배정되고, 적게 맡긴 곳은 차례가 드물게 온다. 맡긴 지분만큼 권한을 나누는 PoS(Proof of Stake) 방식이다.
    2. 채굴 업체가 고성능 그래픽카드 수백 장을 돌려 nonce를 바꿔 가며 해시값을 계산한다. 목표값보다 작은 해시를 먼저 찾아낸 쪽이 블록을 만들고 보상을 받는다. 계산 작업량으로 권한을 얻는 PoW(Proof of Work) 방식이다.
    3. 모바일 OTP 앱 개발자가 시드값을 넣은 생성기로 여섯 자리 숫자를 뽑아낸다. 같은 시드를 넣으면 같은 수열이 다시 나와 진짜 난수와는 성질이 다르다. 이 생성기가 PRNG(Pseudo-Random Number Generator)이며 블록체인 합의와는 관계가 없다.
    4. 은행 네 곳이 함께 운영하는 거래 장부에서 한 노드가 블록을 제안하자 나머지가 준비 메시지와 확정 메시지를 서로 돌린다. 세 노드 이상이 같은 값을 보내 오면 블록이 확정된다. 지분과 상관없이 노드 투표로 정하는 PBFT(Practical Byzantine Fault Tolerance)다.

    보유하거나 예치한 자산의 지분율에 비례해 블록 생성과 검증 권한을 주는 합의 알고리즘은 PoS이므로 정답은 1번이다.

    다음 랜(LAN)에서 ‘공격시스템’이 ARP 스푸핑(spoofing) 공격을 위해 (가), (나)에서 수행하는 작업을 ㄱ ～ ㄹ에서 찾아 바르게 연결한 것은? (단, MAC 주소는 24비트로 가정한다)

    ㄱ. 시스템1의 MAC 주소를 AA-AA-AA라고 알린다.

    ㄴ. 시스템2의 MAC 주소를 AA-AA-AA라고 알린다.

    ㄷ. 시스템1의 MAC 주소를 CC-CC-CC라고 알린다.

    ㄹ. 시스템2의 MAC 주소를 BB-BB-BB라고 알린다. (가) (나)

    1. 1. ㄴ ㄱ
    2. 2. ㄴ ㄷ
    3. 3. ㄹ ㄱ
    4. 4. ㄹ ㄷ

    정답 1번

    🔍 보기별 해설
    1. (가)는 ㄴ이다. 시스템1에게 시스템2의 MAC을 공격자 주소 AA-AA-AA라고 알려야 시스템1이 보내는 프레임이 공격시스템으로 오기 때문이다. (나)는 ㄱ이다. 시스템2에게 시스템1의 MAC을 같은 AA-AA-AA라고 알려야 반대 방향 프레임도 공격시스템을 지나기 때문이다. 두 칸이 모두 맞으므로 옳다(정답).

    ARP 스푸핑은 양쪽 모두에게 상대의 MAC이 공격자 주소 AA-AA-AA라고 속여 알려야 하므로 (가) ㄴ, (나) ㄱ이 되어 정답은 1번이다.
