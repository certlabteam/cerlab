    다음 정수 열에서 연속 부분합의 최댓값은?

    1, －3, 2, 4, －1, 5, －3, 2, 1, －2

    1. 1. 5
    2. 2. 8
    3. 3. 10
    4. 4. 15

    정답 3번

    🔍 보기별 해설
    1. 세 번째 수 2부터 여섯 번째 수 5까지의 연속 합은 2+4−1+5=10이다. 다른 구간보다 크므로 옳다(정답).
    🧮 풀이
    1. ① 첫 두 수 1과 −3을 지나면 새 구간을 시작하는 편이 낫다. 세 번째 수 2에서 현재 연속합을 2로 다시 잡는다.
    2. → 현재 2, 최대 2
    3. ↓
    4. ② 이어 4를 더해 6, −1을 더해 5, 5를 더해 10을 얻는다. 이 네 수는 원래 배열에서 끊기지 않고 이어져 있다.
    5. → 2+4−1+5=10
    6. ↓
    7. ③ 이후 −3, 2, 1, −2를 더해 보아도 앞서 기록한 10을 넘지 못한다. 모든 끝 위치를 확인한 뒤 최대값을 남긴다.
    8. → 10

    연속 구간 2+4−1+5의 합이 10으로 최대여서 정답은 3번이다.

    이진 탐색(binary search) 알고리즘에 대한 설명으로 옳지 않은 것은?

    1. 1. 탐색 범위가 절반씩 줄어든다.
    2. 2. 탐색할 데이터는 순서 없이 저장되어 있다.
    3. 3. 시간 복잡도는 O (logn) 이다.
    4. 4. 1,000개의 데이터가 존재하는 경우, 최대 10회의 탐색으로 완료된다.

    정답 2번

    🔍 보기별 해설
    1. 이진 탐색은 정렬된 배열의 가운데 값과 비교할 때마다 찾는 값이 있을 수 있는 쪽 절반만 남긴다. 탐색 범위가 반씩 줄어드므로 옳다.
    2. 이진 탐색은 자료가 키 순서대로 정렬되어 있어야 한다. 순서 없이 저장해도 된다는 설명은 옳지 않다(정답).
    3. 탐색 범위를 매번 절반으로 줄여 필요한 비교 단계 수가 입력 크기 n의 로그에 비례한다. 시간복잡도가 O(log n)이므로 옳다.
    4. 1000개 자료를 반씩 줄이면 10번 안팎의 비교 단계로 한 원소까지 좁힐 수 있다. 최대 10회의 탐색이라는 설명은 옳다.
    🧮 풀이
    1. 정렬된 1부터 16까지 숫자에서 14를 찾는다. 가운데 8과 비교해 왼쪽 8개를 버리고 오른쪽 구간만 본다. 다음 비교에서도 절반을 버려 후보가 빠르게 줄어든다.
    2. 배열 [9,1,7,3,5]의 가운데 7보다 찾는 값 9가 크다고 오른쪽만 보면 첫 칸의 9를 놓친다. 값들이 정렬되지 않아 가운데 비교로 어느 절반을 버려야 할지 알 수 없다. 정렬 조건이 필요하다.
    3. 자료가 1024개이면 절반씩 줄인 뒤 512·256·128개 순으로 후보가 감소한다. 약 10단계를 지나면 한 칸 수준이 된다. 입력이 두 배가 되어도 비교 단계는 대략 하나만 늘어난다.
    4. 정렬된 1000개 자료를 처음 비교한 뒤 후보를 500개, 다음에는 250개로 줄인다. 계속 반씩 줄이면 열 번째 비교 무렵에는 한 위치에 도달한다. 2의 10제곱이 1024라는 점으로 비교 단계를 가늠한다.

    이진 탐색은 정렬된 자료에서만 절반을 버릴 수 있으므로 정답은 2번이다.

    동적 계획법(dynamic programming)으로 설계된 알고리즘의 동작 방식에 대한 설명으로 옳지 않은 것은?

    1. 1. 큰 문제를 작은 문제로 나눌 수 있어야 한다.
    2. 2. 작은 문제들이 반복해서 사용되며, 이 작은 문제들의 결괏값을 저장해 두고 활용한다.
    3. 3. 상향식(bottom-up) 접근 방식 또는 하향식(top-down) 접근 방식으로 구현할 수 있다.
    4. 4. 메모하기(memoization) 방법을 활용하여 연산과 탐색이 증가하고 실행속도가 저하된다.

    정답 4번

    🔍 보기별 해설
    1. 동적 계획법은 전체 문제를 반복되는 더 작은 상태로 나눌 수 있을 때 적용한다. 구조 조건이 맞으므로 옳다.
    2. 같은 부분 문제가 다시 필요하면 저장해 둔 결괏값을 이용한다. 중복 작업을 줄이는 방식이므로 옳다.
    3. 동적 계획법은 작은 상태부터 표를 채우거나 큰 상태에서 내려가며 필요한 값을 저장할 수 있다. 두 구현 방식이 가능하므로 옳다.
    4. 메모이제이션은 이미 계산한 상태를 재사용해 연산 횟수를 줄인다. 계산과 탐색이 증가해 느려진다는 설명은 옳지 않다(정답).
    🧮 풀이
    1. F(6)을 구할 때 F(5)와 F(4)가 필요하고 두 계산에는 다시 F(3)이 등장한다. 큰 문제를 작은 F(k) 상태로 나누어 풀 수 있다. 이 구조가 동적 계획법의 출발점이다.
    2. F(3)을 처음 계산해 배열의 세 번째 칸에 저장한다. F(5)를 구할 때 다시 F(3)이 필요하면 배열 값을 바로 읽는다. 같은 재귀 가지를 다시 펼치지 않는다.
    3. 상향식 구현은 F(0)부터 차례로 표를 채워 F(6)에 도달한다. 하향식 구현은 F(6)에서 필요한 작은 상태를 호출하되 결과를 캐시에 남긴다. 두 방식 모두 부분 문제의 해를 재사용한다.
    4. 순수 재귀 피보나치 계산은 F(3)을 여러 번 다시 부른다. 메모이제이션을 적용하면 첫 계산 뒤 저장된 값을 읽어 반복 호출을 줄인다. 추가 저장 공간을 쓰는 대신 일반적으로 실행 작업이 감소한다.

    메모이제이션은 중복 계산을 줄이므로 실행속도를 떨어뜨린다는 ④가 정답이다.

    다음 정렬 알고리즘 중에서 동일한 최악 시간 복잡도를 가진 것만을 모두 고르면?

    ㄱ. 선택 정렬(selection sort)

    ㄴ. 삽입 정렬(insertion sort)

    ㄷ. 힙 정렬(heap sort)

    ㄹ. 퀵 정렬(quick sort)

    1. 1. ㄱ, ㄴ, ㄷ
    2. 2. ㄱ, ㄴ, ㄹ
    3. 3. ㄱ, ㄷ, ㄹ
    4. 4. ㄴ, ㄷ, ㄹ

    정답 2번

    🔍 보기별 해설
    1. 선택 정렬은 매 단계 아직 정렬되지 않은 구간을 끝까지 비교해 최소 원소를 찾아낸다. 최악 시간은 O(n²)이다.
    2. 삽입 정렬은 입력이 역순일 때 새 값을 앞의 정렬된 구간에 넣으려고 많은 원소를 비교하고 이동한다. 최악 시간은 O(n²)이다.
    3. 힙 정렬은 삭제 뒤 재조정을 원소마다 수행한다. 최악 시간은 O(n log n)으로 다른 세 정렬과 다르다.
    4. 퀵 정렬은 선택한 피벗이 매번 최솟값이나 최댓값이어서 분할이 한쪽으로 치우칠 수 있다. 최악 시간은 O(n²)이다.
    🧮 풀이
    1. 역순 배열의 첫 위치를 고른 뒤 나머지 전체에서 최솟값을 찾는다. 다음 위치에서도 남은 원소를 다시 끝까지 살핀다. 비교 횟수가 n(n−1)/2 수준으로 늘어난다.
    2. 역순 [4,3,2,1]에 삽입 정렬을 적용한다. 3은 4를 밀고, 2는 앞의 두 값을 밀고, 1은 세 값을 밀어 넣는다. 밀기 횟수가 1+2+3으로 누적되어 입력이 길어지면 제곱 차수로 증가한다.
    3. 최대힙에서 루트를 꺼낸 뒤 끝값을 올려 힙 높이만큼 아래로 조정한다. 이 작업을 n개 원소에 반복한다. 한 번의 조정은 log n 단계이므로 전체 최악도 n log n 차수다.
    4. 오름차순 배열에서 퀵 정렬이 매번 맨 끝의 최대값을 피벗으로 잡는다. 한쪽 분할은 비고 다른 쪽에는 n−1개가 남는다. 비교량이 n+(n−1)+…+1로 누적된다.

    정답은 2번이다.

    그림과 같은 과정을 포함하여 정렬을 실행하는 알고리즘은?

    1. 1. 퀵 정렬
    2. 2. 셸 정렬(shell sort)
    3. 3. 기수 정렬(radix sort)
    4. 4. 병합 정렬(merge sort)

    정답 4번

    🔍 보기별 해설
    1. 퀵 정렬은 피벗을 기준으로 배열을 두 쪽으로 분할해 정렬한다. 정렬된 두 묶음을 차례로 합치는 그림과 다르므로 옳지 않다.
    2. 셸 정렬은 간격을 둔 원소끼리 삽입 정렬을 하며 간격을 줄인다. 두 정렬 구간을 병합하는 절차가 아니므로 옳지 않다.
    3. 기수 정렬은 자리값을 기준으로 원소를 반복 분배·수집한다. 정렬된 두 묶음의 값 비교 병합과 다르므로 옳지 않다.
    4. 병합 정렬은 작은 정렬 구간 둘을 순서대로 결합해 더 큰 정렬 구간을 만든다. 그림의 과정과 같으므로 옳다(정답).
    🧮 풀이
    1. 배열 [4,1,3,2]에서 피벗 3을 기준으로 작은 값과 큰 값을 분할한다. 각 부분 배열을 다시 정렬하지만 이미 정렬된 두 배열을 앞에서부터 비교해 합치는 그림의 핵심 단계는 아니다.
    2. 배열에서 간격 4인 원소끼리 먼저 비교한 뒤 간격을 2, 1로 줄인다. 각 간격의 부분열을 삽입 방식으로 정렬한다. 정렬된 왼쪽 묶음과 오른쪽 묶음을 하나로 합치는 절차와 다르다.
    3. 숫자 23·11·35를 일의 자리 기준 통에 나누고 다시 십의 자리 기준으로 분배한다. 각 자리의 분배 순서를 이용해 전체를 정렬한다. 두 정렬 구간을 직접 비교하며 병합하지 않는다.
    4. 왼쪽 묶음 [1,4]와 오른쪽 묶음 [2,3]의 맨 앞을 비교한다. 1을 먼저 쓰고 2, 3, 4를 이어 쓰면 [1,2,3,4]가 된다. 두 정렬 구간이 하나의 정렬된 구간으로 합쳐진다.

    정렬된 두 묶음을 합쳐 큰 묶음을 만드는 그림은 병합 정렬이므로 정답은 4번이다.

    다음과 같은 배열 A에서 A[0]부터 삽입 연산을 차례대로 적용하여 이진 탐색 트리 T를 생성한 후, T를 전위(preorder) 순회 방법으로 방문한 값들을 배열 B에 B[0]부터 순차적으로 저장한 결과는?

    A[] ＝ 40, 20, 30, 10

    1. 1. B[] ＝ 10, 20, 30, 40
    2. 2. B[] ＝ 10, 30, 20, 40
    3. 3. B[] ＝ 40, 20, 10, 30
    4. 4. B[] ＝ 40, 30, 20, 10

    정답 3번

    🔍 보기별 해설
    1. 40을 루트로 두면 20은 왼쪽, 10은 20의 왼쪽, 30은 20의 오른쪽에 놓인다. 전위 순회가 40·20·10·30이므로 옳다(정답).
    🧮 풀이
    1. ① 첫 원소 40을 루트에 놓는다. 다음 20은 40보다 작아 왼쪽 자식이 된다. 이때 루트의 오른쪽 자리는 아직 비어 있고 이후 값들도 루트 40보다 작다.
    2. → 루트40, 왼쪽20
    3. ↓
    4. ② 30은 40보다 작고 20보다 커서 20의 오른쪽에 들어간다. 10은 40과 20보다 작아 20의 왼쪽에 들어간다. 두 값의 부모가 모두 20이라는 점을 먼저 정해야 순회 순서가 분명해진다.
    5. → 20의 왼쪽10·오른쪽30
    6. ↓
    7. ③ 전위 순회는 루트를 먼저 읽고 왼쪽 서브트리의 루트와 자식을 읽는다. 오른쪽 서브트리는 비어 있다.
    8. → 40,20,10,30

    삽입 후 트리를 전위 순회하면 40·20·10·30이므로 정답은 3번이다.

    30억 개의 정수를 갖는 배열에서 20개의 정수를 제외한 나머지가 모두 정렬되어 있다면, 이 배열을 가장 빠르게 정렬할 수 있는 알고리즘은?

    1. 1. 퀵 정렬
    2. 2. 선택 정렬
    3. 3. 병합 정렬
    4. 4. 삽입 정렬

    정답 4번

    🔍 보기별 해설
    1. 퀵 정렬은 피벗 분할을 반복하며 거의 정렬된 입력이라고 늘 적은 작업을 보장하지 않는다. 이 조건의 최적 선택으로는 옳지 않다.
    2. 선택 정렬은 이미 정렬된 값도 남은 구간 끝까지 비교해 최솟값을 찾는다. 30억 개의 거의 정렬된 자료에 옳지 않다.
    3. 병합 정렬은 입력이 거의 정렬되어도 분할과 병합을 전체 원소에 수행한다. O(n log n) 작업이 필요해 옳지 않다.
    4. 삽입 정렬은 현재 원소를 앞의 정렬된 구간에서 제자리에 넣는다. 어긋난 원소가 극히 적으면 이동이 적어 옳다(정답).
    🧮 풀이
    1. 피벗을 끝값으로 고르는 퀵 정렬에 이미 오름차순인 배열을 준다. 분할이 한쪽으로 몰려 많은 비교가 생길 수 있다. 정렬이 거의 끝났다는 조건을 피벗 분할이 자동으로 활용하지 않는다.
