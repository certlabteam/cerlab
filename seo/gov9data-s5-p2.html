    다음 정수 열에서 연속 부분합의 최댓값은?

    1, －3, 2, 4, －1, 5, －3, 2, 1, －2

    1. 1. 5
    2. 2. 8
    3. 3. 10
    4. 4. 15

    정답 3번

    🔍 보기별 해설
    1. 여섯째 항 5 하나만 고른 값이다. 바로 앞의 4와 -1을 이어 셋째 항 2부터 5까지 합치면 10이 되어 훨씬 크므로 옳지 않다.
    2. 첫 항부터 아홉째 항까지 이으면 8이 나온다. 하지만 앞의 1과 -3을 빼고 셋째 항부터 이으면 더 큰 값이 나와 최댓값이 못 되므로 옳지 않다.
    3. 셋째 항 2부터 여섯째 항 5까지 2, 4, -1, 5를 잇는 합이 10이다. 뒤의 -3, 2, 1을 더해도 0이라 그대로 10이 유지되며 이보다 큰 연속 구간은 없으므로 옳다(정답).
    4. 15는 음수를 빼고 양수 1, 2, 4, 5, 2, 1을 모두 더한 값이다. 사이에 낀 -3과 -1을 건너뛰면 연속 부분이 될 수 없으므로 옳지 않다.
    🧮 풀이
    1. 甲은 열흘치 손익표에서 가장 큰 하루 값인 5만 최고 구간이라 적었다. 앞의 2, 4, -1을 붙여 합쳐 보니 10이 되어 처음에 적어 둔 답을 두 줄로 그어 지우고 새 값을 옆에 적었다.
    2. 甲은 첫날부터 아흐레째까지 모두 더해 8을 얻고 이것을 최댓값으로 삼으려 했다. 첫 이틀을 빼고 셋째 날부터 잡아 다시 더하자 값이 더 커지는 것을 표 옆에 적어 두었다.
    3. 甲은 손익표에 셋째 날부터 여섯째 날까지 괄호를 치고 2, 4, -1, 5를 차례로 더해 10을 적었다. 구간 끝을 한 칸씩 늘려 보아도 더 커지지 않아 그 괄호를 굵게 덧그렸다.
    4. 甲은 양수 칸만 형광펜으로 칠해 모두 더하고 15라는 값을 얻었다. 사이의 -3과 -1을 건너뛴 합이라 연속 구간이 못 됨을 알고 형광펜 자국 위에 큼직한 가위표를 쳤다.

    연속 부분합의 최댓값은 2, 4, -1, 5를 잇는 10이다. 양수만 모은 15는 연속이 아니라서 답이 될 수 없다.

    이진 탐색(binary search) 알고리즘에 대한 설명으로 옳지 않은 것은?

    1. 1. 탐색 범위가 절반씩 줄어든다.
    2. 2. 탐색할 데이터는 순서 없이 저장되어 있다.
    3. 3. 시간 복잡도는 O (logn) 이다.
    4. 4. 1,000개의 데이터가 존재하는 경우, 최대 10회의 탐색으로 완료된다.

    정답 2번

    🔍 보기별 해설
    1. 비교할 때마다 가운데 값을 기준으로 한쪽을 통째로 버리므로 남은 범위가 절반으로 줄어든다. 이진 탐색의 핵심 동작을 바르게 말한 설명이라 맞다.
    2. 이진 탐색은 가운데 값과 비교해 어느 쪽에 있는지 판단하므로 데이터가 미리 정렬되어 있어야 한다. 순서 없이 저장된 배열에서는 한쪽을 버릴 근거가 없으므로 옳지 않다(정답).
    3. 범위를 절반씩 줄이므로 비교 횟수가 n을 2로 몇 번 나누어야 1이 되느냐로 정해져 로그 n에 비례한다. 이진 탐색의 복잡도를 바르게 말한 설명이라 맞다.
    4. 1,000개는 2의 9제곱인 512보다 크고 2의 10제곱인 1,024보다 작아서 범위를 최대 열 번 줄이면 끝난다. 최악의 비교 횟수 계산과 맞는 설명이라 맞다.
    🧮 풀이
    1. 甲은 사전에서 단어를 찾으며 책을 가운데쯤에서 펼쳤다. 찾는 단어가 앞쪽이면 뒤쪽 반을 통째로 넘기고 남은 반에서 다시 가운데를 펼치는 방식으로 쪽수를 차근차근 좁혀 갔다.
    2. 甲은 번호표가 뒤섞여 쌓인 서류함에서 가운데 서류를 꺼내 번호를 살폈다. 그 번호가 크든 작든 어느 쪽에 있는지 알 수 없어 번호순 정리부터 하기로 하고 번호를 매겨 두었다.
    3. 甲은 명단이 1,000명에서 2,000명으로 두 배가 될 때 확인 횟수가 한 번만 늘어난다는 표를 만들었다. 학생 수가 열 배가 되어도 비교가 서너 번밖에 늘지 않는 곡선을 그래프로 그려 두었다.
    4. 甲은 1,000을 계속 절반으로 나누는 계산을 종이에 적었다. 500, 250, 125로 줄어 열 번 나누면 1 아래로 내려가는 것을 세어 보고 옆에 최대 열 번이라고 적었다.

    이진 탐색은 정렬된 데이터에서 범위를 절반씩 줄이며 O(log n)에 찾는다. 순서 없는 데이터에는 쓸 수 없다.

    동적 계획법(dynamic programming)으로 설계된 알고리즘의 동작 방식에 대한 설명으로 옳지 않은 것은?

    1. 1. 큰 문제를 작은 문제로 나눌 수 있어야 한다.
    2. 2. 작은 문제들이 반복해서 사용되며, 이 작은 문제들의 결괏값을 저장해 두고 활용한다.
    3. 3. 상향식(bottom-up) 접근 방식 또는 하향식(top-down) 접근 방식으로 구현할 수 있다.
    4. 4. 메모하기(memoization) 방법을 활용하여 연산과 탐색이 증가하고 실행속도가 저하된다.

    정답 4번

    🔍 보기별 해설
    1. 큰 문제를 겹치는 작은 부분 문제로 쪼갤 수 있어야 동적 계획법을 적용할 수 있다. 문제 분해 조건을 바르게 말한 설명이라 맞다.
    2. 같은 부분 문제가 여러 번 나오기 때문에 한 번 푼 결과를 표에 저장해 두고 다시 꺼내 쓴다. 중복 계산을 피하는 동적 계획법의 핵심을 바르게 말한 설명이라 맞다.
    3. 작은 문제부터 표를 채워 올라가는 상향식과 큰 문제에서 시작해 재귀로 내려가는 하향식 두 방식 모두로 구현할 수 있다. 구현 방식을 바르게 말한 설명이라 맞다.
    4. 메모하기는 한 번 구한 값을 저장해 두고 다시 계산하지 않는 기법이라 반복 연산을 오히려 줄여 실행 속도를 높여 준다. 증가하고 저하된다는 서술은 정반대이므로 옳지 않다(정답).
    🧮 풀이
    1. 甲은 계단 오르기 경우의 수 문제를 풀며 10칸 문제를 9칸과 8칸 문제로 나눠 적었다. 그 두 문제가 다시 더 작은 문제로 갈라지는 나무를 그리다가 나눌 수 있다는 점을 짚어 보았다.
    2. 甲은 피보나치 f(5)를 재귀로 전개하다 f(3)이 두 번 나오는 것을 발견했다. 두 번째부터는 계산하지 않고 이미 구한 값을 표에서 가져오도록 f(3)의 결과를 표 안에 적어 두었다.
    3. 甲은 같은 문제를 두 가지로 짰다. 하나는 f(1)부터 표를 채워 올라가는 반복문이고 다른 하나는 f(n)에서 재귀로 내려가는 방식인데 두 코드가 같은 값을 내는 것을 실행해 견주었다.
    4. 甲은 메모를 붙인 피보나치 함수와 붙이지 않은 함수를 n이 40일 때 각각 실행해 보았다. 메모를 붙인 쪽이 눈 깜짝할 새에 끝나고 붙이지 않은 쪽은 한참 걸려 소요 시간을 표에 나란히 적었다.

    동적 계획법은 겹치는 부분 문제의 결과를 저장해 재사용한다. 메모하기는 연산을 줄여 속도를 높인다.

    다음 정렬 알고리즘 중에서 동일한 최악 시간 복잡도를 가진 것만을 모두 고르면?

    ㄱ. 선택 정렬(selection sort)

    ㄴ. 삽입 정렬(insertion sort)

    ㄷ. 힙 정렬(heap sort)

    ㄹ. 퀵 정렬(quick sort)

    1. 1. ㄱ, ㄴ, ㄷ
    2. 2. ㄱ, ㄴ, ㄹ
    3. 3. ㄱ, ㄷ, ㄹ
    4. 4. ㄴ, ㄷ, ㄹ

    정답 2번

    🔍 보기별 해설
    1. 선택 정렬과 삽입 정렬은 최악에 n제곱이지만 힙 정렬은 어떤 입력에서도 n log n으로 끝난다. 힙 정렬을 함께 묶으면 복잡도가 갈라지므로 옳지 않다.
    2. 선택 정렬은 항상 n제곱, 삽입 정렬은 역순 입력에서 n제곱, 퀵 정렬은 기준이 한쪽으로만 쏠릴 때 n제곱이라 최악이 모두 같다. 세 가지를 묶은 이 묶음이 맞다.
    3. 힙 정렬은 최악에도 n log n인데 선택과 퀵은 n제곱이라 힙 정렬이 낀 이 묶음은 최악 복잡도가 셋으로 갈라진다. 세 정렬이 같은 값을 갖지 않으므로 옳지 않다.
    4. 삽입과 퀵은 최악이 n제곱이나 힙은 n log n이라 서로 차이가 난다. 힙 정렬을 넣은 이 묶음도 세 알고리즘의 최악 복잡도가 한 줄로 이어지지 않으므로 옳지 않다.
    🧮 풀이
    1. 甲은 선택, 삽입, 힙 정렬에 역순 배열을 넣어 비교 횟수를 세어 보았다. 앞의 둘은 입력 크기의 제곱꼴로 늘었지만 힙 정렬만 로그가 붙은 곡선을 그려 세 개를 한 묶음으로 잡을 수 없었다.
    2. 甲은 이미 오름차순인 배열을 퀵 정렬에 넣고 맨 앞 값을 기준으로 삼아 보았다. 기준이 언제나 가장 작아 한쪽으로 쏠리며 선택·삽입 정렬처럼 제곱 횟수가 나오자 세 알고리즘 옆에 같은 표시를 달았다.
    3. 甲은 선택, 힙, 퀵 정렬을 최악 입력에서 각각 돌려 걸린 시간을 쟀다. 힙 정렬만 눈에 띄게 빨라 다른 둘과 같은 자리에 묶을 수 없는 것을 그래프에서 확인하고 힙에 별표를 쳤다.
    4. 甲은 삽입, 힙, 퀵 정렬의 최악 복잡도를 교재 표에서 찾아 나란히 옮겨 적었다. 삽입과 퀵은 제곱, 힙은 로그가 붙은 꼴이라 한 줄로 이어지지 않아 힙 정렬 칸에만 색을 칠해 구분했다.

    선택·삽입·퀵 정렬의 최악은 n제곱이고 힙 정렬만 n log n이다. 정답은 2번.

    그림과 같은 과정을 포함하여 정렬을 실행하는 알고리즘은?

    1. 1. 퀵 정렬
    2. 2. 셸 정렬(shell sort)
    3. 3. 기수 정렬(radix sort)
    4. 4. 병합 정렬(merge sort)

    정답 4번

    🔍 보기별 해설
    1. 퀵 정렬은 기준값을 골라 작은 값과 큰 값으로 나누는 것이 핵심이다. 그림처럼 이미 정렬된 두 묶음을 앞에서부터 비교해 하나로 이어 붙이는 과정은 없으므로 옳지 않다.
    2. 셸 정렬은 일정한 간격만큼 떨어진 원소끼리 삽입 정렬을 하고 간격을 줄여 가는 방식이다. 묶음을 둘씩 합쳐 올라가는 그림의 모양과 다르므로 옳지 않다.
    3. 기수 정렬은 값을 비교하지 않고 자릿수별로 나눠 담았다 꺼내며 정렬한다. 그림처럼 정렬된 두 묶음을 합치는 단계가 없으므로 옳지 않다.
    4. 낱개로 쪼갠 뒤 두 묶음씩 정렬하며 합쳐 마지막에 하나의 정렬된 배열을 만드는 과정이 그림과 같다. 병합 정렬의 합치기 단계가 그대로 나타나므로 옳다(정답).
    🧮 풀이
    1. 甲은 퀵 정렬을 손으로 따라가며 맨 앞 값을 기준으로 잡았다. 기준보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 갈라 세우고 기준을 가운데에 세워 두는 그림을 세 번 그렸다.
    2. 甲은 열 개짜리 배열에 간격을 5, 2, 1로 줄여 가며 셸 정렬을 적용했다. 간격이 5일 때 멀리 떨어진 두 원소끼리 짝지어 순서를 바꾸는 단계를 색연필로 이어 표시했다.
    3. 甲은 세 자리 수 카드를 일의 자리부터 0에서 9까지 통에 나눠 담았다. 통에서 차례로 꺼낸 카드를 십의 자리, 백의 자리로 다시 나눠 담으며 한 번도 두 수를 견주지 않았다.
    4. 甲은 카드 여덟 장을 한 장씩 낱개로 흩어 놓고 두 장씩 짝지어 순서를 맞춰 붙였다. 두 장 묶음을 다시 네 장 묶음으로, 마지막에 한 줄로 합쳐 가는 과정을 그림으로 그려 두었다.

    그림처럼 정렬된 두 묶음을 하나로 합쳐 올라가는 과정이 병합 정렬의 핵심이다.

    다음과 같은 배열 A에서 A[0]부터 삽입 연산을 차례대로 적용하여 이진 탐색 트리 T를 생성한 후, T를 전위(preorder) 순회 방법으로 방문한 값들을 배열 B에 B[0]부터 순차적으로 저장한 결과는?

    A[] ＝ 40, 20, 30, 10

    1. 1. B[] ＝ 10, 20, 30, 40
    2. 2. B[] ＝ 10, 30, 20, 40
    3. 3. B[] ＝ 40, 20, 10, 30
    4. 4. B[] ＝ 40, 30, 20, 10

    정답 3번

    🔍 보기별 해설
    1. 10, 20, 30, 40은 오름차순, 곧 중위 순회의 결과이다. 전위 순회는 루트를 먼저 방문해야 하는데 이 배열은 가장 큰 40이 맨 뒤에 놓여 있어 옳지 않다.
