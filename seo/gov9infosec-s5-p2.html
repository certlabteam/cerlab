    CSRF에 대한 설명으로 옳은 것은?

    1. 1. 취약한 컴포넌트를 악용하여 공격하면 데이터 손실이나 서버 장악 문제가 발생할 수 있는 취약점이다.
    2. 2. 조작된 XPath(XML Path Language) 쿼리를 보냄으로써 비정상적인 데이터를 쿼리를 이용해 가져올 수 있는 취약점이다.
    3. 3. 적절히 보호되지 않은 쿠키를 사용하여, 쿠키 값 변조를 통한 다른 사용자로의 위장 및 권한 상승 등이 가능한 취약점이다.
    4. 4. 로그인한 사용자 브라우저로 하여금 사용자의 세션 쿠키와 기타 인증 정보를 포함하는 위조된 HTTP 요청을 전송할 수 있는 취약점이다.

    정답 4번

    🔍 보기별 해설
    1. 취약한 컴포넌트를 써서 생기는 데이터 손실·서버 장악은 OWASP의 알려진 취약점이 있는 구성요소 사용 항목이다. 사용자 브라우저가 위조 요청을 보내게 만드는 CSRF 설명이 아니므로 옳지 않다.
    2. 조작한 XPath(XML Path Language) 쿼리로 XML 데이터를 비정상적으로 꺼내는 것은 XPath 삽입 취약점이다. CSRF와는 다른 삽입 계열 공격이므로 옳지 않다.
    3. 보호되지 않은 쿠키 값을 바꿔 다른 사용자로 위장하거나 권한을 올리는 것은 쿠키 변조 취약점이다. CSRF는 쿠키를 고치는 것이 아니라 피해자 쿠키가 붙은 요청을 보내게 하므로 옳지 않다.
    4. CSRF(Cross-Site Request Forgery)는 로그인한 사용자가 악성 페이지를 열면 브라우저가 세션 쿠키를 붙여 위조된 HTTP 요청을 대상 사이트로 보내게 하는 취약점이다. 설명이 정확하므로 옳다(정답).
    🧮 풀이
    1. 학교 홈페이지를 관리하는 甲은 3년 전 버전의 게시판 플러그인을 업데이트하지 않고 두었다가, 인터넷에 공개된 공격 코드에 웹 서버 권한을 빼앗기고 회원 DB까지 잃었다. 패치되지 않은 구성요소 하나가 서버 전체를 내준 경우다.
    2. 공격자 甲은 로그인 화면의 아이디 칸에 ' or '1'='1 을 넣어 XPath 조건을 참으로 만들었다. 서버가 XML 사용자 파일에서 첫 번째 계정을 꺼내 와 甲은 비밀번호 없이 그 계정으로 들어갔다.
    3. 웹 수강생 甲이 브라우저 개발자 도구로 쿠키의 role=student를 role=admin으로 고치자 관리자 메뉴가 열렸다. 서버가 쿠키 값을 서명이나 서버 쪽 세션으로 지키지 않아 생긴 쿠키 변조 취약점이다.
    4. 인터넷 뱅킹에 로그인해 둔 甲이 이벤트 당첨 메일의 링크를 열자, 페이지에 숨겨진 이미지 태그가 甲의 브라우저로 은행에 송금 요청을 보냈다. 요청에는 甲의 세션 쿠키가 자동으로 붙어 은행은 본인이 직접 한 이체로 처리했으니 CSRF 공격이다.

    CSRF는 로그인한 사용자의 브라우저가 세션 쿠키를 붙인 위조 요청을 대상 사이트로 보내게 만드는 취약점이다. 정답은 4번이다.

    다음에서 설명하는 검사 도구는?

    어느 한 시점에서 시스템에 존재하는 특정 경로 혹은 모든 파일에 관한 정보를 DB화하여 저장한 후, 수정ㆍ삭제ㆍ생성된 파일에 관한 정보를 알려주며, 해커들에 의한 파일의 위변조 여부를 판별할 수 있는 기능을 제공해 주는 검사 도구이다.

    1. 1. Tripwire
    2. 2. Burp Suite
    3. 3. Snort
    4. 4. NESSUS

    정답 1번

    🔍 보기별 해설
    1. Tripwire는 파일들의 해시와 속성을 기준 DB로 저장해 두고 나중에 다시 계산해 비교하는 무결성 검사 도구다. 생성·수정·삭제된 파일을 알려 위변조를 가리므로 옳다(정답).
    2. Burp Suite는 브라우저와 웹 서버 사이에서 HTTP 요청과 응답을 가로채 고쳐 보는 웹 프록시 진단 도구다. 파일 무결성을 DB로 비교하는 도구가 아니므로 옳지 않다.
    3. Snort는 네트워크 패킷을 규칙과 대조해 공격을 탐지하는 침입 탐지 시스템(IDS)이다. 시스템 파일의 변경 여부를 검사하는 도구가 아니므로 옳지 않다.
    4. NESSUS는 네트워크의 호스트를 스캔해 알려진 취약점과 잘못된 설정을 찾아 주는 취약점 스캐너다. 파일 위변조를 기준 DB와 비교하는 도구가 아니므로 옳지 않다.
    🧮 풀이
    1. 학교 웹 서버 관리자 甲은 설치 직후 Tripwire로 시스템 파일 기준 DB를 만들어 두었다. 한 달 뒤 점검에서 /bin/login의 해시가 달라졌다는 보고가 나와, 침입자가 로그인 프로그램을 바꿔치기한 것을 잡아냈다.
    2. 보안 진단 업체 직원 甲은 Burp Suite를 프록시로 켜고 수강 신청 요청을 가로채 학점 값을 21에서 30으로 바꿔 보냈다. 서버가 그 값을 그대로 받아 주어 수강 한도 검증이 브라우저 쪽에만 있다는 결함이 나왔다.
    3. 관제실 근무자 甲은 웹 공격에 자주 쓰이는 문자열을 Snort 규칙으로 넣어 두었다. 외부에서 그 문자열이 담긴 패킷이 들어오자 경보가 울렸고 甲은 출발지 IP를 방화벽에서 막았다.
    4. 교육청 점검 담당 甲이 NESSUS로 학교 서버들을 스캔하자 패치가 빠진 SMB 서비스와 기본 계정이 남은 장비가 목록으로 나왔다. 甲은 위험도가 높은 순서대로 패치 일정을 잡았다.

    파일 정보를 기준 DB로 저장해 두었다가 다시 비교해 생성·수정·삭제를 알려 주는 무결성 검사 도구는 Tripwire다. 정답은 1번이다.

    robots.txt 파일에 대한 설명으로 옳은 것은?

    1. 1. robots.txt 파일은 웹 루트 디렉터리에 위치한다.
    2. 2. User-agent는 접근거부 디렉터리를 나타내는 키워드이다.
    3. 3. Disallow는 검색 엔진 종류를 나타내는 키워드이다.
    4. 4. User-agent와 Disallow는 동시에 사용할 수 없다.

    정답 1번

    🔍 보기별 해설
    1. robots.txt는 검색 로봇이 사이트에 들어오면 가장 먼저 찾는 파일이라 도메인 바로 아래 최상위 경로에 둔다. 하위 폴더에 두면 로봇이 읽지 않으므로 이 위치 설명은 옳다(정답).
    2. User-agent는 규칙을 적용할 검색 로봇의 이름을 적는 키워드이고, 막을 경로는 Disallow로 적는다. 두 키워드의 역할을 뒤바꿔 말했으므로 옳지 않다.
    3. Disallow는 로봇이 수집하지 말아야 할 디렉터리나 파일 경로를 적는 키워드다. 검색 엔진 종류는 User-agent로 적으므로 옳지 않다.
    4. robots.txt는 User-agent 줄로 로봇을 고르고 그 아래 Disallow 줄로 막을 경로를 적는 식으로 두 키워드를 함께 쓴다. 함께 쓸 수 없다는 말은 틀렸으므로 옳지 않다.
    🧮 풀이
    1. 홈페이지 담당 교사 甲은 robots.txt를 /board/ 폴더에 넣었다가 검색 로봇이 관리자 페이지를 계속 수집하는 일을 겪었다. 파일을 도메인 맨 위 경로로 옮겨 school.ac.kr/robots.txt로 열리게 하자 그제야 규칙이 먹혔다.
    2. 병원 웹 담당 甲은 User-agent: Googlebot 아래에 Disallow: /patient/를 적어 구글 로봇만 환자 안내 폴더를 수집하지 못하게 했다. 다른 검색 로봇은 이 규칙을 따르지 않고 그 폴더를 계속 수집했다.
    3. 쇼핑몰 운영자 甲은 결제 페이지가 검색 결과에 뜨지 않게 하려고 Disallow: /order/ 한 줄을 넣었다. 이 줄만으로는 어느 로봇에 적용할지 정해지지 않아, 甲은 바로 위에 User-agent: * 줄을 함께 두고서야 주문 페이지를 검색 결과에서 뺐다.
    4. 입학처 웹 담당 甲은 robots.txt에 User-agent: *와 Disallow: /admin/ 두 줄을 이어 적었다. 그 뒤 모든 검색 로봇이 관리자 경로를 건너뛰어, 두 키워드를 짝으로 써야 규칙이 완성된다는 것이 그대로 나타났다.

    robots.txt는 웹 루트에 두고 User-agent로 대상 로봇을, Disallow로 막을 경로를 함께 적어 쓴다. 정답은 1번이다.

    다음은 Windows 운영체제가 설치된 시스템에서 SID를 출력한 결과이다. (가), (나)에 대한 설명으로 옳지 않은 것은?

    1. 1. (가)는 시스템 부팅 시마다 새롭게 부여되는 시스템 ID이다.
    2. 2. (나)는 RID를 나타내며, 500의 경우 Administrator임을 의미한다.
    3. 3. (나)는 RID를 나타내며, 501의 경우 Guest임을 의미한다.
    4. 4. (나)는 RID를 나타내며, 일반 사용자에게는 1,000 이상의 숫자가 부여된다.

    정답 1번

    🔍 보기별 해설
    1. SID에서 (가)는 21로 시작하는 컴퓨터(도메인) 식별 부분으로, 운영체제를 설치할 때 한 번 정해져 그대로 유지된다. 부팅할 때마다 새로 부여된다는 설명은 틀렸으므로 옳지 않다(정답).
    2. SID 끝자리 (나)는 RID(Relative ID)이며 500은 설치 때 만들어지는 기본 Administrator 계정에 붙는다. 설명대로이므로 옳다.
    3. RID 501은 Windows가 설치될 때 함께 만들어지는 기본 Guest 계정에 고정으로 붙는 값이다. 설명대로이므로 옳다.
    4. 관리자가 새로 만든 일반 계정의 RID는 1000번부터 차례로 붙는다. 기본 계정과 겹치지 않게 큰 번호를 쓴다는 설명대로이므로 옳다.
    🧮 풀이
    1. PC 수십 대를 한 이미지로 복제한 학교 전산 담당 甲은 whoami /user로 보니 모든 PC의 SID 앞부분이 똑같았다. 재부팅해도 값이 바뀌지 않아, 甲은 sysprep으로 PC마다 새 식별자를 만들고 나서야 도메인 가입 오류를 해결했다.
    2. 보안 점검을 하던 甲은 공격자가 이름을 admin2로 바꿔 숨긴 계정을 SID 끝의 500으로 찾아냈다. 이름이 바뀌어도 RID는 그대로라 내장 Administrator 계정임이 바로 보였다.
    3. 관공서 PC를 점검하던 甲은 SID가 -501로 끝나는 계정이 활성화된 것을 보고 바로 사용 안 함으로 바꿨다. 기본 Guest 계정은 비밀번호 없이 쓰이는 일이 잦아 침입 통로가 되기 쉽다.
    4. 사내 PC에 계정 셋을 새로 만든 관리자 甲이 wmic useraccount로 SID를 조회하자 끝자리가 1001, 1002, 1003으로 이어졌다. 기본 계정의 500·501과 겹치지 않는 번호대가 일반 사용자에게 주어진 것이다.

    SID의 (가) 컴퓨터 식별자는 Windows를 설치할 때 정해져 부팅해도 바뀌지 않는데 부팅마다 새로 부여된다고 했다. 정답은 1번이다.

    디지털 포렌식의 절차에서 사전준비 이후 단계를 순서대로 바르게 나열한 것은?

    (가) 증거 수집 (나) 보관 및 이송 (다) 보고서 작성 (라) 증거 분석 및 조사

    1. 1. (가) → (나) → (다) → (라)
    2. 2. (가) → (나) → (라) → (다)
    3. 3. (나) → (가) → (다) → (라)
    4. 4. (나) → (라) → (가) → (다)

    정답 2번

    🔍 보기별 해설
    1. (가)→(나)→(다)→(라)는 보고서 작성(다)을 증거 분석(라)보다 앞에 두었다. 분석 결과가 없으면 보고서에 적을 내용이 없으므로 옳지 않다.
    2. 디지털 포렌식은 사전준비 뒤 증거를 수집하고(가), 무결성을 지키며 보관·이송한 다음(나), 분석·조사하고(라), 결과를 보고서로 남긴다(다). 이 차례 그대로이므로 옳다(정답).
    3. (나)→(가)→(다)→(라)는 아직 수집하지 않은 증거를 먼저 보관·이송한다고 놓은 순서다. 보고서도 분석보다 앞서 있어 옳지 않다.
    4. (나)→(라)→(가)→(다)는 보관·이송과 분석을 수집보다 먼저 두었다. 손에 넣지 않은 증거를 옮기거나 분석할 수는 없으므로 옳지 않다.
    🧮 풀이
    1. 감사팀 甲은 서둘러 결과를 내라는 지시에 분석도 끝나기 전에 보고서 초안부터 썼다. 이후 분석에서 새 로그가 나오자 초안을 통째로 다시 써야 했고, 보고는 결국 분석 뒤에 나갔다.
    2. 경찰 디지털포렌식팀 甲은 현장에서 노트북 디스크를 쓰기 방지 장치로 이미징하고 해시값을 남겼다. 봉인한 증거물을 운반 기록과 함께 연구실로 옮겨 분석한 뒤, 찾아낸 메신저 대화를 보고서로 묶어 제출했다.
    3. 신입 분석관 甲은 증거 이송 차량부터 예약하려다 아직 압수한 기기가 하나도 없다는 말을 듣고 예약을 취소했다. 현장에서 하드디스크를 수집한 다음에야 봉인과 이송 절차가 시작되었다.

    PGP의 인증에 대한 설명으로 옳지 않은 것은?

    1. 1. 송신자는 일방향 해시함수를 사용하여 송신 메시지의 해시 코드를 생성한다.
    2. 2. 송신자가 생성한 해시 코드는 송신자의 개인키를 사용하여 암호화되며, 그 결괏값이 메시지에 포함된다.
    3. 3. 수신자는 수신한 메시지를 송신자의 공개키로 복호화하고 해시 코드를 알아낸다.
    4. 4. 디지털 서명을 생성하는 데 DSS를 사용하는 것은 허용하지 않는다.

    정답 4번

    🔍 보기별 해설
    1. PGP 인증의 첫 단계에서 송신자는 SHA 같은 일방향 해시함수로 메시지의 요약값인 해시 코드를 만든다. 서명할 값을 얻는 과정이므로 옳다.
    2. PGP는 송신자 개인키로 해시 코드를 암호화해 서명을 만들고 그 서명을 메시지와 함께 묶어 보낸다. 개인키로 만든 서명이 같이 전달되므로 옳다.
    3. 수신자는 송신자의 공개키로 서명을 복호화해 해시 코드를 꺼내고 직접 계산한 해시와 비교한다. 공개키로 서명을 풀어 해시를 얻는 절차이므로 옳다.
    4. PGP는 RSA뿐 아니라 DSS(Digital Signature Standard)로도 디지털 서명을 만들 수 있다. DSS 사용을 허용하지 않는다는 말은 옳지 않다(정답).
    🧮 풀이
    1. 정산 담당 甲은 온라인 쇼핑몰 거래처에 보낼 정산표를 PGP로 서명하기 전에 프로그램이 SHA-256 해시를 먼저 계산하게 했다. 표의 금액 한 글자만 고쳐도 해시값이 완전히 달라져 변조를 가리는 기준이 되었다.
    2. 법무팀 직원 甲은 택배사 계약 변경 메일에 PGP 서명을 걸었다. 프로그램은 본문의 해시 코드를 甲의 개인키로 암호화한 덩어리를 메일에 붙여 보냈고, 그 개인키는 甲만 가지고 있어 다른 사람은 같은 서명을 만들 수 없었다.
    3. 협력 물류사 직원 甲이 서명된 메일을 열자 프로그램이 발신자의 공개키로 서명을 풀어 해시 코드를 꺼냈다. 甲의 PC가 본문으로 새로 계산한 해시와 두 값이 같아 화면에 서명이 유효하다는 표시가 떴다.
    4. 보안 담당 甲은 여행사 거래처의 요구에 맞춰 PGP 키를 만들 때 서명 알고리즘으로 DSS 계열의 DSA를 골랐다. 이 키로 서명한 견적서도 상대방 PGP에서 정상적으로 검증되어 RSA 키와 똑같이 쓰였다.

    PGP는 RSA와 함께 DSS로도 디지털 서명을 만들 수 있으므로 DSS 사용을 허용하지 않는다는 4번이 틀린 설명이다. 정답은 4번이다.

    1. 1. SQL Injection
    2. 2. 디렉터리 인덱싱
    3. 3. 운영체제 명령어 실행
    4. 4. XSS(Cross Site Scripting)

    2. 디렉터리 인덱싱은 기본 페이지가 없는 디렉터리에 접근하면 파일 목록이 그대로 보이는 서버 보안 설정 오류다. URL을 디렉터리까지만 입력해 점검한다는 설명과 같으므로 옳다(정답).
    3. 운영체제 명령어 실행은 입력값이 시스템 명령으로 넘어가 서버에서 임의 명령이 실행되는 취약점이다. 디렉터리 경로로 목록 노출을 점검하는 설명과 다르므로 옳지 않다.
    4. XSS(Cross Site Scripting)는 게시물이나 입력값에 스크립트를 심어 다른 사용자의 브라우저에서 실행되게 하는 공격이다. 웹 서버 설정 오류를 묻는 설명과 다르므로 옳지 않다.

    1. CVE(Common Vulnerabilities and Exposures)는 공개된 취약점마다 연도와 번호로 된 고유 식별자를 붙이는 목록이다. 이름을 붙일 뿐 등급을 매기지 않으므로 옳지 않다.
    2. CVSS(Common Vulnerability Scoring System)는 공격 경로·복잡도·영향 등을 따져 취약점 심각도를 0.0~10.0 점수로 매기는 공개 프레임워크다. 등급을 매긴다는 물음에 맞으므로 옳다(정답).
    3. CWE(Common Weakness Enumeration)는 실제 사건이 아니라 입력값 검증 누락 같은 소프트웨어 약점의 유형을 분류한 목록이다. 점수를 매기는 체계가 아니므로 옳지 않다.
    4. NVD(National Vulnerability Database)는 미국 NIST가 운영하며 CVE 항목에 CVSS 점수와 분석 정보를 더해 제공하는 데이터베이스다. 점수 체계가 아니라 그것을 담는 저장소이므로 옳지 않다.
    🧮 풀이
    1. 보안팀 甲은 택배사 메일 서버의 벤더 패치 공지에 적힌 CVE 번호로 검색해 다른 보안 제품들이 같은 취약점을 어떻게 부르는지 한 번에 찾아냈다. 회사마다 부르는 이름이 달라도 CVE 식별자 하나로 같은 취약점을 가리킬 수 있었다.
    2. 패치 담당 甲은 쇼핑몰 서버의 이번 달 패치 대상 취약점 열두 개를 CVSS 점수 순으로 줄 세웠다. 9.8점짜리 원격 코드 실행 취약점을 그날 밤 먼저 패치하고, 4점대 항목은 다음 정기 점검으로 미뤘으며, 패치 뒤 다시 스캔해 고위험 항목이 사라진 결과를 보고서에 붙였다.
    3. 개발팀장 甲은 여행사 시큐어 코딩 교육 자료를 만들며 CWE 목록에서 입력값 검증 누락 유형 번호를 뽑아 사내 코드 사례와 연결했다. 특정 제품의 사고가 아니라 되풀이해 생기는 약점의 종류를 가르치는 데 쓴 것이다.
    4. 인프라 관리자 甲은 물류센터에서 쓰는 웹 서버 이름을 NVD 웹 사이트에서 검색했다. 각 CVE 항목 옆에 NIST가 분석한 CVSS 점수와 영향받는 버전 목록이 함께 붙어 있어 패치 계획을 바로 세울 수 있었고, 甲은 그날 오후 7점 이상 항목부터 작업 일정을 잡았다.

    실제 발생한 취약점의 심각도를 공격 경로와 영향으로 점수화해 등급을 매기는 공개 프레임워크는 CVSS다. 정답은 2번이다.

    (가), (나)에 들어갈 용어를 바르게 연결한 것은?

    ○ (가) 는 컴파일러가 프로그램의 함수를 호출할 때 ret 앞에 canary 값을 주입하고, 종료할 때 canary 값을 변조했는지 확인하여 공격을 탐지한다.

    ○ (나) 공격은 데이터의 형태와 길이에 대한 불명확한 정의로 인한 문제점 중 데이터 형태에 대한 불명확한 정의로 인한 것이다. (가) (나)

    1. 1. 스택 실드 버퍼 오버플로
    2. 2. 스택 실드 포맷 스트링
    3. 3. 스택 가드 버퍼 오버플로
    4. 4. 스택 가드 포맷 스트링

    정답 4번

    🔍 보기별 해설
    1. 스택 실드는 함수 시작 때 복귀 주소를 별도 영역에 복사해 두었다가 끝날 때 비교하는 방식이고, 버퍼 오버플로는 데이터 길이 정의 문제에서 생긴다. (가)와 (나)가 모두 맞지 않으므로 옳지 않다.
    2. (나)의 포맷 스트링은 맞지만 canary 값을 끼워 넣는 기법은 스택 실드가 아니라 스택 가드다. (가)가 틀리므로 옳지 않다.
    3. (가)의 스택 가드는 맞지만 버퍼 오버플로는 데이터 길이를 명확히 정하지 않아 생기는 문제다. 데이터 형태 문제인 (나)와 맞지 않으므로 옳지 않다.
    4. 스택 가드는 복귀 주소 앞에 canary 값을 넣고 함수가 끝날 때 바뀌었는지 검사하며, 포맷 스트링 공격은 %x·%n 같은 형식 지정자 처리 문제에서 생긴다. 두 칸이 모두 맞으므로 옳다(정답).
    🧮 풀이
    1. 물류 시스템 개발자 甲은 스택 실드를 켜고 컴파일한 프로그램을 디버거로 돌려, 함수가 시작할 때 복귀 주소가 전역 영역에 따로 복사되는 장면을 따라갔다. 함수가 끝날 때 복사본과 스택의 값이 달라지자 프로그램이 종료되었고, 이 방식에는 canary가 쓰이지 않았다.
    2. 보안 점검자 甲은 택배사 프로그램에서 printf(사용자입력) 꼴의 코드를 찾아 입력 칸에 %x를 여러 개 넣었다. 화면에 스택 메모리 값이 줄줄이 출력되어 데이터 형태를 검사하지 않는 포맷 스트링 취약점이 나왔고, 개발팀은 형식 문자열을 고정해 넣었다.
    3. 예약 시스템 개발자 甲은 gets로 받은 예약 번호를 64바이트 배열에 넣었는데 200자를 입력하자 복귀 주소까지 덮여 프로그램이 죽었다. 입력 길이를 정하지 않아 생긴 버퍼 오버플로였고, 스택 가드를 켜고 다시 빌드하자 canary 검사에서 공격이 멈췄다.
    4. 결제 모듈 개발자 甲이 gcc의 -fstack-protector 옵션으로 쇼핑몰 결제 모듈을 다시 빌드하자 함수마다 복귀 주소 앞에 canary 값이 들어갔다. 점검팀이 일부러 긴 입력으로 스택을 덮자 프로그램이 stack smashing detected 메시지를 띄우고 멈췄다.

    canary 값을 복귀 주소 앞에 넣어 변조를 탐지하는 것은 스택 가드이고, 데이터 형태 정의가 불명확해 생기는 공격은 포맷 스트링이다. 정답은 4번이다.

    다음에서 설명하는 인증 방법은?

    사용자가 많이 가입한 웹 사이트(네이버, 구글, 페이스북 등)의 사용자 가입 정보를 이용해서 다른 웹 사이트에 별도의 가입 과정 없이 단순하게 사용자 신원을 검증하는 토큰을 제공하여 제삼자 인증 서비스를 이용할 수 있게 해 준다.

    1. 1. Kerberos
    2. 2. OAuth
    3. 3. SSO
    4. 4. DIAMETER

    정답 2번

    🔍 보기별 해설
    1. Kerberos는 KDC(Key Distribution Center)가 발급한 티켓으로 같은 영역 안의 서버에 인증하는 대칭키 기반 프로토콜이다. 외부 대형 사이트 계정을 빌려 쓰는 방식이 아니므로 옳지 않다.
    2. OAuth는 네이버·구글 같은 사이트가 사용자 동의를 받아 다른 서비스에 접근 토큰을 발급해 주는 권한 위임 표준이다. 별도 가입 없이 기존 계정으로 이용하게 해 주므로 옳다(정답).
    3. SSO(Single Sign-On)는 한 번 로그인으로 한 조직의 여러 시스템을 함께 쓰게 하는 개념이다. 제삼자 사이트가 토큰을 내주는 표준 방식을 가리키는 이름은 아니므로 옳지 않다.
    4. DIAMETER는 RADIUS를 개선한 네트워크 접속 인증·권한·과금(AAA) 프로토콜이다. 웹 사이트 사이 계정 연동과는 쓰임이 다르므로 옳지 않다.
    🧮 풀이
    1. 본사 직원 甲이 아침에 택배사 도메인 PC에 로그온하자 KDC가 TGT를 내주었다. 이후 파일 서버를 열 때는 이 티켓으로 서비스 티켓을 받아 패스워드를 다시 넣지 않았고, 이 과정은 사내망 안에서만 도는 Kerberos 인증이다.
    2. 여행 예약 앱을 처음 연 甲은 회원가입 대신 네이버로 시작하기 버튼을 눌렀다. 네이버 로그인 창에서 이름과 이메일 제공에 동의하자 앱은 OAuth 접근 토큰을 받아 甲을 회원으로 바로 등록했다.
    3. 출근한 물류센터 직원 甲은 사내 포털에 한 번 로그인한 뒤 재고 관리, 전자 결재, 메일 시스템을 따로 로그인하지 않고 차례로 열었다. 같은 회사 시스템끼리 인증 결과를 나눠 쓰는 SSO 덕분이었다.
    4. 통신사 망 운영자 甲은 LTE 가입자가 접속할 때 가입자 인증과 과금 정보를 DIAMETER 메시지로 주고받게 설정했다. 웹 사이트 로그인이 아니라 망 접속 단계에서 쓰이는 AAA 프로토콜이다.

    대형 사이트 계정으로 다른 사이트에 별도 가입 없이 신원을 확인받도록 토큰을 내주는 제삼자 인증 방식은 OAuth다. 정답은 2번이다.

    신뢰 플랫폼 모듈(Trusted Platform Module)의 구성 요소로 옳지 않은 것은?

    1. 1. 난수 발생기
    2. 2. 암복호화 엔진
    3. 3. RSA 키 발생기
    4. 4. MD5 해시값 생성기

    정답 4번

    🔍 보기별 해설
    1. TPM의 난수 발생기는 키 생성과 일회용 값 생성에 쓸 예측 불가능한 난수를 칩 안에서 만든다. TPM 구성 요소이므로 옳다.
    2. TPM의 암복호화 엔진은 칩 내부에서 RSA 암호화·복호화와 서명 연산을 처리한다. 키를 밖으로 내보내지 않고 연산하는 구성 요소이므로 옳다.
    3. TPM의 RSA 키 발생기는 저장 루트 키와 인증 키 같은 RSA 키 쌍을 칩 안에서 만든다. TPM 구성 요소이므로 옳다.
    4. TPM 규격의 해시 엔진은 SHA-1(TPM 2.0은 SHA-256 포함) 해시를 계산하며 MD5 해시값 생성기는 구성 요소로 정해져 있지 않다. TPM 구성 요소로 본 것은 옳지 않다(정답).
    🧮 풀이
    1. 노트북을 관리하는 쇼핑몰 IT 담당 甲이 BitLocker를 켜자 TPM이 칩 안의 난수 발생기로 만든 값을 써서 새 암호화 키를 만들었다. 외부 소프트웨어 난수에 기대지 않아 키를 미리 짐작하기가 어려웠다.
    2. 단말기 개발자 甲은 택배 기사용 단말기 인증서의 개인키를 TPM 안에 두고, 서버가 보낸 임의 문자열의 서명을 TPM 암복호화 엔진에 맡겼다. 개인키가 메모리로 나오지 않아 단말기가 해킹당해도 키를 빼낼 수 없었다.
    3. 여행사 서버 관리자 甲은 TPM 관리 도구로 보증 키와 저장 루트 키를 칩 안에서 만드는 명령을 실행했다. RSA 키 쌍의 개인키 부분은 칩 밖으로 나오지 않고 공개키만 내보내져 원격 증명에 쓰였다.

    리눅스 bash shell의 환경 변수에 대한 설명으로 옳은 것은?

    3. 3. PATH는 명령을 탐색할 경로를 의미한다.

    🧮 풀이
    1. 엔지니어 甲은 택배사 서버에 원격 접속한 화면에서 top 출력이 깨지자 echo $TERM 으로 값을 찍었고 dumb가 나왔다. TERM 값을 xterm으로 바꾸자 터미널 종류가 맞춰져 화면이 정상으로 그려졌다.

    4. 로그 점검을 하던 여행사 관리자 甲은 cd /var/log 로 이동한 뒤 echo $PWD 를 입력해 /var/log가 출력되는 화면을 띄웠다. 디렉터리를 옮길 때마다 PWD 값이 따라 바뀌었고, 패스워드 파일 위치와는 아무 관계가 없었다.

    PATH는 명령을 입력했을 때 실행 파일을 찾아볼 디렉터리 목록을 담는 환경 변수다. 정답은 3번이다.

    1. 외주 작업이 끝난 뒤 물류센터 서버 관리자 甲은 권한 사용 감사 로그에서 누군가 서버 시간을 바꾸려 한 기록을 찾아냈다. 시간 변경 권한을 쓴 계정 이름이 함께 남아 있어 외주 직원의 실수로 밝혀졌다.
    2. 도메인 관리자 甲은 택배사 직원이 지점 PC에 도메인 계정으로 로그온하자 도메인 컨트롤러 보안 로그에 자격 증명 검증 이벤트가 생기는 것을 보았다. 같은 순간 지점 PC 쪽에는 로그온 이벤트가 따로 쌓여, 두 항목이 기록되는 위치가 달랐다.
    3. 고객 정보 폴더를 지키는 쇼핑몰 보안 담당 甲은 그 폴더에 감사 항목을 걸고 개체 액세스 감사를 켰다. 다음 날 보안 로그에 파일 삭제를 시도한 계정과 시각이 남아 있어 그 계정의 접근 권한을 회수했다.
    4. 퇴근 시간 뒤 여행사 IT 담당 甲은 새 관리자 계정이 만들어진 이벤트를 계정 관리 감사 로그에서 발견했다. 누가 어느 그룹에 그 계정을 넣었는지까지 남아 있어 침입 경로를 빠르게 추적하고 계정을 비활성화했다.

    계정 로그온 이벤트는 자격 증명을 검증하는 쪽, 주로 도메인 컨트롤러에서 생기는 인증 이벤트를 감사하므로 2번이 틀린 설명이다. 정답은 2번이다.

    안티 리버싱 기법으로 프로그램의 실행 코드나 데이터를 압축 및 암호화하여 저장하는 기술은?

    1. 1. 패킹
    2. 2. 디컴파일
    3. 3. 시큐어 코딩
    4. 4. 안티 디버깅

    정답 1번

    🔍 보기별 해설
    1. 패킹은 실행 파일의 코드와 데이터를 압축하거나 암호화해 저장하고 실행 순간 메모리에서 풀어 내는 안티 리버싱 기법이다. 물음이 찾는 기술이므로 옳다(정답).
    2. 디컴파일은 기계어나 바이트코드를 사람이 읽기 쉬운 고급 언어 코드로 되돌리는 분석 기법이다. 리버싱을 막는 쪽이 아니라 하는 쪽이므로 옳지 않다.
    3. 시큐어 코딩은 개발 단계에서 입력값 검증 같은 규칙을 지켜 취약점을 줄이는 개발 방법이다. 코드를 압축·암호화하는 안티 리버싱 기법이 아니므로 옳지 않다.
    4. 안티 디버깅은 디버거가 붙었는지 감지해 실행을 멈추거나 흐름을 바꾸는 안티 리버싱 기법이다. 코드를 압축·암호화해 저장하는 기술은 아니므로 옳지 않다.
    🧮 풀이
    1. 앱 개발자 甲은 쇼핑몰 결제 모듈 실행 파일을 UPX로 패킹해 배포했다. 디스어셈블러로 열면 압축된 데이터만 보이고 실제 코드는 실행 순간 메모리에서 풀려, 분석하려는 사람은 언패킹부터 해야 했다.
    2. 악성코드 분석가 甲은 의심 파일의 닷넷 바이트코드를 디컴파일러에 넣어 C# 소스에 가까운 코드로 되돌렸다. 코드 안에 박혀 있던 명령 서버 주소가 그대로 보여 방화벽 차단 목록에 바로 올렸다.
    3. 예약 페이지를 만들던 여행사 웹 개발팀 甲은 모든 입력값을 서버에서 검증하고 SQL은 바인딩 변수로만 짜는 시큐어 코딩 규칙을 적용했다. 이 규칙은 취약점을 줄일 뿐 완성된 실행 파일을 숨기거나 압축하지는 않았다.
    4. 게임 보안 담당 甲은 클라이언트에 IsDebuggerPresent 검사를 넣어 디버거가 붙으면 바로 종료되게 했다. 해커가 디버거로 실행하자 프로그램이 곧바로 꺼졌지만 실행 파일 자체는 압축되지 않은 상태였다.

    실행 코드와 데이터를 압축·암호화해 저장하고 실행할 때 풀어 분석을 어렵게 하는 안티 리버싱 기법은 패킹이다. 정답은 1번이다.

    취약점에 대한 보안 패치가 나오지 않은 시점에서 이루어지는 공격을 의미하는 것은?

    1. 1. 제로데이(Zero-day)
    2. 2. 사회공학(Social Engineering)
    3. 3. 분산 서비스 거부(DDoS)
    4. 4. 무차별 대입(Brute Force)

    정답 1번

    🔍 보기별 해설
    1. 제로데이(Zero-day) 공격은 취약점이 알려졌지만 제조사의 보안 패치가 아직 배포되지 않은 틈을 노린다. 방어 수단이 나오기 전의 무방비 구간을 이용한다는 설명과 같으므로 옳다(정답).
    2. 사회공학(Social Engineering)은 시스템 결함보다 사람의 신뢰나 실수를 이용해 정보를 빼내는 기법이다. 패치가 없는 시점이라는 조건과 관계가 없으므로 옳지 않다.
    3. 분산 서비스 거부(DDoS)는 여러 대의 감염 기기로 대량 트래픽을 보내 서비스를 마비시키는 공격이다. 패치 공개 시점이 아니라 자원 고갈이 목적이므로 옳지 않다.
    4. 무차별 대입(Brute Force)은 가능한 비밀번호나 키를 처음부터 끝까지 하나씩 넣어 맞히는 공격이다. 패치되지 않은 취약점을 노리는 공격과 원리가 다르므로 옳지 않다.
    🧮 풀이
    1. 게임사 보안팀 甲은 새벽에 자사 게임 런처의 미공개 취약점을 노린 악성코드가 퍼진 것을 탐지했다. 개발사도 그때까지 이 결함을 몰라 고칠 패치가 없었고, 甲은 패치가 나올 때까지 런처 업데이트 서버를 임시로 막았다. 패치 이전에 들어온 Zero-day 공격이었다.
    2. 통신사 고객센터 직원 甲은 본사 전산팀을 사칭한 전화를 받고 관리자 계정 비밀번호를 불러 주었다. 공격자는 시스템 취약점을 하나도 건드리지 않고 그 비밀번호로 내부망에 들어왔다. 사람의 신뢰를 이용한 Social Engineering 공격이다.
    3. 스타트업 대표 甲은 수천 대의 좀비 PC가 쇼핑몰 서버에 한꺼번에 접속 요청을 보내 회선이 꽉 차는 일을 겪었다. 정상 고객은 몇 시간 동안 결제 화면조차 열지 못했다. 여러 출발지에서 자원을 소모시키는 DDoS 공격이다.
    4. 제조 공장 MES 관리자 甲은 원격 접속 로그에서 같은 계정에 1초마다 다른 비밀번호가 수만 번 입력된 흔적을 찾았다. 甲은 5회 실패하면 계정을 잠그는 정책을 켜 공격을 멈췄다. 모든 조합을 차례로 넣어 보는 Brute Force 공격이다.

    제로데이 공격은 취약점이 알려졌지만 보안 패치가 아직 배포되지 않은 틈을 노리는 공격이므로 정답은 1번이다.

    침입자에게 거짓 자원을 실제 자원처럼 보이도록 하여 공격을 유도하고, 침입자에 대한 정보를 얻기 위한 시스템은?

    1. 1. IPS
    2. 2. DMZ
    3. 3. Firewall
    4. 4. Honeypot

    정답 4번

    🔍 보기별 해설
    1. IPS(침입방지시스템)는 네트워크 트래픽을 실시간으로 분석해 공격으로 판단한 패킷을 바로 차단하는 장비다. 거짓 자원으로 침입자를 끌어들이는 시스템이 아니므로 옳지 않다.
    2. DMZ(비무장지대)는 외부에 공개할 웹·메일 서버를 내부망과 떼어 두는 중간 네트워크 구역이다. 실제 서비스를 두는 공간이지 미끼 시스템이 아니므로 옳지 않다.
    3. Firewall(방화벽)은 미리 정한 규칙에 따라 IP와 포트 단위로 트래픽을 허용하거나 막는 장치다. 침입자를 유인해 정보를 모으는 기능은 없으므로 옳지 않다.
    4. Honeypot(허니팟)은 실제처럼 꾸민 가짜 서버나 자원을 두어 침입자를 끌어들이고 그 행동을 기록하는 시스템이다. 거짓 자원으로 공격을 유도해 침입자 정보를 얻는다는 설명과 같으므로 옳다(정답).
    🧮 풀이
    1. 5G 관제센터 甲은 IPS 정책에 새로 알려진 웜의 시그니처를 등록했다. 다음 날 그 웜이 내부로 들어오려 하자 IPS가 그 패킷만 골라 즉시 버렸고 서버에는 아무 흔적도 남지 않았다. 탐지와 차단을 한 번에 하는 장비가 IPS다.
    2. 인프라 담당 甲은 스타트업 홈페이지 서버를 내부 개발망과 다른 DMZ 구간으로 옮겼다. 몇 달 뒤 홈페이지가 뚫렸지만 공격자는 방화벽에 막혀 개발 서버까지 내려가지 못했다. 공개 서버를 따로 떼어 두는 구조가 DMZ다.
    3. 네트워크 담당 甲은 게임사 Firewall 규칙에 게임 서버용 443번 포트만 열고 나머지 포트는 모두 막았다. 외부에서 원격 데스크톱 포트로 들어오던 접속 시도는 규칙에 걸려 전부 거부되었다. 규칙대로 출입을 통제하는 장치가 방화벽이다.
    4. 제조 공장 보안 담당 甲은 생산설비 제어 서버처럼 꾸민 가짜 서버를 Honeypot으로 띄웠다. 며칠 뒤 공격자가 그 서버에 들어와 입력한 명령어와 접속 IP가 고스란히 남았고, 甲은 그 IP를 실제 방화벽에서 막았다. 미끼로 공격자를 끌어들여 정보를 얻는 시스템이다.

    실제 자원처럼 꾸민 미끼로 침입자를 끌어들이고 그 행동 정보를 모으는 시스템은 허니팟(Honeypot)이므로 정답은 4번이다.

    다음에서 설명하는 공격은?

    게시판이나 이메일 등에 악의적인 스크립트를 삽입하여 게시글이나 이메일을 읽는 사용자의 쿠키를 탈취하는 공격 기법이다.

    1. 1. XSS
    2. 2. SQL Injection
    3. 3. DNS Spoofing
    4. 4. IP Spoofing

    정답 1번

    🔍 보기별 해설
    1. XSS(Cross-Site Scripting)는 게시판·메일 본문에 악성 스크립트를 넣어 그 글을 연 사용자의 브라우저에서 실행되게 하는 공격이다. 스크립트로 열람자의 쿠키를 빼 가는 기법이 바로 이것이므로 옳다(정답).
    2. SQL Injection은 입력값에 SQL 구문을 끼워 넣어 데이터베이스 질의를 조작하는 공격이다. 서버 DB를 노리지 열람자 브라우저에서 스크립트를 돌리는 공격이 아니므로 옳지 않다.
    3. DNS Spoofing은 DNS 응답을 위조해 사용자를 가짜 사이트 IP로 보내는 공격이다. 게시글에 스크립트를 심는 방식이 아니므로 옳지 않다.
    4. IP Spoofing은 패킷의 출발지 IP 주소를 다른 주소로 위조해 신뢰 관계를 속이는 공격이다. 쿠키를 훔치려고 스크립트를 넣는 공격과 관련이 없으므로 옳지 않다.
    🧮 풀이
    1. 모바일 게임 커뮤니티 운영자 甲은 공략 게시판의 한 글에 스크립트 태그가 숨어 있는 것을 발견했다. 그 글을 연 회원들의 세션 쿠키가 외부 서버로 넘어가 계정이 도용되었고, 甲은 입력값의 꺾쇠 기호를 문자로 바꿔 저장하도록 게시판을 고쳤다. 전형적인 XSS 피해다.
    2. 반도체 장비 업체 개발자 甲은 로그인 창 아이디 칸에 항상 참이 되는 OR 조건문이 입력된 로그를 발견했다. 그 입력 때문에 비밀번호 없이 관리자 계정으로 로그인된 상태였고, 甲은 파라미터 바인딩으로 코드를 바꿨다. DB 질의를 조작하는 SQL Injection이다.
    3. 알뜰폰 통신사 고객 甲은 은행 주소를 정확히 입력했는데도 생김새만 같은 가짜 로그인 화면으로 연결되었다. 공유기가 받은 DNS 응답이 위조되어 은행 도메인이 공격자 서버 IP로 바뀌어 있었다. 이름 풀이 단계를 속인 DNS Spoofing이다.
    4. 자동차 부품 공장 네트워크 담당 甲은 내부 서버 IP를 출발지로 단 패킷이 외부 회선에서 들어오는 것을 탐지했다. 공격자가 신뢰받는 주소로 위장해 접근 제한을 피하려 한 것이었고, 甲은 외부에서 들어오는 내부 대역 패킷을 버리도록 설정했다. 출발지를 위조한 IP Spoofing이다.

    게시판이나 이메일 본문에 스크립트를 심어 그 글을 연 사용자의 쿠키를 빼 가는 공격은 XSS이므로 정답은 1번이다.

    리눅스 커널의 부팅 과정에서 발생하는 로그를 확인할 수 있는 명령어는?

    1. 1. cron
    2. 2. dmesg
    3. 3. wtmp
    4. 4. sulog

    정답 2번

    🔍 보기별 해설
    1. cron은 정해진 시각에 명령을 자동으로 실행하도록 예약해 두는 리눅스 스케줄러 데몬이다. 커널 부팅 메시지를 보여 주는 명령어가 아니므로 옳지 않다.
    2. dmesg는 커널 링 버퍼에 쌓인 메시지를 출력해 부팅 중 장치 인식과 드라이버 적재 과정을 보여 주는 명령어다. 커널 부팅 로그를 보는 도구이므로 옳다(정답).
    3. wtmp는 사용자 로그인·로그아웃과 시스템 재부팅 기록을 모아 두는 로그 파일이며 last 명령으로 읽는다. 명령어가 아닌 접속 기록 파일이므로 옳지 않다.
    4. sulog는 su 명령으로 다른 계정 권한을 얻으려 한 시도와 그 성공·실패를 남기는 로그 파일이다. 커널 부팅 과정과 관련이 없으므로 옳지 않다.
    🧮 풀이
    1. 물류센터 서버 관리자 甲은 매일 새벽 2시에 백업 스크립트가 돌도록 crontab에 한 줄을 추가했다. 그날 밤부터 甲이 자리에 없어도 백업 파일이 자동으로 만들어졌다. 작업 예약을 맡는 데몬이 cron이다.
    2. 제조 라인 PC 담당 甲은 새로 꽂은 USB 바코드 리더가 인식되지 않자 터미널에서 dmesg를 실행했다. 출력 끝부분에 장치 드라이버를 불러오지 못했다는 커널 메시지가 보여 드라이버를 다시 설치했다. 커널이 남긴 부팅·장치 메시지를 보는 명령이다.
    3. 인디 게임 스튜디오 서버 담당 甲은 last 명령으로 /var/log/wtmp를 읽어 새벽 3시에 낯선 IP로 root 로그인이 있었던 사실을 찾아냈다. 甲은 곧바로 비밀번호를 바꾸고 SSH root 접속을 막았다. 로그인 이력이 쌓이는 파일이 wtmp다.
    4. 통신 장비 회사 관리자 甲은 sulog를 열어 개발자 계정이 밤새 su 명령으로 root 전환을 수십 번 실패한 흔적을 보았다. 甲은 그 계정을 잠그고 담당 개발자에게 경위를 물었다. 권한 전환 시도를 남기는 기록이 sulog다.

    리눅스 커널 링 버퍼에 쌓인 부팅·장치 인식 메시지를 출력해 보여 주는 명령어는 dmesg이므로 정답은 2번이다.

    다음에서 설명하는 암호 알고리즘은?

    국내의 국가보안기술연구소 주도로 학계, 연구소, 정부기관 등의 암호 전문가들이 공동 개발한 암호화 알고리즘으로 KS인증을 획득하였다.

    1. 1. ARIA
    2. 2. DES
    3. 3. SEED
    4. 4. IDEA

    정답 1번

    🔍 보기별 해설
    1. ARIA는 국가보안기술연구소가 주도하고 학계·연구소·정부기관 전문가가 함께 만든 128비트 블록 암호로 KS 표준으로 제정되었다. 개발 주체와 KS 인증이라는 조건을 모두 갖추므로 옳다(정답).
    2. DES는 미국이 1977년 연방 표준으로 채택한 56비트 키 블록 암호로 IBM의 설계에서 나왔다. 국내에서 개발된 알고리즘이 아니므로 옳지 않다.
    3. SEED는 지금의 KISA(한국인터넷진흥원) 전신 기관이 중심이 되어 1999년 개발한 128비트 블록 암호다. 국내 암호이지만 국가보안기술연구소 주도로 만든 ARIA와 개발 주체가 다르므로 옳지 않다.
    4. IDEA는 스위스의 라이(Lai)와 메시(Massey)가 1990년대 초 개발한 128비트 키 블록 암호로 PGP에 쓰였다. 해외에서 개발된 알고리즘이므로 옳지 않다.
    🧮 풀이
    1. 공공기관 납품을 준비하는 스타트업 개발자 甲은 국내 표준 암호를 쓰라는 요구에 따라 고객 개인정보 암호화 모듈을 ARIA로 바꿨다. 국가보안기술연구소 주도로 만든 KS 표준 알고리즘이라 보안성 심사를 문제없이 통과했다. 국내 공공 분야에서 널리 쓰는 ARIA다.
    2. 오래된 공장 설비 PC를 점검하던 보안 컨설턴트 甲은 생산 데이터 전송에 DES가 쓰이고 있는 것을 찾아냈다. 56비트 키는 지금 장비로 짧은 시간에 전수 조사가 가능해 甲은 AES로 교체하라고 권고했다. 미국 표준으로 출발한 DES다.
    3. 인터넷뱅킹 플러그인을 유지보수하는 핀테크 개발자 甲은 예전 코드에서 SEED 암호 호출부를 발견했다. 1999년 국내에서 만든 이 알고리즘은 한때 금융권에서 널리 쓰였지만 ARIA와는 만든 기관이 다르다. 甲은 두 알고리즘의 출처를 코드 주석에 남겼다.
    4. 이메일 암호화 도구를 분석하던 통신사 연구원 甲은 구버전 PGP 설정에 IDEA가 기본 대칭 암호로 들어가 있는 것을 보았다. 이 알고리즘은 스위스에서 개발되어 특허 문제로 한동안 사용이 제한되기도 했다. 국외에서 만든 IDEA다.

    국가보안기술연구소 주도로 학계·연구소·정부 전문가가 함께 만들어 KS 표준이 된 블록 암호는 ARIA이므로 정답은 1번이다.

    리버스 엔지니어링 기법에 해당하는 것은?

    1. 1. 난독화
    2. 2. 언패킹
    3. 3. 디지털 서명
    4. 4. 안티 디버깅

    정답 2번

    🔍 보기별 해설
    1. 난독화는 코드의 구조와 변수 이름을 알아보기 어렵게 바꿔 분석을 방해하는 기법이다. 리버스 엔지니어링을 막는 쪽의 기술이므로 옳지 않다.
    2. 언패킹은 패커로 압축·암호화된 실행 파일을 원래 코드 형태로 풀어내는 작업이다. 숨겨진 코드를 꺼내 분석하는 리버스 엔지니어링 과정의 기법이므로 옳다(정답).
    3. 디지털 서명은 개인키로 서명해 데이터의 출처와 무결성을 증명하는 기술이다. 프로그램을 거꾸로 분석하는 기법이 아니므로 옳지 않다.
    4. 안티 디버깅은 디버거가 붙으면 이를 탐지해 실행을 멈추거나 흐름을 바꾸는 기법이다. 분석을 방해하는 안티 리버싱 기술이므로 옳지 않다.
    🧮 풀이
    1. 모바일 게임사 개발자 甲은 앱을 배포하기 전에 변수와 함수 이름을 a, b, c 같은 무의미한 글자로 바꾸는 난독화를 적용했다. 경쟁사가 앱을 디컴파일해도 로직을 읽어 내기 어려워졌다. 분석을 막기 위한 보호 기법이다.
    2. 악성코드 분석가 甲은 UPX로 압축된 랜섬웨어 샘플이 분석 도구에서 읽히지 않자 언패킹부터 했다. 압축이 풀린 코드에서 암호화 대상 확장자 목록과 공격자 서버 주소가 나왔다. 숨긴 코드를 꺼내는 리버스 엔지니어링 단계다.
    3. 산업용 펌웨어를 배포하는 제조사 엔지니어 甲은 업데이트 파일에 회사 개인키로 디지털 서명을 붙였다. 현장 장비는 서명 검증에 실패한 위조 펌웨어의 설치를 거부했다. 출처와 무결성을 보장하는 기술이다.
    4. 치트 방지 솔루션 개발자 甲은 디버거 연결을 감지하면 게임을 즉시 종료하는 안티 디버깅 코드를 넣었다. 치트 제작자가 메모리를 들여다보려 할 때마다 프로세스가 꺼져 분석이 막혔다. 리버싱을 방해하는 기법이다.

    난독화와 안티 디버깅은 분석을 막는 기술이고, 압축된 코드를 풀어 분석하는 언패킹이 리버스 엔지니어링 기법이므로 정답은 2번이다.

    다음에서 설명하는 공격은?

    소유자가 root이고 SetUID 비트를 가진 프로세스가 생성한 임시 파일의 처리가 완료되기 전에 공격자의 프로세스가 동일한 이름의 심볼릭 링크 파일을 생성하여 root 소유의 파일 내용을 수정하는 공격 기법이다.

    1. 1. Race Condition
    2. 2. Format String
    3. 3. Heap Overflow
    4. 4. Stack Overflow

    정답 1번

    🔍 보기별 해설
    1. Race Condition은 두 프로세스가 같은 자원에 접근하는 순서의 틈을 노려 결과를 바꾸는 공격이다. SetUID 프로세스의 임시 파일을 심볼릭 링크로 바꿔치기하는 설명과 같으므로 옳다(정답).
    2. Format String 공격은 printf 같은 함수에 서식 문자열을 검증 없이 넘길 때 %n 등을 넣어 메모리를 읽거나 쓰는 공격이다. 임시 파일과 심볼릭 링크를 이용하지 않으므로 옳지 않다.
    3. Heap Overflow는 동적으로 할당한 힙 영역의 버퍼를 넘치게 써서 인접 데이터나 관리 정보를 덮는 공격이다. 파일 처리 시점의 틈을 노리는 방식이 아니므로 옳지 않다.
    4. Stack Overflow는 지역 버퍼를 넘치게 써서 스택의 반환 주소를 덮어 실행 흐름을 빼앗는 공격이다. 심볼릭 링크 바꿔치기와 관계가 없으므로 옳지 않다.
    🧮 풀이
    1. 모의해킹 담당 甲은 통신사 리눅스 서버에서 root 소유 SetUID 프로그램이 /tmp에 임시 파일을 만들고 잠시 뒤 내용을 쓰는 것을 발견했다. 그 사이에 같은 이름으로 /etc/shadow를 가리키는 심볼릭 링크를 만들자 shadow 내용이 바뀌었다. 시점의 틈을 노린 Race Condition이다.
    2. 보안 연구원 甲은 사내 메신저 서버에서 사용자 입력이 printf의 첫 인자로 그대로 들어가는 코드를 찾았다. 대화명에 %x를 여러 개 넣자 스택 메모리 값이 화면에 쏟아졌다. 서식 문자를 악용하는 Format String 취약점이다.
    3. 채팅 서버를 만드는 게임사 개발자 甲은 malloc으로 받은 64바이트 버퍼에 길이 검사 없이 메시지를 복사하는 코드를 발견했다. 긴 메시지를 보내자 바로 뒤 힙 블록의 관리 정보가 깨지며 서버가 죽었다. 힙 영역을 넘친 Heap Overflow다.
    4. 공장 제어 프로그램을 시험하던 엔지니어 甲은 지역 배열에 strcpy로 긴 문자열을 넣자 함수가 끝날 때 엉뚱한 주소로 점프하는 것을 보았다. 넘친 데이터가 스택의 반환 주소를 덮어쓴 것이었다. 전형적인 Stack Overflow다.

    SetUID 프로세스의 임시 파일 처리가 끝나기 전 틈에 같은 이름의 심볼릭 링크를 끼워 넣는 공격은 Race Condition이므로 정답은 1번이다.

    리눅스에서 파일 시스템의 상태를 점검하고, 문제가 있을 때 복구하는 기능을 가진 명령어는?

    1. 1. fdisk
    2. 2. df
    3. 3. fsck
    4. 4. fstab

    정답 3번

    🔍 보기별 해설
    1. fdisk는 디스크의 파티션을 만들고 지우거나 크기를 바꾸는 파티션 관리 명령어다. 파일 시스템 오류를 점검·복구하지 않으므로 옳지 않다.
    2. df는 마운트된 파일 시스템별 전체 용량과 사용량, 남은 공간을 보여 주는 명령어다. 공간을 보여 줄 뿐 오류를 고치지 않으므로 옳지 않다.
    3. fsck는 파일 시스템의 무결성을 검사하고 깨진 inode나 블록 정보를 찾아 복구하는 명령어다. 상태 점검과 복구 기능을 함께 가지므로 옳다(정답).
    4. fstab은 부팅 때 어떤 장치를 어디에 마운트할지 적어 두는 /etc/fstab 설정 파일이다. 명령어가 아닌 설정 파일이므로 옳지 않다.
    🧮 풀이
    1. 신규 저장 서버를 들인 웹툰 플랫폼 관리자 甲은 fdisk로 2TB 디스크를 두 파티션으로 나눴다. 한쪽은 원고 파일용, 다른 쪽은 백업용으로 따로 포맷해 쓰기 시작했다. 디스크 영역을 나누는 도구가 fdisk다.
    2. 로그가 쌓여 서비스가 느려지자 스타트업 개발자 甲은 df -h를 실행했다. /var 파티션 사용률이 98%로 나와 오래된 로그를 압축해 다른 디스크로 옮기자 서비스가 다시 빨라졌다. 용량 현황을 보여 주는 명령이 df다.
    3. 정전 뒤 생산관리 서버가 부팅 중 멈추자 공장 전산 담당 甲은 그 파티션을 언마운트하고 fsck를 실행했다. 깨진 inode 몇 개가 정리되고 조각 파일이 lost+found로 옮겨진 뒤 서버가 정상 부팅되었다. 검사와 복구를 함께 하는 명령이다.
    4. 새로 단 데이터 디스크가 재부팅 때마다 풀리자 게임사 인프라 담당 甲은 /etc/fstab에 장치와 마운트 위치를 한 줄 추가했다. 그 뒤로는 부팅할 때 디스크가 /data에 자동으로 붙었다. 마운트 정보를 담는 설정 파일이 fstab이다.

    파일 시스템 무결성을 검사하고 깨진 inode나 블록 정보를 찾아 복구하는 명령어는 fsck이므로 정답은 3번이다.
