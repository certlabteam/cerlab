    사용자 A가 사전에 비밀키를 공유하고 있지 않은 사용자 B에게 기밀성 보장이 요구되는 문서 M을 보내기 위한 메시지로 옳은 것은?

    KpuX: 사용자 X의 공개키 KprX: 사용자 X의 개인키 KS: 세션키 H(): 해시 함수 E(): 암호화 ||: 연결(concatenation) 연산자

    1. 1. M || EKprA(H(M))
    2. 2. EKprA(M || H(M))
    3. 3. EKS(M) || EKpuB(KS)
    4. 4. EKS(M) || EKprA(KS)

    정답 3번

    🔍 보기별 해설
    1. M||EKprA(H(M))은 A가 개인키로 해시에 서명한 형태이다. 인증과 무결성은 주지만 M이 평문으로 전달되어 기밀성이 없으므로 옳지 않다.
    2. EKprA(M||H(M))은 A의 개인키로 암호화한 것이라 A의 공개키를 아는 누구나 복호화할 수 있다. 기밀성이 아니라 서명 성격이므로 옳지 않다.
    3. EKS(M)||EKpuB(KS)는 문서를 세션키로 암호화하고 세션키는 B의 공개키로 감싸 B만 풀 수 있게 한 형태이다. 사전 공유 없이 기밀성을 얻는 방식이므로 옳다(정답).
    4. EKS(M)||EKprA(KS)는 세션키를 A의 개인키로 암호화한 것이라 A의 공개키를 가진 누구나 세션키를 얻을 수 있다. 기밀성이 깨지므로 옳지 않다.
    🧮 풀이
    1. 甲은 사전에 비밀번호를 정해 두지 않은 거래처에 계약서를 안전하게 보내야 하는 상황을 그려 보았다. 계약서는 세션키로 암호화하고 세션키는 상대의 공개키로 감싸 함께 보낸다고 적었다.
    2. 甲은 전자서명이 본문을 숨기지 못한다는 설명을 읽었다. 해시에 서명해 본문 옆에 붙이면 본문이 그대로 보인다는 점을 그림에 표시하고 기밀성 방식과 구분해 옆에 놓았다.
    3. 甲은 개인키로 암호화한 메시지를 누가 풀 수 있는지 그림으로 그려 보았다. 공개키를 가진 누구나 풀 수 있다는 사실을 살펴보고 기밀성 보장이 안 된다고 옆에 써 넣었다.
    4. 甲은 세션키를 송신자의 개인키로 감싸 보내는 경우를 종이에 그렸다. 공개키가 공개되어 있으니 누구나 세션키를 꺼낼 수 있다는 점을 짚고 붉은 화살표로 위험 구간을 표시했다.

    사전에 비밀키가 없는 B에게 기밀성을 보장하려면 세션키로 문서를 암호화하고 그 세션키를 B의 공개키로 암호화해 보낸다.

    보안 서비스와 이를 제공하기 위한 보안 기술을 잘못 연결한 것은?

    1. 1. 데이터 무결성 － 암호학적 해시
    2. 2. 신원 인증 － 인증서
    3. 3. 부인방지 － 메시지 인증 코드
    4. 4. 메시지 인증 － 전자 서명

    정답 3번

    🔍 보기별 해설
    1. 암호학적 해시는 데이터가 바뀌면 값이 달라져 위변조를 탐지하므로 데이터 무결성을 제공한다. 연결이 옳으므로 적절하다.
    2. 인증서는 공개키와 소유자를 묶어 인증기관이 보증하므로 상대의 신원을 확인하는 데 쓰인다. 연결이 옳으므로 적절하다.
    3. MAC은 송수신자가 같은 비밀키를 공유하므로 둘 중 누구도 만들 수 있어 제3자에게 송신 사실을 증명하지 못한다. 부인방지는 개인키로 만드는 전자서명으로 제공하므로 잘못 연결되어 옳지 않다(정답).
    4. 전자서명은 서명자만 가진 개인키로 만들어 메시지가 그 사람에게서 왔음을 확인하므로 메시지 인증을 제공한다. 연결이 옳으므로 적절하다.
    🧮 풀이
    1. 甲은 파일을 내려받은 뒤 해시값을 직접 계산해서 배포처에 게시된 값과 견주어 보았다. 값이 같아 파일이 바뀌지 않았다는 점을 확인하고 해시가 무결성용이라고 옆에 따로 써 넣었다.
    2. 甲은 사이트 주소창 옆 자물쇠를 눌러 발급 기관과 사이트 이름이 적힌 인증서 화면을 열었다. 사이트의 신원을 인증서가 보증한다는 사실을 살펴보고 공개키와 이름을 옮겨 적었다.
    3. 甲은 계약서를 MAC으로 보낸 경우 나중에 보낸 쪽이 부인하면 어떻게 되는지 따져 보았다. 두 사람이 같은 키를 갖고 있어 제3자가 누구 것인지 가릴 수 없다는 점을 그림에 표시했다.
    4. 甲은 전자문서에 서명한 사람의 개인키로 만든 서명 값을 공개키로 검증해 보았다. 서명자가 보낸 것이라는 사실이 그대로 확인된다는 점을 표의 메시지 인증 칸에 옮겨 적어 넣었다.

    부인방지는 전자서명으로 제공한다. 메시지 인증 코드(MAC)는 공유 비밀키를 쓰므로 제3자에게 송신 사실을 증명하지 못한다.

    웹 서버와 클라이언트 간의 쿠키 처리 과정으로 옳지 않은 것은?

    1. 1. HTTP 요청 메시지의 헤더 라인을 통한 쿠키 전달
    2. 2. HTTP 응답 메시지의 상태 라인을 통한 쿠키 전달
    3. 3. 클라이언트 브라우저의 쿠키 디렉터리에 쿠키 저장
    4. 4. 웹 서버가 클라이언트에 관해 수집한 정보로부터 쿠키를 생성

    정답 2번

    🔍 보기별 해설
    1. 쿠키를 받은 클라이언트는 이후 요청에서 저장한 값을 Cookie 헤더 항목에 담아 서버에 돌려준다. 요청 메시지의 헤더 라인에 실리는 것이 맞으므로 쿠키 처리 과정으로 적절하다.
    2. 쿠키는 응답 메시지의 상태 라인이 아니라 헤더 라인의 Set-Cookie에 담아 전달한다. 상태 라인에는 HTTP 버전과 상태 코드가 들어가므로 옳지 않다(정답).
    3. 브라우저는 서버가 보낸 쿠키를 자신의 쿠키 디렉터리나 저장소에 보관했다가 이후 요청에 사용한다. 서술이 정확하므로 쿠키 처리 과정으로 적절하다.
    4. 웹 서버는 클라이언트에 관해 수집한 정보로 쿠키 값을 만들어 응답에 실어 보낸다. 서술이 정확하므로 쿠키 처리 과정으로 적절하다.
    🧮 풀이
    1. 甲은 개발자 도구로 로그인 이후의 요청 헤더를 열어 Cookie 항목이 붙은 것을 보았다. 저장된 값이 요청 헤더로 서버에 되돌아간다는 흐름을 화살표로 그려 두었다.
    2. 甲은 HTTP 응답의 첫 줄에는 상태 코드가 있고 Set-Cookie는 그 아래 헤더에 있다는 점을 발견했다. 쿠키가 첫 줄이 아니라 헤더 라인이라는 점을 응답 그림에 표시했다.
    3. 甲은 브라우저 설정에서 저장된 쿠키 목록을 열어 사이트별로 값이 쌓여 있는 것을 확인했다. 서버가 보낸 쿠키를 브라우저가 보관한다는 흐름을 한 줄로 정리해 붙여 두었다.
    4. 甲은 쇼핑몰이 방문자를 구분하려고 쿠키에 식별 번호를 넣어 응답하는 과정을 그려 보았다. 서버가 수집한 정보로 쿠키를 만든다는 단계에 번호를 붙여 그림 옆에 적었다.

    서버는 응답 메시지의 헤더 라인(Set-Cookie)으로 쿠키를 전달한다. 상태 라인으로 전달한다는 서술이 틀렸다.

    「개인정보 보호법」 제15조(개인정보의 수집ㆍ이용)에서 개인정보처리자가 개인정보를 수집할 수 있으며 그 수집 목적의 범위에서 이용할 수 있는 경우에 해당하지 않는 것은?

    1. 1. 정보주체의 동의를 받은 경우
    2. 2. 법률에 특별한 규정이 있거나 법령상 의무를 준수하기 위하여 불가피한 경우
    3. 3. 공공기관이 법령 등에서 정하는 소관 업무의 수행을 위하여 불가피한 경우
    4. 4. 공공기관과의 계약의 체결 및 이행을 위하여 불가피하게 필요한 경우

    정답 4번

    🔍 보기별 해설
    1. 정보주체의 동의를 받은 경우는 제15조 제1항 제1호로 개인정보를 수집·이용할 수 있는 사유이다. 조문에 실제로 들어 있으므로 해당한다.
    2. 법률에 특별한 규정이 있거나 법령상 의무를 지키기 위해 불가피한 경우도 제15조가 정한 수집·이용 사유이다. 조문에 실제로 들어 있으므로 해당한다.
    3. 공공기관이 법령 등에서 정한 소관 업무를 수행하기 위해 불가피한 경우도 수집·이용 사유로 정해져 있다. 조문에 실제로 들어 있으므로 해당한다.
    4. 조문은 정보주체와 체결한 계약의 이행에 필요한 경우를 사유로 정하고 있다. 공공기관과의 계약이라고 한 서술은 조문과 달라 사유에 해당하지 않는다(정답).
    🧮 풀이
    1. 甲은 회원 가입 화면에서 이용약관 동의를 눌러야 다음 단계로 넘어가는 것을 보았다. 정보주체의 동의가 수집·이용 사유라는 점을 조문에서 찾아 동의 항목 옆에 적어 두었다.
    2. 甲은 세금 신고 자료를 국세청에 제출해야 하는 회사의 개인정보 처리를 살펴보았다. 법령상 의무를 지키기 위한 수집이라 조문에 해당한다고 보고 근거 조항을 옆에 써 넣었다.
    3. 甲은 주민센터가 복지 업무를 위해 신청자의 정보를 받는 장면을 떠올렸다. 소관 업무 수행을 위한 수집 사유라는 점을 조문에서 다시 확인하고 공공기관 칸에 굵게 표시해 두었다.
    4. 甲은 택배 회사가 배송을 위해 고객 주소를 받는 상황을 조문에 대어 보았다. 정보주체와 맺은 계약의 이행이 사유라는 점을 확인하고 공공기관과의 계약이라는 보기에는 가위 표시를 했다.

    개인정보 보호법 제15조는 정보주체와 체결한 계약의 이행에 필요한 경우를 든다. 공공기관과의 계약이라는 서술은 조문과 다르다.

    함수 P에서 호출한 함수 Q가 자신의 작업을 마치고 다시 함수 P로 돌아가는 과정에서의 스택 버퍼 운용 과정을 순서대로 바르게 나열한 것은?

    (가) 스택에 저장되어 있는 복귀 주소(return address)를 pop한다. (나) 스택 포인터를 프레임 포인터의 값으로 복원시킨다. (다) 이전 프레임 포인터 값을 pop하여 스택 프레임 포인터를 P의 스택 프레임으로 설정한다. (라) P가 실행했던 함수 호출(function call) 인스트럭션 다음의 인스트럭션을 실행한다.

    1. 1. (가) → (나) → (다) → (라)
    2. 2. (가) → (다) → (라) → (나)
    3. 3. (나) → (가) → (라) → (다)
    4. 4. (나) → (다) → (가) → (라)

    정답 4번

    🔍 보기별 해설
    1. (가)부터 시작하면 스택 포인터가 지역 변수 영역을 지나 프레임 포인터 위치로 돌아오기 전에 복귀 주소를 꺼내게 된다. 첫 단계가 어긋나므로 순서가 옳지 않다.
    2. (가)-(다)-(라)-(나)는 복귀 주소를 먼저 꺼내고 프레임 포인터를 그다음에 복원한다. 프레임 포인터 정리 없이 다음 명령을 실행하려 하므로 순서가 옳지 않다.
    3. (나)-(가)-(라)-(다)는 스택 포인터를 복원한 뒤 이전 프레임 포인터를 꺼내지 않고 곧바로 복귀 주소를 꺼낸다. 이전 프레임 포인터가 스택 맨 위에 있으므로 순서가 옳지 않다.
    4. 먼저 (나) 스택 포인터를 프레임 포인터로 복원하고 (다) 이전 프레임 포인터를 pop해 P의 프레임으로 되돌린 다음 (가) 복귀 주소를 pop해 (라) 호출 다음 명령을 실행한다. 순서가 옳다(정답).
    🧮 풀이
    1. 甲은 함수 Q가 끝날 때 스택에 쌓여 있던 값이 어떤 순서로 빠지는지 그림으로 그렸다. 지역 변수를 버리고 이전 프레임 포인터를 꺼낸 다음 복귀 주소를 꺼낸다고 번호를 붙였다.
    2. 甲은 복귀 주소를 먼저 꺼내면 어떤 일이 생기는지 따져 보았다. 프레임 포인터를 정리하지 못한 채 P로 돌아가면 스택이 어긋난다는 점을 그림 속 해당 자리에 붉은 표시로 남겼다.
    3. 甲은 이전 프레임 포인터가 복귀 주소 바로 아래 스택 맨 위에 놓인다는 점을 그려 확인했다. 그래서 복귀 주소를 꺼내기 전에 이 값이 먼저 나와야 한다는 점을 화살표로 표시했다.
    4. 甲은 스택 프레임 네 단계를 아래에서 위로 쌓은 그림을 그리고 복귀 단계를 번호로 매겼다. 스택 포인터 복원, 프레임 포인터 pop, 복귀 주소 pop, 다음 명령 실행 순으로 적어 넣었다.

    블록 암호의 운영 모드 중 ECB 모드와 CBC 모드에 대한 설명으로 옳은 것은?

    1. 1. ECB 모드는 블록의 변화가 다른 블록에 영향을 주지 않아 안전하다.
    2. 2. ECB 모드는 암호화할 때, 같은 데이터 블록에 대해 같은 암호문 블록을 생성한다.
    3. 3. CBC 모드는 블록의 변화가 이전 블록에 영향을 주므로 패턴을 추적하기 어렵다.
    4. 4. CBC 모드는 암호화할 때, 이전 블록의 결과가 필요하지 않다.

    정답 2번

    🔍 보기별 해설
    1. ECB는 블록이 서로 영향을 주지 않는 것은 맞지만 같은 평문이 같은 암호문이 되어 패턴이 그대로 드러난다. 이를 안전하다고 한 결론이 틀렸으므로 옳지 않다.
    2. ECB는 블록을 독립적으로 같은 키로 암호화하므로 같은 평문 블록은 언제나 같은 암호문 블록이 된다. 이것이 ECB의 대표적 약점이므로 옳다(정답).
    3. CBC는 이전 암호문 블록이 다음 블록의 암호화에 XOR로 들어가므로 영향은 앞에서 뒤로 흐른다. 이전 블록에 영향을 준다고 한 방향이 반대이므로 옳지 않다.
    4. CBC는 평문 블록을 이전 암호문 블록과 XOR한 뒤 암호화하므로 이전 결과가 반드시 필요하다. 첫 블록만 초기 벡터를 쓰므로 옳지 않다.
    🧮 풀이
    1. 甲은 같은 로고가 반복되는 그림 파일을 ECB로 암호화한 결과를 보았다. 같은 색 블록이 같은 암호문으로 바뀌어 윤곽이 그대로 비쳐 보이는 것을 확인하고 그림 옆에 원인을 적어 두었다.
    2. 甲은 모의고사를 채점하다가 블록마다 따로 암호화되니 안전하다는 후배의 말을 듣고 반박 자료를 찾았다. 독립성 때문에 오히려 같은 블록이 같은 값으로 나온다는 점을 ECB 설명 아래에 옮겨 적었다.
    3. 甲은 쉬는 시간에 CBC에서 세 번째 블록을 바꾸면 뒤 블록의 암호문이 달라지는 그림을 그려 보았다. 영향이 앞으로 가지 않고 뒤로만 퍼진다는 점에 화살표를 그려 넣고 방향을 표시했다.
    4. 甲은 일요일 오후 스터디 카페에서 CBC 암호화 순서를 손으로 따라가며 두 번째 블록을 만들어 보았다. 첫 암호문 블록이 있어야 두 번째를 만들 수 있다는 것을 확인하고 초기 벡터 칸에 동그라미를 쳤다.

    ECB는 같은 평문 블록이 같은 암호문 블록이 되어 패턴이 드러나고, CBC는 이전 암호문 블록을 XOR한다.

    3. 甲은 일요일 오후 스터디 카페에서 방범 카메라 영상 속 얼굴로 누구인지 알 수 있는 경우를 조사했다. 영상도 개인정보라는 조문을 확인하고 영상 보관 기간을 수첩에 써 두었다.
    4. 甲은 모의고사를 채점하다가 고인이 남긴 기록의 성격을 법 조문에서 찾아보았다. 이 법이 살아 있는 개인을 대상으로 한다는 문구를 확인하고 사망자 정보를 개인정보 예 목록에서 지웠다.

    개인정보 보호법의 개인정보는 살아 있는 개인에 관한 정보이므로 사망자 정보는 해당하지 않는다.

    다음에서 설명하는 기술은?

    ○ 공인 IP 주소가 내부 사설 IP 주소보다 부족한 경우에 적용 가능한 방식이다.

    ○ 내부 사설 IP 주소나 내부 네트워크 대역을 공인 IP로 자동 매핑하는 기능을 제공한다.

    ○ 내부 IP 주소를 외부로부터 보호해 주는 기능을 제공하기도 한다.

    1. 1. ARP
    2. 2. IPS
    3. 3. NAT
    4. 4. VLAN

    정답 3번

    🔍 보기별 해설
    1. ARP는 IP 주소에 대응하는 MAC 주소를 알아내는 프로토콜이다. 사설 IP를 공인 IP로 매핑하는 기능이 없으므로 옳지 않다.
    2. IPS는 네트워크에서 침입을 탐지하고 실시간으로 차단하는 보안 장비이다. 주소 변환 기능이 아니므로 옳지 않다.
    3. NAT는 내부 사설 IP를 공인 IP로 자동 매핑하여 부족한 공인 주소를 나눠 쓰게 한다. 내부 주소를 외부에 감추는 효과도 있으므로 옳다(정답).
    4. VLAN은 물리 망을 논리적으로 나누어 브로드캐스트 영역을 분리하는 기술이다. 주소 변환과 관계가 없으므로 옳지 않다.
    🧮 풀이
    1. 甲은 퇴근 뒤 도서관 열람실에서 IP 주소로 MAC 주소를 묻는 ARP 요청 패킷을 캡처해 보았다. 주소 변환이 아니라 주소 조회라는 점을 따져 보고 ARP 옆에 그 뜻을 기록해 두었다.
    2. 甲은 기출 문제집을 처음부터 다시 훑어보다가 침입 차단 장비가 의심 패킷을 막는 로그를 읽었다. 이 기능은 침입 방지이지 주소 변환이 아님을 IPS 곁에 정리하여 옮겨 써 두었다.
    3. 甲은 주말 자습 중에 집 공유기에 연결된 여러 기기가 하나의 공인 IP로 나가는 그림을 그렸다. 사설 주소가 공인 주소로 매핑되어 내부가 숨겨진다는 점을 NAT라고 이름 붙여 표시했다.
    4. 甲은 퇴근 뒤 도서관 열람실에서 기출 해설을 소리 내어 읽다가 부서마다 망을 나누는 설정 화면을 열어 보았다. 이는 논리적 분리인 VLAN의 역할이라 주소 변환과 구분하여 다른 항목으로 정리해 두었다.

    공인 IP 부족을 사설 IP 자동 매핑으로 해결하고 내부 주소를 숨기는 기술은 NAT이다.

    다음과 같은 과정으로 진행되는 공격은?

    1. 공개키 암호 방법을 사용하는 A와 B의 통신에 C가 개입한다.

    2. C는 A의 공개키를 가로채어 B에게 C의 공개키를 A의 공개키처럼 전송한다.

    3. B는 C의 공개키로 메시지를 암호화하여 A에게 전송한다.

    4. C는 B가 보낸 메시지를 가로채어 C의 개인키로 복호화한다.

    5. C는 복호화한 메시지를 단계 2에서 가로챈 A의 공개키로 암호화하여 A에게 B가 보낸 것처럼 전송한다.

    6. A는 자신의 개인키로 메시지를 복호화한다.

    1. 1. Smurf
    2. 2. 중간자(MITM)
    3. 3. Sniffing
    4. 4. Slowloris

    정답 2번

    🔍 보기별 해설
    1. Smurf는 위조한 출발지 주소로 ICMP 요청을 브로드캐스트하여 피해자에게 응답이 몰리게 하는 서비스 거부 공격이다. 공개키를 바꿔치는 과정이 없으므로 옳지 않다.
    2. C가 A와 B 사이에서 서로에게 자신의 공개키를 건네 메시지를 복호화하고 다시 암호화해 중계한다. 통신 중간에 끼어든 공격이므로 중간자 공격이며 옳다(정답).
    3. Sniffing은 네트워크를 지나가는 패킷을 몰래 들여다보는 수동적 공격이다. 공개키를 바꿔치고 중계하는 적극적 과정이 없으므로 옳지 않다.
    4. Slowloris는 HTTP 요청을 아주 느리게 보내 서버의 연결 자원을 붙잡아 두는 서비스 거부 공격이다. 공개키와 관계가 없으므로 옳지 않다.
    🧮 풀이
    1. 甲은 주말 자습 중에 위조한 주소로 ICMP 응답을 피해자에게 몰리게 하는 Smurf의 그림을 그렸다. 공개키 이야기가 없다는 점을 눈여겨보고 서비스 거부 계열이라는 분류를 붙여 두었다.
    2. 甲은 점심 먹고 남은 시간에 노트북을 열고 A와 B 사이에 C가 앉아 각자에게 자기 공개키를 내미는 여섯 단계를 도표로 옮겼다. 통신 양쪽을 속이며 내용을 엿보는 구조라 이 공격을 중간자라 적었다.
    3. 甲은 퇴근 뒤 도서관 열람실에서 기출 해설을 소리 내어 읽다가 스니핑 도구로 공용 와이파이에서 지나가는 패킷을 열어 보았다. 몰래 보기만 할 뿐 키를 바꿔치지 않으므로 중간자와 다른 수동적 공격이라고 표시했다.
    4. 甲은 모의고사 오답을 하나씩 정리하다가 HTTP 요청을 매우 느리게 보내 연결을 붙잡아 두는 실험 결과를 읽었다. 이는 자원 고갈 공격이지 키 바꿔치기가 아니라는 점을 슬로로리스 옆에 메모해 두었다.

    공개키 교환 중간에 끼어 서로에게 자기 공개키를 건네고 메시지를 가로채 중계하는 공격은 중간자 공격이다.
