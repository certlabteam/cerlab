    CPU에서 실행되는 머신 코드가 위치하는 시스템 메모리 영역은?

    1. 1. 스택
    2. 2. 힙
    3. 3. 텍스트
    4. 4. 데이터

    정답 3번

    🔍 보기별 해설
    1. 스택은 함수 호출마다 지역변수와 반환주소가 쌓였다 사라지는 영역이지 실행할 명령어 자체가 놓이는 자리가 아니므로 이 설명은 옳지 않다.
    2. 힙은 프로그램이 실행 중에 동적으로 늘였다 줄였다 하며 쓰는 메모리 영역이지 명령어가 놓이는 자리가 아니므로 이 설명은 옳지 않다.
    3. 텍스트 영역은 컴파일된 프로그램의 기계어 명령어가 그대로 담겨 CPU가 순서대로 읽어 실행하는 자리이므로 이 설명이 옳다(정답).
    4. 데이터 영역은 전역변수나 정적변수 같은 값이 저장되는 자리이지 실행할 명령어 자체가 놓이는 자리가 아니므로 이 설명은 옳지 않다.
    🧮 풀이
    1. 甲은 프로그램이 함수를 호출할 때마다 스택 영역에 지역변수와 반환주소가 새로 쌓였다 사라지는 것을 디버거로 지켜보았다. 그 영역에는 실행할 명령어가 아니라 임시 값만 오간다는 것을 확인했다.
    2. 甲은 malloc으로 새 메모리를 요청할 때마다 힙 영역이 조금씩 늘어나는 것을 메모리 맵으로 확인해 보았다. 그 영역도 값을 담는 자리일 뿐 명령어가 놓이는 곳은 아니라는 것을 정리했다.
    3. 甲은 실행 파일을 디스어셈블러로 열어 텍스트 영역에 나열된 기계어 명령어를 한 줄씩 읽어 보았다. CPU가 그 영역의 주소를 프로그램 카운터로 옮겨 가며 순서대로 실행하는 것을 확인했다.
    4. 甲은 전역변수로 선언한 값들이 데이터 영역 한곳에 모여 저장되는 것을 메모리 덤프로 하나하나 확인해 보았다. 그 영역 역시 명령어가 아니라 값이 놓이는 자리라는 것을 메모했다.

    CPU가 실행하는 머신 코드는 텍스트 영역에 놓이므로 3번이 정답이다.

    사용자와 운영체제 사이에서 중간자 역할을 수행하며, 명령어 해석 기능, 프로그래밍 기능, 사용자 환경 설정 기능을 제공하는 것은?

    1. 1. 데몬
    2. 2. 커널
    3. 3. 프로세스
    4. 4. 셸

    정답 4번

    🔍 보기별 해설
    1. 데몬은 사용자가 직접 명령을 입력하지 않아도 백그라운드에서 스스로 돌아가는 프로그램을 가리키는 말이라 사용자와 직접 대화하는 중간자 역할과는 다르므로 이 설명은 옳지 않다.
    2. 커널은 하드웨어를 직접 관리하고 자원을 배분하는 운영체제의 핵심 부분을 가리키는 말이라 사용자가 입력한 명령어를 해석해 주는 중간자와는 다르므로 이 설명은 옳지 않다.
    3. 프로세스는 실행 중인 프로그램 그 자체를 가리키는 말이라 사용자의 명령을 해석하고 프로그래밍·환경설정 기능까지 제공하는 중간자와는 다르므로 이 설명은 옳지 않다.
    4. 셸은 사용자가 입력한 명령을 해석해 커널에 전달하고 스크립트 프로그래밍과 환경설정 기능까지 제공하는 사용자와 운영체제 사이의 중간자이므로 이 설명이 옳다(정답).
    🧮 풀이
    1. 甲은 서버에 접속하지 않아도 스스로 돌아가며 로그를 정리하는 백그라운드 프로그램을 살펴보며 그것을 데몬이라 이름 붙여 보았다. 사용자가 직접 대화를 나누는 프로그램이 아니라는 것을 확인했다.
    2. 甲은 프로세스 스케줄링과 메모리 배분을 도맡는 운영체제의 핵심 부분을 살펴보며 그것을 커널이라 이름 붙여 보았다. 사용자가 입력한 명령을 직접 해석해 주는 것은 아니라는 것을 확인했다.
    3. 甲은 지금 실행 중인 워드프로세서 프로그램을 작업관리자에서 찾아 그것이 하나의 프로세스로 떠 있는 것을 확인해 보았다. 명령어 해석이나 환경설정 기능은 그 프로그램 자체가 아니라 셸의 몫이라는 것을 정리했다.
    4. 甲은 터미널에 ls나 cd 같은 명령을 입력하며 셸이 그 명령을 해석해 커널에 전달하는 과정을 지켜보았다. 환경변수를 설정하고 간단한 스크립트까지 짤 수 있는 것을 직접 확인했다.

    사용자와 OS 사이에서 명령어 해석·프로그래밍·환경설정 기능을 제공하는 것은 셸이므로 4번이 정답이다.

    (가)에 들어갈 용어로 옳은 것은?

    보안 운영체제는 기존의 운영체제에 내재된 보안상의 결함으로 인한 각종 침해로부터 시스템을 보호하기 위하여 기존의 운영체제 내에 보안 기능을 통합시킨 (가) 을/를 추가로 이식한 운영체제이다. 이를 통해 사용자의 모든 접근 행위가 안전하게 통제된다. 이것은 하드웨어, 운영체제 및 기타 시스템 요소 간의 보안 인터페이스를 제공한다.

    1. 1. 보안 커널
    2. 2. 접근 제어
    3. 3. 신뢰 플랫폼 모듈
    4. 4. 하이퍼바이저

    정답 1번

    🔍 보기별 해설
    1. 보안 커널은 기존 운영체제에 보안 기능을 통합해 이식함으로써 하드웨어·운영체제·기타 요소 사이의 보안 인터페이스를 제공하고 모든 접근을 안전하게 통제하는 핵심 부분이므로 이 답이 옳다(정답).
    2. 접근 제어는 보안 운영체제가 수행하는 기능 가운데 하나일 뿐 이식되는 통합 구성요소 자체를 가리키는 이름은 아니므로 이 답은 옳지 않다.
    3. 신뢰 플랫폼 모듈은 하드웨어 칩 형태로 암호키를 안전하게 보관하는 별도 장치를 가리키는 말이라 운영체제 안에 이식되는 보안 기능 통합체와는 다르므로 이 답은 옳지 않다.
    4. 하이퍼바이저는 여러 운영체제를 한 하드웨어 위에서 동시에 돌리는 가상화 계층을 가리키는 말이라 기존 운영체제 안에 보안 기능을 이식하는 것과는 다르므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 기존 운영체제에 보안 커널을 새로 이식해 모든 파일 접근 요청이 그 커널을 거치도록 설정해 보았다. 접근 통제가 이전보다 훨씬 촘촘해지는 것을 시험 접속으로 확인했다.
    2. 甲은 접근 제어 목록을 파일마다 세밀하게 설정하며 이것이 보안 커널이 수행하는 기능 가운데 하나일 뿐이라는 것을 교재에서 확인했다. 통합체 이름 자체와는 다르다는 것을 메모했다.
    3. 甲은 노트북에 내장된 신뢰 플랫폼 모듈 칩을 열어 암호화 키가 하드웨어적으로 안전하게 보관되는 것을 확인해 보았다. 운영체제 안에 소프트웨어로 이식되는 보안 커널과는 다른 물건이라는 것을 정리했다.
    4. 甲은 하이퍼바이저 위에 서로 다른 운영체제 두 개를 띄워 동시에 돌려 보았다. 이 계층은 가상화를 담당할 뿐 기존 운영체제 내부에 보안 기능을 이식하는 것과는 다르다는 것을 확인했다.

    기존 운영체제에 보안 기능을 통합해 이식하는 핵심 요소는 보안 커널이므로 1번이 정답이다.

    보안 모델의 하나인 만리장성(Chinese Wall) 모델에 대한 설명으로 옳은 것은?

    1. 1. 높은 보안 수준에서 낮은 보안 수준으로 정보가 흐르는 것을 방지하기 위한 기밀성 보장 모델이다.
    2. 2. 비즈니스 입장에서 직무 분리 개념을 적용하여 이해가 충돌하는 회사 간에 정보의 흐름이 일어나지 않도록 접근을 통제한다.
    3. 3. 무결성 중심의 상업적 모델로 내․외부의 일관성을 유지하고 비인가자에 의한 불법적인 수정을 방지한다.
    4. 4. 무결성을 위한 모델로 비인가자의 데이터 변형을 방지하기 위한 것이다.

    정답 2번

    🔍 보기별 해설
    1. 높은 보안 수준에서 낮은 보안 수준으로 정보가 흐르는 것을 막는 것은 벨-라파둘라 모델의 설명이지 만리장성 모델의 설명이 아니므로 이 설명은 옳지 않다.
    2. 만리장성 모델은 비즈니스 세계의 직무 분리 개념을 가져와 이해관계가 충돌하는 회사들 사이에 정보가 오가지 못하도록 접근을 통제하는 모델이므로 이 설명이 옳다(정답).
    3. 무결성 중심의 상업적 모델로 비인가자의 불법 수정을 막는다는 것은 클락-윌슨 모델의 설명이지 만리장성 모델의 설명이 아니므로 이 설명은 옳지 않다.
    4. 비인가자의 데이터 변형을 막기 위한 무결성 모델이라는 것은 비바 모델의 설명이지 만리장성 모델의 설명이 아니므로 이 설명은 옳지 않다.
    🧮 풀이
    1. 甲은 군사기밀 문서를 다루는 시스템에서 상위 등급 정보가 하위 등급 사용자에게 새어 나가지 않는지 벨-라파둘라 모델 규칙으로 점검해 보았다. 그 규칙이 만리장성 모델과는 다른 잣대라는 것을 정리했다.
    2. 甲은 컨설팅 회사에서 경쟁 관계에 있는 두 고객사의 자료를 같은 컨설턴트가 동시에 열람하지 못하도록 접근 통제표를 만들어 보았다. 한쪽 회사 자료를 이미 본 직원은 경쟁사 자료에 접근하지 못하게 막는 규칙을 적용했다.
    3. 甲은 은행 전산망에서 승인자와 입력자를 서로 다른 사람으로 나누는 직무분리 규칙이 비인가 수정을 막는지 클락-윌슨 모델 기준으로 점검해 보았다. 그 규칙이 만리장성 모델과는 다른 상업적 무결성 잣대라는 것을 확인했다.
    4. 甲은 문서의 무결성 등급이 낮은 자료가 등급 높은 자료를 함부로 고치지 못하도록 비바 모델 규칙으로 접근을 제한해 보았다. 그 규칙 역시 만리장성 모델과는 다른 목적의 통제라는 것을 정리했다.

    만리장성 모델은 이해충돌 회사 간 정보흐름을 막는 직무분리형 통제이므로 2번이 정답이다.

    윈도시스템의 NTFS에서 폴더 및 파일 접근 권한에 대한 설명으로 옳은 것은?

    1. 1. 그룹 A와 그룹 B에 속한 사용자가 그룹 A에서는 읽기 권한을 할당받고 그룹 B에서는 쓰기 권한을 할당받았다면, 사용자에게 읽기와 쓰기 권한이 모두 주어진다.
    2. 2. 파일이 포함된 폴더 권한이 파일 권한보다 우선한다.
    3. 3. 권한을 중첩해서 적용할 수 있으며, 허용 설정이 거부 설정보다 우선한다.
    4. 4. 폴더 접근 권한은 그룹에게만 부여된다.

    정답 1번

    🔍 보기별 해설
    1. 그룹 A에서 읽기, 그룹 B에서 쓰기 권한을 각각 할당받은 사용자는 두 그룹에 속한 만큼 두 권한을 모두 더해 읽기와 쓰기가 모두 주어지는 것이 NTFS의 누적 규칙이므로 이 설명이 옳다(정답).
    2. 실제로는 파일에 직접 준 권한이 있으면 그 권한이 상위 폴더에서 물려받은 권한보다 우선하는 것이지 폴더 권한이 파일 권한보다 우선하는 것이 아니므로 이 설명은 옳지 않다.
    3. 권한을 중첩해서 적용할 수 있다는 것은 맞지만 실제로는 거부 설정이 허용 설정보다 우선하는 것이지 그 반대가 아니므로 이 설명은 옳지 않다.
    4. 폴더 접근 권한은 그룹뿐 아니라 개별 사용자에게도 직접 부여할 수 있어 그룹에게만 한정된다는 서술은 옳지 않다.
    🧮 풀이
    1. 甲은 한 직원을 그룹 A와 그룹 B에 동시에 넣고 각각 읽기와 쓰기 권한을 나눠 준 뒤 그 직원 계정으로 로그인해 파일에 접근해 보았다. 읽기와 쓰기가 모두 되는 것을 직접 확인했다.
    2. 甲은 상위 폴더에는 읽기만 허용하고 그 안의 특정 파일에는 쓰기까지 직접 허용해 보았다. 파일에 직접 준 권한이 폴더에서 물려받은 권한을 덮어쓰는 것을 접속 시험으로 확인했다.
    3. 甲은 같은 사용자에게 허용과 거부를 동시에 걸어 두고 실제로 접근이 되는지 계정을 바꿔 가며 테스트해 보았다. 거부 설정 하나가 다른 모든 허용 설정을 덮어 접근이 막히는 것을 확인했다.
    4. 甲은 특정 직원 한 명에게만 폴더 접근 권한을 그룹을 거치지 않고 관리자 도구로 직접 부여해 보았다. 개인 계정으로도 권한을 줄 수 있는 것을 접속 시험으로 확인했다.

    NTFS는 여러 그룹의 권한을 모두 더해 적용하므로 1번이 정답이다.

    다음에서 설명하는 전자우편 보안 기술은?

    ○ 종단 사용자에게 투명한 인증 기술을 제공하도록 설계되었다.

    ○ 전자우편 메시지는 전자우편 발신지 관리 도메인의 개인키에 의해 서명된다.

    ○ 서명은 메시지 내용 전체와 메시지 헤더의 일부를 대상으로 한다.

    ○ 수신 측의 MDA(Mail Delivery Agent)는 DNS를 통해 해당 공개키에 접근하여 서명을 검증할 수 있다.

    1. 1. PGP
    2. 2. PEM
    3. 3. MIME
    4. 4. DKIM

    정답 4번

    🔍 보기별 해설
    1. PGP는 개별 사용자의 개인키로 메일을 서명하고 신뢰의 거미줄 방식으로 공개키를 관리하는 기술이라 발신 도메인 단위로 DNS에서 공개키를 조회하는 방식과는 다르므로 옳지 않다.
    2. PEM은 초창기 전자우편 보안 표준으로 계층적 인증서 체계를 쓰는 기술이라 도메인 개인키 서명과 DNS 공개키 조회 방식과는 다르므로 옳지 않다.
    3. MIME은 전자우편에 여러 형식의 첨부와 본문을 담기 위한 형식 표준일 뿐 서명이나 인증 기능 자체를 제공하는 보안 기술이 아니므로 옳지 않다.
    4. DKIM은 발신지 관리 도메인의 개인키로 메시지 전체와 헤더 일부를 서명하고 수신 측이 DNS에서 해당 공개키를 찾아 서명을 검증하도록 설계된 투명한 인증 기술이므로 이 답이 옳다(정답).
    🧮 풀이
    1. 甲은 개인 메일 계정마다 따로 발급받은 개인키로 메일에 서명하고 지인들끼리 서로의 공개키를 주고받아 신뢰망을 쌓아 보았다. 그 방식이 도메인 단위로 자동 서명되는 이번 기술과는 다르다는 것을 확인했다.
    2. 甲은 옛 표준 문서를 뒤져 메일마다 계층적 인증서를 붙이는 초창기 보안 방식을 살펴보았다. 지금 쓰는 DNS 기반 공개키 조회 방식과는 구조가 다르다는 것을 정리했다.
    3. 甲은 첨부파일과 여러 언어의 본문을 담은 메일을 열어 그 형식이 MIME 표준을 따른다는 것을 헤더로 확인해 보았다. 그 표준 자체에는 서명이나 인증 기능이 없다는 것도 함께 확인했다.
    4. 甲은 회사 도메인의 개인키로 발송 메일 전체와 헤더 일부를 자동 서명하도록 메일서버를 설정해 보았다. 수신 서버가 DNS에서 그 도메인의 공개키를 찾아 서명을 검증하는 과정을 로그로 확인했다.

    발신 도메인 개인키로 서명하고 DNS로 공개키를 조회해 검증하는 기술은 DKIM이므로 4번이 정답이다.

    다음에서 설명하는 윈도시스템 인증 구성 요소는?

    사용자의 계정과 패스워드가 일치하는 경우 해당 사용자에게 고유의 SID(Security Identifier)를 부여하며, 파일이나 폴더에 대한 접근 허용 여부를 결정하고 이에 대한 감사 메시지를 생성한다.

    1. 1. SAM
    2. 2. LSA
    3. 3. SRM
    4. 4. SPI

    정답 3번

    🔍 보기별 해설
    1. SAM은 사용자 계정과 패스워드 정보를 담은 데이터베이스 그 자체를 가리키는 말이라 SID를 부여하고 감사 메시지를 만드는 실행 주체와는 다르므로 이 답은 옳지 않다.
    2. LSA는 로그온 정책을 관리하고 보안 토큰을 생성하는 역할을 맡는 구성요소라 파일·폴더 접근 허용 여부를 직접 결정하는 역할과는 다르므로 이 답은 옳지 않다.
    3. SRM은 계정과 패스워드가 일치하면 고유한 SID를 부여하고 파일이나 폴더에 대한 접근을 허용할지 결정하며 그 결과에 대한 감사 메시지까지 만드는 구성요소이므로 이 답이 옳다(정답).
    4. SPI는 상태 기반 패킷 검사 같은 네트워크 보안 기법을 가리키는 말이라 윈도 인증 구성요소 자체를 가리키는 이름이 아니므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 계정 데이터베이스를 열어 사용자마다 저장된 계정명과 암호화된 패스워드 값을 하나하나 확인해 보았다. 그 데이터베이스 자체는 SID를 새로 만들어 내는 주체가 아니라는 것을 정리했다.
    2. 甲은 로그온 정책을 관리하는 구성요소가 사용자에게 보안 토큰을 내주는 과정을 로그로 지켜보았다. 그 구성요소가 파일 접근 허용 여부까지 직접 결정하지는 않는다는 것을 확인했다.
    3. 甲은 로그인에 성공한 사용자에게 고유 SID가 부여되는 것을 확인하고 그 사용자가 특정 폴더에 접근하려 할 때 허용 여부가 결정되는 과정을 감사로그로 지켜보았다. 접근이 거부될 때마다 감사 메시지가 남는 것도 확인했다.
    4. 甲은 네트워크 방화벽 설정에서 상태 기반 패킷 검사 기능을 켜며 그 용어가 윈도 인증 구성요소와는 전혀 다른 자리에 쓰인다는 것을 확인했다. 두 용어를 헷갈리지 않도록 메모해 두었다.

    SID 부여와 접근 허용여부 결정, 감사 메시지 생성을 맡는 것은 SRM이므로 3번이 정답이다.

    (가), (나)에 들어갈 용어를 바르게 연결한 것은?

    1. 1. 전역 프레임
    2. 2. 전역 페이지
    3. 3. 지역 프레임
    4. 4. 지역 페이지

    🔍 보기별 해설
    1. 전역 프레임이라는 조합은 (가) 자리에 들어갈 말이 지역이어야 하는데 전역으로 잘못 짚은 것이라 옳지 않다.

    3. 甲은 각 프로세스에게 물리 메모리의 프레임을 최소 몇 개씩 나눠 줄지 정하고, 페이지 교체 시에는 그 프로세스 자신의 페이지 안에서만 골라내는 지역 알고리즘을 적용해 보았다. 스래싱 구간이 그래프에서 눈에 띄게 줄어드는 것을 확인했다.

    S/MIME에 대한 설명으로 옳지 않은 것은?

    1. 1. 서명된 데이터(signed data)의 디지털 서명은 메시지 다이제스트를 서명자의 개인키로 암호화한 것으로, 서명과 함께 메시지 내용은 base64로 부호화된다.
    2. 2. 서명과 봉인된 데이터(signed and enveloped data)는 서명만 하거나 암호화만 한 개체들이 중첩된 것으로, 암호화한 데이터를 서명하거나 서명한 데이터를 암호화할 수 있다.
    3. 3. 디지털 서명만을 base64로 부호화한 클리어 서명 데이터(clear-signed data)의 경우, S/MIME 기능을 갖추지 않은 수신자도 서명을 검증하고 메시지의 내용을 볼 수 있도록 지원한다.
    4. 4. X.509의 버전 3을 따르는 공개키 인증서를 사용한다.

    정답 3번

    🔍 보기별 해설
    1. 서명자가 자기 개인키로 원문의 요약값을 암호화해 붙이고 그 서명과 함께 편지 내용 전체를 base64라는 문자표기법으로 바꿔 전송한다는 것이 실제 처리 방식과 그대로 맞으므로 이 설명은 옳다.
    2. 먼저 겉봉투를 봉하고 그 위에 다시 도장을 찍거나 먼저 도장을 찍은 뒤 그 편지를 통째로 봉투에 넣는 것처럼, 암호화와 서명 두 단계를 어느 순서로 겹쳐도 되는 방식이 실제 규격과 맞으므로 이 설명은 옳다.
    3. 클리어 서명 데이터는 디지털 서명만 base64로 부호화하고 메시지 본문은 그대로 두는 방식이라 S/MIME 기능이 없는 수신자도 내용은 읽을 수 있지만 서명을 검증할 수는 없는데 지문은 검증까지 지원한다고 거꾸로 말하니 이 설명은 옳지 않다(정답).
    4. X.509 버전 3을 따르는 공개키 인증서를 사용한다는 것은 S/MIME 규격 그대로이므로 이 설명은 옳다.
    🧮 풀이
    1. 甲은 서명된 메일 원본 데이터를 열어 서명자의 개인키로 다이제스트가 암호화된 값을 손으로 계산해 대조해 보았다. 서명과 본문이 함께 부호화된 형식이 규격 문서와 그대로 맞는 것을 정리했다.
    2. 甲은 먼저 암호화한 메일 위에 다시 서명을 얹는 중첩 구조를 손수 만들어 실제 발송 시험까지 해 보았다. 암호화와 서명 순서를 서로 바꿔 적용해도 되는 것을 확인했다.
    3. 甲은 S/MIME 기능이 없는 옛날 메일 클라이언트로 클리어 서명 메일을 열어 본문 내용은 그대로 읽히는 것을 확인해 보았다. 다만 서명 자체를 검증하는 버튼은 아예 뜨지 않는 것을 확인했다.
    4. 甲은 발급받은 인증서를 열어 그것이 X.509 버전 3 형식을 따르는 것을 인증서 상세정보로 확인해 보았다. 메일 서명에 그 인증서가 그대로 쓰이는 것을 확인했다.

    클리어 서명 데이터는 서명 검증까지는 못 하고 내용만 볼 수 있는데 지문이 검증도 된다고 해 3번이 옳지 않다.

    HTTP 버전 1.1에서 정의된 요청 메시지의 메소드에 대한 설명으로 옳은 것은?

    3. 3. HEAD는 서버로부터 웹페이지 자체가 아닌 웹페이지에 대한 일부 정보를 요청하기 위한 것이다.
    4. 4. PUT은 요구 메시지가 서버에 의해 제대로 처리되는가를 검사하기 위한 에코 반환 용도로 사용된다.

    🔍 보기별 해설

    (가) ～ (다) 안에 들어갈 용어를 바르게 연결한 것은?

    함수 P가 함수 Q를 호출하기 위해, P는 Q에 전달할 인수를 스택에 넣는다. Q를 호출하는 call 명령어를 수행하면 (가) 가 스택에 저장된다. Q는 (나) 를 스택에 넣는다. 프레임 포인터 레지스터 값을 현재의 포인터 값으로 설정하고, 스택 포인터를 아래로 움직여 (다) 를 저장할 공간을 할당하고, Q의 코드를 수행한다. 컴파일러의 최적화 기능에 따라 실제 배치는 차이가 있을 수 있으나, 저장된 (가) 와 (나) 에 겹쳐 쓰기는 스택 버퍼 오버플로 공격의 핵심이다. (가) (나) (다)

    1. 1. 반환 주소 P의 스택 프레임 포인터 지역 변수
    2. 2. 반환 주소 Q의 스택 프레임 포인터 지역 변수
    3. 3. P의 스택 프레임 포인터 지역 변수 반환 주소
    4. 4. Q의 스택 프레임 포인터 지역 변수 반환 주소

    정답 1번

    🔍 보기별 해설

(가) (나) (다)

    2. 2. passwrd /etc/passwd SetRID

    정답 2번

    🔍 보기별 해설
    1. Authentication이 자신의 신원을 시스템에 증명하는 과정을 뜻한다는 것은 AAA의 정의 그대로이므로 이 설명은 옳다.
    2. 지문 인식 시스템에 손가락을 댈 때 그 지문 자체는 신원을 증명하는 인증 수단이지 인증된 뒤 무엇을 할 수 있는지 정하는 Authorization과는 다른 개념인데 지문은 이 둘을 같다고 말하니 이 설명은 옳지 않다(정답).
    3. Accounting이 시스템에 접근한 사용자를 추적하는 데 쓰일 수 있다는 것은 AAA의 정의 그대로이므로 이 설명은 옳다.
    4. Accounting이 로그인 기록을 시스템이 남기는 활동을 뜻한다는 것은 AAA의 정의 그대로이므로 이 설명은 옳다.
    🧮 풀이
    1. 甲은 로그인 화면에서 아이디와 비밀번호를 입력해 자신이 누구인지 시스템에 증명하는 과정을 지켜보았다. 그 절차가 Authentication에 해당한다는 것을 확인했다.
    2. 甲은 지문 인식기에 손가락을 대는 순간과 그 뒤 접근할 수 있는 메뉴가 정해지는 순간을 나란히 놓고 두 단계가 서로 다른 것을 확인해 보았다. 지문 자체는 인증 수단이고 메뉴 제한은 권한부여라는 것을 구분했다.
    3. 甲은 특정 계정이 언제 어떤 시스템에 접속했는지 기록을 뒤져 그 사용자의 활동 이력을 추적해 보았다. 그 추적이 Accounting 기능 덕분이라는 것을 확인했다.
    4. 甲은 로그인이 성공할 때마다 시각과 계정명이 자동으로 로그에 남는 것을 확인해 보았다. 그 기록 남기는 활동이 Accounting에 해당한다는 것을 정리해 두었다.

    Authorization은 지문 자체가 아니라 권한을 부여하는 절차라 2번이 옳지 않다.

    전자메일 시스템에서 송신 부인방지 기능을 위해 적용하는 기술은?

    1. 1. 전자 서명(digital signature)
    2. 2. 대칭키 암호화(symmetric encryption)
    3. 3. 앨리어스(alias)
    4. 4. 커버로스(Kerberos)

    정답 1번

    🔍 보기별 해설
    1. 전자 서명은 발신자만이 가진 개인키로 메시지를 서명해 나중에 발신자가 보낸 적 없다고 발뺌하지 못하게 만드는 기술이므로 이 답이 옳다(정답).
    2. 대칭키 암호화는 송수신자가 같은 키를 나눠 쓰는 방식이라 그 키를 아는 누구나 서명한 것처럼 보일 수 있어 부인방지 기능을 보장하지 못하므로 이 답은 옳지 않다.
    3. 앨리어스는 메일 주소를 다른 이름으로 대신 쓰게 해 주는 편의 기능일 뿐 송신 사실을 증명하는 기술이 아니므로 이 답은 옳지 않다.
    4. 커버로스는 티켓을 이용해 네트워크 자원에 접근할 때 신원을 확인해 주는 인증 프로토콜이라 전자메일 송신 부인방지를 위한 기술과는 다르므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 계약서 메일을 보내며 자신의 개인키로 서명을 붙여 나중에 보낸 적 없다고 잡아떼지 못하게 만들어 보았다. 수신자가 공개키로 그 서명을 검증하는 것을 확인했다.
    2. 甲은 부서원 전체가 같은 대칭키로 메일을 암호화해 주고받는 것을 살펴보다 그 키를 아는 사람이라면 누구든 같은 서명처럼 보이게 만들 수 있다는 것을 깨달았다. 부인방지에는 적합하지 않다는 것을 정리했다.
    3. 甲은 여러 별명 주소로 들어오는 메일을 한 계정으로 모아 받도록 앨리어스를 설정해 보았다. 그 기능이 누가 보냈는지 증명하는 것과는 무관하다는 것을 다시 확인했다.
    4. 甲은 사내 파일서버에 접근할 때 커버로스 티켓을 발급받아 신원을 확인하는 과정을 지켜보았다. 이 절차가 전자메일 송신을 부인하지 못하게 막는 기술과는 다른 자리에서 쓰인다는 것을 정리했다.

    송신 부인방지 기능은 전자서명으로 구현하므로 1번이 정답이다.

    OTP기기는 다음 중 어떤 수단에 해당하는가?

    1. 1. Something You Know
    2. 2. Something You Have
    3. 3. Something You Are
    4. 4. Something You Do

    정답 2번

    🔍 보기별 해설
    1. Something You Know는 비밀번호처럼 머릿속으로 기억하는 정보로 인증하는 수단이라 물리적 기기를 손에 쥐는 OTP와는 다르므로 이 답은 옳지 않다.
    2. Something You Have는 신분증이나 보안토큰처럼 사용자가 직접 소지한 물건으로 인증하는 수단이며 OTP기기도 손에 쥐고 있어야만 쓸 수 있는 물건이므로 이 답이 옳다(정답).
    3. Something You Are는 지문이나 홍채처럼 신체 특징으로 인증하는 수단이라 손에 쥐는 물건인 OTP와는 다르므로 이 답은 옳지 않다.
    4. Something You Do는 서명하는 방식이나 걸음걸이처럼 행동 특징으로 인증하는 수단이라 물건을 소지하는 OTP와는 다르므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 비밀번호만 외워서 로그인하는 시스템을 살펴보며 그 인증 수단이 머릿속 지식에 의존하는 것을 확인했다. OTP기기처럼 물건을 손에 쥐는 방식과는 다르다는 것을 정리했다.
    2. 甲은 은행 창구에서 발급받은 OTP기기를 주머니에서 꺼내 화면에 뜬 숫자를 입력해 로그인해 보았다. 그 기기를 잃어버리면 인증 자체를 못 한다는 것에서 소지 기반 인증이라는 것을 체감했다.
    3. 甲은 회사 출입문에 설치된 홍채 인식기를 지나며 그 인증이 눈동자 무늬라는 신체 특징에 의존하는 것을 확인해 보았다. 물건을 챙겨야 하는 OTP와는 다른 방식이라는 것을 정리했다.
    4. 甲은 손글씨 서명의 필압과 속도까지 분석해 본인 여부를 가리는 인증 시스템을 살펴보았다. 행동 특징에 기반한 이 방식이 물건을 쥐는 OTP와는 다른 갈래라는 것을 정리했다.

    OTP기기는 사용자가 가진 물건을 이용한 인증이라 Something You Have에 해당해 2번이 정답이다.

    2017년에 발표된 OWASP TOP 10의 항목 중 (가)에 해당되는 것은?

    (가) 은(는) 신뢰할 수 없는 데이터가 명령어나 쿼리문의 일부분으로서, 인터프리터로 보내질 때 발생한다. 공격자의 악의적인 데이터는 예기치 않은 명령을 실행하거나 올바른 권한 없이 데이터에 접근하도록 인터프리터를 속일 수 있다.

    1. 1. Broken Access Control
    2. 2. Broken Authentication
    3. 3. Sensitive Data Exposure
    4. 4. Injection

    정답 4번

    🔍 보기별 해설
    1. Broken Access Control은 접근 통제가 제대로 걸리지 않아 권한 밖의 자원에 접근할 수 있게 되는 항목이라 명령어·쿼리문에 데이터가 섞여 들어가는 설명과는 다르므로 이 답은 옳지 않다.
    2. Broken Authentication은 인증 절차 자체가 허술해 신원 확인이 뚫리는 항목이라 인터프리터를 속이는 설명과는 다르므로 이 답은 옳지 않다.
    3. Sensitive Data Exposure는 민감한 정보가 암호화되지 않은 채 노출되는 항목이라 명령어·쿼리문 삽입과는 다르므로 이 답은 옳지 않다.
    4. Injection은 신뢰할 수 없는 데이터가 명령어나 쿼리문의 일부로 인터프리터에 전달돼 의도치 않은 명령을 실행시키거나 권한 없이 데이터에 접근하게 만드는 항목이므로 이 답이 옳다(정답).
    🧮 풀이
    1. 甲은 직원용 페이지 URL을 손으로 바꿔 관리자 페이지에 접근해 보았다. 접근 통제가 제대로 걸리지 않아 뚫리는 것을 확인하고 Broken Access Control 사례로 기록했다.
    2. 甲은 비밀번호 시도 횟수 제한이 아예 없는 로그인 화면을 발견해 여러 번 연속으로 시도해 보았다. 인증 절차 자체가 허술한 것을 근거로 Broken Authentication 사례로 기록했다.
    3. 甲은 개인정보가 암호화 없이 그대로 데이터베이스에 저장된 것을 발견해 화면에 평문으로 노출되는 것을 확인했다. Sensitive Data Exposure 사례로 보고서에 정리했다.
    4. 甲은 로그인 입력창에 작은따옴표와 SQL 구문을 섞어 넣어 서버가 그 구문을 그대로 실행하는지 시험해 보았다. 데이터베이스가 조작된 명령을 그대로 수행하는 것을 확인하고 Injection 취약점으로 기록했다.

    신뢰할 수 없는 데이터가 명령어·쿼리문에 섞여 인터프리터를 속이는 항목은 Injection이므로 4번이 정답이다.

    다음 설명에 따라 진행되는 공격 유형은?

    ○ 공격자는 악의적인 스크립트가 포함된 콘텐츠를 웹 애플리케이션 서버에 업로드한다.

    ○ 해당 콘텐츠는 웹 애플리케이션 서버에 저장된다.

    ○ 희생자는 해당 콘텐츠를 웹 애플리케이션 서버에 요청하여 수신한다.

    ○ 해당 콘텐츠에 포함된 악의적인 스크립트가 희생자의 디바이스에서 실행된다.

    1. 1. Stored XSS
    2. 2. Reflected XSS
    3. 3. Brute Force
    4. 4. Buffer Overflow

    정답 1번

    🔍 보기별 해설
    1. 공격자가 올린 악성 스크립트가 서버에 그대로 저장돼 있다가 다른 사용자가 그 콘텐츠를 요청해 받을 때마다 실행되는 것은 저장형 XSS의 전형적인 흐름이므로 이 답이 옳다(정답).
    2. 반사형 XSS는 악성 스크립트가 서버에 저장되지 않고 요청 파라미터에 실려 그 자리에서 응답에 반사돼 실행되는 방식이라 서버에 저장되는 이번 설명과는 다르므로 이 답은 옳지 않다.
    3. 무차별 대입은 비밀번호나 키값을 하나씩 다 넣어 보며 맞는 값을 찾는 공격이라 스크립트를 업로드해 저장시키는 방식과는 다르므로 이 답은 옳지 않다.
    4. 버퍼 오버플로는 메모리 공간보다 많은 데이터를 밀어 넣어 인접 영역을 덮어쓰는 공격이라 웹 콘텐츠에 스크립트를 심어 두는 방식과는 다르므로 이 답은 옳지 않다.
    🧮 풀이
    1. 甲은 게시판 글쓰기 창에 악성 스크립트를 심어 저장한 뒤 다른 이용자가 그 글을 열람할 때마다 스크립트가 실행되는지 확인해 보았다. 글이 삭제되기 전까지 계속 실행되는 것을 확인하고 저장형 XSS로 기록했다.
    2. 甲은 검색창에 스크립트를 넣어 서버가 그 값을 그대로 검색결과 화면에 반사해 보여 주는지 확인해 보았다. 이 스크립트는 그 요청 한 번에만 실행되고 서버에는 남지 않는 것을 확인했다.
    3. 甲은 로그인 화면에 흔한 비밀번호 목록을 자동으로 하나씩 넣어 보는 도구를 돌려 보았다. 스크립트를 심는 방식이 아니라 값을 무작위로 맞혀 보는 방식이라는 것을 정리했다.
    4. 甲은 입력칸에 정해진 길이보다 훨씬 긴 문자열을 밀어 넣어 프로그램이 비정상 종료되는지 확인해 보았다. 메모리 영역을 침범하는 방식이라 웹 콘텐츠에 스크립트를 저장하는 방식과는 다르다는 것을 정리했다.

    악성스크립트가 서버에 저장돼 있다가 다른 사용자가 요청할 때 실행되는 공격은 저장형 XSS이므로 1번이 정답이다.
