    CPU에서 실행되는 머신 코드가 위치하는 시스템 메모리 영역은?

    1. 1. 스택
    2. 2. 힙
    3. 3. 텍스트
    4. 4. 데이터

    정답 3번

    🔍 보기별 해설
    1. 스택은 함수 호출 때 매개변수·지역 변수·반환 주소를 쌓았다가 함수가 끝나면 비우는 영역이다. 실행할 기계어 명령이 놓이는 곳이 아니므로 옳지 않다.
    2. 힙은 malloc이나 new처럼 실행 중에 요청한 만큼 동적으로 할당받는 메모리 영역이다. 프로그램 명령어가 아니라 동적 데이터가 놓이므로 옳지 않다.
    3. 텍스트 영역은 컴파일된 머신 코드가 올라가는 곳으로 보통 읽기 전용으로 보호된다. CPU가 가져다 실행하는 명령어가 여기에 있으므로 옳다(정답).
    4. 데이터 영역은 전역 변수와 정적 변수처럼 프로그램이 시작될 때부터 끝날 때까지 유지되는 값을 담는다. 실행 코드가 아니라 변수 값이 놓이므로 옳지 않다.
    🧮 풀이
    1. 증권사 주문 서버 개발자 甲은 재귀 함수가 끝없이 자기 자신을 부르는 버그를 디버거로 따라갔다. 호출이 거듭될 때마다 반환 주소와 지역 변수가 쌓여 결국 스택 오버플로로 프로세스가 멈췄다. 스택은 호출 기록을 쌓는 공간이고 명령어 저장소가 아니다.
    2. 은행 배치 프로그램을 맡은 甲은 거래 건수만큼 malloc으로 버퍼를 잡고 해제를 빠뜨렸다. 밤새 돌린 뒤 메모리 사용량이 계속 늘어 힙 영역이 바닥나는 누수가 생겼다. 힙은 실행 중 요청한 데이터를 담는 동적 공간이다.
    3. 보험사 보안 담당 甲이 메모리 맵을 열어 보니 실행 파일의 명령어 구간은 읽기와 실행만 허용되어 있었다. 공격 코드로 그 구간을 고쳐 쓰려 하자 접근 위반으로 바로 막혔다. 기계어가 놓이는 텍스트 영역을 쓰기 금지로 보호한 결과다.
    4. 카드사 정산 프로그램을 고치던 甲은 전역 변수로 둔 수수료율이 함수를 몇 번 불러도 같은 값으로 남는 점을 이용했다. 이 값은 프로그램이 뜰 때 데이터 영역에 올라가 끝날 때까지 자리를 지킨다. 명령어가 아니라 변수가 머무는 곳이다.

    CPU가 가져다 실행하는 기계어 명령은 읽기 전용으로 보호되는 텍스트 영역에 놓이고, 스택·힙·데이터 영역은 변수와 호출 정보를 담는다. 정답은 3번이다.

    사용자와 운영체제 사이에서 중간자 역할을 수행하며, 명령어 해석 기능, 프로그래밍 기능, 사용자 환경 설정 기능을 제공하는 것은?

    1. 1. 데몬
    2. 2. 커널
    3. 3. 프로세스
    4. 4. 셸

    정답 4번

    🔍 보기별 해설
    1. 데몬은 백그라운드에서 계속 돌며 메일 수신이나 로그 기록 같은 서비스 요청을 기다리는 프로세스다. 사용자 명령을 받아 해석해 주는 창구가 아니므로 옳지 않다.
    2. 커널은 메모리·프로세스·장치를 직접 관리하는 운영체제의 중심부다. 사용자와 직접 대화하며 명령을 해석하는 일은 셸이 맡으므로 옳지 않다.
    3. 프로세스는 실행 중인 프로그램 하나를 가리키는 말로 CPU와 메모리를 할당받아 움직이는 단위다. 명령어 해석과 환경 설정을 제공하는 중간자 자체가 아니므로 옳지 않다.
    4. 셸은 사용자가 입력한 명령을 해석해 커널에 넘기고, 스크립트 작성과 환경 변수 설정도 지원한다. 사용자와 운영체제 사이의 중간자 설명과 같으므로 옳다(정답).
    🧮 풀이
    1. 지점 서버 관리자 甲은 sshd를 서비스로 등록해 터미널을 닫아도 원격 접속 요청을 계속 받게 했다. 이 프로세스는 사용자와 대화하지 않고 뒤에서 요청이 올 때만 일한다. 이런 상주 프로그램이 데몬이다.
    2. 전산실 엔지니어 甲은 새 저장장치 드라이버를 커널 모듈로 올리고 나서야 디스크를 쓸 수 있었다. 장치 입출력과 메모리 배분은 사용자가 아니라 커널이 직접 처리한다. 사용자의 명령은 셸을 거쳐 커널에 닿는다.
    3. 콜센터 시스템 운영자 甲은 녹취 변환 프로그램을 세 번 실행해 PID가 서로 다른 세 작업이 동시에 돌게 했다. 같은 프로그램이라도 실행할 때마다 따로 메모리를 받은 별개의 프로세스가 된다. 명령을 해석해 주는 쪽과는 다른 개념이다.
    4. 사내망 관리자 甲은 bash에 ls -l | grep log를 입력하고 PATH 변수를 바꾸는 줄을 .bashrc에 넣었다. bash는 이 명령줄을 해석해 커널에 실행을 요청하고, 다음 로그인 때 바뀐 환경을 그대로 적용한다. 이렇게 사용자와 커널 사이에 서는 것이 셸이다.

    사용자 명령을 해석해 커널에 넘기고 스크립트 작성과 환경 설정까지 지원하는 중간자는 셸이며, 커널은 자원을 직접 관리하는 중심부다. 정답은 4번이다.

    (가)에 들어갈 용어로 옳은 것은?

    보안 운영체제는 기존의 운영체제에 내재된 보안상의 결함으로 인한 각종 침해로부터 시스템을 보호하기 위하여 기존의 운영체제 내에 보안 기능을 통합시킨 (가) 을/를 추가로 이식한 운영체제이다. 이를 통해 사용자의 모든 접근 행위가 안전하게 통제된다. 이것은 하드웨어, 운영체제 및 기타 시스템 요소 간의 보안 인터페이스를 제공한다.

    1. 1. 보안 커널
    2. 2. 접근 제어
    3. 3. 신뢰 플랫폼 모듈
    4. 4. 하이퍼바이저

    정답 1번

    🔍 보기별 해설
    1. 보안 커널은 참조 모니터 개념을 구현해 모든 접근 요청을 가로채고 정책에 따라 허용 여부를 정하는 핵심 모듈이다. 기존 운영체제에 이식해 보안 인터페이스를 맡으므로 옳다(정답).
    2. 접근 제어는 주체가 객체에 접근하는 것을 허용하거나 막는 보안 기능 또는 원리를 가리킨다. 운영체제에 이식하는 구성 요소 이름이 아니라 보안 커널이 수행하는 기능이므로 옳지 않다.
    3. 신뢰 플랫폼 모듈(TPM)은 메인보드에 붙은 하드웨어 칩으로 키 보관과 무결성 측정을 맡는다. 운영체제 안에 이식하는 소프트웨어 보안 요소가 아니므로 옳지 않다.
    4. 하이퍼바이저는 하나의 물리 서버 위에서 여러 가상 머신을 만들고 자원을 나눠 주는 가상화 계층이다. 운영체제 보안 결함을 막으려 이식하는 보안 기능 모듈이 아니므로 옳지 않다.
    🧮 풀이
    1. 증권 거래소 연계 서버를 맡은 甲은 기존 리눅스에 보안 커널 모듈을 이식해 보안 운영체제로 바꿨다. 이후 root 계정이라도 정책에 없는 파일을 열려 하면 커널이 요청을 가로채 거부했다. 모든 접근이 이 모듈을 거치게 된 결과다.
    2. 인사팀 서버를 관리하는 甲은 급여 파일을 인사 담당자만 읽도록 권한 목록을 정했다. 다른 부서 직원이 열려 하자 거부 메시지가 떴다. 이것은 접근 제어라는 기능이고, 이 기능을 강제로 집행하는 장치가 보안 커널이다.
    3. 노트북 관리 담당 甲은 디스크 암호화 키를 TPM 칩에 묶어 두었다. 누군가 하드디스크만 떼어 다른 PC에 꽂자 키가 풀리지 않아 데이터를 읽지 못했다. 신뢰 플랫폼 모듈은 이처럼 하드웨어 차원에서 키를 지킨다.
    4. 클라우드 운영자 甲은 물리 서버 한 대에 하이퍼바이저를 설치하고 가상 머신 다섯 대를 만들어 부서별로 나눠 주었다. 각 가상 머신은 자기만의 운영체제를 따로 띄워 서로의 메모리를 보지 못했다. 이것은 가상화 기술로 운영체제 내부의 보안 모듈과는 다르다.

    기존 운영체제에 이식되어 모든 접근을 통제하고 하드웨어·운영체제 사이 보안 인터페이스를 맡는 요소는 보안 커널이다. 정답은 1번이다.

    보안 모델의 하나인 만리장성(Chinese Wall) 모델에 대한 설명으로 옳은 것은?

    1. 1. 높은 보안 수준에서 낮은 보안 수준으로 정보가 흐르는 것을 방지하기 위한 기밀성 보장 모델이다.
    2. 2. 비즈니스 입장에서 직무 분리 개념을 적용하여 이해가 충돌하는 회사 간에 정보의 흐름이 일어나지 않도록 접근을 통제한다.
    3. 3. 무결성 중심의 상업적 모델로 내․외부의 일관성을 유지하고 비인가자에 의한 불법적인 수정을 방지한다.
    4. 4. 무결성을 위한 모델로 비인가자의 데이터 변형을 방지하기 위한 것이다.

    정답 2번

    🔍 보기별 해설
    1. 높은 등급에서 낮은 등급으로 정보가 내려가는 것을 막는 기밀성 모델은 벨라파둘라(BLP) 모델이다. 만리장성 모델의 설명이 아니므로 옳지 않다.
    2. 만리장성 모델은 금융 컨설팅처럼 경쟁 회사의 자료를 함께 다루는 곳에서 이해 충돌을 막으려 만든 모델이다. 한 회사 자료를 본 사람은 경쟁사 자료에 접근하지 못하게 하므로 옳다(정답).
    3. 내부·외부 일관성을 유지하고 비인가자의 불법 수정을 막는 상업적 무결성 모델은 클락-윌슨(Clark-Wilson) 모델이다. 만리장성 모델에 대한 설명이 아니므로 옳지 않다.
    4. 비인가자가 데이터를 바꾸지 못하게 하는 무결성 모델은 비바(Biba) 모델이다. 이해 충돌 회사 간 정보 흐름을 막는 만리장성 모델과는 다른 모델이므로 옳지 않다.
    🧮 풀이
    1. 군 정보 시스템 담당자 甲은 2급 비밀을 다루는 장교가 3급 게시판에 글을 쓰지 못하게 설정했다. 높은 등급의 내용이 아래 등급으로 흘러내리는 길이 막혔다. 이것이 BLP 모델의 No Write Down 규칙이다.
    2. 투자은행 컨설턴트 甲은 A은행의 인수합병 자문을 맡은 뒤 경쟁사인 B은행 폴더를 열려 했지만 시스템이 거부했다. 같은 이해 충돌 집단에 속한 회사 자료는 처음 고른 한 곳만 볼 수 있다. 만리장성 모델이 직무 분리로 정보 흐름을 끊은 결과다.
    3. 손해보험 정산팀 甲은 보험금 지급 기록을 직접 고치지 못하고 승인된 프로그램으로만 바꾸게 되어 있다. 처리 뒤에는 장부 합계와 실제 지급액이 맞는지 감사 절차가 다시 대조한다. 정형화된 거래와 직무 분리로 무결성을 지키는 클락-윌슨 모델이다.
    4. 증권사 시세 서버 관리자 甲은 등급이 낮은 사용자가 등급이 높은 시세 원장에 값을 쓰지 못하게 막았다. 신뢰도가 낮은 입력이 중요한 데이터를 더럽히는 일이 사라졌다. 이것은 비바 모델의 No Write Up 규칙이다.

    만리장성 모델은 경쟁 관계 회사의 자료를 함께 다루는 곳에서 이해 충돌을 막는 직무 분리형 접근 통제이고, 나머지는 BLP·클락-윌슨·비바 모델이다. 정답은 2번이다.

    윈도시스템의 NTFS에서 폴더 및 파일 접근 권한에 대한 설명으로 옳은 것은?

    1. 1. 그룹 A와 그룹 B에 속한 사용자가 그룹 A에서는 읽기 권한을 할당받고 그룹 B에서는 쓰기 권한을 할당받았다면, 사용자에게 읽기와 쓰기 권한이 모두 주어진다.
    2. 2. 파일이 포함된 폴더 권한이 파일 권한보다 우선한다.
    3. 3. 권한을 중첩해서 적용할 수 있으며, 허용 설정이 거부 설정보다 우선한다.
    4. 4. 폴더 접근 권한은 그룹에게만 부여된다.

    정답 1번

    🔍 보기별 해설
    1. NTFS 권한은 사용자가 속한 여러 그룹에 준 허용 권한을 모두 합쳐 적용하는 누적 방식이다. 읽기와 쓰기를 따로 받았다면 둘 다 갖게 되므로 옳다(정답).
    2. NTFS에서는 파일에 직접 준 권한이 상위 폴더에서 물려받은 권한보다 앞선다. 폴더 권한이 파일 권한을 이긴다는 말은 반대이므로 옳지 않다.
    3. NTFS 권한은 겹쳐 적용되지만 같은 수준에서 거부가 설정되면 허용보다 거부가 먼저 적용된다. 허용이 거부보다 우선한다는 말은 반대이므로 옳지 않다.
    4. NTFS 폴더 권한은 그룹뿐 아니라 개별 사용자 계정에도 직접 부여할 수 있다. 그룹에게만 준다는 말은 사실과 다르므로 옳지 않다.
    🧮 풀이
    1. 카드사 파일 서버 관리자 甲은 직원 乙을 조회팀과 작성팀 두 그룹에 넣고 공유 폴더에 각각 읽기와 쓰기를 주었다. 乙은 그 폴더의 보고서를 열고 내용을 고쳐 저장하는 것까지 할 수 있었다. NTFS가 두 그룹의 권한을 더해 적용한 것이다.
    2. 사내 공유 드라이브를 맡은 甲은 공지 폴더를 읽기 전용으로 두고 그 안의 접수 양식 파일 하나에만 쓰기 권한을 직접 주었다. 직원들은 폴더의 다른 파일은 못 고쳤지만 그 양식 파일은 수정할 수 있었다. 파일에 명시한 NTFS 권한이 물려받은 권한보다 먼저 적용된다.
    3. 은행 보안팀 甲은 퇴사 예정자 계정에 인사 폴더 쓰기를 허용한 그룹은 그대로 두고 그 계정에만 거부를 걸었다. 다른 그룹에서 허용을 받았어도 그 계정은 폴더를 열지 못했다. NTFS는 겹친 권한 중 거부를 허용보다 먼저 따진다.
    4. 지점 PC를 관리하는 甲은 그룹을 만들지 않고 감사 담당 직원 한 사람의 계정에 감사 자료 폴더 읽기 권한을 바로 주었다. 그 직원은 혼자서도 문제없이 폴더를 열었다. NTFS 권한은 개별 사용자에게도 붙일 수 있다.

    NTFS는 여러 그룹에서 받은 허용 권한을 더해 적용하므로 읽기와 쓰기를 모두 갖게 되고, 파일 권한 우선·거부 우선·사용자 부여 가능이 원칙이다. 정답은 1번이다.

    다음에서 설명하는 전자우편 보안 기술은?

    ○ 종단 사용자에게 투명한 인증 기술을 제공하도록 설계되었다.

    ○ 전자우편 메시지는 전자우편 발신지 관리 도메인의 개인키에 의해 서명된다.

    ○ 서명은 메시지 내용 전체와 메시지 헤더의 일부를 대상으로 한다.

    ○ 수신 측의 MDA(Mail Delivery Agent)는 DNS를 통해 해당 공개키에 접근하여 서명을 검증할 수 있다.

    1. 1. PGP
    2. 2. PEM
    3. 3. MIME
    4. 4. DKIM

    정답 4번

    🔍 보기별 해설
    1. PGP는 사용자 개인이 자기 키로 메일을 서명·암호화하고 신뢰의 웹으로 공개키를 확인하는 방식이다. 발신 도메인 개인키로 서명하고 DNS에서 공개키를 찾는 방식이 아니므로 옳지 않다.
    2. PEM은 인증서 계층 구조를 쓰는 초기 인터넷 메일 암호화 표준으로 사용자가 직접 암호화를 다룬다. 도메인 단위 서명과 DNS 공개키 조회를 쓰지 않으므로 옳지 않다.
    3. MIME은 메일에 한글·이미지·첨부 파일을 담기 위한 형식 확장 규격일 뿐 서명 기능이 없다. 메일 인증 기술 설명과 맞지 않으므로 옳지 않다.
    4. DKIM은 발신 도메인의 메일 서버가 개인키로 본문과 헤더 일부에 서명하고 수신 측은 DNS에 공개된 키로 검증하는 기술이다. 사용자 모르게 동작하는 도메인 인증 설명과 같으므로 옳다(정답).
    🧮 풀이
    1. 무역회사 대표 甲은 PGP로 키 쌍을 만들고 거래처 乙과 공개키 지문을 전화로 맞춰 본 뒤 계약서 메일을 암호화해 보냈다. 乙은 자기 개인키로 메일을 풀고 甲의 서명을 검사했다. 사용자 둘이 직접 키를 관리하는 방식이다.
    2. 1990년대 대학 전산실에서 일하던 甲은 PEM으로 메일을 보내려고 인증기관 계층에서 인증서를 먼저 받아야 했다. 절차가 번거로워 주변에서 쓰는 사람이 적었고 결국 표준이 널리 퍼지지 못했다. PEM은 사용자 단위 암호화 메일 표준이었다.
    3. 여행사 직원 甲은 일정표 PDF와 지도 이미지를 메일에 첨부했고, 메일 프로그램이 MIME 형식으로 첨부를 나눠 담았다. 받는 쪽에서 파일이 깨지지 않고 열렸지만 보낸 사람이 진짜인지 보증하는 서명은 없었다. MIME은 형식 규격이다.
    4. 증권사 메일 관리자 甲은 메일 서버에 DKIM 서명을 켜고 공개키를 DNS TXT 레코드에 올렸다. 수신 서버가 그 키로 서명을 자동 검증해 위조 발신 메일을 걸러 냈고, 고객은 아무 설정도 하지 않았다. 도메인 단위의 투명한 인증이다.

    발신 도메인의 개인키로 본문과 헤더 일부에 서명하고 수신 측이 DNS에 공개된 키로 검증하는 투명한 도메인 인증은 DKIM이다. 정답은 4번이다.

    다음에서 설명하는 윈도시스템 인증 구성 요소는?

    사용자의 계정과 패스워드가 일치하는 경우 해당 사용자에게 고유의 SID(Security Identifier)를 부여하며, 파일이나 폴더에 대한 접근 허용 여부를 결정하고 이에 대한 감사 메시지를 생성한다.

    1. 1. SAM
    2. 2. LSA
    3. 3. SRM
    4. 4. SPI

    정답 3번

    🔍 보기별 해설
    1. SAM은 사용자 계정과 패스워드 해시를 저장하고 로그인 때 입력값과 대조해 주는 데이터베이스다. SID 부여나 접근 허용 결정을 맡지 않으므로 옳지 않다.
    2. LSA는 로그인을 검증하고 보안 정책과 감사 정책을 관리하는 보안 하위 시스템의 중심이다. SID를 붙여 접근 허용을 결정하고 감사 메시지를 만드는 구성 요소는 따로 있으므로 옳지 않다.
    3. SRM(Security Reference Monitor)은 인증된 사용자에게 SID를 부여하고 객체 접근 허용 여부를 판단해 감사 메시지를 생성한다. 설명과 같으므로 옳다(정답).
    4. SPI는 윈도 인증 구조를 이루는 LSA·SAM·SRM 가운데 하나가 아니며, 보통 상태 기반 패킷 검사 같은 다른 분야 용어로 쓰인다. SID를 부여하고 접근을 결정하는 구성 요소가 아니므로 옳지 않다.
    🧮 풀이
    1. 보험 대리점 PC 관리자 甲은 직원이 로그인할 때 입력한 패스워드를 SAM에 저장된 해시와 대조하도록 로컬 계정을 만들었다. 패스워드가 틀리면 로그인 단계에서 바로 막혔지만 파일 접근 판단은 이 단계에서 하지 않는다. SAM은 계정 정보 저장소다.
    2. 사내망 보안 담당 甲은 그룹 정책으로 로그온 실패 감사를 켜고, LSA가 그 정책을 받아 로그인 검증을 처리하게 했다. 이후 틀린 패스워드 시도가 보안 로그에 남았다. LSA는 로그인 검증과 정책 관리를 맡는 상위 관리자다.
    3. 영업점 서버에서 직원 甲이 로그인하자 SRM이 甲에게 고유 SID를 담은 토큰을 붙였다. 甲이 대출 심사 폴더를 열 때 SRM이 그 SID를 폴더 접근 목록과 대조해 거부하고 감사 메시지를 만들었다. 접근 판정과 감사의 출발점이 SRM이다.
    4. 네트워크 담당 甲은 방화벽 설정 화면에서 SPI 기능을 켜 내부에서 시작한 연결에 대한 응답 패킷만 들어오게 했다. 이 설정은 윈도 로그인이나 파일 권한과는 아무 관계가 없었다. SPI는 윈도 인증 구성 요소가 아니다.

    인증된 사용자에게 SID를 부여하고 파일·폴더 접근 허용 여부를 판단해 감사 메시지를 만드는 것은 SRM이며, SAM은 계정 저장소, LSA는 로그인 검증 담당이다. 정답은 3번이다.

    S/MIME에 대한 설명으로 옳지 않은 것은?

    1. 1. 서명된 데이터(signed data)의 디지털 서명은 메시지 다이제스트를 서명자의 개인키로 암호화한 것으로, 서명과 함께 메시지 내용은 base64로 부호화된다.
    2. 2. 서명과 봉인된 데이터(signed and enveloped data)는 서명만 하거나 암호화만 한 개체들이 중첩된 것으로, 암호화한 데이터를 서명하거나 서명한 데이터를 암호화할 수 있다.
    3. 3. 디지털 서명만을 base64로 부호화한 클리어 서명 데이터(clear-signed data)의 경우, S/MIME 기능을 갖추지 않은 수신자도 서명을 검증하고 메시지의 내용을 볼 수 있도록 지원한다.
    4. 4. X.509의 버전 3을 따르는 공개키 인증서를 사용한다.

    정답 3번

    🔍 보기별 해설
    1. S/MIME의 서명된 데이터(signed data)는 메시지 다이제스트를 서명자 개인키로 암호화해 서명을 만들고, 서명과 내용을 함께 base64로 부호화한다. 설명과 같으므로 옳다.
    2. S/MIME은 서명과 암호화를 겹쳐 쓸 수 있어 먼저 암호화한 뒤 서명하는 순서도, 서명 뒤 암호화하는 순서도 가능하다. 서명과 봉인된 데이터(signed and enveloped data) 설명으로 옳다.
    3. 클리어 서명 데이터(clear-signed data)는 서명만 base64로 바꾸고 본문은 그대로 두어 S/MIME이 없는 수신자도 내용은 읽을 수 있다. 다만 그 수신자는 서명을 검증하지 못하므로 옳지 않다(정답).
    4. S/MIME은 송수신자의 공개키를 X.509 버전 3 형식의 인증서로 주고받는다. 인증서 형식 설명으로 옳다.
    🧮 풀이
    1. 공공기관 메일 담당 甲은 S/MIME으로 공문 메일에 서명했다. 메일 프로그램은 본문 다이제스트를 甲의 개인키로 암호화해 서명을 만들고, 본문과 서명을 함께 base64 덩어리로 바꿔 보냈다. 서명된 데이터 형식이다.
    2. 회계법인 직원 甲은 감사 보고서 메일을 먼저 자기 개인키로 서명하고, 그 결과를 다시 수신자 乙의 공개키로 암호화했다. 乙은 복호화한 뒤 서명을 검증해 보낸 사람과 내용이 모두 진짜임을 알 수 있었다. 서명과 봉인을 겹친 형식이다.
    3. S/MIME을 쓰는 甲이 클리어 서명 방식으로 메일을 보내자, S/MIME 기능이 없는 웹메일을 쓰는 乙도 본문은 그대로 읽었다. 그러나 乙의 화면에는 서명이 알 수 없는 첨부 파일로만 보여 진위를 검증할 수 없었다. 내용 열람과 서명 검증은 별개다.
    4. 보험사 보안팀 甲은 직원 메일 인증서를 X.509 v3 형식으로 발급받아 S/MIME 클라이언트에 등록했다. 인증서 확장 필드에 메일 보호 용도가 표시되어 있어 메일 프로그램이 서명용 인증서로 바로 인식했다. S/MIME이 쓰는 인증서 형식이다.

    클리어 서명 데이터는 본문을 그대로 두어 S/MIME이 없는 수신자도 내용은 읽지만 서명 검증까지는 하지 못하는데, 검증도 된다고 했다. 정답은 3번이다.

    정답 3번

    🔍 보기별 해설
    1. GET 요청에서 가져올 웹페이지의 위치(URL)는 헤더 라인이 아니라 첫 줄인 요청 라인에 메소드·버전과 함께 적힌다. 헤더 라인에 명시된다는 말은 옳지 않다.
    2. 쿠키 정보는 GET 요청에서 Cookie 헤더 라인에 담겨 전송되며, GET은 보통 메시지 몸체를 쓰지 않는다. 몸체에 포함된다는 말은 옳지 않다.
    3. HEAD는 GET과 같은 응답 헤더만 받고 본문은 받지 않는 메소드라 문서 크기나 수정 시각 같은 정보만 알아볼 때 쓴다. 웹페이지 일부 정보를 요청한다는 설명은 옳다(정답).
    4. 요청이 서버에 어떻게 도착하는지 되돌려 보는 에코 용도의 메소드는 TRACE이고, PUT은 지정한 위치에 자원을 올려 저장하는 메소드다. PUT 설명이 아니므로 옳지 않다.
    🧮 풀이
    1. 쇼핑몰 개발자 甲은 패킷을 캡처해 첫 줄이 GET /item/123 HTTP/1.1로 시작하는 요청을 열었다. 상품 경로는 이 요청 라인에 있었고, 그 아래 Host·User-Agent 같은 헤더 라인에는 경로가 따로 없었다. 페이지 위치는 요청 라인에 적힌다.
    2. 포털 로그인 기능을 맡은 甲은 브라우저가 서버에서 받은 세션 쿠키를 다음 GET 요청 때 Cookie 헤더에 실어 돌려보내는 흐름을 개발자 도구로 따라갔다. 요청 몸체는 비어 있었고 쿠키는 헤더 줄에만 있었다. 쿠키는 헤더로 오간다.
    3. 뉴스 사이트 운영자 甲은 대용량 동영상을 내려받기 전에 HEAD 요청을 보내 Content-Length와 Last-Modified 값만 받아 왔다. 파일 본문은 오지 않아 트래픽 없이 크기와 수정 시각을 알 수 있었고, 바뀐 파일만 골라 다시 받았다. HEAD는 정보만 묻는 메소드다.
    4. 웹 서버 점검을 맡은 甲은 PUT 메소드가 열려 있어 아무나 /upload/test.html 파일을 서버에 써 넣을 수 있는 상태를 찾아 막았다. 요청을 그대로 되돌려 주는 진단 기능은 TRACE이며 이것도 함께 껐다. PUT은 자원을 저장하는 메소드다.

    HEAD는 GET과 같은 응답 헤더만 받고 본문은 받지 않아 웹페이지에 대한 정보만 요청하는 메소드이고, URL은 요청 라인에, 쿠키는 헤더에 담긴다. 정답은 3번이다.

    PKI에 대한 설명으로 옳지 않은 것은?

    1. 1. 인증기관(CA), 등록기관(RA), 키 분배 센터(KDC)로 구성된다.
    2. 2. 이용자는 공개키를 이용하기 전에 CA의 인증서 폐기 목록(CRL)을 조사해서 해당 인증서의 유효성을 확인할 필요가 있다.
    3. 3. CA의 공개키에 대해 다른 CA가 디지털 서명을 하는 것으로 그 CA의 공개키를 검증할 수 있다.
    4. 4. CA의 개인키가 노출된 경우에는 그 사실을 CRL을 사용해서 이용자에게 통지할 필요가 있다.

    정답 1번

    🔍 보기별 해설
    1. PKI는 인증기관(CA), 등록기관(RA), 인증서와 CRL을 보관하는 디렉터리, 사용자 등으로 구성된다. 키 분배 센터(KDC)는 대칭키 기반 커버로스의 구성 요소이므로 옳지 않다(정답).
    2. 인증서는 만료 전에도 폐기될 수 있어 이용자는 공개키를 쓰기 전에 CA가 공개한 CRL로 유효성을 따져야 한다. 설명대로이므로 옳다.
    3. 상위 CA가 하위 CA의 공개키에 디지털 서명을 해 주면 이용자는 상위 CA의 공개키로 그 서명을 검증해 하위 CA를 믿을 수 있다. 인증 경로 설명으로 옳다.
    4. CA의 개인키가 노출되면 그 키로 서명한 인증서를 더는 믿을 수 없으므로 CRL로 폐기 사실을 알려야 한다. 설명대로이므로 옳다.
    🧮 풀이
    1. 공공기관 인증 담당 甲은 PKI 구축 계획서에 CA, RA, 디렉터리를 넣고 KDC를 빼자는 의견을 냈다. KDC는 커버로스에서 티켓을 나눠 주는 대칭키 서버라 공개키 인증서 체계에는 필요가 없었다. 계획서는 그대로 승인되었다.
    2. 온라인 뱅킹 서버를 맡은 甲은 고객 인증서를 받을 때마다 CRL을 내려받아 일련번호를 대조하게 했다. 분실 신고로 폐기된 인증서가 들어오자 서명이 정상이어도 로그인을 거부했다. 만료일만 보면 놓치는 사고를 CRL이 막았다.
    3. 전자서명 업무를 맡은 甲은 처음 보는 하위 인증기관 CA-B의 인증서를 받자 그 안에 붙은 최상위 CA의 서명을 미리 설치된 최상위 공개키로 검증했다. 서명이 맞자 CA-B가 발급한 사용자 인증서도 믿고 쓸 수 있었다. 인증 경로를 따라간 결과다.
    4. 인증기관 운영자 甲은 서명 서버 해킹으로 CA 개인키가 새어 나간 정황을 발견하고 그 키로 발급한 인증서를 모두 폐기했다. 폐기 목록을 담은 CRL을 즉시 다시 공개하자 이용자 프로그램들이 그 인증서를 거부하기 시작했다. 키 노출은 CRL로 알린다.

    PKI는 CA·RA·디렉터리·사용자로 구성되고 KDC는 대칭키 기반 커버로스의 구성 요소인데, KDC를 PKI 구성 요소로 넣었다. 정답은 1번이다.

    인증을 받은 사용자가 여러 정보 시스템에 재인증 절차 없이 반복해서 접근할 수 있도록 해주는 것은?

    1. 1. OTP
    2. 2. SSO
    3. 3. Challenge & Response
    4. 4. CAPTCHA

    정답 2번

    🔍 보기별 해설
    1. OTP는 로그인할 때마다 한 번만 쓰는 비밀번호를 새로 만들어 재사용 공격을 막는 인증 수단이다. 한 번 인증으로 여러 시스템에 들어가게 해 주는 기능이 아니므로 옳지 않다.
    2. SSO(Single Sign-On)는 한 번 인증받은 사용자가 연결된 여러 시스템을 다시 로그인하지 않고 쓰게 해 주는 방식이다. 설명과 같으므로 옳다(정답).
    3. Challenge & Response는 서버가 보낸 난수에 사용자가 비밀값으로 계산한 응답을 돌려주어 본인을 증명하는 인증 방식이다. 재인증 없이 여러 시스템을 쓰게 하는 기능이 아니므로 옳지 않다.
    4. CAPTCHA는 일그러진 문자나 그림을 풀게 해 사람인지 자동 프로그램인지 구분하는 기술이다. 사용자 인증을 여러 시스템에 넘겨주는 기능이 아니므로 옳지 않다.
    🧮 풀이
    1. 증권 앱 사용자 甲은 이체 버튼을 누를 때마다 OTP 기기에 새로 뜬 여섯 자리 숫자를 입력했다. 누군가 지난번 숫자를 엿봐 다시 넣어도 이미 쓴 값이라 거부되었다. 다만 다른 사내 시스템에 들어갈 때는 다시 인증해야 했다.
    2. 대학 포털에 로그인한 교직원 甲은 그 상태로 메일, 전자결재, 도서관 시스템을 차례로 열었는데 어디서도 다시 아이디를 묻지 않았다. 포털이 발급한 SSO 인증 정보를 각 시스템이 그대로 믿었기 때문이다. 한 번의 인증으로 여러 시스템을 쓰는 구조다.
    3. 사내 무선랜 관리자 甲은 단말이 접속할 때 서버가 난수를 보내고 단말이 공유 비밀값으로 해시한 응답을 돌려주게 설정했다. 패스워드 자체가 망에 흐르지 않아 도청자는 응답만 보고 비밀값을 알 수 없었다. Challenge & Response 방식이다.
    4. 공연 예매 사이트 운영자 甲은 매크로가 표를 싹쓸이하자 결제 직전에 CAPTCHA를 넣었다. 비틀린 글자를 읽어 입력해야 다음 단계로 넘어가게 되자 자동 예매 프로그램의 시도가 대부분 막혔다. 사람과 프로그램을 구분하는 기술이다.

    한 번 인증받은 사용자가 연결된 여러 시스템을 다시 로그인하지 않고 쓰게 해 주는 것은 SSO이고, 나머지는 인증 강화나 사람 구분 기술이다. 정답은 2번이다.

    공격 대상이 되는 서버에서 먼저 공격자 PC로 연결하게 하여 방화벽 보안 정책을 우회하는 공격은?

    1. 1. 리버스 텔넷
    2. 2. 쿠키 변조
    3. 3. 명령 삽입
    4. 4. 파일 업로드

    정답 1번

    🔍 보기별 해설
    1. 리버스 텔넷은 웹 취약점으로 서버에 명령을 실행시켜 서버가 먼저 공격자 PC로 접속하게 만드는 기법이다. 방화벽이 대개 안에서 밖으로 나가는 연결은 허용한다는 점을 노리므로 옳다(정답).
    2. 쿠키 변조는 브라우저에 저장된 쿠키 값을 고쳐 다른 사용자로 행세하거나 권한을 올리는 공격이다. 서버가 먼저 공격자에게 연결하게 하는 방식이 아니므로 옳지 않다.
    3. 명령 삽입은 입력값에 운영체제 명령을 끼워 넣어 서버에서 실행되게 하는 공격이다. 리버스 텔넷의 발판이 될 수는 있어도 역방향 연결 자체를 가리키는 말은 아니므로 옳지 않다.
    4. 파일 업로드 공격은 웹셸 같은 악성 파일을 서버에 올려 실행하는 공격이다. 방화벽을 우회하는 역방향 접속 기법 자체가 아니므로 옳지 않다.
    🧮 풀이
    1. 모의해킹을 맡은 甲은 방화벽이 외부에서 들어오는 텔넷은 막지만 서버에서 나가는 연결은 열어 둔 점을 알고, 취약한 게시판으로 서버가 자기 PC의 포트로 접속하게 명령을 보냈다. 서버가 먼저 연결을 열자 甲은 그 창으로 서버 셸을 얻었다. 리버스 텔넷이다.
    2. 온라인 쇼핑몰 회원 甲이 브라우저 쿠키의 grade=normal을 grade=vip로 바꿔 요청하자 서버가 그대로 VIP 할인을 적용했다. 서버가 쿠키 값을 검증하지 않아 생긴 쿠키 변조 사고로, 연결 방향과는 관계가 없다.
    3. 보안 점검 담당 甲은 주소 조회 입력창에 8.8.8.8; cat /etc/passwd를 넣었고 응답 화면에 계정 목록이 그대로 찍혔다. 입력값을 셸에 그대로 넘기는 명령 삽입 취약점이었고, 甲은 개발팀에 입력값 필터링을 요청했다.
    4. 취약점 진단원 甲은 이미지 업로드 기능에 확장자를 jpg로 위장한 웹셸 파일을 올렸고, 그 파일 주소를 열자 서버 명령을 실행할 수 있었다. 업로드 폴더의 실행 권한을 막는 조치가 필요했다. 파일 업로드 공격이다.

    방화벽이 안에서 밖으로 나가는 연결은 대개 허용한다는 점을 노려 서버가 먼저 공격자 PC로 접속하게 만드는 기법은 리버스 텔넷이다. 정답은 1번이다.

    (가) ～ (다) 안에 들어갈 용어를 바르게 연결한 것은?

    함수 P가 함수 Q를 호출하기 위해, P는 Q에 전달할 인수를 스택에 넣는다. Q를 호출하는 call 명령어를 수행하면 (가) 가 스택에 저장된다. Q는 (나) 를 스택에 넣는다. 프레임 포인터 레지스터 값을 현재의 포인터 값으로 설정하고, 스택 포인터를 아래로 움직여 (다) 를 저장할 공간을 할당하고, Q의 코드를 수행한다. 컴파일러의 최적화 기능에 따라 실제 배치는 차이가 있을 수 있으나, 저장된 (가) 와 (나) 에 겹쳐 쓰기는 스택 버퍼 오버플로 공격의 핵심이다. (가) (나) (다)

    1. 1. 반환 주소 P의 스택 프레임 포인터 지역 변수
    2. 2. 반환 주소 Q의 스택 프레임 포인터 지역 변수
    3. 3. P의 스택 프레임 포인터 지역 변수 반환 주소
    4. 4. Q의 스택 프레임 포인터 지역 변수 반환 주소

    정답 1번

    🔍 보기별 해설
    1. call 명령을 수행하면 돌아올 위치인 반환 주소가 먼저 스택에 들어가고, 호출된 Q는 호출한 P의 프레임 포인터를 저장한 뒤 지역 변수 공간을 잡는다. 세 칸 순서가 모두 맞으므로 옳다(정답).
    2. Q가 스택에 저장하는 것은 자기 프레임 포인터가 아니라 돌아가서 복원해야 할 P의 스택 프레임 포인터다. (나)가 어긋나므로 옳지 않다.
    3. call 명령이 자동으로 쌓는 값은 반환 주소이고, 반환 주소가 지역 변수 자리에 오지도 않는다. (가)와 (다)가 서로 바뀌어 있으므로 옳지 않다.
    4. (가)에는 반환 주소, (나)에는 P의 프레임 포인터가 와야 하는데 Q의 프레임 포인터와 지역 변수를 앞에 넣고 반환 주소를 맨 뒤에 두었다. 순서가 모두 어긋나므로 옳지 않다.
    🧮 풀이
    1. 보안 분석가 甲은 디버거에서 P가 Q를 부르는 순간 스택 맨 위에 반환 주소가 생기고, 이어 Q가 P의 EBP 값을 push한 뒤 ESP를 내려 지역 변수 버퍼를 만드는 과정을 한 단계씩 실행했다. 버퍼를 넘치게 채우자 저장된 EBP와 반환 주소가 덮였다.
    2. 취약점 연구원 甲은 Q의 함수 시작부에서 push ebp가 실행될 때 들어가는 값이 Q의 새 기준점인지 P의 것인지 레지스터 값을 비교했다. 저장된 값은 P가 쓰던 EBP였고, Q의 프레임 포인터는 그 직후 mov ebp, esp로 새로 만들어졌다.
    3. 악성코드 분석팀 甲은 반환 주소가 지역 변수 자리에 저장된다고 잘못 그린 내부 교육 자료대로 공격 재현을 시도했다. 그림대로 지역 변수 위치를 덮었지만 프로그램 흐름은 바뀌지 않았고, 반환 주소는 call 때 이미 더 높은 주소에 들어가 있었다.
    4. 보안 컨설턴트 甲은 버퍼 오버플로 보고서 초안에서 Q의 프레임 포인터, 지역 변수, 반환 주소 순으로 저장된다고 쓴 문단을 실제 메모리 덤프와 대조해 다시 썼다. 덤프에는 반환 주소가 가장 먼저, 그다음 P의 EBP, 마지막으로 지역 변수 버퍼가 있었다.

    call 명령이 반환 주소를 먼저 쌓고, 호출된 Q는 P의 프레임 포인터를 저장한 뒤 지역 변수 공간을 잡으므로 순서는 반환 주소, P의 프레임 포인터, 지역 변수다. 정답은 1번이다.

    FTP에 대한 설명으로 옳지 않은 것은?

    1. 1. 데이터 연결 시 평문으로 데이터를 전송한다.
    2. 2. 데이터 연결은 송․수신 모두 지정된 포트 20번을 통해서만 가능하다.
    3. 3. 사용자 계정의 패스워드는 암호화되지 않은 상태로 전달된다.
    4. 4. FTP를 이용하여 클라이언트는 서버의 파일을 읽고 서버에 파일을 저장할 수 있을 뿐만 아니라 서버의 파일 목록을 볼 수도 있다.

    정답 2번

    🔍 보기별 해설
    1. FTP의 데이터 연결은 암호화 없이 파일 내용을 평문으로 보낸다. 중간에서 도청하면 파일 내용이 그대로 보이므로 옳다.
    2. FTP 능동 모드에서는 서버가 20번 포트로 데이터 연결을 시작하지만 클라이언트 쪽은 임의 포트를 쓰고, 수동 모드에서는 서버도 1024번 이후 임의 포트를 연다. 늘 20번만 쓴다는 말은 옳지 않다(정답).
    3. FTP는 USER·PASS 명령으로 계정과 패스워드를 제어 연결에 평문으로 실어 보낸다. 스니핑으로 패스워드가 노출될 수 있으므로 옳다.
    4. FTP 클라이언트는 RETR로 파일을 내려받고 STOR로 올리며 LIST로 서버 디렉터리 목록을 볼 수 있다. 읽기·저장·목록 보기가 모두 가능하므로 옳다.
    🧮 풀이
    1. 보안관제 요원 甲은 사내 FTP 서버로 오가는 패킷을 와이어샤크로 잡아 데이터 연결 스트림을 열었다. 고객 명단 엑셀 파일의 내용이 글자 그대로 복원되었다. 평문 전송이라 甲은 SFTP로 바꾸자고 보고했다.
    2. 방화벽 담당 甲은 FTP용으로 20·21번만 열어 두었는데 사용자가 수동 모드로 접속하자 목록 조회에서 멈췄다. 서버가 데이터 연결용으로 50000번대 포트를 알려 주었기 때문이고, 그 범위를 열자 정상으로 돌아왔다. 데이터 포트는 20번에 묶여 있지 않다.
    3. 침해사고 대응팀 甲은 유출 경위를 추적하다가 캡처 파일에서 USER admin, PASS qwer1234 줄을 그대로 찾아냈다. 공격자는 이 계정으로 FTP에 다시 로그인해 자료를 빼 갔다. 패스워드가 암호화되지 않은 탓이다.
    4. 보험사 지점 직원 甲은 FTP 클라이언트로 본사 서버에 접속해 ls로 폴더 목록을 보고, get으로 요율표를 내려받은 뒤 put으로 실적 보고서를 올렸다. 한 번의 접속으로 목록 조회와 내려받기, 올리기를 모두 마쳤다.

    FTP 데이터 연결은 능동 모드에서 서버만 20번을 쓰고 클라이언트와 수동 모드 서버는 임의 포트를 여는데, 늘 20번만 쓴다고 했다. 정답은 2번이다.

    SQL 뷰에 대한 설명으로 옳지 않은 것은?

    1. 1. 사용자가 뷰를 통해서만 데이터에 접근하게 함으로써 기본 테이블에 대한 보안성을 높일 수 있다.
    2. 2. 뷰가 정의된 기본 테이블이 확장되거나 뷰가 속해 있는 데이터베이스에 테이블이 늘어난다고 하더라도 기존의 뷰를 사용하는 프로그램이나 사용자는 영향을 받지 않는다.
    3. 3. 필요한 데이터만 뷰로 정의해서 처리할 수 있기 때문에 사용자 권한 관리가 용이하다.
    4. 4. 대부분의 경우 삽입, 삭제, 갱신 연산에 많은 제한이 따르며 질의문이 복잡해지는 단점이 있다.

    정답 4번

    🔍 보기별 해설
    1. 뷰를 만들어 사용자에게 뷰만 조회하도록 권한을 주면 기본 테이블의 다른 열과 행은 보이지 않는다. 기본 테이블 보안성을 높일 수 있으므로 옳다.
    2. 뷰는 논리적 데이터 독립성을 제공해 기본 테이블에 열이 추가되거나 데이터베이스에 테이블이 늘어도 뷰 정의가 그대로면 기존 프로그램은 바뀌지 않는다. 설명대로이므로 옳다.
    3. 꼭 필요한 열만 골라 뷰로 만들어 두면 사용자마다 뷰 단위로 권한을 주면 되어 권한 관리가 쉬워진다. 설명대로이므로 옳다.
    4. 뷰는 삽입·삭제·갱신에 제약이 많은 것은 맞지만, 복잡한 조인을 미리 정의해 두므로 사용자의 질의문은 오히려 단순해진다. 질의문이 복잡해진다는 단점은 옳지 않다(정답).

    1. 인사 시스템 담당 甲은 직원 테이블에서 주민번호와 연봉 열을 뺀 뷰를 만들어 현업 부서에는 그 뷰 조회 권한만 주었다. 부서 직원들은 이름과 부서는 볼 수 있었지만 원본 테이블은 열 수 없었다. 뷰가 민감한 열을 감췄다.
    2. 보험 계약 DB를 맡은 甲은 계약 테이블에 특약 코드 열을 새로 붙이고 결제 테이블도 하나 추가했다. 기존 고객 조회 화면은 고객 뷰만 읽고 있어 코드 한 줄 고치지 않고도 그대로 돌아갔다. 뷰가 프로그램과 테이블 변경 사이를 막아 준 것이다.
    3. 대출 심사 시스템 관리자 甲은 지점별로 자기 지점 고객 행만 보이는 뷰를 하나씩 만들고 지점 계정에는 그 뷰 권한만 주었다. 새 지점이 생겨도 뷰 하나와 권한 한 줄만 추가하면 끝나 권한 관리 작업이 크게 줄었다.
    4. 데이터 분석가 甲은 고객·주문·배송 세 테이블을 조인한 뷰를 만들어 두고, 현업 직원에게 SELECT * FROM 주문현황 한 줄로 조회하게 했다. 직원은 조인 문법을 몰라도 원하는 자료를 얻었지만, 그 뷰로 값을 수정하려 하자 오류가 났다. 질의는 쉬워지고 갱신은 제한된다.

    뷰는 갱신 연산에 제약이 있지만 복잡한 조인을 미리 정의해 두므로 사용자의 질의는 오히려 단순해지는데, 질의문이 복잡해진다고 했다. 정답은 4번이다.

    리눅스에서 제공하는 특수 권한에 대한 설명으로 옳지 않은 것은?

    1. 1. 숫자로 나타내면 접근 권한의 맨 앞자리에 Set-UID는 4, Set-GID는 2, Sticky-Bit는 1로 표현된다.
    2. 2. Set-UID를 설정하면 소유자 실행 권한 자리에, Set-GID를 설정하면 그룹 실행 권한 자리에 s 혹은 S가 표시된다.
    3. 3. Sticky-Bit는 공유를 목적으로 파일에 설정하는 특수 권한으로, 설정 시 소유자 실행 권한 자리에 t 혹은 T가 표시된다.
    4. 4. Set-UID가 설정된 파일이 실행되는 동안에는 파일을 실행한 사용자의 권한이 아니라 파일 소유자의 권한이 적용된다.

    정답 3번

    🔍 보기별 해설
    1. 특수 권한은 일반 권한 세 자리 앞에 한 자리를 더 붙여 적으며 Set-UID 4, Set-GID 2, Sticky-Bit 1을 더한 값을 쓴다. 4755나 1777처럼 표기하므로 옳다.
    2. Set-UID는 소유자 실행 자리에, Set-GID는 그룹 실행 자리에 s로 표시되고 실행 권한이 없으면 대문자 S로 보인다. 표시 위치 설명으로 옳다.
    3. Sticky-Bit는 /tmp처럼 여럿이 함께 쓰는 디렉터리에 설정해 자기 파일만 지울 수 있게 하는 권한이며, 기타 사용자 실행 자리에 t 또는 T로 표시된다. 파일에 설정하고 소유자 자리에 표시된다는 말은 옳지 않다(정답).
    4. Set-UID 파일을 실행하면 그 프로세스는 실행한 사용자가 아니라 파일 소유자의 유효 권한으로 동작한다. passwd 명령이 이 원리로 동작하므로 옳다.
    🧮 풀이
    1. 서버 운영자 甲은 공유 폴더에 chmod 1777을 주고, 관리 도구에는 chmod 4755를 주었다. ls -l 결과 폴더는 drwxrwxrwt, 도구는 -rwsr-xr-x로 바뀌었다. 맨 앞 숫자 1은 Sticky-Bit, 4는 Set-UID를 뜻한다.
    2. 그룹웨어 서버 담당 甲은 실행 권한이 없는 파일에 chmod u+s를 걸었더니 ls -l에서 소유자 자리가 대문자 S로 나왔다. 실행 권한을 더하자 소문자 s로 바뀌었고, g+s를 준 다른 파일은 그룹 자리에 s가 붙었다. Set-UID와 Set-GID의 표시다.
    3. 개발팀 리더 甲은 팀 공용 디렉터리에 Sticky-Bit를 설정했고, ls -l 끝자리에 t가 붙은 drwxrwxrwt가 나왔다. 이후 팀원 乙이 동료의 파일을 rm으로 지우려 하자 거부되었다. 공유 디렉터리에서 남의 파일 삭제를 막는 권한이다.
    4. 일반 사용자 甲이 passwd 명령으로 자기 패스워드를 바꾸자, root만 쓸 수 있는 /etc/shadow가 정상적으로 고쳐졌다. passwd 파일에 Set-UID가 걸려 있어 실행되는 동안 root 권한으로 움직였기 때문이다.

    Sticky-Bit는 /tmp 같은 공유 디렉터리에 설정해 남의 파일 삭제를 막고 기타 사용자 실행 자리에 t로 표시되는데, 파일에 설정하고 소유자 자리에 표시된다고 했다. 정답은 3번이다.

    프로그램이 실행될 때마다 해당 프로그램이 사용하는 메모리 주소를 무작위로 배치하여 공격 대상 프로그램이 사용하는 메모리 주소를 추측하기 어렵게 만드는 리눅스 운영체제의 기능은?

    1. 1. DLL
    2. 2. Canary
    3. 3. ASLR
    4. 4. Packing

    정답 3번

    🔍 보기별 해설
    1. DLL(Dynamic Link Library)은 여러 프로그램이 함께 불러 쓰는 윈도우의 동적 라이브러리 파일 형식이다. 메모리 주소를 무작위로 배치하는 보호 기능이 아니므로 옳지 않다.
    2. Canary는 스택의 리턴 주소 앞에 임의의 값을 넣어 두고 함수가 끝날 때 그 값이 바뀌었는지 보는 스택 보호 기법이다. 주소 배치를 무작위로 바꾸는 기능과는 다르므로 옳지 않다.
    3. ASLR(Address Space Layout Randomization)은 실행할 때마다 스택·힙·라이브러리가 놓이는 주소를 무작위로 바꾸는 기능이다. 공격자가 메모리 주소를 미리 알 수 없게 만드는 기능이므로 옳다(정답).
    4. Packing은 실행 파일을 압축하거나 암호화해 크기를 줄이고 분석을 어렵게 만드는 기법이다. 실행 중 메모리 주소를 무작위로 배치하는 운영체제 기능이 아니므로 옳지 않다.
    🧮 풀이
    1. 사무 프로그램을 만드는 개발자 甲은 맞춤법 검사 기능을 DLL 파일 하나로 빼서 여러 프로그램이 같이 불러 쓰게 했다. 기능을 고칠 때 DLL만 바꾸면 되어 배포가 가벼워졌지만, 메모리 주소를 숨기는 효과는 생기지 않는다.
    2. 대학 전산실 甲이 C 프로그램을 스택 보호 옵션으로 다시 컴파일하자 함수마다 Canary 값이 리턴 주소 앞에 놓였다. 넘치는 입력이 이 값을 덮어쓰자 프로그램이 곧바로 멈춰 리턴 주소 조작이 막혔다.
    3. 병원 서버 담당 甲은 같은 프로그램을 두 번 실행하고 각각의 스택 시작 주소와 libc 주소를 출력했는데 두 값 모두 실행할 때마다 달랐다. 그래서 공격 코드가 앞선 실행에서 알아낸 주소로 뛰어들려 해도 엉뚱한 곳을 가리켜 프로그램이 멈출 뿐이니, 이것이 ASLR이 주는 방어다.
    4. 악성코드 분석가 甲이 받은 의심 파일은 Packing으로 압축돼 있어 문자열이 거의 보이지 않았다. 甲이 언패킹 도구로 원래 코드를 풀어내자 그제야 접속 주소와 명령 목록이 읽혔다.

    실행할 때마다 스택·힙·라이브러리 주소를 무작위로 바꿔 공격자가 주소를 짐작하지 못하게 하는 리눅스 기능은 ASLR이다. 정답은 3번이다.

(가) (나) (다)

    다음과 같이 시스템에 설정된 umask 값이 ‘022’인 경우, 파일(file1)을 생성하였을 때 생성된 파일의 접근권한은?

    [root@security ~]# umask 022

    [root@security ~]# touch file1

    1. 1. -rwxr-xr-x
    2. 2. -r-xrwxrwx
    3. 3. -rw-r--r--
    4. 4. -rw-------

    정답 3번

    🔍 보기별 해설
    1. -rwxr-xr-x는 755 권한으로, 디렉터리 기본값 777에서 umask 022를 뺐을 때 나오는 값이다. 파일은 실행 권한 없이 666에서 출발하므로 옳지 않다.
    2. -r-xrwxrwx는 소유자보다 그룹·기타 사용자가 더 많은 권한을 갖는 577 권한이다. umask 022는 그룹과 기타의 쓰기 권한을 빼는 값이라 이렇게 될 수 없으므로 옳지 않다.
    3. 새 파일의 기본 권한 666(rw-rw-rw-)에서 umask 022가 그룹·기타의 쓰기 권한을 빼면 644가 된다. 644를 기호로 적은 -rw-r--r--이므로 옳다(정답).
    4. -rw-------는 소유자만 읽고 쓰는 600 권한으로 umask가 077일 때 나오는 값이다. umask 022에서는 그룹·기타에 읽기 권한이 남으므로 옳지 않다.

    전자메일 시스템에서 송신 부인방지 기능을 위해 적용하는 기술은?

    1. 1. 전자 서명(digital signature)
    2. 2. 대칭키 암호화(symmetric encryption)
    3. 3. 앨리어스(alias)
    4. 4. 커버로스(Kerberos)

    정답 1번

    🔍 보기별 해설
    1. 전자 서명(digital signature)은 송신자가 자기 개인키로 메일에 서명하고 받는 쪽이 공개키로 검증하는 기술이다. 그 개인키는 송신자만 가지므로 보낸 사실을 부인할 수 없게 되어 옳다(정답).
    2. 대칭키 암호화(symmetric encryption)는 보내는 쪽과 받는 쪽이 같은 키를 나눠 쓰는 방식이다. 두 사람 모두 같은 암호문을 만들 수 있어 누가 보냈는지 증명하지 못하므로 옳지 않다.
    3. 앨리어스(alias)는 여러 수신 주소를 별칭 하나로 묶어 두는 메일 기능이다. 주소 관리를 편하게 할 뿐 송신 사실을 증명하는 기술이 아니므로 옳지 않다.
    4. 커버로스(Kerberos)는 티켓 발급 서버를 두고 네트워크 사용자를 인증하는 프로토콜이다. 메일 송신자가 보낸 사실을 부인하지 못하게 하는 기술이 아니므로 옳지 않다.
    🧮 풀이
    1. 구청 계약 담당 甲이 업체에 단가 확정 메일을 보내면서 자기 인증서의 개인키로 전자 서명을 붙였다. 석 달 뒤 甲이 그런 메일을 보낸 적 없다고 했지만, 업체가 甲의 공개키로 서명을 검증해 그 메일이 甲의 개인키로 서명되었음을 보이자 甲은 더 다툴 수 없었다.
    2. 법무팀 甲과 거래처 乙이 미리 나눠 가진 같은 대칭키로 계약 메일을 암호화해 주고받았다. 문제가 된 메일을 두고 乙은 甲이 보낸 것이라 주장했지만, 같은 키를 가진 乙도 그 키로 똑같은 메일을 얼마든지 꾸며 낼 수 있어 발신자를 끝내 가리지 못했다.
    3. 총무팀 甲은 all-staff라는 alias를 만들어 직원 120명의 주소를 한 이름에 묶었다. 공지를 보낼 때 주소 하나만 쓰면 되어 편해졌지만, 그 메일을 누가 보냈는지 증명하는 힘은 전혀 생기지 않았다.
    4. 연구실 네트워크를 맡은 甲은 PC 로그인에 Kerberos를 도입해 사용자가 한 번 인증받으면 티켓으로 여러 서버를 쓰게 했다. 로그인은 편해졌지만 학생이 보낸 메일의 송신 사실을 증명하는 데는 이 티켓이 쓰이지 않았다.

    송신자만 가진 개인키로 서명하는 전자 서명이 있어야 받는 쪽이 검증할 수 있고, 메일을 보낸 사실을 부인하지 못한다. 정답은 1번이다.

    2017년에 발표된 OWASP TOP 10의 항목 중 (가)에 해당되는 것은?

    (가) 은(는) 신뢰할 수 없는 데이터가 명령어나 쿼리문의 일부분으로서, 인터프리터로 보내질 때 발생한다. 공격자의 악의적인 데이터는 예기치 않은 명령을 실행하거나 올바른 권한 없이 데이터에 접근하도록 인터프리터를 속일 수 있다.

    1. 1. Broken Access Control
    2. 2. Broken Authentication
    3. 3. Sensitive Data Exposure
    4. 4. Injection

    정답 4번

    🔍 보기별 해설
    1. Broken Access Control(접근 통제 취약점)은 권한 없는 사용자가 남의 데이터나 관리자 기능에 접근하게 되는 취약점이다. 데이터가 쿼리 일부로 인터프리터에 넘어가는 문제와는 다르므로 옳지 않다.
    2. Broken Authentication(취약한 인증)은 세션 관리나 비밀번호 처리를 잘못해 공격자가 다른 사람으로 로그인하게 되는 취약점이다. 명령어에 악성 데이터가 섞이는 문제가 아니므로 옳지 않다.
    3. Sensitive Data Exposure(민감 데이터 노출)는 개인정보나 카드번호를 암호화하지 않고 저장하거나 보내 유출되는 취약점이다. 인터프리터를 속이는 공격과는 다르므로 옳지 않다.
    4. Injection은 SQL·OS 명령·LDAP 쿼리에 신뢰할 수 없는 입력이 그대로 들어가 인터프리터가 공격자의 명령을 실행하게 되는 취약점이다. 지문이 말하는 내용이므로 옳다(정답).
    🧮 풀이
    1. 학습관리시스템을 쓰던 학생 甲이 주소창의 user=1052를 1053으로 바꾸자 다른 학생의 성적표가 그대로 열렸다. 서버가 요청한 사람이 그 기록의 주인인지 보지 않아 생긴 Broken Access Control 사례다.
    2. 쇼핑몰 회원 甲은 PC방에서 로그아웃하지 않고 나왔는데 세션이 몇 시간이 지나도 끊기지 않았다. 다음 손님이 甲의 계정으로 주문을 넣었으니 세션 만료를 두지 않은 Broken Authentication 취약점이다.
    3. 의원 예약 사이트를 만든 개발자 甲은 환자 주민등록번호를 평문 그대로 DB에 넣었다. DB 백업 파일이 외부로 새자 번호가 고스란히 읽혔으니 Sensitive Data Exposure에 대한 대비가 없었던 것이다.
    4. 도서 검색창에 공격자 甲이 ' OR '1'='1을 넣자 서버가 만든 검색 쿼리의 WHERE 조건이 항상 참이 되어 회원 목록 전체가 화면에 나왔다. 개발자가 입력값을 쿼리 문장과 분리하지 않고 문자열로 이어 붙여 생긴 Injection 취약점이다.

    신뢰할 수 없는 입력이 명령어나 쿼리의 일부로 인터프리터에 넘어가 엉뚱한 명령이 실행되는 OWASP 항목은 Injection이다. 정답은 4번이다.

    다음 설명에 따라 진행되는 공격 유형은?

    ○ 공격자는 악의적인 스크립트가 포함된 콘텐츠를 웹 애플리케이션 서버에 업로드한다.

    ○ 해당 콘텐츠는 웹 애플리케이션 서버에 저장된다.

    ○ 희생자는 해당 콘텐츠를 웹 애플리케이션 서버에 요청하여 수신한다.

    ○ 해당 콘텐츠에 포함된 악의적인 스크립트가 희생자의 디바이스에서 실행된다.

    1. 1. Stored XSS
    2. 2. Reflected XSS
    3. 3. Brute Force
    4. 4. Buffer Overflow

    정답 1번

    🔍 보기별 해설
    1. Stored XSS(저장형 XSS)는 악성 스크립트를 게시글처럼 서버에 저장해 두고, 그 글을 요청한 사용자 브라우저에서 실행되게 하는 공격이다. 업로드·저장·요청·실행의 네 단계가 그대로 맞으므로 옳다(정답).
    2. Reflected XSS(반사형 XSS)는 악성 스크립트를 URL 매개변수에 담아 피해자가 링크를 누르면 서버 응답에 그대로 되돌아와 실행되는 공격이다. 서버에 콘텐츠가 저장되는 단계가 없으므로 옳지 않다.
    3. Brute Force(무차별 대입)는 가능한 비밀번호를 하나씩 모두 넣어 보며 맞는 값을 찾는 공격이다. 스크립트를 서버에 올려 피해자 기기에서 실행시키는 공격이 아니므로 옳지 않다.
    4. Buffer Overflow는 정해진 크기를 넘는 입력으로 메모리를 덮어써 실행 흐름을 바꾸는 공격이다. 웹 콘텐츠에 스크립트를 심는 방식과는 다르므로 옳지 않다.
    🧮 풀이
    1. 공격자 甲은 학교 자유게시판에 script 태그로 쿠키를 빼내는 코드를 숨긴 글을 올렸다. 글은 DB에 저장되었고, 그 글을 연 학생들의 브라우저마다 스크립트가 실행되어 세션 쿠키가 甲의 서버로 넘어갔으니 Stored XSS다.
    2. 공격자 甲이 검색어 자리에 스크립트를 넣은 링크를 만들어 병원 직원 乙에게 메일로 보냈다. 乙이 링크를 누르자 검색 결과 페이지가 그 스크립트를 되돌려 주어 乙의 브라우저에서만 실행됐고, 서버에는 아무것도 남지 않는 Reflected XSS였다.
    3. 모의해킹 담당 甲은 학사 포털 로그인에 흔한 비밀번호 1만 개를 차례로 넣는 Brute Force를 돌렸다. 실패 횟수에 따른 잠금이 없어 37분 만에 한 계정이 열렸고, 학교는 곧바로 잠금 정책을 넣었다.
    4. 취약점 연구원 甲은 이름 입력 칸이 64바이트뿐인 프로그램에 200바이트 문자열을 넣었다. 넘친 값이 리턴 주소를 덮어 프로그램이 甲이 넣은 주소로 뛰었으니 Buffer Overflow다.

    악성 스크립트가 담긴 콘텐츠가 서버에 저장되었다가 그 콘텐츠를 요청한 피해자 기기에서 실행되므로 Stored XSS다. 정답은 1번이다.
